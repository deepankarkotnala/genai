What is an array?

An array is a collection of items stored one after another in a single, ordered row. Each item sits in its own numbered slot, and that number is called the index. The first slot is index 0, the next is 1, and so on.

01234

The array above holds five numbers. The value 5 is at index 0, the value 9 is at index 2, and so on. Think of it like a row of numbered lockers: to find one, you just need its number.

Key idea: indexes start at 0, not 1. An array of n items has indexes 0 through n − 1. Off-by-one bugs almost always come from forgetting this.

Reading an item — the one superpower

Because the items sit in a neat row, the computer can jump straight to any slot using its index — it never has to walk past the earlier items first. Reading a[2] takes the same tiny amount of time whether the array has 5 items or 5 million.

We describe this "same time no matter how big" cost as O(1), or constant time. It is the single reason arrays are the default tool for so many problems.

Example — reading and changing by index
indexing.py
a = [5, 1, 9, 2, 7]

print(a[0])      # 5   -> first item
print(a[2])      # 9   -> third item
print(a[-1])     # 7   -> last item (negative index counts from the end)

a[2] = 99        # overwrite the item at index 2
print(a)         # [5, 1, 99, 2, 7]

What does "O(1)" mean in plain words?

O(1) = "constant time." The work does not grow as the array grows. Compare it to O(n) = "linear time," where doubling the data doubles the work. You will see this notation on every operation below — it is just a label for how the cost scales.

In Python, an array is called a list

Python has no separate "array" keyword for everyday use. The built-in list is a resizable array, and it is what interviewers expect you to reach for. You create one with square brackets:

Example — the everyday operations
list_basics.py
nums = [10, 20, 30]     # create a list

len(nums)               # 3        -> how many items
nums[1]                 # 20       -> read by index
nums[1] = 25            # update in place -> [10, 25, 30]
30 in nums              # True     -> membership test (scans the list)

for x in nums:          # walk every item
    print(x)

So far so simple. The interesting part — and where interview points are won or lost — is what happens when the list changes size.

Adding and removing items

Adding to the end of a list is cheap. There is spare room at the back, so Python just drops the item in. This is append, and it is O(1).

Adding or removing at the front is expensive. Every other item has to shift over by one slot to make room (or close the gap). With n items that is n moves — O(n).

NEW5→1→9→2→7→

Insert at the front: the new value takes slot 0 and every old value slides one place to the right. That sliding is the O(n) cost.

Example — cheap end vs expensive front
grow_shrink.py
from collections import deque

a = [1, 2, 3]
a.append(4)       # add at end     -> [1, 2, 3, 4]   O(1)  (cheap)
a.pop()           # remove from end -> [1, 2, 3]      O(1)  (cheap)

a.insert(0, 0)    # add at front   -> [0, 1, 2, 3]   O(n)  (everything shifts)
a.pop(0)          # remove front   -> [1, 2, 3]      O(n)  (everything shifts)

# Need fast adds/removes at BOTH ends? Use a deque, not a list.
q = deque([1, 2, 3])
q.appendleft(0)   # O(1)
q.popleft()       # O(1)
⚠️
The hidden O(n²) trap

Calling list.pop(0) or list.insert(0, x) inside a loop is a classic mistake: each call is O(n), and doing it n times makes the whole loop O(n²) — slow enough to time out. Reach for collections.deque when you add or remove at the front.

Every operation and its cost

Here is the full picture. You do not need to memorise the "why" column yet — just notice that anything touching the end is cheap, anything touching the front or middle is expensive.

Read / write a[i]O(1)Jump straight to the slot
Append / pop at the endO(1)*Spare room at the back
Insert / pop at the frontO(n)All later items shift

Search a sorted list (binary)O(log n)Halve the range each step — see Ch 10

Three gotchas that catch everyone

These three surprises come straight from how Python stores lists. Each has burned people in real interviews, so learn them once here.

1. Two names, one list (aliasing). Assigning a list to a new variable does not copy it. Both names point at the same list, so a change through one is visible through the other.

Example — b = a does not make a copy
aliasing.py
a = [1, 2, 3]
b = a             # b and a are two names for the SAME list
b.append(4)
print(a)          # [1, 2, 3, 4]  <- changed through b, seen through a!

c = a[:]          # a slice makes a REAL copy (a brand-new list)
c.append(5)
print(a)          # [1, 2, 3, 4]  <- unchanged; c is independent
Output[1, 2, 3, 4]
[1, 2, 3, 4]

To copy a list, use a[:], a.copy(), or list(a). Plain = only makes another name.

2. The default-argument trap. A default value like acc=[] is created once, when the function is defined — not fresh on each call. So the same list leaks state between calls.

Example — why def f(acc=[]) is a bug
default_arg.py
def bad(x, acc=[]):        # DON'T: one shared list for all calls
    acc.append(x)
    return acc

print(bad(1))              # [1]
print(bad(2))              # [1, 2]  <- surprise! state leaked

def good(x, acc=None):     # DO: build a fresh list inside
    if acc is None:
        acc = []
    acc.append(x)
    return acc

print(good(1), good(2))    # [1] [2]  <- independent, as expected

3. Building a 2-D grid by multiplying. [[0] * cols] * rows looks like a fresh grid but copies the same inner row rows times. Editing one cell changes that column in every row. Use a comprehension instead.

Example — the aliased-row trap in a matrix
grid.py
grid = [[0] * 3] * 2       # DON'T: both rows are the SAME list
grid[0][0] = 9
print(grid)                # [[9, 0, 0], [9, 0, 0]]  <- both rows changed!

grid = [[0] * 3 for _ in range(2)]   # DO: each row is its own list
grid[0][0] = 9
print(grid)                # [[9, 0, 0], [0, 0, 0]]  <- correct
All three gotchas are the same lesson: a Python variable is a name pointing at an object, not a box holding a copy. When you want an independent list, copy it on purpose.

Two kinds of "space" interviewers ask about

When someone asks "what's the space complexity?", they mean two different things, and mixing them up loses points:

Output space

Memory for the answer you must return — e.g. a result array the problem requires. By convention this is not counted against you.

Auxiliary space

Extra working memory you allocate to compute the answer — a set, a stack, a copy. This is what "O(1) space" refers to.

So "solve it in O(1) space" means "use only a constant amount of extra memory beyond the output" — and it usually implies you are allowed to modify the input. Always confirm that last part out loud.

Under the hood (nice to know, not day-one)

A Python list doesn't store the numbers themselves in a row — it stores references (pointers) to number objects in a row. That is why a list can hold mixed types, and why it uses more memory than a packed C array. numpy and array.array store the raw values contiguously, which is lighter and more cache-friendly.

Strengths, weaknesses, and the nearest alternative

✅ Strengths

Instant O(1) access by index; fast to scan in order; the natural home for prefix sums, two pointers, and sorting.

⚠️ Weaknesses

Inserting or deleting anywhere but the end is O(n) because items shift; storing references adds memory overhead.

Nearest alternative — the linked list. A linked list can insert or delete in O(1) once you're holding the right node, but reading item i costs O(n) because you must walk from the start. Rule of thumb: index a lot → array; splice in the middle a lot → linked list. Full treatment in Chapter 03.

1 LC 1Two Sum Easy Hashing · remember what you have seen

Problem. Return the indices of the two numbers that add up to a target. Exactly one answer exists. LeetCode 1 ↗

Clarify: Exactly one solution? (Yes.) Can I use the same element twice? (No.) Are there negatives? (Yes.)

Hint 1
The slow way checks every pair — O(n²). Can a lookup table remove the inner loop?
Hint 2
For each number x, the partner you need is target − x. Store numbers you have seen in a dict as you go, and check for the partner before storing.

How to think about it Walk the list once. For each value x, the number that would complete the pair is target − x. Keep a dictionary of value → index for everything seen so far; if the partner is already in it, you have the answer. Checking and inserting are both O(1).

two_sum.py
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}                      # value -> index
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:
                return [seen[need], i]
            seen[x] = i
        return []

Time O(n) · Space O(n) for the dictionary. Watch out: check for the partner before inserting the current value, or a value could match itself.

2 LC 26Remove Duplicates from Sorted Array Easy Two pointers · a slow writer and a fast reader

Problem. The array is sorted. Remove duplicates in place so each value appears once, and return the new length k. The first k slots must hold the result. LeetCode 26 ↗

Clarify: Is the input sorted? (Yes — that is what makes duplicates adjacent.) Does the order matter? (Keep ascending.) Extra array allowed? (No — do it in place.)

Hint 1
Because it is sorted, duplicates sit next to each other. Compare each item with the last one you kept.
Hint 2
Use a write pointer k for the next slot to fill and a read pointer i scanning ahead. Copy a value only when it differs from the last kept value.

How to think about it Keep a write index k that marks where the next unique value goes. Scan with i; whenever nums[i] differs from the previously kept value nums[k-1], write it at k and advance k. Everything before k stays unique and sorted.

remove_duplicates.py
from typing import List

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if not nums:
            return 0
        k = 1                          # next write position
        for i in range(1, len(nums)):
            if nums[i] != nums[k - 1]:
                nums[k] = nums[i]
                k += 1
        return k

Time O(n) · Space O(1). Watch out: compare against the last kept value nums[k-1], not nums[i-1].

3 LC 27Remove Element Easy Two pointers · keep the ones you want

Problem. Remove every occurrence of val in place and return the count k of remaining elements. Order of the kept elements does not matter. LeetCode 27 ↗

Clarify: Does the order of the remaining elements matter? (No.) What is beyond index k? (Anything — ignored.)

Hint 1
Instead of deleting (which shifts everything), overwrite: copy the values you want to keep to the front.
Hint 2
A single write pointer k is enough: for every value that is not val, place it at k and advance.

How to think about it This is a filter done in place. A write pointer k collects the survivors at the front of the array. Each value that is not val gets copied to nums[k]; k ends as the new length.

remove_element.py
from typing import List

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        k = 0
        for x in nums:
            if x != val:
                nums[k] = x
                k += 1
        return k

Time O(n) · Space O(1). This 'compact by overwriting' move is the base pattern behind Move Zeroes and Remove Duplicates.

4 LC 283Move Zeroes Easy Two pointers · swap non-zeros forward

Problem. Move all 0s to the end while keeping the relative order of the non-zero numbers. Do it in place. LeetCode 283 ↗

Clarify: Keep the order of non-zeros? (Yes.) In place, no copy? (Yes.) Minimise writes? (Nice-to-have.)

Hint 1
Think of it as pulling every non-zero to the front, in order; the zeros fall to the back automatically.
Hint 2
Keep a write index k. When you meet a non-zero, swap it into slot k and advance k.

How to think about it A write pointer k marks the front region that is already packed with non-zeros in order. Scan the array; each non-zero swaps into nums[k]. Because k never runs ahead of the scan, zeros naturally accumulate at the tail.

move_zeroes.py
from typing import List

class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        k = 0                          # next slot for a non-zero
        for i in range(len(nums)):
            if nums[i] != 0:
                nums[k], nums[i] = nums[i], nums[k]
                k += 1

Time O(n) · Space O(1). Swapping (rather than overwriting then zero-filling) keeps the order and needs no second pass.

5 LC 88Merge Sorted Array Easy Two pointers · fill from the back

Problem. Merge two sorted arrays into the first one, which has trailing space (m+n slots). Do it in place. LeetCode 88 ↗

Clarify: Is nums1 sized m + n with the last n slots as padding? (Yes.) Merge in place? (Yes.)

Hint 1
Merging from the front would overwrite nums1 values you have not read yet.
Hint 2
Fill from the back: the largest remaining element goes into the last empty slot, working left.

How to think about it Write from the end. Three pointers: i at the tail of the real part of nums1, j at the tail of nums2, and k at the very last slot. Copy the larger of the two tails into k and step inward. Writing backwards means you never clobber a value you still need.

merge_sorted.py
from typing import List

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i, j, k = m - 1, n - 1, m + n - 1
        while j >= 0:
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[k] = nums1[i]; i -= 1
            else:
                nums1[k] = nums2[j]; j -= 1
            k -= 1

Time O(m + n) · Space O(1). Watch out: the loop runs while j >= 0 — once nums2 is placed, the rest of nums1 is already in order.

6 LC 977Squares of a Sorted Array Easy Two pointers · biggest square is at an end

Problem. Given a sorted array (which may contain negatives), return the squares of each number, sorted ascending. LeetCode 977 ↗

Clarify: Can there be negatives? (Yes — that is the whole trick.) Must the output be sorted? (Yes.) O(n) expected? (Yes.)

Hint 1
Squaring makes big negatives large again, so the input order is lost. But where do the largest squares live?
Hint 2
The largest square is always at one of the two ends. Compare the ends, take the bigger square, and fill the answer from the back.

How to think about it After squaring, the biggest value comes from whichever end has the larger magnitude. Put pointers at both ends and fill the output array back-to-front, each time taking the larger of the two end-squares and moving that pointer inward.

squares.py
from typing import List

class Solution:
    def sortedSquares(self, nums: List[int]) -> List[int]:
        n = len(nums)
        out = [0] * n
        l, r = 0, n - 1
        for pos in range(n - 1, -1, -1):
            if abs(nums[l]) > abs(nums[r]):
                out[pos] = nums[l] * nums[l]; l += 1
            else:
                out[pos] = nums[r] * nums[r]; r -= 1
        return out

Time O(n) · Space O(n) for the output. Sorting the squares directly would be O(n log n) — the two-pointer fill beats it.

7 LC 121Best Time to Buy and Sell Stock Easy Running state · cheapest buy so far

Problem. Pick one day to buy and a later day to sell to maximise profit. Return 0 if no profit is possible. LeetCode 121 ↗

Clarify: Single transaction only? (Yes.) Can prices be empty? (Yes — return 0.) Must sell after buy? (Yes.)

Hint 1
The best sale on day i pairs with the cheapest buy on any earlier day.
Hint 2
Track min_price so far; at each day the best profit is price − min_price.

How to think about it Sweep left to right holding the cheapest price seen so far. On each day, the best possible profit if you sold today is today − cheapest-so-far; keep the maximum of those. One pass, O(1) memory.

best_time.py
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        min_price, best = float("inf"), 0
        for p in prices:
            min_price = min(min_price, p)
            best = max(best, p - min_price)
        return best

Time O(n) · Space O(1). Watch out: keep the running best profit — don't reset it to 0 when the price dips.

8 LC 122Best Time to Buy and Sell Stock II Easy Greedy · grab every uphill step

Problem. You may buy and sell as many times as you like (one share at a time). Maximise total profit. LeetCode 122 ↗

Clarify: Unlimited transactions? (Yes.) Can I hold and sell same day? (Yes, no fee.) Any transaction cost? (No.)

Hint 1
Any profit over several rising days equals the sum of the day-to-day gains within that rise.
Hint 2
So just add up every positive difference prices[i] − prices[i-1].

How to think about it Because there is no fee, capturing every rising step is optimal: a long climb is the same profit as buying at the bottom and selling at the top. Add each positive consecutive difference and ignore the drops.

best_time_ii.py
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        profit = 0
        for i in range(1, len(prices)):
            if prices[i] > prices[i - 1]:
                profit += prices[i] - prices[i - 1]
        return profit

Time O(n) · Space O(1). Contrast with LC 121 (single transaction) — the fee-free rule is what makes greedy correct here.

9 LC 169Majority Element Easy Boyer–Moore voting · O(1) space

Problem. Return the element that appears more than ⌊n/2⌋ times. It is guaranteed to exist. LeetCode 169 ↗

Clarify: Is a majority guaranteed? (Yes.) Can I use O(1) space? (That is the elegant version.)

Hint 1
A hash count works but uses O(n) space. Can each non-majority element cancel one majority element?
Hint 2
Keep a candidate and a count: +1 when the value matches, −1 otherwise; reset the candidate when the count hits 0.

How to think about it Pair up and cancel opposite votes. Hold a candidate and a counter. Equal values reinforce it; different values cancel one vote. Because the true majority outnumbers everything else combined, it is the last one standing.

majority.py
from typing import List

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        count, cand = 0, None
        for x in nums:
            if count == 0:
                cand = x
            count += 1 if x == cand else -1
        return cand

Time O(n) · Space O(1) — the win over a hash count. See LC 229 for the '> n/3' version with two candidates.

10 LC 217Contains Duplicate Easy Hashing · a seen-set
🔗
Canonical write-up: Chapter 04 — Hashing. The array-lens solution is shown here in full.

Problem. Return True if any value appears at least twice, else False. LeetCode 217 ↗

Clarify: Sort allowed? (Sure — that is one option.) Optimise for time or memory? (Usually time.)

Hint 1
Sorting first puts duplicates next to each other — O(n log n), O(1) extra.
Hint 2
A set gives O(n) time: add as you go and stop the moment you see a repeat.

How to think about it Trading memory for speed: keep a set of values seen so far. If the current value is already in it, there is a duplicate. Sorting instead would be O(n log n) but avoids the extra memory — name that trade-off out loud.

contains_dup.py
from typing import List

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()
        for x in nums:
            if x in seen:
                return True
            seen.add(x)
        return False

Time O(n) · Space O(n). Or return len(set(nums)) != len(nums) as a one-liner.

11 LC 66Plus One Easy Math · carry from the right

Problem. A non-negative integer is stored as an array of digits, most significant first. Add one and return the digits. LeetCode 66 ↗

Clarify: Could it carry all the way (e.g. 999)? (Yes — the array grows by one.) Leading zeros? (No.)

Hint 1
Add from the last digit, exactly like grade-school addition.
Hint 2
If a digit is below 9, bump it and you are done. If it is 9, it becomes 0 and the carry moves left.

How to think about it Walk from the least-significant digit. If it is less than 9, increment and return immediately — no carry. If it is 9, set it to 0 and continue left. If every digit was 9, the loop ends and you prepend a leading 1.

plus_one.py
from typing import List

class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        for i in range(len(digits) - 1, -1, -1):
            if digits[i] < 9:
                digits[i] += 1
                return digits
            digits[i] = 0
        return [1] + digits

Time O(n) · Space O(1) (O(n) only in the all-nines case). Returning early avoids touching digits after the carry stops.

12 LC 268Missing Number Easy Math · expected sum minus actual

Problem. The array holds n distinct numbers taken from 0..n. Return the one number that is missing. LeetCode 268 ↗

Clarify: Exactly one missing? (Yes.) Range is 0..n inclusive? (Yes.) O(1) space? (Achievable.)

Hint 1
You know exactly which numbers should be there: 0, 1, …, n.
Hint 2
The sum of 0..n is n(n+1)/2. Subtract the actual sum and you are left with the gap.

How to think about it The full set 0..n has a known total, n(n+1)/2. Whatever is missing equals that expected total minus the actual sum of the array. (XOR-ing all indices and values also works and avoids overflow in other languages.)

missing_number.py
from typing import List

class Solution:
    def missingNumber(self, nums: List[int]) -> int:
        n = len(nums)
        total = n * (n + 1) // 2
        return total - sum(nums)

Time O(n) · Space O(1). Clean, but say the XOR alternative if the interviewer worries about integer overflow.

13 LC 136Single Number Easy Bit trick · XOR cancels pairs

Problem. Every element appears twice except one. Find that single one, in O(n) time and O(1) space. LeetCode 136 ↗

Clarify: Exactly one loner, all others in pairs? (Yes.) O(1) space required? (That is the point.)

Hint 1
A hash count works but uses extra space. Is there an operation where x combined with x disappears?
Hint 2
XOR: x ^ x == 0 and x ^ 0 == x. XOR the whole array and the pairs cancel.

How to think about it XOR is its own inverse, so identical pairs cancel to 0, and order does not matter. Fold XOR across every element; the only survivor is the number without a partner.

single_number.py
from typing import List

class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        result = 0
        for x in nums:
            result ^= x
        return result

Time O(n) · Space O(1). A textbook example of using a bit operation to hit O(1) space.

14 LC 485Max Consecutive Ones Easy Running state · count the current streak

Problem. Given a binary array, return the length of the longest run of consecutive 1s. LeetCode 485 ↗

Clarify: Only 0s and 1s? (Yes.) Empty array? (Return 0.)

Hint 1
Track the current streak length as you scan.
Hint 2
A 1 extends the streak; a 0 resets it to 0. Remember the best streak seen.

How to think about it Keep a running counter of the current streak of ones. Each 1 increases it; each 0 resets it to zero. Track the maximum along the way.

max_ones.py

    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []
        n = len(nums)
        for i in range(n - 2):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            if nums[i] > 0:
                break
            l, r = i + 1, n - 1

                s = nums[i] + nums[l] + nums[r]

                    l += 1
                elif s > 0:

                        r -= 1

How to think about it Sweep left to right holding the farthest index reachable. At each index, first check it is within reach; if not, return False. Otherwise extend the reach to i + nums[i]. If the scan finishes, the end is reachable.

class Solution:

                end = farthest
        return jumps

find_duplicate.py
from typing import List

class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        slow = fast = nums[0]
        while True:
            slow = nums[slow]
            fast = nums[nums[fast]]
            if slow == fast:
                break
        slow = nums[0]
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]
        return slow

class Solution:

        n1 = n2 = 0

            if x == c1:
                n1 += 1

            elif n2 == 0:

class Solution:

        n = len(matrix)
        for r in range(n):                    # transpose

        for row in matrix:                    # reverse each row

43 LC 54Spiral Matrix Medium Four shrinking boundaries

Problem. Return all matrix elements in clockwise spiral order. LeetCode 54 ↗

Clarify: Can it be non-square or empty? (Yes — handle both.)

Hint 1

Hint 2

How to think about it Keep the unvisited region as a rectangle [top..bottom] × [left..right]. Each loop peels the top row, right column, bottom row, and left column, shrinking that boundary. Two guards stop you re-reading the last row or column when the shape is odd.

spiral_matrix.py
from typing import List

class Solution:
    def spiralOrder(self, matrix: List[List[int]]) -> List[int]:
        if not matrix:
            return []
        top, bottom = 0, len(matrix) - 1
        left, right = 0, len(matrix[0]) - 1
        out = []
        while top <= bottom and left <= right:
            for c in range(left, right + 1):
                out.append(matrix[top][c])
            top += 1
            for r in range(top, bottom + 1):
                out.append(matrix[r][right])
            right -= 1
            if top <= bottom:
                for c in range(right, left - 1, -1):
                    out.append(matrix[bottom][c])
                bottom -= 1
            if left <= right:
                for r in range(bottom, top - 1, -1):
                    out.append(matrix[r][left])
                left += 1
        return out

Time O(rows × cols) · Space O(1) beyond the output. Forgetting the two guards double-counts the middle line — the classic bug.

45 LC 289Game of Life Medium In-place encode · two-bit states

Problem. Compute the next state of Conway's Game of Life, updating the board in place (all cells change simultaneously). LeetCode 289 ↗

Hint 1

Hint 2

How to think about it You need the old value while writing the new one. Encode transitions in the same cell: keep 0/1 for unchanged, use 2 for live→dead and 3 for dead→live. Neighbour counts read value in (1,2) to mean 'was live'. A final pass decodes each cell to its new 0/1.

game_of_life.py
from typing import List

class Solution:
    def gameOfLife(self, board: List[List[int]]) -> None:
        rows, cols = len(board), len(board[0])
        def live_neighbors(r, c):
            count = 0
            for dr in (-1, 0, 1):
                for dc in (-1, 0, 1):
                    if dr == 0 and dc == 0:
                        continue
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] in (1, 2):
                        count += 1
            return count
        for r in range(rows):
            for c in range(cols):
                n = live_neighbors(r, c)
                if board[r][c] == 1 and (n < 2 or n > 3):
                    board[r][c] = 2          # was live, now dead
                elif board[r][c] == 0 and n == 3:
                    board[r][c] = 3          # was dead, now live
        for r in range(rows):
            for c in range(cols):
                board[r][c] = 1 if board[r][c] in (1, 3) else 0

Time O(rows × cols) · Space O(1). Encoding old+new in one number is the standard way to do a simultaneous update in place.

How to think about it Binary search with a twist. Compare the midpoint to the low end to learn which half is sorted. If the target falls inside that sorted half's range, search there; otherwise search the other half. Each step still halves the range.

search_rotated.py
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[lo] <= nums[mid]:              # left half sorted
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:                                   # right half sorted
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return -1

Time O(log n) · Space O(1). The whole difficulty is the 'which half is sorted, is the target in it' branch — the rest is standard binary search.

search_range.py
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def bound(is_left):
            lo, hi, ans = 0, len(nums) - 1, -1
            while lo <= hi:
                mid = (lo + hi) // 2
                if nums[mid] < target or (not is_left and nums[mid] == target):
                    lo = mid + 1
                else:
                    hi = mid - 1
                if nums[mid] == target:
                    ans = mid
            return ans
        return [bound(True), bound(False)]

randomized_set.py
import random

class RandomizedSet:
    def __init__(self):
        self.pos = {}          # value -> index in self.vals
        self.vals = []
    def insert(self, val: int) -> bool:
        if val in self.pos:
            return False
        self.pos[val] = len(self.vals)
        self.vals.append(val)
        return True
    def remove(self, val: int) -> bool:
        if val not in self.pos:
            return False
        idx = self.pos[val]
        last = self.vals[-1]
        self.vals[idx] = last          # move last into the gap
        self.pos[last] = idx
        self.vals.pop()
        del self.pos[val]
        return True
    def getRandom(self) -> int:
        return random.choice(self.vals)

All operations O(1) average · Space O(n). The swap-with-last delete is the pattern worth remembering — it turns array removal into O(1) when order does not matter.

Clarify: Water above bar i is min(maxLeft, maxRight) − height[i]? (Yes.) O(1) space possible? (Yes, with two pointers.)

Hint 2

How to think about it Two pointers from the ends carry the running max on each side. trapping_rain.py
from typing import List

class Solution:
    def trap(self, height: List[int]) -> int:
        if not height:
            return 0
        l, r = 0, len(height) - 1
        left_max, right_max = height[l], height[r]
        water = 0
        while l < r:
            if left_max < right_max:
                l += 1
                left_max = max(left_max, height[l])
                water += left_max - height[l]
            else:
                r -= 1
                right_max = max(right_max, height[r])
                water += right_max - height[r]
        return water

Time O(n) · Space O(1). The prefix-max-arrays version (O(n) space) is the clearer first answer — present it, then optimise to two pointers.

Cheat sheet

  • "Except self" / range aggregate → prefix × suffix, no division.
  • Max/min contiguous → Kadane (cur = max(x, cur+x)).

Concept checks

Why does list.pop(0) make an otherwise-linear loop quadratic?
Because it copies the whole list on every call
Because removing the front shifts every remaining element left — O(n) per call, O(n²) across the loop
Because it triggers a resize each time
A list is a contiguous array of references; removing index 0 shifts all others down by one. Use collections.deque.popleft() for O(1).
You claim your Product-of-Array-Except-Self is "O(1) space". What must you state to be correct?
That the output array is output space (excluded), and no additional arrays are used beyond two scalars
That you used NumPy to save memory
Nothing — O(1) space is obvious
