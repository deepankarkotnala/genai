1 · Foundations

New to string problems? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is a string?

A string is an ordered sequence of characters — much like an array whose elements happen to be single characters. You can index it (s[0]), slice it (s[1:4]), and loop over it, all the familiar array moves.

Example — indexing and slicing
basics.py
s = "hello"
print(s[0])       # h        -> index, O(1)
print(s[-1])      # o        -> last character
print(s[1:4])     # ell      -> slice [start:end), makes a NEW string
print(len(s))     # 5
for ch in s:      # iterate character by character
    pass
Outputh
o
ell
5

The one big difference: strings are immutable

Unlike a list, a string cannot be changed in place. There is no s[0] = "H" — it raises an error. Any "edit" actually builds a brand-new string. That single fact drives the whole chapter.

Example — you can't edit, you rebuild
immutable.py
s = "hello"
# s[0] = "H"            # TypeError: 'str' object does not support item assignment

s = "H" + s[1:]         # build a NEW string instead
print(s)                # Hello

chars = list("hello")   # to edit in place, convert to a list first
chars[0] = "H"
print("".join(chars))   # Hello  -> join back into a string
To modify text in place (two-pointer swaps, in-place compression), convert the string to a list of characters, do the work, then "".join(...) it back. This is why LeetCode hands you a List[str] in problems like Reverse String.

The concatenation trap

Because every "change" makes a new string, building a string with += inside a loop is secretly O(n²): each += copies the whole string so far. The fix is to collect pieces in a list and join them once at the end — O(n).

Example — the slow way vs the fast way
build.py
# SLOW: each += copies everything so far -> O(n^2)
out = ""
for ch in "hello":
    out += ch

# FAST: collect pieces, join once -> O(n)
pieces = []
for ch in "hello":
    pieces.append(ch)
out = "".join(pieces)
Whenever you're assembling a result string piece by piece, reach for a list + join. You'll see this in almost every "build the answer" solution below.

Common operations and their cost

Characters are numbers underneath

Every character has an integer code (its ASCII/Unicode value). ord(ch) gives the number, chr(n) gives the character back. Because letters sit in contiguous blocks, you can do arithmetic on them — the basis of frequency arrays, base-26 conversions, and case shifts.

Example — ord, chr, and letter math
chars.py
print(ord("a"))            # 97
print(chr(97))             # a
print(ord("c") - ord("a")) # 2   -> 'c' is the 3rd letter (index 2)

# a 26-slot frequency array indexed by letter:
freq = [0] * 26
for ch in "banana":
    freq[ord(ch) - ord("a")] += 1
⚠️
String pitfalls

Don't build strings with += in a loop — use a list + join. Remember slicing copies (an O(n) slice inside a loop hides an O(n²)). And strings can't be mutated, so convert to a list for in-place work. For counting characters, collections.Counter (Ch 04) is your friend.

1 LC 344Reverse String Easy Two pointers · swap ends inward

Problem. Reverse a list of characters in place, using O(1) extra space. LeetCode 344 ↗

Clarify: Modify the input array in place (no new list)? (Yes.) O(1) space? (Yes.)

Hint 1
Swap the first and last characters, then move inward.
Hint 2
Two pointers, one from each end, meeting in the middle.

How to think about it The base two-pointer move. Put one pointer at each end and swap the characters they point to, then step both toward the centre. Stop when they meet. Nothing is copied, so it's O(1) space.

reverse_string.py
from typing import List

class Solution:
    def reverseString(self, s: List[str]) -> None:
        l, r = 0, len(s) - 1
        while l < r:
            s[l], s[r] = s[r], s[l]
            l += 1; r -= 1

Time O(n) · Space O(1). Strings are immutable, which is why LeetCode hands you a list of characters to mutate here.

2 LC 125Valid Palindrome Easy Filtered two pointers

Problem. Return whether the string is a palindrome, considering only alphanumeric characters and ignoring case. LeetCode 125 ↗

Clarify: Ignore spaces and punctuation? (Yes — only alphanumerics count.) Case-insensitive? (Yes.)

Hint 1
Compare characters from both ends inward.
Hint 2
Skip anything that isn't a letter or digit, and lowercase before comparing.

How to think about it Two pointers from the ends. Whenever a pointer sits on a non-alphanumeric character, skip it. Compare the surviving characters case-insensitively; any mismatch means it's not a palindrome. This avoids building a cleaned copy of the string.

valid_palindrome.py
class Solution:
    def isPalindrome(self, s: str) -> bool:
        l, r = 0, len(s) - 1
        while l < r:
            while l < r and not s[l].isalnum():
                l += 1
            while l < r and not s[r].isalnum():
                r -= 1
            if s[l].lower() != s[r].lower():
                return False
            l += 1; r -= 1
        return True

Time O(n) · Space O(1). Filtering in place (rather than pre-cleaning the string) keeps it O(1) extra space.

3 LC 345Reverse Vowels of a String Easy Two pointers · swap only the targets

Problem. Reverse only the vowels in the string, leaving all other characters in place. LeetCode 345 ↗

Clarify: Both cases count as vowels (a and A)? (Yes.) 'y' is a vowel? (No.)

Hint 1
Two pointers from the ends, but only act when both land on vowels.
Hint 2
Advance a pointer past any non-vowel; swap when both point at vowels.

How to think about it A targeted two-pointer swap. Move each pointer inward until it rests on a vowel; when both do, swap them and step inward. Non-vowels are simply skipped, so they stay put. Work on a list since strings are immutable.

reverse_vowels.py
class Solution:
    def reverseVowels(self, s: str) -> str:
        vowels = set("aeiouAEIOU")
        chars = list(s)
        l, r = 0, len(chars) - 1
        while l < r:
            if chars[l] not in vowels:
                l += 1
            elif chars[r] not in vowels:
                r -= 1
            else:
                chars[l], chars[r] = chars[r], chars[l]
                l += 1; r -= 1
        return "".join(chars)

Time O(n) · Space O(n) for the char list. The 'skip non-targets, swap targets' shape generalises to many in-place reorderings.

4 LC 14Longest Common Prefix Easy Shrink a candidate prefix

Problem. Return the longest common prefix shared by all strings, or an empty string. LeetCode 14 ↗

Clarify: Case-sensitive? (Yes.) Empty array possible? (Assume at least one string; guard if unsure.)

Hint 1
Start by assuming the whole first word is the prefix.
Hint 2
For each other word, trim the prefix until that word starts with it.

How to think about it Take the first string as a candidate prefix. For every other string, chop the last character off the candidate until the string starts with it. Whatever survives all comparisons is the longest common prefix; if it shrinks to empty, there is none.

lcp.py
from typing import List

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        prefix = strs[0]
        for w in strs[1:]:
            while not w.startswith(prefix):
                prefix = prefix[:-1]        # trim one char and retry
                if not prefix:
                    return ""
        return prefix

Time O(total characters) · Space O(1). A vertical scan (compare column by column) is an equally good alternative.

5 LC 28Find the Index of the First Occurrence Easy Substring search (sliding compare)

Problem. Return the index of the first occurrence of needle in haystack, or −1. LeetCode 28 ↗

Clarify: Empty needle returns 0? (Yes.) Case-sensitive? (Yes.)

Hint 1
Try to match the needle starting at each possible index.
Hint 2
Only starting positions up to len(haystack) − len(needle) can fit.

How to think about it Slide a window of length len(needle) across the haystack and compare each window to the needle. The straightforward check is O(n·m); mention KMP as the O(n+m) upgrade that reuses partial matches via a prefix table.

str_str.py
class Solution:
    def strStr(self, haystack: str, needle: str) -> int:
        n, m = len(haystack), len(needle)
        for i in range(n - m + 1):
            if haystack[i:i + m] == needle:
                return i
        return -1

Time O(n·m) worst case · Space O(1). KMP (Ch on strings/advanced) removes the re-scanning to reach O(n+m).

6 LC 58Length of Last Word Easy Scan from the end

Problem. Return the length of the last word (maximal run of non-space characters). LeetCode 58 ↗

Clarify: Trailing spaces possible? (Yes — skip them first.) At least one word guaranteed? (Yes.)

Hint 1
Start at the end and skip any trailing spaces.
Hint 2
Then count characters until you hit a space or the start.

How to think about it Walk backward from the end. First skip trailing spaces, then count consecutive non-space characters until the next space or the string's beginning. Scanning from the right avoids splitting the whole string.

last_word.py
class Solution:
    def lengthOfLastWord(self, s: str) -> int:
        i = len(s) - 1
        while i >= 0 and s[i] == " ":         # skip trailing spaces
            i -= 1
        length = 0
        while i >= 0 and s[i] != " ":         # count the last word
            length += 1
            i -= 1
        return length

Time O(n) · Space O(1). len(s.split()[-1]) works too but allocates the whole word list.

7 LC 13Roman to Integer Easy Char arithmetic · subtractive pairs

Problem. Convert a Roman numeral string to its integer value. LeetCode 13 ↗

Clarify: Input is always valid (1–3999)? (Yes.) Handle subtractive forms like IV, IX? (Yes.)

Hint 1
Usually add each symbol's value.
Hint 2
But when a smaller symbol sits before a larger one (IV, IX, XL…), subtract it instead.

How to think about it Map each Roman letter to its value. Scan left to right: normally add the value, but if the current symbol is smaller than the one after it, it's a subtractive pair, so subtract it. This single rule handles IV, IX, XL, and the rest.

roman_to_int.py
class Solution:
    def romanToInt(self, s: str) -> int:
        val = {"I":1,"V":5,"X":10,"L":50,"C":100,"D":500,"M":1000}
        total = 0
        for i in range(len(s)):
            if i + 1 < len(s) and val[s[i]] < val[s[i + 1]]:
                total -= val[s[i]]            # subtractive pair (IV, IX, ...)
            else:
                total += val[s[i]]
        return total

Time O(n) · Space O(1). The look-ahead comparison is the whole trick; Integer to Roman (LC 12) is the greedy inverse.

8 LC 709To Lower Case Easy Char arithmetic · ASCII shift

Problem. Return the string with every uppercase letter converted to lowercase (without str.lower, to learn the mechanic). LeetCode 709 ↗

Clarify: Only ASCII letters? (Yes.) Leave non-letters unchanged? (Yes.)

Hint 1
Uppercase 'A'–'Z' and lowercase 'a'–'z' differ by a fixed gap in ASCII.
Hint 2
That gap is 32; add it to shift an uppercase letter down to lowercase.

How to think about it Each uppercase letter maps to its lowercase form by adding 32 to its character code (the constant distance between the 'A'–'Z' and 'a'–'z' blocks in ASCII). Leave every other character untouched. ord/chr do the conversion.

to_lower.py
class Solution:
    def toLowerCase(self, s: str) -> str:
        out = []
        for ch in s:
            if "A" <= ch <= "Z":
                ch = chr(ord(ch) + 32)        # shift to lowercase via ASCII gap
            out.append(ch)
        return "".join(out)

Time O(n) · Space O(n). Understanding this ASCII gap underlies frequency arrays indexed by ord(c) − ord('a').

9 LC 412Fizz Buzz Easy Build output · check divisibility

Problem. Return the Fizz Buzz sequence from 1 to n: multiples of 3 → 'Fizz', of 5 → 'Buzz', of both → 'FizzBuzz'. LeetCode 412 ↗

Clarify: Check 15 (both) first? (Yes — otherwise you'd stop at Fizz.) 1-indexed? (Yes.)

Hint 1
Check divisibility by 15 before 3 or 5.
Hint 2
Otherwise a number divisible by both would match 'Fizz' first.

How to think about it Loop 1..n building the output list. Test divisibility by 15 first (both 3 and 5), then 3, then 5, else the number itself. The ordering of the checks is what makes 'FizzBuzz' appear for multiples of both.

fizz_buzz.py
from typing import List

class Solution:
    def fizzBuzz(self, n: int) -> List[str]:
        out = []
        for i in range(1, n + 1):
            if i % 15 == 0:
                out.append("FizzBuzz")
            elif i % 3 == 0:
                out.append("Fizz")
            elif i % 5 == 0:
                out.append("Buzz")
            else:
                out.append(str(i))
        return out

Time O(n) · Space O(n) for the output. Simple, but the check-both-first ordering is the classic gotcha.

10 LC 415Add Strings Easy Digit arithmetic · carry from the right

Problem. Add two non-negative integers given as strings, without converting them to int. LeetCode 415 ↗

Clarify: No use of int()/BigInteger? (Yes — that's the exercise.) No leading zeros in input? (Yes.)

Hint 1
Add digit by digit from the right, like on paper.
Hint 2
Track a carry; the loop continues while either string has digits or a carry remains.

How to think about it Schoolbook addition. Walk both strings from the least-significant end, summing the two digits plus the carry, using divmod(sum, 10) to split the new digit from the carry. Collect digits and reverse at the end. The i≥0 or j≥0 or carry condition handles unequal lengths and a final carry.

add_strings.py
class Solution:
    def addStrings(self, num1: str, num2: str) -> str:
        i, j, carry = len(num1) - 1, len(num2) - 1, 0
        out = []
        while i >= 0 or j >= 0 or carry:
            d1 = int(num1[i]) if i >= 0 else 0
            d2 = int(num2[j]) if j >= 0 else 0
            carry, digit = divmod(d1 + d2 + carry, 10)
            out.append(str(digit))
            i -= 1; j -= 1
        return "".join(reversed(out))

Time O(max(n, m)) · Space O(max(n, m)). Same skeleton as Add Binary (LC 67) and the Add Two Numbers linked-list problems.

11 LC 67Add Binary Easy Digit arithmetic · base 2

Problem. Add two binary strings and return the sum as a binary string. LeetCode 67 ↗

Clarify: No converting to int? (The educational version does it manually.) No leading zeros except '0'? (Yes.)

Hint 1
Identical to Add Strings, but the carry rolls over at 2, not 10.
Hint 2
Use divmod(total, 2) for the digit and carry.

How to think about it The same right-to-left carry addition as Add Strings, but in base 2: each column's total splits with divmod(total, 2). Continue while either string has bits or a carry remains, then reverse the collected bits.

add_binary.py
class Solution:
    def addBinary(self, a: str, b: str) -> str:
        i, j, carry = len(a) - 1, len(b) - 1, 0
        out = []
        while i >= 0 or j >= 0 or carry:
            total = carry
            if i >= 0:
                total += int(a[i]); i -= 1
            if j >= 0:
                total += int(b[j]); j -= 1
            carry, digit = divmod(total, 2)
            out.append(str(digit))
        return "".join(reversed(out))

Time O(max(n, m)) · Space O(max(n, m)). Manual base-2 addition shows you understand carries beyond decimal.

12 LC 168Excel Sheet Column Title Easy Base-26 encode (1-indexed, no zero)

Problem. Convert a column number (1 → A, 28 → AB) to its Excel column title. LeetCode 168 ↗

Clarify: 1-indexed with no zero digit? (Yes — that's the twist.) Uppercase letters only? (Yes.)

Hint 1
This is base-26, but there's no '0' — 'A' is 1, 'Z' is 26.
Hint 2
Subtract 1 before each mod/div to shift into 0-based digits.

How to think about it It's almost base-26, except the alphabet has no zero. Decrement the number by 1 before taking % 26 (giving 0–25 → 'A'–'Z') and dividing by 26. Build digits from the least significant and reverse.

col_title.py
class Solution:
    def convertToTitle(self, columnNumber: int) -> str:
        out = []
        while columnNumber > 0:
            columnNumber -= 1                 # shift to 0-based before mod
            out.append(chr(ord("A") + columnNumber % 26))
            columnNumber //= 26
        return "".join(reversed(out))

Time O(log n) · Space O(log n). The −1 before each step is what makes the zero-less numbering work.

13 LC 171Excel Sheet Column Number Easy Base-26 decode (Horner's method)

Problem. Convert an Excel column title (A → 1, AB → 28) to its column number. LeetCode 171 ↗

Clarify: Inverse of LC 168? (Yes.) Title is uppercase and valid? (Yes.)

Hint 1
Read left to right; each letter is worth 26× the running total plus its own value.
Hint 2
Letter value is ord(c) − ord('A') + 1.

How to think about it Horner's method in base 26. Sweep left to right, each step multiplying the accumulated number by 26 and adding the current letter's value (1–26). No exponent bookkeeping needed.

col_number.py
class Solution:
    def titleToNumber(self, columnTitle: str) -> int:
        n = 0
        for ch in columnTitle:
            n = n * 26 + (ord(ch) - ord("A") + 1)
        return n

Time O(n) · Space O(1). Same shift-and-add pattern as parsing a binary number (Ch 04, LC 1290).

15 LC 3Longest Substring Without Repeating Characters Medium Sliding window + last-index map

Problem. Return the length of the longest substring with no repeated characters. LeetCode 3 ↗

Clarify: Substring (contiguous), not subsequence? (Yes.) Any characters? (Yes.)

Hint 1
Keep a window with no repeats; when a repeat appears, move the left edge past it.
Hint 2
Store each character's last index to jump the window start in O(1).

How to think about it A sliding window tracked by a last-seen-index map. When the current character was last seen at or after the window start, jump start to just past that position. The window [start, i] stays repeat-free, so its running max is the answer.

longest_unique.py
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}
        start = best = 0
        for i, ch in enumerate(s):
            if ch in last and last[ch] >= start:
                start = last[ch] + 1          # jump past the repeat
            last[ch] = i
            best = max(best, i - start + 1)
        return best

Time O(n) · Space O(min(n, alphabet)). Jumping start (not stepping it) keeps it one pass.

16 LC 424Longest Repeating Character Replacement Medium Sliding window · window − maxfreq ≤ k

Problem. You may replace up to k characters. Return the longest substring of a single repeated letter you can then form. LeetCode 424 ↗

Clarify: Replace with any uppercase letter? (Yes.) k can be 0? (Yes.)

Hint 1
A window is valid if the characters needing replacement (window size − most frequent count) is ≤ k.
Hint 2
Grow the window; when it becomes invalid, shrink from the left.

How to think about it Slide a window keeping a count of letters inside it and the highest single-letter frequency max_freq. The window is achievable if window_size − max_freq ≤ k (the rest can be replaced). When it isn't, advance the left edge. Track the largest valid window.

char_replacement.py
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        left = max_freq = best = 0
        for right, ch in enumerate(s):
            count[ch] = count.get(ch, 0) + 1
            max_freq = max(max_freq, count[ch])
            # shrink if too many chars would need replacing
            while (right - left + 1) - max_freq > k:
                count[s[left]] -= 1
                left += 1
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(1) (≤26 letters). Not recomputing max_freq downward is a valid, standard simplification here.

17 LC 5Longest Palindromic Substring Medium Expand around center

Problem. Return the longest palindromic substring. LeetCode 5 ↗

Clarify: Return the substring, not its length? (Yes.) Ties: any longest is fine? (Yes.)

Hint 1
Every palindrome has a center — a single character (odd length) or a gap between two (even length).
Hint 2
From each of the 2n−1 centers, expand outward while the two sides match.

How to think about it A palindrome mirrors around its center, so try all centers. From each index, expand outward for both the odd case (center on a character) and the even case (center between two characters), keeping the longest span where the ends keep matching.

longest_palindrome.py
class Solution:
    def longestPalindrome(self, s: str) -> str:
        if not s:
            return ""
        start, end = 0, 0
        def expand(l, r):
            while l >= 0 and r < len(s) and s[l] == s[r]:
                l -= 1; r += 1
            return l + 1, r - 1
        for i in range(len(s)):
            l1, r1 = expand(i, i)             # odd-length center
            l2, r2 = expand(i, i + 1)         # even-length center
            if r1 - l1 > end - start:
                start, end = l1, r1
            if r2 - l2 > end - start:
                start, end = l2, r2
        return s[start:end + 1]

Time O(n²) · Space O(1). Handling both odd and even centers is the detail people miss; Manacher's gets O(n) but is rarely needed.

18 LC 647Palindromic Substrings Medium Expand around center · count

Problem. Count how many substrings are palindromes (each occurrence counts). LeetCode 647 ↗

Clarify: Count substrings by position (overlaps included)? (Yes.) Single characters count? (Yes.)

Hint 1
Same center-expansion idea as Longest Palindromic Substring.
Hint 2
Every successful expansion step from a center is one more palindrome — add them all up.

How to think about it Reuse expand-around-center, but instead of tracking the longest, count how many palindromes each center produces. Each time the two sides match while expanding, that's a distinct palindromic substring. Sum over all odd and even centers.

count_palindromes.py
class Solution:
    def countSubstrings(self, s: str) -> int:
        n = len(s)
        def expand(l, r):
            c = 0
            while l >= 0 and r < n and s[l] == s[r]:
                c += 1; l -= 1; r += 1
            return c
        total = 0
        for i in range(n):
            total += expand(i, i)             # odd centers
            total += expand(i, i + 1)         # even centers
        return total

Time O(n²) · Space O(1). The twist over LC 5 is counting expansions rather than keeping the max.

19 LC 680Valid Palindrome II Medium Two pointers · one allowed deletion

Problem. Return whether the string can become a palindrome by deleting at most one character. LeetCode 680 ↗

Clarify: At most one deletion (zero is fine)? (Yes.) Only lowercase letters? (Yes.)

Hint 1
Move two pointers inward while characters match.
Hint 2
At the first mismatch, you must delete one side — check if skipping the left OR the right leaves a palindrome.

How to think about it Two pointers close in while characters match. At the first mismatch you have one deletion to spend, so test both options: is the substring with the left character skipped a palindrome, or the one with the right skipped? If either is, the answer is yes.

valid_palindrome_ii.py
class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_pal(i, j):
            while i < j:
                if s[i] != s[j]:
                    return False
                i += 1; j -= 1
            return True
        l, r = 0, len(s) - 1
        while l < r:
            if s[l] != s[r]:
                # try deleting either the left or the right char
                return is_pal(l + 1, r) or is_pal(l, r - 1)
            l += 1; r -= 1
        return True

Time O(n) · Space O(1). The 'branch on the first mismatch' idea generalises to at-most-k-deletion variants.

21 LC 8String to Integer (atoi) Medium Stateful parsing · sign, digits, clamp

Problem. Implement atoi: skip leading spaces, read an optional sign, then digits, and clamp to the signed 32-bit range. LeetCode 8 ↗

Clarify: Leading whitespace skipped, then optional +/−, then digits until a non-digit? (Yes.) Clamp overflow to [−2³¹, 2³¹−1]? (Yes.)

Hint 1
Process in fixed phases: strip spaces, read a sign, read digits, stop at the first non-digit.
Hint 2
Clamp the final value to the 32-bit range.

How to think about it A small state machine. Strip leading spaces, capture an optional sign, then accumulate digits until a non-digit stops you. Apply the sign and clamp to [−2³¹, 2³¹−1]. The strict phase order is what makes the tricky inputs behave.

atoi.py
class Solution:
    def myAtoi(self, s: str) -> int:
        s = s.lstrip()
        if not s:
            return 0
        sign, i = 1, 0
        if s[0] in "+-":
            sign = -1 if s[0] == "-" else 1
            i = 1
        num = 0
        while i < len(s) and s[i].isdigit():
            num = num * 10 + int(s[i])
            i += 1
        num *= sign
        return max(-2**31, min(2**31 - 1, num))   # clamp to 32-bit range

Time O(n) · Space O(1). It's less an algorithm than careful, ordered parsing — narrate each phase.

22 LC 394Decode String Medium Stack parsing · nested repeats

Problem. Decode a string like 3[a2[c]] where k[...] means the bracketed part repeated k times. LeetCode 394 ↗

Clarify: Brackets can nest? (Yes — that's why a stack is needed.) k is a positive integer, possibly multi-digit? (Yes.)

Hint 1
A '[' opens a new nested context; a ']' closes it and multiplies.
Hint 2
Push the current partial string and repeat-count on a stack when you hit '['.

How to think about it Use a stack to handle nesting. Build the current string and current number as you scan. On '[', push the string-so-far and the number, then reset. On ']', pop them and set current = previous + current × k. Digits accumulate the multiplier; letters append.

decode_string.py
class Solution:
    def decodeString(self, s: str) -> str:
        stack = []
        cur, num = "", 0
        for ch in s:
            if ch.isdigit():
                num = num * 10 + int(ch)
            elif ch == "[":
                stack.append((cur, num))      # save context, start a new group
                cur, num = "", 0
            elif ch == "]":
                prev, k = stack.pop()
                cur = prev + cur * k          # repeat and splice back
            else:
                cur += ch
        return cur

Time O(output length) · Space O(depth). The 'push context on open, resolve on close' pattern solves most nested-parsing problems.

23 LC 71Simplify Path Medium Stack of path components

Problem. Simplify a Unix-style absolute path (handle ., .., and repeated slashes). LeetCode 71 ↗

Hint 1
Split on '/' to get components; ignore empty ones and '.'.
Hint 2
'..' pops the last real directory off a stack; everything else pushes.

How to think about it Split the path on slashes and process each component with a stack. Empty pieces and '.' are ignored, '..' pops the top directory if any, and a real name is pushed. Join the stack with slashes for the canonical path.

simplify_path.py
class Solution:
    def simplifyPath(self, path: str) -> str:
        stack = []
        for part in path.split("/"):
            if part == "" or part == ".":
                continue
            elif part == "..":
                if stack:
                    stack.pop()               # go up one directory
            else:
                stack.append(part)
        return "/" + "/".join(stack)

Time O(n) · Space O(n). A stack is the natural model for 'go up / go down' navigation.

24 LC 443String Compression Medium Read / write pointers · in place

Problem. Compress runs in place: write each character followed by its run length if > 1, and return the new length. LeetCode 443 ↗

Clarify: In place, O(1) extra? (Yes.) Counts > 9 are written as multiple digit chars? (Yes.)

Hint 1
Use a read pointer to measure each run and a write pointer to emit the compressed form.
Hint 2
Write the character, and only write the count when the run length exceeds 1.

How to think about it Two pointers over the same array. The read pointer measures each maximal run of equal characters; the write pointer emits the character and, if the run is longer than 1, the digits of its length. Because the compressed output is never longer, it fits in place.

string_compression.py
from typing import List

class Solution:
    def compress(self, chars: List[str]) -> int:
        write = read = 0
        n = len(chars)
        while read < n:
            ch = chars[read]
            count = 0
            while read < n and chars[read] == ch:
                read += 1; count += 1
            chars[write] = ch; write += 1
            if count > 1:
                for d in str(count):          # write multi-digit counts
                    chars[write] = d; write += 1
        return write

Time O(n) · Space O(1). Writing multi-digit counts one character at a time is the fiddly detail.

25 LC 6Zigzag Conversion Medium Row buckets · bounce direction

Problem. Write the string in a zigzag across numRows rows, then read it off row by row. LeetCode 6 ↗

Clarify: Single row returns the string unchanged? (Yes.) Direction flips at the top and bottom rows? (Yes.)

Hint 1
Simulate the zigzag: append each character to its current row.
Hint 2
Flip the vertical direction whenever you hit the top or bottom row.

How to think about it Keep one string per row. Walk the input appending each character to the current row, moving down until you hit the last row, then up until the first, bouncing at the edges. Concatenate the rows in order for the answer.

zigzag.py
class Solution:
    def convert(self, s: str, numRows: int) -> str:
        if numRows == 1:
            return s
        rows = [""] * numRows
        cur, step = 0, 1
        for ch in s:
            rows[cur] += ch
            if cur == 0:
                step = 1                      # bounce down
            elif cur == numRows - 1:
                step = -1                     # bounce up
            cur += step
        return "".join(rows)

Time O(n) · Space O(n). Simulating the bounce is clearer (and just as fast) as deriving the index formula.

26 LC 12Integer to Roman Medium Greedy · largest symbol first

Problem. Convert an integer (1–3999) to its Roman numeral. LeetCode 12 ↗

Clarify: Include subtractive symbols (CM, XL, IV…)? (Yes.) Range 1–3999? (Yes.)

Hint 1
List value→symbol pairs from largest to smallest, including subtractive ones like 900=CM.
Hint 2
Greedily subtract the biggest value that fits, repeatedly.

How to think about it Greedy. Prepare value/symbol pairs in descending order, including the subtractive forms (900→CM, 400→CD, 90→XC, …). Repeatedly append the largest symbol whose value still fits and subtract it. Because the pairs are ordered, greedy is optimal.

int_to_roman.py
class Solution:
    def intToRoman(self, num: int) -> str:
        vals = [(1000,"M"),(900,"CM"),(500,"D"),(400,"CD"),(100,"C"),
                (90,"XC"),(50,"L"),(40,"XL"),(10,"X"),(9,"IX"),(5,"V"),(4,"IV"),(1,"I")]
        out = []
        for v, sym in vals:
            while num >= v:                   # greedily take the largest symbol
                out.append(sym)
                num -= v
        return "".join(out)

Time O(1) (bounded by 3999) · Space O(1). Including the subtractive pairs in the table is what lets plain greedy work.

27 LC 38Count and Say Medium Run-length encoding · iterate n times

Problem. Generate the n-th term of the count-and-say sequence, where each term describes the previous as 'count digit' runs. LeetCode 38 ↗

Clarify: Build up from '1'? (Yes.) n is small enough to iterate? (Yes.)

Hint 1
Each term is the run-length encoding of the previous term, read aloud.
Hint 2
Group consecutive equal digits and emit 'count' then 'digit'.

How to think about it Start at '1' and apply the say-what-you-see transform n−1 times. Each transform scans the current string, groups maximal runs of the same digit, and appends the run length followed by the digit. The result becomes the input to the next round.

count_and_say.py
class Solution:
    def countAndSay(self, n: int) -> str:
        s = "1"
        for _ in range(n - 1):
            out = []
            i = 0
            while i < len(s):
                j = i
                while j < len(s) and s[j] == s[i]:
                    j += 1
                out.append(str(j - i) + s[i]) # "count" then "digit"
                i = j
            s = "".join(out)
        return s

Time O(n · length) · Space O(length). Pure run-length encoding applied iteratively — no closed form.

28 LC 43Multiply Strings Medium Grid multiplication · positional carries

Problem. Multiply two non-negative integers given as strings, without converting to int. LeetCode 43 ↗

Clarify: No int()/BigInteger? (Yes.) Result has no leading zeros (except '0')? (Yes.)

Hint 1
Digits i and j of the inputs contribute to positions i+j and i+j+1 of the result.
Hint 2
Accumulate all products into a result array, then handle carries.

How to think about it Long multiplication on a digit array of length n+m. The product of digits at positions i and j lands at result positions i+j (carry) and i+j+1 (units). Add each product into place, propagate carries, then strip leading zeros.

multiply_strings.py
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"
        n, m = len(num1), len(num2)
        res = [0] * (n + m)
        for i in range(n - 1, -1, -1):
            for j in range(m - 1, -1, -1):
                mul = int(num1[i]) * int(num2[j])
                p1, p2 = i + j, i + j + 1      # positions in the result
                total = mul + res[p2]
                res[p2] = total % 10
                res[p1] += total // 10
        out = "".join(map(str, res)).lstrip("0")
        return out or "0"

Time O(n·m) · Space O(n+m). The fixed i+j/i+j+1 position mapping is the key insight.

29 LC 227Basic Calculator II Medium Stack · defer + and −, apply × and ÷ now

Problem. Evaluate an expression with non-negative integers and + − × ÷ (no parentheses); integer division truncates toward zero. LeetCode 227 ↗

Clarify: No parentheses? (Yes.) Standard precedence (× ÷ before + −)? (Yes.) Division truncates toward zero? (Yes.)

Hint 1
Push additions/subtractions onto a stack as signed numbers.
Hint 2
For × and ÷, pop the last value and combine immediately (they bind tighter).

How to think about it Scan building each number. When you reach an operator (or the end), act on the previous operator: +/− push the number (signed) for later, while ×/÷ pop the top and combine right away, respecting precedence. The answer is the sum of the stack.

calculator_ii.py
class Solution:
    def calculate(self, s: str) -> int:
        stack = []
        num, op = 0, "+"
        for i, ch in enumerate(s):
            if ch.isdigit():
                num = num * 10 + int(ch)
            if (not ch.isspace() and not ch.isdigit()) or i == len(s) - 1:
                if op == "+":
                    stack.append(num)
                elif op == "-":
                    stack.append(-num)
                elif op == "*":
                    stack.append(stack.pop() * num)
                else:                          # '/', truncate toward zero
                    stack.append(int(stack.pop() / num))
                op, num = ch, 0
        return sum(stack)

Time O(n) · Space O(n). Use int(a / b) (not //) so negative division truncates toward zero as required.

30 LC 165Compare Version Numbers Medium Split on dots · compare as integers

class Solution:

31 LC 179Largest Number Medium Custom comparator · which order concatenates bigger

Problem. Arrange the numbers to form the largest possible number and return it as a string. LeetCode 179 ↗

Clarify: Return a string (result can be huge)? (Yes.) All zeros → '0'? (Yes.)

Hint 1
Sorting numerically fails (e.g. 3 vs 30). Compare by which concatenation is larger.
Hint 2
Order a before b if a+b > b+a as strings.

How to think about it Define a custom order: string a should come before b when a+b is larger than b+a. Sort the numbers-as-strings by that comparator and concatenate. Guard the all-zeros case so the result is '0', not '00…'.

largest_number.py
from typing import List
from functools import cmp_to_key

class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        def cmp(a, b):
            if a + b > b + a:
                return -1
            if a + b < b + a:
                return 1
            return 0
        strs = sorted(map(str, nums), key=cmp_to_key(cmp))
        out = "".join(strs)
        return "0" if out[0] == "0" else out

Time O(n log n · L) · Space O(n). The a+b vs b+a comparator is the entire idea; cmp_to_key adapts it for sorted.

32 LC 767Reorganize String Medium Greedy + heap · place the most frequent first

Problem. Rearrange the string so no two adjacent characters are the same, or return '' if impossible. LeetCode 767 ↗

Clarify: Return any valid arrangement? (Yes.) Impossible when a char count > ⌈n/2⌉? (Yes.)

Hint 1
It's impossible only if some character appears more than ⌈n/2⌉ times.
Hint 2
Always place the currently most frequent character that isn't the one you just placed.

How to think about it Greedy with a max-heap by frequency. Repeatedly take the most frequent available character (never the one placed immediately before — hold it aside for one step), append it, and decrement. Holding the just-used character on cooldown guarantees no two neighbours match. If some count exceeds ⌈n/2⌉, it's impossible.

reorganize_string.py
from collections import Counter
import heapq

class Solution:
    def reorganizeString(self, s: str) -> str:
        n = len(s)
        counts = Counter(s)
        if max(counts.values()) > (n + 1) // 2:
            return ""
        heap = [(-c, ch) for ch, c in counts.items()]
        heapq.heapify(heap)
        out = []
        prev = None                            # the char used last (on cooldown)
        while heap:
            c, ch = heapq.heappop(heap)
            out.append(ch)
            if prev:
                heapq.heappush(heap, prev)     # release the cooled-down char
                prev = None
            c += 1                             # one use spent (c is negative)
            if c < 0:
                prev = (c, ch)
        return "".join(out)

Time O(n log k) · Space O(k). The one-step cooldown (prev) is what enforces the no-adjacent rule.

33 LC 763Partition Labels Medium Greedy · extend to each letter's last index

Problem. Partition the string into as many parts as possible so each letter appears in at most one part. Return the part sizes. LeetCode 763 ↗

Clarify: Each letter confined to one part? (Yes.) Maximise the number of parts? (Yes.)

Hint 1
Record the last index of every character first.
Hint 2
Sweep, extending the current part's end to the farthest last-index seen; cut when you reach it.

How to think about it Precompute each character's last occurrence. Sweep left to right tracking the current part's end as the maximum last-index of any character seen so far. When the scan position reaches that end, every character inside is contained, so close the part and start a new one.

partition_labels.py
from typing import List

class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        last = {ch: i for i, ch in enumerate(s)}
        out = []
        start = end = 0
        for i, ch in enumerate(s):
            end = max(end, last[ch])           # extend to the farthest last-seen
            if i == end:                        # every char in [start,i] ends here
                out.append(end - start + 1)
                start = i + 1
        return out

Time O(n) · Space O(1) (≤26 last-indices). The 'extend end to the farthest reach' idea is a greedy-interval classic.

34 LC 76Minimum Window Substring Hard Sliding window + need counts

Problem. Return the shortest substring of s that contains all characters of t (with multiplicity), or ''. LeetCode 76 ↗

Clarify: Include duplicates of t's characters? (Yes.) No valid window → return ''? (Yes.)

Hint 1
Expand the window to the right until it covers all of t.
Hint 2
Then shrink from the left as far as possible while still covering t, recording the best.

How to think about it A grow-then-shrink sliding window with a need-count map and a missing counter. Extend the right edge, decrementing needs; when missing hits 0 the window is valid, so shrink from the left to find the tightest valid window, tracking the smallest seen.

min_window.py
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not s or not t:
            return ""
        need = Counter(t)
        missing = len(t)
        left = start = 0
        best = float("inf")
        best_start = 0
        for right, ch in enumerate(s):
            if need[ch] > 0:
                missing -= 1
            need[ch] -= 1
            while missing == 0:                # window has everything; shrink it
                if right - left + 1 < best:
                    best = right - left + 1
                    best_start = left
                need[s[left]] += 1
                if need[s[left]] > 0:
                    missing += 1
                left += 1
        return "" if best == float("inf") else s[best_start:best_start + best]

Time O(n + m) · Space O(unique chars in t). Each character enters and leaves the window once, so despite the inner loop it's linear.

35 LC 68Text Justification Hard Greedy line packing · space distribution

Problem. Format words into lines of exactly maxWidth, fully justified (extra spaces spread left-heavy); the last line is left-justified. LeetCode 68 ↗

Clarify: Extra spaces go to the leftmost gaps first? (Yes.) Last line and single-word lines are left-justified? (Yes.)

Hint 1
Greedily pack as many words per line as fit (with one space minimum between).
Hint 2
Distribute the leftover spaces across the gaps, giving the left gaps the extra ones; pad the last line on the right.

How to think about it Greedily fill each line with as many words as fit given one space between them. To justify a full line, spread the remaining spaces across the gaps — divmod(spaces, gaps) gives a base amount per gap plus extras assigned to the leftmost gaps. Single-word lines and the final line are left-justified and right-padded.

text_justification.py
from typing import List

class Solution:
    def fullJustify(self, words: List[str], maxWidth: int) -> List[str]:
        res = []
        line, line_len = [], 0
        for w in words:
            # if adding w would overflow (min one space between words), flush
            if line_len + len(line) + len(w) > maxWidth:
                spaces = maxWidth - line_len
                if len(line) == 1:
                    res.append(line[0] + " " * spaces)
                else:
                    gaps = len(line) - 1
                    base, extra = divmod(spaces, gaps)
                    row = ""
                    for idx, word in enumerate(line):
                        row += word
                        if idx < gaps:
                            row += " " * (base + (1 if idx < extra else 0))
                    res.append(row)
                line, line_len = [], 0
            line.append(w)
            line_len += len(w)
        last = " ".join(line)                  # final line: left-justified
        res.append(last + " " * (maxWidth - len(last)))
        return res

Time O(total characters) · Space O(output). Pure careful bookkeeping — the left-heavy space distribution and last-line special case are where bugs hide.

4 · Interview playbook

  • Remember immutability. To edit in place, convert to a list; to build a result, collect pieces and join once — never += in a loop.
  • Name the pattern out loud: two pointers, expand-around-center, sliding window, stack parsing, character arithmetic, or build/transform.
  • Palindromes have centers. For substring palindrome problems, expand around all 2n−1 centers (odd and even).
  • Windows for "substring with a property": grow right, shrink left when the property breaks; a frequency map tracks the window.
  • Edge cases: empty string, single character, all-same characters, leading/trailing spaces, mixed case, and multi-digit run counts.

6 · Review

Cheat sheet
  • Palindrome check / reverse / compare inward → two pointers from the ends.
  • Longest / count of palindromic substrings → expand around center (odd + even).
  • Longest / shortest / contains substring with a condition → sliding window + frequency map.
  • Nesting, brackets, paths, expressions → stack parsing (push on open, resolve on close).
  • Roman, base conversions, add/multiply as strings → character/digit arithmetic with a carry.
  • Compression, count-and-say, formatting → build with a list + join.
  • Never += in a loop; convert to a list to edit in place.

Concept checks

Why is building a string with result += ch inside a loop O(n²)?
Strings are immutable, so each += copies the entire string built so far into a new one
Because += is slower than append for lists
Because Python re-hashes the string each time
Immutability means += can't extend in place — it allocates a new string and copies all existing characters, so n appends copy 1 + 2 + … + n ≈ O(n²) characters. Collect pieces in a list and join once for O(n).
For "longest palindromic substring", why expand around 2n−1 centers instead of n?
Palindromes can have an even length, whose center falls between two characters — those are the extra n−1 centers
To handle Unicode characters
Because the string might be empty
Odd-length palindromes are centered on a character (n centers); even-length ones are centered between two characters (n−1 centers). Checking both covers every palindrome.

Mastery checklist

  • I know strings are immutable and build results with a list + join.
  • I can reverse and palindrome-check with two pointers.
  • I can find/count palindromic substrings by expanding around centers.
  • I can solve substring problems with a sliding window and a frequency map.
  • I can parse nested/bracketed input with a stack.
  • I use ord/chr and running carries for base conversions and string arithmetic.
