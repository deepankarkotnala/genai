1 · Foundations

New to the two-pointer technique? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is the two-pointer technique?

Many problems look like they need to compare every pair of elements — an O(n²) nested loop. The two-pointer technique keeps two positions in the data and moves them cleverly so each element is visited a constant number of times, collapsing that O(n²) into O(n). The art is knowing which pointer to move and why that move can't skip the answer.

Two pointers work when you can prove that moving a pointer in one direction can only make things better or is safe to discard — so you never need to look back. That proof is the invariant you say out loud.

The three shapes

Almost every two-pointer solution is one of three arrangements:

① Converging (opposite ends)

One pointer at each end, moving toward the middle. Great for sorted-pair search, palindromes, and area problems.

② Same direction (fast/slow)

Both start on the left; one races ahead or writes while the other reads. Powers in-place filtering, sliding windows, and cycle detection.

③ Two sequences

One pointer per input, advanced independently — merging two sorted lists, intersecting intervals, subsequence checks.

The payoff

Each element is touched O(1) times, so the whole scan is O(n) time and usually O(1) extra space.

Converging: why sorted data is the sweet spot

On a sorted array, the sum of the two end elements is a dial: if it's too small, the only way up is to move the left pointer right; if it's too big, move the right pointer left. Each move rules out a whole set of pairs you never have to check.

Example — Two Sum on a sorted array
converge.py
def two_sum_sorted(nums, target):
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:
            return [l, r]
        elif s < target:
            l += 1          # too small -> need a bigger left value
        else:
            r -= 1          # too big -> need a smaller right value
    return []

print(two_sum_sorted([2, 7, 11, 15], 9))   # [0, 1]
Output[0, 1]

Moving a pointer is safe because sortedness makes the sum change predictably — that monotonicity is the invariant. This same dial drives 3Sum, Container With Most Water, and Trapping Rain Water.

Same direction: the slow writer

When you need to rewrite an array in place — drop some elements, compact others — a write pointer trails a read pointer. The read pointer scans everything; the write pointer only advances when it keeps a value. Everything before the write pointer is the finished result.

Example — remove a value in place
same_dir.py
def remove_value(nums, val):
    w = 0                       # write pointer
    for x in nums:              # read pointer (implicit)
        if x != val:
            nums[w] = x         # keep it
            w += 1
    return w                    # new length; nums[:w] is the result

a = [3, 2, 2, 3]
k = remove_value(a, 3)
print(k, a[:k])                 # 2 [2, 2]
No shifting, no extra array — O(n) time, O(1) space. Move Zeroes, Remove Duplicates, and String Compression are all this shape.

Fast & slow: two speeds

A special same-direction setup moves one pointer twice as fast as the other. When the fast pointer reaches the end, the slow one is exactly halfway — that finds a midpoint in one pass. On a cyclic structure the fast pointer eventually laps the slow one, which detects loops. This is the engine behind Linked List Cycle and Middle of the List.

⚠️
Two-pointer pitfalls

State the invariant before moving a pointer — an unjustified move skips answers. Converging search usually needs sorted input (sort first if allowed, and note the O(n log n) cost). After a swap toward the far end (Sort Colors), don't advance the scan pointer — you haven't examined what arrived. And guard fast.next before fast.next.next in fast/slow walks.

1 LC 344Reverse String Easy Converging · swap the ends inward

Problem. Reverse a list of characters in place, O(1) extra space. LeetCode 344 ↗

Clarify: Modify in place? (Yes.) O(1) space? (Yes.)

Hint 1
Swap the first and last, then move inward.
Hint 2
One pointer from each end, meeting in the middle.

How to think about it The simplest two-pointer move. Put l at the start and r at the end, swap what they point to, and step both toward the centre until they meet.

reverse_string.py
from typing import List

class Solution:
    def reverseString(self, s: List[str]) -> None:
        l, r = 0, len(s) - 1
        while l < r:
            s[l], s[r] = s[r], s[l]
            l += 1; r -= 1

Time O(n) · Space O(1). This converging-pointers swap is the template every palindrome/reverse problem reuses.

2 LC 125Valid Palindrome Easy Converging · skip non-alphanumeric

Problem. Return whether the string is a palindrome, considering only alphanumeric characters and ignoring case. LeetCode 125 ↗

Clarify: Ignore punctuation/spaces? (Yes.) Case-insensitive? (Yes.)

Hint 1
Compare from both ends inward.
Hint 2
Skip characters that aren't letters or digits; lowercase before comparing.

How to think about it Two pointers from the ends. Advance each past any non-alphanumeric character, then compare the surviving characters case-insensitively. Any mismatch means it isn't a palindrome — no cleaned copy needed.

valid_palindrome.py
class Solution:
    def isPalindrome(self, s: str) -> bool:
        l, r = 0, len(s) - 1
        while l < r:
            while l < r and not s[l].isalnum():
                l += 1
            while l < r and not s[r].isalnum():
                r -= 1
            if s[l].lower() != s[r].lower():
                return False
            l += 1; r -= 1
        return True

Time O(n) · Space O(1). Filtering inside the loop keeps it O(1) extra.

3 LC 680Valid Palindrome II Easy Converging · one allowed deletion

Problem. Return whether the string can become a palindrome by deleting at most one character. LeetCode 680 ↗

Clarify: At most one deletion (zero is fine)? (Yes.) Lowercase only? (Yes.)

Hint 1
Move inward while characters match.
Hint 2
At the first mismatch, try skipping the left OR the right character and check if the rest is a palindrome.

How to think about it Converge from the ends. At the first mismatch you have one deletion to spend, so check both branches: is the substring with the left character removed a palindrome, or the one with the right removed? Either success means yes.

valid_palindrome_ii.py
class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_pal(i, j):
            while i < j:
                if s[i] != s[j]:
                    return False
                i += 1; j -= 1
            return True
        l, r = 0, len(s) - 1
        while l < r:
            if s[l] != s[r]:
                return is_pal(l + 1, r) or is_pal(l, r - 1)
            l += 1; r -= 1
        return True

Time O(n) · Space O(1). Branching on the first mismatch is the whole idea.

4 LC 977Squares of a Sorted Array Easy Converging · biggest square is at an end

Problem. Given a sorted array (possibly with negatives), return the sorted squares. LeetCode 977 ↗

Clarify: Negatives possible? (Yes — the trick.) Output sorted, O(n)? (Yes.)

Hint 1
After squaring, the largest values come from the two ends.
Hint 2
Compare the ends, take the bigger square, and fill the output from the back.

How to think about it Squaring makes big negatives large again, so the maxima sit at the ends. Two pointers at both ends fill the answer back-to-front, each step taking the larger end-square and moving that pointer inward.

sorted_squares.py
from typing import List

class Solution:
    def sortedSquares(self, nums: List[int]) -> List[int]:
        n = len(nums)
        out = [0] * n
        l, r = 0, n - 1
        for pos in range(n - 1, -1, -1):        # fill from the largest square down
            if abs(nums[l]) > abs(nums[r]):
                out[pos] = nums[l] * nums[l]; l += 1
            else:
                out[pos] = nums[r] * nums[r]; r -= 1
        return out

Time O(n) · Space O(n) output. Beats sorting the squares (O(n log n)).

5 LC 88Merge Sorted Array Easy Two sequences · fill from the back

Problem. Merge two sorted arrays into the first, which has trailing space. In place. LeetCode 88 ↗

Clarify: nums1 sized m+n with padding? (Yes.) Merge in place? (Yes.)

Hint 1
Merging from the front overwrites unread values.
Hint 2
Write from the back: the largest remaining element goes into the last slot.

How to think about it Three pointers writing backward: tails of the two real regions and the write cursor at the very end. Copy the larger tail into the cursor each step. Writing back-to-front means you never clobber a value you still need.

merge_sorted.py
from typing import List

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i, j, k = m - 1, n - 1, m + n - 1
        while j >= 0:
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[k] = nums1[i]; i -= 1
            else:
                nums1[k] = nums2[j]; j -= 1
            k -= 1

Time O(m + n) · Space O(1). Looping while j >= 0 is enough — once nums2 is placed, nums1's rest is already sorted.

6 LC 26Remove Duplicates from Sorted Array Easy Same-direction · slow writer, fast reader

Problem. Remove duplicates in place from a sorted array so each value appears once; return the new length. LeetCode 26 ↗

Clarify: Sorted input (so dups are adjacent)? (Yes.) In place? (Yes.)

Hint 1
A write pointer marks where the next unique value goes.
Hint 2
Copy a value only when it differs from the last kept one.

How to think about it A slow write pointer k and a fast read scan. Whenever the read value differs from the last kept value (nums[k-1]), write it at k and advance. Everything before k stays unique and sorted.

remove_dups.py
from typing import List

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if not nums:
            return 0
        k = 1
        for i in range(1, len(nums)):
            if nums[i] != nums[k - 1]:
                nums[k] = nums[i]; k += 1
        return k

Time O(n) · Space O(1). Compare against the last kept value, not the previous index.

7 LC 27Remove Element Easy Same-direction · overwrite the keepers

Problem. Remove all occurrences of val in place; return the count of remaining elements. LeetCode 27 ↗

Clarify: Order of survivors matters? (No.) Beyond k is anything? (Yes.)

Hint 1
Don't delete (which shifts) — overwrite the values you keep to the front.
Hint 2
A single write pointer collects the survivors.

How to think about it An in-place filter. A write pointer k collects every value that isn't val at the front. k ends as the new length.

remove_element.py
from typing import List

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        k = 0
        for x in nums:
            if x != val:
                nums[k] = x; k += 1
        return k

Time O(n) · Space O(1). The base 'compact by overwriting' move behind Move Zeroes and Remove Duplicates.

8 LC 283Move Zeroes Easy Same-direction · swap non-zeros forward

Problem. Move all zeros to the end while keeping the order of non-zeros. In place. LeetCode 283 ↗

Clarify: Keep the order of non-zeros? (Yes.) In place? (Yes.)

Hint 1
Pull each non-zero to the front, in order; zeros fall to the back.
Hint 2
A write pointer marks the next non-zero slot; swap into it.

How to think about it A write pointer k marks the packed front region. Each non-zero swaps into nums[k] and advances it; zeros accumulate at the tail automatically. Swapping (not overwriting) preserves order in one pass.

move_zeroes.py
from typing import List

class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        k = 0
        for i in range(len(nums)):
            if nums[i] != 0:
                nums[k], nums[i] = nums[i], nums[k]
                k += 1

Time O(n) · Space O(1). Same slow/fast skeleton as Remove Element.

9 LC 905Sort Array By Parity Easy Partitioning · evens left, odds right

Problem. Reorder so every even number comes before every odd number (any order within each group). LeetCode 905 ↗

Clarify: Order within groups free? (Yes.) In place? (Reuse the array.)

Hint 1
Two pointers from the ends, swapping a misplaced odd on the left with a misplaced even on the right.
Hint 2
Advance a pointer whenever it already sits on the correct parity.

How to think about it A converging partition. The left pointer skips evens (already correct), the right skips odds; when both point at misplaced elements, swap them. They meet with evens on the left and odds on the right.

sort_by_parity.py
from typing import List

class Solution:
    def sortArrayByParity(self, nums: List[int]) -> List[int]:
        l, r = 0, len(nums) - 1
        while l < r:
            if nums[l] % 2 == 0:
                l += 1                          # already on the correct (even) side
            elif nums[r] % 2 == 1:
                r -= 1                          # already on the correct (odd) side
            else:
                nums[l], nums[r] = nums[r], nums[l]
                l += 1; r -= 1
        return nums

Time O(n) · Space O(1). The same two-way partition idea generalises to Sort Colors.

10 LC 917Reverse Only Letters Easy Converging · swap only letters

Problem. Reverse only the English letters, leaving all other characters in place. LeetCode 917 ↗

Clarify: Non-letters stay put? (Yes.) Both cases are letters? (Yes.)

Hint 1
Two pointers; skip any non-letter.
Hint 2
Swap only when both pointers rest on letters.

How to think about it Converge from the ends. Advance a pointer past any non-letter; when both sit on letters, swap and step inward. Non-letters never move.

reverse_only_letters.py
class Solution:
    def reverseOnlyLetters(self, s: str) -> str:
        chars = list(s)
        l, r = 0, len(chars) - 1
        while l < r:
            if not chars[l].isalpha():
                l += 1
            elif not chars[r].isalpha():
                r -= 1
            else:
                chars[l], chars[r] = chars[r], chars[l]
                l += 1; r -= 1
        return "".join(chars)

Time O(n) · Space O(n) for the char list. 'Skip non-targets, swap targets' — same shape as Reverse Vowels.

11 LC 345Reverse Vowels of a String Easy Converging · swap only vowels

Problem. Reverse only the vowels in the string, leaving other characters in place. LeetCode 345 ↗

Clarify: Both cases count as vowels? (Yes.) 'y' is a vowel? (No.)

Hint 1
Two pointers; advance past non-vowels.
Hint 2
Swap when both pointers land on vowels.

How to think about it Identical machinery to Reverse Only Letters, but the target set is the vowels. Skip non-vowels; swap when both pointers rest on vowels.

reverse_vowels.py
class Solution:
    def reverseVowels(self, s: str) -> str:
        vowels = set("aeiouAEIOU")
        chars = list(s)
        l, r = 0, len(chars) - 1
        while l < r:
            if chars[l] not in vowels:
                l += 1
            elif chars[r] not in vowels:
                r -= 1
            else:
                chars[l], chars[r] = chars[r], chars[l]
                l += 1; r -= 1
        return "".join(chars)

Time O(n) · Space O(n). The target-set generalisation of the reverse move.

12 LC 392Is Subsequence Easy Two sequences · advance on match

Problem. Return whether s is a subsequence of t (same order, gaps allowed). LeetCode 392 ↗

Clarify: Subsequence keeps order but allows skips? (Yes.) Empty s is a subsequence? (Yes.)

Hint 1
Walk t; each time its character matches the next needed character of s, advance in s.
Hint 2
s is a subsequence iff you consume all of it.

How to think about it Two pointers over the two strings, but only one advances on the driver. Sweep t; whenever the current character equals the next unmatched character of s, move forward in s. You succeed if the whole of s is consumed.

is_subsequence.py
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0
        for ch in t:
            if i < len(s) and s[i] == ch:
                i += 1                          # matched one char of s
        return i == len(s)

Time O(|t|) · Space O(1). For many queries against the same t, preprocess t into per-character index lists and binary-search.

13 LC 141Linked List Cycle Easy Fast / slow · detect a loop
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Return whether a linked list contains a cycle. LeetCode 141 ↗

Clarify: O(1) space (vs a visited set)? (Yes — fast/slow.)

Hint 1
Two pointers at different speeds.
Hint 2
If there's a loop, the fast one laps and meets the slow one; otherwise it runs off the end.

How to think about it The fast/slow shape on a linked list. Slow moves one node, fast moves two. In a cycle the fast pointer keeps closing the gap by one each step until they collide (compared with is); with no cycle, fast reaches the end.

has_cycle.py
from typing import Optional

class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                return True
        return False

Time O(n) · Space O(1). Guard fast.next before fast.next.next.

14 LC 876Middle of the Linked List Easy Fast / slow · two-speed walk to the middle
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Return the middle node; for two middles, return the second. LeetCode 876 ↗

Clarify: Second middle for even length? (Yes.) One pass? (Yes.)

Hint 1
Move one pointer twice as fast as the other.
Hint 2
When the fast one reaches the end, the slow one is at the middle.

How to think about it Fast/slow again: by the time fast falls off the end, slow has travelled exactly half, landing on the middle. The loop guard makes it the second middle for even lengths.

middle_node.py
from typing import Optional

class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        return slow

Time O(n) · Space O(1). The midpoint step underlies Reorder List and Palindrome Linked List.

15 LC 234Palindrome Linked List Easy Fast / slow + reverse + compare
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Return whether a linked list reads the same forwards and backwards. LeetCode 234 ↗

Clarify: O(1) space? (Yes.) May mutate then restore? (Yes.)

Hint 1
Find the middle with fast/slow.
Hint 2
Reverse the second half, then compare it against the first half node by node.

How to think about it Compose three two-pointer moves: fast/slow to the midpoint, the reversal move on the second half, then a lock-step comparison of the first half and reversed second half.

ll_palindrome.py
from typing import Optional

class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:               # slow ends at the middle
            slow = slow.next
            fast = fast.next.next
        prev = None                             # reverse the second half
        while slow:
            nxt = slow.next
            slow.next = prev
            prev = slow
            slow = nxt
        left, right = head, prev                # compare the two halves
        while right:
            if left.val != right.val:
                return False
            left = left.next
            right = right.next
        return True

Time O(n) · Space O(1). Comparing only while the reversed half exists ignores the odd middle node.

16 LC 167Two Sum II - Input Array Is Sorted Medium Converging on sorted data

Problem. Given a 1-indexed sorted array, return the indices of the two numbers that add to target. LeetCode 167 ↗

Clarify: Sorted input? (Yes — that enables two pointers.) Exactly one answer? (Yes.) 1-indexed output? (Yes.)

Hint 1
Start at both ends; the sum is a dial you can turn.
Hint 2
Sum too small → move left in; too big → move right in.

How to think about it The canonical converging search on sorted data. The end-pair gives some sum; if it's too small, only a larger left value can help, so move l right; if too big, move r left. Because the array is sorted, each move changes the sum monotonically, so you never miss the pair.

two_sum_ii.py
from typing import List

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        l, r = 0, len(numbers) - 1
        while l < r:
            s = numbers[l] + numbers[r]
            if s == target:
                return [l + 1, r + 1]           # 1-indexed
            elif s < target:
                l += 1                          # need a bigger sum
            else:
                r -= 1                          # need a smaller sum
        return []

Time O(n) · Space O(1). Sortedness is what turns the O(n²) hash-free search into O(n) — say why the pointer moves are safe.

17 LC 11Container With Most Water Medium Converging · move the shorter wall

Problem. Given wall heights, choose two walls holding the most water. Return that area. LeetCode 11 ↗

Clarify: Area = min(height) × width? (Yes.) Equal heights allowed? (Yes.)

Hint 1
Start with the widest pair (both ends).
Hint 2
The shorter wall caps the area, so moving the taller one only loses width — move the shorter.

How to think about it Start wide and narrow greedily. Water is bounded by the shorter wall, so advancing the taller pointer can't help; only moving the shorter one could find a taller bound. Track the best area as the pointers converge.

max_area.py
from typing import List

class Solution:
    def maxArea(self, height: List[int]) -> int:
        l, r = 0, len(height) - 1
        best = 0
        while l < r:
            best = max(best, min(height[l], height[r]) * (r - l))
            if height[l] < height[r]:           # move the shorter wall inward
                l += 1
            else:
                r -= 1
        return best

Time O(n) · Space O(1), vs O(n²) brute force. Justify 'move the shorter wall' out loud — it's the crux.

18 LC 153Sum Medium Sort + converging inner search

Problem. Return all unique triplets that sum to zero. LeetCode 15 ↗

Clarify: Unique triplets? (Yes.) Reuse an index? (No.) Order free? (Yes.)

Hint 1
Sort so you can use two pointers and skip duplicates easily.
Hint 2
Fix one number, then two-pointer the rest for the negation; skip equal values.

How to think about it Sort, then fix each element and run a converging two-pointer search in the remaining tail for a pair summing to its negation. Skip repeated values at all three levels so each triplet appears once; break early once the fixed value goes positive.

three_sum.py
from typing import List

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res, n = [], len(nums)
        for i in range(n - 2):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            if nums[i] > 0:
                break
            l, r = i + 1, n - 1
            while l < r:
                s = nums[i] + nums[l] + nums[r]
                if s < 0:
                    l += 1
                elif s > 0:
                    r -= 1
                else:
                    res.append([nums[i], nums[l], nums[r]])
                    l += 1; r -= 1
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1
                    while l < r and nums[r] == nums[r + 1]:
                        r -= 1
        return res

Time O(n²) · Space O(1) beyond output. The duplicate-skipping (three places) makes it unique without a set.

19 LC 163Sum Closest Medium Sort + converging · track closest sum

Problem. Return the sum of the three integers closest to target. LeetCode 16 ↗

Clarify: Exactly one closest sum? (Yes.) Any triple (indices distinct)? (Yes.)

Hint 1
Same fix-one-then-two-pointer structure as 3Sum.
Hint 2
Track the sum with the smallest distance to target as you go.

How to think about it Sort, fix each element, and converge the remaining pair. At every step compare the current triple sum's distance to target against the best seen and keep the closer. Move the pointers by whether the sum is below or above target.

three_sum_closest.py
from typing import List

class Solution:
    def threeSumClosest(self, nums: List[int], target: int) -> int:
        nums.sort()
        n = len(nums)
        best = nums[0] + nums[1] + nums[2]
        for i in range(n - 2):
            l, r = i + 1, n - 1
            while l < r:
                s = nums[i] + nums[l] + nums[r]
                if abs(s - target) < abs(best - target):
                    best = s
                if s < target:
                    l += 1
                elif s > target:
                    r -= 1
                else:
                    return s
        return best

Time O(n²) · Space O(1). An exact match lets you return immediately.

20 LC 184Sum Medium Sort + two fixed + converging pair

Problem. Return all unique quadruples summing to target. LeetCode 18 ↗

Clarify: Unique quadruples? (Yes.) Target arbitrary (may be negative)? (Yes.)

Hint 1
Extend 3Sum: fix two indices with nested loops, two-pointer the rest.
Hint 2
Skip duplicates at every level.

How to think about it Generalise 3Sum by one level. Sort, fix i and j with two loops, and converge a two-pointer pair for the remaining amount. Duplicate-skipping at each of the four positions keeps the results unique.

four_sum.py
from typing import List

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        res = []
        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue
                l, r = j + 1, n - 1
                while l < r:
                    s = nums[i] + nums[j] + nums[l] + nums[r]
                    if s < target:
                        l += 1
                    elif s > target:
                        r -= 1
                    else:
                        res.append([nums[i], nums[j], nums[l], nums[r]])
                        l += 1; r -= 1
                        while l < r and nums[l] == nums[l - 1]:
                            l += 1
                        while l < r and nums[r] == nums[r + 1]:
                            r -= 1
        return res

Time O(n³) · Space O(1) beyond output. The k-Sum recursion generalises this to any k.

21 LC 2593Sum Smaller Medium Sort + converging · count in bulk

Problem. Count triples with i<j<k whose sum is strictly less than target. LeetCode 259 ↗

Clarify: Count triples, not list them? (Count.) Strictly less than target? (Yes.)

Hint 1
Sort, fix one, two-pointer the rest.
Hint 2
If the smallest+largest of a pair is under target, so are all pairs between them — add them at once.

How to think about it Sort and fix the smallest element. For the converging pair, if nums[i]+nums[l]+nums[r] < target, then pairing l with everything from l+1 to r also works, so add r − l and advance l; otherwise shrink r. Counting in bulk is what keeps it O(n²).

three_sum_smaller.py
from typing import List

class Solution:
    def threeSumSmaller(self, nums: List[int], target: int) -> int:
        nums.sort()
        n = len(nums)
        count = 0
        for i in range(n - 2):

                    l += 1
                else:
                    r -= 1
        return count

Time O(n²) · Space O(1). The 'count r − l at once' trick avoids an inner loop.

22 LC 75Sort Colors Medium Partitioning · Dutch national flag

Problem. Sort an array of 0s, 1s, and 2s in place in a single pass. LeetCode 75 ↗

Clarify: Only 0/1/2? (Yes.) One pass, O(1) space? (Yes.)

Hint 1
Three regions: 0s at the front, 2s at the back, 1s in the middle.
Hint 2
Pointers low/mid/high: send 0s down, 2s up, leave 1s.

How to think about it Three-way partition. low bounds the 0-region, high the 2-region, mid scans. A 0 swaps down to low; a 2 swaps up to high (don't advance mid — the swapped-in value is unexamined); a 1 just advances mid.

sort_colors.py
from typing import List

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        low, mid, high = 0, 0, len(nums) - 1
        while mid <= high:
            if nums[mid] == 0:
                nums[low], nums[mid] = nums[mid], nums[low]
                low += 1; mid += 1
            elif nums[mid] == 1:
                mid += 1
            else:
                nums[mid], nums[high] = nums[high], nums[mid]
                high -= 1

Time O(n) · Space O(1). Not advancing mid after a high-swap is the classic gotcha.

23 LC 80Remove Duplicates from Sorted Array II Medium Same-direction · allow two of each

Problem. Remove duplicates in place so each value appears at most twice; return the new length. LeetCode 80 ↗

Clarify: Keep up to two copies? (Yes.) Sorted input? (Yes.)

Hint 1
A write pointer builds the result; keep a value only if it wouldn't be a third copy.
Hint 2
Compare the incoming value with the one two slots back in the output.

How to think about it Slow/fast write with a 'look back two' rule: write x if fewer than two are written yet, or if x differs from nums[k-2] (so at most two equal values survive). Elegant because the output itself records the count.

remove_dups_ii.py
from typing import List

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        k = 0
        for x in nums:
            if k < 2 or x != nums[k - 2]:       # keep at most two of each value
                nums[k] = x
                k += 1
        return k

Time O(n) · Space O(1). Generalises to 'keep at most m' by comparing with nums[k-m].

24 LC 881Boats to Save People Medium Sort + converging greedy

Problem. Each boat carries at most two people within a weight limit. Return the minimum number of boats. LeetCode 881 ↗

Clarify: At most two per boat? (Yes.) Sort allowed? (Yes.)

Hint 1
Sort, then pair the lightest with the heaviest when they fit.
Hint 2
The heaviest person always leaves on this boat; the lightest joins only if there's room.

How to think about it Greedy converging pointers on a sorted array. The heaviest remaining person takes a boat; if the lightest also fits under the limit, they ride along (advance l). Either way the heaviest leaves (decrement r) and the boat count rises.

rescue_boats.py
from typing import List

class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        people.sort()
        l, r = 0, len(people) - 1
        boats = 0
        while l <= r:
            if people[l] + people[r] <= limit:  # lightest + heaviest share a boat
                l += 1
            r -= 1                              # heaviest always leaves
            boats += 1
        return boats

Time O(n log n) · Space O(1). The exchange argument (pairing extremes) is why greedy is optimal.

25 LC 633Sum of Square Numbers Medium Converging on a value range

Problem. Return whether c = a² + b² for some non-negative integers a, b. LeetCode 633 ↗

Clarify: Non-negative a, b? (Yes.) a and b can be equal? (Yes.)

Hint 1
The candidates for a and b lie between 0 and √c.
Hint 2
Two pointers on that range: sum too small → raise the low; too big → lower the high.

How to think about it Treat 0 and ⌊√c⌋ as the two pointers over candidate values. Their squares' sum is a dial: below c raise the low pointer, above c lower the high one, equal means success. It's Two Sum on a numeric range rather than an array.

square_sum.py
import math

class Solution:
    def judgeSquareSum(self, c: int) -> bool:
        l, r = 0, math.isqrt(c)
        while l <= r:
            s = l * l + r * r
            if s == c:
                return True
            elif s < c:
                l += 1
            else:
                r -= 1
        return False

Time O(√c) · Space O(1). Two pointers don't need an array — a sorted range is enough.

26 LC 611Valid Triangle Number Medium Sort + converging · fix the longest side

Problem. Count triples that can form a triangle (each pair's sum exceeds the third side). LeetCode 611 ↗

Hint 1

Hint 2

How to think about it Sort so only the two-smaller-sides-sum condition matters. Fix the largest side at index k and converge a pair below it: when nums[l]+nums[r] > nums[k], every index from l to r−1 also pairs with r, so add r − l and shrink r; else advance l.

triangle_number.py
from typing import List

class Solution:

27 LC 986Interval List Intersections Medium Two sequences · merge-style sweep

Problem. Given two lists of sorted, disjoint intervals, return their intersections. LeetCode 986 ↗

Clarify: Both lists sorted and disjoint? (Yes.) Touching intervals intersect at a point? (Yes.)

Hint 1
Walk both lists with a pointer each, like merging.
Hint 2
The overlap of the two current intervals is [max(starts), min(ends)]; advance whichever ends first.

How to think about it A two-sequence sweep. For the current interval from each list, their intersection is [max(starts), min(ends)] — record it if valid. Then advance the pointer whose interval ends first, since it can't intersect anything later.

interval_intersection.py
from typing import List

class Solution:
    def intervalIntersection(self, firstList: List[List[int]], secondList: List[List[int]]) -> List[List[int]]:
        i = j = 0
        res = []
        while i < len(firstList) and j < len(secondList):
            lo = max(firstList[i][0], secondList[j][0])
            hi = min(firstList[i][1], secondList[j][1])
            if lo <= hi:
                res.append([lo, hi])
            if firstList[i][1] < secondList[j][1]:   # advance the one that ends first
                i += 1
            else:
                j += 1
        return res

Time O(n + m) · Space O(output). Advancing 'whoever ends first' is the merge-pointer heartbeat.

28 LC 19Remove Nth Node From End of List Medium Fixed-gap pointers on a list
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Remove the n-th node from the end of a linked list, in one pass. LeetCode 19 ↗

Clarify: n valid? (Yes.) One pass? (Yes.) Head may be removed? (Use a dummy.)

Hint 1
Put a gap of n between two pointers.
Hint 2
When the front pointer reaches the end, the back pointer sits just before the target.

How to think about it Two pointers with a fixed gap. Advance fast n nodes ahead of slow (both from a dummy), then move them together until fast is last; slow now precedes the node to unlink.

remove_nth.py
from typing import Optional

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        fast = slow = dummy
        for _ in range(n):                      # open a gap of n
            fast = fast.next
        while fast.next:
            fast = fast.next
            slow = slow.next
        slow.next = slow.next.next
        return dummy.next

Time O(n) · Space O(1). Starting both at the dummy fixes the off-by-one when the head is removed.

29 LC 142Linked List Cycle II Medium Fast / slow · find the cycle entrance
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Return the node where the cycle begins, or None. LeetCode 142 ↗

Clarify: Return the entry node? (Yes.) O(1) space? (Yes.)

Hint 1
Find a meeting point with fast/slow first.
Hint 2
The distance from head to entry equals the distance from the meeting point to entry — walk both one step.

How to think about it After the tortoise and hare meet, modular arithmetic shows the head and the meeting point are equidistant (mod loop length) from the entry. Restart one pointer at the head and step both one node at a time; they collide at the cycle's start.

detect_cycle.py
from typing import Optional

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                p = head
                while p is not slow:
                    p = p.next
                    slow = slow.next
                return p
        return None

Time O(n) · Space O(1). Only one pointer restarts at the head — the classic slip.

30 LC 143Reorder List Medium Fast/slow + reverse + weave
🔗
Also covered in Chapter 03 — Linked Lists; shown here through the two-pointer lens with a full solution.

Problem. Reorder L0→L1→…→Ln into L0→Ln→L1→Ln-1→… in place. LeetCode 143 ↗

Clarify: In place, O(1) space? (Yes.) Modify nodes? (Yes.)

Hint 1
Three moves: find the middle, reverse the second half, interleave.
Hint 2
Cut the first half with slow.next = None before reversing.

How to think about it Compose the two-pointer primitives: fast/slow to split at the midpoint, the reversal move on the second half, then a weave that alternates nodes from each half.

reorder_list.py
from typing import Optional

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        if not head or not head.next:
            return
        slow = fast = head
        while fast.next and fast.next.next:     # find the midpoint
            slow = slow.next
            fast = fast.next.next
        second = slow.next
        slow.next = None
        prev = None                             # reverse the second half
        while second:
            nxt = second.next
            second.next = prev
            prev = second
            second = nxt
        first, second = head, prev              # weave the two halves
        while second:
            f_next, s_next = first.next, second.next
            first.next = second
            second.next = f_next
            first, second = f_next, s_next

Time O(n) · Space O(1). Cutting the first half prevents an accidental cycle during the weave.

31 LC 209Minimum Size Subarray Sum Medium Sliding window · grow then shrink

Problem. Given positive numbers and a target, return the shortest subarray length with sum ≥ target (or 0). LeetCode 209 ↗

Clarify: All values positive? (Yes — enables the window.) Shortest length? (Yes.)

Hint 1
Grow a window on the right until the sum reaches target.
Hint 2
Then shrink from the left while still ≥ target, recording the length.

How to think about it A same-direction sliding window (both pointers move right). Extend the right edge accumulating the sum; whenever it reaches target, record the window length and shrink from the left to find the tightest valid window. Positivity guarantees monotonic behaviour.

min_subarray_len.py
from typing import List

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = running = 0
        best = float("inf")
        for right, x in enumerate(nums):
            running += x
            while running >= target:            # shrink while still valid
                best = min(best, right - left + 1)
                running -= nums[left]
                left += 1
        return 0 if best == float("inf") else best

Time O(n) (each index enters/leaves once) · Space O(1). With negatives you'd need prefix sums instead.

32 LC 3Longest Substring Without Repeating Characters Medium Sliding window · jump the left edge

Problem. Return the length of the longest substring without repeating characters. LeetCode 3 ↗

Clarify: Contiguous substring? (Yes.) Any characters? (Yes.)

Hint 1
Keep a window with no repeats; on a repeat, move the left edge past the previous occurrence.
Hint 2
Store each character's last index to jump in O(1).

How to think about it A sliding window with a last-seen-index map. When the current character was seen at or after the window start, jump start just past it. The window stays repeat-free, so track its max length.

longest_unique.py
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}
        start = best = 0
        for i, ch in enumerate(s):
            if ch in last and last[ch] >= start:
                start = last[ch] + 1
            last[ch] = i
            best = max(best, i - start + 1)
        return best

Time O(n) · Space O(min(n, alphabet)). Jumping (not stepping) the left edge keeps it one pass.

33 LC 42Trapping Rain Water Hard Converging · advance the lower side

Problem. Given bar heights, compute how much rain water is trapped. LeetCode 42 ↗

Clarify: Water over bar i is min(maxLeft, maxRight) − height[i]? (Yes.) O(1) space? (Yes, with two pointers.)

Hint 1
Water over a bar depends on the tallest bars to its left and right.
Hint 2
With two pointers, the smaller running max is the binding constraint — process that side and move inward.

How to think about it Two pointers carrying the running max on each side. Whichever side has the smaller max is the limiting wall, so that bar's trapped water is fully determined — add sideMax − height and advance that pointer. This reaches O(1) space versus the O(n) prefix-max arrays.

trap.py
from typing import List

class Solution:
    def trap(self, height: List[int]) -> int:
        if not height:
            return 0
        l, r = 0, len(height) - 1
        left_max, right_max = height[l], height[r]
        water = 0
        while l < r:
            if left_max < right_max:            # the lower wall bounds the water
                l += 1
                left_max = max(left_max, height[l])
                water += left_max - height[l]
            else:
                r -= 1
                right_max = max(right_max, height[r])
                water += right_max - height[r]
        return water

Time O(n) · Space O(1). Present the clearer O(n)-space prefix-max version first, then optimise to two pointers.

34 LC 76Minimum Window Substring Hard Sliding window + need counts

Problem. Return the shortest substring of s containing all characters of t (with multiplicity), or ''. LeetCode 76 ↗

Clarify: Include duplicate requirements from t? (Yes.) No valid window → ''? (Yes.)

Hint 1
Expand right until the window covers all of t.
Hint 2
Then shrink from the left while it still covers t, tracking the smallest.

How to think about it A grow-then-shrink window with a need-count map and a missing counter. Extend the right edge decrementing needs; when missing hits 0 the window is valid, so shrink from the left to the tightest valid window, recording the best.

min_window.py
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not s or not t:
            return ""
        need = Counter(t)
        missing = len(t)
        left = best_start = 0
        best = float("inf")
        for right, ch in enumerate(s):
            if need[ch] > 0:
                missing -= 1
            need[ch] -= 1
            while missing == 0:                 # window covers t; shrink it
                if right - left + 1 < best:
                    best = right - left + 1
                    best_start = left
                need[s[left]] += 1
                if need[s[left]] > 0:
                    missing += 1
                left += 1
        return "" if best == float("inf") else s[best_start:best_start + best]

Time O(n + m) · Space O(unique chars in t). Each character enters and leaves the window once, so it's linear despite the inner loop.

4 · Interview playbook

  • Justify every pointer move. Name the invariant ("the sum only grows if I move left", "the shorter wall bounds the area") — an unproven move skips answers.
  • Sorted? Converging search usually needs sorted input; sort first if allowed and state the O(n log n) cost.
  • Pick the shape: converging, sorted k-sum, same-direction read/write, fast/slow, partition, or two-sequence.
  • In-place compaction: a write pointer that advances only on keepers avoids shifting and stays O(1) space.
  • Edge cases: empty, one/two elements, all-equal, duplicates (skip them in k-sum), and pointer crossings (l < r vs l <= r).

5 · Role notes

SDE / Python backend

Two pointers are the go-to for turning quadratic scans linear. Be fluent in the converging sorted-pair search, in-place compaction, and fast/slow on linked structures.

Data Science / ML / AI / GenAI

6 · Review

Cheat sheet
  • Sorted pair for a target / area between ends → converging pointers.
  • Triples/quads summing to a value → sort + fix outer + converge inner (skip duplicates).
  • Compact / filter / dedup in place → slow write pointer, fast read.
  • Midpoint / cycle / nth-from-end → fast & slow (2× speed or fixed gap).
  • Group by parity / 0-1-2 → partition with swaps across a boundary.
  • Merge / intersect / subsequence → two sequences, advance the one that lags.
  • Longest/shortest substring with a rule → sliding window (grow right, shrink left).

Concept checks

In Container With Most Water, why is it safe to always move the pointer at the shorter wall?
The area is capped by the shorter wall, so moving the taller one only reduces width and can't increase area — only moving the shorter one could help
Because the array is sorted
Because the taller wall is always on the right
Area = min(heights) × width. Moving the taller wall keeps the same (or smaller) limiting height while shrinking width, so it can never beat the current area. Only advancing the shorter wall gives a chance at a taller bound — that invariant makes discarding it safe.
In Sort Colors (Dutch flag), why don't you advance mid after swapping a 2 to the high end?
The value swapped in from the high end hasn't been examined yet — it could be a 0, 1, or 2
Because mid and high must always be equal
To make the algorithm O(n²)
Swapping with high brings an unknown value to mid. You must inspect it on the next iteration, so mid stays put. Swapping with low is different — that value was already scanned, so mid advances.
