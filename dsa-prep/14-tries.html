Tries

A trie (prefix tree) stores strings by their shared prefixes, so lookups cost O(word length) no matter how many words you've stored — and it answers a question a hash set can't: "is there any word starting with this prefix?" 1 · Foundations

New to tries? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is a trie?

A trie (say "try", from retrieval), or prefix tree, stores strings as paths of characters from a common root. Words that share a prefix share the same path until they diverge — so "app", "apple", and "apply" all reuse the "app" path. Insert and lookup cost O(length of the word), completely independent of how many words are stored.

Example — a minimal trie with nested dicts
trie.py
root = {}

def insert(word):
    node = root
    for ch in word:
        node = node.setdefault(ch, {})   # walk/create the child
    node["$"] = True                     # mark the end of a word

def contains(word):
    node = root
    for ch in word:
        if ch not in node:
            return False
        node = node[ch]
    return "$" in node                   # a word ends exactly here

insert("app"); insert("apple")
print(contains("app"), contains("appl"))   # True False
OutputTrue False
Each trie node is just "a map from a character to a child node". The end marker ("$" here) is essential — without it you can't tell "apple is a word" from "app is just a prefix of apple".

Why not just use a hash set?

A hash set answers "is this exact word present?" in O(1) — often better than a trie. The trie earns its place with prefix queries: "does any stored word start with app?" or "how many words share this prefix?" A hash set would have to scan every key; a trie walks len(prefix) characters and stops. Autocomplete, spell-check, and dictionary matching all live on this ability.

Example — the prefix query a hash set can't do cheaply
prefix.py
def starts_with(prefix):          # any word beginning with `prefix`?
    node = root
    for ch in prefix:
        if ch not in node:
            return False
        node = node[ch]
    return True                   # reached the prefix -> some word has it

print(starts_with("ap"))          # True
print(starts_with("bat"))         # False

Store an aggregate at each node — a count of words passing through, or a running sum — and you can answer "how many / total value of words with this prefix?" in O(len(prefix)) too.

Searching with wildcards (DFS)

Once a query can contain a wildcard like '.' (match any character), a simple downward walk isn't enough — you must DFS, branching into every child when you hit the wildcard. This is the pattern behind "add and search words" and fuzzy matching with one allowed edit.

The bit trie: XOR problems

A trie doesn't have to store letters. Store each number as a path of its bits (most significant first) and you get a bit trie, which makes "maximum XOR of two numbers" fast: to maximise XOR against a number, greedily walk toward the opposite bit at each level, since a differing high bit beats any lower bits.

⚠️
Trie pitfalls

Always store an end marker — a prefix that exists isn't necessarily a complete word. If you keep meta-data in the node dict (counts, sums, end flags), use keys that can't collide with real characters (e.g. "$", "$c"). Tries use more memory than a hash set, so when you only need exact lookups, a set (or a sorted list + binary search) may be simpler. And for deletion/window problems, store counts per node so you can decrement.

1 LC 2185Counting Words With a Given Prefix Easy Prefix check (warm-up)

Clarify: Prefix match (not substring)? (Yes.) Case-sensitive? (Yes.)

Hint 1
startswith answers this directly for a single query.
Hint 2

class Solution:

2 LC 3042Count Prefix and Suffix Pairs I Easy Prefix + suffix test (brute force)

Problem. Count pairs (i, j) with i < j where words[i] is both a prefix and a suffix of words[j]. LeetCode 3042 ↗

Clarify: Both prefix AND suffix? (Yes.) Small input, so O(n²) is fine? (Yes.)

Hint 1
For each ordered pair, check startswith and endswith.
Hint 2
The O(n²) brute force passes here; a paired-character trie is the scalable version (see part II).

How to think about it Check every ordered pair directly with startswith and endswith. The scalable trie idea — a trie keyed by (front char, back char) pairs — is developed in the hard-tier part II; here the brute force suffices.

prefix_suffix_i.py
from typing import List

class Solution:
    def countPrefixSuffixPairs(self, words: List[str]) -> int:
        count = 0
        n = len(words)
        for i in range(n):
            for j in range(i + 1, n):
                w, x = words[i], words[j]
                if x.startswith(w) and x.endswith(w):   # w is prefix AND suffix of x
                    count += 1
        return count

Time O(n²·L) · Space O(1). Sets up the paired-char trie you'll build in LC 3045.

4 LC 14Longest Common Prefix Easy Trie · walk the single shared path

Problem. Return the longest common prefix shared by all strings. LeetCode 14 ↗

Clarify: Empty result if none shared? (Yes.) At least one string? (Guard for empty.)

Hint 1
Insert all words into a trie; the common prefix is the single non-branching path from the root.
Hint 2
Stop when a node has more than one child or a word ends there.

How to think about it Build a trie of all words. The longest common prefix is the path from the root that never branches and never passes the end of a word — so walk down while a node has exactly one child and no word ends there. (A vertical character scan is the simpler O(n·L) alternative; this shows the trie framing.)

lcp_trie.py
from typing import List

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        if not strs:
            return ""
        trie = {}
        for w in strs:
            node = trie
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = True                        # mark end of a word
        prefix, node = [], trie
        while len(node) == 1 and "$" not in node:   # single child, no word ends here
            ch = next(iter(node))
            prefix.append(ch)
            node = node[ch]
        return "".join(prefix)

Time O(total chars) · Space O(total chars). Seeing LCP as 'the trie's non-branching root path' is a clean mental model.

5 LC 208Implement Trie (Prefix Tree) Medium Design · the fundamental trie

Problem. Implement a trie with insert, search (exact word), and startsWith (any word with this prefix). LeetCode 208 ↗

Clarify: search is exact; startsWith is prefix? (Yes.) Lowercase letters only? (Yes.)

Hint 1
Each node maps a character to a child node; a nested dict works well.
Hint 2
Mark where a word ends so 'app' and 'apple' are distinguishable.

How to think about it Represent the trie as nested dicts: each node maps a character to its child node. insert walks/creates the path and marks the end with a sentinel key ("$"). search follows the path and checks the end marker; startsWith just checks the path exists. Every operation is O(word length), independent of how many words are stored.

trie.py
class Trie:
    def __init__(self):
        self.root = {}
    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node["$"] = True                            # "$" marks a complete word
    def _find(self, s):
        node = self.root
        for ch in s:
            if ch not in node:
                return None
            node = node[ch]
        return node
    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and "$" in node
    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None

Ops O(L) · Space O(total chars). This is the structure the entire chapter builds on — the end marker is what separates 'a word ends here' from 'just a prefix'.

6 LC 1804Implement Trie II (Prefix Tree) Medium Design · counts through and at each node

Problem. Implement a trie supporting insert, countWordsEqualTo, countWordsStartingWith, and erase. LeetCode 1804 ↗

Clarify: Words can be inserted multiple times? (Yes.) erase removes one occurrence? (Yes.)

Hint 1
Keep two counters per node: words passing through, and words ending here.
Hint 2
insert increments both along the path; erase decrements them.

How to think about it Augment each node with two counters: $c (words passing through this node) and $e (words ending here). insert bumps $c along the path and $e at the end; countWordsStartingWith reads $c at the prefix's node; countWordsEqualTo reads $e; erase decrements the same counters. Using $-prefixed keys avoids clashing with single-character children.

trie_ii.py
class Trie:
    def __init__(self):
        self.root = {}
    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
            node["$c"] = node.get("$c", 0) + 1      # words passing through
        node["$e"] = node.get("$e", 0) + 1          # words ending here
    def countWordsEqualTo(self, word: str) -> int:
        node = self.root
        for ch in word:
            if ch not in node:
                return 0
            node = node[ch]
        return node.get("$e", 0)
    def countWordsStartingWith(self, prefix: str) -> int:
        node = self.root
        for ch in prefix:
            if ch not in node:
                return 0
            node = node[ch]
        return node.get("$c", 0)
    def erase(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node[ch]
            node["$c"] -= 1
        node["$e"] -= 1

Ops O(L) · Space O(total chars). Counters-along-the-path is the trie pattern behind prefix-frequency queries.

7 LC 211Design Add and Search Words Data Structure Medium Trie + DFS · '.' wildcard

Problem. Support addWord and search, where a search word may contain '.' matching any single letter. LeetCode 211 ↗

Clarify: '.' matches exactly one character? (Yes.) Letters only otherwise? (Yes.)

Hint 1
Store words in a trie as usual.
Hint 2
For search, DFS: a normal char follows one edge; '.' branches into every child.

How to think about it Store words in a standard trie. search is a DFS over the trie: a concrete character follows its single edge, while a '.' tries every child at that position. A match requires reaching an end marker after consuming the whole pattern. The wildcard is what forces DFS instead of a simple walk.

word_dictionary.py
class WordDictionary:
    def __init__(self):
        self.root = {}
    def addWord(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node["$"] = True
    def search(self, word: str) -> bool:
        def dfs(node, i):
            if i == len(word):
                return "$" in node
            ch = word[i]
            if ch == ".":                           # wildcard: try every child
                return any(k != "$" and dfs(child, i + 1) for k, child in node.items())
            return ch in node and dfs(node[ch], i + 1)
        return dfs(self.root, 0)

search O(L) typical, O(N·L) worst with many wildcards · Space O(total chars). Branching on '.' is the canonical fuzzy-trie technique.

8 LC 677Map Sum Pairs Medium Trie · running prefix sum

Problem. Support insert(key, val) and sum(prefix) = total of values whose keys start with prefix. LeetCode 677 ↗

Clarify: Re-inserting a key overwrites its value? (Yes.) sum aggregates by prefix? (Yes.)

Hint 1
Store a running sum at each node = total value of keys passing through.
Hint 2
On re-insert, add only the delta (new value − old value) so updates stay correct.

How to think about it Keep a running sum $s at each node — the total value of all keys passing through it. insert adds the delta from any previous value of the key along its path (tracking values in a side dict), so overwrites work. sum(prefix) just reads $s at the prefix's node.

map_sum.py
class MapSum:
    def __init__(self):
        self.root = {}
        self.vals = {}                              # key -> value, to support updates
    def insert(self, key: str, val: int) -> None:
        delta = val - self.vals.get(key, 0)         # handle re-inserts
        self.vals[key] = val
        node = self.root
        for ch in key:
            node = node.setdefault(ch, {})
            node["$s"] = node.get("$s", 0) + delta  # running prefix sum
    def sum(self, prefix: str) -> int:
        node = self.root
        for ch in prefix:
            if ch not in node:
                return 0
            node = node[ch]
        return node.get("$s", 0)

insert/sum O(L) · Space O(total chars). Storing an aggregate along the path turns prefix-sum queries into O(L) lookups.

9 LC 676Implement Magic Dictionary Medium Trie + DFS · exactly one change

Problem. Build a dictionary, then search returns True if the word matches a stored word with exactly one character changed. LeetCode 676 ↗

Clarify: Exactly one substitution (not zero, not insert/delete)? (Yes.) Same length required? (Yes.)

Hint 1
Store words in a trie; DFS carrying whether you've used your one change.
Hint 2
Match must end with the change used and on a word boundary.

How to think about it Store words in a trie and DFS the search word, threading a changed flag. A matching character follows its edge with the flag unchanged; a mismatching character may follow another edge only if the change hasn't been used yet, setting the flag. A valid result ends on a word marker with the change spent.

magic_dictionary.py
from typing import List

class MagicDictionary:
    def __init__(self):
        self.root = {}
    def buildDict(self, dictionary: List[str]) -> None:
        for w in dictionary:
            node = self.root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = True
    def search(self, searchWord: str) -> bool:
        def dfs(node, i, changed):
            if i == len(searchWord):
                return changed and "$" in node      # exactly one change used
            ch = searchWord[i]
            for k, child in node.items():
                if k == "$":
                    continue
                if k == ch and dfs(child, i + 1, changed):
                    return True
                if k != ch and not changed and dfs(child, i + 1, True):
                    return True
            return False
        return dfs(self.root, 0, False)

search O(L·26) worst · Space O(total chars). 'DFS with a budget of one edit' generalises to k-edit fuzzy matching.

10 LC 648Replace Words Medium Trie · shortest matching root

Problem. Replace every word in a sentence with the shortest dictionary root that is a prefix of it, if any. LeetCode 648 ↗

Clarify: Use the shortest applicable root? (Yes.) Keep the word if no root matches? (Yes.)

Hint 1
Insert the roots into a trie, marking word ends.
Hint 2
For each sentence word, walk the trie and stop at the first end marker (shortest root).

How to think about it Build a trie of the dictionary roots, storing the full root string at each end. For each word in the sentence, walk down the trie; the moment you hit an end marker you've found the shortest matching root, so return it. If the walk falls off the trie, keep the original word.

replace_words.py
from typing import List

class Solution:
    def replaceWords(self, dictionary: List[str], sentence: str) -> str:
        root = {}
        for w in dictionary:
            node = root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = w
        def shortest_root(word):
            node = root
            for ch in word:
                if ch not in node:
                    break
                node = node[ch]
                if "$" in node:
                    return node["$"]                # first (shortest) root found
            return word
        return " ".join(shortest_root(w) for w in sentence.split())

Time O(total chars) · Space O(dict chars). 'Stop at the first end marker' gives the shortest prefix for free.

11 LC 720Longest Word in Dictionary Medium Every prefix must be a word

Problem. Return the longest word that can be built one character at a time, where every prefix is also in the list; ties break lexicographically smallest. LeetCode 720 ↗

Clarify: Every prefix (length 1..len) must be present? (Yes.) Ties → smallest word? (Yes.)

Hint 1
A word is buildable iff all its proper prefixes are also words.
Hint 2
Sort ascending so ties resolve to the smaller word, then keep the longest buildable one.

How to think about it A word qualifies only if every one of its prefixes is also in the set. Put the words in a set, sort them ascending (so equal-length ties favour the lexicographically smaller word), and keep the longest word all of whose prefixes exist. (A trie storing which nodes are word-ends answers the prefix check directly.)

longest_word.py
from typing import List

class Solution:
    def longestWord(self, words: List[str]) -> str:
        word_set = set(words)
        best = ""
        for w in sorted(words):                     # ascending -> ties pick the smaller
            if all(w[:i] in word_set for i in range(1, len(w))):
                if len(w) > len(best):
                    best = w
        return best

Time O(total chars) after sort · Space O(n). The 'incrementally buildable word' idea is pure trie thinking even via a set.

12 LC 1268Search Suggestions System Medium Sorted list + binary search per prefix

Problem. As each character of a search word is typed, return up to three lexicographically smallest products sharing the typed prefix. LeetCode 1268 ↗

Clarify: At most 3 suggestions per prefix? (Yes.) Lexicographically smallest? (Yes.)

Hint 1
Sort the products; a prefix's matches are a contiguous block.
Hint 2
Binary-search the block start, then take the next up-to-3 that still match.

How to think about it Sort the products so any prefix's matches form a contiguous range. For each growing prefix, binary-search (lower bound) the first product ≥ the prefix and take the next three that still start with it. (A trie storing the smallest three completions per node is the alternative when products are fixed and prefixes many.)

search_suggestions.py
from typing import List
import bisect

class Solution:
    def suggestedProducts(self, products: List[str], searchWord: str) -> List[List[str]]:
        products.sort()
        res = []
        prefix = ""
        for ch in searchWord:
            prefix += ch
            i = bisect.bisect_left(products, prefix)
            matches = []
            for p in products[i:i + 3]:             # up to 3 lexicographically smallest
                if p.startswith(prefix):
                    matches.append(p)
            res.append(matches)
        return res

Time O(n log n + L·3) · Space O(1). Autocomplete is the archetypal trie use case; sort + binary search is a lean substitute.

13 LC 139Word Break Medium Trie + DP

Problem. Return whether s can be segmented into a sequence of dictionary words. LeetCode 139 ↗

Clarify: Words reusable? (Yes.) Must consume all of s? (Yes.)

Hint 1
dp[i] = can s[:i] be segmented; extend from each reachable position.
Hint 2
Walk a trie from position i to enumerate dictionary-word matches in one pass.

How to think about it Build a trie of the dictionary. DP over positions: from each breakable start i, walk the trie through s[i:], and whenever you hit a word end at position j, mark dp[j+1] reachable. The trie makes 'which dictionary words start here' a single left-to-right walk rather than repeated substring lookups.

word_break.py
from typing import List

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> bool:
        root = {}
        for w in wordDict:
            node = root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = True
        n = len(s)
        dp = [False] * (n + 1)                      # dp[i] = s[:i] is breakable
        dp[0] = True
        for i in range(n):
            if not dp[i]:
                continue
            node = root
            for j in range(i, n):                   # walk the trie from position i
                if s[j] not in node:
                    break
                node = node[s[j]]
                if "$" in node:
                    dp[j + 1] = True
        return dp[n]

Time O(n²) · Space O(dict chars + n). Trie-walk + DP is the pattern for segmentation problems (Word Break II, Concatenated Words).

14 LC 421Maximum XOR of Two Numbers in an Array Medium Bit trie · greedily pick opposite bits

Problem. Return the maximum XOR of any two numbers in the array. LeetCode 421 ↗

Clarify: XOR of two distinct elements (or the same, giving 0)? (Any pair.) Numbers fit in 32 bits? (Yes.)

Hint 1
Store each number as a path of 32 bits in a trie (most significant bit first).
Hint 2
For each number, walk the trie preferring the opposite bit at every step to maximise XOR.

How to think about it Insert every number into a bit trie: a path of 32 bits from most to least significant. Then, for each number, greedily walk the trie choosing the opposite bit whenever available — each opposite bit sets a high bit in the XOR. The best XOR found over all numbers is the answer.

max_xor.py
from typing import List

class Solution:
    def findMaximumXOR(self, nums: List[int]) -> int:
        root = {}
        for num in nums:                            # insert every number bit by bit
            node = root
            for i in range(31, -1, -1):
                bit = (num >> i) & 1
                node = node.setdefault(bit, {})
        best = 0
        for num in nums:
            node, cur = root, 0
            for i in range(31, -1, -1):
                bit = (num >> i) & 1
                want = 1 - bit                      # greedily take the opposite bit
                if want in node:
                    cur |= (1 << i)
                    node = node[want]
                else:
                    node = node[bit]
            best = max(best, cur)
        return best

Time O(32n) · Space O(32n). The bit trie turns 'max XOR pair' from O(n²) into linear — a whole family of XOR problems builds on it.

15 LC 1023Camelcase Matching Medium Subsequence match with a capital rule

Problem. For each query, return whether the pattern can be made by inserting only lowercase letters into it to match the query. LeetCode 1023 ↗

Clarify: Pattern chars must appear in order as a subsequence? (Yes.) Every capital in the query must be matched by the pattern? (Yes.)

Hint 1
Two pointers: advance through the pattern when characters match.
Hint 2
Any unmatched uppercase letter in the query is fatal.

How to think about it Scan each query with a pointer into the pattern. When characters match, advance the pattern pointer; extra lowercase query letters are allowed (they'd be inserted), but any uppercase query letter that isn't the next pattern character breaks the match. A query matches iff the whole pattern is consumed.

camel_match.py
from typing import List

class Solution:
    def camelMatch(self, queries: List[str], pattern: str) -> List[bool]:
        def matches(q):
            i = 0
            for ch in q:
                if i < len(pattern) and ch == pattern[i]:
                    i += 1                          # consume a pattern char
                elif ch.isupper():
                    return False                    # unmatched capital -> fail
            return i == len(pattern)
        return [matches(q) for q in queries]

Time O(total chars) · Space O(1). A subsequence matcher with a case constraint — dictionary-matching cousin of the trie problems.

16 LC 820Short Encoding of Words Medium Suffix trie · count the leaves

Problem. Encode words into a reference string using shared suffixes (a word is kept unless it's a suffix of another). Return the minimum encoded length. LeetCode 820 ↗

Clarify: A word is redundant if it's a suffix of another? (Yes.) Encoding adds a '#' per kept word? (Yes.)

Hint 1
Insert words REVERSED into a trie so shared suffixes share a path.
Hint 2
A word needs its own encoding iff its (reversed) end node is a leaf.

How to think about it Build a suffix trie by inserting each word reversed — now words sharing a suffix share a root path. A word must be encoded on its own only if its reversed path ends at a leaf (nothing extends it, so it isn't a suffix of another). Sum len(word) + 1 over those leaf words.

short_encoding.py
from typing import List

class Solution:
    def minimumLengthEncoding(self, words: List[str]) -> int:
        words = list(set(words))
        root = {}
        ends = {}
        for w in words:
            node = root
            for ch in reversed(w):                  # insert reversed -> suffix trie
                node = node.setdefault(ch, {})
            ends[w] = node
        total = 0
        for w in words:
            if not ends[w]:                         # leaf -> not a suffix of another word
                total += len(w) + 1
        return total

Time O(total chars) · Space O(total chars). Reversing to get a suffix trie is a trick worth internalising.

17 LC 2416Sum of Prefix Scores of Strings Medium Trie · count words sharing each prefix

Problem. For each word, its score is the number of words (in the list) that have each of its prefixes; return the sum of those counts per word. LeetCode 2416 ↗

Clarify: Every prefix of a word contributes the count of words sharing it? (Yes.) A word counts itself? (Yes.)

Hint 1
At each trie node, store how many words pass through it.
Hint 2
A word's score sums those counts along its path.

How to think about it Insert all words, incrementing a counter $c at each node for every word passing through. Then for each word, walk its path summing the counter at every node — that sum is exactly the number of words sharing each prefix, accumulated. Two passes, each O(total chars).

prefix_scores.py
from typing import List

class Solution:
    def sumPrefixScores(self, words: List[str]) -> List[int]:
        root = {}
        for w in words:
            node = root
            for ch in w:
                node = node.setdefault(ch, {})
                node["$c"] = node.get("$c", 0) + 1  # how many words share this prefix
        res = []
        for w in words:
            node, score = root, 0
            for ch in w:
                node = node[ch]
                score += node["$c"]                 # sum over all prefixes of w
            res.append(score)
        return res

Time O(total chars) · Space O(total chars). The clearest example of 'store an aggregate at every node, then read it back'.

lcp_two_arrays.py
from typing import List

class Solution:
    def longestCommonPrefix(self, arr1: List[int], arr2: List[int]) -> int:

            node = root

19 LC 140Word Break II Medium Backtracking + memoization

Problem. Return all sentences formable by segmenting s into dictionary words. LeetCode 140 ↗

Clarify: Return every valid segmentation? (Yes.) Words reusable? (Yes.)

Hint 1
From each start, try every dictionary word that is a prefix, then recurse on the rest.
Hint 2
Memoize the list of sentences buildable from each start index.

How to think about it Recurse from a start index: for each dictionary word matching the prefix of s[start:], prepend it to every sentence buildable from the remainder. Memoise the sentence lists per start index so shared suffixes aren't recomputed. (A trie makes the 'which words start here' step a single walk.)

word_break_ii.py
from typing import List

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        words = set(wordDict)
        memo = {}
        def bt(start):
            if start == len(s):
                return [""]
            if start in memo:
                return memo[start]
            res = []
            for end in range(start + 1, len(s) + 1):
                w = s[start:end]
                if w in words:
                    for rest in bt(end):
                        res.append(w if rest == "" else w + " " + rest)
            memo[start] = res
            return res
        return bt(0)

Time O(n² + output) · Space O(output). Returning and memoising lists of answers — the enumerate-all cousin of Word Break.

20 LC 2707Extra Characters in a String Medium Trie + DP · minimise leftovers

Problem. Break s into dictionary words to minimise the number of leftover (extra) characters. LeetCode 2707 ↗

Clarify: Leftover characters counted individually? (Yes.) Words reusable? (Yes.)

Hint 1
dp[i] = fewest extra characters in s[i:].
Hint 2
Either treat s[i] as extra (1 + dp[i+1]) or match a dictionary word starting at i.

How to think about it DP from the end: dp[i] is the fewest extra characters in s[i:]. Option one skips s[i] as an extra (1 + dp[i+1]); option two matches any dictionary word s[i:j] and takes dp[j]. The minimum wins. (A trie makes enumerating the words starting at i a single walk.)

extra_characters.py
from typing import List

class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        words = set(dictionary)
        n = len(s)
        dp = [0] * (n + 1)                          # dp[i] = min extra chars in s[i:]
        for i in range(n - 1, -1, -1):
            dp[i] = dp[i + 1] + 1                    # skip s[i] as an extra char
            for j in range(i + 1, n + 1):
                if s[i:j] in words:
                    dp[i] = min(dp[i], dp[j])
        return dp[0]

Time O(n²) · Space O(n). A minimisation variant of Word Break — same trie-walk + DP skeleton.

21 LC 212Word Search II Medium Trie + grid backtracking

Problem. Given a board and a list of words, return all words that can be formed by adjacent cells (each cell used once per word). LeetCode 212 ↗

Clarify: Many words at once? (Yes — a trie shares prefixes.) 4-directional moves, no cell reuse? (Yes.)

Hint 1
Put all words in a trie, then DFS the board once, descending the trie as letters match.
Hint 2
When a trie node marks a word, record it (and remove the marker to avoid duplicates).

How to think about it Build a trie of all words, then DFS the grid once. As you step to a neighbouring cell, descend the matching trie edge; when a node marks the end of a word, record it and delete the marker (dedup). Mark cells visited during the DFS to prevent reuse. The trie prunes dead prefixes across all words simultaneously.

word_search_ii.py
from typing import List

class Solution:
    def findWords(self, board: List[List[str]], words: List[str]) -> List[str]:
        root = {}
        for w in words:
            node = root
            for ch in w:
                node = node.setdefault(ch, {})
            node["$"] = w
        rows, cols = len(board), len(board[0])
        res = []
        def dfs(r, c, node):
            ch = board[r][c]
            if ch not in node:
                return
            nxt = node[ch]
            if "$" in nxt:
                res.append(nxt.pop("$"))            # found; remove to avoid duplicates
            board[r][c] = "#"
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != "#":
                    dfs(nr, nc, nxt)
            board[r][c] = ch
        for r in range(rows):
            for c in range(cols):
                dfs(r, c, root)
        return res

Time O(cells · 4·3^(L−1)) · Space O(total word chars). Combining a trie with grid backtracking is the reason to learn both — searching one word at a time would be far slower.

23 LC 745Prefix and Suffix Search Hard Design · index every prefix#suffix

Problem. Build a structure over words, then answer queries for the highest-weight word with a given prefix and suffix. LeetCode 745 ↗

Clarify: Weight = the word's index (later = higher)? (Yes.) Many queries? (Yes — precompute.)

Hint 1
A query fixes both ends; precompute every (prefix, suffix) combination.
Hint 2
Store 'prefix#suffix' -> weight, keeping the largest weight (latest word).

How to think about it At build time, for each word generate every prefix + "#" + suffix combination and map it to the word's weight (later words overwrite earlier ones, keeping the max). A query is then a single dict lookup on pref + "#" + suff. Trades build time and memory for O(1) queries. (A merged prefix/suffix trie is the space-lean alternative.)

word_filter.py
from typing import List

class WordFilter:
    def __init__(self, words: List[str]):
        self.d = {}
        for weight, w in enumerate(words):          # later words have higher weight
            n = len(w)
            for j in range(n + 1):                  # every prefix
                for i in range(n + 1):              # every suffix
                    self.d[w[:j] + "#" + w[i:]] = weight
    def f(self, pref: str, suff: str) -> int:
        return self.d.get(pref + "#" + suff, -1)

Build O(N·L²) · Query O(1) · Space O(N·L²). Encoding both constraints into one lookup key is the trick.

24 LC 1032Stream of Characters Hard Suffix trie · match the stream's tail

Problem. Stream characters one at a time; after each, report whether any dictionary word is a suffix of the stream so far. LeetCode 1032 ↗

Clarify: Match a suffix of the whole stream? (Yes.) Words known up front? (Yes.)

Hint 1
Store words REVERSED in a trie so a suffix of the stream is a prefix of the reversed tail.
Hint 2
On each query, walk the reversed recent characters down the trie.

How to think about it Insert every word reversed into a trie. Keep the streamed characters; on each query, walk backward from the newest character down the trie — matching a reversed word means the original word is a suffix of the stream. Bounding the walk by the longest word length keeps each query O(maxLen).

stream_of_characters.py
from typing import List

class StreamOfCharacters:
    def __init__(self, words: List[str]):
        self.root = {}
        self.max_len = 0
        for w in words:
            node = self.root
            for ch in reversed(w):                  # store words reversed
                node = node.setdefault(ch, {})
            node["$"] = True
            self.max_len = max(self.max_len, len(w))
        self.stream = []
    def query(self, letter: str) -> bool:
        self.stream.append(letter)
        node = self.root
        for ch in reversed(self.stream[-self.max_len:]):   # match a suffix of the stream
            if ch not in node:
                return False
            node = node[ch]
            if "$" in node:
                return True
        return False

query O(maxLen) · Space O(dict chars). Reversing so 'suffix of stream' becomes 'prefix in trie' is the key insight (Aho–Corasick is the industrial-strength version).

Hint 2

How to think about it Put all words in a set. For each word, run a Word-Break DP that forbids using the whole word as a single piece (so at least two pieces are required). concatenated_words.py
from typing import List

class Solution:
    def findAllConcatenatedWords(self, words: List[str]) -> List[str]:
        word_set = set(words)
        def can_form(w):
            n = len(w)
            dp = [False] * (n + 1)
            dp[0] = True
            for i in range(1, n + 1):
                for j in range(i):
                    if dp[j] and w[j:i] in word_set and (j != 0 or i != n):
                        dp[i] = True                # (j,i) != whole word -> must use >=2 pieces
                        break
            return dp[n]
        return [w for w in words if w and can_form(w)]

26 LC 2935Maximum Strong Pair XOR II Hard Bit trie + sliding window (with removal)

Problem. A strong pair satisfies |x−y| ≤ min(x, y). Return the maximum XOR over all strong pairs. LeetCode 2935 ↗

Clarify: Pair can be an element with itself? (Yes, giving 0.) Numbers up to ~2²⁰? (Yes.)

Hint 1
Sort; the condition |x−y| ≤ min(x,y) becomes a sliding window (y ≤ 2x for x ≤ y).
Hint 2
Use a bit trie that supports removal (counts per node) as the window's left edge advances.

How to think about it Sort the numbers so the strong-pair condition reduces to a window: for the larger value y, valid partners satisfy y − x ≤ x. Maintain a bit trie of the current window with per-node counts so numbers can be removed as the window's left edge advances. For each right endpoint, query the trie for the max-XOR partner within the window.

strong_pair_xor.py
from typing import List

class Solution:
    def maximumStrongPairXor(self, nums: List[int]) -> int:
        nums.sort()
        HIGH = 20
        root = {}
        def update(num, delta):
            node = root
            for i in range(HIGH, -1, -1):
                bit = (num >> i) & 1
                node = node.setdefault(bit, {})
                node["c"] = node.get("c", 0) + delta
        def query(num):
            node, cur = root, 0
            for i in range(HIGH, -1, -1):
                bit = (num >> i) & 1
                want = 1 - bit
                if want in node and node[want].get("c", 0) > 0:
                    cur |= (1 << i)
                    node = node[want]
                else:
                    node = node[bit]
            return cur
        best = left = 0
        for right in range(len(nums)):
            update(nums[right], 1)
            while nums[right] - nums[left] > nums[left]:   # strong pair: y - x <= x
                update(nums[left], -1)
                left += 1
            best = max(best, query(nums[right]))
        return best

Time O(n·bits) · Space O(n·bits). A bit trie with counts (so you can delete) plus a sliding window — the advanced form of Max XOR.

27 LC 1707Maximum XOR With an Element From Array Hard Bit trie + offline queries

Problem. For each query (x, m), return the maximum XOR of x with any array element ≤ m, or −1 if none. LeetCode 1707 ↗

Clarify: Only elements ≤ m are eligible per query? (Yes.) Queries can be reordered? (Yes — process offline.)

Hint 1
Sort the array and sort queries by their limit m.
Hint 2
Incrementally insert elements ≤ m into a bit trie, then query max XOR.

How to think about it Process queries offline: sort the array ascending and the queries by their limit m. Sweep the queries in increasing m, inserting all array elements ≤ m into a bit trie as you go, then answer each query with the standard max-XOR trie walk. Elements once inserted stay valid for later (larger-m) queries. Empty trie → −1.

max_xor_with_limit.py
from typing import List

class Solution:
    def maximizeXor(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        nums.sort()
        HIGH = 30
        root = {}
        def add(num):
            node = root
            for b in range(HIGH, -1, -1):
                node = node.setdefault((num >> b) & 1, {})
        def query(num):
            node, cur = root, 0
            for b in range(HIGH, -1, -1):
                bit = (num >> b) & 1
                want = 1 - bit
                if want in node:
                    cur |= (1 << b); node = node[want]
                else:
                    node = node[bit]
            return cur
        order = sorted(range(len(queries)), key=lambda i: queries[i][1])
        res = [0] * len(queries)
        j = 0
        for qi in order:                            # process queries by increasing m
            x, m = queries[qi]
            while j < len(nums) and nums[j] <= m:
                add(nums[j]); j += 1
            res[qi] = query(x) if root else -1
        return res

Time O((n + q)·bits + sort) · Space O(n·bits). Sorting queries so constraints only relax is the offline-processing idea, layered on the bit trie.

28 LC 336Palindrome Pairs Hard Split each word · match reversed halves

Problem. Return all index pairs (i, j) such that words[i] + words[j] is a palindrome. LeetCode 336 ↗

Clarify: Ordered pairs, i ≠ j? (Yes.) Empty string possible in the list? (Yes.)

Hint 1
Split each word at every cut into prefix and suffix.
Hint 2
If the suffix is a palindrome, look up reverse(prefix); if the prefix is a palindrome, look up reverse(suffix).

How to think about it For each word, try every split into prefix + suffix. If the suffix is a palindrome and the reversed prefix is another word, that word can follow to complete a palindrome ([i, j]). Symmetrically, if the prefix is a palindrome and the reversed suffix is another word, it can precede ([j, i]). A guard on the empty-prefix split avoids double-counting reverse pairs. (A trie of reversed words is the trie-native formulation.)

palindrome_pairs.py
from typing import List

class Solution:
    def palindromePairs(self, words: List[str]) -> List[List[int]]:
        lookup = {w: i for i, w in enumerate(words)}
        def is_pal(s):
            return s == s[::-1]
        res = []
        for i, w in enumerate(words):
            n = len(w)
            for j in range(n + 1):
                prefix, suffix = w[:j], w[j:]
                if is_pal(suffix):                  # w + reverse(prefix)
                    rev = prefix[::-1]
                    if rev in lookup and lookup[rev] != i:
                        res.append([i, lookup[rev]])
                if j != 0 and is_pal(prefix):       # reverse(suffix) + w  (j!=0 avoids dup)
                    rev = suffix[::-1]
                    if rev in lookup and lookup[rev] != i:
                        res.append([lookup[rev], i])
        return res

Time O(n·L²) · Space O(n·L). The subtle part is the empty-split guard that stops (i, j) and (j, i) being counted twice.

29 LC 425Word Squares Hard Prefix map + backtracking

Problem. Return all word squares (grids where the k-th row equals the k-th column) buildable from the given words. LeetCode 425 ↗

Clarify: All words the same length? (Yes.) Words reusable? (Yes.)

Hint 1
Row r's word must start with the prefix formed by the r-th characters of the rows chosen so far.
Hint 2
Precompute prefix -> words, then backtrack row by row using that required prefix.

How to think about it Precompute a map from every prefix to the words having it (a trie-like index). Backtrack row by row: the next row's word must begin with the prefix formed by taking the current row index's character from each already-placed word. Try every candidate with that prefix, recurse, and undo. A complete stack of rows is a valid square.

word_squares.py
from typing import List
from collections import defaultdict

class Solution:
    def wordSquares(self, words: List[str]) -> List[List[str]]:
        n = len(words[0])
        prefixes = defaultdict(list)
        for w in words:
            for i in range(len(w) + 1):
                prefixes[w[:i]].append(w)           # map every prefix to its words
        res = []
        def bt(square):
            if len(square) == n:
                res.append(square[:]); return
            row = len(square)
            prefix = "".join(w[row] for w in square)   # required prefix for the next word
            for cand in prefixes[prefix]:
                square.append(cand)
                bt(square)
                square.pop()
        for w in words:
            bt([w])
        return res

Time exponential, heavily pruned · Space O(prefix index). The prefix map (a trie in spirit) is what makes the backtracking tractable.

30 LC 3045Count Prefix and Suffix Pairs II Hard Trie keyed by (front, back) character pairs

Problem. Count pairs (i, j), i < j, where words[i] is both a prefix and a suffix of words[j] — at scale. LeetCode 3045 ↗

Clarify: Same definition as part I, but large input? (Yes — need better than O(n²·L).)

Hint 1
A word is a prefix AND suffix of w iff it matches w[:k] and w[-k:] simultaneously.
Hint 2
Walk a trie keyed by the pair (front char, back char) of w to match both ends at once.

How to think about it Build a trie whose edges are keyed by pairs (w[i], w[n−1−i]) — the i-th character from the front and the mirror from the back. Inserting a word this way, and counting end-markers passed at each depth, tallies exactly the earlier words that match both a prefix and a suffix of the current word. One pass over all words.

prefix_suffix_ii.py
from typing import List

class Solution:
    def countPrefixSuffixPairs(self, words: List[str]) -> int:
        root = {}
        count = 0
        for w in words:
            n = len(w)
            cur = root
            for i in range(n):
                pair = (w[i], w[n - 1 - i])         # trie keyed by (front char, back char)
                if pair not in cur:
                    cur[pair] = {}
                cur = cur[pair]
                count += cur.get("$", 0)            # earlier words that are prefix & suffix
            cur["$"] = cur.get("$", 0) + 1
        return count

Time O(total chars) · Space O(total chars). Keying trie edges by character pairs matches both ends simultaneously — the scalable upgrade of part I.

4 · Interview playbook

  • Reach for a trie when prefixes matter: autocomplete, "words with this prefix", shared-prefix aggregation — things a hash set can't do cheaply.
  • Always store an end marker so a prefix isn't mistaken for a complete word; keep node metadata under non-character keys.
  • Wildcards → DFS: branch into every child on a '.' or an allowed edit.
  • Combine tries: with grid backtracking (Word Search II) or DP (Word Break) to search many words at once.
  • Bit trie for XOR: store numbers as bit paths and greedily chase the opposite bit; add per-node counts to support deletion (sliding-window XOR).

6 · Review

Cheat sheet
  • Insert/search/startsWith → nested-dict trie + end marker (O(L)).
  • Count / sum / smallest with a prefix → aggregate stored at each node.
  • '.' wildcard or one-edit search → DFS branching over children.
  • Find many words in a grid → trie + backtracking (dedup on the marker).
  • Word break / segmentation → trie walk + DP.
  • Shortest root / autocomplete → stop at the first / collect smallest completions.
  • Suffix queries → insert words reversed (suffix trie).
  • Maximum XOR pair → bit trie, chase the opposite bit; counts per node for windows.

Concept checks

Why does a trie node need an explicit "end of word" marker?
Because a path can be both a complete word and a prefix of longer words — without a marker you can't tell "app" (a word) from "app" (just a prefix of "apple")
To save memory
Because Python dicts require it
Reaching a node only proves the prefix exists. The end marker records that a word actually terminates there, so search("app") can return True only when "app" was inserted, not merely because "apple" was.
When does a trie beat a hash set, and when is the set better?
The trie wins for prefix queries ("any/how many words start with X?"); the hash set wins for plain exact-membership, with O(1) lookups and less memory
The trie is always faster and smaller
They are interchangeable in every case
A hash set can't answer prefix questions without scanning all keys, whereas a trie walks only the prefix length. But for exact membership a set is simpler and lighter — use the trie specifically when prefixes (or shared structure) matter.

  • I can implement a trie (insert/search/startsWith) with an end marker.
  • I can store counts/sums at nodes for prefix-aggregation queries.
  • I can search with a '.' wildcard via DFS over children.
  • I can combine a trie with grid backtracking (Word Search II).
  • I can use a trie walk inside DP for word segmentation.
  • I can build a bit trie and solve maximum-XOR problems.
