1 · Foundations

New to hashing? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is hashing?

Imagine searching a list of a million names for "Priya". You'd check them one by one — up to a million comparisons. A hash structure removes that scan. A hash function turns each key into a number, and that number points straight to the slot where the key's data lives. So "is Priya here?" becomes a single jump, not a walk — roughly O(1), no matter how big the collection.

The whole idea: compute where something lives from its value, instead of searching for it. That is what turns repeated O(n) lookups into O(1) ones.

Python gives you two: set and dict

You almost never write a hash function yourself — Python's built-in set and dict are hash structures. A set stores unique keys and answers "is this in here?". A dict stores key → value pairs and answers "what's stored under this key?". Both do it in O(1) on average.

Example — set and dict basics
basics.py
seen = set()
seen.add(3)
print(3 in seen)      # True   -> O(1) membership
print(9 in seen)      # False

price = {}            # a dict (hash map)
price["apple"] = 40
price["mango"] = 90
print(price["apple"]) # 40     -> O(1) lookup by key
print("kiwi" in price) # False -> check before indexing a missing key
OutputTrue
False
40
False

Indexing a missing key (price["kiwi"]) raises KeyError. Use key in d, or d.get(key, default), to read safely.

Why is it O(1)? (and what's a collision)

The hash function scatters keys across many internal "buckets". To find a key, Python hashes it, jumps to that bucket, and looks there — no full scan. Occasionally two different keys hash to the same bucket: a collision. The bucket then holds a short list, and Python checks those few entries. Collisions are rare enough that lookups stay O(1) on average (the worst case, everything colliding, is O(n) — you rarely hit it).

💡
Set vs. sorting for "is it there?"

Two ways to detect duplicates: sort then scan neighbours — O(n log n) time, O(1) extra — or drop everything into a set — O(n) time, O(n) memory. Hashing usually trades memory for speed. Saying that trade-off out loud is the point of many of these problems.

Two tools you'll reach for constantly

Counting is so common that Python ships helpers for it in collections. Counter tallies how many times each item appears; defaultdict is a dict that auto-creates a starting value the first time you touch a key, so you skip "if key not in d" boilerplate.

Example — Counter and defaultdict
counting.py
from collections import Counter, defaultdict

freq = Counter("banana")
print(freq)                 # Counter({'a': 3, 'n': 2, 'b': 1})
print(freq.most_common(1))  # [('a', 3)]  -> handy for "top-k"

groups = defaultdict(list)  # missing keys start as []
groups["fruit"].append("apple")   # no KeyError, list is auto-created
print(groups)               # defaultdict(<class 'list'>, {'fruit': ['apple']})
Counter(a) == Counter(b) is the fastest way to test "same items with same counts" — the heart of every anagram problem below.

What can be a key?

Only hashable (effectively, immutable) values. Numbers, strings, and tuples are hashable and make fine keys. A list is mutable and therefore not hashable — using one as a key raises TypeError. This is why "group by a signature" problems convert a list of counts into a tuple before using it as a key.

Example — tuples work as keys, lists don't
keys.py
d = {}
d[(2, 3)] = "point"      # tuple key -> fine
print(d[(2, 3)])         # point

d[[2, 3]] = "oops"       # TypeError: unhashable type: 'list'
⚠️
Common hashing pitfalls

Reading a missing dict key throws KeyError — prefer d.get(k, default) or defaultdict. A set is unordered, so don't rely on iteration order. And remember the memory cost: a hash solution that's O(n) time is usually O(n) space too — always separate the answer's output space from your auxiliary map/set.

1 LC 1Two Sum Easy Complement lookup · remember what you've seen

Problem. Return the indices of the two numbers that add up to target. Exactly one answer exists. LeetCode 1 ↗

Clarify: Exactly one solution? (Yes.) Reuse the same element? (No.) Negatives allowed? (Yes.)

Hint 1
Checking every pair is O(n²). What if a lookup table could find the partner instantly?
Hint 2
For each x, the partner you need is target − x. Store seen values in a dict and check for the partner before inserting.

How to think about it The founding hashing pattern. As you walk the array, ask: 'have I already seen the number that completes this pair?' A dict of value → index answers that in O(1). Check for target − x first, then store x.

two_sum.py
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, x in enumerate(nums):
            if target - x in seen:
                return [seen[target - x], i]
            seen[x] = i
        return []

Time O(n) · Space O(n). Check for the partner before inserting, or a value could pair with itself.

2 LC 217Contains Duplicate Easy Seen set · membership as you go

Problem. Return True if any value appears at least twice. LeetCode 217 ↗

Clarify: Optimise for time or memory? (Usually time.) Sort allowed? (An O(n log n) alternative.)

Hint 1
A set answers 'have I seen this before?' in O(1).
Hint 2
Add each value; the moment one is already present, you're done.

How to think about it The seen-set pattern in its purest form: keep a running set of values encountered. If the current value is already inside, there's a duplicate. Trades O(n) memory for O(n) time versus the O(n log n) sort-and-compare.

contains_dup.py
from typing import List

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()
        for x in nums:
            if x in seen:
                return True
            seen.add(x)
        return False

Time O(n) · Space O(n). One-liner: len(set(nums)) != len(nums).

3 LC 242Valid Anagram Easy Frequency map · compare letter counts

Problem. Return whether t is an anagram of s (same letters, same counts). LeetCode 242 ↗

Clarify: Case-sensitive? (Yes, per the base problem.) Only lowercase letters? (Yes.) Unicode follow-up? (A dict still works.)

Hint 1
Two strings are anagrams exactly when their letter counts match.
Hint 2
Count letters in each and compare the two count maps.

How to think about it Anagrams are defined by letter frequency, so build a frequency map of each string and compare. collections.Counter does the counting and supports == directly. A quick length check rejects mismatches early.

valid_anagram.py
from collections import Counter

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        return Counter(s) == Counter(t)

Time O(n) · Space O(1) (at most 26 keys for lowercase). Sorting both strings also works but is O(n log n).

4 LC 383Ransom Note Easy Frequency map · spend from a budget

Problem. Return whether ransomNote can be built from the letters in magazine (each magazine letter used once). LeetCode 383 ↗

Clarify: Each magazine letter usable once? (Yes.) Lowercase only? (Yes.)

Hint 1
Count what the magazine offers, then spend those letters on the note.
Hint 2
If any needed letter runs out, it's impossible.

How to think about it Count the magazine's letters into a frequency map — a budget. Walk the note spending one of each letter; if the budget for a letter hits zero when you still need it, return False.

ransom_note.py
from collections import Counter

class Solution:
    def canConstruct(self, ransomNote: str, magazine: str) -> bool:
        have = Counter(magazine)
        for ch in ransomNote:
            if have[ch] <= 0:
                return False
            have[ch] -= 1
        return True

Time O(n + m) · Space O(1). Also expressible as not (Counter(ransomNote) - Counter(magazine)).

5 LC 771Jewels and Stones Easy Seen set · O(1) membership test

Problem. Count how many characters in stones are also jewels (listed in jewels). LeetCode 771 ↗

Clarify: Case-sensitive (a ≠ A)? (Yes.) Characters in jewels are distinct? (Yes.)

Hint 1
Scanning jewels for every stone is O(J·S).
Hint 2
Put the jewels in a set once; each membership test is then O(1).

How to think about it Convert jewels to a set so 'is this stone a jewel?' is O(1), then count the matches in one pass. The set turns a nested scan into a linear one.

jewels.py
class Solution:
    def numJewelsInStones(self, jewels: str, stones: str) -> int:
        jewel_set = set(jewels)
        return sum(1 for s in stones if s in jewel_set)

Time O(J + S) · Space O(J). The simplest illustration of 'set for membership'.

6 LC 349Intersection of Two Arrays Easy Set intersection · unique overlap

Problem. Return the unique values that appear in both arrays. LeetCode 349 ↗

Clarify: Result unique (no duplicates)? (Yes.) Order matters? (No.)

Hint 1
Duplicates don't matter and order doesn't matter — that screams 'set'.
Hint 2
Convert both to sets and intersect.

How to think about it Both arrays become sets, and Python's & gives their intersection directly. The set construction dedups automatically, matching the required output.

intersection.py
from typing import List

class Solution:
    def intersection(self, nums1: List[int], nums2: List[int]) -> List[int]:
        return list(set(nums1) & set(nums2))

Time O(n + m) · Space O(n + m). Contrast with LC 350, where counts matter and a set is not enough.

7 LC 350Intersection of Two Arrays II Easy Frequency map · overlap with multiplicity

Problem. Return the intersection including duplicates: each element appears as many times as it does in both. LeetCode 350 ↗

Clarify: Keep multiplicity (min of the two counts)? (Yes.) Order matters? (No.)

Hint 1
A set loses counts. You need how many times each value appears.
Hint 2
Count one array, then walk the other spending from those counts.

How to think about it Because multiplicity matters, use a frequency map instead of a set. Count the first array; for each value in the second, if its count is positive, take it and decrement. That yields the min of the two counts per value.

intersect_ii.py
from typing import List
from collections import Counter

class Solution:
    def intersect(self, nums1: List[int], nums2: List[int]) -> List[int]:
        counts = Counter(nums1)
        out = []
        for x in nums2:
            if counts[x] > 0:
                out.append(x)
                counts[x] -= 1
        return out

Time O(n + m) · Space O(min(n, m)). The count-and-spend idiom is the same as Ransom Note.

8 LC 387First Unique Character in a String Easy Frequency map · then a second scan

Problem. Return the index of the first character that appears exactly once, or −1. LeetCode 387 ↗

Clarify: First by index, not by value? (Yes.) Lowercase only? (Yes.)

Hint 1
You need to know each character's total count before deciding.
Hint 2
Count in one pass, then scan again for the first character with count 1.

How to think about it Two passes. First build the frequency map of all characters. Then walk the string again in order and return the index of the first character whose count is 1 — order is preserved because you re-scan the original string.

first_unique.py
from collections import Counter

class Solution:
    def firstUniqChar(self, s: str) -> int:
        freq = Counter(s)
        for i, ch in enumerate(s):
            if freq[ch] == 1:
                return i
        return -1

Time O(n) · Space O(1). The 'count then re-scan' shape recurs whenever a decision needs global counts.

9 LC 202Happy Number Easy Seen set · detect a cycle

Problem. Repeatedly replace n with the sum of the squares of its digits. Return whether it reaches 1. LeetCode 202 ↗

Clarify: What if it loops forever? (It cycles — detect the repeat.) n is a positive int? (Yes.)

Hint 1
The process either reaches 1 or falls into a repeating cycle.
Hint 2
Track numbers you've seen; if one repeats, you're in a loop and the answer is False.

How to think about it This is cycle detection with a set. Keep transforming n; store every value seen. If you reach 1 it's happy; if you revisit a number you're stuck in a loop, so return False. (Floyd's fast/slow pointers give an O(1)-space alternative.)

happy_number.py
class Solution:
    def isHappy(self, n: int) -> bool:
        seen = set()
        while n != 1 and n not in seen:
            seen.add(n)
            n = sum(int(d) ** 2 for d in str(n))
        return n == 1

Time O(log n) per step, bounded total · Space O(1) practically (values stay small). The set turns 'infinite loop?' into a membership check.

10 LC 205Isomorphic Strings Easy Two maps · enforce a bijection

Problem. Return whether s and t are isomorphic: characters of s can be consistently replaced to get t (one-to-one). LeetCode 205 ↗

Clarify: Mapping must be one-to-one (no two chars map to the same target)? (Yes.) Same length required? (Yes.)

Hint 1
A single map s→t isn't enough: two different s-chars could map to the same t-char.
Hint 2
Keep two maps, s→t and t→s, and check both stay consistent.

How to think about it A consistent one-to-one replacement is a bijection, which needs mappings in both directions. Walk the paired characters; if either map already binds a character to a different partner, it's not isomorphic. Otherwise record both bindings.

isomorphic.py
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        s_to_t, t_to_s = {}, {}
        for a, b in zip(s, t):
            if a in s_to_t and s_to_t[a] != b:
                return False
            if b in t_to_s and t_to_s[b] != a:
                return False
            s_to_t[a] = b
            t_to_s[b] = a
        return True

Time O(n) · Space O(1) (bounded alphabet). Word Pattern (LC 290) is the same idea over words.

11 LC 290Word Pattern Easy Two maps · bijection between letters and words

Problem. Given a pattern and a sentence s, return whether the words follow the pattern one-to-one. LeetCode 290 ↗

Clarify: Bijection both ways? (Yes.) Split s on spaces? (Yes.) Counts must match? (Yes.)

Hint 1
Same trap as Isomorphic Strings — enforce the mapping in both directions.
Hint 2
Map each pattern letter to a word and each word to a letter; reject any conflict.

How to think about it Split the sentence into words and pair them with the pattern letters. Maintain letter→word and word→letter maps; if either already disagrees with the current pair, fail. A length check up front handles mismatched counts.

word_pattern.py
class Solution:
    def wordPattern(self, pattern: str, s: str) -> bool:
        words = s.split()
        if len(pattern) != len(words):
            return False
        p_to_w, w_to_p = {}, {}
        for c, w in zip(pattern, words):
            if p_to_w.get(c, w) != w or w_to_p.get(w, c) != c:
                return False
            p_to_w[c] = w
            w_to_p[w] = c
        return True

Time O(n) · Space O(n). Using dict.get(key, current) compactly checks 'unseen, or already matches'.

12 LC 219Contains Duplicate II Easy Last-seen index map · window check

Problem. Return whether there are two equal values whose indices differ by at most k. LeetCode 219 ↗

Clarify: Indices within k of each other? (Yes — |i − j| ≤ k.) Any pair, not just adjacent? (Any.)

Hint 1
For each value, only the most recent index matters.
Hint 2
Store value → last index; when you see a repeat, check the index gap against k.

How to think about it Keep a map from each value to the last index where it appeared. On seeing a value again, if the gap to its previous index is ≤ k, return True; otherwise update the stored index to the current one.

contains_dup_ii.py
from typing import List

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        last = {}                              # value -> last index seen
        for i, x in enumerate(nums):
            if x in last and i - last[x] <= k:
                return True
            last[x] = i
        return False

Time O(n) · Space O(n). Storing only the latest index is what makes the window check correct.

13 LC 1512Number of Good Pairs Easy Running frequency · count pairs on the fly

Problem. Count pairs (i, j) with i < j and nums[i] == nums[j]. LeetCode 1512 ↗

Clarify: Ordered pairs with i < j? (Yes.) Small array? (Yes — but O(n) is easy.)

Hint 1
When you reach a value, how many earlier equal values can it pair with?
Hint 2
Exactly the count of that value seen so far — add it, then increment the count.

How to think about it Each new occurrence of a value forms a good pair with every earlier occurrence. So keep a running count per value: before counting the current one, add how many you've already seen, then bump the count.

good_pairs.py
from typing import List
from collections import defaultdict

class Solution:
    def numIdenticalPairs(self, nums: List[int]) -> int:
        seen = defaultdict(int)
        pairs = 0
        for x in nums:
            pairs += seen[x]                   # each earlier equal value pairs with x
            seen[x] += 1
        return pairs

Time O(n) · Space O(n). The 'add-then-increment' order avoids counting a value with itself.

14 LC 594Longest Harmonious Subsequence Easy Frequency map · pair adjacent values

Problem. A harmonious sequence has max − min exactly 1. Return the length of the longest harmonious subsequence. LeetCode 594 ↗

Clarify: Subsequence (any order, pick freely)? (Yes.) Difference exactly 1, not ≤ 1? (Exactly 1.)

Hint 1
Order doesn't matter for a subsequence, only counts do.
Hint 2
For each value v present, if v+1 is also present, the best sequence uses all of both.

How to think about it Count every value. A harmonious subsequence must consist of some value v and v+1 only, so its length is freq[v] + freq[v+1] whenever both exist. Take the maximum over all such adjacent pairs.

harmonious.py
from typing import List
from collections import Counter

class Solution:
    def findLHS(self, nums: List[int]) -> int:
        freq = Counter(nums)
        best = 0
        for v in freq:
            if v + 1 in freq:
                best = max(best, freq[v] + freq[v + 1])
        return best

Time O(n) · Space O(n). Reducing a 'subsequence' problem to pure counts is the insight.

15 LC 496Next Greater Element I Easy Map + monotonic stack

Problem. For each value in nums1 (a subset of nums2), find the next greater element to its right in nums2; −1 if none. LeetCode 496 ↗

Clarify: All values distinct? (Yes.) nums1 is a subset of nums2? (Yes.)

Hint 1
Precompute, for every value in nums2, its next greater element.
Hint 2
A decreasing stack does this in one pass: when a bigger value arrives, it's the answer for everything smaller on the stack.

How to think about it Sweep nums2 with a stack of values still waiting for a bigger neighbour. When the current value exceeds the stack top, pop and record 'next greater = current' in a map. Then answer each nums1 query with an O(1) map lookup.

next_greater.py
from typing import List

class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        nxt = {}                               # value -> next greater value
        stack = []
        for x in nums2:
            while stack and stack[-1] < x:
                nxt[stack.pop()] = x
            stack.append(x)
        return [nxt.get(x, -1) for x in nums1]

Time O(n + m) · Space O(n). The map decouples the precomputation from the queries — a common hashing + stack combo (Ch 08).

16 LC 705Design HashSet Easy Design · buckets + modulo (chaining)

Problem. Implement a hash set with add, remove, and contains — without a built-in set. LeetCode 705 ↗

Clarify: Keys are non-negative ints? (Yes.) Collisions must be handled? (Yes — chaining.)

Hint 1
Spread keys across many buckets with key % n.
Hint 2
Each bucket is a small list; two keys landing in the same bucket (a collision) just coexist there.

How to think about it This is how a hash set works under the hood. Pick a bucket count (a prime reduces clustering) and hash each key with modulo into a bucket. Each bucket is a list; add/remove/contains scan only that short list — separate chaining for collisions.

my_hashset.py
class MyHashSet:
    def __init__(self):
        self.n = 1009                          # a prime reduces clustering
        self.buckets = [[] for _ in range(self.n)]
    def add(self, key: int) -> None:
        b = self.buckets[key % self.n]
        if key not in b:
            b.append(key)
    def remove(self, key: int) -> None:
        b = self.buckets[key % self.n]
        if key in b:
            b.remove(key)
    def contains(self, key: int) -> bool:
        return key in self.buckets[key % self.n]

Time O(1) average, O(n) worst if everything collides · Space O(n). Building it once makes 'why is a set O(1)?' concrete.

17 LC 706Design HashMap Easy Design · buckets of key–value pairs

Problem. Implement a hash map with put, get, and remove — without a built-in dict. LeetCode 706 ↗

Clarify: get returns −1 if absent? (Yes.) put overwrites an existing key? (Yes.)

Hint 1
Same bucket idea as Design HashSet, but each entry stores a (key, value) pair.
Hint 2
put updates in place if the key exists, else appends; get/remove scan the bucket.

How to think about it Identical structure to the HashSet, but buckets hold (key, value) pairs. put searches the bucket to overwrite an existing key or appends a new pair; get and remove scan the bucket by key. Modulo hashing spreads keys across buckets.

my_hashmap.py
class MyHashMap:
    def __init__(self):
        self.n = 1009
        self.buckets = [[] for _ in range(self.n)]
    def put(self, key: int, value: int) -> None:
        b = self.buckets[key % self.n]
        for i, (k, _) in enumerate(b):
            if k == key:
                b[i] = (key, value)
                return
        b.append((key, value))
    def get(self, key: int) -> int:
        for k, v in self.buckets[key % self.n]:
            if k == key:
                return v
        return -1
    def remove(self, key: int) -> None:
        b = self.buckets[key % self.n]
        for i, (k, _) in enumerate(b):
            if k == key:
                del b[i]
                return

Time O(1) average · Space O(n). Real dicts also resize when buckets fill — mention that as a follow-up.

18 LC 49Group Anagrams Medium Grouping by key · a canonical signature

Problem. Group the strings so that anagrams are together. LeetCode 49 ↗

Clarify: Output order free? (Yes.) Lowercase only? (Yes.)

Hint 1
Anagrams need a shared 'signature' that ignores letter order.
Hint 2
The sorted letters (or a 26-length count) make a key; bucket words under it.

How to think about it The grouping-by-key pattern. Map each word to a canonical key that all its anagrams share — the sorted tuple of its letters. A dict of key → list collects the groups in one pass. (A 26-length count tuple is an O(n) key alternative to sorting.)

group_anagrams.py
from typing import List
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)
        for w in strs:
            key = tuple(sorted(w))             # anagrams share a sorted key
            groups[key].append(w)
        return list(groups.values())

Time O(n·k log k) with sorted keys · Space O(n·k). Choosing the right canonical key is the whole trick.

19 LC 347Top K Frequent Elements Medium Frequency map + selection

Problem. Return the k most frequent elements. LeetCode 347 ↗

Clarify: k is valid (1 ≤ k ≤ #distinct)? (Yes.) Ties broken arbitrarily? (Yes.)

Hint 1
First count frequencies with a map.
Hint 2
Then pick the top k — a heap is O(n log k); bucket sort by frequency is O(n).

How to think about it Count with a frequency map, then select the top k. Counter.most_common(k) handles the selection; under the hood a heap gives O(n log k), and bucket sort (index by frequency 0..n) gives O(n) when you want to state the optimum.

top_k.py
from typing import List
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        freq = Counter(nums)
        return [v for v, _ in freq.most_common(k)]

Time O(n log k) · Space O(n). Know the O(n) bucket-sort variant for the follow-up.

20 LC 128Longest Consecutive Sequence Medium Set · count only from run starts

Problem. Return the length of the longest run of consecutive integers, in O(n) (unsorted input). LeetCode 128 ↗

Clarify: O(n) expected (not O(n log n) sort)? (Yes.) Duplicates? (A set absorbs them.)

Hint 1
Put everything in a set for O(1) membership.
Hint 2
Start counting a run only from a value whose predecessor is absent — that's a run's beginning.

How to think about it Load all values into a set. For each value that starts a run (no x−1 present), walk forward x+1, x+2, … counting the streak. The 'only start from a beginning' guard means each element is visited at most twice, so it's O(n).

longest_consecutive.py
from typing import List

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        s = set(nums)
        best = 0
        for x in s:
            if x - 1 not in s:                 # only start from a run's beginning
                length = 1
                while x + length in s:
                    length += 1
                best = max(best, length)
        return best

Time O(n) · Space O(n). Without the run-start guard it degrades badly — that guard is the point.

21 LC 560Subarray Sum Equals K Medium Prefix sum + map

Problem. Count the contiguous subarrays whose sum equals k. LeetCode 560 ↗

Clarify: Negatives allowed? (Yes — rules out sliding window.) Count, not list? (Count.)

Hint 1
A subarray sum is prefix[j] − prefix[i]; you want that to equal k.
Hint 2
Track counts of prefix sums seen; at each step add how many earlier prefixes equal running − k.

How to think about it The prefix-sum + map pattern. A subarray ending here sums to k whenever some earlier prefix equals running − k. Keep a map of prefix-sum → occurrences (seeded with {0:1}) and add the needed count at each step.

subarray_sum_k.py
from typing import List
from collections import defaultdict

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        seen = defaultdict(int)
        seen[0] = 1
        prefix = count = 0
        for x in nums:
            prefix += x
            count += seen[prefix - k]
            seen[prefix] += 1
        return count

Time O(n) · Space O(n). Seeding {0:1} lets a prefix equal to k count on its own.

22 LC 36Valid Sudoku Medium Multiple seen sets · rows, cols, boxes

Problem. Return whether a partially filled 9×9 board violates any Sudoku rule (no repeat in a row, column, or 3×3 box). LeetCode 36 ↗

Clarify: Only check the filled cells? (Yes.) Board is always 9×9? (Yes.)

Hint 1
Each digit must be unique within its row, its column, and its 3×3 box.
Hint 2

How to think about it Run three families of seen-sets simultaneously. For each filled cell, check its value against the sets for its row, column, and box (keyed by (r//3, c//3)). Any hit is a violation; otherwise record it in all three.

valid_sudoku.py
from typing import List
from collections import defaultdict

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        rows = defaultdict(set)
        cols = defaultdict(set)
        boxes = defaultdict(set)
        for r in range(9):
            for c in range(9):
                v = board[r][c]
                if v == ".":
                    continue
                b = (r // 3, c // 3)
                if v in rows[r] or v in cols[c] or v in boxes[b]:
                    return False
                rows[r].add(v)
                cols[c].add(v)
                boxes[b].add(v)
        return True

Time O(81) = O(1) · Space O(1). The box key (r//3, c//3) is the neat part.

23 LC 380Insert Delete GetRandom O(1) Medium Map + array · swap-with-last delete

Problem. Design a set with average O(1) insert, remove, and getRandom. LeetCode 380 ↗

Clarify: All three O(1) average? (Yes.) getRandom uniform? (Yes.) Values unique? (Yes.)

Hint 1
getRandom in O(1) needs a contiguous array to index into. But deleting from the middle of an array is O(n)…
Hint 2
…unless you swap the target with the last element then pop. A dict maps value → array index.

How to think about it Pair an array (for O(1) random indexing) with a dict of value → index. Insert appends and records the index. Remove overwrites the target's slot with the last element, fixes that element's index, and pops the tail — O(1) instead of a shift. getRandom picks a random slot.

randomized_set.py
import random

class RandomizedSet:
    def __init__(self):
        self.pos = {}                          # value -> index in self.vals
        self.vals = []
    def insert(self, val: int) -> bool:
        if val in self.pos:
            return False
        self.pos[val] = len(self.vals)
        self.vals.append(val)
        return True
    def remove(self, val: int) -> bool:
        if val not in self.pos:
            return False
        idx = self.pos[val]
        last = self.vals[-1]
        self.vals[idx] = last                  # move last into the gap
        self.pos[last] = idx
        self.vals.pop()
        del self.pos[val]
        return True
    def getRandom(self) -> int:
        return random.choice(self.vals)

All ops O(1) average · Space O(n). The swap-with-last delete is the reusable trick.

24 LC 4544Sum II Medium Meet in the middle · sum the halves

Problem. Given four arrays, count tuples (i, j, k, l) with a[i] + b[j] + c[k] + d[l] == 0. LeetCode 454 ↗

Clarify: Count tuples across the four arrays? (Yes.) Arrays equal length n? (Yes.)

Hint 1
Brute force is O(n⁴). Split the four arrays into two halves.
Hint 2
Count all sums of the first two arrays in a map; for each sum of the last two, look up its negation.

How to think about it Meet in the middle. Precompute every pair-sum a+b into a frequency map (O(n²)). Then for each pair-sum c+d, add the count of −(c+d) from the map. Two O(n²) phases instead of one O(n⁴).

four_sum_ii.py
from typing import List
from collections import Counter

class Solution:
    def fourSumCount(self, nums1: List[int], nums2: List[int], nums3: List[int], nums4: List[int]) -> int:
        first = Counter(a + b for a in nums1 for b in nums2)
        count = 0
        for c in nums3:
            for d in nums4:
                count += first[-(c + d)]       # need a+b == -(c+d)
        return count

Time O(n²) · Space O(n²). Splitting the search space in half and hashing one side is the pattern.

25 LC 3Longest Substring Without Repeating Characters Medium Sliding window + last-index map

Problem. Return the length of the longest substring without repeating characters. LeetCode 3 ↗

Clarify: Substring (contiguous), not subsequence? (Yes.) Any characters, not just letters? (Yes.)

Hint 1
Keep a window with no repeats; when a repeat appears, shrink from the left.
Hint 2
Store each character's last index so you can jump the window start past the previous occurrence.

How to think about it A sliding window whose left edge is tracked by a last-seen-index map. When the current character was seen at or after the window start, jump start to just past its previous position. The window [start, i] is always repeat-free, so track its max length.

longest_substring.py
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}                              # char -> last index
        start = best = 0
        for i, ch in enumerate(s):
            if ch in last and last[ch] >= start:
                start = last[ch] + 1           # jump past the repeat
            last[ch] = i
            best = max(best, i - start + 1)
        return best

Time O(n) · Space O(min(n, alphabet)). Jumping start (vs stepping) keeps it a single pass.

26 LC 438Find All Anagrams in a String Medium Fixed-window frequency match

Problem. Return the start indices of every substring of s that is an anagram of p. LeetCode 438 ↗

Clarify: Substrings of length |p|? (Yes.) Lowercase only? (Yes.)

Hint 1
Slide a window of length |p| across s and compare letter counts to p's counts.
Hint 2
Update the window count in O(1) per step: add the entering char, drop the leaving char.

How to think about it Maintain a frequency map for a fixed-size window of length |p|. Each step adds the new character and removes the one sliding out (deleting zero entries so equality checks match Counter(p)). Whenever the window map equals p's, record the start index.

find_anagrams.py
from typing import List
from collections import Counter

class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        need = Counter(p)
        window = Counter()
        L = len(p)
        res = []
        for i, ch in enumerate(s):
            window[ch] += 1
            if i >= L:
                left = s[i - L]
                window[left] -= 1
                if window[left] == 0:
                    del window[left]
            if window == need:
                res.append(i - L + 1)
        return res

Time O(n) · Space O(1) (≤26 keys). Deleting zeroed keys is what lets == compare the two Counters cleanly.

27 LC 567Permutation in String Medium Fixed-window frequency match (boolean)

Problem. Return whether s2 contains a permutation of s1 as a substring. LeetCode 567 ↗

Clarify: Contiguous substring that is a permutation? (Yes.) Lowercase only? (Yes.)

Hint 1
A permutation of s1 is any window with exactly s1's letter counts.
Hint 2
Same sliding-window count-match as Find All Anagrams, but stop at the first match.

How to think about it Identical machinery to LC 438: slide a window of length |s1| over s2, keeping a frequency map updated in O(1) per step. The moment the window map equals s1's counts, a permutation exists — return True.

permutation_in_string.py
from collections import Counter

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        need = Counter(s1)
        window = Counter()
        L = len(s1)
        for i, ch in enumerate(s2):
            window[ch] += 1
            if i >= L:
                left = s2[i - L]
                window[left] -= 1
                if window[left] == 0:
                    del window[left]
            if window == need:
                return True
        return False

Time O(n) · Space O(1). The anagram-window template solves a whole family of substring problems (Ch 07).

28 LC 974Subarray Sums Divisible by K Medium Prefix remainder + map

Problem. Count contiguous subarrays whose sum is divisible by k. LeetCode 974 ↗

Clarify: Negatives allowed? (Yes — normalise the remainder.) Count, not list? (Count.)

Hint 1
A subarray sum is divisible by k when two prefix sums share the same remainder mod k.
Hint 2
Count occurrences of each remainder as you go; add the running count of the current remainder.

How to think about it A variant of prefix-sum + map keyed on the remainder mod k. Two prefixes with the same remainder bound a subarray divisible by k. Count remainders seen (seed {0:1}) and add the current remainder's count each step. Python's % keeps remainders non-negative, handling negatives for free.

subarrays_div_k.py
from typing import List
from collections import defaultdict

class Solution:
    def subarraysDivByK(self, nums: List[int], k: int) -> int:
        count = defaultdict(int)
        count[0] = 1
        prefix = res = 0
        for x in nums:
            prefix = (prefix + x) % k          # Python % is always non-negative
            res += count[prefix]
            count[prefix] += 1
        return res

Time O(n) · Space O(k). The 'same remainder ⇒ divisible difference' fact is the key.

29 LC 523Continuous Subarray Sum Medium Prefix remainder + earliest index

Problem. Return whether there is a subarray of length ≥ 2 whose sum is a multiple of k. LeetCode 523 ↗

Clarify: Length at least 2? (Yes.) A multiple includes 0·k? (Yes.)

Hint 1
Same remainder trick — two equal remainders bound a multiple-of-k subarray.
Hint 2
Store the earliest index for each remainder, and require the index gap to be ≥ 2.

How to think about it Track the running prefix sum mod k and remember the earliest index at which each remainder occurred (seed {0:-1}). When a remainder repeats and the index gap is at least 2, a valid subarray exists. Keeping the earliest index maximises the chance of a length ≥ 2 span.

continuous_subarray.py
from typing import List

class Solution:
    def checkSubarraySum(self, nums: List[int], k: int) -> bool:
        first = {0: -1}                        # remainder -> earliest index
        prefix = 0
        for i, x in enumerate(nums):
            prefix = (prefix + x) % k
            if prefix in first:
                if i - first[prefix] >= 2:     # need length >= 2
                    return True
            else:
                first[prefix] = i
        return False

Time O(n) · Space O(k). Store the first occurrence (not the last) so the length-≥-2 check can succeed.

30 LC 525Contiguous Array Medium Prefix balance + earliest index

Problem. Given a binary array, return the length of the longest subarray with equal numbers of 0s and 1s. LeetCode 525 ↗

Clarify: Equal count of 0s and 1s? (Yes.) Only 0/1 values? (Yes.)

Hint 1
Treat 0 as −1; then 'equal counts' means a subarray sum of 0.
Hint 2
Two indices with the same running balance bound such a subarray — remember each balance's first index.

How to think about it Map the problem to prefix sums by treating 0 as −1, so a balanced subarray has sum 0 — i.e. two positions with the same running balance. Record the earliest index for each balance value (seed {0:-1}) and take the largest span between equal balances.

contiguous_array.py
from typing import List

class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        first = {0: -1}                        # running balance -> earliest index
        balance = best = 0
        for i, x in enumerate(nums):
            balance += 1 if x == 1 else -1     # treat 0 as -1
            if balance in first:
                best = max(best, i - first[balance])
            else:
                first[balance] = i
        return best

Time O(n) · Space O(n). The 0→−1 reframing turns a counting problem into the prefix-sum pattern.

33 LC 299Bulls and Cows Medium Frequency map · bulls then cows

Problem. Compare a secret and a guess: 'bulls' are correct-digit-correct-place, 'cows' are correct-digit-wrong-place. Return "xAyB". LeetCode 299 ↗

Clarify: Digits can repeat? (Yes — that's why counts matter.) Same length? (Yes.)

Hint 1
Bulls are the exact positional matches — count those directly.
Hint 2
For cows, count leftover digits on each side and take the multiset overlap.

How to think about it First count bulls where the digits align. For the rest, tally the unmatched secret digits and unmatched guess digits into two frequency maps; the number of cows is the sum of the minimum counts per digit — a multiset intersection (Counter & Counter).

bulls_and_cows.py
from collections import Counter

class Solution:
    def getHint(self, secret: str, guess: str) -> str:
        bulls = sum(a == b for a, b in zip(secret, guess))
        s_left = Counter(a for a, b in zip(secret, guess) if a != b)
        g_left = Counter(b for a, b in zip(secret, guess) if a != b)
        cows = sum((s_left & g_left).values())  # multiset intersection
        return f"{bulls}A{cows}B"

Time O(n) · Space O(1) (10 digits). The & of two Counters giving the per-key minimum is the elegant part.

34 LC 811Subdomain Visit Count Medium Frequency map · accumulate over suffixes

Problem. Given counts like "9001 discuss.leetcode.com", return the visit count for every (sub)domain. LeetCode 811 ↗

Hint 2
Split on dots and, for each suffix, add the count into a map.

How to think about it Parse each entry into a count and a domain. Split the domain on dots; every suffix (from the full domain up to the top-level) is a subdomain that receives the count. Accumulate all of these in a frequency map, then format the results.

subdomain_visits.py
from typing import List
from collections import defaultdict

class Solution:
    def subdomainVisits(self, cpdomains: List[str]) -> List[str]:
        counts = defaultdict(int)
        for entry in cpdomains:
            count_str, domain = entry.split()
            count = int(count_str)

        return [f"{c} {d}" for d, c in counts.items()]

35 LC 249Group Shifted Strings Medium Grouping by key · the gap signature

Problem. Group strings that are 'shift' sequences of each other (e.g. abc → bcd → cde). LeetCode 249 ↗

Clarify: Shift wraps z→a? (Yes — mod 26.) Different lengths never group? (Correct.)

Hint 1
Two strings shift into each other iff the gaps between consecutive letters match (mod 26).
Hint 2
Use that gap tuple as the group key.

How to think about it Grouping by key again: the invariant under shifting is the sequence of differences between consecutive letters, taken mod 26. Build that tuple as the key and bucket words under it. Different lengths get different-length keys, so they never mix.

group_shifted.py
from typing import List
from collections import defaultdict

class Solution:
    def groupStrings(self, strings: List[str]) -> List[List[str]]:
        groups = defaultdict(list)
        for w in strings:
            # key = gaps between consecutive letters, mod 26
            key = tuple((ord(w[i]) - ord(w[i - 1])) % 26 for i in range(1, len(w)))
            groups[key].append(w)
        return list(groups.values())

Time O(total characters) · Space O(n). Choosing a shift-invariant signature is the same skill as Group Anagrams' sorted key.

36 LC 149Max Points on a Line Hard Slope map · reduced fractions as keys

Problem. Given points on a plane, return the maximum number that lie on the same straight line. LeetCode 149 ↗

Clarify: Points are distinct? (Yes.) Vertical lines allowed? (Yes — handle infinite slope.) Precision? (Use exact integer slopes, not floats.)

Hint 1
Fix one point; every other point defines a slope from it. Points sharing a slope are collinear with it.
Hint 2
Represent each slope as a reduced fraction (dy, dx) with a canonical sign — floats lose precision.

How to think about it For each anchor point, count how many other points share each slope, using a map. Represent slopes exactly as integer pairs reduced by their gcd and given a canonical sign so equal slopes collide as the same key. The best count for any anchor, plus the anchor itself, is the answer.

max_points.py
from typing import List
from math import gcd
from collections import defaultdict

class Solution:
    def maxPoints(self, points: List[List[int]]) -> int:
        n = len(points)
        if n <= 2:
            return n
        best = 1
        for i in range(n):
            slopes = defaultdict(int)
            for j in range(i + 1, n):
                dx = points[j][0] - points[i][0]
                dy = points[j][1] - points[i][1]
                g = gcd(dx, dy)
                dx, dy = dx // g, dy // g       # reduce the slope to lowest terms
                if dx < 0 or (dx == 0 and dy < 0):
                    dx, dy = -dx, -dy           # canonical direction
                slopes[(dx, dy)] += 1
                best = max(best, slopes[(dx, dy)] + 1)
        return best

Time O(n²) · Space O(n). Using reduced integer fractions (not float slopes) as hash keys is what makes it exact and robust.

4 · Interview playbook

  • Spot the repeated work. State the brute-force complexity first, then ask "what could I remember to avoid re-searching?" — that's usually a set or a map.
  • Name the pattern out loud: seen set, complement, frequency, grouping, prefix-sum + map, or a frequency window.
  • Say the trade-off: hashing typically buys O(1) lookups with O(n) memory. Separate the answer's output space from your auxiliary map.
  • Pick the right key. Grouping problems live or die on the canonical signature (sorted letters, gap tuple, reduced slope) — and remember only immutable values are hashable.
  • Edge cases: empty input, one element, all-duplicates, negatives (they break sliding windows but not prefix maps), and missing keys (get/defaultdict).

SDE / Python backend

Dicts and sets are everyday tools. Be fluent in Counter, defaultdict, and the prefix-sum + map trick, and be able to explain average vs worst-case O(1) and how a real hash table resizes.

6 · Review

Cheat sheet
  • "Seen before?" / dedup / membership → seen set.
  • "Two sum to a target" → complement lookup (target − x in a map).
  • Counting / anagrams / top-k → frequency map (Counter).
  • "Group items alike in some way" → grouping by a canonical key.
  • Subarray sum = k / divisible by k / equal 0s and 1s → prefix sum (or remainder/balance) + map, seed {0: ...}.
  • Anagram / permutation substring → fixed-size frequency window.
  • Bijection check (isomorphic, word pattern) → two maps, one each direction.
  • O(1) lookup costs O(n) memory — name the trade-off.

Concept checks

Why can a tuple be a dict key but a list cannot?
Tuples are smaller in memory
Keys must be hashable, and only immutable objects like tuples are — a list can change, which would break its bucket
Lists are slower to hash
A hash key's value must never change while it's in the table, or it would hash to the wrong bucket. Python enforces this by allowing only hashable (immutable) keys; lists are mutable, so they're unhashable.
In Subarray Sum Equals K, why seed the prefix-count map with {0: 1}?
So a prefix that equals k on its own (a subarray starting at index 0) is counted
To avoid a division-by-zero error
Because the array might be empty
A subarray from the start has no earlier prefix to subtract. Seeding {0:1} represents the empty prefix, so when running − k == 0 the whole prefix counts as a valid subarray.

  • I can explain why set/dict lookup is O(1) average and what a collision is.
  • I can write Two Sum with a complement map without notes.
  • I use Counter and defaultdict fluently for counting and grouping.
  • I can solve subarray-sum problems with prefix sums + a map and seed it correctly.
  • I know which values are hashable and how to build a canonical grouping key.
  • I can match an anagram/permutation with a sliding-window frequency count.
