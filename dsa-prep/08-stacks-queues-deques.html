Stacks, Queues & Deques

A stack remembers the most recent thing; a queue remembers the oldest; a deque does both ends. This chapter builds each from scratch and drills the monotonic-stack pattern that quietly solves a huge class of "next greater / previous smaller" problems — every problem has a full, tested solution in LeetCode's class Solution format.

Outcome

Use stacks for matching, parsing, and monotonic scans; use queues and deques for streaming and sliding-window extremes; and implement each structure and its classic designs cleanly.

1 · Foundations

New to these structures? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

The stack: last in, first out

A stack is a pile: you add to the top and remove from the top. The last thing pushed is the first thing popped — LIFO. Both operations are O(1). In Python a plain list is a perfect stack: append to push, pop to remove the top.

Example — a list is a stack
stack.py
stack = []
stack.append(1)     # push
stack.append(2)
stack.append(3)
print(stack[-1])    # 3   -> peek at the top
print(stack.pop())  # 3   -> remove the top
print(stack.pop())  # 2
print(stack)        # [1]
Output3
3
2
[1]
Reach for a stack whenever the problem cares about the most recent unresolved thing: matching brackets, undo, evaluating nested expressions, or "the previous element still waiting for its answer".

The queue: first in, first out

A queue is a line: you add at the back and remove from the front — FIFO. Use collections.deque, whose append and popleft are both O(1).

⚠️
Don't use a list as a queue

list.pop(0) removes from the front but is O(n) — every remaining element shifts left. In a loop that's a hidden O(n²). Always use collections.deque for FIFO.

Example — a deque is a queue (and more)
queue.py
from collections import deque

q = deque()
q.append(1); q.append(2); q.append(3)
print(q.popleft())   # 1   -> FIFO: oldest out first

# a deque is double-ended — O(1) at BOTH ends:
q.appendleft(0)      # add to the front
print(q.pop())       # 3   -> remove from the back
print(q)             # deque([0, 2])

A deque (double-ended queue) supports O(1) add/remove at both ends, so it can act as a stack, a queue, or the sliding-window tool you'll meet below.

The monotonic stack — the pattern to master

Many array problems ask, for each element, "what is the next element greater than it?" (or smaller, or the previous one). Checking every pair is O(n²). A monotonic stack — one kept sorted (increasing or decreasing) as you scan — answers all of them in O(n). The idea: keep elements that are still waiting for their answer; when a new element resolves some of them, pop and record.

Example — next greater element for each position
monotonic.py
def next_greater(nums):
    res = [-1] * len(nums)
    stack = []                      # indices whose answer is unknown
    for i, v in enumerate(nums):
        while stack and nums[stack[-1]] < v:
            res[stack.pop()] = v     # v is the next greater for that index
        stack.append(i)
    return res

print(next_greater([2, 1, 2, 4, 3]))   # [4, 2, 4, -1, -1]
Output[4, 2, 4, -1, -1]

Each index is pushed once and popped once, so the whole scan is O(n) despite the inner while. Daily Temperatures, stock spans, histograms, and 132-patterns are all this pattern with a twist.

The monotonic deque: window extremes

The same monotonic idea on a deque gives the max (or min) of a sliding window in O(1) amortised: keep indices with decreasing values, drop the front when it leaves the window, and the front is always the current maximum. It's the workhorse behind Sliding Window Maximum.

💡
Which structure?

Stack — most-recent-first, matching, nested parsing, next-greater. Queue — oldest-first, streaming, BFS (Ch 12/15). Deque — both ends, sliding-window max/min. And a plain counter can replace a stack when you only need its size (as in balancing parentheses).

1 LC 20Valid Parentheses Easy Matching stack · push opens, match closes

Problem. Given a string of brackets ()[]{}, return whether every bracket is properly opened and closed in order. LeetCode 20 ↗

Clarify: Only bracket characters? (Yes.) Must nesting order match? (Yes.) Empty string is valid? (Yes.)

Hint 1
The most recent unmatched opener must match the next closer — that's last-in-first-out.
Hint 2
Push each opener; on a closer, the top of the stack must be its partner.

How to think about it The founding stack pattern. Push every opening bracket. On a closing bracket, the correct match is whatever is on top of the stack (the most recent opener) — pop it if it matches, else fail. A non-empty stack at the end means unclosed brackets.

valid_parens.py
class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {")": "(", "]": "[", "}": "{"}
        stack = []
        for ch in s:
            if ch in pairs:                       # a closing bracket
                if not stack or stack[-1] != pairs[ch]:
                    return False
                stack.pop()
            else:
                stack.append(ch)
        return not stack

Time O(n) · Space O(n). LIFO matching is the reason a stack exists — the same idea drives every nesting/parsing problem here.

2 LC 1047Remove All Adjacent Duplicates In String Easy Cancelling stack

Problem. Repeatedly remove two adjacent equal characters until none remain; return the result. LeetCode 1047 ↗

Clarify: Remove all such pairs, cascading? (Yes.) Lowercase only? (Yes.)

Hint 1
A new character cancels the previous one if they're equal.
Hint 2
A stack naturally exposes 'the previous surviving character'.

How to think about it Push characters onto a stack; if the incoming character equals the top, they cancel (pop instead of push). The stack always holds the reduced string so far, and cascading removals happen for free.

remove_adjacent.py
class Solution:
    def removeDuplicates(self, s: str) -> str:
        stack = []
        for ch in s:
            if stack and stack[-1] == ch:
                stack.pop()                       # cancel the adjacent pair
            else:
                stack.append(ch)
        return "".join(stack)

Time O(n) · Space O(n). 'Cancel against the top' is a recurring stack motif (see Make The String Great).

3 LC 1021Remove Outermost Parentheses Easy Depth counter

Problem. Split a valid parentheses string into primitive pieces and remove the outermost parentheses of each. LeetCode 1021 ↗

Clarify: Input is always valid? (Yes.) A primitive is a minimal balanced piece? (Yes.)

Hint 1
Track the nesting depth as you scan.
Hint 2
Keep a bracket only when it isn't at the outermost level.

How to think about it You don't even need an explicit stack — a depth counter suffices. Increment on '(' and decrement on ')'. Keep a '(' only when depth is already > 0, and a ')' only when depth stays > 0 after decrementing, which skips exactly the outermost pair of each primitive.

remove_outer.py
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        res = []
        depth = 0
        for ch in s:
            if ch == "(":
                if depth > 0:
                    res.append(ch)               # keep only inner '('
                depth += 1
            else:
                depth -= 1
                if depth > 0:
                    res.append(ch)               # keep only inner ')'
        return "".join(res)

Time O(n) · Space O(n) output. A counter is a stack when you only need its size — a useful simplification to recognise.

4 LC 682Baseball Game Easy Stack of running scores

Problem. Process operations that push a score, double the last, sum the last two, or cancel the last; return the total. LeetCode 682 ↗

Clarify: Operations are '+', 'D', 'C', or an integer? (Yes.) Always valid (enough prior scores)? (Yes.)

Hint 1
Each operation refers to the most recent score(s).
Hint 2
A stack lets you read and modify the recent history in O(1).

How to think about it Keep a stack of valid scores. Each operation reads the top one or two entries: 'C' pops, 'D' pushes double the top, '+' pushes the sum of the top two, and a number pushes itself. The answer is the sum of the stack.

baseball.py
from typing import List

class Solution:
    def calPoints(self, operations: List[str]) -> int:
        stack = []
        for op in operations:
            if op == "+":
                stack.append(stack[-1] + stack[-2])
            elif op == "D":
                stack.append(2 * stack[-1])
            elif op == "C":
                stack.pop()
            else:
                stack.append(int(op))
        return sum(stack)

Time O(n) · Space O(n). A gentle 'stack as recent history' warm-up.

5 LC 921Minimum Add to Make Parentheses Valid Easy Balance counters

Problem. Return the minimum number of brackets to insert to make the string valid. LeetCode 921 ↗

Clarify: Insert anywhere? (Yes.) Only '(' and ')'? (Yes.)

Hint 1
Track how many '(' are currently unmatched.
Hint 2
A ')' with no open '(' to match needs a new '(' — count those separately.

How to think about it Two counters replace the stack. open_count tracks unmatched '('; a ')' matches one if available, otherwise it needs an inserted '(' (count it in need). The answer is the leftover opens plus the unmatched closers.

min_add_valid.py
class Solution:
    def minAddToMakeValid(self, s: str) -> int:
        open_count = 0        # unmatched '('
        need = 0              # unmatched ')'
        for ch in s:
            if ch == "(":
                open_count += 1
            elif open_count > 0:
                open_count -= 1
            else:
                need += 1
        return open_count + need

Time O(n) · Space O(1). When a matching stack would only hold identical op, a counter is enough.

6 LC 1544Make The String Great Easy Cancelling stack (case pairs)

Problem. Repeatedly remove adjacent pairs of the same letter in opposite cases (e.g. 'aA'); return the result. LeetCode 1544 ↗

Clarify: Only same-letter opposite-case pairs cancel? (Yes.) Cascading removals? (Yes.)

Hint 1
Same idea as removing adjacent duplicates, but the cancel rule is 'same letter, different case'.
Hint 2
Compare the incoming character to the stack top with a case-insensitive test.

How to think about it Push characters; cancel with the top when it's the same letter in the opposite case (top != ch but top.lower() == ch.lower()). The stack holds the good string so far.

make_good.py
class Solution:
    def makeGood(self, s: str) -> str:
        stack = []
        for ch in s:
            if stack and stack[-1] != ch and stack[-1].lower() == ch.lower():
                stack.pop()                       # same letter, opposite case
            else:
                stack.append(ch)
        return "".join(stack)

Time O(n) · Space O(n). Just a different cancel predicate on the same cancelling-stack template.

7 LC 155Min Stack Easy Design · track the min alongside each value

Problem. Design a stack with O(1) push, pop, top, and getMin. LeetCode 155 ↗

Clarify: getMin is O(1)? (Yes.) Duplicates allowed? (Yes.)

Hint 1
A separate scan for the min would be O(n). Store the min with each element.
Hint 2
Each entry remembers the minimum of the stack up to and including it.

How to think about it Store pairs (value, min-so-far). When pushing, the new min is the smaller of the incoming value and the current top's min. Then getMin just reads the top pair's second field — no scanning.

min_stack.py
class MinStack:
    def __init__(self):
        self.stack = []                           # (value, min-so-far)
    def push(self, val: int) -> None:
        m = val if not self.stack else min(val, self.stack[-1][1])
        self.stack.append((val, m))
    def pop(self) -> None:
        self.stack.pop()
    def top(self) -> int:
        return self.stack[-1][0]
    def getMin(self) -> int:
        return self.stack[-1][1]

All ops O(1) · Space O(n). Carrying auxiliary state per entry is the trick for O(1) aggregate queries.

8 LC 232Implement Queue using Stacks Easy Design · two stacks, amortised O(1)

Problem. Implement a FIFO queue using only two stacks. LeetCode 232 ↗

Clarify: Amortised O(1) per operation? (Yes.) Only stack operations allowed? (Yes.)

Hint 1
One stack takes pushes; another serves pops in reversed order.
Hint 2
Only move elements between stacks when the output stack is empty.

How to think about it An in stack receives pushes; an out stack serves the front. When out is empty, pour in into it (reversing order so the oldest is on top). Each element is moved at most once, giving amortised O(1).

queue_using_stacks.py
class MyQueue:
    def __init__(self):
        self.inp = []
        self.out = []
    def push(self, x: int) -> None:
        self.inp.append(x)
    def pop(self) -> int:
        self.peek()
        return self.out.pop()
    def peek(self) -> int:
        if not self.out:                          # flip only when out is empty
            while self.inp:
                self.out.append(self.inp.pop())
        return self.out[-1]
    def empty(self) -> bool:
        return not self.inp and not self.out

Amortised O(1) · Space O(n). Flipping only when out empties is what keeps the amortised bound.

9 LC 225Implement Stack using Queues Easy Design · rotate a single queue

Problem. Implement a LIFO stack using queue operations only. LeetCode 225 ↗

Clarify: One queue or two? (One suffices.) Which op is O(n)? (push, by design.)

Hint 1
After enqueuing, rotate the queue so the newest element sits at the front.
Hint 2
Then dequeue always returns the most recent element.

How to think about it Use one queue. On push, append the value, then rotate the queue by moving every earlier element to the back — the new value ends up at the front. pop/top then read the front, giving stack (LIFO) order.

stack_using_queues.py
from collections import deque

class MyStack:
    def __init__(self):
        self.q = deque()
    def push(self, x: int) -> None:
        self.q.append(x)
        for _ in range(len(self.q) - 1):          # rotate so newest is at front
            self.q.append(self.q.popleft())
    def pop(self) -> int:
        return self.q.popleft()
    def top(self) -> int:
        return self.q[0]
    def empty(self) -> bool:
        return not self.q

push O(n), others O(1) · Space O(n). The mirror of Queue-using-Stacks: you pay the cost on push instead of pop.

10 LC 933Number of Recent Calls Easy Sliding queue over a time window

Problem. Count how many pings occurred within the last 3000 ms of the current one. LeetCode 933 ↗

Clarify: Pings arrive with strictly increasing timestamps? (Yes.) Window is [t−3000, t]? (Yes.)

Hint 1
Old pings outside the window never matter again.
Hint 2
A queue of timestamps: drop from the front anything older than t − 3000.

How to think about it Keep timestamps in a queue. On each ping(t), enqueue t, then pop from the front while the oldest is older than t − 3000. The queue's size is the answer — a sliding time window over a stream.

recent_counter.py
from collections import deque

class RecentCounter:
    def __init__(self):
        self.q = deque()
    def ping(self, t: int) -> int:
        self.q.append(t)
        while self.q[0] < t - 3000:               # drop calls older than 3000ms
            self.q.popleft()
        return len(self.q)

Amortised O(1) · Space O(window). A queue is the natural structure for 'events within the last T'.

11 LC 150Evaluate Reverse Polish Notation Medium Stack evaluation · postfix

Problem. Evaluate an arithmetic expression given in Reverse Polish (postfix) notation. LeetCode 150 ↗

Clarify: Division truncates toward zero? (Yes.) Tokens are ints or + − * /? (Yes.)

Hint 1
Operands wait on a stack until an operator arrives.
Hint 2
An operator pops its two operands and pushes the result.

How to think about it Scan tokens: push numbers; on an operator, pop the two most recent operands, apply the operator, and push the result. Postfix needs no precedence handling — the order is already explicit. Use int(a / b) for truncation toward zero.

eval_rpn.py
from typing import List

class Solution:
    def evalRPN(self, tokens: List[str]) -> int:
        stack = []
        for tok in tokens:
            if tok in ("+", "-", "*", "/"):
                b = stack.pop(); a = stack.pop()
                if tok == "+":
                    stack.append(a + b)
                elif tok == "-":
                    stack.append(a - b)
                elif tok == "*":
                    stack.append(a * b)
                else:
                    stack.append(int(a / b))      # truncate toward zero
            else:
                stack.append(int(tok))
        return stack[0]

Time O(n) · Space O(n). Postfix + stack is how calculators and VMs evaluate expressions.

12 LC 394Decode String Medium Stack parsing · nested repeats

Problem. Decode a string like 3[a2[c]] where k[...] repeats the bracketed part k times. LeetCode 394 ↗

Clarify: Brackets nest? (Yes — needs a stack.) k may be multi-digit? (Yes.)

Hint 1
A '[' opens a nested context; a ']' resolves it by repeating.
Hint 2
Push the current string and count on '['; pop and combine on ']'.

How to think about it Track the current string and current number. On '[', push (current string, k) and reset. On ']', pop them and set current = previous + current × k. Digits build the multiplier; letters append. The stack handles arbitrary nesting.

decode_string.py
class Solution:
    def decodeString(self, s: str) -> str:
        stack = []
        cur, num = "", 0
        for ch in s:
            if ch.isdigit():
                num = num * 10 + int(ch)
            elif ch == "[":
                stack.append((cur, num))
                cur, num = "", 0
            elif ch == "]":
                prev, k = stack.pop()
                cur = prev + cur * k
            else:
                cur += ch
        return cur

Time O(output) · Space O(depth). 'Push context on open, resolve on close' is the parsing template.

13 LC 71Simplify Path Medium Stack of path components

Problem. Simplify a Unix-style absolute path (handle ., .., and repeated slashes). LeetCode 71 ↗

Clarify: '..' goes up, '.' stays, '//' collapses? (Yes.) Always absolute? (Yes.)

Hint 1
Split on '/'; ignore '' and '.'.
Hint 2
'..' pops a directory; a real name pushes.

How to think about it Split on slashes and use a stack of directory names. Skip empty pieces and '.', pop on '..' (if possible), and push real names. Join the stack with slashes for the canonical path.

simplify_path.py
class Solution:
    def simplifyPath(self, path: str) -> str:
        stack = []
        for part in path.split("/"):
            if part == "" or part == ".":
                continue
            elif part == "..":
                if stack:
                    stack.pop()
            else:
                stack.append(part)
        return "/" + "/".join(stack)

Time O(n) · Space O(n). A stack models 'go up / go down' navigation exactly.

14 LC 856Score of Parentheses Medium Stack of frame scores

Problem. Score a balanced parentheses string: () = 1, AB = A + B, (A) = 2·A. LeetCode 856 ↗

Clarify: Input always balanced? (Yes.) Scores combine as defined? (Yes.)

Hint 1
Each open bracket starts a new inner score frame.
Hint 2
On close, the inner score becomes 2× it (or 1 if empty) and adds to the enclosing frame.

How to think about it Keep a stack where each entry is the accumulated score of the current depth. '(' pushes a fresh 0. ')' pops the inner score v and adds max(2v, 1) to the frame below — 1 for an empty (), doubled otherwise.

score_parens.py
class Solution:
    def scoreOfParentheses(self, s: str) -> int:
        stack = [0]                               # score of the current frame
        for ch in s:
            if ch == "(":
                stack.append(0)
            else:
                v = stack.pop()
                stack[-1] += max(2 * v, 1)        # "()" = 1, "(A)" = 2*A
        return stack[0]

Time O(n) · Space O(depth). A stack of partial results is a clean way to evaluate nested structure.

15 LC 227Basic Calculator II Medium Stack · defer + −, apply × ÷ now

Problem. Evaluate an expression with non-negative integers and + − × ÷ (no parentheses); division truncates toward zero. LeetCode 227 ↗

Clarify: No parentheses? (Yes.) Standard precedence? (Yes.) Division truncates toward zero? (Yes.)

Hint 1
Push additions/subtractions as signed numbers for a final sum.
Hint 2
For × and ÷, pop the last value and combine immediately — they bind tighter.

How to think about it Track each number and the operator before it. On the next operator (or end), act on the previous one: +/− push the value (signed) to defer, while ×/÷ pop the top and combine now, honouring precedence. The answer is the sum of the stack.

calculator_ii.py
class Solution:
    def calculate(self, s: str) -> int:
        stack = []
        num, op = 0, "+"
        for i, ch in enumerate(s):
            if ch.isdigit():
                num = num * 10 + int(ch)
            if (not ch.isspace() and not ch.isdigit()) or i == len(s) - 1:
                if op == "+":
                    stack.append(num)
                elif op == "-":
                    stack.append(-num)
                elif op == "*":
                    stack.append(stack.pop() * num)
                else:
                    stack.append(int(stack.pop() / num))
                op, num = ch, 0
        return sum(stack)

Time O(n) · Space O(n). Deferring low-precedence ops onto a stack is the standard no-parentheses evaluator.

16 LC 739Daily Temperatures Medium Monotonic stack · next greater

Problem. For each day, how many days until a warmer temperature? 0 if none. LeetCode 739 ↗

Clarify: Strictly warmer? (Yes.) Return the day gap, not the temperature? (Yes.)

Hint 1
Keep indices of days still waiting for a warmer day.
Hint 2
When today is warmer, it resolves everything cooler on the stack.

How to think about it A monotonic (decreasing) stack of indices. When the current temperature exceeds the temperature at the stack top, that earlier day's answer is the index gap — pop and fill it. Push the current index. Each index is pushed and popped once.

daily_temps.py
from typing import List

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        res = [0] * n
        stack = []                                # indices, decreasing temps
        for i, t in enumerate(temperatures):
            while stack and temperatures[stack[-1]] < t:
                j = stack.pop()
                res[j] = i - j                    # days until warmer
            stack.append(i)
        return res

Time O(n) · Space O(n). The canonical 'next greater element' monotonic-stack problem.

17 LC 496Next Greater Element I Medium Monotonic stack + map

Problem. For each value in nums1 (a subset of nums2), find its next greater element in nums2; −1 if none. LeetCode 496 ↗

Clarify: All values distinct? (Yes.) nums1 ⊆ nums2? (Yes.)

Hint 1
Precompute the next greater element for every value in nums2.
Hint 2
A decreasing stack resolves each value when a bigger one arrives; store results in a map.

How to think about it Sweep nums2 with a decreasing stack. When the current value exceeds the top, pop and record 'next greater = current' in a map. Then answer each nums1 query with an O(1) lookup.

next_greater_i.py
from typing import List

class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        nxt = {}
        stack = []
        for x in nums2:
            while stack and stack[-1] < x:
                nxt[stack.pop()] = x
            stack.append(x)
        return [nxt.get(x, -1) for x in nums1]

Time O(n + m) · Space O(n). The map decouples precomputation from queries — a common stack + hashing combo.

18 LC 503Next Greater Element II Medium Circular monotonic stack

Problem. Find the next greater element for each item in a circular array; −1 if none. LeetCode 503 ↗

Clarify: Array wraps around? (Yes.) Duplicates possible? (Yes.)

Hint 1
Same monotonic stack, but the search wraps past the end.
Hint 2
Iterate twice over the array (using index mod n) to simulate the wrap.

How to think about it Run the decreasing-stack scan over 2n steps, indexing with i % n so the array wraps once. Only push real indices during the first pass; the second pass just resolves anything still waiting.

next_greater_ii.py
from typing import List

class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        res = [-1] * n
        stack = []
        for i in range(2 * n):                    # wrap around once
            while stack and nums[stack[-1]] < nums[i % n]:
                res[stack.pop()] = nums[i % n]
            if i < n:
                stack.append(i)
        return res

Time O(n) · Space O(n). Doubling the scan is the standard trick for circular next-greater problems.

19 LC 901Online Stock Span Medium Monotonic stack · consecutive spans (design)

Problem. For a stream of daily prices, return how many consecutive prior days (including today) had a price ≤ today's. LeetCode 901 ↗

Clarify: Span counts today plus consecutive ≤ days back? (Yes.) Online (one price at a time)? (Yes.)

Hint 1
A new price absorbs the spans of all recent days with a smaller-or-equal price.
Hint 2
Keep a stack of (price, span) and merge while the top price ≤ the new one.

How to think about it Keep a decreasing stack of (price, span). For a new price, start span at 1 and, while the top price is ≤ the new price, pop it and add its span — those days are now part of this span. Push the merged (price, span).

stock_spanner.py
class StockSpanner:
    def __init__(self):
        self.stack = []                           # (price, span)
    def next(self, price: int) -> int:
        span = 1
        while self.stack and self.stack[-1][0] <= price:
            span += self.stack.pop()[1]           # absorb spans of smaller days
        self.stack.append((price, span))
        return span

Amortised O(1) · Space O(n). Merging spans on the stack is the streaming form of next-greater.

20 LC 402Remove K Digits Medium Monotonic stack · greedy smallest

Problem. Remove k digits from a number string to make the smallest possible result. LeetCode 402 ↗

Clarify: No leading zeros in the output (except '0')? (Yes.) Result can be empty → '0'? (Yes.)

Hint 1
A larger digit followed by a smaller one should be removed to shrink the number.
Hint 2
Keep an increasing stack; pop bigger digits while you still have removals left.

How to think about it Greedy with a monotonic (increasing) stack. For each digit, pop larger digits from the top while removals remain — a smaller digit earlier makes the number smaller. If removals are left over, trim from the end. Strip leading zeros.

remove_k_digits.py
class Solution:
    def removeKdigits(self, num: str, k: int) -> str:
        stack = []
        for d in num:
            while k and stack and stack[-1] > d:  # pop bigger leading digits
                stack.pop(); k -= 1
            stack.append(d)
        stack = stack[:len(stack) - k] if k else stack
        return "".join(stack).lstrip("0") or "0"

Time O(n) · Space O(n). Building the smallest sequence by popping bigger tops is a reusable greedy-stack idea (see Remove Duplicate Letters).

21 LC 316Remove Duplicate Letters Medium Monotonic stack + greedy + last-index

Problem. Remove duplicate letters so every letter appears once and the result is the smallest in lexicographic order. LeetCode 316 ↗

Clarify: Each letter appears exactly once in the result? (Yes.) Smallest lexicographic order? (Yes.)

Hint 1
Greedily keep letters small: pop a bigger top if it appears again later.
Hint 2
Track each letter's last index and which letters are already in the stack.

How to think about it Greedy monotonic stack. For each unseen letter, pop larger letters from the top if they occur again later (safe to re-add), then push the current letter and mark it seen. A last-index map tells you whether a popped letter can reappear.

remove_dup_letters.py
class Solution:
    def removeDuplicateLetters(self, s: str) -> str:
        last = {ch: i for i, ch in enumerate(s)}
        stack = []
        seen = set()
        for i, ch in enumerate(s):
            if ch in seen:
                continue
            # pop bigger letters that still appear later
            while stack and stack[-1] > ch and last[stack[-1]] > i:
                seen.discard(stack.pop())
            stack.append(ch)
            seen.add(ch)
        return "".join(stack)

Time O(n) · Space O(1) (≤26). Combines a seen-set, a last-index map, and a monotonic stack — a rich pattern to narrate.

22 LC 456132 Pattern Medium Monotonic stack scanned right-to-left

Problem. Return whether there exist i < j < k with nums[i] < nums[k] < nums[j] (a '132' pattern). LeetCode 456 ↗

Clarify: Strict inequalities? (Yes.) Any such triple suffices? (Yes.)

Hint 1
Scan from the right, maintaining the best possible '2' value.
Hint 2
Use a decreasing stack for candidate '3' values; when the current is below the '2', you've found the '1'.

How to think about it Scan right to left. Keep a decreasing stack of candidate middle ('3') values and a running third = the largest value popped as a valid '2'. If the current value is less than third, it's a valid '1' and the pattern exists. Otherwise pop smaller stack tops into third and push the current value.

pattern_132.py
from typing import List

class Solution:
    def find132pattern(self, nums: List[int]) -> bool:
        stack = []                                # candidates for the "3"
        third = float("-inf")                     # best "2" so far
        for x in reversed(nums):
            if x < third:                         # found the "1"
                return True
            while stack and stack[-1] < x:
                third = stack.pop()
            stack.append(x)
        return False

Time O(n) · Space O(n). The right-to-left scan with a 'best 2 so far' is the clever part.

23 LC 1019Next Greater Node In Linked List Medium Monotonic stack over list values

Problem. For each node, find the value of the first later node with a greater value; 0 if none. Return an array. LeetCode 1019 ↗

Hint 1
Copy the list values to an array (you can't index a list backward).

Apply the standard next-greater monotonic stack.

How to think about it Read the linked list into an array, then run the decreasing-stack next-greater scan by index: when the current value exceeds the value at the stack-top index, fill that index's answer and pop. Push the current index.

next_larger_ll.py
from typing import List, Optional

class Solution:

            vals.append(head.val); head = head.next

24 LC 622Design Circular Queue Medium Design · fixed array + head and count

Problem. Implement a fixed-capacity circular queue with O(1) operations. LeetCode 622 ↗

Clarify: Fixed capacity k? (Yes.) Wrap around on a fixed array? (Yes.)

Hint 1
Store a head index and a count; compute the tail with modulo.
Hint 2
Enqueue writes at (head + count) % cap; dequeue advances head.

How to think about it A ring buffer over a fixed array. Track head and count. Enqueue writes at (head + count) % cap and grows the count; dequeue moves head forward and shrinks the count. Front/rear are read with modular indexing. No shifting, all O(1).

circular_queue.py
class MyCircularQueue:
    def __init__(self, k: int):
        self.q = [0] * k
        self.cap = k
        self.head = 0
        self.count = 0
    def enQueue(self, value: int) -> bool:
        if self.isFull():
            return False
        self.q[(self.head + self.count) % self.cap] = value
        self.count += 1
        return True
    def deQueue(self) -> bool:
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % self.cap
        self.count -= 1
        return True
    def Front(self) -> int:
        return -1 if self.isEmpty() else self.q[self.head]
    def Rear(self) -> int:
        return -1 if self.isEmpty() else self.q[(self.head + self.count - 1) % self.cap]
    def isEmpty(self) -> bool:
        return self.count == 0
    def isFull(self) -> bool:
        return self.count == self.cap

All ops O(1) · Space O(k). Head + count + modulo is the classic ring-buffer implementation.

25 LC 641Design Circular Deque Medium Design · ring buffer, both ends

Problem. Implement a fixed-capacity double-ended queue with O(1) operations at both ends. LeetCode 641 ↗

Clarify: Insert/delete at both ends? (Yes.) Fixed capacity? (Yes.)

Hint 1
Same ring buffer as the circular queue, plus front insertion.
Hint 2
insertFront moves head back by one (mod cap) and writes there.

How to think about it Extend the ring buffer with front operations. insertFront moves head back one slot (mod cap) and writes; insertLast writes at the tail; the delete operations adjust head/count symmetrically. Modular arithmetic keeps every operation O(1).

circular_deque.py
class MyCircularDeque:
    def __init__(self, k: int):
        self.q = [0] * k
        self.cap = k
        self.head = 0
        self.count = 0
    def insertFront(self, value: int) -> bool:
        if self.isFull():
            return False
        self.head = (self.head - 1) % self.cap
        self.q[self.head] = value
        self.count += 1
        return True
    def insertLast(self, value: int) -> bool:
        if self.isFull():
            return False
        self.q[(self.head + self.count) % self.cap] = value
        self.count += 1
        return True
    def deleteFront(self) -> bool:
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % self.cap
        self.count -= 1
        return True
    def deleteLast(self) -> bool:
        if self.isEmpty():
            return False
        self.count -= 1
        return True
    def getFront(self) -> int:
        return -1 if self.isEmpty() else self.q[self.head]
    def getRear(self) -> int:
        return -1 if self.isEmpty() else self.q[(self.head + self.count - 1) % self.cap]
    def isEmpty(self) -> bool:
        return self.count == 0
    def isFull(self) -> bool:
        return self.count == self.cap

All ops O(1) · Space O(k). The deque generalises the circular queue to both ends.

26 LC 239Sliding Window Maximum Medium Monotonic deque · front is the max

Problem. Return the maximum of every contiguous window of size k. LeetCode 239 ↗

Clarify: Fixed window k? (Yes.) O(n) expected? (Yes — a heap is O(n log k).)

Hint 1
Keep a deque of indices with decreasing values; the front is the window max.
Hint 2
Pop smaller values off the back; drop the front when it leaves the window.

How to think about it Maintain a deque of indices whose values are decreasing. Before adding an index, pop smaller values off the back (they can't be the max while the new one is present). Drop the front if it's outside the window. The front index always holds the current window maximum.

window_max.py
from typing import List
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        dq = deque()                              # indices, values decreasing
        res = []
        for i, v in enumerate(nums):
            while dq and nums[dq[-1]] <= v:
                dq.pop()
            dq.append(i)
            if dq[0] <= i - k:
                dq.popleft()
            if i >= k - 1:
                res.append(nums[dq[0]])
        return res

Time O(n) · Space O(k). The monotonic deque is the queue-side analogue of the monotonic stack.

27 LC 735Asteroid Collision Medium Stack simulation

Problem. Simulate asteroids moving left/right (sign = direction, value = size); return the survivors after all collisions. LeetCode 735 ↗

Clarify: Collisions only between a right-mover then a left-mover? (Yes.) Equal sizes both explode? (Yes.)

Hint 1
A leftward asteroid may collide with rightward ones already on the stack.
Hint 2
Resolve collisions in a loop: smaller explodes, equal both explode, else the incoming explodes.

How to think about it Push asteroids onto a stack. A negative (leftward) asteroid collides with positive tops: pop the top if it's smaller, pop and stop if equal, or discard the incoming if the top is larger. If the incoming survives all collisions, push it.

asteroid.py
from typing import List

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        stack = []
        for a in asteroids:
            alive = True
            while alive and a < 0 and stack and stack[-1] > 0:
                if stack[-1] < -a:
                    stack.pop()                   # existing one explodes
                elif stack[-1] == -a:
                    stack.pop(); alive = False    # both explode
                else:
                    alive = False                 # incoming explodes
            if alive:
                stack.append(a)
        return stack

Time O(n) · Space O(n). A stack naturally models 'the last thing still moving right'.

28 LC 1249Minimum Remove to Make Valid Parentheses Medium Stack of indices · mark for removal

Problem. Remove the minimum parentheses so the string is valid; return any valid result. LeetCode 1249 ↗

Clarify: Keep all letters, only remove some parentheses? (Yes.) Any valid answer? (Yes.)

Hint 1
Track indices of unmatched '(' on a stack; a ')' with none is invalid.
Hint 2
Mark unmatched brackets for deletion, then rebuild the string.

How to think about it Scan tracking indices of open parentheses on a stack. A ')' matches by popping; if the stack is empty it's unmatched, so mark it for removal. Any indices left on the stack at the end are unmatched '(' — mark those too. Rebuild without the marked positions.

min_remove_valid.py
class Solution:

                stack.append(i)
            elif ch == ")":

                    stack.pop()
                else:
                    s[i] = ""                     # unmatched ')'

        return "".join(s)

29 LC 84Largest Rectangle in Histogram Hard Monotonic stack · widths on pop

Problem. Given bar heights, return the area of the largest rectangle that fits under the histogram. LeetCode 84 ↗

Clarify: Bars have unit width? (Yes.) Heights non-negative? (Yes.)

Hint 1
A bar's rectangle extends left and right until a shorter bar stops it.
Hint 2
Keep an increasing stack of indices; when a shorter bar arrives, pop and compute widths.

How to think about it Maintain a stack of indices with increasing heights. When the current bar is shorter than the top, that top bar's rectangle is now bounded: pop it, its height is the bar, and its width spans from the new left boundary to the current index. A trailing sentinel of height 0 flushes the stack.

largest_rectangle.py
from typing import List

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        stack = []                                # indices, increasing heights
        best = 0
        heights = heights + [0]                   # sentinel flushes the stack
        for i, h in enumerate(heights):
            while stack and heights[stack[-1]] > h:
                height = heights[stack.pop()]
                width = i if not stack else i - stack[-1] - 1
                best = max(best, height * width)
            stack.append(i)
        return best

Time O(n) · Space O(n). Computing width on pop (using the new stack top as the left wall) is the crux — draw one pop to see it.

30 LC 85Maximal Rectangle Hard Histogram per row

Problem. Given a binary matrix, return the area of the largest all-ones rectangle. LeetCode 85 ↗

Clarify: Cells are '0'/'1' strings? (Yes.) Rectangle must be axis-aligned all-ones? (Yes.)

Hint 1
Build a histogram of consecutive ones ending at each row.
Hint 2
Apply Largest Rectangle in Histogram to each row's heights.

How to think about it Reduce to LC 84. For each row, maintain per-column heights of consecutive ones ending at that row (reset to 0 on a '0'). Run the histogram largest-rectangle routine on each row's heights and take the maximum across all rows.

maximal_rectangle.py
from typing import List

class Solution:
    def maximalRectangle(self, matrix: List[List[str]]) -> int:
        if not matrix or not matrix[0]:
            return 0
        n = len(matrix[0])
        heights = [0] * n
        best = 0
        def largest(hs):
            stack = []
            area = 0
            hs = hs + [0]
            for i, h in enumerate(hs):
                while stack and hs[stack[-1]] > h:
                    height = hs[stack.pop()]
                    width = i if not stack else i - stack[-1] - 1
                    area = max(area, height * width)
                stack.append(i)
            return area
        for row in matrix:
            for i in range(n):
                heights[i] = heights[i] + 1 if row[i] == "1" else 0
            best = max(best, largest(heights))
        return best

Time O(rows·cols) · Space O(cols). Layering the histogram trick over rows is a powerful reduction to learn.

31 LC 42Trapping Rain Water Hard Monotonic stack · fill layer by layer

Problem. Given bar heights, compute the trapped rain water — here with a stack. LeetCode 42 ↗

Clarify: Water sits between taller bars? (Yes.) O(n) with a stack? (Yes.)

Hint 1
Keep a decreasing stack of indices; a taller bar closes a basin.
Hint 2
When a taller bar arrives, pop the bottom and add water bounded by the two side walls.

How to think about it A decreasing stack of indices. When the current bar is taller than the top, that top is a basin floor: pop it, and if a left wall remains, add water of width (i − left − 1) and height min(leftWall, current) − floor. This fills water in horizontal layers.

trap_stack.py
from typing import List

class Solution:
    def trap(self, height: List[int]) -> int:
        stack = []                                # indices, decreasing heights
        water = 0
        for i, h in enumerate(height):
            while stack and height[stack[-1]] < h:
                bottom = stack.pop()
                if not stack:
                    break
                left = stack[-1]
                width = i - left - 1
                bounded = min(height[left], h) - height[bottom]
                water += width * bounded
            stack.append(i)
        return water

Time O(n) · Space O(n). A different lens on the same problem solved with two pointers in Ch 06 — good to know both.

32 LC 224Basic Calculator Hard Stack of signs across parentheses

Problem. Evaluate an expression with +, −, non-negative integers, and parentheses. LeetCode 224 ↗

Clarify: Parentheses nest? (Yes.) Only + and − (plus unary via context)? (Yes.)

Hint 1
Carry a running result and the current sign.
Hint 2
On '(', push the result and sign; on ')', fold the inner result back with the saved sign.

How to think about it Maintain result, the current num, and the current sign. '+'/'−' fold the number into the result and set the next sign. '(' pushes the result and sign, then resets for the sub-expression; ')' folds the inner result and multiplies by the pushed sign before adding the pushed result. No precedence needed since only + and − appear.

basic_calculator.py
class Solution:
    def calculate(self, s: str) -> int:
        stack = []
        result, num, sign = 0, 0, 1
        for ch in s:
            if ch.isdigit():
                num = num * 10 + int(ch)
            elif ch == "+":
                result += sign * num; num = 0; sign = 1
            elif ch == "-":
                result += sign * num; num = 0; sign = -1
            elif ch == "(":
                stack.append(result); stack.append(sign)
                result, sign = 0, 1
            elif ch == ")":
                result += sign * num; num = 0
                result *= stack.pop()             # sign before '('
                result += stack.pop()             # result before '('
        return result + sign * num

Time O(n) · Space O(depth). Pushing (result, sign) at each '(' is the clean way to handle nested parentheses.

33 LC 895Maximum Frequency Stack Hard Design · frequency-bucketed stacks

Problem. Design a stack whose pop returns the most frequent element (ties broken by most recent). LeetCode 895 ↗

Clarify: Ties broken by most recently pushed? (Yes.) O(1) push/pop? (Amortised, yes.)

Hint 1
Group elements by their current frequency; pop from the highest non-empty group.
Hint 2
Each frequency level is itself a stack, preserving recency.

How to think about it Track each value's frequency and, for each frequency level, a stack of values that reached it. Push increments the value's frequency and appends it to that level's stack, updating maxfreq. Pop takes from the top of the maxfreq stack (most recent among the most frequent) and lowers maxfreq if that level empties.

freq_stack.py
from collections import defaultdict

class FreqStack:
    def __init__(self):
        self.freq = defaultdict(int)
        self.group = defaultdict(list)            # frequency -> stack of values
        self.maxfreq = 0
    def push(self, val: int) -> None:
        self.freq[val] += 1
        f = self.freq[val]
        self.maxfreq = max(self.maxfreq, f)
        self.group[f].append(val)
    def pop(self) -> int:
        val = self.group[self.maxfreq].pop()
        self.freq[val] -= 1
        if not self.group[self.maxfreq]:
            self.maxfreq -= 1
        return val

All ops O(1) · Space O(n). Stacking values per frequency elegantly encodes both frequency and recency.

34 LC 862Shortest Subarray with Sum at Least K Hard Prefix sums + monotonic deque

Problem. Return the length of the shortest contiguous subarray with sum at least k, or −1. Values may be negative. LeetCode 862 ↗

Clarify: Negatives allowed? (Yes — rules out a plain window.) Shortest length? (Yes.)

Hint 1
Work with prefix sums; a valid subarray is prefix[j] − prefix[i] ≥ k.
Hint 2
Keep a deque of prefix indices with increasing values; pop from both ends smartly.

How to think about it Compute prefix sums. Maintain a deque of indices with increasing prefix values. For each i, pop from the front while prefix[i] − prefix[front] ≥ k (recording lengths — these fronts are done), and pop from the back while prefix[back] ≥ prefix[i] (they can never beat i as a left endpoint). Then push i.

shortest_subarray.py
from typing import List
from collections import deque

class Solution:
    def shortestSubarray(self, nums: List[int], k: int) -> int:
        n = len(nums)
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]
        dq = deque()                              # indices, increasing prefix
        best = n + 1
        for i in range(n + 1):
            while dq and prefix[i] - prefix[dq[0]] >= k:
                best = min(best, i - dq.popleft())
            while dq and prefix[dq[-1]] >= prefix[i]:
                dq.pop()
            dq.append(i)
        return best if best <= n else -1

Time O(n) · Space O(n). The negatives are what force prefix sums + a monotonic deque over a simple sliding window.

4 · Interview playbook

  • Pick the structure by recency: most-recent-first → stack; oldest-first → queue; both ends → deque.
  • Spot the monotonic stack: "next/previous greater or smaller", spans, and histogram problems all keep a sorted stack of unresolved indices — O(n), not O(n²).
  • Parsing? Push context on an opening token, resolve it on the closing one. A counter replaces the stack when you only need its depth.
  • Never use a list as a queue — pop(0) is O(n); use collections.deque.
  • Design questions: carry extra state per element (Min Stack) or pair two structures (queue from two stacks, frequency-bucketed stacks).

6 · Review

Cheat sheet
  • Balanced brackets / cancel adjacent → matching stack.
  • RPN / calculator / path / decode → parsing stack (push on open, resolve on close).
  • Next/previous greater or smaller, spans → monotonic stack (pop the resolved tops).
  • Histogram largest rectangle / trapping water → monotonic stack with widths on pop.
  • Sliding-window max/min → monotonic deque.
  • Recent events / FIFO stream / circular buffer → queue (deque or head+count).
  • O(1) min / queue-from-stacks / max-frequency → design with auxiliary state.
  • Never list.pop(0) — it's O(n).

Concept checks

Why is a monotonic-stack solution O(n) even though it has a while loop inside a for loop?
Each index is pushed exactly once and popped at most once, so total push/pop work is O(n) across the whole scan
Because the while loop runs at most twice per element
Because the input is sorted
Amortised analysis: over the entire run, every element enters the stack once and leaves once. The inner while loop can only pop what was pushed, so the sum of all its iterations is bounded by n — total O(n).
Why prefer collections.deque over a list when implementing a queue?
deque.popleft() is O(1), while list.pop(0) is O(n) because it shifts every remaining element
deque uses less memory
list can't store arbitrary objects
A list is contiguous, so removing the front element shifts all others left — O(n). A deque is a doubly linked block structure with O(1) operations at both ends, so FIFO stays O(1) per operation.
