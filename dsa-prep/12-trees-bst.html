What is a binary tree?

A binary tree is a set of nodes where each node holds a value and up to two children (left and right). One node is the root; nodes with no children are leaves. Because each child is itself the root of a smaller tree, trees are recursive by nature — the reason nearly every solution here is a short recursive function.

Example — the node, and a recursive walk
node.py
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def count_nodes(root):
    if not root:              # base case: empty subtree
        return 0
    return 1 + count_nodes(root.left) + count_nodes(root.right)

#     1
#    / \
#   2   3
root = TreeNode(1, TreeNode(2), TreeNode(3))
print(count_nodes(root))      # 3
Output3
The universal tree recipe: handle the empty node (base case), recurse on both children, combine their answers. "Count nodes", "max depth", "sum values" — all the same three lines with a different combine step.

The four traversals

Visiting every node comes in two flavours. Depth-first (DFS) goes deep before wide and has three orders by when you visit the node relative to its children: preorder (node, left, right), inorder (left, node, right), postorder (left, right, node). Breadth-first (BFS) visits level by level using a queue.

Example — recursive inorder
inorder.py
def inorder(root, out):
    if not root:
        return
    inorder(root.left, out)   # left
    out.append(root.val)      # node
    inorder(root.right, out)  # right

#     2
#    / \
#   1   3
r = TreeNode(2, TreeNode(1), TreeNode(3))
vals = []; inorder(r, vals)
print(vals)                   # [1, 2, 3]
Output[1, 2, 3]

Preorder is great for copying/serialising (you see the root first); postorder for deleting/aggregating from children up; inorder is special for BSTs (below).

DFS or BFS? Level-order with a queue

Reach for DFS (recursion) when a node's answer depends on its subtrees — depth, path sums, validation. Reach for BFS (a queue) when the problem is about levels — "level order", "right side view", "minimum depth". The BFS template processes one whole level per outer iteration.

Example — level-order BFS
bfs.py
from collections import deque

def level_order(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):        # exactly one level per pass
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res
Snapshotting len(q) before the inner loop is what cleanly separates the levels.

The Binary Search Tree ordering

A Binary Search Tree (BST) adds one rule: for every node, all values in its left subtree are smaller and all in its right subtree are larger. Two consequences you'll use constantly: search/insert/delete are O(h) (follow the ordering, never both sides), and an inorder traversal visits values in sorted order.

⚠️
Tree pitfalls

Complexity is O(h), the height — on a balanced tree h ≈ log n, but a degenerate (skewed) tree makes h = n, so recursion can hit Python's ~1000-frame limit. Always handle the empty-node base case first. And to validate a BST, remember a node must fit the range from all its ancestors, not just its parent.

1 LC 104Maximum Depth of Binary Tree Easy DFS · depth = 1 + max(children)

Problem. Return the maximum depth (root-to-deepest-leaf node count) of a binary tree. LeetCode 104 ↗

Clarify: Empty tree is depth 0? (Yes.) Depth counts nodes, not edges? (Yes.)

Hint 1
A tree's depth is one more than the deeper of its two subtrees.
Hint 2
Recurse; the base case is an empty node (depth 0).

How to think about it The archetypal tree recursion: solve the children first, then combine. The depth of a node is 1 + max(depth of left, depth of right), with an empty node contributing 0. This 'return info up from the children' shape recurs across the whole chapter.

max_depth.py
from typing import Optional

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        return 1 + max(self.maxDepth(root.left), self.maxDepth(root.right))

Time O(n) · Space O(h) recursion stack. Learn this shape — most tree problems are a variation of it.

2 LC 111Minimum Depth of Binary Tree Easy DFS · mind the one-child case

Problem. Return the minimum depth: the shortest path from the root to any leaf. LeetCode 111 ↗

Clarify: Depth to the nearest leaf (not any node)? (Yes.) A node with one child isn't a leaf? (Correct.)

Hint 1
The min depth is 1 + the smaller child's depth — but only if both children exist.
Hint 2
With one child missing, you must descend the existing child (a null child isn't a leaf).

How to think about it Almost like max depth, with one trap: min of the two subtrees is wrong when a child is missing, because a null child would give depth 0 yet the node isn't a leaf. So if one side is empty, recurse only into the non-empty side.

min_depth.py
from typing import Optional

class Solution:
    def minDepth(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        if not root.left:
            return 1 + self.minDepth(root.right)   # only-child: must go down it
        if not root.right:
            return 1 + self.minDepth(root.left)
        return 1 + min(self.minDepth(root.left), self.minDepth(root.right))

Time O(n) · Space O(h). The one-child special case is exactly what separates this from Maximum Depth.

3 LC 226Invert Binary Tree Easy DFS · swap children everywhere

Problem. Invert a binary tree (mirror it left-to-right) and return the root. LeetCode 226 ↗

Clarify: Mirror the whole tree recursively? (Yes.) Modify in place? (Fine.)

Hint 1
Swap the left and right subtrees at every node.
Hint 2
Recurse into both children.

How to think about it Recursively invert each subtree, then swap the node's two children. The order doesn't matter as long as every node's children end up swapped. A tiny problem that cements the recursive structure.

invert_tree.py
from typing import Optional

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if not root:
            return None
        root.left, root.right = self.invertTree(root.right), self.invertTree(root.left)
        return root

Time O(n) · Space O(h). Famous for a reason — three lines once you see 'swap and recurse'.

4 LC 100Same Tree Easy DFS · compare in lockstep

Problem. Return whether two binary trees are identical in structure and values. LeetCode 100 ↗

Clarify: Both structure and values must match? (Yes.) Empty == empty? (Yes.)

Hint 1
Two trees match if their roots match and their subtrees match pairwise.
Hint 2
Handle the base cases: both empty, or one empty.

How to think about it Recurse on both trees together. They're the same when both nodes are null, or both are non-null with equal values and matching left and right subtrees. Any mismatch short-circuits to False.

same_tree.py
from typing import Optional

class Solution:
    def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
        if not p and not q:
            return True
        if not p or not q or p.val != q.val:
            return False
        return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)

Time O(n) · Space O(h). Comparing two trees in parallel is the base skill for Symmetric Tree and Subtree checks.

5 LC 101Symmetric Tree Easy DFS · mirror comparison

Problem. Return whether a binary tree is a mirror image of itself around its center. LeetCode 101 ↗

Clarify: Mirror symmetry (not just equal subtrees)? (Yes.)

Hint 1
Compare the left subtree against the right subtree, but mirrored.
Hint 2
left.left pairs with right.right, and left.right with right.left.

How to think about it Symmetry is Same-Tree with a twist: a helper compares two nodes as mirrors, matching the outer children (a.left vs b.right) and inner children (a.right vs b.left). Run it on the root's two subtrees.

symmetric_tree.py
from typing import Optional

class Solution:
    def isSymmetric(self, root: Optional[TreeNode]) -> bool:
        def mirror(a, b):
            if not a and not b:
                return True
            if not a or not b or a.val != b.val:
                return False
            return mirror(a.left, b.right) and mirror(a.right, b.left)
        return not root or mirror(root.left, root.right)

Time O(n) · Space O(h). The mirrored pairing (outer/inner) is the whole idea.

6 LC 112Path Sum Easy DFS · carry the remaining target

Problem. Return whether any root-to-leaf path sums to targetSum. LeetCode 112 ↗

Clarify: Must end at a leaf? (Yes.) Values can be negative? (Yes.)

Hint 1
Subtract the current value from the target as you descend.
Hint 2
At a leaf, success means the remaining target equals the leaf's value.

How to think about it Pass the shrinking remaining target down the recursion. At a leaf, check whether it exactly hits the target; otherwise recurse into either child with the reduced target. The OR of the two branches gives the answer.

path_sum.py
from typing import Optional

class Solution:
    def hasPathSum(self, root: Optional[TreeNode], targetSum: int) -> bool:
        if not root:
            return False
        if not root.left and not root.right:      # leaf
            return targetSum == root.val
        rem = targetSum - root.val
        return self.hasPathSum(root.left, rem) or self.hasPathSum(root.right, rem)

Time O(n) · Space O(h). Carrying an accumulator down the recursion is the setup for Path Sum II and III.

7 LC 543Diameter of Binary Tree Easy DFS · update a global while returning depth

Problem. Return the diameter: the length (in edges) of the longest path between any two nodes. LeetCode 543 ↗

Clarify: Path need not pass through the root? (Correct.) Length in edges? (Yes.)

Hint 1
The longest path through a node = left depth + right depth.
Hint 2
Compute depths recursively; track the best sum seen in a shared variable.

How to think about it A single DFS that returns each node's depth and updates a running best. The longest path passing through a node is leftDepth + rightDepth; record the maximum across all nodes while the function returns 1 + max(depths) upward.

diameter.py
from typing import Optional

class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        self.best = 0
        def depth(node):
            if not node:
                return 0
            l, r = depth(node.left), depth(node.right)
            self.best = max(self.best, l + r)     # longest path through this node
            return 1 + max(l, r)
        depth(root)
        return self.best

Time O(n) · Space O(h). 'Return one thing, track another via a shared variable' is a key tree idiom (see Max Path Sum).

8 LC 617Merge Two Binary Trees Easy DFS · overlay two trees

Problem. Overlay two trees, summing overlapping node values; where only one has a node, keep it. LeetCode 617 ↗

Clarify: Sum overlapping nodes, keep the rest? (Yes.) Reuse input nodes? (Fine.)

Hint 1
If one tree is empty at a position, the merged node is the other tree's node.
Hint 2
Otherwise add the values and merge both pairs of children.

How to think about it Recurse over both trees together. If either node is null, return the other. Otherwise add the values and recursively merge the left pair and the right pair, returning the combined node.

merge_trees.py
from typing import Optional

class Solution:
    def mergeTrees(self, root1: Optional[TreeNode], root2: Optional[TreeNode]) -> Optional[TreeNode]:
        if not root1:
            return root2
        if not root2:
            return root1
        root1.val += root2.val
        root1.left = self.mergeTrees(root1.left, root2.left)
        root1.right = self.mergeTrees(root1.right, root2.right)
        return root1

Time O(min(n, m)) · Space O(h). Two-tree recursion again — same skeleton as Same Tree, different combine step.

9 LC 700Search in a Binary Search Tree Easy BST · the ordering guides the walk

Problem. Return the subtree rooted at the node with a given value in a BST, or null. LeetCode 700 ↗

Clarify: Input is a valid BST? (Yes.) Return the node/subtree? (Yes.)

Hint 1
Use the BST property: go left if the target is smaller, right if larger.
Hint 2
Each step halves the search (on a balanced tree).

How to think about it The BST ordering (left < node < right) means you never search both sides: compare the target to the current value and descend accordingly. It's binary search on a tree, O(h) instead of O(n).

search_bst.py
from typing import Optional

class Solution:
    def searchBST(self, root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
        while root and root.val != val:
            root = root.left if val < root.val else root.right   # BST guides the walk
        return root

Time O(h) · Space O(1). Your first taste of the BST invariant that powers the whole medium tier.

10 LC 108Convert Sorted Array to BST Easy Divide and conquer · middle as root

Problem. Build a height-balanced BST from a sorted array. LeetCode 108 ↗

Clarify: Must be height-balanced? (Yes.) Any valid balanced BST accepted? (Yes.)

Hint 1
The middle element becomes the root so the two halves are balanced.
Hint 2
Recurse on the left and right halves for the subtrees.

How to think about it Pick the middle element as the root — this keeps the halves equal in size, so the tree stays balanced. Recurse on the left half for the left subtree and the right half for the right subtree. Sorted input + middle-as-root gives a valid, balanced BST.

sorted_to_bst.py
from typing import List, Optional

class Solution:
    def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:
        def build(lo, hi):
            if lo > hi:
                return None
            mid = (lo + hi) // 2                  # middle element balances the tree
            node = TreeNode(nums[mid])
            node.left = build(lo, mid - 1)
            node.right = build(mid + 1, hi)
            return node
        return build(0, len(nums) - 1)

Time O(n) · Space O(log n). Choosing the middle to balance is the same instinct as binary search.

11 LC 102Binary Tree Level Order Traversal Medium BFS · one queue level at a time

Problem. Return node values grouped by level, top to bottom. LeetCode 102 ↗

Clarify: Group each level into its own list? (Yes.) Left to right? (Yes.)

Hint 1
Use a queue; process it in batches sized by the current level.
Hint 2
Snapshot the queue length before the loop to know where the level ends.

How to think about it The BFS template for trees. Push the root, then repeatedly process exactly len(queue) nodes — one complete level — collecting their values and enqueuing their children. The level-size snapshot is what separates the levels cleanly.

level_order.py
from typing import List, Optional
from collections import deque

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []
        res, q = [], deque([root])
        while q:
            level = []
            for _ in range(len(q)):               # process one full level
                node = q.popleft()
                level.append(node.val)
                if node.left: q.append(node.left)
                if node.right: q.append(node.right)
            res.append(level)
        return res

Time O(n) · Space O(n). This level-batched BFS underlies Right Side View, Zigzag, and Maximum Width.

12 LC 199Binary Tree Right Side View Medium BFS · last node of each level

Problem. Return the values visible from the right side, top to bottom. LeetCode 199 ↗

Clarify: Rightmost node per level? (Yes.) Empty tree → empty list? (Yes.)

Hint 1
From the right, you see the last node of each level.
Hint 2
Level-order BFS; record the node when it's the last in its level.

How to think about it Run level-order BFS and record the value of the last node processed in each level — that's the one visible from the right. A small variation on the standard BFS batch loop.

right_side_view.py
from typing import List, Optional
from collections import deque

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        res, q = [], deque([root])
        while q:
            n = len(q)
            for i in range(n):
                node = q.popleft()
                if i == n - 1:                    # last node of the level = rightmost
                    res.append(node.val)
                if node.left: q.append(node.left)
                if node.right: q.append(node.right)
        return res

Time O(n) · Space O(n). Same batched BFS, just picking the last node per level.

13 LC 103Binary Tree Zigzag Level Order Traversal Medium BFS · alternate direction per level

Problem. Return level-order values, but alternate left-to-right and right-to-left by level. LeetCode 103 ↗

Clarify: First level left-to-right? (Yes.) Alternate each level? (Yes.)

Hint 1
Do normal level-order BFS, but flip a direction flag each level.
Hint 2
Build each level with a deque so you can append to either end.

How to think about it Standard level-order BFS with a direction flag. Build each level into a deque, appending to the right on left-to-right levels and to the left on the reversed ones, then flip the flag. Using a deque avoids reversing a list afterward.

zigzag.py
from typing import List, Optional
from collections import deque

class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []
        res, q, ltr = [], deque([root]), True
        while q:
            level = deque()
            for _ in range(len(q)):
                node = q.popleft()
                if ltr:
                    level.append(node.val)
                else:
                    level.appendleft(node.val)    # reverse direction on this level
                if node.left: q.append(node.left)
                if node.right: q.append(node.right)
            res.append(list(level))
            ltr = not ltr
        return res

Time O(n) · Space O(n). The deque append-to-either-end trick keeps it O(n) with no reversals.

14 LC 98Validate Binary Search Tree Medium BST · pass down valid bounds

Problem. Return whether a binary tree is a valid BST. LeetCode 98 ↗

Clarify: Strictly less/greater (no equal values)? (Yes.) Must hold for whole subtrees, not just parents? (Yes.)

Hint 1
A node isn't just bigger than its parent — it must fit a range from all ancestors.
Hint 2
Pass a (low, high) bound down; each node must lie strictly inside it.

How to think about it The subtle part: comparing only parent and child is wrong. Carry an open interval (low, high) down the recursion — every node must lie strictly inside it, and recursing left tightens the upper bound to the node's value while recursing right tightens the lower bound.

validate_bst.py
from typing import Optional

class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        def valid(node, lo, hi):
            if not node:
                return True
            if not (lo < node.val < hi):          # must fall inside the open range
                return False
            return valid(node.left, lo, node.val) and valid(node.right, node.val, hi)
        return valid(root, float("-inf"), float("inf"))

Time O(n) · Space O(h). An inorder traversal that stays strictly increasing is an equivalent approach worth knowing.

15 LC 230Kth Smallest Element in a BST Medium BST · inorder yields sorted order

Problem. Return the k-th smallest value in a BST. LeetCode 230 ↗

Clarify: 1-indexed k? (Yes.) BST guaranteed valid? (Yes.)

Hint 1
An inorder traversal of a BST visits values in ascending order.
Hint 2
Stop at the k-th visited node — an iterative inorder avoids visiting the rest.

How to think about it Because a BST's inorder traversal is sorted, the k-th node visited inorder is the answer. An explicit stack-based inorder lets you stop as soon as you've popped k nodes, without traversing the whole tree.

kth_smallest_bst.py
from typing import Optional

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        stack, node = [], root
        while stack or node:                      # iterative inorder
            while node:
                stack.append(node); node = node.left
            node = stack.pop()
            k -= 1
            if k == 0:
                return node.val
            node = node.right

Time O(h + k) · Space O(h). 'Inorder of a BST is sorted' is one of the most useful BST facts.

16 LC 235Lowest Common Ancestor of a BST Medium BST · the split point

Problem. Return the lowest common ancestor of two nodes in a BST. LeetCode 235 ↗

Clarify: Both nodes exist in the tree? (Yes.) A node can be an ancestor of itself? (Yes.)

Hint 1
Use the ordering: if both targets are smaller, the LCA is left; if both larger, right.
Hint 2
The first node that sits between them (a split) is the LCA.

How to think about it Walk down using the BST property. If both targets are less than the current node, go left; if both greater, go right; otherwise the current node is where their paths diverge — the lowest common ancestor. O(h), no extra space.

lca_bst.py
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        while root:
            if p.val < root.val and q.val < root.val:
                root = root.left                  # both smaller -> go left
            elif p.val > root.val and q.val > root.val:
                root = root.right
            else:
                return root                       # split point = LCA
        return None

Time O(h) · Space O(1). The ordering makes this far simpler than the general-tree version below.

17 LC 236Lowest Common Ancestor of a Binary Tree Medium DFS · found-on-both-sides

Problem. Return the lowest common ancestor of two nodes in a general binary tree (no ordering). LeetCode 236 ↗

Clarify: Both nodes present? (Yes.) Self-ancestor allowed? (Yes.)

Hint 1
Recurse; report up whether each subtree contains p or q.
Hint 2
The node where the two targets are found in different subtrees is the LCA.

How to think about it Without ordering, recurse everywhere. A node returns non-null if its subtree contains p or q (or is one of them). When both left and right recursions return non-null, the two targets lie on opposite sides, so the current node is the LCA; otherwise bubble up whichever side found something.

lca_tree.py
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        if not root or root is p or root is q:
            return root
        left = self.lowestCommonAncestor(root.left, p, q)
        right = self.lowestCommonAncestor(root.right, p, q)
        if left and right:                        # p and q on opposite sides
            return root
        return left or right

Time O(n) · Space O(h). 'Both children report a hit ⇒ this is the meeting point' is the core insight.

18 LC 105Construct Binary Tree from Preorder and Inorder Medium Construction · root from preorder, split by inorder

Problem. Rebuild a binary tree from its preorder and inorder traversals. LeetCode 105 ↗

Clarify: Values unique? (Yes.) Both traversals of the same tree? (Yes.)

Hint 1
Preorder's first element is the root; find it in inorder to split left/right.
Hint 2
Use a value→index map on inorder for O(1) splits, and a moving preorder pointer.

How to think about it Preorder visits root, then left, then right — so the next preorder value is always the current subtree's root. Locate that root in inorder (via a value→index map) to know how many nodes fall in the left subtree, then recurse. A single advancing preorder pointer builds the whole tree.

build_pre_in.py
from typing import List, Optional

class Solution:
    def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
        idx = {v: i for i, v in enumerate(inorder)}
        self.pre = 0
        def build(lo, hi):
            if lo > hi:
                return None
            val = preorder[self.pre]; self.pre += 1   # preorder gives the root
            node = TreeNode(val)
            mid = idx[val]
            node.left = build(lo, mid - 1)
            node.right = build(mid + 1, hi)
            return node
        return build(0, len(inorder) - 1)

Time O(n) · Space O(n). Understanding what each traversal reveals (root vs boundaries) is the key.

19 LC 106Construct Binary Tree from Inorder and Postorder Medium Construction · root from postorder (reversed)

Problem. Rebuild a binary tree from its inorder and postorder traversals. LeetCode 106 ↗

Clarify: Values unique? (Yes.) Same tree? (Yes.)

Hint 1
Postorder's last element is the root; consume postorder from the back.
Hint 2
Because you take roots from the end, build the RIGHT subtree before the left.

How to think about it Postorder ends with the root, so consume it back-to-front. Since the last-but-one postorder value belongs to the right subtree, build the right child before the left. Split with the inorder index map exactly as in LC 105.

build_in_post.py
from typing import List, Optional

class Solution:
    def buildTree(self, inorder: List[int], postorder: List[int]) -> Optional[TreeNode]:
        idx = {v: i for i, v in enumerate(inorder)}
        self.post = len(postorder) - 1
        def build(lo, hi):
            if lo > hi:
                return None
            val = postorder[self.post]; self.post -= 1   # postorder (reversed) gives root
            node = TreeNode(val)
            mid = idx[val]
            node.right = build(mid + 1, hi)           # build right before left
            node.left = build(lo, mid - 1)
            return node
        return build(0, len(inorder) - 1)

Time O(n) · Space O(n). The right-before-left order is the one thing that differs from the preorder version.

20 LC 114Flatten Binary Tree to Linked List Medium Rewire · splice left subtree into the right

Problem. Flatten the tree into a right-leaning linked list following preorder, in place. LeetCode 114 ↗

Clarify: In place (right pointers form the list, left set to null)? (Yes.) Preorder order? (Yes.)

Hint 1
For each node with a left child, the left subtree should come before the right.
Hint 2
Find the left subtree's rightmost node and attach the old right subtree after it.

How to think about it Walk down the right spine. Whenever a node has a left child, find the rightmost node of that left subtree, hang the current right subtree off it, then move the whole left subtree to the right and null the left. Continue right. An O(1)-space Morris-like rewiring.

flatten_tree.py
from typing import Optional

class Solution:
    def flatten(self, root: Optional[TreeNode]) -> None:
        cur = root
        while cur:
            if cur.left:
                prev = cur.left
                while prev.right:                 # rightmost node of the left subtree
                    prev = prev.right
                prev.right = cur.right            # splice the right subtree after it
                cur.right = cur.left
                cur.left = None
            cur = cur.right

Time O(n) · Space O(1). Pointer rewiring on a tree — the skills from Linked Lists (Ch 03) pay off.

21 LC 116Populating Next Right Pointers in Each Node Medium Level links using established next pointers

Problem. In a perfect binary tree, set each node's next to the node to its right on the same level (or null). LeetCode 116 ↗

Clarify: Perfect binary tree (all levels full)? (Yes.) O(1) extra space expected? (Yes.)

Hint 1
Connect a node's two children directly; bridge across gaps using the parent's next.
Hint 2
Process level by level using the next pointers you already set.

How to think about it Use the next pointers of the current level to wire the level below without a queue. For each node: link its left child to its right child, and link its right child to the left child of the node's next (bridging the gap between subtrees). Move down via the leftmost node each level.

connect.py
from typing import Optional

class Solution:
    def connect(self, root: 'Optional[Node]') -> 'Optional[Node]':
        if not root:
            return None
        leftmost = root
        while leftmost.left:                      # perfect tree: has children
            node = leftmost
            while node:
                node.left.next = node.right       # connect the two children
                if node.next:
                    node.right.next = node.next.left   # bridge across the gap
                node = node.next
            leftmost = leftmost.left
        return root

Time O(n) · Space O(1). Reusing the level's own next pointers is what avoids the BFS queue's O(n) space.

22 LC 129Sum Root to Leaf Numbers Medium DFS · build the number down each path

Problem. Each root-to-leaf path spells a number; return the sum of all such numbers. LeetCode 129 ↗

Clarify: Digits 0–9 at each node? (Yes.) Sum over all root-to-leaf paths? (Yes.)

Hint 1
Carry the running number down: cur = cur*10 + node.val.
Hint 2
Add it to the total only at leaves.

How to think about it DFS carrying the number formed so far. At each node extend it (cur*10 + val); at a leaf, that's a complete number — return it. Sum the results from both children. A clean accumulator-down-the-path recursion.

from typing import Optional

class Solution:

23 LC 113Path Sum II Medium Backtracking on a tree

Problem. Return all root-to-leaf paths whose values sum to targetSum. LeetCode 113 ↗

Clarify: Only root-to-leaf paths? (Yes.) Return the actual paths? (Yes.)

Hint 1
Track the current path and remaining target as you descend.
Hint 2
Record a copy of the path at a qualifying leaf, and pop on the way back.

How to think about it Backtracking (Ch 11) applied to a tree. Append the node to the path and reduce the remaining target; at a leaf that hits zero, record a copy of the path. Always pop the node when returning so sibling branches start clean.

path_sum_ii.py
from typing import List, Optional

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> List[List[int]]:
        res = []
        def dfs(node, remaining, path):
            if not node:
                return
            path.append(node.val)
            remaining -= node.val
            if not node.left and not node.right and remaining == 0:
                res.append(path[:])               # record a copy at a qualifying leaf
            else:
                dfs(node.left, remaining, path)
                dfs(node.right, remaining, path)
            path.pop()                            # backtrack
        dfs(root, targetSum, [])
        return res

Time O(n²) worst · Space O(h). The choose/recurse/un-choose rhythm from backtracking, now on tree paths.

24 LC 437Path Sum III Medium Prefix sums along the path

Problem. Count downward paths (not necessarily root-to-leaf) whose values sum to targetSum. LeetCode 437 ↗

Clarify: Paths go downward only? (Yes.) Any start/end node? (Yes.)

Hint 1
A path summing to target = two prefix sums differing by target on the current root-to-node path.
Hint 2
Keep a running count of prefix sums seen on the current path; undo on the way back.

How to think about it Bring the prefix-sum + hashmap trick (Ch 07) onto a root-to-node path. Track counts of running prefix sums; at each node, the number of valid paths ending here is how many earlier prefixes equal cur − target. Decrement the count when leaving the node so it only reflects the current path.

path_sum_iii.py
from typing import Optional
from collections import defaultdict

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        count = defaultdict(int)
        count[0] = 1                              # empty prefix
        self.res = 0
        def dfs(node, cur):
            if not node:
                return
            cur += node.val
            self.res += count[cur - targetSum]    # prefix-sum trick on a path
            count[cur] += 1
            dfs(node.left, cur)
            dfs(node.right, cur)
            count[cur] -= 1                        # undo when leaving this node
        dfs(root, 0)
        return self.res

Time O(n) · Space O(h). A beautiful crossover: prefix-sum counting from arrays applied to tree paths.

25 LC 662Maximum Width of Binary Tree Medium BFS · heap-style index per node

Problem. Return the maximum width of any level (distance between the leftmost and rightmost non-null nodes, counting gaps). LeetCode 662 ↗

Clarify: Width counts null gaps between the ends? (Yes.) Indices can grow large? (Yes — Python ints are fine.)

Hint 1
Give each node a position index as if the tree were a complete heap: children of i are 2i and 2i+1.
Hint 2
A level's width is the last index minus the first index plus one.

How to think about it Run level-order BFS but tag each node with a heap-style index (children of i are 2i and 2i+1). The width of a level is lastIndex − firstIndex + 1, which correctly counts the null gaps between the extreme nodes.

max_width.py
from typing import Optional
from collections import deque

class Solution:
    def widthOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        best = 0
        q = deque([(root, 0)])                    # (node, heap-style index)
        while q:
            _, first = q[0]
            for _ in range(len(q)):
                node, idx = q.popleft()
                if node.left: q.append((node.left, 2 * idx))
                if node.right: q.append((node.right, 2 * idx + 1))
            best = max(best, idx - first + 1)
        return best

Time O(n) · Space O(n). Indexing nodes like a heap array is the trick that measures gaps for free.

26 LC 173Binary Search Tree Iterator Medium Design · controlled inorder with a stack

Problem. Design an iterator over a BST returning values in ascending order, with average O(1) next and O(h) space. LeetCode 173 ↗

Clarify: next returns the next smallest? (Yes.) Amortised O(1) next, O(h) space? (Yes.)

Hint 1
Simulate an inorder traversal but pause between steps using an explicit stack.
Hint 2
Push all left descendants; on next, pop one and push the left spine of its right child.

How to think about it Turn the recursive inorder into a controllable stack machine. Initialise by pushing the entire left spine. next pops the top (the smallest unseen node) and pushes the left spine of its right child. Each node is pushed and popped once, so next is amortised O(1) with O(h) stack space.

bst_iterator.py
from typing import Optional

class BSTIterator:
    def __init__(self, root: Optional[TreeNode]):
        self.stack = []
        self._push_left(root)
    def _push_left(self, node):
        while node:
            self.stack.append(node); node = node.left
    def next(self) -> int:
        node = self.stack.pop()
        self._push_left(node.right)
        return node.val
    def hasNext(self) -> bool:
        return bool(self.stack)

next O(1) amortised · Space O(h). Converting recursion into an explicit stack for on-demand iteration is a broadly useful technique.

27 LC 450Delete Node in a BST Medium BST · replace with successor

Problem. Delete a node with a given key from a BST and return the (still valid) root. LeetCode 450 ↗

Clarify: Key may not exist? (Return tree unchanged.) Keep it a valid BST? (Yes.)

Hint 1
Search for the node using the BST property.
Hint 2
If it has two children, replace its value with the in-order successor, then delete that successor.

How to think about it Recurse to find the node. If it has zero or one child, splice it out by returning its (possibly null) child. With two children, copy the in-order successor's value (the smallest in the right subtree) into the node, then recursively delete that successor from the right subtree — preserving the BST order.

delete_bst.py
from typing import Optional

class Solution:
    def deleteNode(self, root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
        if not root:
            return None
        if key < root.val:
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:
            root.right = self.deleteNode(root.right, key)
        else:
            if not root.left:
                return root.right
            if not root.right:
                return root.left
            succ = root.right                     # in-order successor
            while succ.left:
                succ = succ.left
            root.val = succ.val
            root.right = self.deleteNode(root.right, succ.val)
        return root

Time O(h) · Space O(h). The two-children case (successor replacement) is the classic BST-deletion subtlety.

28 LC 701Insert into a Binary Search Tree Medium BST · walk down to a null spot

Problem. Insert a value into a BST and return the root; any valid BST result is accepted. LeetCode 701 ↗

Clarify: Value not already present? (Guaranteed.) Any valid position accepted? (Yes.)

Hint 1
Follow the BST property until you fall off the tree.
Hint 2
Create the new node at that empty spot.

How to think about it Recurse down using the ordering — left if smaller, right if larger — until you hit an empty child, where the new node goes. Each recursive call returns the (possibly new) subtree, wiring the node into place on the way back up.

insert_bst.py
from typing import Optional

class Solution:

29 LC 99Recover Binary Search Tree Medium Inorder · find the two swapped nodes

Problem. Two nodes of a BST were swapped by mistake. Recover the tree without changing its structure. LeetCode 99 ↗

Clarify: Exactly two nodes swapped? (Yes.) Fix values in place, keep structure? (Yes.)

Hint 1
Inorder of a correct BST is strictly increasing; the swap creates one or two descents.
Hint 2
Track the first and second offending nodes during inorder, then swap their values.

How to think about it Do an inorder traversal (which should be sorted). A swap produces a descent where prev.val > node.val: the first offending node is the earlier prev, and the second is the later node (updated on the second descent, if any). Swap their values to restore the BST.

recover_bst.py
from typing import Optional

class Solution:
    def recoverTree(self, root: Optional[TreeNode]) -> None:
        self.first = self.second = self.prev = None
        def inorder(node):
            if not node:
                return
            inorder(node.left)
            if self.prev and self.prev.val > node.val:   # a descent = a swapped pair
                if not self.first:
                    self.first = self.prev
                self.second = node
            self.prev = node
            inorder(node.right)
        inorder(root)
        self.first.val, self.second.val = self.second.val, self.first.val

Time O(n) · Space O(h). Spotting the one-or-two descents in the inorder sequence is the whole puzzle.

30 LC 124Binary Tree Maximum Path Sum Hard DFS · return one branch, track both

Problem. Return the maximum sum of any path (any node to any node) in the tree. LeetCode 124 ↗

Clarify: Path can start and end anywhere? (Yes.) At least one node? (Yes.)

Hint 1
At a node, the best path through it is node + best-left + best-right (clamp negatives to 0).
Hint 2
But you can only return ONE side upward to a parent.

How to think about it A DFS returning each node's best downward gain (node value plus the larger of its two positive branches). While recursing, update a global best with the full path through the node — node + leftGain + rightGain. Negative branches are clamped to 0 so they're simply dropped.

max_path_sum.py
from typing import Optional

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        self.best = float("-inf")
        def gain(node):
            if not node:
                return 0
            left = max(gain(node.left), 0)        # ignore negative branches
            right = max(gain(node.right), 0)
            self.best = max(self.best, node.val + left + right)   # path through node
            return node.val + max(left, right)    # can extend only one side upward
        gain(root)
        return self.best

Time O(n) · Space O(h). The split between 'what I return up (one side)' and 'what I record (both sides)' is the essential idea.

31 LC 297Serialize and Deserialize Binary Tree Hard Design · preorder with null markers

Problem. Encode a binary tree to a string and decode it back to the same tree. LeetCode 297 ↗

Clarify: Round-trip must reproduce the exact tree? (Yes.) Any format allowed? (Yes.)

Hint 1
A preorder traversal with explicit null markers uniquely encodes the tree.
Hint 2
Deserialize by consuming tokens in the same preorder, building recursively.

How to think about it Serialize with a preorder DFS, writing each value and a marker (#) for nulls — this fully captures the structure. Deserialize by consuming the tokens in the same order: a non-null token becomes a node whose left and right are built by recursive consumption. The null markers make the reconstruction unambiguous.

serialize_tree.py
from typing import Optional

class Codec:
    def serialize(self, root: Optional[TreeNode]) -> str:
        vals = []
        def dfs(node):
            if not node:
                vals.append("#"); return
            vals.append(str(node.val))
            dfs(node.left); dfs(node.right)       # preorder
        dfs(root)
        return ",".join(vals)
    def deserialize(self, data: str) -> Optional[TreeNode]:
        vals = iter(data.split(","))
        def build():
            v = next(vals)
            if v == "#":
                return None
            node = TreeNode(int(v))
            node.left = build()
            node.right = build()
            return node
        return build()

Time O(n) · Space O(n). Preorder + null sentinels is the cleanest serialization; BFS with markers works too.

32 LC 968Binary Tree Cameras Hard Greedy DFS · three states, place from leaves

Problem. Place the minimum number of cameras so every node is monitored (a camera covers its parent, itself, and children). LeetCode 968 ↗

Clarify: Each camera covers node + parent + children? (Yes.) Minimise cameras? (Yes.)

Hint 1
Work bottom-up; a node returns one of three states: uncovered, covered, or has-camera.
Hint 2
Place a camera only when a child is uncovered — greedily, as high as possible.

How to think about it Greedy DFS returning one of three states per node: uncovered, covered (no camera), or has-camera. Place a camera exactly when a child comes back uncovered (so leaves never hold cameras, their parents do); a node is covered if a child has a camera. After the DFS, if the root is still uncovered, add one camera.

tree_cameras.py
from typing import Optional

class Solution:
    def minCameraCover(self, root: Optional[TreeNode]) -> int:
        self.cameras = 0
        # 0 = uncovered, 1 = covered (no camera), 2 = has a camera
        def dfs(node):
            if not node:
                return 1
            l, r = dfs(node.left), dfs(node.right)
            if l == 0 or r == 0:                  # a child is uncovered -> place camera
                self.cameras += 1
                return 2
            if l == 2 or r == 2:                  # a child has a camera -> covered
                return 1
            return 0                              # both children covered but no camera
        if dfs(root) == 0:                        # root ended uncovered
            self.cameras += 1
        return self.cameras

Time O(n) · Space O(h). Encoding a greedy decision as three returned states is a powerful tree-DP idiom.

33 LC 987Vertical Order Traversal of a Binary Tree Hard DFS + coordinate sort

Problem. Group nodes by column (left −1, right +1); within a column, order by row then by value. LeetCode 987 ↗

Clarify: Ties within the same (row, col) sorted by value? (Yes.) Columns left to right? (Yes.)

Hint 1
Give each node a (row, col) coordinate during a DFS.
Hint 2
Bucket by column; sort each column's entries by (row, value).

How to think about it DFS assigning coordinates: going left decreases the column and increases the row; going right increases both differently. Collect (row, value) per column, then output columns left to right, sorting each column's nodes by row and then by value to break ties.

vertical_traversal.py
from typing import List, Optional
from collections import defaultdict

class Solution:
    def verticalTraversal(self, root: Optional[TreeNode]) -> List[List[int]]:
        nodes = defaultdict(list)                 # column -> list of (row, value)
        def dfs(node, row, col):
            if not node:
                return
            nodes[col].append((row, node.val))
            dfs(node.left, row + 1, col - 1)
            dfs(node.right, row + 1, col + 1)
        dfs(root, 0, 0)
        res = []
        for col in sorted(nodes):
            res.append([val for _, val in sorted(nodes[col])])   # by row, then value
        return res

Time O(n log n) · Space O(n). The careful tie-break (row then value) is what makes this a Hard rather than a Medium.

34 LC 834Sum of Distances in Tree Hard Rerooting DP · two passes

Problem. For each node in an undirected tree, return the sum of distances to all other nodes. LeetCode 834 ↗

Clarify: Tree given as edges (n nodes)? (Yes.) O(n) expected (not O(n²))? (Yes.)

Hint 1
Compute the answer for one root and every subtree size with a post-order pass.
Hint 2
Re-root to each child in a second pass: nodes in the child's subtree get 1 closer, the rest 1 farther.

How to think about it Rerooting dynamic programming. First DFS (post-order from node 0) computes subtree sizes and node 0's total distance. Second DFS pushes the answer to each child: moving the root from parent to child brings count[child] nodes one step closer and the other n − count[child] one step farther, so ans[child] = ans[parent] − count[child] + (n − count[child]).

sum_distances.py
from typing import List, Optional
from collections import defaultdict

class Solution:
    def sumOfDistancesInTree(self, n: int, edges: List[List[int]]) -> List[int]:
        graph = defaultdict(list)
        for a, b in edges:
            graph[a].append(b); graph[b].append(a)
        count = [1] * n                           # subtree sizes rooted at 0
        ans = [0] * n
        def dfs1(node, parent):                   # post-order: sizes + distances at 0
            for child in graph[node]:
                if child != parent:
                    dfs1(child, node)
                    count[node] += count[child]
                    ans[node] += ans[child] + count[child]
        def dfs2(node, parent):                   # re-root: shift the answer to children
            for child in graph[node]:
                if child != parent:
                    ans[child] = ans[node] - count[child] + (n - count[child])
                    dfs2(child, node)
        dfs1(0, -1)
        dfs2(0, -1)
        return ans

Time O(n) · Space O(n). Rerooting turns n independent O(n) computations into two linear passes — a hallmark tree-DP technique.

4 · Interview playbook

  • Default to recursion: handle the empty node, recurse on both children, combine. Say what each call returns.
  • DFS vs BFS: subtree-dependent answer → DFS; anything "by level" → BFS with a queue processing one level per pass.
  • Traversal choice: preorder to serialize/copy, postorder to aggregate from children, inorder for BSTs (it yields sorted order).
  • BST tricks: use left<node<right for O(h) search/LCA; validate with a (low, high) bound, not just parent comparisons.
  • Global-state DFS: when the answer isn't what you return upward (diameter, max path sum), track it in a shared variable while returning the single-branch value.

6 · Review

Cheat sheet
  • Depth / count / diameter / "path through node" → bottom-up DFS, return info up.
  • Root-to-leaf sums / paths → top-down DFS with an accumulator (+ backtrack).
  • "By level" / right view / min depth / width → BFS, one level per pass.
  • BST search/insert/delete/LCA → use the ordering (O(h)).
  • Validate BST → pass a (low, high) bound; kth smallest → inorder.
  • Build from traversals → root from pre/postorder, split via inorder.
  • Answer ≠ returned value (diameter, max path sum) → global variable + single-branch return.
  • Serialize → preorder with null markers; all-pairs distance → rerooting DP.

Concept checks

Why does validating a BST need a (low, high) range rather than just comparing each node to its parent?
A node must be greater/less than all its ancestors, not just its parent — a value can satisfy its parent yet violate a grandparent's bound
Because recursion is faster with a range
Because the tree might be unbalanced
Consider a node in the right subtree of a left child: it must still be smaller than the grandparent. Only a range inherited from every ancestor (tightened at each step) captures that; parent-only comparisons accept invalid trees.
In Binary Tree Maximum Path Sum, why does the DFS return only one branch's gain but record both?
A path passing through a node can use both children, but a path extending to the parent can only continue through one child — so you return the better single branch and record the two-branch total separately
Because negative values are ignored
Because the tree is a BST
The best path through a node bends through both subtrees, but that bent path can't be extended upward. The parent can only attach to one downward branch, so the function returns node + max(left, right) while the global best captures node + left + right.

Mastery checklist

  • I can write bottom-up DFS that returns info from children and combines it.
  • I can carry an accumulator down for root-to-leaf path problems.
  • I can write level-order BFS and its variants (right view, width).
  • I can use the BST ordering for search, validate, kth, and LCA.
  • I can construct a tree from traversals or a sorted array.
  • I can use a global variable with a single-branch return (diameter, max path sum).
