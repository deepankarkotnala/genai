Dynamic Programming — 1D

Dynamic programming solves a problem by breaking it into overlapping subproblems and remembering their answers instead of recomputing them. This chapter builds the core skill on a single dimension: define a state, write the recurrence, pick an order, and — usually — collapse the table to a couple of variables. Master the 1D case here and the 2D chapter becomes a natural extension. Every problem has a full, tested solution in LeetCode's class Solution format.

Outcome

Define a DP state and recurrence over one dimension, choose the right iteration order (including combinations vs permutations), recognise the classic families (Fibonacci-style, House Robber, Kadane, coin-change/knapsack, string partition, LIS, stock state machines), and reduce space to O(1) when only the last few states matter.

1 · Foundations

Read top to bottom — the state/recurrence/order framework is the reusable core of every DP problem. Already fluent? Skip to §2 Pattern library.

What is dynamic programming?

Dynamic programming applies when a problem has two properties: overlapping subproblems (the same smaller problems recur) and optimal substructure (an optimal answer is built from optimal answers to those subproblems). DP computes each subproblem once and stores it, turning exponential recursion into polynomial time. The whole method comes down to four questions:

1. State — what does dp[i] mean? 2. Recurrence — how does dp[i] depend on earlier states? 3. Base case — what are the smallest states? 4. Order — in what sequence can we fill them so dependencies are ready?

Two ways to fill the table: memoization vs tabulation

Top-down (memoization) writes the recursion naturally and caches results. Bottom-up (tabulation) fills an array from the base cases forward. They compute the same thing; tabulation avoids recursion limits and makes the space optimisation below obvious. We'll mostly tabulate.

Example — the same recurrence, both ways (Fibonacci)
fib_ways.py
from functools import lru_cache

@lru_cache(None)                 # top-down: recursion + cache
def fib_memo(n):
    if n < 2:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

def fib_tab(n):                  # bottom-up: fill from base cases
    if n < 2:
        return n
    dp = [0, 1]
    for i in range(2, n + 1):
        dp.append(dp[i - 1] + dp[i - 2])
    return dp[n]

print(fib_memo(10), fib_tab(10))   # 55 55
Output55 55

Both are O(n). The recursion caches each n once; the table computes each dp[i] once. Same subproblems, same work.

The 1D space optimisation: keep only what you need

When dp[i] depends only on the last one or two states, you don't need the whole array — just those variables. Fibonacci needs two; House Robber needs two; the stock DPs need a fixed handful. This drops O(n) space to O(1) and is expected in interviews once the recurrence is clear.

Example — House Robber, table then rolled to O(1)
rob_roll.py
def rob(nums):
    prev, curr = 0, 0            # best up to the two previous houses
    for n in nums:
        # either skip house n (keep curr) or rob it (prev + n)
        prev, curr = curr, max(curr, prev + n)
    return curr

print(rob([2, 7, 9, 3, 1]))      # 12  (rob houses 2, 9, 1)
Output12

Iteration order changes the answer: combinations vs permutations

In counting DPs, the loop order can decide what you count. Looping items on the outside counts each combination once (Coin Change II); looping the target on the outside counts every ordering (Combination Sum IV). Same recurrence, different loop nesting, different meaning — a subtlety worth internalising.

⚠️
1D DP pitfalls

State the meaning of dp[i] in words before coding — a fuzzy state is the #1 source of wrong recurrences. Initialise base cases correctly (dp[0]=1 for counting, 0/∞ for min). In 0/1 knapsack iterate capacity downward so each item is used once; in unbounded knapsack, upward. And watch loop order in counting DPs — it silently switches combinations and permutations.

1 LC 509Fibonacci Number Easy The DP starter · roll two variables

Problem. Return the n-th Fibonacci number, where F(0)=0, F(1)=1, F(n)=F(n−1)+F(n−2). LeetCode 509 ↗

Clarify: 0-indexed? (Yes.) Iterative to avoid exponential recursion? (Yes.)

Hint 1
Naive recursion recomputes the same values exponentially — the signature DP problem.
Hint 2
Each value depends only on the previous two, so keep just those two.

How to think about it The canonical introduction to DP: the recurrence F(n)=F(n−1)+F(n−2) has overlapping subproblems, so naive recursion is exponential. Since each term needs only the two before it, roll two variables forward — O(n) time, O(1) space. This 'keep the last k states' idea powers most of the chapter.

fibonacci.py
class Solution:
    def fib(self, n):
        if n < 2:
            return n
        a, b = 0, 1
        for _ in range(2, n + 1):
            a, b = b, a + b        # roll the window forward
        return b

Time O(n) · Space O(1). Recognising that only the last two states matter is the first and most reused DP space optimisation.

2 LC 1137N-th Tribonacci Number Easy Window of three states

Problem. Return the n-th Tribonacci number: T(0)=0, T(1)=T(2)=1, T(n)=T(n−1)+T(n−2)+T(n−3). LeetCode 1137 ↗

Clarify: Sum of the previous three? (Yes.) Handle the small base cases explicitly? (Yes.)

Hint 1
Same rolling idea as Fibonacci, but keep three values.
Hint 2
Handle n = 0, 1, 2 as base cases first.

How to think about it Identical structure to Fibonacci with a window of three. After the base cases, roll (a, b, c) forward so each step computes the next term as their sum. The state size (here three) is dictated by how far back the recurrence reaches.

tribonacci.py
class Solution:
    def tribonacci(self, n):
        if n == 0:
            return 0
        if n <= 2:
            return 1
        a, b, c = 0, 1, 1
        for _ in range(3, n + 1):
            a, b, c = b, c, a + b + c
        return c

Time O(n) · Space O(1). The recurrence's depth sets your state width — three terms back means three variables.

3 LC 70Climbing Stairs Easy Count paths · it's Fibonacci

Problem. You can climb 1 or 2 steps at a time. Count the distinct ways to reach the top of n steps. LeetCode 70 ↗

Clarify: Steps of size 1 or 2 only? (Yes.) Count distinct ordered sequences? (Yes.)

Hint 1
Ways to reach step n = ways to reach n−1 (then +1) plus ways to reach n−2 (then +2).
Hint 2
That's exactly the Fibonacci recurrence.

How to think about it The number of ways to reach step n is the ways to reach n−1 plus the ways to reach n−2 (the last move is +1 or +2) — the Fibonacci recurrence in disguise. Roll two counters forward. This is the archetypal 'count the paths' 1D DP.

climbing_stairs.py
class Solution:
    def climbStairs(self, n):
        a, b = 1, 1                # ways to reach the two previous steps
        for _ in range(n):
            a, b = b, a + b
        return a

Time O(n) · Space O(1). Many counting problems reduce to a familiar recurrence — spotting it saves you from reinventing the DP.

4 LC 746Min Cost Climbing Stairs Easy Minimise over two predecessors

Problem. Each step has a cost paid on stepping off it. Starting from step 0 or 1, return the minimum cost to reach the top. LeetCode 746 ↗

Clarify: You may start at index 0 or 1? (Yes.) The 'top' is one past the last step? (Yes.)

Hint 1
dp[i] = min cost to reach step i.
Hint 2
Reach i from i−1 or i−2, paying that step's cost: dp[i] = min(dp[i−1]+cost[i−1], dp[i−2]+cost[i−2]).

How to think about it Let dp[i] be the minimum cost to reach step i. You arrive from i−1 or i−2, paying that step's cost, so dp[i] = min(dp[i−1]+cost[i−1], dp[i−2]+cost[i−2]). The top is index n. This adds a cost/minimisation to the climbing-stairs recurrence.

min_cost_stairs.py
from typing import List

class Solution:
    def minCostClimbingStairs(self, cost):
        n = len(cost)
        dp = [0] * (n + 1)         # dp[i] = min cost to reach step i (top = n)
        for i in range(2, n + 1):
            dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])
        return dp[n]

Time O(n) · Space O(n). Turning 'count' into 'minimise cost' keeps the same transition shape — just swap sum for min.

5 LC 198House Robber Easy Take-or-skip · the DP template

Problem. You can't rob two adjacent houses. Return the maximum amount you can rob along a street. LeetCode 198 ↗

Clarify: Adjacent houses can't both be robbed? (Yes.) Maximise the total? (Yes.)

Hint 1
At each house, either skip it (keep the best so far) or rob it (best from two houses back + this).
Hint 2
dp[i] = max(dp[i−1], dp[i−2] + nums[i]).

How to think about it The foundational take-or-skip DP. At each house you either skip it — keeping the best through the previous house — or rob it, adding its value to the best through two houses back (since neighbours are off-limits). So dp[i] = max(dp[i−1], dp[i−2]+nums[i]), rolled with two variables.

house_robber.py
from typing import List

class Solution:
    def rob(self, nums):
        prev = curr = 0            # best without / with the previous house
        for n in nums:
            prev, curr = curr, max(curr, prev + n)
        return curr

Time O(n) · Space O(1). 'Include-this vs exclude-this' is one of the most transferable DP transitions — House Robber II and Delete-and-Earn are the same engine.

6 LC 121Best Time to Buy and Sell Stock Easy Track the best state so far

Problem. With one buy and one sell allowed, return the maximum profit (0 if none). LeetCode 121 ↗

Clarify: Exactly one transaction? (Yes.) Sell must come after buy? (Yes.)

Hint 1
Track the cheapest price seen so far as you scan.
Hint 2
The best profit is the largest (today's price − cheapest so far).

How to think about it A minimal DP: carry one piece of state — the cheapest price seen so far. At each day, the best sell-today profit is price − min_so_far; keep the maximum. It's the two-state stock DP collapsed to a single running minimum, and the gateway to the harder stock problems later in the chapter.

stock_i.py
from typing import List

class Solution:
    def maxProfit(self, prices):
        min_price = float("inf")
        best = 0
        for p in prices:
            min_price = min(min_price, p)   # cheapest day so far
            best = max(best, p - min_price)
        return best

Time O(n) · Space O(1). Carrying the best 'buy state' forward is the seed of the multi-state stock DPs (III, IV, cooldown, fee).

7 LC 213House Robber II Medium Circular · two linear runs

Problem. Houses are arranged in a circle, so the first and last are adjacent. Return the maximum robbery amount. LeetCode 213 ↗

Clarify: First and last houses can't both be robbed? (Yes.) Single house ⇒ rob it? (Yes.)

Hint 1
The circle means you can't take both the first and last house.
Hint 2
Run linear House Robber twice — once excluding the first house, once excluding the last — and take the max.

How to think about it The circular adjacency splits into two linear cases: either the first house is off the table or the last one is. Run the standard linear House Robber on nums[1:] and on nums[:-1] and take the better — this cleanly enforces 'not both ends' without extra state.

house_robber_ii.py
from typing import List

class Solution:
    def rob(self, nums):
        if len(nums) == 1:
            return nums[0]

        def rob_line(arr):
            prev = curr = 0
            for n in arr:
                prev, curr = curr, max(curr, prev + n)
            return curr

        # houses are circular ⇒ can't take both first and last
        return max(rob_line(nums[1:]), rob_line(nums[:-1]))

Time O(n) · Space O(1). Reducing a circular constraint to two linear subproblems is a widely reusable trick (see Circular Subarray).

8 LC 740Delete and Earn Medium Bucket by value · then House Robber

Problem. Taking a value earns all its copies but deletes every value±1. Maximise total points. LeetCode 740 ↗

Clarify: Taking value v removes all v−1 and v+1? (Yes.) You earn v times its count? (Yes.)

Hint 1
Sum the points contributed by each distinct value.
Hint 2
Taking value v forbids v−1 and v+1 — exactly House Robber over the value axis.

How to think about it Reframe onto the value axis: let points[v] be v × (count of v). Because taking v deletes v−1 and v+1, no two adjacent values can both be taken — the House Robber constraint. Run the take-or-skip DP over values 1..max.

delete_and_earn.py
from collections import Counter
from typing import List

class Solution:
    def deleteAndEarn(self, nums):
        counts = Counter(nums)
        max_val = max(nums)
        points = [v * counts[v] for v in range(max_val + 1)]
        prev = curr = 0            # taking value v forbids v-1 and v+1 ⇒ House Robber
        for v in range(1, max_val + 1):
            prev, curr = curr, max(curr, prev + points[v])
        return curr

Time O(n + maxV) · Space O(maxV). Transforming the input into a known DP's shape (here, House Robber) is often the whole solution.

9 LC 53Maximum Subarray Medium Kadane's algorithm

Problem. Return the largest sum of any contiguous subarray. LeetCode 53 ↗

Clarify: At least one element must be included? (Yes.) Values can be negative? (Yes.)

Hint 1
At each index, the best subarray ending here either extends the previous one or restarts at this element.
Hint 2
cur = max(nums[i], cur + nums[i]); track the global best.

How to think about it Kadane's algorithm. Track the best subarray sum ending at the current index: either extend the previous run (cur + n) or start fresh at n, whichever is larger. The global answer is the maximum such value over all indices. It's a 1D DP where the state is 'best run ending here'.

max_subarray.py
from typing import List

class Solution:
    def maxSubArray(self, nums):
        best = cur = nums[0]
        for n in nums[1:]:
            cur = max(n, cur + n)  # extend or restart the run
            best = max(best, cur)
        return best

Time O(n) · Space O(1). 'Extend or restart' is the essence of Kadane — the base for product and circular variants.

10 LC 918Maximum Sum Circular Subarray Medium Kadane twice · total minus min

Problem. Like Maximum Subarray, but the array is circular (the subarray may wrap around). LeetCode 918 ↗

Clarify: A wrapping subarray is allowed? (Yes.) The subarray must be non-empty? (Yes.)

Hint 1
The answer is either a normal (non-wrapping) max subarray, or a wrapping one.
Hint 2
A wrapping max = total − (minimum subarray). Guard the all-negative case.

How to think about it Two cases. A non-wrapping best is plain Kadane (best_max). A wrapping best leaves out a middle chunk, so it equals total − (minimum subarray) — found with a Kadane for the minimum. Return the larger, but if every element is negative the 'total − min' case degenerates to empty, so fall back to best_max.

circular_subarray.py
from typing import List

class Solution:
    def maxSubarraySumCircular(self, nums):
        total = cur_max = best_max = cur_min = best_min = nums[0]
        for n in nums[1:]:
            cur_max = max(n, cur_max + n)
            best_max = max(best_max, cur_max)
            cur_min = min(n, cur_min + n)
            best_min = min(best_min, cur_min)
            total += n
        # wrap-around best = total minus the minimum subarray; guard all-negative
        return best_max if best_max < 0 else max(best_max, total - best_min)

Time O(n) · Space O(1). Running Kadane for both max and min in one pass, plus the total, handles the wrap elegantly.

11 LC 152Maximum Product Subarray Medium Track both max and min

Problem. Return the largest product of any contiguous subarray. LeetCode 152 ↗

Clarify: Values may be negative or zero? (Yes.) Non-empty subarray? (Yes.)

Hint 1
A negative number flips the sign, so the smallest (most negative) product can become the largest.
Hint 2
Track BOTH the running max and running min product at each index.

How to think about it Unlike sums, a negative factor turns a large negative product into a large positive one — so you must track both the running maximum and minimum product ending here. Each step, the new max/min come from {n, cur_max·n, cur_min·n}. Zeros naturally reset both. The global maximum is the answer.

max_product_subarray.py
from typing import List

class Solution:
    def maxProduct(self, nums):
        best = cur_max = cur_min = nums[0]
        for n in nums[1:]:
            candidates = (n, cur_max * n, cur_min * n)   # a negative can flip min↔max
            cur_max, cur_min = max(candidates), min(candidates)
            best = max(best, cur_max)
        return best

Time O(n) · Space O(1). Carrying a second (min) state to survive sign flips is a common DP extension.

12 LC 322Coin Change Medium Unbounded knapsack · fewest coins

Problem. Return the fewest coins that sum to a target amount, or −1 if impossible. LeetCode 322 ↗

Clarify: Unlimited coins of each denomination? (Yes.) Return −1 if unreachable? (Yes.)

Hint 1
dp[a] = fewest coins to make amount a.
Hint 2
dp[a] = min over coins c of dp[a−c] + 1; start dp[0] = 0, rest = ∞.

How to think about it Bottom-up over amounts. dp[a] is the fewest coins summing to a; to make a, use some coin c and add one to dp[a−c], minimised over all coins. Initialise dp[0]=0 and the rest to infinity; an amount still infinite at the end is unreachable, so return −1.

coin_change.py
from typing import List

class Solution:
    def coinChange(self, coins, amount):
        dp = [0] + [float("inf")] * amount
        for a in range(1, amount + 1):
            for c in coins:
                if c <= a:
                    dp[a] = min(dp[a], dp[a - c] + 1)
        return dp[amount] if dp[amount] != float("inf") else -1

Time O(amount·coins) · Space O(amount). The unbounded-knapsack template — build every amount from smaller ones.

13 LC 518Coin Change II Medium Count combinations · coin-outer loop

Problem. Return the number of distinct combinations of coins that sum to the amount. LeetCode 518 ↗

Clarify: Order doesn't matter (combinations, not permutations)? (Yes.) Unlimited coins? (Yes.)

Hint 1
dp[a] = number of ways to make amount a; start dp[0] = 1.
Hint 2
Loop coins on the OUTSIDE so each combination is counted once regardless of order.

How to think about it Count ways with dp[a] += dp[a−c], seeding dp[0]=1. The crucial detail: iterate coins on the outer loop and amounts inside. This considers each coin type once, so {1,2} and {2,1} aren't counted separately — you get combinations, not permutations.

coin_change_ii.py
from typing import List

class Solution:
    def change(self, amount, coins):
        dp = [1] + [0] * amount    # one way to make 0
        for c in coins:            # coin outer loop ⇒ combinations, not permutations
            for a in range(c, amount + 1):
                dp[a] += dp[a - c]
        return dp[amount]

Time O(amount·coins) · Space O(amount). Loop order decides combinations vs permutations — contrast with Combination Sum IV next.

14 LC 377Combination Sum IV Medium Count permutations · target-outer loop

Problem. Return the number of ordered sequences of numbers that sum to the target. LeetCode 377 ↗

Clarify: Different orderings count as different (permutations)? (Yes.) Numbers reusable? (Yes.)

Hint 1
Same ways-counting DP as Coin Change II, but order matters here.
Hint 2
Loop the TARGET on the outside so each ordering is counted.

How to think about it Also dp[a] += dp[a−n] with dp[0]=1, but here order matters, so loop amounts on the outer loop and numbers inside. Every arrival at amount a considers all possible last elements, so {1,2} and {2,1} are counted separately — permutations.

combination_sum_iv.py
from typing import List

class Solution:
    def combinationSum4(self, nums, target):
        dp = [1] + [0] * target
        for a in range(1, target + 1):     # target outer ⇒ order matters (permutations)
            for n in nums:
                if n <= a:
                    dp[a] += dp[a - n]
        return dp[target]

Time O(target·n) · Space O(target). The mirror of Coin Change II: swapping the loop order swaps combinations for permutations.

15 LC 279Perfect Squares Medium Fewest-items knapsack · squares as coins

Problem. Return the least number of perfect squares that sum to n. LeetCode 279 ↗

Clarify: Squares like 1, 4, 9, … reusable any number of times? (Yes.)

Hint 1
It's Coin Change where the 'coins' are the perfect squares ≤ n.
Hint 2
dp[a] = min over squares sq of dp[a−sq] + 1.

How to think about it Recognise this as Coin Change with the perfect squares (1, 4, 9, …) as denominations. Precompute the squares up to n, then dp[a] = min(dp[a−sq]) + 1. Since every number is a sum of squares (Lagrange), no −1 case is needed.

perfect_squares.py
class Solution:
    def numSquares(self, n):
        dp = [0] + [float("inf")] * n
        squares = [i * i for i in range(1, int(n ** 0.5) + 1)]
        for a in range(1, n + 1):
            for sq in squares:
                if sq <= a:
                    dp[a] = min(dp[a], dp[a - sq] + 1)
        return dp[n]

Time O(n·√n) · Space O(n). Mapping an unfamiliar problem onto the coin-change template is the recurring skill.

16 LC 139Word Break Medium String partition DP

Problem. Return whether the string can be segmented into a space-separated sequence of dictionary words. LeetCode 139 ↗

Clarify: Words reusable? (Yes.) Must use the entire string? (Yes.)

Hint 1
dp[i] = can s[:i] be segmented?
Hint 2
dp[i] is true if some j < i has dp[j] true and s[j:i] is a word.

How to think about it Let dp[i] mean the prefix s[:i] is fully segmentable. It's true when some split point j has dp[j] true and the tail s[j:i] is a dictionary word. Seed dp[0]=True (empty prefix) and build up to dp[len(s)]. A set of words makes the membership check O(1).

word_break.py
from typing import List

class Solution:
    def wordBreak(self, s, wordDict):
        words = set(wordDict)
        dp = [True] + [False] * len(s)     # dp[i] = s[:i] is breakable
        for i in range(1, len(s) + 1):
            for j in range(i):
                if dp[j] and s[j:i] in words:
                    dp[i] = True
                    break
        return dp[len(s)]

Time O(n²·L) · Space O(n). 'Is the prefix solvable, split at some earlier point' is the string-partition DP shape.

17 LC 91Decode Ways Medium Count decodings · Fibonacci-like

Problem. Digits map A→1 … Z→26. Count the ways to decode a digit string into letters. LeetCode 91 ↗

Clarify: Leading zeros are invalid? (Yes.) '0' can only pair as 10 or 20? (Yes.)

Hint 1
dp[i] = ways to decode s[:i].
Hint 2
Add dp[i−1] if the single digit is valid (1–9), plus dp[i−2] if the two-digit is 10–26.

How to think about it A Fibonacci-shaped count with validity gates. The ways to decode up to position i add the ways ending in a valid single digit (s[i] ≠ '0') and the ways ending in a valid two-digit block (10–26). Careful handling of zeros (which can't stand alone) is the whole difficulty; roll two counters forward.

decode_ways.py
class Solution:
    def numDecodings(self, s):
        if not s or s[0] == "0":
            return 0
        prev, curr = 1, 1          # ways for s[:i-1], s[:i]
        for i in range(1, len(s)):
            temp = 0
            if s[i] != "0":                        # single-digit decode
                temp += curr
            if 10 <= int(s[i - 1:i + 1]) <= 26:    # two-digit decode
                temp += prev
            prev, curr = curr, temp
        return curr

Time O(n) · Space O(1). Same two-term recurrence as climbing stairs, gated by which decodings are legal.

18 LC 300Longest Increasing Subsequence Medium Patience sorting · binary search

Problem. Return the length of the longest strictly increasing subsequence. LeetCode 300 ↗

Clarify: Strictly increasing? (Yes.) Subsequence (not contiguous)? (Yes.)

Hint 1
The O(n²) DP is dp[i] = 1 + max(dp[j]) for j < i with nums[j] < nums[i].
Hint 2
The O(n log n) trick keeps 'tails' — the smallest possible tail for each LIS length — and binary-searches each number in.

How to think about it The fast solution maintains tails, where tails[k] is the smallest possible tail value of an increasing subsequence of length k+1. For each number, binary-search its insertion point: if it extends all tails, append it; otherwise overwrite the first tail ≥ it, keeping tails minimal. The LIS length is len(tails).

lis.py
import bisect
from typing import List

class Solution:
    def lengthOfLIS(self, nums):
        tails = []                 # tails[k] = smallest tail of an LIS of length k+1
        for n in nums:
            i = bisect.bisect_left(tails, n)
            if i == len(tails):
                tails.append(n)
            else:
                tails[i] = n       # keep tails as small as possible
        return len(tails)

Time O(n log n) · Space O(n). The patience-sorting insight turns a quadratic subsequence DP into a log-linear one.

19 LC 673Number of Longest Increasing Subsequence Medium LIS DP · carry a count

Problem. Return how many longest strictly increasing subsequences the array has. LeetCode 673 ↗

Clarify: Count distinct LIS of the maximum length? (Yes.)

Hint 1
Alongside length[i] (LIS ending at i), keep count[i] (how many such LIS).
Hint 2
When length[j]+1 beats length[i], copy the count; when it ties, add to it.

How to think about it Extend the O(n²) LIS DP with a parallel count. For each pair j < i with nums[j] < nums[i]: if length[j]+1 gives a new best length ending at i, inherit count[j]; if it ties the current best, add count[j]. Sum the counts over all indices achieving the global maximum length.

num_lis.py
from typing import List

class Solution:
    def findNumberOfLIS(self, nums):
        n = len(nums)
        length = [1] * n           # LIS length ending at i
        count = [1] * n            # number of such LIS
        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    if length[j] + 1 > length[i]:
                        length[i] = length[j] + 1
                        count[i] = count[j]
                    elif length[j] + 1 == length[i]:
                        count[i] += count[j]
        longest = max(length)
        return sum(c for l, c in zip(length, count) if l == longest)

Time O(n²) · Space O(n). Pairing a 'count' array with a 'length' array is the standard way to count optimal solutions.

20 LC 96Unique Binary Search Trees Medium Catalan numbers · split on the root

Problem. Return the number of structurally distinct BSTs storing values 1..n. LeetCode 96 ↗

Clarify: Count structurally unique BST shapes? (Yes.) Values are 1..n? (Yes.)

Hint 1
Fix each value as the root; the left subtree uses the smaller values, the right the larger.
Hint 2
dp[n] = Σ dp[i−1]·dp[n−i] over each choice of root i (Catalan recurrence).

How to think about it Choose each value i as the root: the i−1 smaller values form the left subtree and the n−i larger ones the right, independently. So dp[n] = Σ dp[i−1]·dp[n−i] — the Catalan number recurrence. Build dp up from dp[0]=dp[1]=1.

unique_bst.py
class Solution:
    def numTrees(self, n):
        dp = [1] * (n + 1)         # dp[0]=dp[1]=1 (Catalan numbers)
        for nodes in range(2, n + 1):
            total = 0
            for root in range(1, nodes + 1):      # each value as the root
                total += dp[root - 1] * dp[nodes - root]
            dp[nodes] = total
        return dp[n]

Time O(n²) · Space O(n). 'Split on a pivot and multiply independent subproblems' is a recurring counting-DP structure.

21 LC 343Integer Break Medium Break into a sum · maximise product

Problem. Break n into the sum of at least two positive integers to maximise their product. LeetCode 343 ↗

Clarify: At least two parts required? (Yes.) Parts are positive integers? (Yes.)

Hint 1
dp[i] = max product from breaking i (into ≥ 2 parts).
Hint 2
For each first part j: either leave i−j whole (j·(i−j)) or break it further (j·dp[i−j]).

How to think about it Let dp[i] be the best product from breaking i. Trying each first factor j, you either stop (product j·(i−j), leaving i−j whole) or break the rest (j·dp[i−j]). Take the max over both choices and all j. Considering 'leave whole vs break further' avoids forcing an unwanted extra split.

integer_break.py
class Solution:
    def integerBreak(self, n):
        dp = [0] * (n + 1)
        dp[1] = 1
        for i in range(2, n + 1):
            for j in range(1, i):
                # j × (leave i-j whole)  or  j × (best break of i-j)
                dp[i] = max(dp[i], j * (i - j), j * dp[i - j])
        return dp[n]

Time O(n²) · Space O(n). The 'stop or recurse' choice inside the transition is a subtle but common DP detail.

22 LC 416Partition Equal Subset Sum Medium 0/1 knapsack · reachable sums

Problem. Return whether the array can be split into two subsets of equal sum. LeetCode 416 ↗

Clarify: Each number used in exactly one subset? (Yes.) Equal halves? (Yes.)

Hint 1
Feasible only if the total is even; target is total / 2.
Hint 2
Boolean 0/1 knapsack: can we reach exactly target? Iterate the capacity DOWNWARD per item.

How to think about it If the total is odd, no split exists. Otherwise it's a subset-sum: can some subset reach total/2? Use a boolean dp over sums, and for each number update capacities downward (target … num) so each item is used at most once — the 0/1 knapsack space optimisation.

partition_subset_sum.py
from typing import List

class Solution:
    def canPartition(self, nums):
        total = sum(nums)
        if total % 2:
            return False
        target = total // 2
        dp = [True] + [False] * target        # subset-sum reachability
        for n in nums:
            for a in range(target, n - 1, -1):  # iterate down ⇒ each item used once
                dp[a] = dp[a] or dp[a - n]
        return dp[target]

Time O(n·target) · Space O(target). Iterating capacity downward is what distinguishes 0/1 knapsack from the unbounded coin-change loop.

23 LC 264Ugly Number II Medium Merge three multiplied streams

Problem. Return the n-th ugly number (whose only prime factors are 2, 3, and 5). LeetCode 264 ↗

Clarify: 1 is the first ugly number? (Yes.) Factors limited to 2, 3, 5? (Yes.)

Hint 1
Every ugly number is a previous ugly number times 2, 3, or 5.
Hint 2
Keep three pointers into the built list; each step take the min of the three candidates and advance whichever produced it.

How to think about it Build the sequence in order. Each ugly number is an earlier one multiplied by 2, 3, or 5, so keep three pointers into the list already built and, each step, take the smallest of dp[i2]·2, dp[i3]·3, dp[i5]·5. Advance every pointer that produced that minimum (to skip duplicates like 6 = 2·3 = 3·2).

ugly_number_ii.py
class Solution:
    def nthUglyNumber(self, n):
        dp = [1] * n
        i2 = i3 = i5 = 0           # pointers into already-built ugly numbers
        for i in range(1, n):
            nxt = min(dp[i2] * 2, dp[i3] * 3, dp[i5] * 5)
            dp[i] = nxt
            if nxt == dp[i2] * 2:
                i2 += 1
            if nxt == dp[i3] * 3:
                i3 += 1
            if nxt == dp[i5] * 5:
                i5 += 1
        return dp[n - 1]

Time O(n) · Space O(n). Merging multiple monotonic streams with pointers is a neat DP-flavoured technique.

24 LC 309Stock with Cooldown Hard State machine · hold / sold / rest

Problem. Unlimited transactions, but after selling you must cooldown one day before buying. Maximise profit. LeetCode 309 ↗

Clarify: One-day cooldown after each sell? (Yes.) Hold at most one share? (Yes.)

Hint 1
Model three daily states: holding, just-sold (cooldown), and resting.
Hint 2
hold = max(hold, rest−p); sold = hold+p; rest = max(rest, prev sold).

How to think about it A three-state machine tracked per day. hold = best while owning a share; sold = best having just sold today (must rest tomorrow); rest = best while idle and free to buy. Transitions: buy only from rest (enforcing cooldown), sell moves hold→sold, and rest carries the previous sold. The answer is max(sold, rest) at the end.

stock_cooldown.py
from typing import List

class Solution:
    def maxProfit(self, prices):
        hold = float("-inf")       # best while holding a share
        sold = 0                   # best having just sold (cooldown next)
        rest = 0                   # best while resting (free to buy)
        for p in prices:
            prev_sold = sold
            sold = hold + p
            hold = max(hold, rest - p)
            rest = max(rest, prev_sold)
        return max(sold, rest)

Time O(n) · Space O(1). Modelling constraints as a small state machine is the key to the entire stock-DP family.

25 LC 714Stock with Transaction Fee Hard Two-state DP · pay a fee per sell

Problem. Unlimited transactions, but each sale charges a fixed fee. Maximise profit. LeetCode 714 ↗

Clarify: Fee charged once per completed transaction (on sell)? (Yes.)

Hint 1
Two states: cash (not holding) and hold (holding).
Hint 2
cash = max(cash, hold + price − fee); hold = max(hold, cash − price).

How to think about it Track two states each day: cash (not holding) and hold (holding). Selling adds price − fee to move from hold to cash; buying subtracts price to move from cash to hold. Charging the fee on sale keeps the accounting clean. The final cash is the answer.

stock_fee.py
from typing import List

class Solution:
    def maxProfit(self, prices, fee):
        hold = -prices[0]          # holding a share
        cash = 0                   # not holding
        for p in prices[1:]:
            cash = max(cash, hold + p - fee)
            hold = max(hold, cash - p)
        return cash

Time O(n) · Space O(1). The two-state hold/cash DP underlies every unlimited-transaction stock variant.

26 LC 123Stock III (at most 2 transactions) Hard Four running states

Problem. With at most two transactions, return the maximum profit. LeetCode 123 ↗

Clarify: At most two complete buy-sell pairs? (Yes.) No overlapping transactions? (Yes.)

Hint 1
Track four states in order: after buy1, sell1, buy2, sell2.
Hint 2
Each depends on the previous: buy2 uses sell1's profit as its 'starting cash'.

How to think about it Carry four running bests, chained: buy1 (best after the first buy), sell1 (after the first sell), buy2 (after the second buy, funded by sell1), and sell2 (after the second sell). Updating them in order each day lets the second transaction build on the first's profit. The answer is sell2.

stock_iii.py
from typing import List

class Solution:
    def maxProfit(self, prices):
        buy1 = buy2 = float("-inf")
        sell1 = sell2 = 0
        for p in prices:           # at most two transactions
            buy1 = max(buy1, -p)
            sell1 = max(sell1, buy1 + p)
            buy2 = max(buy2, sell1 - p)
            sell2 = max(sell2, buy2 + p)
        return sell2

Time O(n) · Space O(1). Chaining fixed states in order generalises to k transactions (Stock IV next).

27 LC 188Stock IV (at most k transactions) Hard Generalise to k · arrays of states

Problem. With at most k transactions, return the maximum profit. LeetCode 188 ↗

Clarify: k can exceed the useful maximum (n/2)? (Yes — then it's unlimited.)

Hint 1
If k ≥ n/2, transactions are effectively unlimited — sum every uptick.
Hint 2
Otherwise keep buy[j], sell[j] for j = 1..k and update all j each day.

How to think about it Generalise Stock III to arrays. If k ≥ n/2 you can take every profitable day (unlimited case), so short-circuit to summing upticks. Otherwise maintain buy[j] and sell[j] for each transaction count j = 1..k; each day update every j so buy[j] uses sell[j−1] as its funding. The answer is sell[k].

stock_iv.py
from typing import List

class Solution:
    def maxProfit(self, k, prices):
        n = len(prices)
        if k >= n // 2:            # unlimited transactions ⇒ grab every uptick
            return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, n))
        buy = [float("-inf")] * (k + 1)
        sell = [0] * (k + 1)
        for p in prices:
            for j in range(1, k + 1):
                buy[j] = max(buy[j], sell[j - 1] - p)
                sell[j] = max(sell[j], buy[j] + p)
        return sell[k]

Time O(n·k) · Space O(k). The unlimited-case short-circuit avoids blowing up when k is large — a common DP guard.

28 LC 32Longest Valid Parentheses Hard DP on runs ending at i

Problem. Return the length of the longest valid (well-formed) parentheses substring. LeetCode 32 ↗

Clarify: Only '(' and ')'? (Yes.) Substring must be contiguous and balanced? (Yes.)

Hint 1
dp[i] = length of the longest valid substring ending exactly at i.
Hint 2
For s[i]=')': pair with s[i−1]='(' directly, or jump over the run dp[i−1] to find a matching '(' before it.

How to think about it Let dp[i] be the longest valid substring ending at index i (nonzero only when s[i]=')'). Two cases: a direct pair () adds 2 plus whatever ended before it; or a ))-style close where the matching ( sits just before the valid run dp[i−1], in which case add that run, the new pair, and any valid substring preceding the match.

longest_valid_paren.py
class Solution:
    def longestValidParentheses(self, s):
        dp = [0] * len(s)          # dp[i] = length of valid run ending at i
        best = 0
        for i in range(1, len(s)):
            if s[i] == ")":
                if s[i - 1] == "(":
                    dp[i] = (dp[i - 2] if i >= 2 else 0) + 2
                elif i - dp[i - 1] - 1 >= 0 and s[i - dp[i - 1] - 1] == "(":
                    dp[i] = dp[i - 1] + 2 + (dp[i - dp[i - 1] - 2] if i - dp[i - 1] - 2 >= 0 else 0)
                best = max(best, dp[i])
        return best

Time O(n) · Space O(n). 'Longest valid run ending here', with careful index arithmetic, is a classic hard 1D DP (a stack solution also works).

4 · Interview playbook

  • Say the state out loud. "dp[i] = the fewest coins to make amount i" — a precise state makes the recurrence almost write itself.
  • Name the family. Adjacency/exclusion → House Robber; contiguous best → Kadane; reach/count/minimise a target → knapsack; constrained transactions → state machine.
  • Get the base cases and loop order right — dp[0]=1 for counting, downward capacity for 0/1 knapsack, and coins-outer vs target-outer for combinations vs permutations.
  • Optimise space last. Write the array DP for clarity, then collapse to a few variables once the dependency depth is clear.
  • If greedy felt tempting but unprovable (previous chapter), DP is usually the correct, safe tool.

6 · Review

Cheat sheet
  • Ways/value at step n from previous steps → linear recurrence (roll variables).
  • Pick items with an adjacency/exclusion rule → House Robber take-or-skip.
  • Best contiguous sum/product → Kadane (extend or restart; track min too for products/circular).
  • Reach / count / minimise a target from items → knapsack / coin change (loop order = combinations vs permutations; downward = 0/1).
  • Segment or decode a string → partition DP over split points.
  • Longest increasing subsequence → patience sorting + binary search (O(n log n)).
  • Constrained transactions (cooldown, fee, k limit) → state-machine DP.
  • Only the last few states used → collapse to O(1) space.

Concept checks

In a counting DP, why does looping coins on the outside (Coin Change II) count combinations, while looping the target on the outside (Combination Sum IV) counts permutations?
Coins-outer considers each coin type only once for all amounts, so an order like {1,2} is built the same way as {2,1}; target-outer reconsiders every coin at each amount, counting each ordering separately
Because Combination Sum IV uses larger numbers
Because one uses addition and the other uses minimum
With coins on the outer loop, once you finish processing a coin you never revisit it, so each unordered combination is counted exactly once. With the target on the outer loop, every amount reconsiders all coins as the possible last element, so {1,2} and {2,1} are both counted — permutations. Same recurrence, different loop nesting.
When can you reduce a 1D DP from O(n) space to O(1)?
When dp[i] depends only on a fixed, small number of the most recent states (e.g. dp[i−1] and dp[i−2]) — you keep just those in rolling variables instead of the whole array
Only when the array is sorted
Whenever the answer is a single number
The space optimisation is valid exactly when the recurrence reaches back a bounded distance. Fibonacci and House Robber reach two steps back, so two variables suffice; the stock DPs keep a fixed handful. If a transition needs an arbitrary earlier state (like LIS's O(n²) form), you can't collapse it that way.

  • I can apply Kadane (and its min/product/circular variants).
  • I can write coin-change/knapsack DPs and get the loop order right.
