Python's sort, and sorting by a key

Python's sorted() and list.sort() use Timsort: O(n log n), and stable (equal elements keep their original order — which matters more than people expect). The real power is the key argument: sort by any derived value, including a tuple for multi-level ordering.

Example — key functions and tuple keys
sorting.py
words = ["banana", "kiwi", "apple", "fig"]
print(sorted(words, key=len))          # ['fig', 'kiwi', 'apple', 'banana']

people = [("Ann", 30), ("Bob", 25), ("Cid", 30)]
# sort by age ascending, then name ascending  (tuple key)
print(sorted(people, key=lambda p: (p[1], p[0])))
# [('Bob', 25), ('Ann', 30), ('Cid', 30)]

nums = [3, 1, 2]
print(sorted(nums, reverse=True))      # [3, 2, 1]
Output['fig', 'kiwi', 'apple', 'banana']
[('Bob', 25), ('Ann', 30), ('Cid', 30)]
[3, 2, 1]
A tuple key encodes multi-level ordering: (-count, word) means "highest count first, ties alphabetical". When the order can't be expressed as a key (it depends on pairs of elements), use a comparator with functools.cmp_to_key — as in Largest Number.

When comparison sort is overkill: counting sort

Comparison sorts can't beat O(n log n) in general. But if the values are integers in a small, known range, you can sort in O(n) by counting occurrences — no comparisons at all. Great for bounded data like ages, heights, or lowercase letters.

Intervals: sort, then sweep

Nearly every interval problem starts the same way: sort by start time (sometimes by end), then make one pass. Once sorted, overlaps become local — you only compare each interval to the previous kept one.

Example — merge overlapping intervals
merge.py
def merge(intervals):
    intervals.sort(key=lambda iv: iv[0])     # sort by start
    out = []
    for s, e in intervals:
        if out and s <= out[-1][1]:          # overlaps the last kept interval
            out[-1][1] = max(out[-1][1], e)  # extend it
        else:
            out.append([s, e])               # disjoint -> new interval
    return out

print(merge([[1,3],[2,6],[8,10],[15,18]]))   # [[1,6],[8,10],[15,18]]
Output[[1, 6], [8, 10], [15, 18]]

Sort by start to merge; sort by end for greedy "keep the most / remove the fewest" problems (Non-overlapping Intervals, Burst Balloons). Choosing the right sort key is the whole game.

Selection: don't always sort

If you only need the k-th element or the top k, fully sorting (O(n log n)) is wasteful. Two better tools: a heap of size k gives top-k in O(n log k) and works on streams; quickselect finds the k-th element in O(n) average by partitioning and recursing into only one side.

Example — a size-k heap for the k largest
topk.py
import heapq

def k_largest(nums, k):
    heap = []                       # min-heap of the k largest so far
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)     # drop the smallest -> keep top k
    return sorted(heap, reverse=True)

print(k_largest([3, 1, 5, 12, 2, 11], 3))   # [12, 11, 5]
⚠️
Sorting & selection pitfalls

Python's heapq is a min-heap — negate values (or keys) for a max-heap. Rely on stability only when you mean to. For "top k", prefer a size-k heap or quickselect over a full sort. And for intervals, always ask: sort by start or by end? Getting that wrong quietly breaks the greedy.

2 · Pattern library

Almost every problem here is one of these six. Learn the signal and the core move, and the code follows.

1Custom comparator / key sort

Signal
order by a derived value or pairwise rule
Move
key= tuple, or cmp_to_key for pairwise
Cost
O(n log n)

2Counting / bucket sort

Signal
values in a small known range; top-k by count
Move
tally into buckets, read them in order
Cost
O(n + range)

3Interval merge (sort by start)

Signal
merge/insert/cover overlapping ranges
Move
sort by start, sweep, extend or open
Cost
O(n log n)

4Interval greedy (sort by end)

Signal
keep the most / remove the fewest / min arrows
Move
sort by end, greedily keep earliest finishers
Cost
O(n log n)

5Heap for top-k / kth / streaming

Signal
k largest/smallest, running median, k-way merge
Move
size-k heap, or two heaps at the median
Cost
O(n log k)

6Quickselect & merge-sort counting

Signal
k-th element; count inversions / cross-pairs
Move
partition and recurse one side; count during merge
Cost
O(n) avg / O(n log n)

1 LC 1051Height Checker Easy Compare to the sorted order

Problem. Count how many students stand out of non-decreasing height order. LeetCode 1051 ↗

Clarify: Compare against the sorted arrangement? (Yes.) Count mismatched positions? (Yes.)

Hint 1
The 'expected' order is just the sorted array.
Hint 2
Count positions where the current height differs from the sorted one.

How to think about it The expected lineup is the array sorted ascending. Zip the original with the sorted copy and count the positions that differ. (Because heights are bounded, counting sort gives an O(n) alternative to the O(n log n) sort.)

height_checker.py
from typing import List

class Solution:
    def heightChecker(self, heights: List[int]) -> int:
        expected = sorted(heights)
        return sum(1 for a, b in zip(heights, expected) if a != b)

Time O(n log n) · Space O(n). A one-line intro to 'sort, then compare' — the backbone of the chapter.

2 LC 561Array Partition Easy Sort, then pair neighbours

Problem. Split the array into pairs to maximise the sum of each pair's minimum. LeetCode 561 ↗

Clarify: Maximise the sum of min of each pair? (Yes.) 2n elements? (Yes.)

Hint 1
To not 'waste' large numbers, pair each with the closest smaller number.
Hint 2
After sorting, pairing adjacent elements and summing every first one is optimal.

How to think about it Sort ascending. Pairing adjacent elements minimises the loss from each min, and the answer is the sum of every other element (indices 0, 2, 4, …). A quick exchange argument shows any other pairing does no better.

array_partition.py
from typing import List

class Solution:
    def arrayPairSum(self, nums: List[int]) -> int:
        nums.sort()
        return sum(nums[::2])                 # pair neighbours; take every first

Time O(n log n) · Space O(1). A tidy example of sorting to expose a greedy structure.

3 LC 1122Relative Sort Array Easy Custom key · rank then value

Problem. Sort arr1 so elements appear in the order given by arr2; anything not in arr2 goes last, ascending. LeetCode 1122 ↗

Clarify: Elements of arr2 are distinct and appear in arr1? (Yes.) The rest sorted ascending after? (Yes.)

Hint 1
Give each arr2 value a rank; unknown values get a rank after all of them.
Hint 2
Sort by (rank, value).

How to think about it Build a rank map from arr2. Sort arr1 by the compound key (rank, value) — known values order by their arr2 rank, and unknown values fall to the end (given a sentinel rank) ordered by value.

relative_sort.py
from typing import List

class Solution:
    def relativeSortArray(self, arr1: List[int], arr2: List[int]) -> List[int]:
        order = {v: i for i, v in enumerate(arr2)}
        # in arr2 order first (by rank), then the rest ascending
        return sorted(arr1, key=lambda x: (order.get(x, len(arr2)), x))

Time O(n log n) · Space O(n). Encoding a two-level ordering in a tuple key is the reusable idea.

4 LC 506Relative Ranks Easy Sort indices by score

Problem. Assign 'Gold/Silver/Bronze Medal' to the top three scores and numeric ranks to the rest. LeetCode 506 ↗

Clarify: Scores are distinct? (Yes.) Top three get medals, others get rank numbers? (Yes.)

Hint 1
Sort the positions by descending score.
Hint 2
Walk them assigning medal or rank based on position.

How to think about it Sort the indices by score descending. The first three get medals; the rest get their 1-based rank as a string. Writing back to a result array by index preserves the original order.

relative_ranks.py
from typing import List

class Solution:
    def findRelativeRanks(self, score: List[int]) -> List[str]:
        ranked = sorted(range(len(score)), key=lambda i: -score[i])
        medals = ["Gold Medal", "Silver Medal", "Bronze Medal"]
        res = [""] * len(score)
        for rank, i in enumerate(ranked):
            res[i] = medals[rank] if rank < 3 else str(rank + 1)
        return res

Time O(n log n) · Space O(n). Sorting indices (not values) is how you rank while keeping positions.

5 LC 252Meeting Rooms Easy Sort by start, check adjacency

Problem. Given meeting intervals, return whether a person can attend all of them (no overlaps). LeetCode 252 ↗

Clarify: Touching intervals (end == next start) are OK? (Yes.) Sort first? (Yes.)

Hint 1
After sorting by start, overlaps can only be between adjacent meetings.
Hint 2
If any meeting starts before the previous one ends, they conflict.

How to think about it Sort by start time. Then a conflict can only occur between consecutive meetings, so scan adjacent pairs: if any meeting starts before the previous one ends, return False. This 'sort then sweep' is the interval template.

meeting_rooms.py
from typing import List

class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        intervals.sort()
        for i in range(1, len(intervals)):
            if intervals[i][0] < intervals[i - 1][1]:   # overlap
                return False
        return True

Time O(n log n) · Space O(1). The simplest interval problem — sorting makes overlaps local.

6 LC 414Third Maximum Number Easy Selection · keep the top three

Problem. Return the third distinct maximum; if it doesn't exist, return the maximum. LeetCode 414 ↗

Clarify: Distinct values only for 'maximum'? (Yes.) Fewer than 3 distinct → return the max? (Yes.)

Hint 1
You only need the three largest distinct values, not a full sort.
Hint 2
Keep a set of size ≤ 3, evicting the smallest when it grows.

How to think about it Selection without sorting. Maintain a set of the largest distinct values, capped at three; whenever it exceeds three, drop its minimum. At the end, return the set's min if it holds three, else its max.

third_max.py
from typing import List

class Solution:
    def thirdMax(self, nums: List[int]) -> int:
        top = set()
        for x in nums:
            top.add(x)
            if len(top) > 3:
                top.remove(min(top))          # keep only the three largest
        return min(top) if len(top) == 3 else max(top)

Time O(n) · Space O(1). When you need only the top few, track them directly rather than sorting.

7 LC 1046Last Stone Weight Easy Max-heap · repeatedly smash the two largest

Problem. Repeatedly smash the two heaviest stones; return the weight of the last remaining stone (or 0). LeetCode 1046 ↗

Clarify: Smash the two heaviest each round? (Yes.) Equal weights annihilate? (Yes.)

Hint 1
You repeatedly need the two largest — that's a heap.
Hint 2
Python's heapq is a min-heap; negate values for a max-heap.

How to think about it A max-heap gives the two heaviest stones in O(log n) each round. Pop two, and if they differ push back the difference. Since heapq is a min-heap, store negatives. Repeat until one or zero stones remain.

last_stone.py
from typing import List
import heapq

class Solution:
    def lastStoneWeight(self, stones: List[int]) -> int:
        heap = [-s for s in stones]           # max-heap via negation
        heapq.heapify(heap)
        while len(heap) > 1:
            a = -heapq.heappop(heap)
            b = -heapq.heappop(heap)
            if a != b:
                heapq.heappush(heap, -(a - b))
        return -heap[0] if heap else 0

Time O(n log n) · Space O(n). Negating for a max-heap is the standard Python idiom.

8 LC 703Kth Largest Element in a Stream Easy Design · min-heap of size k

Problem. Design a class that returns the k-th largest element seen so far after each add. LeetCode 703 ↗

Clarify: k-th largest overall (with duplicates counted)? (Yes.) Stream of adds? (Yes.)

Hint 1
Keep only the k largest values in a min-heap.
Hint 2
Its smallest element is exactly the k-th largest.

How to think about it Maintain a min-heap capped at size k. Adding pushes the value and pops the smallest if the size exceeds k, so the heap always holds the top-k and its root is the k-th largest. Streaming-friendly and O(log k) per add.

kth_largest_stream.py
from typing import List
import heapq

class KthLargest:
    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = nums
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)          # keep only the k largest
    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]                   # kth largest = heap min

add O(log k) · Space O(k). A size-capped min-heap is the canonical top-k-in-a-stream tool.

9 LC 912Sort an Array Medium Implement merge sort

Problem. Sort an integer array in O(n log n) without using the language's built-in sort. LeetCode 912 ↗

Clarify: Must implement a real O(n log n) sort? (Yes.) Stability required? (Merge sort is stable.)

Hint 1
Divide the array in half, sort each half, then merge.
Hint 2
Merging two sorted halves is a linear two-pointer walk.

How to think about it Classic merge sort: recursively split to single elements, then merge sorted halves by repeatedly taking the smaller front. O(n log n) time, stable, with O(n) auxiliary space. (Quicksort is the in-place alternative; mention its O(n²) worst case.)

sort_array.py
from typing import List

class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        def merge_sort(a):
            if len(a) <= 1:
                return a
            mid = len(a) // 2
            left = merge_sort(a[:mid])
            right = merge_sort(a[mid:])
            merged, i, j = [], 0, 0
            while i < len(left) and j < len(right):
                if left[i] <= right[j]:
                    merged.append(left[i]); i += 1
                else:
                    merged.append(right[j]); j += 1
            merged.extend(left[i:])
            merged.extend(right[j:])
            return merged
        return merge_sort(nums)

Time O(n log n) · Space O(n). Knowing how sort() works under the hood — and merge sort specifically — pays off in the divide-and-conquer hard problems below.

10 LC 969Pancake Sorting Medium Selection sort via prefix flips

Problem. Sort the array using only 'flip the first k elements' operations; return the sequence of flip sizes. LeetCode 969 ↗

Clarify: Only prefix reversals allowed? (Yes.) Any valid flip sequence accepted? (Yes.)

Hint 1
Place the largest unsorted value at its final spot each round, like selection sort.
Hint 2
Flip it to the front, then flip it to its correct position.

How to think about it Selection sort with flips. For each target size from n down to 2, find the current maximum in the unsorted prefix, flip it to the front, then flip the whole prefix so it lands at the end. Record each flip size.

pancake_sort.py
from typing import List

class Solution:
    def pancakeSort(self, arr: List[int]) -> List[int]:
        res = []
        for size in range(len(arr), 1, -1):
            mi = arr.index(max(arr[:size]))   # index of the current max
            if mi != size - 1:
                if mi != 0:
                    arr[:mi + 1] = arr[:mi + 1][::-1]   # flip max to the front
                    res.append(mi + 1)
                arr[:size] = arr[:size][::-1]           # flip it to its place
                res.append(size)
        return res

Time O(n²) · Space O(1) extra. A fun constraint-driven variant that reinforces selection sort's structure.

11 LC 179Largest Number Medium Custom comparator · which order concatenates bigger

Problem. Arrange the numbers to form the largest possible number; return it as a string. LeetCode 179 ↗

Clarify: Result can be huge (return a string)? (Yes.) All zeros → '0'? (Yes.)

Hint 1
Numeric sort fails (3 vs 30). Compare by which concatenation is larger.
Hint 2
Order a before b when a+b > b+a as strings.

How to think about it Define a custom order: string a precedes b when a+b > b+a. Sort the numbers-as-strings by that comparator and concatenate. Guard the all-zeros case so the result is '0'. Comparators like this are why cmp_to_key exists.

largest_number.py
from typing import List
from functools import cmp_to_key

class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        def cmp(a, b):
            if a + b > b + a:
                return -1
            if a + b < b + a:
                return 1
            return 0
        out = "".join(sorted(map(str, nums), key=cmp_to_key(cmp)))
        return "0" if out[0] == "0" else out

Time O(n log n · L) · Space O(n). The pairwise-concatenation comparator is the whole trick.

12 LC 937Reorder Data in Log Files Medium Custom key · stable multi-rule sort

Problem. Reorder logs so letter-logs (sorted by content, then id) come before digit-logs (in original order). LeetCode 937 ↗

Clarify: Digit-logs keep their relative order? (Yes.) Letter-logs sort by content then identifier? (Yes.)

Hint 1
Split each log into identifier and the rest; classify by whether the rest starts with a digit.
Hint 2
Give digit-logs an equal key so a stable sort preserves their order.

How to think about it Build a sort key: letter-logs get (0, content, identifier); digit-logs all get the same key (1,), so Python's stable sort keeps their original order and places them after all letter-logs.

reorder_logs.py
from typing import List

class Solution:
    def reorderLogFiles(self, logs: List[str]) -> List[str]:
        def key(log):
            ident, rest = log.split(" ", 1)
            if rest[0].isdigit():
                return (1,)                   # digit logs: keep original order, go last
            return (0, rest, ident)           # letter logs: by content, then id
        return sorted(logs, key=key)

Time O(n·k log n) · Space O(n·k). Relying on stable sort for the equal-key group is the elegant part.

13 LC 274H-Index Medium Sort descending, scan

Problem. Return the h-index: the largest h such that h papers each have at least h citations. LeetCode 274 ↗

Clarify: h papers with ≥ h citations each? (Yes.) Return the maximum such h? (Yes.)

Hint 1
Sort citations descending.
Hint 2
At position i (0-based), you have i+1 papers with ≥ citations[i]; the h-index is the largest i+1 with citations[i] ≥ i+1.

How to think about it Sort descending. Scanning, the paper at index i is the (i+1)-th most cited, so i+1 papers have at least citations[i] citations. The h-index is the largest i+1 where citations[i] ≥ i+1; stop once it fails.

h_index.py
from typing import List

class Solution:
    def hIndex(self, citations: List[int]) -> int:
        citations.sort(reverse=True)
        h = 0
        for i, c in enumerate(citations):
            if c >= i + 1:
                h = i + 1
            else:
                break
        return h

Time O(n log n) · Space O(1). Counting sort gives an O(n) version — worth mentioning as a follow-up.

14 LC 324Wiggle Sort II Medium Sort, then interleave halves

Problem. Reorder so nums[0] < nums[1] > nums[2] < nums[3] … (strict). LeetCode 324 ↗

Clarify: Strict inequalities? (Yes.) Duplicates possible? (Yes — interleave carefully.)

Hint 1
Sort, then place the smaller half at even indices and the larger half at odd indices.
Hint 2
Fill each half from its largest end so equal values never touch.

How to think about it Sort, split into a smaller and larger half. Place the smaller half (reversed) at even indices and the larger half (reversed) at odd indices. Reversing each half separates equal values across the two groups, preserving the strict wiggle even with duplicates.

wiggle_sort.py
from typing import List

class Solution:
    def wiggleSort(self, nums: List[int]) -> None:
        arr = sorted(nums)
        mid = (len(nums) + 1) // 2
        # interleave the smaller and larger halves, each reversed
        nums[::2] = arr[:mid][::-1]
        nums[1::2] = arr[mid:][::-1]

Time O(n log n) · Space O(n). Filling from the ends inward is what prevents equal neighbours (an O(n) virtual-index version exists).

15 LC 56Merge Intervals Medium Sort by start, then sweep

Problem. Merge all overlapping intervals and return the non-overlapping result. LeetCode 56 ↗

Clarify: Sorted input? (No — sort first.) Touching intervals merge? (Yes.)

Hint 1
Sort by start so overlaps are adjacent.
Hint 2
Extend the last kept interval's end if the next starts within it; else start a new one.

How to think about it Sort by start. Sweep: if the current interval starts at or before the last kept interval's end, extend that end; otherwise it's disjoint, so append it. Sorting dominates the cost — the archetypal interval-merge pattern.

merge_intervals.py
from typing import List

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        intervals.sort(key=lambda iv: iv[0])
        out = []
        for s, e in intervals:
            if out and s <= out[-1][1]:
                out[-1][1] = max(out[-1][1], e)
            else:
                out.append([s, e])
        return out

Time O(n log n) · Space O(n). 'Sort by start, then sweep' recurs across the whole intervals family.

16 LC 57Insert Interval Medium Three phases · before, overlap, after

Problem. Insert a new interval into a sorted, non-overlapping list, merging as needed. LeetCode 57 ↗

Clarify: Input already sorted and disjoint? (Yes.) Output stays sorted? (Yes.)

Hint 1
Copy intervals ending before the new one starts.
Hint 2
Absorb everything overlapping the new interval, then copy the rest.

How to think about it One linear sweep in three phases: copy intervals that end before the new one starts; while intervals overlap, merge them into the new interval by widening its bounds; append the merged interval; copy the remaining tail. No sort needed since the input is pre-sorted.

insert_interval.py
from typing import List

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        out = []
        i, n = 0, len(intervals)
        s, e = newInterval
        while i < n and intervals[i][1] < s:
            out.append(intervals[i]); i += 1
        while i < n and intervals[i][0] <= e:
            s = min(s, intervals[i][0]); e = max(e, intervals[i][1]); i += 1
        out.append([s, e])
        while i < n:
            out.append(intervals[i]); i += 1
        return out

Time O(n) · Space O(n). Pre-sorted input is what lets a single sweep suffice.

17 LC 435Non-overlapping Intervals Medium Interval greedy · sort by end

Problem. Return the minimum number of intervals to remove so the rest don't overlap. LeetCode 435 ↗

Clarify: Touching endpoints don't count as overlap? (Yes.) Minimise removals? (Yes.)

Hint 1
Keep as many intervals as possible — that's the activity-selection problem.
Hint 2
Sort by end time; always keep the interval that finishes earliest.

How to think about it Greedy activity selection. Sort by end time and keep an interval whenever it starts at or after the last kept end; otherwise it overlaps and must be removed (count it). Finishing earliest leaves the most room, which is provably optimal.

erase_overlap.py
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        intervals.sort(key=lambda x: x[1])    # greedy by earliest end
        count = 0
        end = float("-inf")
        for s, e in intervals:
            if s >= end:
                end = e                       # keep it
            else:
                count += 1                    # overlaps -> remove
        return count

Time O(n log n) · Space O(1). Sorting by end (not start) is the key for the greedy to work.

18 LC 452Minimum Number of Arrows to Burst Balloons Medium Interval greedy · sort by end

Problem. Balloons span horizontal intervals; an arrow at x bursts every balloon covering x. Return the minimum arrows. LeetCode 452 ↗

Clarify: Touching intervals share an arrow? (Yes.) Minimise arrows? (Yes.)

Hint 1
This is the complement of activity selection — count the groups you keep.
Hint 2
Sort by end; shoot at each end, skipping balloons it already bursts.

How to think about it Sort by end. Shoot an arrow at the earliest end; it bursts every balloon that starts at or before it. Move to the next balloon starting after that arrow, and repeat. The number of arrows equals the number of non-overlapping groups.

min_arrows.py
from typing import List

class Solution:
    def findMinArrowShots(self, points: List[List[int]]) -> int:
        points.sort(key=lambda x: x[1])
        arrows = 0
        end = float("-inf")
        for s, e in points:
            if s > end:                       # need a new arrow
                arrows += 1
                end = e
        return arrows

Time O(n log n) · Space O(1). Same sort-by-end greedy as Non-overlapping Intervals, counting kept groups instead of removals.

19 LC 1288Remove Covered Intervals Medium Sort by start (end desc), track max end

Problem. Remove intervals covered by another and return how many remain. LeetCode 1288 ↗

Clarify: Covered means [a,b] ⊆ [c,d]? (Yes.) Count remaining after removal? (Yes.)

Hint 1
Sort by start ascending; for equal starts, longer intervals first.
Hint 2
An interval survives only if its end exceeds every previous end.

How to think about it Sort by start ascending and, for ties, by end descending — so a covering interval always comes before the one it covers. Track the maximum end seen; an interval is new (not covered) only when its end exceeds that maximum.

remove_covered.py
from typing import List

class Solution:
    def removeCoveredIntervals(self, intervals: List[List[int]]) -> int:
        intervals.sort(key=lambda x: (x[0], -x[1]))
        count = 0
        prev_end = 0
        for s, e in intervals:
            if e > prev_end:                  # not covered by the previous one
                count += 1
                prev_end = e
        return count

Time O(n log n) · Space O(1). The tie-break (end descending) is what makes the single max-end scan correct.

Problem. Given pairs where (a,b) can follow (c,d) if b < c, return the longest chain you can form. LeetCode 646 ↗

Clarify: Pairs can be used in any order? (Yes.) Strict b < c to chain? (Yes.)

Hint 1
Same greedy as activity selection: pick pairs that finish earliest.
Hint 2
Sort by second element; extend the chain when the next start exceeds the current end.

How to think about it Sort by the second element. Greedily extend the chain: whenever the next pair's start exceeds the current chain end, add it and advance the end. Finishing earliest maximises the remaining options — the activity-selection argument again.

pair_chain.py
from typing import List

class Solution:

21 LC 253Meeting Rooms II Medium Sort + min-heap of end times

Problem. Return the minimum number of conference rooms required for all meetings. LeetCode 253 ↗

Clarify: Rooms reused once free? (Yes.) Answer is the peak concurrency? (Yes.)

Hint 1
Process meetings by start time; track when rooms free up.
Hint 2
A min-heap of end times: if the earliest end is ≤ the new start, reuse that room.

How to think about it Sort by start. Keep a min-heap of room end times. For each meeting, if the earliest-ending room is free by its start, pop it (reuse); then push this meeting's end. The heap size at the end is the peak number of simultaneous meetings — the rooms needed.

meeting_rooms_ii.py
from typing import List
import heapq

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0
        intervals.sort(key=lambda x: x[0])
        ends = []                             # min-heap of room end times
        for s, e in intervals:
            if ends and ends[0] <= s:
                heapq.heappop(ends)           # a room freed up
            heapq.heappush(ends, e)
        return len(ends)                      # rooms in use = peak concurrency

Time O(n log n) · Space O(n). The heap tracks 'when does a room next free up' — a sweep-line in disguise.

22 LC 215Kth Largest Element in an Array Medium Quickselect · partition to the answer

Problem. Return the k-th largest element (by value, duplicates counted). LeetCode 215 ↗

Clarify: k-th largest by value? (Yes.) Better than sorting? (Quickselect is O(n) average.)

Hint 1
A heap gives O(n log k); can you avoid touching every element repeatedly?
Hint 2
Quickselect partitions around a pivot and recurses into only one side.

How to think about it Quickselect. The k-th largest is at index n − k when sorted ascending. Partition around a random pivot (three-way to handle duplicates); if the target index lands in the equal region you're done, otherwise recurse into the side that contains it. Average O(n), since you discard half each step.

kth_largest.py
from typing import List
import random

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        target = len(nums) - k                # index in ascending order
        def quickselect(lo, hi):
            pivot = nums[random.randint(lo, hi)]
            lt, gt, i = lo, hi, lo
            while i <= gt:                    # 3-way (Dutch flag) partition
                if nums[i] < pivot:
                    nums[lt], nums[i] = nums[i], nums[lt]; lt += 1; i += 1
                elif nums[i] > pivot:
                    nums[i], nums[gt] = nums[gt], nums[i]; gt -= 1
                else:
                    i += 1
            if target < lt:
                return quickselect(lo, lt - 1)
            if target > gt:
                return quickselect(gt + 1, hi)
            return nums[target]
        return quickselect(0, len(nums) - 1)

Time O(n) average, O(n²) worst · Space O(1). A random pivot makes the worst case vanishingly unlikely; a size-k heap is the O(n log k) alternative.

23 LC 347Top K Frequent Elements Medium Bucket sort by frequency

Problem. Return the k most frequent elements. LeetCode 347 ↗

Clarify: k is valid? (Yes.) Ties broken arbitrarily? (Yes.)

Hint 1
Count frequencies, then you only need the top k by count.
Hint 2
Bucket elements by frequency (0..n) and read from the highest bucket down — O(n).

How to think about it Count with a frequency map, then bucket each value by its count into an array indexed 0..n. Reading buckets from the highest frequency down collects the top k in O(n) — beating the O(n log k) heap when you want the optimum.

top_k_frequent.py
from typing import List
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        buckets = [[] for _ in range(len(nums) + 1)]
        for v, c in count.items():
            buckets[c].append(v)              # index by frequency
        res = []
        for c in range(len(buckets) - 1, 0, -1):
            for v in buckets[c]:
                res.append(v)
                if len(res) == k:
                    return res
        return res

Time O(n) · Space O(n). Bucket sort works because counts are bounded by n — no comparison sort needed.

25 LC 378Kth Smallest Element in a Sorted Matrix Medium k-way merge with a min-heap

Problem. Given a matrix with rows and columns sorted ascending, return the k-th smallest element. LeetCode 378 ↗

Clarify: Rows and columns both sorted? (Yes.) k-th in overall order? (Yes.)

Hint 1
Merge the sorted rows like k sorted lists.
Hint 2
A min-heap holds the current front of each row; pop k−1 times, then read the top.

How to think about it Treat each row as a sorted list and do a k-way merge. Seed a min-heap with the first element of the first k rows; repeatedly pop the smallest and push the next element from the same row. After k−1 pops, the heap top is the k-th smallest.

kth_smallest_matrix.py
from typing import List
import heapq

class Solution:
    def kthSmallest(self, matrix: List[List[int]], k: int) -> int:
        n = len(matrix)
        heap = [(matrix[r][0], r, 0) for r in range(min(n, k))]
        heapq.heapify(heap)
        for _ in range(k - 1):
            val, r, c = heapq.heappop(heap)
            if c + 1 < n:
                heapq.heappush(heap, (matrix[r][c + 1], r, c + 1))
        return heap[0][0]

Time O(k log k) · Space O(k). A binary-search-on-value approach gives O(n log(range)) as an alternative.

26 LC 658Find K Closest Elements Medium Binary search the window start

Problem. Return the k elements closest to x from a sorted array, in ascending order. LeetCode 658 ↗

Clarify: Sorted input? (Yes.) Ties prefer the smaller element? (Yes.)

Hint 1
The answer is a contiguous length-k window (the array is sorted).
Hint 2
Binary search for the best window start by comparing the two boundary distances.

How to think about it Because the array is sorted, the answer is a contiguous window of size k. Binary search the window's start: compare the element just left of the window to the one just right; if the left is farther from x, move the window right. The converged window is the answer.

k_closest_elements.py
from typing import List

class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        lo, hi = 0, len(arr) - k              # binary search the window start
        while lo < hi:
            mid = (lo + hi) // 2
            if x - arr[mid] > arr[mid + k] - x:
                lo = mid + 1
            else:
                hi = mid
        return arr[lo:lo + k]

Time O(log(n−k) + k) · Space O(1). Binary-searching the window (not a value) is the clever framing.

27 LC 826Most Profit Assigning Work Medium Sort both, sweep with a running best

Problem. Assign each worker the most profitable job they can do (difficulty ≤ ability); return total profit. LeetCode 826 ↗

Clarify: A job can be done by many workers? (Yes.) Each worker does at most one job? (Yes.)

Hint 1
Sort jobs by difficulty and workers by ability.
Hint 2
As ability rises, the set of doable jobs only grows — track the best profit so far.

How to think about it Sort jobs by difficulty and workers by ability. Sweep workers in increasing ability, advancing a job pointer to include every newly-affordable job while tracking the best profit seen. Each worker takes that running best — a two-pointer merge over two sorted lists.

max_profit_work.py
from typing import List

class Solution:
    def maxProfitAssignment(self, difficulty: List[int], profit: List[int], worker: List[int]) -> int:
        jobs = sorted(zip(difficulty, profit))
        worker.sort()
        i = best = total = 0
        for w in worker:
            while i < len(jobs) and jobs[i][0] <= w:
                best = max(best, jobs[i][1])  # best profit workable so far
                i += 1
            total += best
        return total

Time O(n log n + m log m) · Space O(n). Sorting both sides turns a nested search into a linear sweep.

28 LC 220Contains Duplicate III Medium Bucketing by value window

Problem. Return whether two elements within index distance indexDiff differ by at most valueDiff. LeetCode 220 ↗

Clarify: Both index and value constraints? (Yes.) valueDiff can be 0? (Yes.)

Hint 1
Group values into buckets of width valueDiff+1; same bucket means within valueDiff.
Hint 2
Keep only buckets for the last indexDiff elements (a sliding window).

How to think about it Bucket each value by value // (valueDiff+1). Two values in the same bucket differ by at most valueDiff; adjacent buckets need an explicit check. Maintain buckets only for the last indexDiff elements, evicting the oldest as the window slides.

contains_dup_iii.py
from typing import List

class Solution:
    def containsNearbyAlmostDuplicate(self, nums: List[int], indexDiff: int, valueDiff: int) -> bool:
        if valueDiff < 0:
            return False
        buckets = {}
        w = valueDiff + 1                     # bucket width
        for i, x in enumerate(nums):
            b = x // w
            if b in buckets:
                return True                   # same bucket -> within valueDiff
            if b - 1 in buckets and abs(x - buckets[b - 1]) <= valueDiff:
                return True
            if b + 1 in buckets and abs(x - buckets[b + 1]) <= valueDiff:
                return True
            buckets[b] = x
            if i >= indexDiff:
                del buckets[nums[i - indexDiff] // w]   # slide the window
        return False

Time O(n) · Space O(min(n, indexDiff)). Bucketing turns a range query into O(1) neighbour checks — a sorting-adjacent idea.

29 LC 295Find Median from Data Stream Hard Two heaps balanced at the median

Problem. Design a structure that ingests a stream of numbers and returns the running median in O(log n) per add. LeetCode 295 ↗

Clarify: Median of even count is the average of the middle two? (Yes.) Online (adds interleaved with queries)? (Yes.)

Hint 1
Split the numbers into a lower half and an upper half.
Hint 2
A max-heap holds the lower half, a min-heap the upper; keep their sizes balanced.

How to think about it Keep a max-heap of the smaller half and a min-heap of the larger half. Each add pushes to one heap, moves its extreme to the other to keep values ordered, then rebalances sizes. The median is the top of the larger heap, or the average of both tops when sizes are equal.

median_finder.py
import heapq

class MedianFinder:
    def __init__(self):
        self.small = []      # max-heap (negated) — lower half
        self.large = []      # min-heap — upper half
    def addNum(self, num: int) -> None:
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))   # balance values
        if len(self.large) > len(self.small):                    # balance sizes
            heapq.heappush(self.small, -heapq.heappop(self.large))
    def findMedian(self) -> float:
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2

add O(log n), findMedian O(1) · Space O(n). Two heaps meeting at the middle is the canonical streaming-median design.

30 LC 218The Skyline Problem Hard Sweep line + max-heap of heights

Problem. Given buildings as (left, right, height), return the skyline as a list of key points. LeetCode 218 ↗

Clarify: Output key points where the height changes? (Yes.) Adjacent equal heights merge? (Yes.)

Hint 1
Sweep x left to right, tracking the set of buildings currently overhead.
Hint 2
At each event, the skyline height is the tallest live building; record it when it changes.

How to think about it Create start and end events, sorted so that at each x the tallest starting building is processed first. Maintain a max-heap of (height, end) for live buildings, lazily discarding expired ones. Whenever the current max height changes, emit a key point.

skyline.py
from typing import List
import heapq

class Solution:
    def getSkyline(self, buildings: List[List[int]]) -> List[List[int]]:
        events = []
        for l, r, h in buildings:
            events.append((l, -h, r))         # start: negative height sorts tall-first
            events.append((r, 0, 0))          # end marker
        events.sort()
        res = []
        live = [(0, float("inf"))]            # (neg height, end) — ground level
        for x, neg_h, r in events:
            while live[0][1] <= x:            # drop buildings that have ended
                heapq.heappop(live)
            if neg_h:
                heapq.heappush(live, (neg_h, r))
            cur = -live[0][0]
            if not res or res[-1][1] != cur:  # height changed -> key point
                res.append([x, cur])
        return res

Time O(n log n) · Space O(n). The sweep-line + heap combo generalises to many interval-overlap problems.

31 LC 1235Maximum Profit in Job Scheduling Hard Sort + DP + binary search

Problem. Choose non-overlapping jobs (start, end, profit) to maximise total profit. LeetCode 1235 ↗

Clarify: Jobs can't overlap? (Yes.) A job starting at another's end time is OK? (Yes.)

Hint 1
Sort by start time; decide for each job to skip it or take it.
Hint 2
If you take a job, jump to the next job starting at or after its end — find it with binary search.

How to think about it Sort by start and compute suffix DP: dp[i] = best profit using jobs from i onward. For each job either skip it (dp[i+1]) or take it and add dp[next], where next is the first job starting at or after this job's end (binary search over starts). The answer is dp[0].

job_scheduling.py
from typing import List
import bisect

class Solution:
    def jobScheduling(self, startTime: List[int], endTime: List[int], profit: List[int]) -> int:
        jobs = sorted(zip(startTime, endTime, profit))
        starts = [j[0] for j in jobs]
        n = len(jobs)
        dp = [0] * (n + 1)                    # dp[i] = best profit using jobs[i:]
        for i in range(n - 1, -1, -1):
            s, e, p = jobs[i]
            nxt = bisect.bisect_left(starts, e)   # first job starting at/after e
            dp[i] = max(dp[i + 1], p + dp[nxt])
        return dp[0]

Time O(n log n) · Space O(n). Weighted interval scheduling — sorting plus binary search is what makes the DP efficient.

32 LC 4Median of Two Sorted Arrays Hard Binary search the partition

Problem. Return the median of two sorted arrays in O(log(m+n)). LeetCode 4 ↗

Clarify: O(log) required (not merge)? (Yes.) Arrays may differ in length? (Yes.)

Hint 1
Binary search a cut in the shorter array; the cut in the other is forced by the total size.
Hint 2
A valid cut has every left element ≤ every right element across both arrays.

How to think about it Binary search a partition of the shorter array so that the combined left half has the correct size. A partition is valid when the largest left element (each side) is ≤ the smallest right element (other side). Adjust the cut based on which side is too big; the median comes from the boundary elements.

median_two_sorted.py
from typing import List

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        A, B = nums1, nums2
        if len(A) > len(B):
            A, B = B, A
        m, n = len(A), len(B)
        lo, hi, half = 0, m, (m + n + 1) // 2
        while lo <= hi:
            i = (lo + hi) // 2                # cut in A; j is the matching cut in B
            j = half - i
            a_left = A[i - 1] if i > 0 else float("-inf")
            a_right = A[i] if i < m else float("inf")
            b_left = B[j - 1] if j > 0 else float("-inf")
            b_right = B[j] if j < n else float("inf")
            if a_left <= b_right and b_left <= a_right:
                if (m + n) % 2:
                    return max(a_left, b_left)
                return (max(a_left, b_left) + min(a_right, b_right)) / 2
            elif a_left > b_right:
                hi = i - 1
            else:
                lo = i + 1
        return 0.0

Time O(log min(m, n)) · Space O(1). Searching for the cut (not a value) is the elegant idea; watch the ±∞ sentinels at the ends.

33 LC 315Count of Smaller Numbers After Self Hard Merge sort counting inversions

Problem. For each element, count how many later elements are smaller. LeetCode 315 ↗

Clarify: Count strictly smaller elements to the right? (Yes.) O(n log n) expected? (Yes.)

Hint 1
This is counting inversions — merge sort can tally them.
Hint 2
Sort indices; when a right element merges before a left one, it's smaller than all remaining left elements.

How to think about it Merge sort over indices (to attribute counts back to original positions). During each merge, when an element from the right half is placed before elements still remaining in the left half, it is smaller than them — accumulate that running right-count for each left element as it is merged.

count_smaller.py
from typing import List

class Solution:
    def countSmaller(self, nums: List[int]) -> List[int]:
        n = len(nums)
        counts = [0] * n
        idx = list(range(n))                  # sort indices, not values
        def sort(lo, hi):
            if hi - lo <= 1:
                return
            mid = (lo + hi) // 2
            sort(lo, mid); sort(mid, hi)
            merged, i, j, right_done = [], lo, mid, 0
            while i < mid and j < hi:
                if nums[idx[j]] < nums[idx[i]]:
                    right_done += 1           # this right element beats idx[i]..
                    merged.append(idx[j]); j += 1
                else:
                    counts[idx[i]] += right_done
                    merged.append(idx[i]); i += 1
            while i < mid:
                counts[idx[i]] += right_done
                merged.append(idx[i]); i += 1
            while j < hi:
                merged.append(idx[j]); j += 1
            idx[lo:hi] = merged
        sort(0, n)
        return counts

Time O(n log n) · Space O(n). Counting inversions during the merge step is a fundamental divide-and-conquer trick (a Fenwick tree also works).

34 LC 493Reverse Pairs Hard Merge sort counting cross-pairs

Problem. Count pairs i < j with nums[i] > 2·nums[j]. LeetCode 493 ↗

Clarify: Strictly greater than twice? (Yes.) O(n log n) expected? (Yes.)

Hint 1
Count qualifying pairs across the split during merge sort.
Hint 2
Before merging two sorted halves, count for each left element how many right elements it beats (> 2×).

How to think about it Merge sort. Before merging two sorted halves, use a two-pointer scan to count, for each left element, how many right-half elements satisfy left > 2·right — both halves being sorted makes this linear. Then merge normally. Sum counts across all levels.

reverse_pairs.py
from typing import List

class Solution:
    def reversePairs(self, nums: List[int]) -> int:
        def sort(lo, hi):
            if hi - lo <= 1:
                return 0
            mid = (lo + hi) // 2
            count = sort(lo, mid) + sort(mid, hi)
            j = mid
            for i in range(lo, mid):          # count pairs across the split
                while j < hi and nums[i] > 2 * nums[j]:
                    j += 1
                count += j - mid
            nums[lo:hi] = sorted(nums[lo:hi])  # merge step
            return count
        return sort(0, len(nums))

Time O(n log n) · Space O(n). The counting scan is separate from the merge — a clean variation on inversion counting.

4 · Interview playbook

  • Sort by a key. Reach for a tuple key for multi-level order; use cmp_to_key only when the order depends on pairs (Largest Number).
  • Intervals: which sort? By start to merge/insert; by end for greedy "keep the most / fewest arrows". State it explicitly.
  • Don't over-sort. For top-k or the k-th element, use a size-k heap (O(n log k), stream-friendly) or quickselect (O(n) average).
  • Bounded values? Counting/bucket sort is O(n) and beats comparison sort.
  • heapq is a min-heap — negate for max-heaps; the streaming median uses two heaps meeting in the middle.

5 · Role notes

SDE / Python backend

Custom sorts, interval merging (calendars, ranges, log windows), and top-k queries are everyday work. Know quickselect and heaps for large-scale "top N" without sorting everything.

Data Science / ML / AI / GenAI

6 · Review

Cheat sheet
  • Multi-level order → tuple key; pairwise order → cmp_to_key.
  • Bounded integer values / top-k by count → counting or bucket sort (O(n)).
  • Merge / insert / cover intervals → sort by start, sweep.
  • Keep the most / fewest removals / min arrows → sort by end, greedy.
  • Rooms / concurrency → sort by start + min-heap of end times.
  • k-th largest / top-k → size-k heap or quickselect.
  • Running median / k-way merge → heap(s).
  • Count inversions / cross-pairs → merge sort with counting.

Concept checks

Why does Non-overlapping Intervals sort by end time rather than start?
Keeping the interval that finishes earliest leaves the most room for later intervals — the provably optimal greedy choice
Because end times are always larger than start times
Because sorting by start is O(n²)
This is activity selection: among overlapping options, the one ending soonest maximises remaining capacity. Sorting by start can force you to keep a long interval that blocks several short ones, which isn't optimal.
You need the 5th largest of a million numbers. Why prefer a size-5 heap or quickselect over sorting?
Sorting is O(n log n); a size-k heap is O(n log k) and quickselect is O(n) average — both avoid ordering elements you don't care about
Sorting can't handle a million numbers
Heaps are always faster than sorting for every task
You only need one element's rank, not the full order. A size-k heap keeps just the k largest (O(n log k)); quickselect partitions toward the target and recurses one side (O(n) average). Full sorting wastes work ordering the other ~999,995 numbers.

  • I can solve interval greedy problems by sorting on end time.
  • I can use a size-k heap and two heaps for top-k and running median.
