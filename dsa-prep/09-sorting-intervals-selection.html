1 · Foundations

Mental model. Use ordering to simplify relationships, merge ranges, and find ranks efficiently. Do not memorize isolated solutions. Learn what information must be remembered, when it changes, and why that makes the algorithm correct.

Use it when

The input has the recognition signals listed below and a simpler brute-force solution repeats the same work.

Avoid it when

The assumptions do not hold. For example, binary search needs monotonicity, greedy needs a proof, and sliding windows usually need a condition that changes predictably as pointers move.

Python model and trade-offs

Prefer built-ins such as dict, set, list, deque, heapq, and bisect when they match the job. Always separate output space from auxiliary working space, and mention mutation when the input is modified.

✓
Simple interview routine

Clarify constraints → describe brute force → identify the repeated work → choose a pattern → state the invariant → code → test tiny and awkward cases.

4 · Interview playbook

  • Say the brute-force complexity before optimizing.
  • Name the exact invariant your loop or recursion preserves.
  • Test empty input, one item, duplicates, boundaries, and the smallest valid case.
  • Use descriptive names. A clear solution is better than a compressed trick.
  • After coding, re-check mutation, auxiliary space, and worst-case behavior.
