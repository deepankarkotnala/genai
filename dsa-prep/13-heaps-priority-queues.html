Heaps & Priority Queues

A heap answers one question instantly and forever: "what is the smallest (or largest) thing right now?" That single power — O(1) peek at the extreme, O(log n) to add or remove — solves top-k, streaming medians, and a whole family of greedy scheduling problems. Every problem here has a full, tested solution in LeetCode's class Solution format.

Outcome

Use heapq fluently (including max-heaps and tuple keys), apply the size-k heap for top-k, merge k streams, balance two heaps for a running median, and drive greedy scheduling with a priority queue.

New to heaps? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is a heap?

A heap (a priority queue) keeps a collection so that the smallest element is always instantly available. Peeking at the minimum is O(1); adding an element or removing the minimum is O(log n). Crucially, a heap is not fully sorted — it only guarantees the extreme, which is exactly why it's faster than sorting when you keep only need the next-smallest.

Example — heapq is a min-heap
heap.py
import heapq

h = [5, 1, 8, 3]
heapq.heapify(h)          # O(n): turn a list into a heap in place
print(h[0])               # 1   -> the minimum, O(1) peek
heapq.heappush(h, 2)      # O(log n)
print(heapq.heappop(h))   # 1   -> remove & return the minimum
print(heapq.heappop(h))   # 2
Output1
1
2
Reach for a heap whenever you repeatedly need the current smallest or largest from a changing collection — top-k, "merge sorted streams", "always process the highest-priority item next".

Max-heaps: negate the values

Python's heapq is only a min-heap. To get a max-heap, push the negatives and negate again on the way out. This one trick appears in half the problems in this chapter.

Example — a max-heap via negation
maxheap.py
import heapq

nums = [5, 1, 8, 3]
h = [-x for x in nums]    # store negatives
heapq.heapify(h)
print(-heapq.heappop(h))  # 8   -> the largest original value
print(-heapq.heappop(h))  # 5
Output8
5

The top-k idiom (and when to sort instead)

To find the k largest elements, keep a min-heap of size k: push everything, and whenever the heap grows past k, pop the smallest. What survives are the k largest, and the heap's root is the k-th largest. This is O(n log k) — better than the O(n log n) of a full sort when k is small, and it works on a stream.

Example — k largest with a size-k min-heap
topk.py
import heapq

def k_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)   # drop the smallest -> keep the k largest
    return sorted(h, reverse=True)

print(k_largest([3, 1, 5, 12, 2, 11], 3))   # [12, 11, 5]

# shortcuts for one-shot top-k:
print(heapq.nlargest(3, [3, 1, 5, 12, 2, 11]))    # [12, 11, 5]
print(heapq.nsmallest(2, [3, 1, 5, 12, 2, 11]))   # [1, 2]
Counter-intuitive but key: to keep the largest k, use a min-heap (so the smallest of your keepers is the easiest to evict).

Tuples, tie-breakers, and two heaps

Heaps order by the whole element, so push tuples like (priority, tiebreaker, item) — the first field ranks, later fields break ties. Always include a tiebreaker (often an index) when the final item isn't comparable (e.g. a ListNode), or Python will try to compare items and crash. Two heaps facing each other — a max-heap of the lower half and a min-heap of the upper half — track a running median in O(log n).

⚠️
Heap pitfalls

heapq is min-only — negate for a max-heap. When storing tuples, add an index tiebreaker so unorderable objects (nodes, dicts) are never compared. heapq.nlargest/nsmallest are handy for one-shot top-k but a maintained size-k heap wins on streams. And remember a heap gives you the extreme, not a sorted order — don't iterate a heap expecting sorted output.

1 LC 1046Last Stone Weight Easy Max-heap · smash the two heaviest

Problem. Repeatedly smash the two heaviest stones; return the last remaining stone's weight (or 0). LeetCode 1046 ↗

Clarify: Smash the two heaviest each round? (Yes.) Equal stones annihilate? (Yes.)

Hint 1
You repeatedly need the two largest — that's a heap.
Hint 2
Python's heapq is a min-heap, so store negatives for a max-heap.

How to think about it A max-heap gives the two heaviest stones in O(log n). Pop two; if they differ, push back the difference. Since heapq is a min-heap, negate on the way in and out. Repeat until one or zero stones remain.

last_stone.py
from typing import List
import heapq

class Solution:
    def lastStoneWeight(self, stones: List[int]) -> int:
        h = [-s for s in stones]                 # max-heap via negation
        heapq.heapify(h)
        while len(h) > 1:
            a = -heapq.heappop(h)
            b = -heapq.heappop(h)
            if a != b:
                heapq.heappush(h, -(a - b))
        return -h[0] if h else 0

Time O(n log n) · Space O(n). Negating for a max-heap is the Python idiom you'll reuse all chapter.

2 LC 703Kth Largest Element in a Stream Easy Design · min-heap of size k

Problem. Return the k-th largest element seen so far after each add. LeetCode 703 ↗

Clarify: k-th largest overall (duplicates count)? (Yes.) Stream of adds? (Yes.)

Hint 1
Keep only the k largest values in a min-heap.
Hint 2
Its smallest element (the root) is exactly the k-th largest.

How to think about it Maintain a min-heap capped at size k. Each add pushes and, if the size exceeds k, pops the smallest — so the heap always holds the top-k and its root is the k-th largest. O(log k) per add and stream-friendly.

kth_largest_stream.py
from typing import List
import heapq

class KthLargest:
    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = nums
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)             # keep only the k largest
    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]                      # root = k-th largest

add O(log k) · Space O(k). The size-capped min-heap is the canonical 'top-k in a stream' tool.

3 LC 2558Take Gifts From the Richest Pile Easy Max-heap · repeatedly shrink the largest

Problem. For k seconds, take the largest pile and leave behind ⌊√pile⌋; return the total remaining. LeetCode 2558 ↗

Clarify: Operate on the current largest each second? (Yes.) Floor of the square root stays? (Yes.)

Hint 1
Each step touches the maximum — use a max-heap.
Hint 2
Replace the popped max with floor(sqrt(max)).

How to think about it A max-heap surfaces the largest pile each of the k seconds. Pop it, push back floor(sqrt(pile)), and after k operations sum whatever remains. A clean 'operate on the extreme repeatedly' simulation.

take_gifts.py
from typing import List
import heapq
import math

class Solution:
    def pickGifts(self, gifts: List[int], k: int) -> int:
        h = [-g for g in gifts]                  # max-heap
        heapq.heapify(h)
        for _ in range(k):
            top = -heapq.heappop(h)
            heapq.heappush(h, -math.isqrt(top))  # leave floor(sqrt) behind
        return -sum(h)

Time O(k log n) · Space O(n). Whenever a problem says 'repeatedly act on the current max/min', reach for a heap.

4 LC 506Relative Ranks Easy Heap · pop scores highest-first

Problem. Assign 'Gold/Silver/Bronze Medal' to the top three scores and numeric ranks to the rest. LeetCode 506 ↗

Clarify: Scores distinct? (Yes.) Top three get medals? (Yes.)

Hint 1
Pop athletes from a max-heap in descending score order.
Hint 2
The pop order directly gives ranks 1, 2, 3, …

How to think about it Push (-score, index) and pop in descending score order; the k-th pop is rank k. Assign medals for the first three and the numeric rank otherwise, writing back by original index. (A sort works too — this is the heap lens.)

relative_ranks.py
from typing import List
import heapq

class Solution:
    def findRelativeRanks(self, score: List[int]) -> List[str]:
        heap = [(-s, i) for i, s in enumerate(score)]
        heapq.heapify(heap)
        res = [""] * len(score)
        medals = ["Gold Medal", "Silver Medal", "Bronze Medal"]
        rank = 1
        while heap:
            _, i = heapq.heappop(heap)           # highest score first
            res[i] = medals[rank - 1] if rank <= 3 else str(rank)
            rank += 1
        return res

Time O(n log n) · Space O(n). Popping a heap is just an incremental sort — handy when you only need order, not the sorted array.

5 LC 3264Final Array State After K Multiplication Operations I Easy Min-heap · multiply the smallest

Problem. Do k operations, each multiplying the current minimum element by multiplier; return the final array. LeetCode 3264 ↗

Clarify: Ties broken by smallest index? (Yes.) Preserve positions in the output? (Yes.)

Hint 1
Each operation touches the minimum — use a min-heap with an index tie-breaker.
Hint 2
After k operations, write each value back to its original index.

How to think about it Push (value, index) so the heap orders by value then index (matching the tie-break rule). Pop the smallest, multiply, push back k times, then reconstruct the array by placing each heap entry at its index.

final_state.py
from typing import List
import heapq

class Solution:
    def getFinalState(self, nums: List[int], k: int, multiplier: int) -> List[int]:
        heap = [(v, i) for i, v in enumerate(nums)]   # tie-break by index
        heapq.heapify(heap)
        for _ in range(k):
            v, i = heapq.heappop(heap)           # smallest value
            heapq.heappush(heap, (v * multiplier, i))
        res = nums[:]
        for v, i in heap:
            res[i] = v
        return res

Time O(k log n) · Space O(n). Pairing the index into the tuple is what enforces the smallest-index tie-break.

6 LC 215Kth Largest Element in an Array Medium Size-k min-heap

Problem. Return the k-th largest element (by value, duplicates counted). LeetCode 215 ↗

Clarify: k-th largest by value? (Yes.) Better than a full sort? (Yes, O(n log k).)

Hint 1
Keep the k largest values in a min-heap.
Hint 2
Push each element; if the heap exceeds k, pop the smallest.

How to think about it Maintain a min-heap of size k: push every element and pop the smallest whenever the size passes k. The heap ends holding the k largest values, and its root is the answer — O(n log k) versus O(n log n) to sort. (Quickselect gives O(n) average.)

kth_largest.py
from typing import List
import heapq

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        heap = []
        for x in nums:
            heapq.heappush(heap, x)
            if len(heap) > k:
                heapq.heappop(heap)              # size-k min-heap of largest
        return heap[0]

Time O(n log k) · Space O(k). The size-k heap is the workhorse behind every top-k problem here.

7 LC 347Top K Frequent Elements Medium Frequency map + heap

Problem. Return the k most frequent elements. LeetCode 347 ↗

Clarify: k valid? (Yes.) Ties arbitrary? (Yes.)

Hint 1
Count frequencies, then pick the k largest by count.
Hint 2
heapq.nlargest keyed by frequency does it in O(n log k).

How to think about it Count with a frequency map, then take the k items with the highest counts via a heap. heapq.nlargest(k, …, key=count) keeps only k in the heap, giving O(n log k). (Bucket sort by count is the O(n) alternative.)

top_k_frequent.py
from typing import List
import heapq
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        return [v for v, _ in heapq.nlargest(k, count.items(), key=lambda x: x[1])]

Time O(n log k) · Space O(n). Count first, then heap the counts — the standard two-step for frequency top-k.

8 LC 973K Closest Points to Origin Medium Heap by squared distance

Problem. Return the k points closest to the origin. LeetCode 973 ↗

Clarify: Squared distance suffices for ordering? (Yes — skip the square root.) Any order among k? (Yes.)

Hint 1
Order by x²+y²; the square root is monotonic and unnecessary.
Hint 2
A heap (or quickselect) selects the k smallest without full sorting.

How to think about it Rank by squared distance x²+y² (the root is order-preserving, so drop it). heapq.nsmallest(k, …) selects the closest k in O(n log k); quickselect gives O(n) average.

k_closest.py
from typing import List
import heapq

class Solution:
    def kClosest(self, points: List[List[int]], k: int) -> List[List[int]]:
        return heapq.nsmallest(k, points, key=lambda p: p[0] * p[0] + p[1] * p[1])

Time O(n log k) · Space O(k). Skipping the square root is a small, classic optimisation.

9 LC 692Top K Frequent Words Medium Heap with a compound key

Problem. Return the k most frequent words, most frequent first, ties broken alphabetically. LeetCode 692 ↗

Clarify: Ties broken lexicographically ascending? (Yes.) Case-sensitive? (Yes.)

Hint 1
Two-level order: frequency descending, then word ascending.
Hint 2
A key of (-freq, word) captures both at once.

How to think about it Count, then select with a heap keyed by (-frequency, word) so higher counts come first and ties fall back to alphabetical order. heapq.nsmallest(k, …) under that key returns exactly the required ordering.

top_k_words.py
from typing import List
import heapq
from collections import Counter

class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        count = Counter(words)
        # smallest by (-freq, word): highest freq first, ties lexicographically
        return heapq.nsmallest(k, count.keys(), key=lambda w: (-count[w], w))

Time O(n log k) · Space O(n). Encoding a two-level order in the heap key is the trick.

10 LC 451Sort Characters By Frequency Medium Max-heap by count

Problem. Return the string with characters ordered by decreasing frequency. LeetCode 451 ↗

Clarify: Ties in any order? (Yes.) Keep all occurrences? (Yes.)

Hint 1
Count characters, then emit the most frequent first.
Hint 2
A max-heap of (count, char) pops in the right order.

How to think about it Count characters and push (-count, char) onto a heap. Pop repeatedly, appending each character repeated by its count, to build the result most-frequent-first.

frequency_sort.py
import heapq
from collections import Counter

class Solution:
    def frequencySort(self, s: str) -> str:
        heap = [(-c, ch) for ch, c in Counter(s).items()]
        heapq.heapify(heap)
        res = []
        while heap:
            c, ch = heapq.heappop(heap)
            res.append(ch * (-c))
        return "".join(res)

Time O(n + m log m) · Space O(n). Same 'rebuild from counts' idea as bucket-based sorting, here via a heap.

11 LC 378Kth Smallest Element in a Sorted Matrix Medium K-way merge over rows

Problem. In a matrix with sorted rows and columns, return the k-th smallest value. LeetCode 378 ↗

Clarify: Rows and columns both sorted? (Yes.) k-th in overall order? (Yes.)

Hint 1
Treat each row as a sorted list and merge them.
Hint 2
A min-heap holds the current front of each row; pop k times.

How to think about it A k-way merge. Seed a min-heap with the first element of the first k rows; repeatedly pop the smallest and push the next element from the same row. The k-th pop is the answer.

kth_smallest_matrix.py
from typing import List
import heapq

class Solution:
    def kthSmallest(self, matrix: List[List[int]], k: int) -> int:
        n = len(matrix)
        heap = [(matrix[r][0], r, 0) for r in range(min(n, k))]
        heapq.heapify(heap)
        val = 0
        for _ in range(k):
            val, r, c = heapq.heappop(heap)
            if c + 1 < n:
                heapq.heappush(heap, (matrix[r][c + 1], r, c + 1))
        return val

Time O(k log k) · Space O(k). Binary-search-on-value is the alternative; the heap merge is the natural heap-chapter approach.

12 LC 373Find K Pairs with Smallest Sums Medium Heap over a sorted grid frontier

Problem. Given two sorted arrays, return the k pairs (one from each) with the smallest sums. LeetCode 373 ↗

Clarify: Pairs (u, v) with smallest u+v? (Yes.) Arrays sorted ascending? (Yes.)

Hint 1
Think of pair sums as a sorted grid; the smallest is (0,0).
Hint 2
Seed the heap with the first column, then expand each popped pair to its right neighbour.

How to think about it Seed the heap with pairs (nums1[i] + nums2[0], i, 0) for the first k rows. Each pop is the next smallest sum; push its right neighbour (i, j+1). This explores the sorted-sum grid's frontier without generating all pairs.

k_smallest_pairs.py
from typing import List
import heapq

class Solution:
    def kSmallestPairs(self, nums1: List[int], nums2: List[int], k: int) -> List[List[int]]:
        if not nums1 or not nums2:
            return []
        heap = []
        for i in range(min(k, len(nums1))):
            heapq.heappush(heap, (nums1[i] + nums2[0], i, 0))
        res = []
        while heap and len(res) < k:
            s, i, j = heapq.heappop(heap)
            res.append([nums1[i], nums2[j]])
            if j + 1 < len(nums2):
                heapq.heappush(heap, (nums1[i] + nums2[j + 1], i, j + 1))
        return res

Time O(k log k) · Space O(k). A best-first expansion over an implicit sorted grid — the same shape as matrix k-th smallest.

13 LC 621Task Scheduler Medium Greedy heap + cooldown queue

Problem. Given tasks and a cooldown n between identical tasks, return the minimum total time (including idles). LeetCode 621 ↗

Clarify: Same task needs n gaps between runs? (Yes.) Idle slots count as time? (Yes.)

Hint 1
Always run the most frequent available task next — a max-heap by remaining count.
Hint 2
Hold a just-run task in a cooldown queue until its ready time.

How to think about it Greedy with a max-heap of remaining counts and a cooldown queue. Each tick, run the most frequent ready task (pop the heap) and, if copies remain, park it in the queue with a ready time of now + n; when a queued task's time arrives, return it to the heap. Advance time until both are empty.

task_scheduler.py
from typing import List
import heapq
from collections import Counter
from collections import deque

class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        heap = [-c for c in Counter(tasks).values()]
        heapq.heapify(heap)
        time = 0
        cooldown = deque()                       # (ready_time, remaining_count)
        while heap or cooldown:
            time += 1
            if heap:
                cnt = heapq.heappop(heap) + 1    # run one (values are negative)
                if cnt != 0:
                    cooldown.append((time + n, cnt))
            if cooldown and cooldown[0][0] == time:
                heapq.heappush(heap, cooldown.popleft()[1])
        return time

Time O(total time) · Space O(unique tasks). The heap-plus-cooldown simulation generalises to any 'rate-limited scheduling' problem (a closed-form formula also exists).

14 LC 767Reorganize String Medium Greedy heap · most frequent first, cooldown 1

Problem. Rearrange the string so no two adjacent characters are equal, or return '' if impossible. LeetCode 767 ↗

Clarify: Any valid arrangement? (Yes.) Impossible when a char exceeds ⌈n/2⌉? (Yes.)

Hint 1
Place the most frequent available character each step — a max-heap.
Hint 2
Hold the just-placed character aside for one step so it can't repeat.

How to think about it A max-heap by remaining frequency, with a one-step cooldown. Pop the most frequent character not on cooldown, append it, then release the previously used character back into the heap. Holding the last-used character out for exactly one step guarantees no two neighbours match; impossibility is detected up front.

reorganize_string.py
import heapq
from collections import Counter

class Solution:
    def reorganizeString(self, s: str) -> str:
        counts = Counter(s)
        if max(counts.values()) > (len(s) + 1) // 2:
            return ""
        heap = [(-c, ch) for ch, c in counts.items()]
        heapq.heapify(heap)
        res, prev = [], None
        while heap:
            c, ch = heapq.heappop(heap)
            res.append(ch)
            if prev:
                heapq.heappush(heap, prev); prev = None   # release cooled char
            c += 1
            if c < 0:
                prev = (c, ch)
        return "".join(res)

Time O(n log k) · Space O(k). Task Scheduler with cooldown 1 — the same greedy-heap skeleton.

15 LC 253Meeting Rooms II Medium Sort + min-heap of end times

Problem. Return the minimum number of rooms required for all meetings. LeetCode 253 ↗

Clarify: Rooms reused once free? (Yes.) Answer = peak concurrency? (Yes.)

Hint 1
Process meetings by start time; track when rooms free up.
Hint 2
A min-heap of end times: if the earliest end ≤ the new start, reuse that room.

How to think about it Sort by start and keep a min-heap of room end times. For each meeting, if the earliest-ending room is free by its start, pop it (reuse); then push this meeting's end. The heap size is the peak number of simultaneous meetings — the rooms needed.

meeting_rooms_ii.py
from typing import List
import heapq

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0
        intervals.sort(key=lambda x: x[0])
        ends = []                                # min-heap of room end times
        for s, e in intervals:
            if ends and ends[0] <= s:
                heapq.heappop(ends)              # a room freed up
            heapq.heappush(ends, e)
        return len(ends)

Time O(n log n) · Space O(n). The heap answers 'when does a room next free up' — a sweep-line via a priority queue.

16 LC 1642Furthest Building You Can Reach Medium Heap · spend ladders on the biggest climbs

Problem. With limited bricks and ladders (a ladder covers any single climb), return the furthest building index reachable. LeetCode 1642 ↗

Clarify: A ladder covers one climb of any height? (Yes.) Bricks cover a climb equal to its height? (Yes.)

Hint 1
Use ladders for the largest climbs, bricks for the rest — but you decide as you go.
Hint 2
Keep the climbs where you used a ladder in a min-heap; if you run out, pay the smallest with bricks.

How to think about it Greedy with a min-heap. Tentatively cover each positive climb with a ladder (push it); once you've used more ladders than you have, pop the smallest ladder-climb and pay for it with bricks instead. If bricks go negative, you're stuck at the current building.

furthest_building.py
from typing import List
import heapq

class Solution:
    def furthestBuilding(self, heights: List[int], bricks: int, ladders: int) -> int:
        heap = []                                # min-heap of climbs spent on ladders
        for i in range(len(heights) - 1):
            diff = heights[i + 1] - heights[i]
            if diff > 0:
                heapq.heappush(heap, diff)
                if len(heap) > ladders:          # ran out of ladders
                    bricks -= heapq.heappop(heap)   # pay the smallest climb with bricks
                    if bricks < 0:
                        return i
        return len(heights) - 1

Time O(n log n) · Space O(n). Reassigning the smallest climb from ladder to bricks keeps ladders on the biggest climbs — a lovely exchange argument.

17 LC 1834Single-Threaded CPU Medium Heap of ready tasks by processing time

Problem. Process tasks (enqueue time, processing time) on one CPU, always picking the shortest available task; return the execution order. LeetCode 1834 ↗

Clarify: Ties broken by task index? (Yes.) Pick shortest among available? (Yes.)

Hint 1
Sort tasks by enqueue time; advance a clock.
Hint 2
A min-heap of (processing time, index) holds tasks available at the current time.

How to think about it Sort tasks by enqueue time. Maintain a clock and a min-heap of currently-available tasks keyed by (processing time, index). Each step, add all tasks that have arrived, then run the shortest available one (advancing the clock); if none are ready, jump the clock to the next arrival.

single_threaded_cpu.py
from typing import List
import heapq

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        indexed = sorted((t[0], t[1], i) for i, t in enumerate(tasks))
        res, heap = [], []                       # heap of (proc_time, index) ready now
        time, i, n = 0, 0, len(tasks)
        while len(res) < n:
            while i < n and indexed[i][0] <= time:
                _, proc, idx = indexed[i]
                heapq.heappush(heap, (proc, idx))
                i += 1
            if heap:
                proc, idx = heapq.heappop(heap)
                time += proc
                res.append(idx)
            else:
                time = indexed[i][0]             # idle until the next arrival
        return res

Time O(n log n) · Space O(n). Sort-by-arrival + heap-by-priority is the template for event-driven scheduling.

min_stone_sum.py
from typing import List
import heapq

class Solution:
    def minStoneSum(self, piles: List[int], k: int) -> int:

        heapq.heapify(heap)

            top -= top // 2                      # remove floor(top/2)

        return -sum(heap)

21 LC 1167Minimum Cost to Connect Sticks Medium Greedy heap · merge two smallest (Huffman)

Problem. Repeatedly connect two sticks at a cost equal to their combined length; return the minimum total cost to connect them all. LeetCode 1167 ↗

How to think about it This is Huffman-style greedy: always combine the two smallest sticks, add their sum to the cost, and push the merged stick back. A min-heap makes each 'take the two smallest' step O(log n). Merging small sticks first minimises how many times their length is re-added.

connect_sticks.py
from typing import List
import heapq

class Solution:
    def connectSticks(self, sticks: List[int]) -> int:
        heapq.heapify(sticks)
        cost = 0
        while len(sticks) > 1:
            a = heapq.heappop(sticks)
            b = heapq.heappop(sticks)
            cost += a + b                        # merging the two smallest is optimal
            heapq.heappush(sticks, a + b)
        return cost

Time O(n log n) · Space O(n). The Huffman-coding pattern — merge cheapest pairs first — recurs in file-merging and optimal-merge problems.

Problem. Design Twitter with postTweet, getNewsFeed (10 most recent from self + followees), follow, and unfollow. LeetCode 355 ↗

twitter.py
from typing import List
import heapq
from collections import defaultdict

class Twitter:
    def __init__(self):
        self.time = 0
        self.tweets = defaultdict(list)          # user -> [(time, tweetId)]
        self.following = defaultdict(set)
    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.time, tweetId))
        self.time += 1
    def getNewsFeed(self, userId: int) -> List[int]:
        users = self.following[userId] | {userId}
        candidates = []
        for u in users:
            candidates.extend(self.tweets[u][-10:])
        return [tid for _, tid in heapq.nlargest(10, candidates)]
    def follow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].add(followeeId)
    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.following[followerId].discard(followeeId)

23 LC 1845Seat Reservation Manager Medium Design · min-heap of freed seats

seat_manager.py
import heapq

class SeatManager:
    def __init__(self, n: int):
        self.nxt = 1                             # smallest never-used seat
        self.freed = []                          # min-heap of returned seats
    def reserve(self) -> int:
        if self.freed:
            return heapq.heappop(self.freed)
        seat = self.nxt
        self.nxt += 1
        return seat
    def unreserve(self, seatNumber: int) -> None:
        heapq.heappush(self.freed, seatNumber)

24 LC 2336Smallest Number in Infinite Set Medium Design · counter + min-heap of re-added

Hint 2

How to think about it Track the smallest never-popped number with a counter. popSmallest prefers the min-heap of re-added numbers, else returns the counter's value and advances it. addBack pushes a number to the heap only if it's below the counter and not already queued (a set prevents duplicates).

infinite_set.py
import heapq

class SmallestInfiniteSet:
    def __init__(self):
        self.nxt = 1
        self.added = []                          # min-heap of re-added numbers
        self.in_heap = set()
    def popSmallest(self) -> int:
        if self.added:
            val = heapq.heappop(self.added)
            self.in_heap.discard(val)
            return val
        val = self.nxt
        self.nxt += 1
        return val
    def addBack(self, num: int) -> None:
        if num < self.nxt and num not in self.in_heap:
            heapq.heappush(self.added, num)
            self.in_heap.add(num)

Ops O(log n) · Space O(re-added). Representing an infinite set lazily (counter + heap of exceptions) is the key idea.

25 LC 786K-th Smallest Prime Fraction Medium Heap over a sorted fraction frontier

How to think about it Seed the heap with arr[i]/arr[-1] for every numerator (the smallest fraction each can make). Each pop is the next smallest fraction; push the same numerator paired with the next-smaller denominator. The k-th pop is the answer — a best-first walk over the sorted fraction grid.

prime_fraction.py
from typing import List
import heapq

class Solution:
    def kthSmallestPrimeFraction(self, arr: List[int], k: int) -> List[int]:
        n = len(arr)
        heap = [(arr[i] / arr[-1], i, n - 1) for i in range(n - 1)]
        heapq.heapify(heap)
        for _ in range(k - 1):
            _, i, j = heapq.heappop(heap)

        _, i, j = heapq.heappop(heap)
        return [arr[i], arr[j]]

How to think about it Sort the pairs by nums2 descending, so as you scan, the current element's nums2 is the minimum of any subset ending here. Maintain a size-k min-heap of chosen nums1 values (and their running sum); once you have k, the candidate score is sum × currentNums2. Track the best.

max_subsequence_score.py
from typing import List
import heapq

class Solution:
    def maxScore(self, nums1: List[int], nums2: List[int], k: int) -> int:
        pairs = sorted(zip(nums1, nums2), key=lambda x: -x[1])   # by nums2 desc
        heap, total, best = [], 0, 0
        for a, b in pairs:
            heapq.heappush(heap, a)
            total += a
            if len(heap) > k:
                total -= heapq.heappop(heap)     # drop the smallest nums1 chosen
            if len(heap) == k:
                best = max(best, total * b)      # b is the current min multiplier
        return best

Time O(n log n) · Space O(k). Fixing the minimum by sort order, then heaping the sum, is a powerful two-part technique.

How to think about it Seed a heap with the head of every non-empty list (keyed by value, with a tiebreaker index so nodes never compare directly). Pop the smallest, append it, and push its next. merge_k_lists.py
import heapq

class Solution:
    def mergeKLists(self, lists):
        heap = []
        for i, node in enumerate(lists):
            if node:
                heapq.heappush(heap, (node.val, i, node))   # i breaks ties
        dummy = ListNode()
        tail = dummy
        while heap:
            val, i, node = heapq.heappop(heap)
            tail.next = node
            tail = node
            if node.next:
                heapq.heappush(heap, (node.next.val, i, node.next))
        tail.next = None
        return dummy.next

29 LC 295Find Median from Data Stream Hard Two heaps balanced at the median

Problem. Ingest a stream of numbers and return the running median in O(log n) per add. LeetCode 295 ↗

Clarify: Even count → average of the middle two? (Yes.) Online (interleaved adds/queries)? (Yes.)

Hint 1
Split values into a lower half (max-heap) and upper half (min-heap).
Hint 2

How to think about it Keep a max-heap for the smaller half and a min-heap for the larger half. Each add pushes to one, moves its extreme to the other to keep values ordered, then rebalances sizes. The median is the top of the larger heap, or the average of the two tops when sizes are equal.

median_finder.py
import heapq

class MedianFinder:
    def __init__(self):
        self.small = []      # max-heap (negated) — lower half
        self.large = []      # min-heap — upper half
    def addNum(self, num: int) -> None:
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))   # balance values
        if len(self.large) > len(self.small):                    # balance sizes
            heapq.heappush(self.small, -heapq.heappop(self.large))
    def findMedian(self) -> float:
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2

30 LC 480Sliding Window Median Hard Two heaps + lazy deletion

Problem. Return the median of every contiguous window of size k. LeetCode 480 ↗

Clarify: Even k → average of the middle two? (Yes.) Elements leave the window as it slides? (Yes.)

Hint 1
Two heaps as in Find Median, but you must also remove the element leaving the window.
Hint 2
Removing from a heap's middle is hard — mark it 'delayed' and discard it lazily when it surfaces.

How to think about it Extend the two-heap median to a sliding window. Adding the incoming element and marking the outgoing one for lazy deletion keeps amortised O(log k): track a running size balance to know which heap each affects, rebalance, then discard any stale tops that were marked deleted. The median reads off the heap roots as before.

sliding_window_median.py
from typing import List
import heapq
from collections import defaultdict

class Solution:
    def medianSlidingWindow(self, nums: List[int], k: int) -> List[float]:
        small, large = [], []                    # small: max-heap(neg), large: min-heap
        delayed = defaultdict(int)               # numbers pending lazy removal
        for i in range(k):
            heapq.heappush(small, -nums[i])
        for _ in range(k // 2):                  # move half up so small has the median root
            heapq.heappush(large, -heapq.heappop(small))
        def median():
            return float(-small[0]) if k % 2 else (-small[0] + large[0]) / 2
        res = [median()]
        for i in range(k, len(nums)):
            out, inn = nums[i - k], nums[i]
            delayed[out] += 1
            balance = -1 if small and out <= -small[0] else 1   # side `out` leaves
            if small and inn <= -small[0]:
                heapq.heappush(small, -inn); balance += 1
            else:
                heapq.heappush(large, inn); balance -= 1
            if balance > 0:
                heapq.heappush(large, -heapq.heappop(small))
            elif balance < 0:
                heapq.heappush(small, -heapq.heappop(large))
            while small and delayed[-small[0]] > 0:              # clean stale tops
                delayed[-small[0]] -= 1; heapq.heappop(small)
            while large and delayed[large[0]] > 0:
                delayed[large[0]] -= 1; heapq.heappop(large)
            res.append(median())
        return res

Time O(n log k) · Space O(k). Lazy deletion — mark now, evict when it reaches the top — is the standard fix for 'heaps can't remove from the middle'.

31 LC 407Trapping Rain Water II Hard Best-first flood fill from the border

Problem. Given a 2-D height map, compute the volume of water it can trap. LeetCode 407 ↗

Clarify: Water escapes off the grid edges? (Yes.) Trapped where surrounded by higher walls? (Yes.)

Hint 1
Water level at a cell is set by the lowest surrounding wall — process cells from the outside in.
Hint 2
A min-heap always expands the lowest boundary cell first, like a rising flood.

How to think about it Push all border cells into a min-heap (water escapes there at their own height). Repeatedly pop the lowest boundary cell and visit its unvisited neighbours: each neighbour traps max(0, boundaryHeight − neighbourHeight) water, and enters the heap at max(boundaryHeight, neighbourHeight) — the effective wall for cells further in. The lowest-first order guarantees correct water levels.

trap_rain_water_ii.py
from typing import List
import heapq

class Solution:
    def trapRainWater(self, heightMap: List[List[int]]) -> int:
        if not heightMap or not heightMap[0]:
            return 0
        m, n = len(heightMap), len(heightMap[0])
        visited = [[False] * n for _ in range(m)]
        heap = []
        for i in range(m):                       # push the whole border
            for j in range(n):
                if i in (0, m - 1) or j in (0, n - 1):
                    heapq.heappush(heap, (heightMap[i][j], i, j))
                    visited[i][j] = True
        water = 0
        while heap:
            h, i, j = heapq.heappop(heap)        # lowest boundary cell
            for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < m and 0 <= nj < n and not visited[ni][nj]:
                    visited[ni][nj] = True
                    water += max(0, h - heightMap[ni][nj])       # trapped above neighbour
                    heapq.heappush(heap, (max(h, heightMap[ni][nj]), ni, nj))
        return water

Time O(rc log(rc)) · Space O(rc). A Dijkstra-flavoured best-first expansion — the 2-D generalisation of the 1-D two-pointer version (Ch 06).

32 LC 632Smallest Range Covering Elements from K Lists Hard K-way merge tracking the current max

Problem. Find the smallest range that includes at least one number from each of the k sorted lists. LeetCode 632 ↗

Clarify: Range must cover ≥ 1 element from every list? (Yes.) Smallest by width, then by start? (Yes.)

Hint 1
A valid range spans from the current minimum across the lists to the current maximum.
Hint 2
Advance the list holding the minimum; track the running max as you push its successor.

How to think about it Do a k-way merge: a min-heap holds one 'pointer' per list, and you also track the maximum currently across all lists. The range [heap min, current max] always covers every list, so record it, then advance the list owning the minimum (pushing its next element and updating the max). Stop when any list is exhausted.

smallest_range.py
from typing import List
import heapq

class Solution:
    def smallestRange(self, nums: List[List[int]]) -> List[int]:
        heap = [(row[0], i, 0) for i, row in enumerate(nums)]
        heapq.heapify(heap)
        cur_max = max(row[0] for row in nums)
        best = [heap[0][0], cur_max]
        while True:
            val, i, j = heapq.heappop(heap)      # current minimum across lists
            if cur_max - val < best[1] - best[0]:
                best = [val, cur_max]
            if j + 1 == len(nums[i]):            # a list is exhausted -> stop
                break
            nxt = nums[i][j + 1]
            cur_max = max(cur_max, nxt)
            heapq.heappush(heap, (nxt, i, j + 1))
        return best

Time O(N log k) · Space O(k). Simultaneously tracking the heap's min and a separate running max is the crux.

How to think about it Greedy with a max-heap of fuel amounts from stations already reached. from typing import List
import heapq

class Solution:
    def minRefuelStops(self, target: int, startFuel: int, stations: List[List[int]]) -> int:

        fuel, stops, i, n = startFuel, 0, 0, len(stations)
        while fuel < target:
            while i < n and stations[i][0] <= fuel:
                heapq.heappush(heap, -stations[i][1])
                i += 1
            if not heap:
                return -1                        # can't reach any further station
            fuel += -heapq.heappop(heap)         # refuel at the biggest passed station
            stops += 1
        return stops

from typing import List
import heapq

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        projects = sorted(zip(capital, profits))
        heap = []                                # affordable profits (max-heap)

4 · Interview playbook

  • Spot the heap: "repeatedly need the current min/max", "top-k", "merge k sorted", "always process the highest priority" — all priority-queue problems.
  • Max-heap = negate. Python's heapq is min-only.
  • Top-k: keep a size-k heap of the opposite polarity (min-heap to retain the largest). O(n log k), stream-friendly.
  • Tuples: push (priority, tiebreaker, item); always add an index tiebreaker so unorderable items never get compared.
  • Two heaps for medians; lazy deletion when you must remove an arbitrary element from a heap (as in the sliding-window median).

5 · Role notes

SDE / Python backend

Priority queues drive schedulers, rate limiters, event loops, Dijkstra/A*, and "top-N" queries. heapq and the two-heap median show up in real streaming systems.

Data Science / ML / AI / GenAI

Heaps back k-nearest-neighbour selection, beam search, streaming quantiles/medians, and priority-based sampling. Top-k over embeddings or scores is a daily operation.

6 · Review

Cheat sheet
  • k largest / k-th largest / k most frequent → size-k min-heap (O(n log k)).
  • Merge k sorted lists / k-th in a sorted matrix → k-way merge with a heap.
  • Running / sliding-window median → two heaps (+ lazy deletion for windows).
  • Scheduling / cooldown / rooms → heap by count/end-time, often with a queue.
  • Merge cost / connect sticks → Huffman greedy (merge two smallest).
  • Refuel / IPO / "unlock then pick best" → sort by one key, heap by another.
  • 2-D water / generate-in-order → best-first expansion from a heap.
  • heapq is min-only → negate for max; add an index tiebreaker for tuples.

Concept checks

To keep the k largest elements in a heap, why use a min-heap rather than a max-heap?
The min-heap's root is the smallest of your current keepers, so it's the one to evict when a bigger element arrives — keeping exactly the k largest in O(n log k)
Because a max-heap can't store k elements
Because min-heaps are always faster
You want quick access to the weakest member of your top-k so you can drop it for a stronger newcomer. A min-heap surfaces that weakest (smallest) element at the root; a max-heap would surface the largest, which you never want to evict.
Why push tuples like (value, index, node) instead of just (value, node) when merging linked lists?
If two values tie, Python compares the next tuple field; a unique index prevents it from ever comparing the ListNode objects (which raises a TypeError)
To make the heap larger
Because nodes must be sorted
Heaps order by comparing tuples field by field. On a tie in value, Python moves to the next field; without a unique tiebreaker it would try to compare ListNodes, which aren't orderable and throw. A monotonic index guarantees a decisive, safe comparison.

  • I can merge k sorted sources with a heap.
  • I can maintain a running median with two heaps (and lazy deletion for windows).

  • I can do best-first expansion (2-D water, generate-in-order) with a heap.
