When (and when not) to reach for these

Every tool here trades simplicity for a better asymptotic bound on a specific operation. That trade is worth it only when the naive approach is genuinely too slow for the constraints — and interviewers rarely require it. Learn the signal for each so you can name it if asked, and go deep only for roles that lean competitive (some senior SDE, quant, research).

The signals: range query + updates → Fenwick / segment tree · window max/min → monotonic deque · interval overlaps with a running extreme → sweep line + heap · substring search → KMP · optimise over subsets of a small set → bitmask DP · 2ⁿ too big but 2^(n/2) fine → meet in the middle.

The Fenwick tree (BIT): prefix sums that update

A plain prefix-sum array answers range sums in O(1) but needs O(n) to rebuild after an update. A Fenwick tree gets both to O(log n) using one beautiful trick: each index is responsible for a range whose length is its lowest set bit, and you traverse by adding or stripping that bit.

Example — the whole Fenwick tree in a few lines
fenwick.py
class Fenwick:
    def __init__(self, n):
        self.tree = [0] * (n + 1)          # 1-indexed

    def update(self, i, delta):            # add delta at position i (1-indexed)
        while i < len(self.tree):
            self.tree[i] += delta
            i += i & (-i)                   # jump to the next responsible node

    def prefix(self, i):                   # sum of [1..i]
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & (-i)                   # strip the lowest set bit
        return s

f = Fenwick(5)
for i, v in enumerate([3, 2, 5, 1, 4], 1):
    f.update(i, v)
print(f.prefix(3), f.prefix(5))            # 10 15
Output10 15

The i & -i idiom isolates the lowest set bit — that's the entire secret of the BIT's O(log n) traversal.

The monotonic deque: window extrema in O(1)

To get the max (or min) of every sliding window without an O(k) rescan, keep a deque of indices whose values are monotonic. Pop smaller values off the back before pushing (they can never win), and drop the front once it leaves the window. The front is always the answer.

⚠️
Advanced-DSA pitfalls

Fenwick/segment trees are usually 1-indexed — off-by-one here is the classic bug. Compress coordinates before indexing a BIT by value. In a monotonic deque, store indices (not values) so you can test the window boundary. And don't reach for these at all when a simpler O(n log n) sort or prefix-sum already meets the constraints — complexity you don't need is just risk.

1 LC 307Range Sum Query - Mutable Medium Fenwick tree (BIT)

Problem. Support point updates and range-sum queries on an array, both in O(log n). LeetCode 307 ↗

Clarify: Updates and queries are interleaved and frequent? (Yes.) Prefix-sum arrays give O(n) updates — too slow? (Yes.)

Hint 1
A plain prefix-sum array answers queries in O(1) but costs O(n) to update after a change.
Hint 2
A Fenwick tree (Binary Indexed Tree) does both update and prefix-sum in O(log n) using the low-bit trick.

How to think about it Use a Fenwick tree / Binary Indexed Tree. Each node stores a partial sum covering a range determined by its lowest set bit. To update index i, add the delta and jump via i += i & -i; to get a prefix sum, accumulate while i -= i & -i. A range sum is the difference of two prefix sums.

num_array.py
class NumArray:                                  # LC 307 — Fenwick / BIT
    def __init__(self, nums):
        self.n = len(nums)
        self.nums = [0] * self.n
        self.tree = [0] * (self.n + 1)
        for i, v in enumerate(nums):
            self.update(i, v)

    def update(self, index, val):
        delta = val - self.nums[index]
        self.nums[index] = val
        i = index + 1
        while i <= self.n:
            self.tree[i] += delta
            i += i & (-i)                        # move to the next responsible node

    def _prefix(self, i):                        # sum of nums[0..i]
        s, i = 0, i + 1
        while i > 0:
            s += self.tree[i]
            i -= i & (-i)                        # strip the lowest set bit
        return s

    def sumRange(self, left, right):
        return self._prefix(right) - (self._prefix(left - 1) if left > 0 else 0)

Update / query O(log n) · Space O(n). The BIT is the compact answer to 'prefix sums with updates' — memorise the low-bit jumps.

2 LC 239Sliding Window Maximum Hard Monotonic deque

Problem. Return the maximum of every contiguous window of size k as it slides across the array. LeetCode 239 ↗

Clarify: Window of fixed size k? (Yes.) Better than O(n·k)? (Yes — O(n).)

Hint 1
Maintain a deque of indices whose values are strictly decreasing.
Hint 2
The front is always the window's max; pop smaller values from the back, and drop indices that slid out.

How to think about it Keep a monotonic deque of indices with decreasing values. Before adding index i, pop back indices whose values are ≤ nums[i] (they can never be the max again). Drop the front if it has slid out of the window. The front index always holds the current window maximum.

sliding_window_max.py
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums, k):
        dq = deque()                             # indices, decreasing by value
        res = []
        for i, n in enumerate(nums):
            while dq and nums[dq[-1]] <= n:
                dq.pop()                         # smaller values can never be the max again
            dq.append(i)
            if dq[0] <= i - k:
                dq.popleft()                     # drop indices that fell out of the window
            if i >= k - 1:
                res.append(nums[dq[0]])
        return res

Time O(n) · Space O(k). The monotonic deque is the definitive tool for window extrema — each index is pushed and popped once.

3 LC 862Shortest Subarray with Sum at Least K Hard Monotonic deque over prefix sums

Problem. Return the length of the shortest contiguous subarray whose sum is at least k (values may be negative), or −1. LeetCode 862 ↗

Clarify: Values can be negative? (Yes — that's what makes it hard.) Shortest such subarray? (Yes.)

Hint 1
Work on prefix sums: a subarray sum ≥ k is prefix[j] − prefix[i] ≥ k.
Hint 2
Keep a deque of increasing prefix indices; pop the front when it satisfies k, pop the back when it's not useful.

How to think about it On the prefix-sum array, a window sums to ≥ k when prefix[j] − prefix[i] ≥ k. Maintain a deque of candidate start indices with increasing prefix values: pop the front whenever it forms a valid window (recording the length), and pop the back whenever a new prefix is ≤ an old one (it dominates). Negatives are handled correctly because the deque stays monotonic.

shortest_subarray.py
from collections import deque

class Solution:
    def shortestSubarray(self, nums, k):
        n = len(nums)
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]
        dq = deque()                             # indices with increasing prefix sums
        ans = n + 1
        for i in range(n + 1):
            while dq and prefix[i] - prefix[dq[0]] >= k:
                ans = min(ans, i - dq.popleft())
            while dq and prefix[dq[-1]] >= prefix[i]:
                dq.pop()
            dq.append(i)
        return ans if ans <= n else -1

Time O(n) · Space O(n). Combining prefix sums with a monotonic deque extends the sliding window to arrays with negatives.

4 LC 1425Constrained Subsequence Sum Hard Deque-optimised DP

Problem. Find the maximum sum of a non-empty subsequence where consecutive chosen indices are at most k apart. LeetCode 1425 ↗

Clarify: Chosen indices differ by at most k? (Yes.) Subsequence, order preserved? (Yes.)

Hint 1
dp[i] = nums[i] + max(0, best dp in the previous k positions).
Hint 2
A monotonic deque gives that windowed max in O(1) amortised.

How to think about it A DP where dp[i] = nums[i] + max(0, max dp[i−k..i−1]). The inner windowed maximum is exactly Sliding Window Maximum, so a monotonic deque supplies it in O(1) amortised. Slide the deque as i advances, and the answer is the best dp value.

constrained_subseq.py
from collections import deque

class Solution:
    def constrainedSubsetSum(self, nums, k):
        dq = deque()                             # indices of best dp in the last k
        dp = nums[:]
        for i in range(len(nums)):
            if dq and dq[0] < i - k:
                dq.popleft()
            dp[i] = nums[i] + (max(0, dp[dq[0]]) if dq else 0)
            while dq and dp[dq[-1]] <= dp[i]:
                dq.pop()
            dq.append(i)
        return max(dp)

Time O(n) · Space O(n). When a DP transition needs a windowed max/min, a monotonic deque removes the inner loop.

5 LC 528Random Pick with Weight Medium Prefix sums + binary search

Problem. Pick an index at random with probability proportional to its weight. LeetCode 528 ↗

Clarify: Higher weight ⇒ proportionally more likely? (Yes.) Many picks after one build? (Yes.)

Hint 1
Build cumulative weights; a uniform target in [1, total] lands in exactly one bucket.
Hint 2
Binary-search the prefix array for the first cumulative sum ≥ the target.

How to think about it Precompute cumulative weights so index i owns the range (prefix[i−1], prefix[i]]. Draw a uniform integer target in [1, total] and binary-search (bisect_left) for the first prefix ≥ target — that index is chosen with probability proportional to its weight.

random_pick_weight.py
import random
import bisect

class Solution:                                    # LC 528 — prefix sums + binary search
    def __init__(self, w):
        self.prefix = []
        s = 0
        for x in w:
            s += x
            self.prefix.append(s)
        self.total = s

    def pickIndex(self):
        target = random.randint(1, self.total)   # weighted target in [1, total]
        return bisect.bisect_left(self.prefix, target)

Build O(n) · pick O(log n). Prefix sums plus binary search is the standard weighted-sampling trick (also used in alias-free samplers).

6 LC 398Random Pick Index Medium Reservoir sampling

Problem. Given a target value, return a uniformly random index at which it occurs — using O(1) extra space. LeetCode 398 ↗

Clarify: Uniform among all matching indices? (Yes.) O(1) memory (no index list)? (Yes.)

Hint 1
You can't store all matching indices if space is O(1).
Hint 2
Reservoir sampling: keep the k-th match with probability 1/k as you scan.

How to think about it Reservoir sampling of size 1. Scan the array counting matches; when you hit the c-th occurrence of the target, replace the chosen index with probability 1/c. After one pass every matching index is equally likely, with no auxiliary storage.

random_pick_index.py
import random

class Solution:                                    # LC 398 — reservoir sampling
    def __init__(self, nums):
        self.nums = nums

    def pick(self, target):
        count, result = 0, -1
        for i, n in enumerate(self.nums):
            if n == target:
                count += 1
                if random.randint(1, count) == 1:  # keep i with probability 1/count
                    result = i
        return result

pick O(n) · Space O(1). Reservoir sampling is the technique for uniform selection from a stream of unknown or unstored size.

7 LC 28Find First Occurrence (strStr) Easy KMP string matching

Problem. Return the index of the first occurrence of needle in haystack, or −1. LeetCode 28 ↗

Clarify: Return the first match index? (Yes.) Aim for O(n + m), not O(n·m)? (Yes.)

Hint 1
The naive scan rechecks characters after a mismatch — KMP avoids that.
Hint 2
Precompute the longest-proper-prefix-suffix (LPS) table, then never move the haystack pointer backward.

How to think about it Knuth-Morris-Pratt. Precompute the needle's failure function (LPS) — for each position, the length of the longest proper prefix that is also a suffix. On a mismatch, jump the needle pointer via the LPS instead of restarting, so the haystack pointer only moves forward. Total O(n + m).

str_str.py
class Solution:
    def strStr(self, haystack, needle):
        if not needle:
            return 0
        lps = [0] * len(needle)                  # KMP failure function
        length, i = 0, 1
        while i < len(needle):
            if needle[i] == needle[length]:
                length += 1
                lps[i] = length
                i += 1
            elif length:
                length = lps[length - 1]
            else:
                lps[i] = 0
                i += 1
        i = j = 0
        while i < len(haystack):
            if haystack[i] == needle[j]:
                i += 1
                j += 1
                if j == len(needle):
                    return i - j
            elif j:
                j = lps[j - 1]                   # fall back without rescanning haystack
            else:
                i += 1
        return -1

Time O(n + m) · Space O(m). The LPS/failure function is the heart of KMP and reused in Shortest Palindrome and Longest Happy Prefix.

8 LC 1109Corporate Flight Bookings Medium Difference array

Problem. Apply many range-increment bookings to a flight array and return the final seat totals. LeetCode 1109 ↗

Clarify: Each booking adds seats to a contiguous range? (Yes.) Many ranges, one final read? (Yes.)

Hint 1
Adding to every element of a range is O(range) — too slow across many bookings.
Hint 2
Record only the boundaries in a difference array, then prefix-sum once.

How to think about it Use a difference array: for a range [l, r] add the value at l and subtract it just past r. Each booking is O(1). A single prefix-sum pass at the end reconstructs the actual per-flight totals in O(n).

flight_bookings.py
class Solution:
    def corpFlightBookings(self, bookings, n):
        diff = [0] * (n + 1)                      # difference array
        for first, last, seats in bookings:
            diff[first - 1] += seats
            diff[last] -= seats                  # cancel after the range ends
        res, run = [], 0
        for i in range(n):
            run += diff[i]                       # prefix sum reconstructs the totals
            res.append(run)
        return res

Time O(n + bookings) · Space O(n). Difference arrays turn many range updates + one read into linear time — the offline cousin of a Fenwick tree.

9 LC 315Count of Smaller Numbers After Self Hard Fenwick tree + coordinate compression

Problem. For each element, count how many elements to its right are smaller than it. LeetCode 315 ↗

Clarify: Values can be large/negative? (Yes — compress them.) O(n log n)? (Yes.)

Hint 1
Scan right to left, asking 'how many smaller values have I already seen?'.
Hint 2
A Fenwick tree over compressed ranks answers that count and records the value in O(log n).

How to think about it Compress the values to ranks 1..m. Scan right to left, maintaining a Fenwick tree of seen ranks. For each element, query the prefix count of strictly-smaller ranks (how many smaller values are already to its right), then insert its own rank. A merge-sort with inversion counting is an equivalent approach.

count_smaller.py
class Solution:
    def countSmaller(self, nums):
        order = sorted(set(nums))
        rank = {v: i + 1 for i, v in enumerate(order)}   # compressed 1-based ranks
        m = len(order)
        tree = [0] * (m + 1)

        def update(i):
            while i <= m:
                tree[i] += 1
                i += i & (-i)

        def query(i):                            # count of ranks in [1, i]
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & (-i)
            return s

        res = [0] * len(nums)
        for i in range(len(nums) - 1, -1, -1):   # scan right to left
            r = rank[nums[i]]
            res[i] = query(r - 1)                # how many smaller already seen to the right
            update(r)
        return res

Time O(n log n) · Space O(n). Counting 'smaller/greater to one side' is the flagship Fenwick-tree application.

10 LC 493Reverse Pairs Hard Merge sort with counting

Problem. Count pairs (i, j) with i < j and nums[i] > 2·nums[j]. LeetCode 493 ↗

Clarify: Strictly i < j and the 2× factor? (Yes.) O(n log n)? (Yes.)

Hint 1
During a merge sort, count cross-pairs between the two sorted halves before merging.
Hint 2
For each left element, advance a pointer over the right half while nums[i] > 2·nums[j].

How to think about it Modified merge sort. When merging two already-sorted halves, count qualifying cross-pairs: for each left element, advance a right pointer while nums[i] > 2·nums[j], adding the count. Then merge normally. Pairs within a half are counted by the recursive calls; cross-pairs at each level sum to O(n log n).

reverse_pairs.py
class Solution:
    def reversePairs(self, nums):
        def sort(lo, hi):
            if hi - lo <= 1:
                return 0
            mid = (lo + hi) // 2
            count = sort(lo, mid) + sort(mid, hi)
            j = mid
            for i in range(lo, mid):             # both halves already sorted
                while j < hi and nums[i] > 2 * nums[j]:
                    j += 1
                count += j - mid
            nums[lo:hi] = sorted(nums[lo:hi])    # merge
            return count

        return sort(0, len(nums))

Time O(n log n) · Space O(n). Merge sort's merge step is a natural place to count order-based pairs (inversions and their variants).

11 LC 327Count of Range Sum Hard Merge sort over prefix sums

Problem. Count contiguous subarrays whose sum lies in [lower, upper]. LeetCode 327 ↗

Clarify: Inclusive bounds? (Yes.) Subarray sums via prefix sums? (Yes.)

Hint 1
A subarray sum in [lower, upper] means prefix[j] − prefix[i] ∈ [lower, upper].
Hint 2
Merge-sort the prefix array; for each left prefix, count right prefixes landing in the valid band.

How to think about it Build prefix sums, then merge sort them. While merging sorted halves, for each left prefix prefix[i] use two moving pointers to count right prefixes prefix[j] with prefix[j] − prefix[i] ∈ [lower, upper]. Accumulate across all levels for O(n log n).

count_range_sum.py
class Solution:
    def countRangeSum(self, nums, lower, upper):
        prefix = [0]
        for x in nums:
            prefix.append(prefix[-1] + x)

        def sort(lo, hi):
            if hi - lo <= 1:
                return 0
            mid = (lo + hi) // 2
            count = sort(lo, mid) + sort(mid, hi)
            lo2 = hi2 = mid
            for i in range(lo, mid):
                while lo2 < hi and prefix[lo2] - prefix[i] < lower:
                    lo2 += 1
                while hi2 < hi and prefix[hi2] - prefix[i] <= upper:
                    hi2 += 1
                count += hi2 - lo2               # prefixes giving a sum in [lower, upper]
            prefix[lo:hi] = sorted(prefix[lo:hi])
            return count

        return sort(0, len(prefix))

Time O(n log n) · Space O(n). Range-sum counting reduces to counting ordered prefix pairs within a band — again during the merge step.

12 LC 218The Skyline Problem Hard Sweep line + max-heap

Problem. Given buildings as (left, right, height), return the skyline as a list of key points. LeetCode 218 ↗

Clarify: Output key points where the height changes? (Yes.) Merge collinear points? (Yes.)

Hint 1
Sweep left to right over building starts and ends.
Hint 2
Keep a max-heap of active heights (with their end x); a key point appears whenever the top height changes.

How to think about it A sweep line with a max-heap. Turn each building into a start event (push its height) and an end event. Sorting events so taller starts come first, sweep x-coordinates: lazily pop heights whose building has ended, then read the current max height. Emit a key point whenever that max changes.

skyline.py
import heapq

class Solution:
    def getSkyline(self, buildings):
        events = []
        for l, r, h in buildings:
            events.append((l, -h, r))            # start: negative height sorts taller first
            events.append((r, 0, 0))             # end marker
        events.sort()
        result = []
        live = [(0, float("inf"))]               # max-heap of (-height, end)
        for x, neg_h, r in events:
            while live[0][1] <= x:               # drop buildings that have ended
                heapq.heappop(live)
            if neg_h:
                heapq.heappush(live, (neg_h, r))
            cur = -live[0][0]
            if not result or result[-1][1] != cur:
                result.append([x, cur])
        return result

Time O(n log n) · Space O(n). Sweep-line-plus-heap is the template for interval-overlap problems where you track a running extreme.

13 LC 699Falling Squares Hard Coordinate intervals (segment-tree territory)

Problem. Squares drop one by one onto a number line; after each, report the tallest stack height so far. LeetCode 699 ↗

Clarify: A square rests on the highest overlapping surface? (Yes.) Report the running max height? (Yes.)

Hint 1
Each square's base is the max height over any horizontal interval it overlaps.
Hint 2
Track placed intervals with their top heights; the clean O(n log n) version uses a segment tree with coordinate compression.

How to think about it Each falling square lands at base + size, where base is the maximum top height among already-placed squares that overlap it horizontally. The direct O(n²) version scans placed intervals; the optimal solution uses a segment tree over compressed coordinates supporting range-max query and range assignment. Track the running maximum.

falling_squares.py
class Solution:
    def fallingSquares(self, positions):
        placed = []                              # (left, right, top height)
        res = []
        best = 0
        for left, size in positions:
            right = left + size
            base = 0
            for l, r, h in placed:
                if left < r and l < right:       # horizontal overlap
                    base = max(base, h)
            top = base + size
            placed.append((left, right, top))
            best = max(best, top)
            res.append(best)
        return res

Time O(n²) shown (O(n log n) with a segment tree) · Interval range-max-with-update is exactly what segment trees are built for.

14 LC 732My Calendar III Hard Sweep with a difference map

Problem. Book intervals and after each booking return the maximum number of simultaneous overlaps (k-booking). LeetCode 732 ↗

Clarify: Return the peak overlap count after each booking? (Yes.) Intervals half-open? (Yes.)

Hint 1
Increment a counter at each start and decrement at each end.
Hint 2
Sweep the sorted boundary points; the running sum's peak is the max overlap.

How to think about it Maintain a difference map from time to net change: +1 at each start, −1 at each end. After each booking, sweep the sorted boundaries accumulating the active count; its peak is the maximum simultaneous overlap. (A balanced-BST / segment tree with lazy propagation gives the O(log n)-per-op version.)

my_calendar_iii.py
from collections import defaultdict

class MyCalendarThree:                            # LC 732 — sweep with a difference map
    def __init__(self):
        self.delta = defaultdict(int)

    def book(self, startTime, endTime):
        self.delta[startTime] += 1
        self.delta[endTime] -= 1
        active = best = 0
        for t in sorted(self.delta):             # sweep left to right
            active += self.delta[t]
            best = max(best, active)
        return best

book O(n log n) here · The boundary-sweep counts overlaps directly; it's the same +1/−1 idea as a difference array, kept sorted.

15 LC 698Partition to K Equal Sum Subsets Medium Backtracking with pruning

Problem. Decide whether the array can be split into k subsets all with the same sum. LeetCode 698 ↗

Clarify: All k subsets have equal sum total/k? (Yes.) Use every element? (Yes.)

Hint 1
Target per subset is total/k; reject early if it doesn't divide or any element exceeds it.
Hint 2
Fill one bucket at a time with backtracking; sort descending and prune when an empty bucket can't place an item.

How to think about it Backtracking. The target per subset is total/k. Sort descending (fail-fast), then fill buckets one at a time: place items into the current bucket up to the target, and when it's full start the next. Key prunes: skip used items, and if placing an item into an empty bucket fails, no other item will start it either — so break. (A bitmask DP over subsets is the alternative.)

k_equal_subsets.py
class Solution:
    def canPartitionKSubsets(self, nums, k):
        total = sum(nums)
        if total % k:
            return False
        target = total // k
        nums.sort(reverse=True)
        if nums[0] > target:
            return False
        n = len(nums)
        used = [False] * n

        def backtrack(start, count, cur):
            if count == k:
                return True
            if cur == target:
                return backtrack(0, count + 1, 0)   # this bucket done, start a new one
            for i in range(start, n):
                if not used[i] and cur + nums[i] <= target:
                    used[i] = True
                    if backtrack(i + 1, count, cur + nums[i]):
                        return True
                    used[i] = False
                    if cur == 0:                 # this item can't start any bucket ⇒ prune
                        break
            return False

        return backtrack(0, 0, 0)

Time exponential (heavily pruned) · The 'if the current bucket is empty and this fails, break' prune is what makes it tractable.

16 LC 1125Smallest Sufficient Team Hard Bitmask DP over skill sets

Problem. Pick the smallest team of people that together cover every required skill. LeetCode 1125 ↗

Clarify: At most ~16 skills (so a bitmask fits)? (Yes.) Return the actual team? (Yes.)

Hint 1
Represent each person's skills and the covered set as a bitmask over the required skills.
Hint 2
DP keyed by covered-skill mask: for each person, extend every reachable mask and keep the smallest team.

How to think about it With ≤16 skills, encode each person and the covered set as a bitmask. Keep a DP from covered-mask to the smallest team achieving it. For each person, OR their mask into every existing state; if the new coverage is reached with a smaller team, record it. The answer is the team stored at the all-skills mask.

sufficient_team.py
class Solution:
    def smallestSufficientTeam(self, req_skills, people):
        n = len(req_skills)
        idx = {s: i for i, s in enumerate(req_skills)}
        masks = []
        for p in people:
            m = 0
            for s in p:
                if s in idx:
                    m |= 1 << idx[s]
            masks.append(m)
        full = (1 << n) - 1
        dp = {0: []}                             # covered-skill mask -> smallest team
        for i, pm in enumerate(masks):
            for covered, team in list(dp.items()):
                nc = covered | pm
                if nc == covered:
                    continue
                if nc not in dp or len(dp[nc]) > len(team) + 1:
                    dp[nc] = team + [i]
        return dp[full]

Time O(people·2^skills) · Space O(2^skills). Bitmask DP is the standard tool for set-cover-style problems over a small universe.

17 LC 214Shortest Palindrome Hard KMP on s + '#' + reverse(s)

Problem. Prepend the fewest characters to make the whole string a palindrome. LeetCode 214 ↗

Clarify: Only characters added at the front? (Yes.) Fewest possible? (Yes.)

Hint 1
You want the longest palindromic PREFIX of s; the rest must be mirrored in front.
Hint 2
Run KMP on s + '#' + reverse(s); the final LPS value is that longest palindromic prefix length.

How to think about it The answer prepends the reverse of the suffix that isn't part of the longest palindromic prefix. Compute that prefix length with KMP on s + '#' + reverse(s): the last value of the failure function is exactly the longest prefix of s that is also a suffix of its reverse — i.e. the longest palindromic prefix.

shortest_palindrome.py
class Solution:
    def shortestPalindrome(self, s):
        if not s:
            return s
        combined = s + "#" + s[::-1]             # KMP on s#reverse finds the longest palindromic prefix
        lps = [0] * len(combined)
        for i in range(1, len(combined)):
            length = lps[i - 1]
            while length and combined[i] != combined[length]:
                length = lps[length - 1]
            if combined[i] == combined[length]:
                length += 1
            lps[i] = length
        add = s[lps[-1]:][::-1]                   # the suffix not already a palindrome prefix
        return add + s

Time O(n) · Space O(n). A clever framing turns a palindrome question into a single failure-function computation.

18 LC 1392Longest Happy Prefix Hard KMP failure function

Problem. Return the longest proper prefix that is also a suffix of the string. LeetCode 1392 ↗

Clarify: Proper (not the whole string)? (Yes.) Longest such? (Yes.)

Hint 1
This is exactly the last value of the KMP failure function (LPS).
Hint 2
Build the LPS array; lps[-1] is the answer length.

How to think about it This is the KMP failure function's final value. Build the LPS array where lps[i] is the length of the longest proper prefix of s[:i+1] that is also a suffix. The last entry, lps[-1], gives the longest happy prefix length; slice it off the front.

longest_happy_prefix.py
class Solution:
    def longestPrefix(self, s):
        lps = [0] * len(s)                        # KMP failure function
        for i in range(1, len(s)):
            length = lps[i - 1]
            while length and s[i] != s[length]:
                length = lps[length - 1]
            if s[i] == s[length]:
                length += 1
            lps[i] = length
        return s[:lps[-1]]                        # longest proper prefix that is also a suffix

Time O(n) · Space O(n). The purest use of the failure function — the whole answer is one LPS pass.

19 LC 1755Closest Subsequence Sum Hard Meet in the middle

Problem. Choose a subsequence whose sum is as close as possible to a goal; return the minimum absolute difference. LeetCode 1755 ↗

Clarify: n up to ~40 (2ⁿ too big, 2^(n/2) fine)? (Yes.) Minimise |sum − goal|? (Yes.)

Hint 1
2ⁿ subsets is too many, but 2^(n/2) per half is feasible.
Hint 2
Enumerate each half's subset sums, sort one, and binary-search for the complement of each sum in the other.

How to think about it Meet in the middle. Split the array in two, enumerate all subset sums of each half (2^(n/2) each). Sort the right half's sums; for every left-half sum, binary-search the right half for the value closest to goal − leftSum, checking the neighbours on both sides. Track the minimum absolute difference.

closest_subseq_sum.py
import bisect

class Solution:
    def minAbsDifference(self, nums, goal):
        n = len(nums)

        def subset_sums(arr):
            sums = {0}
            for x in arr:
                sums |= {s + x for s in sums}    # all subset sums of this half
            return sorted(sums)

        left = subset_sums(nums[:n // 2])
        right = subset_sums(nums[n // 2:])       # meet in the middle
        best = abs(goal)
        for l in left:
            need = goal - l
            i = bisect.bisect_left(right, need)  # closest right-half sum to `need`
            if i < len(right):
                best = min(best, abs(need - right[i]))
            if i > 0:
                best = min(best, abs(need - right[i - 1]))
        return best

Time O(2^(n/2)·n) · Space O(2^(n/2)). Meet-in-the-middle halves the exponent — the go-to when n≈40 defeats a full subset scan.

20 LC 691Stickers to Spell Word Hard Bitmask DP + memoisation

Problem. Return the fewest stickers (each a multiset of letters, reusable) needed to spell the target, or −1. LeetCode 691 ↗

Clarify: Stickers reusable any number of times? (Yes.) Target up to ~15 chars (bitmask)? (Yes.)

Hint 1
State = bitmask of which target positions are already covered.
Hint 2
From a state, try each sticker that covers the first uncovered letter; memoise on the mask.

How to think about it Bitmask DP over which target positions are filled. From a state, find the first uncovered letter and only try stickers that contain it (a symmetry-breaking prune). Applying a sticker fills as many still-needed letters as it can, yielding a new mask; recurse with memoisation. The answer is the fewest stickers to reach the all-filled mask.

stickers.py
from collections import Counter
from functools import lru_cache

class Solution:
    def minStickers(self, stickers, target):
        n = len(target)
        counts = [Counter(s) for s in stickers]

        @lru_cache(None)
        def dp(state):                           # state = bitmask of covered target chars
            if state == (1 << n) - 1:
                return 0
            i = 0
            while state & (1 << i):              # first uncovered position
                i += 1
            best = float("inf")
            for c in counts:
                if target[i] not in c:
                    continue                     # only try stickers that help position i
                avail = dict(c)
                ns = state
                for j in range(n):
                    if not (ns & (1 << j)) and avail.get(target[j], 0) > 0:
                        avail[target[j]] -= 1
                        ns |= 1 << j
                best = min(best, 1 + dp(ns))
            return best

        r = dp(0)
        return r if r != float("inf") else -1

Time O(2^n · stickers · n) · Bitmask-over-target with the 'cover the first missing letter' prune keeps this exponential search feasible.

21 LC 715Range Module Hard Merged sorted intervals (segment-tree territory)

Problem. Track ranges of numbers: add a range, remove a range, and query whether a range is fully tracked. LeetCode 715 ↗

Clarify: Ranges are half-open [left, right)? (Yes.) Overlapping adds merge? (Yes.)

Hint 1
Keep disjoint sorted intervals; add merges overlaps, remove splits them.
Hint 2
The optimal structure is a balanced BST / segment tree keyed on interval boundaries.

How to think about it Maintain disjoint sorted intervals. addRange inserts and merges overlapping/adjacent intervals; removeRange trims or splits any interval it intersects; queryRange checks that a single stored interval fully contains the query. The shown version is O(n) per op for clarity; a balanced BST or segment tree of boundaries gives O(log n).

range_module.py
class RangeModule:                                # LC 715 — merged sorted intervals
    def __init__(self):
        self.intervals = []                       # sorted, disjoint [start, end)

    def addRange(self, left, right):
        merged = []
        for s, e in sorted(self.intervals + [[left, right]]):
            if merged and s <= merged[-1][1]:
                merged[-1][1] = max(merged[-1][1], e)
            else:
                merged.append([s, e])
        self.intervals = merged

    def queryRange(self, left, right):
        for s, e in self.intervals:
            if s <= left and right <= e:
                return True
            if s > left:
                break
        return False

    def removeRange(self, left, right):
        new = []
        for s, e in self.intervals:
            if e <= left or s >= right:
                new.append([s, e])
            else:
                if s < left:
                    new.append([s, left])
                if e > right:
                    new.append([right, e])
        self.intervals = new

Ops O(n) shown (O(log n) with an interval tree) · Managing dynamic disjoint intervals is a recurring systems problem (allocators, calendars).

22 LC 480Sliding Window Median Hard Two heaps + lazy deletion

Problem. Return the median of every window of size k as it slides across the array. LeetCode 480 ↗

Clarify: Median of even k is the average of the two middle values? (Yes.) Efficient removal from the window? (Yes.)

Hint 1
Two heaps (a max-heap for the low half, min-heap for the high half) give the median in O(1).
Hint 2
Removing the element leaving the window is the hard part — use lazy deletion: defer removals until they reach a heap top.

How to think about it Balance a max-heap (lower half) and min-heap (upper half) so the median is read from their tops. Sliding the window means removing the outgoing element and adding the incoming one — done with lazy deletion: mark the outgoing value in a to-remove map, adjust a balance counter, rebalance, then purge marked values only once they surface at a heap top.

sliding_window_median.py
import heapq
from collections import defaultdict

class Solution:
    def medianSlidingWindow(self, nums, k):
        lo = []                                   # max-heap (negated) — lower half
        hi = []                                   # min-heap — upper half
        for i in range(k):
            heapq.heappush(lo, -nums[i])
        for _ in range(k // 2):
            heapq.heappush(hi, -heapq.heappop(lo))

        def median():
            return float(-lo[0]) if k % 2 else (-lo[0] + hi[0]) / 2.0

        res = [median()]
        to_remove = defaultdict(int)              # lazy-deletion counts
        for i in range(k, len(nums)):
            out, inn, balance = nums[i - k], nums[i], 0
            if out <= -lo[0]:                     # out leaves the lower half
                balance -= 1
                if out == -lo[0]:
                    heapq.heappop(lo)
                else:
                    to_remove[out] += 1
            else:                                 # out leaves the upper half
                balance += 1
                if out == hi[0]:
                    heapq.heappop(hi)
                else:
                    to_remove[out] += 1
            if lo and inn <= -lo[0]:              # inn joins a half
                balance += 1
                heapq.heappush(lo, -inn)
            else:
                balance -= 1
                heapq.heappush(hi, inn)
            if balance < 0:                       # rebalance sizes
                heapq.heappush(lo, -heapq.heappop(hi))
            elif balance > 0:
                heapq.heappush(hi, -heapq.heappop(lo))
            while lo and to_remove[-lo[0]] > 0:   # purge deleted values that reached a top
                to_remove[-lo[0]] -= 1
                heapq.heappop(lo)
            while hi and to_remove[hi[0]] > 0:
                to_remove[hi[0]] -= 1
                heapq.heappop(hi)
            res.append(median())
        return res

Time O(n log k) · Space O(k). The two-heap median plus lazy deletion is the canonical technique for a streaming/windowed median.

  • Only when justified. State the naive bound first; reach for a specialist structure only when the constraints actually rule it out. Naming the technique is often enough.
  • Range query + updates → Fenwick tree (prefix sums) or segment tree (range assign / lazy). Remember coordinate compression and 1-indexing.
  • Window extrema → monotonic deque of indices; also optimises windowed-max DP transitions.
  • Counting order-based pairs (inversions, reverse pairs, range sums) → count during a merge sort, or use a BIT over compressed ranks.
  • Substring / prefix-suffix → KMP's failure function; subsets of a small set → bitmask DP; 2ⁿ but halvable → meet in the middle.

6 · Review

Cheat sheet
  • Prefix sums that must update → Fenwick tree (i & -i jumps).
  • Range query + range update → segment tree (with lazy propagation).
  • Sliding-window max/min → monotonic deque of indices.
  • Interval overlaps / skyline / k-booking → sweep line + heap or difference map.
  • Inversions / reverse pairs / range-sum counts → merge-sort counting (or a BIT).
  • Substring search / longest prefix=suffix → KMP failure function.
  • Optimise over subsets of ≤~16 items → bitmask DP.
  • 2ⁿ too big, 2^(n/2) fine → meet in the middle.
  • Weighted / uniform random selection → prefix sums + binary search / reservoir sampling.

Concept checks

What does the i & (-i) operation compute, and why is it central to a Fenwick tree?
It isolates the lowest set bit of i, which is exactly the length of the range that index i is responsible for — so adding/subtracting it walks the tree in O(log n)
It negates i, halving the update cost
It rounds i down to the nearest power of two for array sizing
In two's complement, i & -i yields the value of the lowest set bit. A Fenwick node at index i covers a range of exactly that many elements, so i += i & -i (update) and i -= i & -i (query) hop between responsible nodes, giving logarithmic updates and prefix sums.
When is 'meet in the middle' the right technique?
When a full 2ⁿ subset enumeration is too large but n is small enough (≈40) that enumerating 2^(n/2) subsets per half and combining them (e.g. by sorting + binary search) is feasible
Whenever the array is sorted
Only when the answer is a contiguous subarray
Meet in the middle halves the exponent: splitting into two halves turns 2ⁿ into two batches of 2^(n/2), which you then combine (sort one side, binary-search the complement of each element of the other). It's the standard escape when n≈40 makes a full subset scan hopeless but a halved one is fine.
