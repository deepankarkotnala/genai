Binary Search

Halve the search space every step and O(n) becomes O(log n) — but the real power is binary search on the answer: when "is X feasible?" is monotone, you can search for the best X directly. This chapter builds both, and every problem has a full, tested solution in LeetCode's class Solution format.

Outcome

Write bug-free binary search with the half-open template, find lower/upper bounds, search rotated arrays, and — the big one — recognise and solve "binary search on the answer" problems by defining a monotone feasibility check.

1 · Foundations

New to binary search? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

The idea: throw away half every step

Binary search works on any range where you can, at the midpoint, decide which half the answer is in and discard the other. Halving repeatedly means only about log₂(n) steps — 20 steps covers a million elements, 30 covers a billion. The classic use is finding a value in a sorted array.

Example — the classic template
classic.py
def search(nums, target):
    lo, hi = 0, len(nums) - 1          # inclusive range [lo, hi]
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1               # answer is in the right half
        else:
            hi = mid - 1              # answer is in the left half
    return -1

print(search([-1, 0, 3, 5, 9, 12], 9))   # 4
Output4
Binary search needs monotonicity: as you move right, the thing you test must change in one direction (sorted values, a false→true predicate). No monotonic structure, no binary search.

Lower bound: the off-by-one-proof template

Exact-match search is easy; the bugs live in "find the first element ≥ target" (a lower bound). A half-open window [lo, hi) with hi = len(nums) and the invariant "the answer is in [lo, hi]" avoids almost every off-by-one. When the loop ends, lo == hi is the answer.

Example — first index whose value is ≥ target
lower_bound.py
def lower_bound(nums, target):
    lo, hi = 0, len(nums)              # half-open: hi can be len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid                   # keep mid as a candidate
    return lo                          # first index with nums[i] >= target

print(lower_bound([1, 3, 5, 6], 5))    # 2   (also where you'd insert 5)
Python's bisect_left / bisect_right are exactly lower/upper bound. Reach for them when you don't need to hand-roll the loop.

The big idea: binary search on the answer

The move that unlocks the hardest problems: sometimes the array isn't sorted, but the answer is a number in a range, and "is a value X good enough?" is a monotone yes/no question (once true, it stays true). Then you can binary-search the answer itself — no sorted array required.

Take Koko Eating Bananas: find the slowest eating speed that finishes in time. Faster speed → fewer hours, so "finishes within h hours?" flips from false to true exactly once as speed grows. Binary-search the speed for that first true:

Example — search the answer via a feasibility check
on_answer.py
def min_eating_speed(piles, h):
    def hours(speed):                          # monotone: bigger speed, fewer hours
        return sum((p + speed - 1) // speed for p in piles)
    lo, hi = 1, max(piles)                     # the answer lives in this range
    while lo < hi:
        mid = (lo + hi) // 2
        if hours(mid) <= h:
            hi = mid                           # feasible -> try slower
        else:
            lo = mid + 1                       # too slow -> speed up
    return lo

print(min_eating_speed([3, 6, 7, 11], 8))      # 4
Output4

The recipe: (1) identify the answer's range, (2) write a monotone feasible(x) check, (3) binary-search for the smallest/largest feasible x. Koko, Ship Packages, Split Array, and many "minimise the maximum" problems are all this.

Rotated and modified arrays

Binary search still applies when a sorted array has been rotated: at any midpoint one half is still sorted, so you check which half is clean and whether the target lies in it. The same "detect a local direction" idea finds a peak in an array that isn't globally sorted at all.

⚠️
Binary search pitfalls

Pick a loop style and stick to it: while lo <= hi with mid±1 for exact match, or while lo < hi with hi = mid for bounds — mixing them causes infinite loops. When searching for a maximum, bias the midpoint up ((lo+hi+1)//2) to avoid getting stuck. And always confirm the monotonicity that justifies discarding a half — it's the assumption everything rests on.

1 LC 704Binary Search Easy The classic template

Problem. Return the index of target in a sorted array, or −1. LeetCode 704 ↗

Clarify: Distinct values? (Yes.) O(log n) required? (Yes.)

Hint 1
Compare the middle element to the target and discard half the array.
Hint 2
Keep lo and hi inclusive; loop while lo <= hi.

How to think about it The textbook binary search. Look at the midpoint: if it's the target you're done; if it's too small, the answer is in the right half (lo = mid+1); if too big, the left half (hi = mid-1). Each step halves the range, so it's O(log n).

binary_search.py
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return -1

Time O(log n) · Space O(1). Memorise this shape — every other problem in the chapter is a variation of it.

3 LC 278First Bad Version Easy Boundary search on a monotone predicate

Problem. Versions after a bad one are all bad. Using an isBadVersion API, find the first bad version. LeetCode 278 ↗

Clarify: Once bad, always bad (monotone)? (Yes.) Minimise API calls? (O(log n).)

Hint 1
'Bad' is monotone: false…false, true…true. Find the first true.
Hint 2
If mid is bad, the answer is mid or earlier; otherwise it's after mid.

How to think about it Binary search a boundary. The predicate isBadVersion flips from false to true exactly once; find that first true. If mid is bad, keep it as a candidate and search left (hi = mid); otherwise search right (lo = mid+1).

first_bad_version.py
class Solution:
    def firstBadVersion(self, n: int) -> int:
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if isBadVersion(mid):
                hi = mid               # bad -> answer is mid or earlier
            else:
                lo = mid + 1
        return lo

Time O(log n) · Space O(1). 'Find the first true of a monotone predicate' is the mental model behind binary-search-on-the-answer.

4 LC 374Guess Number Higher or Lower Easy Interactive binary search

Problem. Guess a hidden number in 1..n; a guess API tells you higher, lower, or correct. LeetCode 374 ↗

Clarify: API returns −1/0/1? (Yes.) Minimise guesses? (O(log n).)

Hint 1
Each guess halves the remaining range.
Hint 2
Move the boundary toward the side the API points to.

How to think about it Plain binary search driven by the feedback: if guess(mid) says the pick is lower, shrink hi; if higher, raise lo; equal means found. Straightforward interactive search over a sorted range.

guess_number.py
class Solution:
    def guessNumber(self, n: int) -> int:
        lo, hi = 1, n
        while lo <= hi:
            mid = (lo + hi) // 2
            r = guess(mid)
            if r == 0:
                return mid
            elif r < 0:                # mid is too high
                hi = mid - 1
            else:
                lo = mid + 1
        return -1

Time O(log n) · Space O(1). Interactive problems are binary search where the comparison is an API call.

5 LC 69Sqrt(x) Easy Binary search on a value

Problem. Return the integer square root of x (floor). LeetCode 69 ↗

Clarify: Return the floor of the square root? (Yes.) No float sqrt? (That's the exercise.)

Hint 1
Search for the largest m with m·m ≤ x.
Hint 2
That's a monotone condition — binary search m in [0, x].

How to think about it Binary-search the answer over values 0..x. The condition mid·mid ≤ x is monotone (true then false), so keep the largest mid that satisfies it. This is your first taste of searching a numeric range rather than an array.

sqrtx.py
class Solution:
    def mySqrt(self, x: int) -> int:
        lo, hi, ans = 0, x, 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if mid * mid <= x:
                ans = mid              # feasible, try larger
                lo = mid + 1
            else:
                hi = mid - 1
        return ans

Time O(log x) · Space O(1). Binary search doesn't need an array — a sorted range of answers is enough.

6 LC 367Valid Perfect Square Easy Binary search on a value

Problem. Return whether num is a perfect square, without using a built-in sqrt. LeetCode 367 ↗

Clarify: No sqrt built-in? (Yes.) num is positive? (Yes.)

Hint 1
Search for an m with m·m == num.
Hint 2
m·m is monotone increasing, so binary search works.

How to think about it Binary-search m in 1..num for m·m == num, moving the bounds by whether the square is below or above the target. Same value-search idea as Sqrt(x), but returning a boolean.

perfect_square.py
class Solution:
    def isPerfectSquare(self, num: int) -> bool:
        lo, hi = 1, num
        while lo <= hi:
            mid = (lo + hi) // 2
            sq = mid * mid
            if sq == num:
                return True
            elif sq < num:
                lo = mid + 1
            else:
                hi = mid - 1
        return False

Time O(log num) · Space O(1). Newton's method is an O(log) alternative worth mentioning.

7 LC 744Find Smallest Letter Greater Than Target Easy Upper bound (first > target), with wrap

Problem. Given sorted letters, return the smallest letter strictly greater than target, wrapping around if needed. LeetCode 744 ↗

Clarify: Wrap to the first letter if none is greater? (Yes.) Letters sorted? (Yes.)

Hint 1
This is the 'upper bound' — the first element strictly greater than target.
Hint 2
If the index runs off the end, wrap with modulo.

How to think about it The upper-bound template: find the first letter strictly greater than the target by moving lo past any letter ≤ target. If lo reaches the end, wrap to index 0 with modulo (the letters are circular here).

next_letter.py
from typing import List

class Solution:
    def nextGreatestLetter(self, letters: List[str], target: str) -> str:
        lo, hi = 0, len(letters)       # upper bound: first letter > target
        while lo < hi:
            mid = (lo + hi) // 2
            if letters[mid] <= target:
                lo = mid + 1
            else:
                hi = mid
        return letters[lo % len(letters)]   # wrap around if none is greater

Time O(log n) · Space O(1). Lower bound (≥) vs upper bound (>) differ by one comparison — know both.

8 LC 852Peak Index in a Mountain Array Easy Binary search on the slope

Problem. A mountain array rises then falls. Return the index of the peak. LeetCode 852 ↗

Clarify: Guaranteed a single peak (strictly up then down)? (Yes.) O(log n)? (Yes.)

Hint 1
If the midpoint is still rising (arr[mid] < arr[mid+1]), the peak is to the right.
Hint 2
Otherwise the peak is at mid or to the left.

How to think about it Binary search on the slope. Compare the midpoint to its right neighbour: if it's still climbing, the peak lies to the right (lo = mid+1); otherwise it's at mid or left (hi = mid). The window converges on the peak.

peak_index.py
from typing import List

class Solution:
    def peakIndexInMountainArray(self, arr: List[int]) -> int:
        lo, hi = 0, len(arr) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] < arr[mid + 1]:
                lo = mid + 1           # still climbing -> peak is right
            else:
                hi = mid
        return lo

Time O(log n) · Space O(1). Binary search works on any array where a monotone direction can be detected locally — not just fully sorted ones.

9 LC 34Find First and Last Position Medium Lower and upper bound together

Problem. Return the first and last index of target in a sorted array, or [-1, -1]. LeetCode 34 ↗

Clarify: Duplicates present? (Yes.) O(log n)? (Yes.)

Hint 1
Run binary search twice with different tie-breaking.
Hint 2
For the left bound, keep going left on a match; for the right, keep going right.

How to think about it Two boundary searches sharing one helper. When the midpoint equals the target, the left search keeps moving left (remembering the hit) and the right search keeps moving right. Each is a standard O(log n) search; together they bracket the run of equal values.

search_range.py
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def bound(is_left):
            lo, hi, ans = 0, len(nums) - 1, -1
            while lo <= hi:
                mid = (lo + hi) // 2
                if nums[mid] < target or (not is_left and nums[mid] == target):
                    lo = mid + 1
                else:
                    hi = mid - 1
                if nums[mid] == target:
                    ans = mid
            return ans
        return [bound(True), bound(False)]

Time O(log n) · Space O(1). Factoring the bias into one helper keeps the two searches consistent.

10 LC 540Single Element in a Sorted Array Medium Binary search on pair parity

Problem. Every element appears twice except one. Find the single element in O(log n). LeetCode 540 ↗

Clarify: Sorted, exactly one loner? (Yes.) O(log n) required? (Yes.)

Hint 1
Before the single element, pairs start at even indices; after it, they shift to odd.
Hint 2
Check the pair at an even-aligned mid to decide which half holds the loner.

How to think about it Use the pairing pattern. Align mid to an even index; if nums[mid] == nums[mid+1], the pairs are still intact, so the single element is to the right; otherwise it's at mid or left. The parity break locates the loner in O(log n).

single_element.py
from typing import List

class Solution:
    def singleNonDuplicate(self, nums: List[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if mid % 2 == 1:
                mid -= 1               # align mid to the even index of a pair
            if nums[mid] == nums[mid + 1]:
                lo = mid + 2           # single element is to the right
            else:
                hi = mid
        return nums[lo]

Time O(log n) · Space O(1). Exploiting index parity is the trick that beats the O(n) XOR scan.

11 LC 33Search in Rotated Sorted Array Medium One half is always sorted

Problem. A sorted array was rotated at an unknown pivot. Find target in O(log n), or −1. LeetCode 33 ↗

Clarify: Distinct values? (Yes.) O(log n)? (Yes.)

Hint 1
At any midpoint, one of the two halves is fully sorted.
Hint 2
Check which half is sorted, then whether the target lies in its clean range.

How to think about it Binary search with a twist: compare the midpoint to the low end to learn which half is sorted. If the target falls inside that sorted half's range, search there; otherwise search the other half. Each step still halves the range.

search_rotated.py
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[lo] <= nums[mid]:              # left half is sorted
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:                                  # right half is sorted
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return -1

Time O(log n) · Space O(1). The whole difficulty is the 'which half is sorted, is the target in it' branch.

12 LC 81Search in Rotated Sorted Array II Medium Rotated search with duplicates

Problem. Same as Search in Rotated Sorted Array, but values may repeat. Return whether the target exists. LeetCode 81 ↗

Clarify: Duplicates allowed? (Yes — the complication.) Return a boolean? (Yes.)

Hint 1
Duplicates can make nums[lo] == nums[mid] == nums[hi], hiding which half is sorted.
Hint 2
In that ambiguous case, shrink both ends by one and continue.

How to think about it Extend the rotated search: when nums[lo] == nums[mid] == nums[hi] you can't tell which side is sorted, so nudge lo up and hi down by one. Otherwise proceed as in LC 33. Duplicates degrade the worst case to O(n).

search_rotated_ii.py
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return True
            if nums[lo] == nums[mid] == nums[hi]:  # can't tell which half is sorted
                lo += 1; hi -= 1
            elif nums[lo] <= nums[mid]:
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return False

Time O(log n) average, O(n) worst · Space O(1). The equal-ends ambiguity is why duplicates break the log bound.

13 LC 153Find Minimum in Rotated Sorted Array Medium Compare mid to the right end

Problem. A rotated sorted array of distinct values — find the minimum in O(log n). LeetCode 153 ↗

Clarify: Distinct values? (Yes.) Could be un-rotated? (Yes — min is nums[0].)

Hint 1
The minimum is the single 'drop' in the rotation.
Hint 2
Compare mid with the rightmost value to decide which side the drop is on.

How to think about it Binary-search the rotation point. If nums[mid] > nums[hi], the minimum lies strictly right of mid; otherwise it's at mid or left. Comparing against the right end (not the left) makes the un-rotated case fall out correctly.

find_min_rotated.py
from typing import List

class Solution:

14 LC 162Find Peak Element Medium Climb uphill on an unsorted array

Problem. A peak is greater than its neighbours (edges compare to −∞). Return any peak index in O(log n). LeetCode 162 ↗

Clarify: Any peak, not the global max? (Any.) Neighbours never equal? (Guaranteed.)

Hint 1
If nums[mid] < nums[mid+1], a peak must exist to the right.

Always move toward the higher neighbour — you climb toward some peak.

How to think about it Binary search on slope: if the midpoint is lower than its right neighbour, the array is rising, so a peak lies to the right; otherwise a peak is at mid or left. The window shrinks to a peak because you always walk uphill — surprisingly, on an unsorted array.

from typing import List

class Solution:

15 LC 74Search a 2D Matrix Medium Treat the matrix as one sorted array

Problem. Each row is sorted and every row's first element exceeds the previous row's last. Search for a target. LeetCode 74 ↗

Clarify: Fully sorted when flattened row-major? (Yes.) O(log(mn))? (Yes.)

Hint 1
The matrix is one big sorted sequence read row by row.
Hint 2
Map a 1-D index to (row, col) with divmod by the column count.

How to think about it Because the rows chain together, the matrix behaves like a single sorted array of length m·n. Binary-search that virtual array, converting each 1-D index to (mid // n, mid % n) to read the real cell.

search_matrix.py
from typing import List

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        lo, hi = 0, m * n - 1          # treat the matrix as one sorted array
        while lo <= hi:
            mid = (lo + hi) // 2
            val = matrix[mid // n][mid % n]
            if val == target:
                return True
            elif val < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return False

Time O(log(m·n)) · Space O(1). The index↔coordinate mapping is the only new idea.

16 LC 240Search a 2D Matrix II Medium Staircase from a corner

Problem. Rows and columns are each sorted ascending (but rows don't chain). Search for a target. LeetCode 240 ↗

Clarify: Only rows and columns individually sorted? (Yes.) O(m + n)? (Yes.)

Hint 1
Start at the top-right corner: everything left is smaller, everything below is bigger.
Hint 2
Each comparison eliminates a whole row or column.

How to think about it Start at the top-right corner. If the value is larger than the target, the whole column is too big — move left. If smaller, the whole row is too small — move down. Each step removes a row or column, giving O(m + n).

search_matrix_ii.py
from typing import List

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        r, c = 0, len(matrix[0]) - 1   # start at the top-right corner
        while r < len(matrix) and c >= 0:
            v = matrix[r][c]
            if v == target:
                return True
            elif v > target:
                c -= 1                 # too big -> drop this column
            else:
                r += 1                 # too small -> drop this row
        return False

Time O(m + n) · Space O(1). Not strictly binary search, but the same 'eliminate half the possibilities per step' spirit.

17 LC 875Koko Eating Bananas Medium Binary search on the answer

Problem. Koko eats k bananas/hour. Find the smallest k that finishes all piles within h hours. LeetCode 875 ↗

Clarify: Slower eating means more hours (monotone)? (Yes.) Answer is a speed in [1, max pile]? (Yes.)

Hint 1
Feasibility (can she finish at speed k in ≤ h hours?) is monotone in k.
Hint 2
Binary search k in [1, max(piles)] for the smallest feasible speed.

How to think about it The signature 'binary search on the answer'. The hours needed at speed k only decrease as k grows, so 'finishes in time' is a monotone predicate. Binary-search the speed range [1, max pile] for the smallest feasible k, using a ceil-divide to count hours per pile.

koko.py
from typing import List

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        def hours(k):
            return sum((p + k - 1) // k for p in piles)   # ceil-divide each pile
        lo, hi = 1, max(piles)
        while lo < hi:
            mid = (lo + hi) // 2
            if hours(mid) <= h:
                hi = mid               # slow enough -> try slower
            else:
                lo = mid + 1
        return lo

Time O(n log(max)) · Space O(1). The pattern: define a monotone feasibility check, then binary-search the smallest/largest feasible value.

18 LC 1011Capacity To Ship Packages Within D Days Medium Binary search on the answer

Problem. Ship packages in order within days days; find the least ship capacity that suffices. LeetCode 1011 ↗

Clarify: Packages shipped in the given order? (Yes.) Bigger capacity → fewer days (monotone)? (Yes.)

Hint 1
Feasibility: with capacity C, how many days are needed? That's monotone in C.
Hint 2
Search C in [max package, total weight].

How to think about it Binary-search the capacity. The lower bound is the heaviest single package (must fit) and the upper bound is the total (one day). Count the days a candidate capacity needs by greedily filling the ship; find the smallest capacity needing ≤ days.

ship_capacity.py
from typing import List

class Solution:
    def shipWithinDays(self, weights: List[int], days: int) -> int:
        def need(cap):
            d, cur = 1, 0
            for w in weights:
                if cur + w > cap:
                    d += 1; cur = 0
                cur += w
            return d
        lo, hi = max(weights), sum(weights)
        while lo < hi:
            mid = (lo + hi) // 2
            if need(mid) <= days:
                hi = mid
            else:
                lo = mid + 1
        return lo

Time O(n log(sum)) · Space O(1). Same shape as Koko — the art is choosing the search bounds and the feasibility function.

Hint 1
The summed ceilings decrease as the divisor grows — monotone.
Hint 2
Binary search the divisor in [1, max(nums)].

How to think about it Another answer-search: the ceil-division sum shrinks monotonically as the divisor increases, so binary-search the divisor in [1, max] for the smallest value keeping the sum within the threshold.

smallest_divisor.py
from typing import List

class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        def total(d):
            return sum((x + d - 1) // d for x in nums)

20 LC 1552Magnetic Force Between Two Balls Medium Binary search the maximum minimum gap

Problem. Place m balls in given positions to maximise the minimum distance between any two. LeetCode 1552 ↗

Clarify: Maximise the minimum spacing? (Yes.) Positions given, sort first? (Yes.)

Hint 1
Feasibility: can you place m balls all at least `gap` apart? That's monotone in gap.
Hint 2

How to think about it Binary-search the answer, but for a maximum. Sort positions. 'Can we place all m balls with every pair at least gap apart?' is monotone (harder as gap grows), checkable by a greedy placement. Search for the largest feasible gap.

magnetic_force.py
from typing import List

class Solution:
    def maxDistance(self, position: List[int], m: int) -> int:
        position.sort()
        def can(gap):
            count, last = 1, position[0]
            for p in position[1:]:
                if p - last >= gap:
                    count += 1; last = p
            return count >= m
        lo, hi, ans = 1, position[-1] - position[0], 1
        while lo <= hi:                # maximise the minimum gap
            mid = (lo + hi) // 2
            if can(mid):
                ans = mid; lo = mid + 1
            else:
                hi = mid - 1
        return ans

Time O(n log(range)) · Space O(1). Maximising-the-minimum (or minimising-the-maximum) is the tell for answer-search.

21 LC 1300Sum of Mutated Array Closest to Target Medium Binary search a cap value

Problem. Choose a value so that capping every element at it makes the array sum closest to target; ties pick the smaller value. LeetCode 1300 ↗

Clarify: Cap each element at the chosen value? (Yes.) Ties → smaller value? (Yes.)

Hint 1
The capped sum is monotone in the chosen value.
Hint 2
Binary search the smallest value reaching ≥ target, then compare it with one less.

How to think about it The capped sum increases monotonically with the cap. Binary-search the smallest cap whose sum reaches the target, then compare that cap and the one below it, returning whichever sum is closer (ties favouring the smaller cap).

best_value.py
from typing import List

class Solution:
    def findBestValue(self, arr: List[int], target: int) -> int:
        def total(v):
            return sum(min(x, v) for x in arr)
        lo, hi = 0, max(arr)
        while lo < hi:                 # smallest v with total(v) >= target
            mid = (lo + hi) // 2
            if total(mid) < target:
                lo = mid + 1
            else:
                hi = mid
        if lo == 0:
            return 0
        # compare lo and lo-1; ties go to the smaller value
        if abs(total(lo) - target) < abs(total(lo - 1) - target):
            return lo
        return lo - 1

Time O(n log(max)) · Space O(1). Answer-search plus a final two-candidate comparison for the 'closest' tie rule.

23 LC 2300Successful Pairs of Spells and Potions Medium Sort + binary search per query

Problem. For each spell, count potions whose product with it reaches success. LeetCode 2300 ↗

Hint 2
Binary search that threshold; everything from it onward qualifies.

How to think about it Sort the potions. For each spell, the minimum qualifying potion is ceil(success / spell); binary-search (lower bound) its position, and every potion from there to the end qualifies. Amortises the per-query cost to O(log m).

successful_pairs.py
from typing import List
import bisect

class Solution:
    def successfulPairs(self, spells: List[int], potions: List[int], success: int) -> List[int]:
        potions.sort()
        m = len(potions)
        res = []
        for s in spells:
            need = (success + s - 1) // s          # smallest potion that works
            idx = bisect.bisect_left(potions, need)
            res.append(m - idx)
        return res

Time O((n + m) log m) · Space O(1). Sort-once-then-binary-search-many is a workhorse for batched threshold queries.

24 LC 528Random Pick with Weight Medium Prefix sums + binary search

Build cumulative weights; a random point in [1, total] lands in one index's band.
Hint 2
Binary search (lower bound) for the band containing the random target.

How to think about it Precompute prefix sums of the weights. A uniform random target in [1, total] falls into exactly one index's cumulative band; binary-search (lower bound) the prefix array for it. Larger weights own wider bands, giving the correct distribution.

import bisect
import random

class Solution:
    def __init__(self, w: List[int]):
        self.prefix = []
        total = 0
        for x in w:
            total += x
            self.prefix.append(total)          # cumulative weights
        self.total = total
    def pickIndex(self) -> int:

25 LC 981Time Based Key-Value Store Medium Binary search over timestamps

Hint 1

Hint 2

How to think about it Keep, per key, a list of (timestamp, value) in insertion order (already sorted, since timestamps increase). get binary-searches the rightmost entry whose timestamp is ≤ the query using an upper-bound trick, returning that value or '' if none.

time_map.py
import bisect

class TimeMap:
    def __init__(self):
        self.store = {}                        # key -> list of (timestamp, value)
    def set(self, key: str, value: str, timestamp: int) -> None:
        self.store.setdefault(key, []).append((timestamp, value))
    def get(self, key: str, timestamp: int) -> str:
        if key not in self.store:
            return ""
        arr = self.store[key]
        idx = bisect.bisect_right(arr, (timestamp, chr(127)))  # last <= timestamp
        return arr[idx - 1][1] if idx else ""

set O(1) · get O(log n) · Space O(n). Binary search over a time-ordered log is a common versioned-store pattern.

26 LC 436Find Right Interval Medium Sort starts + binary search

Problem. For each interval, find the interval whose start is the smallest value ≥ this interval's end; return its index or −1. LeetCode 436 ↗

Clarify: 'Right' interval starts at or after this end? (Yes.) Return original indices? (Yes.)

Hint 1

Hint 2
For each end, binary-search the first start ≥ it.

How to think about it Sort the start values paired with their original indices. For each interval's end, binary-search (lower bound) the first start that is at least that end; map back to the original index, or −1 if none exists.

right_interval.py
from typing import List
import bisect

class Solution:
    def findRightInterval(self, intervals: List[List[int]]) -> List[int]:
        starts = sorted((iv[0], i) for i, iv in enumerate(intervals))
        start_vals = [s for s, _ in starts]
        res = []
        for s, e in intervals:
            idx = bisect.bisect_left(start_vals, e)   # first start >= this end
            res.append(starts[idx][1] if idx < len(starts) else -1)
        return res

Problem. Flowers bloom on given days; a bouquet needs k adjacent bloomed flowers. Find the earliest day to make m bouquets. LeetCode 1482 ↗

Clarify: Bouquets need k adjacent bloomed flowers? (Yes.) Impossible if m·k > n? (Yes — return −1.)

Hint 1

Hint 2

How to think about it Binary-search the day. Feasibility ('can we make m bouquets by day d?') is monotone: scan the flowers, counting runs of k consecutive blooms (a broken run resets). Search the day range for the earliest feasible day; rule out the impossible case up front.

min_days_bouquets.py
from typing import List

class Solution:
    def minDays(self, bloomDay: List[int], m: int, k: int) -> int:
        if m * k > len(bloomDay):
            return -1
        def can(day):
            flowers = bouquets = 0
            for b in bloomDay:
                if b <= day:
                    flowers += 1
                    if flowers == k:
                        bouquets += 1; flowers = 0
                else:
                    flowers = 0        # run broken; need k adjacent bloomed
            return bouquets >= m
        lo, hi = min(bloomDay), max(bloomDay)
        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo

Time O(n log(maxDay)) · Space O(1). The feasibility check counts adjacent bloomed runs — the twist over plain answer-search.

Hint 2

How to think about it 'Is p still a subsequence after removing the first k marks?' is monotone (removing more can only hurt). Binary-search the largest feasible k, biasing the midpoint upward, and check subsequence-hood by skipping the removed indices during a linear scan.

max_removals.py
from typing import List

class Solution:
    def maximumRemovals(self, s: str, p: str, removable: List[int]) -> int:
        def is_subseq(k):
            removed = set(removable[:k])
            j = 0
            for i in range(len(s)):
                if i in removed:
                    continue
                if j < len(p) and s[i] == p[j]:
                    j += 1
            return j == len(p)
        lo, hi = 0, len(removable)
        while lo < hi:
            mid = (lo + hi + 1) // 2    # bias up: searching for the largest k
            if is_subseq(mid):
                lo = mid
            else:
                hi = mid - 1
        return lo

Time O((|s|) log(|removable|)) · Space O(|removable|). Binary-searching a count with a linear feasibility check is a versatile combo.

29 LC 4Median of Two Sorted Arrays Hard Binary search the partition

Problem. Return the median of two sorted arrays in O(log(m+n)). LeetCode 4 ↗

Clarify: O(log) required (not merge)? (Yes.) Different lengths? (Yes.)

Hint 1
Binary search a cut in the shorter array; the cut in the other is forced by total size.
Hint 2
A valid cut has every left element ≤ every right element across both arrays.

How to think about it Binary-search a partition of the shorter array so the combined left half has the right size. A cut is valid when the largest left element (each side) is ≤ the smallest right element (other side). Adjust the cut based on which side is too big; the median comes from the boundary values.

median_two_sorted.py
from typing import List

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        A, B = nums1, nums2
        if len(A) > len(B):
            A, B = B, A
        m, n = len(A), len(B)
        lo, hi, half = 0, m, (m + n + 1) // 2
        while lo <= hi:
            i = (lo + hi) // 2         # cut in A; forced cut j in B
            j = half - i
            a_left = A[i - 1] if i > 0 else float("-inf")
            a_right = A[i] if i < m else float("inf")
            b_left = B[j - 1] if j > 0 else float("-inf")
            b_right = B[j] if j < n else float("inf")
            if a_left <= b_right and b_left <= a_right:
                if (m + n) % 2:
                    return max(a_left, b_left)
                return (max(a_left, b_left) + min(a_right, b_right)) / 2
            elif a_left > b_right:
                hi = i - 1
            else:
                lo = i + 1
        return 0.0

Time O(log min(m, n)) · Space O(1). Searching for the cut (not a value), with ±∞ sentinels at the ends, is the crux.

30 LC 154Find Minimum in Rotated Sorted Array II Hard Rotated min with duplicates

Problem. A rotated sorted array that may contain duplicates — find the minimum. LeetCode 154 ↗

Clarify: Duplicates allowed? (Yes — the complication.) O(log n) average? (Yes.)

Hint 1

Hint 2

How to think about it Like LC 153, compare nums[mid] to nums[hi]: greater means the min is right, smaller means it's at mid or left. But when they're equal, the min could be on either side, so decrement hi by one — a safe step since nums[hi] is duplicated at mid.

from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] > nums[hi]:
                lo = mid + 1
            elif nums[mid] < nums[hi]:
                hi = mid
            else:
                hi -= 1                # can't decide -> shrink the ambiguous end

32 LC 719Find K-th Smallest Pair Distance Hard Binary search on the distance + counting

Problem. Return the k-th smallest absolute difference among all pairs. LeetCode 719 ↗

Hint 1
Binary search the distance value; count how many pairs have distance ≤ mid.
Hint 2
That count is monotone, and a two-pointer sweep computes it in O(n).

How to think about it Sort, then binary-search the distance. For a candidate distance, count pairs with difference ≤ it using a sliding two-pointer window (monotone as the distance grows). Find the smallest distance whose count reaches k — that's the k-th smallest pair distance.

kth_pair_distance.py
from typing import List

class Solution:
    def smallestDistancePair(self, nums: List[int], k: int) -> int:
        nums.sort()
        def count(dist):               # pairs with distance <= dist
            cnt = j = 0
            for i in range(len(nums)):
                while nums[i] - nums[j] > dist:
                    j += 1
                cnt += i - j
            return cnt
        lo, hi = 0, nums[-1] - nums[0]
        while lo < hi:
            mid = (lo + hi) // 2
            if count(mid) >= k:
                hi = mid
            else:
                lo = mid + 1
        return lo

34 LC 878Nth Magical Number Hard Binary search + inclusion-exclusion

Problem. A magical number is divisible by a or b. Return the n-th magical number, modulo 1e9+7. LeetCode 878 ↗

Clarify: Divisible by a or b? (Yes.) Answer modulo 1e9+7? (Yes — mod only at the end.)

Hint 1
Count magical numbers ≤ x with inclusion-exclusion: x//a + x//b − x//lcm.
Hint 2
That count is monotone, so binary search x for the n-th.

How to think about it Binary-search the value. The count of magical numbers ≤ x is x//a + x//b − x//lcm(a,b) (inclusion–exclusion). It's monotone, so search for the smallest x whose count reaches n, taking the modulo only on the final answer.

nth_magical.py
from math import gcd

class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        MOD = 10 ** 9 + 7
        lcm = a * b // gcd(a, b)
        def count(x):                  # magical numbers <= x
            return x // a + x // b - x // lcm
        lo, hi = 1, n * min(a, b)
        while lo < hi:
            mid = (lo + hi) // 2
            if count(mid) >= n:
                hi = mid
            else:
                lo = mid + 1
        return lo % MOD

Time O(log(n·min(a,b))) · Space O(1). Counting via inclusion–exclusion turns an intractable enumeration into a logarithmic search.

4 · Interview playbook

  • Confirm monotonicity first. Binary search only works if moving right changes the test in one direction — sorted values or a false→true predicate.
  • One loop style. lo <= hi with mid±1 for exact match; lo < hi with hi = mid for bounds. Don't mix them.
  • Spot "search on the answer": "minimise the maximum", "maximise the minimum", capacity/speed/threshold — define a monotone feasible(x) and search the value range.
  • k-th smallest without enumerating: binary-search the value and count how many are ≤ it.
  • Maximum search: bias the midpoint up ((lo+hi+1)//2) so the loop can't stall; use bisect when a plain lower/upper bound suffices.

5 · Role notes

SDE / Python backend

Binary search backs lookups in sorted stores, versioned key-value reads, rate/capacity tuning, and any "smallest config that meets an SLA" search. bisect is everyday tooling.

Data Science / ML / AI / GenAI

Search-on-the-answer tunes thresholds and budgets; binary search over a monotone metric finds cutoffs; quantile/percentile lookups and time-series version reads are bound searches.

6 · Review

Cheat sheet
  • Find a value in a sorted array → classic template (lo <= hi).
  • First/last position, insert point, count → lower/upper bound (bisect).
  • Rotated sorted array → find the sorted half, then decide.
  • Peak in an un-sorted array → climb toward the higher neighbour.
  • "Minimise the max / maximise the min", capacity, speed, days → search on the answer with a monotone feasible(x).
  • k-th smallest value → binary search value + count ≤ x.
  • 2D matrix (row-chained) → treat as one array; (row/col sorted) → staircase from a corner.

Concept checks

What single property must hold for binary search to be applicable?
Monotonicity — moving in one direction changes the tested condition consistently (sorted values, or a predicate that flips false→true once)
The data must be stored in an array
The array must contain distinct values
Binary search discards half the space based on a midpoint test. That's only valid if the answer can't be in the discarded half — which requires monotonicity. It needn't be a literal sorted array (Koko searches a range of speeds), and duplicates are fine.
In "search on the answer" for a minimise-the-maximum problem, what are you binary-searching over?
Candidate answer values, using a monotone feasibility check to decide which half of the value range to keep
The indices of the input array
The number of subarrays
You search the value range of the answer (e.g. possible largest-subarray-sums). A feasibility function ("can we achieve this cap?") is monotone in that value, so binary search finds the smallest feasible one — even though the input itself isn't what you're bisecting.

Mastery checklist

  • I can write the classic search and explain the loop invariant.
  • I can write lower/upper bound with the half-open template (and use bisect).
  • I can search a rotated array by finding the sorted half.
  • I can binary-search a peak using a local comparison.
  • I can recognise and solve "search on the answer" with a monotone feasibility check.
  • I can find a k-th smallest value by binary-searching the value and counting.
