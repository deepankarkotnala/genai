What is a linked list?

A linked list is a chain of little boxes called nodes. Each node holds two things: a value, and a link (a reference) to the next node. Follow the links and you walk the whole list; the last node links to None, which marks the end.

head is your only handle on the list — it points at the first node. Lose head and you lose the whole list, because nothing else remembers where it starts.

An array stores its items side by side in one block; a linked list scatters its nodes anywhere in memory and threads them together with links. That one difference explains every trade-off in this chapter.

The node in Python

Python has no built-in linked list, so you define the node yourself. This tiny class is the one every interview uses — memorise it:

Example — the node, plus two helpers for testing
node.py
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val        # the data this node holds
        self.next = next      # link to the next node (or None at the end)

# Build 1 -> 2 -> 3 by hand:
a = ListNode(1)
a.next = ListNode(2)
a.next.next = ListNode(3)

# Walk it, collecting values into a normal list:
def to_list(head):
    out = []
    while head:               # stop when we fall off the end (None)
        out.append(head.val)
        head = head.next      # step to the next node
    return out

print(to_list(a))             # [1, 2, 3]
Output[1, 2, 3]

The while head: loop is the fundamental move: keep hopping head = head.next until you reach None. Almost every linked-list algorithm is a variation on this walk.

You cannot jump to the middle

With an array, a[500] is instant — the computer jumps straight there. A linked list has no index arithmetic: to reach the 500th node you must start at head and follow 500 links, one at a time. Reaching position k is therefore O(k), not O(1).

So why use one at all? Because changing the list is cheap. To insert or delete, you just re-point a couple of links — no shifting of everything else the way an array insert requires.

Example — inserting is just two link changes
insert.py
# List: 1 -> 3.  Insert 2 between them.
one = ListNode(1)
three = ListNode(3)
one.next = three

two = ListNode(2)
two.next = one.next     # 2 points to 3   (do this FIRST)
one.next = two          # 1 points to 2
# Now: 1 -> 2 -> 3, and nothing else moved.

Notice the order: we linked the new node to the rest of the list before re-pointing the previous node. Reverse that order and you would lose the 3. That ordering rule is so important it gets its own section below.

Linked list vs array — when to use which

OperationLinked listArray

Reach for a linked list when…

you add or remove at the ends or middle a lot and rarely need the k-th item — e.g. an LRU cache, a queue, or a free list.

Reach for an array when…

you index or scan often and want simplicity and speed. In real systems arrays usually win on cache behaviour — say so when asked to compare.

The one rule: save next before you rewire

Almost every linked-list bug is a lost node: you overwrote a link before saving where it pointed, and now the rest of the list is unreachable. The fix is a habit — save next in a temporary variable first, then re-point.

The golden rule of rewiring

Before you overwrite cur.next, do nxt = cur.next. When in doubt, draw three nodes and move one arrow at a time. This single discipline prevents the majority of linked-list mistakes.

The dummy-head trick

A recurring headache: what if the operation changes the first node? Deleting the head, or inserting before it, needs special-case code. The trick is to add a fake node — a dummy head — in front of the real list. Now the real head is just "the node after the dummy," so it is no longer a special case, and you return dummy.next at the end.

Example — deleting the head without a special case
dummy_head.py
def drop_first(head):
    dummy = ListNode(0, head)   # dummy -> head -> ...
    dummy.next = dummy.next.next  # unlink the real head uniformly
    return dummy.next             # the (possibly new) head

You will see dummy = ListNode(0, head) in most problems where the head can change — Remove Nth From End, Merge Two Lists, Remove Duplicates II, Reverse in k-Groups, and more.

Three variants you should recognise

  • Singly linked — each node points forward only. The interview default, and what this chapter uses unless stated.
  • Doubly linked — each node points both forward and back. That back-link lets you remove a node in O(1) without hunting for its predecessor; it is the backbone of the LRU cache (Ch 21).
  • Circular — the last node links back into the list instead of to None. Useful for round-robin scheduling, and the cause of accidental infinite loops.
⚠️
Python-specific pitfalls

Recursion over a long list hits Python's ~1000-frame limit and raises RecursionError — prefer an iterative walk for reversals and merges (Ch 01). Compare nodes with is (identity), not == (value). And a link you forgot to set to None can leave an accidental cycle that hangs your loop forever.

1 LC 206Reverse Linked List Easy The reversal move — the foundation of the chapter

Problem. Reverse a singly linked list and return the new head. LeetCode 206 ↗

Clarify: In place (O(1) space), or a new list? (In place.) Iterative or recursive? (Iterative is safest for long lists.)

Hint 1
Walk the list, flipping each next pointer to point backward.
Hint 2
Keep three references: prev, the current node, and nxt (saved before you overwrite next).

How to think about it This is the golden rule in action. prev is the head of the part already reversed; the current node is the next one to flip. Save its next, point its link back at prev, then slide both forward. When you fall off the end, prev is the new head.

reverse_list.py
from typing import Optional

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        while head:
            nxt = head.next        # save before overwriting (the golden rule)
            head.next = prev       # flip the arrow backward
            prev = head            # extend the reversed prefix
            head = nxt             # step into the untouched suffix
        return prev

Time O(n) · Space O(1). The recursive version is O(n) stack — state that trade-off. This four-line move reappears in half the chapter.

2 LC 876Middle of the Linked List Easy Fast / slow pointers · the two-speed walk

Problem. Return the middle node. If there are two middles, return the second. LeetCode 876 ↗

Clarify: Two middles on even length — return the second? (Yes.) Can I do it in one pass? (Yes.)

Hint 1
Counting the length then walking halfway is two passes. Can you do it in one?
Hint 2
Move one pointer 1 step and another 2 steps; when the fast one runs off the end, the slow one is at the middle.

How to think about it The two-speed trick: fast moves twice as quickly as slow. By the time fast reaches the end, slow has covered exactly half the distance, so it sits on the middle node. This fast/slow pattern powers cycle detection and palindrome checks too.

middle_node.py
from typing import Optional

class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next       # 1 step
            fast = fast.next.next  # 2 steps
        return slow                # slow is at the middle when fast falls off

Time O(n) · Space O(1). The loop guard fast and fast.next is what makes it land on the second middle for even lengths.

3 LC 21Merge Two Sorted Lists Easy Dummy head + merge pointers

Problem. Splice two sorted lists into one sorted list and return its head. LeetCode 21 ↗

Clarify: Reuse the existing nodes (no new allocation)? (Yes.) Stable on ties? (Take from list1 on equality.)

Hint 1
A dummy head lets you append without special-casing the very first node.
Hint 2
Attach the smaller front each step; when one list empties, attach the other whole in one move.

How to think about it Build the result behind a dummy node so appending is uniform. Compare the two fronts, attach the smaller, and advance that list. When one runs out, the remaining list is already sorted, so link it on wholesale. Return dummy.next.

merge_two.py
from typing import Optional

class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()
        tail = dummy
        while list1 and list2:
            if list1.val <= list2.val:      # <= keeps it stable
                tail.next = list1; list1 = list1.next
            else:
                tail.next = list2; list2 = list2.next
            tail = tail.next
        tail.next = list1 or list2          # attach whatever remains
        return dummy.next

Time O(n + m) · Space O(1). The leftover attach tail.next = list1 or list2 is the neat part — no final loop needed.

4 LC 83Remove Duplicates from Sorted List Easy Skip forward over equal neighbours

Problem. The list is sorted. Remove duplicates so each value appears once; return the head. LeetCode 83 ↗

Clarify: Input sorted? (Yes — duplicates are adjacent.) Keep one copy of each value? (Yes — that is the difference from LC 82.)

Hint 1
Because it is sorted, equal values are neighbours.
Hint 2
When the current node equals the next, unlink the next; otherwise advance.

How to think about it Walk with a single pointer. If the current node's value equals the next node's, skip the next node by re-pointing cur.next — but stay on cur in case there are more copies. Only advance when the neighbour differs. The head never changes, so no dummy is needed.

delete_dups.py
from typing import Optional

class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        cur = head
        while cur and cur.next:
            if cur.val == cur.next.val:
                cur.next = cur.next.next    # skip the duplicate, keep one
            else:
                cur = cur.next
        return head

Time O(n) · Space O(1). Don't advance after a delete — a run of three equal values needs two skips from the same node.

5 LC 203Remove Linked List Elements Easy Dummy head · unlink matching nodes

Problem. Remove every node whose value equals val and return the head. LeetCode 203 ↗

Clarify: Could the head itself match? (Yes — so use a dummy.) Remove all occurrences? (Yes.)

Hint 1
The head might be removed, so a dummy head avoids a special case.
Hint 2
Keep a prev pointer; when the current node matches, point prev.next past it.

How to think about it A dummy head sits in front so removing the real head is uniform. Track prev (last kept node) and cur. On a match, unlink by setting prev.next = cur.next; otherwise move prev up. Either way advance cur.

remove_elements.py
from typing import Optional

class Solution:
    def removeElements(self, head: Optional[ListNode], val: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev, cur = dummy, head
        while cur:
            if cur.val == val:
                prev.next = cur.next        # unlink
            else:
                prev = cur
            cur = cur.next
        return dummy.next

Time O(n) · Space O(1). Only advance prev when you keep a node — advancing it on a delete would strand the link.

6 LC 237Delete Node in a Linked List Easy The copy-forward trick · no head given

Problem. Delete a node given only a reference to that node (not the head). The node is guaranteed not to be the tail. LeetCode 237 ↗

Clarify: You don't get the head? (Correct — only the node.) Is it ever the last node? (No, guaranteed.)

Hint 1
You can't reach the previous node to re-point it, so you can't unlink this node the usual way.
Hint 2
But you can make this node become the next node: copy the next value in, then skip the next node.

How to think about it A clever cheat. Since you can't reach the predecessor, don't delete this node — impersonate the next one. Copy the next node's value into this node, then unlink the next node. The list looks identical to having deleted the original.

delete_node.py
from typing import Optional

class Solution:
    def deleteNode(self, node: 'ListNode') -> None:
        node.val = node.next.val            # copy the next value into this node
        node.next = node.next.next          # then skip the next node

Time O(1) · Space O(1). This only works because the node is never the tail — there is always a next node to copy from.

7 LC 141Linked List Cycle Easy Floyd's tortoise and hare

Problem. Return whether the list contains a cycle. LeetCode 141 ↗

Clarify: Can I use O(1) space (vs a visited set)? (Yes — Floyd.) May I mutate nodes? (No need.)

Hint 1
A visited set works but costs O(n) memory. Can two pointers at different speeds notice a loop?
Hint 2
If there is a cycle, a 2× pointer eventually laps and lands on the 1× pointer.

How to think about it Send a slow pointer (1 step) and a fast pointer (2 steps) through the list. If it ends, there is no cycle. If there is a loop, the fast pointer keeps circling and closes the gap by one each step until it meets the slow pointer — compare with is, since a cycle is about the same object.

has_cycle.py
from typing import Optional

class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:                # identity, not value
                return True
        return False

Time O(n) · Space O(1), versus O(n) for a visited set. Guard fast.next before fast.next.next or you crash at the end.

8 LC 160Intersection of Two Linked Lists Easy Two-pointer length equaliser

Problem. Return the node where two lists first merge, or None. LeetCode 160 ↗

Clarify: They share a common tail (by identity, not value)? (Yes.) O(1) space? (Achievable.)

Hint 1
The shared tail is the same length for both; only the prefixes differ.
Hint 2
When a pointer reaches the end, send it to the other list's head. Both then travel len(a)+len(b) and line up.

How to think about it Walk two pointers, one per list. Each time a pointer hits the end, redirect it to the other list's head. After at most one switch, both have walked the same total distance, so they arrive at the intersection at the same moment — or both hit None together if there is none.

intersection.py
from typing import Optional

class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        if not headA or not headB:
            return None
        pa, pb = headA, headB
        while pa is not pb:
            pa = pa.next if pa else headB    # switch to the other head at the end
            pb = pb.next if pb else headA
        return pa                            # the shared node, or None

Time O(n + m) · Space O(1). Switch to the other list's head (not the current one), and compare identity with is.

9 LC 234Palindrome Linked List Easy Midpoint, reverse half, compare

Problem. Return whether the list reads the same forwards and backwards. LeetCode 234 ↗

Clarify: Copying to an array is O(n) space — can you do O(1)? (Yes.) May I mutate the list? (Yes — restore it if asked.)

Hint 1
Copy to a list and use two pointers — but that's O(n) space.
Hint 2
Find the middle, reverse the second half in place, then compare it against the first half.

How to think about it Three familiar moves: fast/slow to find the middle, the reversal move on the second half, then walk the first half and the reversed second half together comparing values. Equal all the way ⇒ palindrome. (In production, reverse the half back to restore the list.)

is_palindrome.py
from typing import Optional

class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:            # slow reaches the middle
            slow = slow.next
            fast = fast.next.next
        prev = None                          # reverse the second half
        while slow:
            nxt = slow.next
            slow.next = prev
            prev = slow
            slow = nxt
        left, right = head, prev             # compare the two halves
        while right:
            if left.val != right.val:
                return False
            left = left.next
            right = right.next
        return True

Time O(n) · Space O(1), versus O(n) for the copy-to-array approach. Comparing only while right exists neatly ignores the odd middle node.

10 LC 1290Convert Binary Number in a Linked List to Integer Easy Horner's method · shift and add

Problem. The list holds a binary number, most-significant bit first. Return its decimal value. LeetCode 1290 ↗

Clarify: Most-significant bit at the head? (Yes.) Values are only 0 or 1? (Yes.)

Hint 1
Reading left to right, each new bit is worth twice the running total plus itself.
Hint 2
So num = num * 2 + bit as you walk — no need to know the length first.

How to think about it Horner's method. Because the high bit comes first, each step you shift the accumulated value left by one binary place (multiply by 2) and add the new bit. One clean pass, no exponent bookkeeping.

get_decimal.py
from typing import Optional

class Solution:
    def getDecimalValue(self, head: Optional[ListNode]) -> int:
        num = 0
        while head:
            num = num * 2 + head.val         # shift left, add the new bit
            head = head.next
        return num

Time O(n) · Space O(1). The shift-and-add idiom is the standard way to parse a digit stream in any base.

11 LC 92Reverse Linked List II Medium Dummy head · reverse a middle segment

Problem. Reverse the nodes from position left to right (1-indexed) and return the head. LeetCode 92 ↗

Clarify: 1-indexed positions? (Yes.) In one pass, O(1) space? (Yes.) Could left be 1 (head moves)? (Yes — use a dummy.)

Hint 1
Walk to the node just before left; call it prev.
Hint 2
Repeatedly take the node after cur and splice it to the front of the segment — the 'head-insertion' reversal.

How to think about it Use a dummy so a segment starting at the head is not special. Advance prev to the node before left. Then, right − left times, lift the node just after cur and insert it right after prev — this rotates the segment into reverse order without a separate reversal pass.

reverse_between.py
from typing import Optional

class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        for _ in range(left - 1):            # stop just before position `left`
            prev = prev.next
        cur = prev.next
        for _ in range(right - left):        # repeatedly move cur.next in front
            nxt = cur.next
            cur.next = nxt.next
            nxt.next = prev.next
            prev.next = nxt
        return dummy.next

Time O(n) · Space O(1). The head-insertion technique keeps cur fixed as the segment's moving tail — draw two iterations to see it.

12 LC 24Swap Nodes in Pairs Medium Dummy head · relink each adjacent pair

Problem. Swap every two adjacent nodes and return the head. Swap the nodes themselves, not just values. LeetCode 24 ↗

Clarify: Swap nodes, not values? (Yes — that's the intended version.) Odd length leaves the last node alone? (Yes.)

Hint 1
Work pair by pair with a prev anchor before each pair.
Hint 2
For nodes a,b: point a past b, point b back to a, and hook the anchor to b.

How to think about it A dummy anchors the first pair. For each pair (a, b): set a.next to whatever follows b, set b.next = a, and connect the previous group to b. Then a becomes the anchor for the next pair. Stop when fewer than two nodes remain.

swap_pairs.py
from typing import Optional

class Solution:
    def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        while prev.next and prev.next.next:
            a, b = prev.next, prev.next.next
            a.next = b.next                  # a jumps past b
            b.next = a                       # b points back to a
            prev.next = b                    # previous group points to b
            prev = a                         # a is now the group tail
        return dummy.next

Time O(n) · Space O(1). Draw the three link changes once; the order (a→after, b→a, prev→b) is what keeps nothing lost.

13 LC 19Remove Nth Node From End of List Medium Dummy head + a fixed-gap one pass

Problem. Remove the n-th node from the end and return the head. LeetCode 19 ↗

Clarify: Is n valid (1 ≤ n ≤ length)? (Yes.) One pass? (Yes.) The head may be removed — use a dummy.

Hint 1
If fast is n nodes ahead of slow, when fast hits the last node slow sits just before the target.
Hint 2
Start both at a dummy so removing the head needs no special case.

How to think about it Open a gap: advance fast n steps first. Then move fast and slow together until fast is the last node — now slow is right before the one to drop. Unlink it. The dummy makes head-removal uniform.

remove_nth.py
from typing import Optional

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        fast = slow = dummy
        for _ in range(n):                   # open a gap of n
            fast = fast.next
        while fast.next:                     # move both until fast is last
            fast = fast.next
            slow = slow.next
        slow.next = slow.next.next           # unlink the target
        return dummy.next

Time O(n) single pass · Space O(1). Starting both at the dummy (not the head) is what fixes the off-by-one when removing the head.

14 LC 2095Delete the Middle Node of a Linked List Medium Fast / slow · keep the predecessor

Problem. Delete the middle node (index ⌊n/2⌋) and return the head. LeetCode 2095 ↗

Clarify: Middle is the ⌊n/2⌋-th (0-indexed) node? (Yes.) Single node returns empty? (Yes — None.)

Hint 1
Fast/slow finds the middle — but to delete it you need the node just before it.
Hint 2
Track a prev pointer one behind slow, then unlink slow.

How to think about it Run fast/slow to locate the middle, but also carry a prev that trails slow by one. When slow lands on the middle, prev.next = slow.next unlinks it. Handle the single-node case up front by returning None.

delete_middle.py
from typing import Optional

class Solution:
    def deleteMiddle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return None
        prev = None
        slow = fast = head
        while fast and fast.next:
            prev = slow
            slow = slow.next
            fast = fast.next.next
        prev.next = slow.next                # skip the middle node
        return head

Time O(n) · Space O(1). Deletion always needs the predecessor — that's why plain middleNode isn't enough here.

15 LC 142Linked List Cycle II Medium Floyd · find where the cycle begins

Problem. Return the node where the cycle starts, or None. LeetCode 142 ↗

Clarify: Return the entry node, not just yes/no? (Yes.) O(1) space? (Yes.)

Hint 1
First find a meeting point with fast/slow, as in Linked List Cycle.
Hint 2
From the meeting point, the distance to the entry equals the distance from the head to the entry. Walk two pointers one step at a time.

How to think about it After the tortoise and hare meet inside the loop, a short piece of modular arithmetic shows the head and the meeting point are equidistant (mod the loop length) from the entry. So restart one pointer at the head, keep the other at the meeting point, and advance both one step — they collide exactly at the cycle's start.

detect_cycle.py
from typing import Optional

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:                 # meeting point inside the loop
                p = head
                while p is not slow:         # head-distance == entry-distance
                    p = p.next
                    slow = slow.next
                return p
        return None

Time O(n) · Space O(1). Only one pointer restarts at the head; restarting both is the classic bug.

16 LC 328Odd Even Linked List Medium Split into two chains, then join

Problem. Group all odd-positioned nodes together, then all even-positioned nodes, preserving order. Do it in place, O(1) space. LeetCode 328 ↗

Clarify: Group by position (1st, 2nd, 3rd…), not by value? (Yes.) Keep relative order within each group? (Yes.)

Hint 1
Weave two chains as you walk: one of odd-index nodes, one of even-index nodes.
Hint 2
Remember the head of the even chain so you can attach it after the odd chain.

How to think about it Maintain two tails, odd and even, and remember where the evens start. Each iteration links odd to the node after it (the next odd) and even to the node after that (the next even). Finally stitch the even chain onto the end of the odd chain.

odd_even.py
from typing import Optional

class Solution:

How to think about it Two dummy-headed chains collect nodes as you walk once: less for values below x, ge for the rest, each preserving order naturally. Terminate the second chain with None and link the end of less to the start of ge.

from typing import Optional

class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:

        ge_d = ListNode(); ge = ge_d         # nodes >= x

            if head.val < x:

        return less_d.next

How to think about it Measure the length and find the tail. Take k %= n. Close the list into a ring by linking tail to head, then walk n − k − 1 steps to the new tail; the node after it is the new head. Break the ring there.

rotate_right.py
from typing import Optional

class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if not head or not head.next or k == 0:
            return head
        n, tail = 1, head
        while tail.next:                     # measure length, find tail
            tail = tail.next; n += 1
        k %= n
        if k == 0:
            return head
        tail.next = head                     # close into a ring

        new_tail = head
        for _ in range(steps - 1):
            new_tail = new_tail.next
        new_head = new_tail.next
        new_tail.next = None                 # break the ring
        return new_head

Problem. Reorder L0→L1→…→Ln into L0→Ln→L1→Ln-1→… in place. LeetCode 143 ↗

Hint 2

How to think about it Compose three primitives: (1) fast/slow to find the midpoint and cut the list in two; (2) the reversal move on the second half; (3) weave the two halves, alternating one node from each. Every step is O(n) and O(1) space.

from typing import Optional

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        if not head or not head.next:
            return
        slow = fast = head                   # 1) find the midpoint
        while fast.next and fast.next.next:
            slow = slow.next
            fast = fast.next.next
        second = slow.next
        slow.next = None
        prev = None                          # 2) reverse the second half

            nxt = second.next
            second.next = prev
            prev = second
            second = nxt

            second.next = f_next
            first, second = f_next, s_next

25 LC 1171Remove Zero Sum Consecutive Nodes Medium Prefix sums · jump over zero-sum runs

Hint 2

How to think about it A prefix-sum idea from arrays applied to a list. First pass: compute the running sum at each node and remember, for each sum value, the last node that reached it. remove_zero_sum.py
from typing import Optional

class Solution:
    def removeZeroSumSublists(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prefix = 0
        last = {0: dummy}                    # prefix sum -> last node reaching it
        cur = dummy
        while cur:
            prefix += cur.val
            last[prefix] = cur               # keep the LAST occurrence
            cur = cur.next
        prefix = 0
        cur = dummy
        while cur:
            prefix += cur.val
            cur.next = last[prefix].next     # jump over any zero-sum run
            cur = cur.next
        return dummy.next

Time O(n) · Space O(n) for the map. Keeping the last occurrence of each prefix (not the first) is what collapses overlapping zero-sum runs in one shot.

How to think about it Divide and conquer. Find the midpoint with fast/slow and cut the list into halves. Recursively sort each half, then merge the two sorted halves (the same merge as LC 21). Each level costs O(n) to merge and there are O(log n) levels.

sort_list.py
from typing import Optional

class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head
        slow, fast = head, head.next         # split into two halves
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        mid = slow.next
        slow.next = None
        left = self.sortList(head)
        right = self.sortList(mid)

            if left.val <= right.val:
                tail.next = left; left = left.next

            tail = tail.next
        tail.next = left or right
        return dummy.next

class MyLinkedList:
    def __init__(self):
        self.head = None
        self.size = 0
    def get(self, index: int) -> int:
        if index < 0 or index >= self.size:
            return -1
        cur = self.head
        for _ in range(index):
            cur = cur.next
        return cur.val
    def addAtHead(self, val: int) -> None:
        self.addAtIndex(0, val)
    def addAtTail(self, val: int) -> None:
        self.addAtIndex(self.size, val)
    def addAtIndex(self, index: int, val: int) -> None:
        if index < 0 or index > self.size:
            return
        if index == 0:
            self.head = ListNode(val, self.head)
        else:
            prev = self.head
            for _ in range(index - 1):
                prev = prev.next
            prev.next = ListNode(val, prev.next)
        self.size += 1
    def deleteAtIndex(self, index: int) -> None:
        if index < 0 or index >= self.size:
            return
        if index == 0:
            self.head = self.head.next
        else:
            prev = self.head
            for _ in range(index - 1):
                prev = prev.next
            prev.next = prev.next.next
        self.size -= 1

get / add / delete O(index) · Space O(n). Uses the standard ListNode(val, next). Maintaining size turns every bounds check into a simple comparison.

34 LC 146LRU Cache Medium Doubly linked list + hash map (here via OrderedDict)

Canonical write-up: Chapter 21 — Data Structure Design. The linked-list solution is shown here in full.

Problem. Design a cache with O(1) get and put that evicts the least-recently-used key when it exceeds capacity. LeetCode 146 ↗

Clarify: Both operations O(1)? (Yes.) A get counts as a use? (Yes.) On overflow evict the least-recently-used? (Yes.)

Hint 1

Hint 2

How to think about it The idea: a hash map keys → nodes for O(1) lookup, plus a doubly linked list ordering nodes by recency so you can move a node to 'most recent' and evict from 'least recent' in O(1). Python's OrderedDict is exactly that combo: move_to_end marks recency and popitem(last=False) evicts the oldest. Be ready to hand-build the DLL when asked (Ch 21).

lru_cache.py
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.d = OrderedDict()               # ordered by recency
    def get(self, key: int) -> int:
        if key not in self.d:
            return -1
        self.d.move_to_end(key)              # mark most-recent
        return self.d[key]
    def put(self, key: int, value: int) -> None:
        if key in self.d:
            self.d.move_to_end(key)
        self.d[key] = value
        if len(self.d) > self.cap:
            self.d.popitem(last=False)       # evict least-recent

get / put O(1) · Space O(capacity). This is why doubly linked lists exist in interviews — the back-link is what makes O(1) eviction possible.

Tier 3 · Hard — segmented & k-way (2)
35 LC 23Merge k Sorted Lists Hard Min-heap over the k list fronts

Problem. Merge k sorted lists into one sorted list. LeetCode 23 ↗

Clarify: Can lists (or the outer list) be empty? (Yes.) How big is k vs total N? (Heap uses O(k).)

Hint 1
Repeatedly pick the smallest current front across the k lists.
Hint 2
A min-heap of size k gives that smallest front in O(log k); push the popped node's successor.

How to think about it Seed a heap with the head of every non-empty list, keyed by value with a tiebreaker index so nodes never get compared directly. Pop the smallest, append it, and push its next. The heap always holds the current front of each still-nonempty list, so N pops × O(log k) gives O(N log k).

merge_k.py
from typing import List, Optional
import heapq

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        h = []
        for i, node in enumerate(lists):
            if node:
                heapq.heappush(h, (node.val, i, node))   # i breaks ties
        dummy = ListNode()
        tail = dummy
        while h:
            val, i, node = heapq.heappop(h)
            tail.next = node
            tail = node
            if node.next:
                heapq.heappush(h, (node.next.val, i, node.next))
        tail.next = None
        return dummy.next

Time O(N log k) · Space O(k) for the heap. The tiebreaker index is essential — without it Python tries to compare ListNodes and crashes on equal values.

36 LC 25Reverse Nodes in k-Group Hard Segmented reversal with a group anchor

Problem. Reverse the list in groups of k; a trailing group smaller than k stays as-is. LeetCode 25 ↗

Clarify: Leave a final short group unreversed? (Yes.) In place, O(1) space? (Yes.)

Hint 1
Reversal you know; the work is stitching each reversed block to its neighbours.
Hint 2
Keep a group_prev anchor; find the k-th node first, and stop if fewer than k remain.

How to think about it For each group, walk k nodes to find the k-th (returning early if the list runs out — the short tail stays). Reverse the block between the anchor and the k-th node, then re-stitch: the anchor points to the k-th (new block head) and the old block head becomes the next anchor. Everything before the anchor is finalised.

reverse_k_group.py
from typing import Optional

class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        group_prev = dummy
        while True:
            kth = group_prev                 # find the k-th node of this group
            for _ in range(k):
                kth = kth.next
                if not kth:
                    return dummy.next         # fewer than k remain -> done
            group_next = kth.next
            prev, cur = group_next, group_prev.next   # reverse the block
            while cur is not group_next:
                nxt = cur.next
                cur.next = prev
                prev = cur
                cur = nxt
            tmp = group_prev.next            # re-stitch and advance the anchor
            group_prev.next = kth
            group_prev = tmp

Time O(n) · Space O(1). The two tricky parts: return early when fewer than k remain, and remember the old head as the next anchor before re-pointing.

4 · Interview playbook

  • Before any rewiring: save node.next. Draw three nodes and move one arrow at a time.
  • Use a dummy head whenever the head might be removed or replaced (LC 19, 21, 82, 25).
  • State the invariant: "everything before cur is reversed", "fast leads slow by n", "tail points at the smaller frontier".
  • Cycle safety: compare node identity with is, guard fast.next before fast.next.next, and null-terminate any list you split.
  • Edge cases: empty list, one node, two nodes, odd vs even length, head/tail change, and (for detection problems) a cycle.
  • Recursion caution: a 10⁵-node list overflows the default recursion limit — prefer iterative reversal and merges.

6 · Review

Cheat sheet
  • Reversal move: nxt = cur.next; cur.next = prev; prev = cur; cur = nxt.
  • Dummy head when the head can change: dummy = ListNode(0, head).
  • Midpoint / cycle / kth-from-end → fast & slow pointers.
  • Cycle start → Floyd, then walk from head and meeting point together.
  • Two lists intersect → switch heads to equalise length.
  • Sort a list → merge sort (split, sort, merge).
  • Merge k lists → min-heap with a tiebreaker index.
  • O(1) recency cache → doubly linked list + hash map (LRU).

Concept checks

Why do we compare pointers with is (not ==) in cycle detection?
Two different nodes can hold equal values; a cycle means the same object is revisited, which is identity
Because == is slower
Because values might be None
A cycle is defined by node identity — the fast pointer must land on the exact same object the slow pointer is on. Value equality could give false positives on lists with repeated values.
You are asked to reverse a 200,000-node list. Which reversal do you write and why?
Iterative — recursion would exceed Python's ~1000-frame limit and raise RecursionError
Recursive — it is shorter
Either; they behave identically
Recursive reversal uses O(n) stack frames; at 200k nodes that overflows the default limit. Iterative reversal is O(1) auxiliary space and safe.
