Linked Lists

Linked lists test one thing above all: can you rewire pointers without losing nodes? This chapter is nearly self-contained — fourteen of its fifteen problems are owned here — and every pattern comes down to a small set of pointer moves you can draw before you type.

Outcome

Manipulate singly and doubly linked lists confidently: use a dummy head when the head may change, save next before overwriting it, run fast/slow pointers for midpoints and cycles, and reverse in place — always stating what each pointer means as an invariant.

1 · Foundations

Mental model. A linked list is a chain of nodes, each holding a value and a reference to the next node. There is no index arithmetic: to reach the k-th node you walk k links. That single difference from arrays — no O(1) random access — shapes every trade-off.

How Python represents it. There is no built-in linked list — you define a node class. Each node is a separate heap object holding a reference to the next, so nodes are scattered in memory (poor cache locality) and each carries Python object overhead. The standard interview definition:

node.py
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

# small helpers used in the tests below
def build(vals):
    dummy = ListNode()
    cur = dummy
    for v in vals:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

assert to_list(build([1, 2, 3])) == [1, 2, 3]
print("node ok")

Variants and the golden rule

  • Singly linked: each node points forward only. The interview default.
  • Doubly linked: nodes point both ways — O(1) removal given a node, the backbone of LRU (Ch 21).
  • Circular: the tail points back into the list; the source of accidental cycles.
🔗
The golden rule of rewiring

Before you overwrite node.next, save it. Almost every linked-list bug is a lost reference — you reassigned a pointer and can no longer reach the rest of the list. Draw three nodes and move one arrow at a time.

Operations and complexity

OperationLinked listArray
Access k-th elementO(n)O(1)
Insert / delete at headO(1)O(n)
Insert / delete given the nodeO(1)O(n)
Search by valueO(n)O(n)
Memory localityPoor (scattered nodes)Good (contiguous)

Choose a linked list when…

you splice at the ends or middle frequently and rarely index; you need stable O(1) insert/delete given a node (LRU, free lists, adjacency).

Prefer an array when…

you index or scan a lot; locality and simplicity matter. In real systems arrays usually win on cache behaviour — say so when asked to compare.

⚠️
Python-specific pitfalls

Recursion over a long list hits the ~1000-frame limit — prefer iteration (Ch 01). Aliasing two names to the same node and rewiring one can create an unintended cycle. A dangling next you forgot to set to None can leave a loop that hangs your traversal.

The three moves you will reuse everywhere

Reversal is nxt = cur.next; cur.next = prev; prev = cur; cur = nxt. The dummy head is dummy = ListNode(0, head). Fast/slow is slow = slow.next; fast = fast.next.next. Memorise these three and most problems become composition.

1 LC 206Reverse Linked List EasyCanonical Pattern 3 · The reversal move — the foundation of the chapter

Summary. Reverse a singly linked list and return the new head. LeetCode 206 ↗ · ~15 min.

Clarify: in place (O(1) space) or a new list? Recursive or iterative — do they want to see both? (Iterative is safest for long lists.)

Hint 1
Walk the list, flipping each next pointer to point backward.
Hint 2
Keep three references: prev, cur, and nxt (saved before you overwrite cur.next).

Approach Invariant: prev is the head of the already-reversed prefix; cur is the next node to flip. Save cur.next, point cur.next at prev, then advance both. When cur is None, prev is the new head.

lc206.py
def reverse_list(head):
    prev = None
    while head:
        nxt = head.next     # save before overwriting (golden rule)
        head.next = prev    # flip the pointer
        prev = head         # extend the reversed prefix
        head = nxt          # advance into the untouched suffix
    return prev

assert to_list(reverse_list(build([1, 2, 3, 4, 5]))) == [5, 4, 3, 2, 1]
assert to_list(reverse_list(build([]))) == []       # empty
assert to_list(reverse_list(build([1]))) == [1]     # single node
print("lc206 ok")

Time O(n) · Auxiliary space O(1) iterative (the recursive version is O(n) stack — state that trade-off) · Mutation pointers rewired in place. Common mistakes: overwriting head.next before saving it (loses the rest of the list). Follow-up: reverse between positions m and n (LC 92). Narration: "prev holds the reversed part; I flip one arrow at a time, saving next first."

2 LC 21Merge Two Sorted Lists EasyCanonical Patterns 1 + 4 · Dummy head and merge pointers

Summary. Splice two sorted lists into one sorted list and return its head. LeetCode 21 ↗ · ~15 min.

Clarify: reuse the existing nodes (no new allocations)? (Yes.) Stable on ties? (Take from l1 on equality.)

Hint 1
A dummy head lets you append without special-casing the first node.
Hint 2
Attach the smaller front each step; at the end, one list may remain — attach it whole.

Approach Invariant: tail is the last node of the merged list; dummy.next is the eventual head. Compare fronts, attach the smaller, advance. When one list empties, tail.next = l1 or l2 attaches the remainder in O(1).

lc21.py
def merge_two(l1, l2):
    dummy = ListNode()
    tail = dummy
    while l1 and l2:
        if l1.val <= l2.val:        # <= keeps it stable
            tail.next = l1; l1 = l1.next
        else:
            tail.next = l2; l2 = l2.next
        tail = tail.next
    tail.next = l1 or l2            # attach whatever remains
    return dummy.next

assert to_list(merge_two(build([1, 2, 4]), build([1, 3, 4]))) == [1, 1, 2, 3, 4, 4]
assert to_list(merge_two(build([]), build([]))) == []
assert to_list(merge_two(build([]), build([0]))) == [0]
print("lc21 ok")

Time O(n + m) · Auxiliary space O(1) (nodes reused; recursion would cost O(n+m) stack) · Mutation relinks inputs. Common mistakes: forgetting the leftover tail; building a new list when reuse is expected. Follow-up: merge k lists (problem 13). Narration: "Dummy head, take the smaller front each time, then attach the leftover in one step."

3 LC 141Linked List Cycle EasyCanonical Pattern 5 · Floyd's tortoise and hare

Summary. Return whether the list contains a cycle. LeetCode 141 ↗ · ~15 min.

Clarify: can I use O(1) space (vs a visited set)? (Yes — Floyd.) May I mutate nodes? (No need to.)

Hint 1
A visited set works but costs O(n) memory. Can two pointers at different speeds detect a loop?
Hint 2
If a cycle exists, a 2× pointer eventually laps and meets the 1× pointer.

Approach Invariant: in a cycle, each step the fast pointer closes the gap to the slow pointer by one, so they must meet; with no cycle, fast reaches the end. Dry run: on 3→2→0→-4→(back to 2), slow and fast meet inside the loop.

lc141.py
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:        # identity, not value
            return True
    return False

# build a cycle: tail links back to node index 1
h = build([3, 2, 0, -4])
nodes = []
cur = h
while cur:
    nodes.append(cur); cur = cur.next
nodes[-1].next = nodes[1]
assert has_cycle(h) is True
assert has_cycle(build([1, 2])) is False
assert has_cycle(build([])) is False
print("lc141 ok")

Time O(n) · Auxiliary space O(1) (vs O(n) for a visited set — the memory win) · Mutation none. Common mistakes: comparing .val instead of node identity (is); missing the fast.next guard (crashes at the end). Narration: "Tortoise and hare — if the hare laps the tortoise there's a loop; otherwise it runs off the end."

4 LC 142Linked List Cycle II MediumCanonical Pattern 5 · Find the node where the cycle begins

Summary. Return the node where the cycle starts, or None. LeetCode 142 ↗ · ~25 min.

Hint 1
First detect the meeting point with Floyd, as in problem 3.
Hint 2
From the meeting point, the distance to the cycle entry equals the distance from the head to the entry. Walk two pointers one step at a time from head and from the meeting point.

Approach Why it works: let the head-to-entry distance be a and the meeting point be b into the loop of length c. Floyd's math gives a ≡ (c − b) (mod c), so a pointer from the head and a pointer from the meeting point, each moving one step, collide exactly at the entry. Invariant: both walkers are equidistant (mod c) from the entry.

lc142.py
def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:                 # meeting point inside the loop
            p = head
            while p is not slow:         # both advance one step
                p = p.next
                slow = slow.next
            return p                      # the cycle entry
    return None

h = build([3, 2, 0, -4])
nodes = []
cur = h
while cur:
    nodes.append(cur); cur = cur.next
nodes[-1].next = nodes[1]
assert detect_cycle(h) is nodes[1]
assert detect_cycle(build([1, 2])) is None
print("lc142 ok")

Time O(n) · Auxiliary space O(1) · Mutation none. Common mistakes: restarting both pointers from the head (only one restarts); returning the meeting point instead of the entry. Narration: "Detect the meeting point, then the head-distance equals the entry-distance, so two one-step walkers meet at the start of the loop."

5 LC 19Remove Nth Node From End of List MediumCanonical Patterns 1 + 6 · Dummy head + a fixed-gap one pass

Summary. Remove the n-th node from the end and return the head. LeetCode 19 ↗ · ~20 min.

Clarify: is n valid (1 ≤ n ≤ length)? Can we do it in one pass? (Yes.) The head itself may be removed — so use a dummy.

Hint 1
If fast is n nodes ahead of slow, when fast hits the end slow sits just before the target.
Hint 2
Start both at a dummy so removing the head is not a special case.

Approach Invariant: fast leads slow by exactly n links. Advance both until fast.next is None; then slow.next is the node to unlink. The dummy makes head-removal uniform.

lc19.py
def remove_nth(head, n):
    dummy = ListNode(0, head)
    fast = slow = dummy
    for _ in range(n):        # open a gap of n
        fast = fast.next
    while fast.next:          # move both until fast is last
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next  # unlink the target
    return dummy.next

assert to_list(remove_nth(build([1, 2, 3, 4, 5]), 2)) == [1, 2, 3, 5]
assert to_list(remove_nth(build([1]), 1)) == []          # remove only node
assert to_list(remove_nth(build([1, 2]), 2)) == [2]      # remove head
print("lc19 ok")

Time O(n) single pass · Auxiliary space O(1) · Mutation one unlink. Common mistakes: not using a dummy (head removal breaks); an off-by-one in the gap. Narration: "Open an n-node gap, slide both to the end, and the trailing pointer lands right before the node to drop."

6 LC 143Reorder List MediumCanonical Patterns 2 + 3 + 4 · Midpoint, reverse the tail, interleave

Summary. Reorder L0→L1→…→Ln into L0→Ln→L1→Ln-1→… in place. LeetCode 143 ↗ · ~25 min.

Hint 1
This is three known moves in sequence — split at the middle, reverse the second half, then zip the two halves together.

Approach Composition: (1) fast/slow to find the midpoint and cut; (2) reverse the second half; (3) merge the two halves alternately. Each step is O(n) and O(1) space. Invariant of the zip: at each step you attach the next node of the reversed tail between two front nodes.

lc143.py
def reorder(head):
    if not head or not head.next:
        return head
    # 1) midpoint (slow ends at end of first half)
    slow = fast = head
    while fast.next and fast.next.next:
        slow = slow.next
        fast = fast.next.next
    second = slow.next
    slow.next = None
    # 2) reverse the second half
    prev = None
    while second:
        nxt = second.next
        second.next = prev
        prev = second
        second = nxt
    # 3) interleave the two halves
    first, second = head, prev
    while second:
        f_next, s_next = first.next, second.next
        first.next = second
        second.next = f_next
        first, second = f_next, s_next
    return head

assert to_list(reorder(build([1, 2, 3, 4]))) == [1, 4, 2, 3]
assert to_list(reorder(build([1, 2, 3, 4, 5]))) == [1, 5, 2, 4, 3]
assert to_list(reorder(build([1]))) == [1]
print("lc143 ok")

Time O(n) · Auxiliary space O(1) · Mutation extensive rewiring. Common mistakes: not cutting the first half (slow.next = None) creates a cycle; picking the wrong midpoint on even lengths. Narration: "Find the middle, reverse the back, then zip front and back together."

7 LC 2Add Two Numbers MediumCanonical Pattern 1 · Dummy head with a running carry

Summary. Two numbers are stored as digit lists in reverse order; return their sum as a list. LeetCode 2 ↗ · ~20 min.

Clarify: digits least-significant first? (Yes — convenient.) Lists of different lengths? (Yes.) Final carry can add a node.

Hint 1
Add digit by digit like grade-school addition, carrying to the next place.
Hint 2
Loop while either list has digits or a carry remains.

Approach Invariant: after processing place i, carry holds the overflow into place i+1. divmod(sum, 10) splits digit and carry cleanly. The loop condition l1 or l2 or carry handles unequal lengths and a trailing carry in one place.

lc2.py
def add_two(l1, l2):
    dummy = ListNode()
    cur = dummy
    carry = 0
    while l1 or l2 or carry:
        s = carry
        if l1:
            s += l1.val; l1 = l1.next
        if l2:
            s += l2.val; l2 = l2.next
        carry, digit = divmod(s, 10)
        cur.next = ListNode(digit)
        cur = cur.next
    return dummy.next

assert to_list(add_two(build([2, 4, 3]), build([5, 6, 4]))) == [7, 0, 8]   # 342+465=807
assert to_list(add_two(build([9, 9]), build([1]))) == [0, 0, 1]            # 99+1=100
assert to_list(add_two(build([0]), build([0]))) == [0]
print("lc2 ok")

Time O(max(n, m)) · Auxiliary space O(1) beyond the output list · Mutation none of the inputs. Common mistakes: dropping the final carry; stopping when one list ends. Follow-up: digits stored most-significant first (LC 445 — reverse or use a stack). Narration: "Schoolbook addition with a carry; loop while any digit or carry remains."

8 LC 138Copy List with Random Pointer MediumCanonical Pattern 7 · Interleave clones for O(1) extra space

Summary. Deep-copy a list where each node has an extra random pointer to any node or null. LeetCode 138 ↗ · ~25 min.

Clarify: is O(1) extra space required (vs a hash map original→copy)? Both approaches are worth stating.

Hint 1
A hash map from original node to its copy makes random pointers trivial — O(n) space.
Hint 2
To avoid the map, weave each copy right after its original, wire randoms from that adjacency, then unzip.

Approach Three passes. (1) Insert copy after each original. (2) Set copy.random = original.random.next — the copy of the target sits right after it. (3) Detach the copies to restore both lists. Invariant: a node's copy is always its immediate successor during passes 1–2.

lc138.py
class Node:
    def __init__(self, x, next=None, random=None):
        self.val = x; self.next = next; self.random = random

def copy_random(head):
    if not head:
        return None
    cur = head                       # 1) weave copies in
    while cur:
        cur.next = Node(cur.val, cur.next)
        cur = cur.next.next
    cur = head                       # 2) wire random pointers
    while cur:
        if cur.random:
            cur.next.random = cur.random.next
        cur = cur.next.next
    cur = head                       # 3) unzip original / copy
    copy_head = head.next
    while cur:
        nxt = cur.next
        cur.next = nxt.next
        if nxt.next:
            nxt.next = nxt.next.next
        cur = cur.next
    return copy_head

a = Node(1); b = Node(2); a.next = b; a.random = b; b.random = b
cp = copy_random(a)
assert cp.val == 1 and cp.next.val == 2
assert cp.random is cp.next and cp.next.random is cp.next   # deep, not aliased
assert cp is not a and cp.next is not b
assert copy_random(None) is None
print("lc138 ok")

Time O(n) · Auxiliary space O(1) interleave (vs O(n) hash-map version — state both) · Mutation temporarily interleaves then restores. Common mistakes: not restoring the original list; mishandling a null random. Narration: "Clone each node right behind its original so random pointers are one hop away, then unzip."

9 LC 160Intersection of Two Linked Lists EasyCanonical Pattern 2 · Two-pointer length equaliser

Summary. Return the node where two lists merge, or None. LeetCode 160 ↗ · ~20 min.

Hint 1
The tails are shared; only the prefixes differ in length.
Hint 2
Redirect each pointer to the other list's head when it ends — both then travel len(a)+len(b) and align at the intersection.

Approach Invariant: after switching heads once, both pointers have walked the same total distance, so they arrive at the intersection simultaneously (or both reach None). No length counting, O(1) space.

lc160.py
def get_intersection(a, b):
    if not a or not b:
        return None
    pa, pb = a, b
    while pa is not pb:
        pa = pa.next if pa else b     # switch to the other head at the end
        pb = pb.next if pb else a
    return pa                          # the shared node, or None

common = build([8, 4, 5])
la, lb = build([4, 1]), build([5, 6, 1])
for lst in (la, lb):
    cur = lst
    while cur.next:
        cur = cur.next
    cur.next = common
assert get_intersection(la, lb) is common
assert get_intersection(build([2, 6, 4]), build([1, 5])) is None
print("lc160 ok")

Time O(n + m) · Auxiliary space O(1) (vs O(n) visited-set) · Mutation none. Common mistakes: switching to the current head instead of the other list's; comparing values not identity. Narration: "Each pointer walks its list then the other's, so they cover equal distance and meet at the join."

10 LC 234Palindrome Linked List EasyCanonical Patterns 2 + 3 · Midpoint, reverse half, compare

Summary. Return whether the list reads the same forwards and backwards. LeetCode 234 ↗ · Secondary: two pointers · ~20 min.

Hint 1
Copying to a list and using two pointers is O(n) space. Can you do O(1)?
Hint 2
Reverse the second half in place, then compare it against the first half.

Approach Find the midpoint with fast/slow, reverse from the midpoint, then walk the first half and the reversed second half in lock-step. Invariant: equal values at mirrored positions ⇒ palindrome. (An interview-clean variant restores the list afterward; note it if asked.)

lc234.py
def is_palindrome(head):
    slow = fast = head
    while fast and fast.next:         # slow reaches the middle
        slow = slow.next
        fast = fast.next.next
    prev = None                        # reverse the second half
    while slow:
        nxt = slow.next
        slow.next = prev
        prev = slow
        slow = nxt
    left, right = head, prev           # compare halves
    while right:
        if left.val != right.val:
            return False
        left = left.next
        right = right.next
    return True

assert is_palindrome(build([1, 2, 2, 1])) is True   # even
assert is_palindrome(build([1, 2, 3, 2, 1])) is True # odd
assert is_palindrome(build([1, 2])) is False
assert is_palindrome(build([1])) is True
print("lc234 ok")

Time O(n) · Auxiliary space O(1) (vs O(n) copy-to-array) · Mutation reverses the second half (restore it if the caller reuses the list). Common mistakes: mishandling odd length (the middle node is ignored by comparing only while right exists). Narration: "Middle, reverse the back half, then walk both halves inward comparing values."

11 LC 82Remove Duplicates from Sorted List II MediumCanonical Pattern 1 · Dummy head, skip whole runs

Summary. In a sorted list, delete every node that has a duplicate, keeping only distinct values. LeetCode 82 ↗ · ~25 min.

Clarify: keep one copy, or remove all duplicated values entirely? (Remove entirely — that's the "II" twist.) Head may be a duplicate ⇒ dummy.

Hint 1
When you see a value repeated, skip the entire run, not just the extra copies.
Hint 2
Keep prev at the last confirmed-unique node; point it past the whole duplicated run.

Approach Invariant: prev is the last node guaranteed unique so far; cur scans ahead. If cur begins a run of equals, advance cur past all of them and set prev.next = cur to excise the run; otherwise move prev forward.

lc82.py
def delete_duplicates(head):
    dummy = ListNode(0, head)
    prev = dummy
    cur = head
    while cur:
        if cur.next and cur.val == cur.next.val:
            v = cur.val
            while cur and cur.val == v:   # skip the whole run
                cur = cur.next
            prev.next = cur               # excise it
        else:
            prev = cur
            cur = cur.next
    return dummy.next

assert to_list(delete_duplicates(build([1, 2, 3, 3, 4, 4, 5]))) == [1, 2, 5]
assert to_list(delete_duplicates(build([1, 1, 1, 2, 3]))) == [2, 3]   # head dup
assert to_list(delete_duplicates(build([1, 1]))) == []
print("lc82 ok")

Time O(n) · Auxiliary space O(1) · Mutation unlinks runs. Common mistakes: keeping one copy (that's LC 83, not II); not using a dummy when the head is duplicated. Narration: "prev is the last safe node; whenever a value repeats I jump prev past the entire run."

12 LC 148Sort List MediumCanonical Pattern 9 · Merge sort on a linked list

Summary. Sort the list in O(n log n) time. LeetCode 148 ↗ · Secondary: sorting (Ch 09) · ~30 min.

Clarify: constant extra space beyond recursion? (Merge sort is the natural fit; quicksort is unstable and awkward on lists.)

Hint 1
Merge sort suits linked lists: splitting and merging are pure pointer work, no shifting.
Hint 2
Split at the midpoint (fast/slow), sort each half recursively, then reuse the merge-two-lists routine.

Approach Classic divide and conquer. Find the midpoint, cut, recurse on both halves, and merge. Invariant: each recursive call returns a fully sorted sublist. Note on space: arrays merge in O(n) auxiliary; on a list the merge is O(1) extra, but the recursion stack is O(log n).

lc148.py
def sort_list(head):
    if not head or not head.next:
        return head
    slow, fast = head, head.next        # split into two halves
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    mid = slow.next
    slow.next = None
    left = sort_list(head)
    right = sort_list(mid)
    return merge_two(left, right)        # reuse problem 2's merge

assert to_list(sort_list(build([4, 2, 1, 3]))) == [1, 2, 3, 4]
assert to_list(sort_list(build([-1, 5, 3, 4, 0]))) == [-1, 0, 3, 4, 5]
assert to_list(sort_list(build([]))) == []
print("lc148 ok")

Time O(n log n) · Auxiliary space O(log n) recursion stack (O(1) merge work) · Mutation relinks in place. Common mistakes: using slow = head (not head.next) — can loop forever on length 2; forgetting to cut with slow.next = None. Narration: "Merge sort — split at the middle, sort halves, merge; pointers only, so no element shifting."

13 LC 23Merge k Sorted Lists HardCanonical Pattern 8 · Min-heap over the k list fronts

Summary. Merge k sorted lists into one sorted list. LeetCode 23 ↗ · Secondary: heaps (Ch 13) · ~30 min.

Clarify: can lists be empty or the input list of lists empty? (Yes.) How large is k vs total N?

Hint 1
Repeatedly pick the smallest current front across the k lists.
Hint 2
A min-heap of size k gives the smallest front in O(log k); push the popped node's successor.

Approach Push the head of each non-empty list into a heap keyed by value (with a tiebreak index so nodes never compare). Pop the smallest, append it, and push its next. Invariant: the heap always holds the current front of every list that still has nodes. Total N pops × O(log k) = O(N log k).

lc23.py
import heapq

def merge_k(lists):
    h = []
    for i, node in enumerate(lists):
        if node:
            heapq.heappush(h, (node.val, i, node))   # i breaks ties on equal vals
    dummy = ListNode()
    tail = dummy
    while h:
        val, i, node = heapq.heappop(h)
        tail.next = node
        tail = node
        if node.next:
            heapq.heappush(h, (node.next.val, i, node.next))
    tail.next = None
    return dummy.next

assert to_list(merge_k([build([1,4,5]), build([1,3,4]), build([2,6])])) == [1,1,2,3,4,4,5,6]
assert to_list(merge_k([])) == []
assert to_list(merge_k([build([])])) == []
print("lc23 ok")

Time O(N log k) · Auxiliary space O(k) for the heap · Mutation relinks nodes. Common mistakes: comparing ListNode objects (crashes) — always carry a tiebreaker index; forgetting to null-terminate tail. Follow-up: divide-and-conquer pairwise merge, same O(N log k) without a heap. Narration: "A size-k heap always holds each list's front; pop the smallest and push its successor."

14 LC 25Reverse Nodes in k-Group HardCanonical Pattern 3 · Segmented reversal with a group anchor

Summary. Reverse the list in groups of k; a trailing group smaller than k stays as-is. LeetCode 25 ↗ · ~35 min.

Hint 1
Reversal you know; the work is stitching each reversed block to its neighbours.
Hint 2
Keep a group_prev anchor; find the k-th node; if fewer than k remain, stop.

Approach For each group, walk k nodes to find kth (stop if the list runs out). Reverse the block [group_prev.next .. kth] so it points at group_next = kth.next. Re-attach: group_prev.next becomes kth, and the old block head becomes the next group_prev. Invariant: everything before group_prev is finalised.

lc25.py
def reverse_k_group(head, k):
    dummy = ListNode(0, head)
    group_prev = dummy
    while True:
        kth = group_prev                    # find the k-th node of this group
        for _ in range(k):
            kth = kth.next
            if not kth:
                return dummy.next            # fewer than k remain -> done
        group_next = kth.next
        # reverse [group_prev.next .. kth]
        prev, cur = group_next, group_prev.next
        while cur is not group_next:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt
        # re-stitch and advance the anchor
        tmp = group_prev.next
        group_prev.next = kth
        group_prev = tmp

assert to_list(reverse_k_group(build([1,2,3,4,5]), 2)) == [2,1,4,3,5]
assert to_list(reverse_k_group(build([1,2,3,4,5]), 3)) == [3,2,1,4,5]
assert to_list(reverse_k_group(build([1,2,3,4,5]), 1)) == [1,2,3,4,5]
print("lc25 ok")

Time O(n) · Auxiliary space O(1) iterative · Mutation heavy rewiring. Common mistakes: reversing the final short group (it must stay); losing the anchor when re-stitching. Narration: "Anchor before each group; if k nodes exist, reverse the block and reconnect, else leave the tail alone."

15 LC 146LRU Cache MediumCross-ref → Design Full editorial lives in Chapter 21 — Data Structure Design
🔗
Canonical write-up: Chapter 21 — Data Structure Design. The full editorial builds the doubly-linked-list-plus-hash-map from scratch. LeetCode 146 ↗

Linked-list lens. This is why doubly linked lists exist in interviews. A hash map gives O(1) lookup key → node; a doubly linked list orders nodes by recency so you can move a node to the front and evict from the back in O(1) (a singly linked list cannot unlink in O(1) because it can't reach the predecessor). In Python you can prototype it with collections.OrderedDict and move_to_end / popitem(last=False), but be ready to hand-build the doubly linked list when asked.

lc146_prototype.py
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()          # ordered by recency

    def get(self, key):
        if key not in self.d:
            return -1
        self.d.move_to_end(key)         # mark most-recent
        return self.d[key]

    def put(self, key, value):
        if key in self.d:
            self.d.move_to_end(key)
        self.d[key] = value
        if len(self.d) > self.cap:
            self.d.popitem(last=False)  # evict least-recent

c = LRUCache(2)
c.put(1, 1); c.put(2, 2)
assert c.get(1) == 1
c.put(3, 3)                 # evicts key 2
assert c.get(2) == -1
c.put(4, 4)                 # evicts key 1
assert c.get(1) == -1 and c.get(3) == 3 and c.get(4) == 4
print("lc146 prototype ok")

4 · Interview playbook

  • Before any rewiring: save node.next. Draw three nodes and move one arrow at a time.
  • Use a dummy head whenever the head might be removed or replaced (LC 19, 21, 82, 25).
  • State the invariant: "everything before cur is reversed", "fast leads slow by n", "tail points at the smaller frontier".
  • Cycle safety: compare node identity with is, guard fast.next before fast.next.next, and null-terminate any list you split.
  • Edge cases: empty list, one node, two nodes, odd vs even length, head/tail change, and (for detection problems) a cycle.
  • Recursion caution: a 10⁵-node list overflows the default recursion limit — prefer iterative reversal and merges.

6 · Review

Cheat sheet
  • Reversal move: nxt = cur.next; cur.next = prev; prev = cur; cur = nxt.
  • Dummy head when the head can change: dummy = ListNode(0, head).
  • Midpoint / cycle / kth-from-end → fast & slow pointers.
  • Cycle start → Floyd, then walk from head and meeting point together.
  • Two lists intersect → switch heads to equalise length.
  • Sort a list → merge sort (split, sort, merge).
  • Merge k lists → min-heap with a tiebreaker index.
  • O(1) recency cache → doubly linked list + hash map (LRU).

Concept checks

Why do we compare pointers with is (not ==) in cycle detection?
Two different nodes can hold equal values; a cycle means the same object is revisited, which is identity
Because == is slower
Because values might be None
A cycle is defined by node identity — the fast pointer must land on the exact same object the slow pointer is on. Value equality could give false positives on lists with repeated values.
You are asked to reverse a 200,000-node list. Which reversal do you write and why?
Iterative — recursion would exceed Python's ~1000-frame limit and raise RecursionError
Recursive — it is shorter
Either; they behave identically
Recursive reversal uses O(n) stack frames; at 200k nodes that overflows the default limit. Iterative reversal is O(1) auxiliary space and safe.
