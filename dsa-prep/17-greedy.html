Greedy

A greedy algorithm builds a solution by always taking the locally best move — and the whole art is knowing when that's safe. This chapter teaches the recurring greedy families (sort-and-match, interval scheduling, reachability, exchange arguments, and heap/stack greedies) and, crucially, the argument that justifies each one. Every problem has a full, tested solution in LeetCode's class Solution format.

Outcome

Recognise when a greedy choice is provably safe, pick the right ordering (by end time, by cost difference, by frequency), and implement interval scheduling, jump/reachability, exchange-argument, and heap/monotonic-stack greedies with confidence.

1 · Foundations

Read top to bottom — the mindset section is what separates a correct greedy from a plausible-but-wrong one. Already fluent? Skip to §2 Pattern library.

What is a greedy algorithm — and when is it safe?

A greedy algorithm makes the choice that looks best right now and never reconsiders it. That's fast and simple, but only correct when the problem has the greedy-choice property: a locally optimal choice is part of some globally optimal solution. When it holds, greedy beats dynamic programming on both speed and code size; when it doesn't, greedy silently returns wrong answers.

Before trusting a greedy, find its justification. Usually it's an exchange argument: show that any optimal solution can be transformed into the greedy one without getting worse. If you can't sketch that argument, reach for DP instead.

Greedy isn't always right: a cautionary example

To make change for 6 with coins {1, 3, 4}, the greedy "take the largest coin ≤ remaining" gives 4 + 1 + 1 = 3 coins, but the optimum is 3 + 3 = 2 coins. Greedy fails here because no exchange argument holds. Contrast that with sorting-based greedies (below), where one does.

Example — a correct greedy: maximise non-overlapping intervals
intervals.py
def max_meetings(intervals):
    intervals.sort(key=lambda x: x[1])     # sort by END time
    count, last_end = 0, float("-inf")
    for start, end in intervals:
        if start >= last_end:              # doesn't overlap the last kept one
            count += 1
            last_end = end
    return count

print(max_meetings([(0, 3), (1, 2), (3, 5), (2, 4)]))   # 2
Output2

Keeping the earliest-finishing interval leaves the most room for the rest — provable by an exchange argument. Sorting by start time, by contrast, is wrong.

The heart of most greedies: choosing the sort key

A huge fraction of greedy problems reduce to sort by the right key, then sweep. The skill is picking that key: by end time (interval scheduling), by cost difference (two-city scheduling), by value density (units on a truck), or by frequency (task scheduling). Once sorted, a single linear pass usually finishes the job.

When sorting isn't enough: heaps and stacks

Some greedies need to revise a decision as new information arrives. A heap lets you retroactively pick or drop the best/worst item chosen so far — "take every course, then evict the longest when you overrun" (Course Schedule III), or "refuel from the biggest station passed" (Refueling Stops). A monotonic stack builds the lexicographically best subsequence by popping now-suboptimal earlier choices (Remove K Digits). And a running balance with a reset handles circular problems like Gas Station.

⚠️
Greedy pitfalls

Don't assume greedy works because it passes small examples — construct a potential counterexample or prove an exchange argument. Sort by the right key (end time, not start, for scheduling). Watch tie-breaking (Queue Reconstruction needs a specific one). And when two constraints pull in opposite directions (Candy), a single pass usually can't satisfy both — use one pass per direction.

1 LC 455Assign Cookies Easy Sort both · two pointers

Problem. Each child has a greed factor and each cookie a size; a child is content if a cookie's size ≥ their greed. Maximise the number of content children. LeetCode 455 ↗

Clarify: Each child gets at most one cookie? (Yes.) Reuse cookies? (No.)

Hint 1
Sort both children and cookies ascending.
Hint 2
Give the smallest sufficient cookie to the least greedy remaining child.

How to think about it The exchange argument: satisfy the least-greedy child with the smallest cookie that works, never wasting a big cookie on a small need. Sort both arrays and walk two pointers — advance the child pointer whenever the current cookie satisfies them, always advancing the cookie pointer.

assign_cookies.py
from typing import List

class Solution:
    def findContentChildren(self, g, s):
        g.sort()
        s.sort()
        i = j = 0
        while i < len(g) and j < len(s):
            if s[j] >= g[i]:                 # this cookie satisfies child i
                i += 1
            j += 1
        return i

Time O(n log n) · Space O(1). The template greedy: sort, then match smallest-to-smallest with two pointers.

2 LC 122Best Time to Buy and Sell Stock II Easy Sum every upward step

Problem. You may buy and sell as many times as you like (one share at a time). Return the maximum profit. LeetCode 122 ↗

Clarify: Unlimited transactions, but hold at most one share? (Yes.) Same-day buy/sell allowed? (Yes.)

Hint 1
Any multi-day gain is the sum of the daily gains within it.
Hint 2
So capture every day where the price rises versus the day before.

How to think about it A rising run from a valley to a peak has profit equal to the sum of its consecutive daily increases. So you can greedily add every positive day-over-day difference — it's equivalent to buying at each valley and selling at each peak, without needing to find them explicitly.

stock_ii.py
from typing import List

class Solution:
    def maxProfit(self, prices):
        return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, len(prices)))

Time O(n) · Space O(1). 'Grab every uptick' works because a big climb decomposes into its daily gains.

3 LC 605Can Place Flowers Easy Plant greedily where legal

Problem. Flowers can't be planted in adjacent plots. Given a bed (some plots taken), can you plant n new flowers? LeetCode 605 ↗

Clarify: No two adjacent flowers, ever? (Yes.) Count the maximum you can add? (Yes.)

Hint 1
Scan left to right; plant whenever a plot and both neighbours are empty.
Hint 2
Padding the bed with empty sentinels removes the first/last edge cases.

How to think about it Greedily plant at the earliest legal spot: a plot is plantable when it and both neighbours are empty. Planting as early as possible never blocks a later opportunity, so a single left-to-right pass gives the maximum. Sentinel zeros at both ends handle the boundary plots uniformly.

can_place_flowers.py
from typing import List

class Solution:
    def canPlaceFlowers(self, flowerbed, n):
        bed = [0] + flowerbed + [0]          # sentinels remove edge cases
        planted = 0
        for i in range(1, len(bed) - 1):
            if bed[i - 1] == 0 == bed[i] == bed[i + 1]:
                bed[i] = 1
                planted += 1
        return planted >= n

Time O(n) · Space O(n). Earliest-legal placement is a common greedy that provably reaches the maximum.

4 LC 860Lemonade Change Easy Prefer larger bills for change

Problem. Customers pay with $5, $10, or $20 for a $5 lemonade. Can you give every customer correct change, starting with none? LeetCode 860 ↗

Clarify: Give exact change each time? (Yes.) Start with no bills? (Yes.)

Hint 1
Track how many $5 and $10 bills you hold.
Hint 2
For a $20, prefer giving a $10 + $5 over three $5s — keep small bills for flexibility.

How to think about it Track your $5 and $10 counts. A $10 needs one $5; a $20 needs $15 — greedily hand back a $10 + $5 if you can, since $5s are more flexible and better hoarded. Only fall back to three $5s. If you ever can't make change, it's impossible.

lemonade_change.py
from typing import List

class Solution:
    def lemonadeChange(self, bills):
        five = ten = 0
        for b in bills:
            if b == 5:
                five += 1
            elif b == 10:
                if five == 0:
                    return False
                five -= 1
                ten += 1
            else:                            # $20: prefer a $10 + $5 over three $5s
                if ten > 0 and five > 0:
                    ten -= 1
                    five -= 1
                elif five >= 3:
                    five -= 3
                else:
                    return False
        return True

Time O(n) · Space O(1). Spending the least-flexible (largest) bills first is the greedy insight.

5 LC 1005Maximize Sum After K Negations Easy Flip the most negative first

Problem. Negate exactly k elements (repeats allowed). Return the maximum possible array sum. LeetCode 1005 ↗

Clarify: You must perform exactly k negations? (Yes.) An element may be negated more than once? (Yes.)

Hint 1
Flip the most negative numbers first — each such flip adds the most.
Hint 2
If flips remain after all negatives are gone, wasting them on the smallest magnitude costs the least (and an even count cancels out).

How to think about it Sort ascending and flip the most negative values while flips remain — each turns a big negative into a big positive. If flips are left once everything is non-negative, an even count is harmless; an odd count must flip the smallest-magnitude element once, so subtract twice the current minimum.

k_negations.py
from typing import List

class Solution:
    def largestSumAfterKNegations(self, nums, k):
        nums.sort()
        for i in range(len(nums)):
            if k > 0 and nums[i] < 0:        # flip the most negative values first
                nums[i] = -nums[i]
                k -= 1
        # any leftover flips: an odd number wastes on the smallest element
        return sum(nums) - (2 * min(nums) if k % 2 == 1 else 0)

Time O(n log n) · Space O(1). Spend each negation where it gains most; dump the unavoidable leftover on the smallest element.

6 LC 1710Maximum Units on a Truck Easy Load densest boxes first

Problem. Boxes come in types (count, units-per-box). Load at most truckSize boxes to maximise total units. LeetCode 1710 ↗

Clarify: Load whole boxes up to the size limit? (Yes.) Maximise total units, not boxes? (Yes.)

Hint 1
Every box occupies the same space, so prefer boxes carrying more units.
Hint 2
Sort box types by units descending and fill greedily.

How to think about it Since each box takes one slot regardless of type, the value per slot is its unit count — so load the highest-unit boxes first. Sort types by units descending and take as many of each as fit until the truck is full.

max_units.py
from typing import List

class Solution:
    def maximumUnits(self, boxTypes, truckSize):
        boxTypes.sort(key=lambda b: -b[1])   # densest boxes first
        total = 0
        for count, units in boxTypes:
            take = min(count, truckSize)
            total += take * units
            truckSize -= take
            if truckSize == 0:
                break
        return total

Time O(n log n) · Space O(1). Equal-cost items ⇒ take highest-value first, a fractional-knapsack-style greedy.

7 LC 976Largest Perimeter Triangle Easy Sort · check the top triple

Problem. Return the largest perimeter of a valid triangle formed from three of the given lengths, or 0 if none exists. LeetCode 976 ↗

Clarify: A valid triangle needs the two smaller sides to exceed the largest? (Yes.)

Hint 1
Sort descending; a valid triangle needs the largest side < sum of the other two.
Hint 2
The first consecutive triple that satisfies this gives the largest perimeter.

How to think about it Sort descending and test consecutive triples. For the largest possible perimeter you want the biggest sides, and if the top three don't form a triangle (largest ≥ other two combined), no triple involving that largest side can — so slide down. The first valid consecutive triple is optimal.

largest_perimeter.py
from typing import List

class Solution:
    def largestPerimeter(self, nums):
        nums.sort(reverse=True)
        for i in range(len(nums) - 2):       # check the largest valid triple
            if nums[i] < nums[i + 1] + nums[i + 2]:
                return nums[i] + nums[i + 1] + nums[i + 2]
        return 0

Time O(n log n) · Space O(1). Sorting lets you check only adjacent triples instead of all O(n³) combinations.

8 LC 55Jump Game Medium Track the farthest reach

Problem. Each value is the maximum jump length from that index. Determine whether you can reach the last index from index 0. LeetCode 55 ↗

Clarify: Jump any distance up to nums[i] from index i? (Yes.) Reach the final index? (Yes.)

Hint 1
Track the farthest index reachable so far.
Hint 2
If you ever stand on an index beyond that reach, you're stuck.

How to think about it Sweep left to right maintaining the farthest index reachable. At each index, if it lies beyond the current reach you can never have arrived, so fail. Otherwise extend the reach by i + nums[i]. Surviving to the end means the last index is reachable.

jump_game.py
from typing import List

class Solution:
    def canJump(self, nums):
        reach = 0
        for i, n in enumerate(nums):
            if i > reach:                    # a gap we can't cross
                return False
            reach = max(reach, i + n)
        return True

Time O(n) · Space O(1). A single 'farthest reach' variable replaces any search — the essence of reachability greedy.

9 LC 45Jump Game II Medium BFS-by-layers · minimum jumps

Problem. Return the minimum number of jumps to reach the last index (a solution is guaranteed). LeetCode 45 ↗

Clarify: Always reachable? (Yes.) Minimise the jump count? (Yes.)

Hint 1
Think of it as BFS in layers: each jump covers a range of reachable indices.
Hint 2
Only increment the jump count when you exhaust the current range and must extend.

How to think about it Implicit BFS by layers. Track the end of the current jump's reach and the farthest index seen. As you scan, keep extending the farthest reach; when you hit the current range's end you're forced to jump, so increment the count and move the boundary out to the farthest reach. This counts the minimum jumps in one pass.

jump_game_ii.py
from typing import List

class Solution:
    def jump(self, nums):
        jumps = cur_end = farthest = 0
        for i in range(len(nums) - 1):
            farthest = max(farthest, i + nums[i])
            if i == cur_end:                 # must jump; extend to the best reach
                jumps += 1
                cur_end = farthest
        return jumps

Time O(n) · Space O(1). Counting a jump only at each range boundary turns layered BFS into an O(n) greedy.

10 LC 435Non-overlapping Intervals Medium Interval scheduling · sort by end

Problem. Return the minimum number of intervals to remove so the rest don't overlap. LeetCode 435 ↗

Clarify: Intervals sharing only an endpoint don't overlap? (Yes.) Remove the fewest? (Yes.)

Hint 1
Keep as many as possible by always keeping the interval that finishes earliest.
Hint 2
Sort by end time; drop any interval starting before the last kept one ends.

How to think about it This is the classic interval-scheduling greedy: to keep the most non-overlapping intervals, always keep the one that finishes earliest, leaving maximum room for the rest. Sort by end time; step through, keeping an interval when it starts at/after the last kept end, and counting a removal otherwise.

non_overlapping.py
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals):
        intervals.sort(key=lambda x: x[1])   # earliest finishing first
        removed = 0
        prev_end = float("-inf")
        for s, e in intervals:
            if s >= prev_end:
                prev_end = e                 # keep it
            else:
                removed += 1                 # overlaps ⇒ drop it
        return removed

Time O(n log n) · Space O(1). 'Sort by end, keep earliest-finishing' is the single most important interval greedy.

11 LC 452Minimum Arrows to Burst Balloons Medium Interval scheduling · shared arrows

Problem. Balloons span horizontal intervals; a vertical arrow bursts all balloons it passes through. Return the minimum arrows to burst all. LeetCode 452 ↗

Clarify: One arrow bursts every balloon whose interval it intersects? (Yes.) Touching endpoints count as overlap? (Yes.)

Hint 1
Sort by end coordinate; shoot an arrow at the end of the first balloon.
Hint 2
That arrow bursts every balloon starting before it; move on to the first balloon it misses.

How to think about it The dual of non-overlapping intervals: sort by end and greedily fire an arrow at the earliest end point, which pops every balloon overlapping it. Advance to the first balloon whose start is beyond that arrow and repeat. Each new arrow marks a group that couldn't be merged with the previous.

min_arrows.py
from typing import List

class Solution:
    def findMinArrowShots(self, points):
        points.sort(key=lambda x: x[1])
        arrows = 0
        end = float("-inf")
        for s, e in points:
            if s > end:                      # current arrow can't reach it
                arrows += 1
                end = e
        return arrows

Time O(n log n) · Space O(1). Same 'sort by end' engine as interval scheduling — here counting groups instead of removals.

12 LC 763Partition Labels Medium Extend to each char's last index

Problem. Partition the string into as many parts as possible so each letter appears in at most one part. Return the part sizes. LeetCode 763 ↗

Clarify: Every occurrence of a letter must stay in one part? (Yes.) Maximise the number of parts? (Yes.)

Hint 1
Record the last index of every character.
Hint 2
Grow the current part until you reach the farthest last-index of any character seen so far.

How to think about it Precompute each character's last position. Sweep the string extending the current part's end to the maximum last-index of any character seen. When the scan index reaches that end, every character inside is fully contained, so close the part and start a new one.

partition_labels.py
from typing import List

class Solution:
    def partitionLabels(self, s):
        last = {c: i for i, c in enumerate(s)}
        res = []
        start = end = 0
        for i, c in enumerate(s):
            end = max(end, last[c])          # stretch to the last use of any seen char
            if i == end:
                res.append(end - start + 1)
                start = i + 1
        return res

Time O(n) · Space O(1) (≤26 letters). Cutting at the point where 'everything seen ends here' is a reach-tracking greedy like Jump Game.

13 LC 134Gas Station Medium Running balance · reset the start

Problem. Around a circular route, gas[i] is fuel at station i and cost[i] the fuel to reach the next. Return a start index to complete the loop, or −1. LeetCode 134 ↗

Clarify: A unique solution exists if any? (Yes.) Tank starts empty? (Yes.)

Hint 1
If total gas < total cost, it's impossible.
Hint 2
If the running tank goes negative at station i, no start in [previous start, i] works — reset the start to i+1.

How to think about it First, if total gas is less than total cost, return −1. Otherwise track a running tank from a candidate start; the moment it dips below zero at station i, no station from the current start through i can be the answer, so reset the start to i+1 and zero the tank. With a feasible total, the last surviving start completes the loop.

gas_station.py
from typing import List

class Solution:
    def canCompleteCircuit(self, gas, cost):
        if sum(gas) < sum(cost):
            return -1                        # impossible overall
        total = start = 0
        for i in range(len(gas)):
            total += gas[i] - cost[i]
            if total < 0:                    # can't reach i+1 from current start
                start = i + 1
                total = 0
        return start

Time O(n) · Space O(1). The reset trick skips every doomed start in one pass instead of retrying each.

14 LC 406Queue Reconstruction by Height Medium Tallest first · insert at k

Problem. Each person is (height, k) where k is how many taller-or-equal people stand ahead. Rebuild the queue. LeetCode 406 ↗

Clarify: k counts people with height ≥ this person's ahead of them? (Yes.) Reconstruct any valid order? (The answer is unique.)

Hint 1
Place the tallest people first; shorter people inserted later won't affect their k counts.
Hint 2
Sort by height descending (ties by k ascending), then insert each person at index k.

How to think about it Insert tallest-first. Sort by height descending, breaking ties by k ascending. Then insert each person at position k: because everyone already placed is at least as tall, exactly k taller-or-equal people precede them, and later-inserted shorter people don't disturb that count.

queue_reconstruction.py
from typing import List

class Solution:
    def reconstructQueue(self, people):
        people.sort(key=lambda p: (-p[0], p[1]))   # tallest first, then by k
        res = []
        for p in people:
            res.insert(p[1], p)              # insert at its k index
        return res

Time O(n²) · Space O(n). Processing in an order where later choices can't invalidate earlier ones is a key greedy design idea.

15 LC 621Task Scheduler Medium Fill the cooldown skeleton

Problem. Identical tasks need a cooldown of n intervals between them. Return the minimum total intervals (including idles) to run all tasks. LeetCode 621 ↗

Clarify: Cooldown n applies only between identical tasks? (Yes.) Idle slots count toward time? (Yes.)

Hint 1
The most frequent task dictates the schedule's skeleton.
Hint 2
Arrange (max_count − 1) blocks of size (n + 1), then append the tasks tied for most frequent.

How to think about it The busiest task forces the structure: place its max_count copies with n gaps, forming (max_count − 1) frames of width (n + 1), then a final group of all tasks sharing that peak frequency. Other tasks fill the gaps. If there are enough tasks to leave no idle slots, the answer is simply the task count — hence the max(...).

task_scheduler.py
from collections import Counter
from typing import List

class Solution:
    def leastInterval(self, tasks, n):
        counts = Counter(tasks)
        max_count = max(counts.values())
        max_freq = sum(1 for v in counts.values() if v == max_count)
        # skeleton of the most frequent task, or just len(tasks) if no idling needed
        return max(len(tasks), (max_count - 1) * (n + 1) + max_freq)

Time O(n) · Space O(1). A closed-form greedy: the schedule length is determined by the most frequent task's skeleton.

16 LC 846Hand of Straights Medium Start runs from the smallest card

Problem. Rearrange the hand into groups of groupSize consecutive cards. Return whether it's possible. LeetCode 846 ↗

Clarify: Every group is exactly groupSize consecutive integers? (Yes.) Use all cards? (Yes.)

Hint 1
The smallest remaining card must start a group.
Hint 2
Count cards; repeatedly consume a run of groupSize starting at the lowest available card.

How to think about it The smallest available card can only be the start of a group, so it forces a run of groupSize consecutive cards. Count occurrences, then for each card in sorted order with leftovers, consume that many of each of the next groupSize values; if any is missing, it's impossible.

hand_of_straights.py
from collections import Counter
from typing import List

class Solution:
    def isNStraightHand(self, hand, groupSize):
        if len(hand) % groupSize != 0:
            return False
        count = Counter(hand)
        for card in sorted(count):
            if count[card] > 0:
                need = count[card]
                for k in range(card, card + groupSize):   # build the run upward
                    if count[k] < need:
                        return False
                    count[k] -= need
        return True

Time O(n log n) · Space O(n). 'The minimum element forces the next move' is a recurring greedy lever.

17 LC 1029Two City Scheduling Medium Sort by the cost difference

Problem. Send 2n people to city A or B (n each). Given each person's cost for both cities, minimise total cost. LeetCode 1029 ↗

Clarify: Exactly n people to each city? (Yes.) Minimise total cost? (Yes.)

Hint 1
Consider the extra cost of sending someone to A instead of B: costA − costB.
Hint 2
Sort by that difference; the n most 'A-favourable' people go to A.

How to think about it Rank people by how much cheaper A is than B (costA − costB). The most A-favourable half go to A and the rest to B — this exchange argument minimises total cost because swapping any A-person for a B-person with a larger difference would only increase it. Sort and split at the midpoint.

two_city_scheduling.py
from typing import List

class Solution:
    def twoCitySchedCost(self, costs):
        # sort by how much cheaper city A is than city B
        costs.sort(key=lambda c: c[0] - c[1])
        n = len(costs) // 2
        return sum(c[0] for c in costs[:n]) + sum(c[1] for c in costs[n:])

Time O(n log n) · Space O(1). Sorting by a relative cost (the difference) is the classic exchange-argument setup.

18 LC 678Valid Parenthesis String Medium Track a range of open counts

Problem. '*' can be '(', ')', or empty. Return whether the string can be a valid parenthesisation. LeetCode 678 ↗

Clarify: Each '*' is independently one of three options? (Yes.) Fully balanced result required? (Yes.)

Hint 1
Track the range [low, high] of possible unmatched '(' counts.
Hint 2
'(' bumps both; ')' drops both; '*' widens the range. Clamp low at 0 and fail if high goes negative.

How to think about it Maintain the possible range of open parentheses. ( raises both bounds, ) lowers both, * widens the range (it could add or remove an open). If high ever goes negative there are too many ), so fail; clamp low at 0 since we can't have negative open count. The string is valid iff low can reach 0 at the end.

valid_paren_string.py
class Solution:
    def checkValidString(self, s):
        low = high = 0                       # range of possible open-paren counts
        for c in s:
            if c == "(":
                low += 1
                high += 1
            elif c == ")":
                low -= 1
                high -= 1
            else:                            # '*' could be '(', ')' or ''
                low -= 1
                high += 1
            if high < 0:                     # too many ')'
                return False
            low = max(low, 0)
        return low == 0

Time O(n) · Space O(1). Tracking a feasible range avoids the exponential blow-up of trying each '*' assignment.

19 LC 738Monotone Increasing Digits Medium Borrow at the first drop

Problem. Return the largest number ≤ n whose digits are monotonically non-decreasing. LeetCode 738 ↗

Clarify: Digits must never decrease left to right? (Yes.) Return the largest such number ≤ n? (Yes.)

Hint 1
Scan right to left; at any place where a digit exceeds the next, decrement it and mark the position.
Hint 2
Set everything after the last such mark to 9.

How to think about it Work right to left. Wherever a digit is greater than the one after it, the number can't be monotone there, so decrement that digit and remember the position — everything to its right should become 9 to stay as large as possible. After the pass, flood the marked suffix with 9s.

monotone_digits.py
class Solution:
    def monotoneIncreasingDigits(self, n):
        digits = list(str(n))
        marker = len(digits)
        for i in range(len(digits) - 1, 0, -1):
            if digits[i - 1] > digits[i]:    # a drop ⇒ borrow and mark
                marker = i
                digits[i - 1] = str(int(digits[i - 1]) - 1)
        for i in range(marker, len(digits)):
            digits[i] = "9"
        return int("".join(digits))

Time O(digits) · Space O(digits). Borrow-and-fill-nines is a digit-DP problem solved greedily in one backward pass.

20 LC 402Remove K Digits Medium Monotonic stack · pop bigger digits

Problem. Remove k digits from a number string to make the smallest possible resulting number. LeetCode 402 ↗

Clarify: Preserve digit order (no rearranging)? (Yes.) Strip leading zeros in the result? (Yes.)

Hint 1
A smaller number wants smaller digits earlier — pop a larger digit before a smaller one that follows.
Hint 2
Use a monotonic non-decreasing stack; if k remains, trim from the end.

How to think about it Build a non-decreasing digit stack: before pushing a digit, pop any larger digit on top while removals remain — a smaller digit earlier makes the number smaller. If k removals are unused at the end (digits were already increasing), trim them from the back. Finally strip leading zeros.

remove_k_digits.py
class Solution:
    def removeKdigits(self, num, k):
        stack = []
        for d in num:
            while k > 0 and stack and stack[-1] > d:   # pop bigger leading digits
                stack.pop()
                k -= 1
            stack.append(d)
        stack = stack[:len(stack) - k] if k else stack  # remove from the end if k left
        return "".join(stack).lstrip("0") or "0"

Time O(n) · Space O(n). The monotonic-stack greedy — 'pop bigger-earlier' — recurs in many 'smallest/largest subsequence' problems.

21 LC 767Reorganize String Medium Heap · always place the most frequent

Problem. Rearrange the string so no two adjacent characters are equal, or return "" if impossible. LeetCode 767 ↗

Clarify: Return any valid arrangement? (Yes.) Empty string if impossible? (Yes.)

Hint 1
Impossible iff some character's count exceeds ⌈n/2⌉.
Hint 2
Repeatedly place the most frequent remaining char, holding it back one step so it isn't placed twice in a row.

How to think about it If any character occurs more than ⌈n/2⌉ times, no valid arrangement exists. Otherwise use a max-heap by remaining count: each step pop the most frequent character, append it, and hold it aside for one turn (reinserting the previous held character) so the same character is never placed consecutively.

reorganize_string.py
import heapq
from collections import Counter

class Solution:
    def reorganizeString(self, s):
        counts = Counter(s)
        if max(counts.values()) > (len(s) + 1) // 2:
            return ""
        heap = [(-v, c) for c, v in counts.items()]
        heapq.heapify(heap)
        res = []
        prev = None
        while heap:
            v, c = heapq.heappop(heap)       # most frequent remaining
            res.append(c)
            if prev:                         # release the one held back last step
                heapq.heappush(heap, prev)
            v += 1
            prev = (v, c) if v < 0 else None
        return "".join(res)

Time O(n log k) · Space O(k). 'Place the most constrained item first, defer its reuse' is the heap-greedy spacing pattern (also Task Scheduler).

22 LC 316Remove Duplicate Letters Medium Monotonic stack · keep it if it recurs

Problem. Remove duplicate letters so every letter appears once and the result is the smallest in lexical order. LeetCode 316 ↗

Clarify: Keep exactly one of each letter? (Yes.) Result must be lexicographically smallest? (Yes.)

Hint 1
Use a stack; before pushing a new letter, pop larger letters that still appear later.
Hint 2
Never pop a letter that has no remaining occurrence, and skip letters already in the stack.

How to think about it A monotonic-stack greedy. Track each letter's last index and which letters are on the stack. For each new letter not already used, pop any larger top letter that still occurs later (it can be re-added), then push the current one. This keeps the stack as lexically small as possible while guaranteeing every letter still appears.

remove_dup_letters.py
class Solution:
    def removeDuplicateLetters(self, s):
        last = {c: i for i, c in enumerate(s)}
        stack = []
        seen = set()
        for i, c in enumerate(s):
            if c in seen:
                continue
            # pop bigger chars that still appear later ⇒ smaller lexical result
            while stack and stack[-1] > c and last[stack[-1]] > i:
                seen.discard(stack.pop())
            stack.append(c)
            seen.add(c)
        return "".join(stack)

Time O(n) · Space O(1) (≤26 letters). The 'pop-if-it-recurs' guard is what separates this from plain Remove-K-Digits.

23 LC 135Candy Hard Two passes · left then right

Problem. Each child has a rating; each needs ≥1 candy and more than any lower-rated neighbour. Return the minimum total candies. LeetCode 135 ↗

Clarify: Only strictly higher-rated neighbours require more candy? (Yes.) Equal ratings have no constraint? (Yes.)

Hint 1
A single greedy pass can't satisfy both neighbours at once.
Hint 2
Left-to-right fixes the left-neighbour rule; right-to-left fixes the right, taking the max.

How to think about it Two sweeps. Give everyone one candy, then left to right give a child one more than its left neighbour whenever its rating is higher. Then right to left, if a child outranks its right neighbour, raise its candy to at least the neighbour's plus one (using max to preserve the first pass). Summing satisfies both directions minimally.

candy.py
from typing import List

class Solution:
    def candy(self, ratings):
        n = len(ratings)
        candies = [1] * n
        for i in range(1, n):                # satisfy left neighbour
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1
        for i in range(n - 2, -1, -1):       # satisfy right neighbour
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)
        return sum(candies)

Time O(n) · Space O(n). When two opposing constraints exist, one greedy pass per direction (then combine) is a powerful template.

24 LC 630Course Schedule III Hard Heap · swap out the longest course

Problem. Each course has a duration and a deadline (end by which it must finish). Return the maximum number of courses you can take. LeetCode 630 ↗

Clarify: Courses are taken sequentially from day 1? (Yes.) A course must finish by its deadline? (Yes.)

Hint 1
Process courses by deadline; greedily take each one.
Hint 2
If taking it overruns the deadline, drop the longest course taken so far (maybe this one) via a max-heap.

How to think about it Sort courses by deadline and take them in that order, accumulating time and pushing each duration onto a max-heap. Whenever total time exceeds the current deadline, remove the longest course taken so far — swapping it out frees the most time while keeping the count. The heap's size is the maximum number of courses.

course_schedule_iii.py
import heapq
from typing import List

class Solution:
    def scheduleCourse(self, courses):
        courses.sort(key=lambda c: c[1])     # by deadline
        heap = []                            # max-heap of taken durations
        time = 0
        for dur, end in courses:
            heapq.heappush(heap, -dur)
            time += dur
            if time > end:                   # over deadline ⇒ drop the longest so far
                time += heapq.heappop(heap)
        return len(heap)

Time O(n log n) · Space O(n). 'Take everything, then undo the costliest choice on conflict' is a classic exchange-argument heap greedy.

25 LC 502IPO Hard Two heaps · unlock then pick best profit

Problem. With starting capital w and at most k projects (each needing capital and yielding profit), maximise final capital. LeetCode 502 ↗

Clarify: Profit adds to capital, enabling pricier projects? (Yes.) Each project done at most once? (Yes.)

Hint 1
Sort projects by capital requirement.
Hint 2
At each step, unlock all affordable projects into a max-heap by profit and take the most profitable.

How to think about it Sort projects by capital needed. Repeatedly, push every project you can now afford into a max-heap keyed on profit, then take the single most profitable available — raising your capital and possibly unlocking more. Do this up to k times (stopping early if nothing is affordable). Greedily grabbing the biggest profit each round is optimal.

ipo.py
import heapq
from typing import List

class Solution:
    def findMaximizedCapital(self, k, w, profits, capital):
        projects = sorted(zip(capital, profits))
        heap = []
        i, n = 0, len(projects)
        for _ in range(k):
            while i < n and projects[i][0] <= w:   # unlock all affordable projects
                heapq.heappush(heap, -projects[i][1])
                i += 1
            if not heap:
                break
            w -= heapq.heappop(heap)         # take the most profitable one
        return w

Time O(n log n) · Space O(n). Sort-by-cost to unlock, heap-by-value to choose — the two-heap greedy also powers refueling and scheduling.

26 LC 871Minimum Number of Refueling Stops Hard Heap · refuel from the biggest station passed

Problem. Reach a target distance from a start fuel; each passed station can add fuel once. Return the fewest stops, or −1. LeetCode 871 ↗

Clarify: You may refuel at a station only when you reach it? (Yes.) Choose stops to minimise their count? (Yes.)

Hint 1
Drive as far as current fuel allows, banking every station you pass in a max-heap.
Hint 2
When you can't proceed, refuel from the largest banked station; repeat until you reach the target.

How to think about it Greedily defer refueling. Advance as far as your fuel permits, pushing each passed station's fuel onto a max-heap. When fuel is insufficient to continue, take the biggest banked station (one stop) and add its fuel; repeat. If the heap empties before reaching the target, it's impossible. Choosing the largest available station each time minimises the number of stops.

min_refuel_stops.py
import heapq
from typing import List

class Solution:
    def minRefuelStops(self, target, startFuel, stations):
        heap = []                            # max-heap of passed fuel amounts
        fuel = startFuel
        stops = i = 0
        n = len(stations)
        while fuel < target:
            while i < n and stations[i][0] <= fuel:   # bank fuel we could take
                heapq.heappush(heap, -stations[i][1])
                i += 1
            if not heap:
                return -1                    # stuck
            fuel -= heapq.heappop(heap)      # refuel from the biggest banked station
            stops += 1
        return stops

Time O(n log n) · Space O(n). Deciding a stop only when forced — and picking the fullest station retroactively — gives the minimum count.

27 LC 321Create Maximum Number Hard Best subsequence per array · merge

Problem. From two digit arrays, pick k digits preserving each array's relative order to form the largest possible number. LeetCode 321 ↗

Clarify: Digits keep their original order within each array? (Yes.) Choose how many from each array? (Yes.)

Hint 1
For each split i, take the max subsequence of length i from array 1 and k−i from array 2.
Hint 2
Merge the two greedily (pick from the lexicographically larger remaining suffix), and keep the best merge over all splits.

How to think about it Try every split: i digits from the first array and k − i from the second. For each array, a monotonic-stack picks the largest-value subsequence of the needed length. Then merge the two subsequences by repeatedly taking from whichever remaining suffix is lexicographically larger. The best result across all valid splits is the answer.

create_max_number.py
from typing import List

class Solution:
    def maxNumber(self, nums1, nums2, k):
        def pick_max(nums, t):
            drop = len(nums) - t
            stack = []
            for x in nums:
                while drop and stack and stack[-1] < x:
                    stack.pop()
                    drop -= 1
                stack.append(x)
            return stack[:t]

        def merge(a, b):
            # greedily take from whichever remaining suffix is lexicographically larger
            return [max(a, b).pop(0) for _ in range(len(a) + len(b))]

        best = []
        for i in range(k + 1):
            if i <= len(nums1) and k - i <= len(nums2):
                best = max(best, merge(pick_max(nums1, i), pick_max(nums2, k - i)))
        return best

Time O(k·(m+n)²) · Space O(k). Combines two greedies: 'largest subsequence of length t' (stack) and lexical merge.

28 LC 632Smallest Range Covering Elements from K Lists Hard Heap · advance the current minimum

Problem. Find the smallest range [a, b] that includes at least one number from each of k sorted lists. LeetCode 632 ↗

Clarify: Lists are individually sorted ascending? (Yes.) Prefer the smaller range, then smaller start? (Yes.)

Hint 1
Maintain one pointer per list; the range spans the current min and max across pointers.
Hint 2
Pop the minimum (a min-heap) and advance that list — shrinking the range from the left.

How to think about it Keep a min-heap holding the current element of each list, and track the current maximum. The tightest range covering all lists spans the heap's minimum to that maximum. Record it, then advance the list owning the minimum (pushing its next value, updating the max). Stop when any list is exhausted — the smallest recorded range is the answer.

smallest_range.py
from typing import List

class Solution:
    def smallestRange(self, nums):
        heap = [(row[0], i, 0) for i, row in enumerate(nums)]
        heapq.heapify(heap)
        cur_max = max(row[0] for row in nums)
        best = [-10 ** 9, 10 ** 9]
        while heap:
            val, r, c = heapq.heappop(heap)  # current minimum across the lists
            if cur_max - val < best[1] - best[0]:
                best = [val, cur_max]
            if c + 1 == len(nums[r]):        # a list is exhausted ⇒ can't cover all
                break
            nxt = nums[r][c + 1]
            cur_max = max(cur_max, nxt)
            heapq.heappush(heap, (nxt, r, c + 1))
        return best

Time O(N log k) · Space O(k). Advancing the current minimum is a k-way merge greedy — the same engine as merging k sorted lists.

4 · Interview playbook

  • Justify before you code. State the exchange argument (or a counterexample). "I sort by end time because keeping the earliest-finishing interval leaves the most room" is what interviewers want to hear.
  • Interval problems almost always want sort by end time, keep earliest-finishing — non-overlapping intervals, arrows, meetings.
  • Reachability / min-jumps reduce to tracking the farthest reach and acting only at range boundaries.
  • Exchange-argument greedies sort by a relative measure — the cost difference (Two City), value density (Truck), or frequency (Task Scheduler).
  • Reach for a heap when you must revise a past choice (evict the longest course, refuel from the biggest station); a monotonic stack for lexicographically smallest/largest subsequences.
  • If no argument holds, it's probably DP — greedy that only "looks right" is the most common interview trap.

5 · Role notes

SDE / Python backend

Greedy drives real scheduling (jobs, tasks, meeting rooms), rate limiting, load shedding, cache eviction, and resource allocation. Interval merging and heap-based selection appear constantly in systems code.

Data Science / ML / AI / GenAI

Greedy underlies decision-tree splits, feature selection, beam search, huffman/coding schemes, and many approximation algorithms; recognising when a greedy heuristic is provably (or acceptably) near-optimal is a core modelling skill.

6 · Review

Cheat sheet
  • Assign / pair / select to optimise a total → sort & match (two pointers).
  • Non-overlapping / min removals / min arrows → sort by end time, keep earliest-finishing.
  • Can-reach / min jumps / partition by reach → track farthest reach.
  • Choose subset/order minimising cost → exchange argument (sort by difference/ratio).
  • Revise best/worst pick as you go → heap greedy (evict/select the extreme).
  • Smallest/largest subsequence → monotonic stack; circular feasibility → running balance + reset.
  • Two opposing constraints → one greedy pass per direction (Candy).
  • No exchange argument? → it's likely DP, not greedy.

Concept checks

For interval scheduling (keep the most non-overlapping intervals), why sort by end time rather than start time?
Keeping the interval that finishes earliest leaves the maximum remaining room for future intervals — provable by an exchange argument; sorting by start can pick a long early interval that blocks several later ones
Sorting by end time is faster than sorting by start time
Start times are often negative
The greedy-choice property here is that the earliest-finishing interval is always safe to keep: any optimal set can be modified to include it without reducing the count. Sorting by start time lacks this guarantee — a single wide interval starting first could crowd out many short ones.
How do you know a greedy approach is actually correct for a problem?
You can prove the greedy-choice property — typically via an exchange argument showing any optimal solution can be reshaped into the greedy one without getting worse
It produces the right answer on a few small test cases
It runs faster than a dynamic-programming solution
Passing small tests and being fast prove nothing about correctness — the coin problem {1,3,4} for amount 6 shows greedy can look right yet fail. Only an exchange argument (or equivalent proof of the greedy-choice property) guarantees a greedy is optimal; without one, prefer DP.

Mastery checklist

  • I can state an exchange argument (or find a counterexample) before trusting a greedy.
  • I can solve interval-scheduling problems by sorting on end time.
  • I can solve reachability / min-jump problems by tracking the farthest reach.
  • I can pick the right sort key for exchange-argument greedies.
  • I can use a heap to revise past choices (schedule, refuel, reorganise).
  • I can build a lexicographically optimal subsequence with a monotonic stack.
