Sliding Window & Prefix Sums

Two techniques that turn repeated subarray work into single passes: a sliding window reuses a computation as it moves, and a prefix sum precomputes cumulative totals so any range answers in O(1). This chapter builds both from scratch — every problem has a full, tested solution in LeetCode's class Solution format.

Outcome

Recognise window vs prefix problems, choose fixed/variable windows, prefix maps, 2D prefix, difference arrays, or monotonic deques, and state the invariant and complexity precisely.

The problem both techniques solve

Many questions ask about contiguous subarrays or substrings: the largest sum of any window of size k, the longest substring with some property, the number of subarrays summing to a value. The brute force recomputes each range from scratch — O(n²) or worse. Sliding windows and prefix sums both remove that repeated work, usually reaching O(n).

Sliding window reuses the previous window's answer as the window moves by one. Prefix sums precompute cumulative totals once, so any range is a single subtraction. Learn to spot which one a problem wants.

Sliding window: fixed size

When the window has a fixed length k, you compute the first window directly, then slide: add the element entering on the right and subtract the one leaving on the left. Each step is O(1), so the whole scan is O(n).

Example — max sum of any window of size k
fixed_window.py
def max_window_sum(nums, k):
    window = sum(nums[:k])          # first window, computed once
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]   # add entering, drop leaving
        best = max(best, window)
    return best

print(max_window_sum([1, 12, -5, -6, 50, 3], 4))   # 41  (window -6,50,3,... )
Output41

Never re-sum the whole window — the add-one/drop-one update is what makes it O(n) instead of O(n·k).

Sliding window: variable size

When the window can grow and shrink to satisfy a condition ("longest substring without repeats", "shortest subarray with sum ≥ target"), use two pointers: grow the right edge to include more, and shrink the left edge whenever the window breaks the rule. Each index enters and leaves at most once, so it's still O(n).

Example — longest substring of at most 2 distinct characters
variable_window.py
def at_most_two_distinct(s):
    from collections import defaultdict
    freq = defaultdict(int)
    left = best = 0
    for right, ch in enumerate(s):
        freq[ch] += 1
        while len(freq) > 2:            # rule broken -> shrink from the left
            freq[s[left]] -= 1
            if freq[s[left]] == 0:
                del freq[s[left]]
            left += 1
        best = max(best, right - left + 1)
    return best

print(at_most_two_distinct("eceba"))   # 3  ("ece")
The whole family — longest/shortest/at-most-k — shares this grow-right, shrink-left skeleton. The condition in the while is all that changes.

Prefix sums: precompute once, query fast

A prefix sum array stores cumulative totals: prefix[i] is the sum of the first i elements. Then the sum of any range [l, r] is a single subtraction, prefix[r+1] − prefix[l] — O(1) per query after an O(n) build. This is the right tool when a window won't work (e.g. arrays with negative numbers).

Example — build once, answer ranges in O(1)
prefix_sum.py
nums = [3, 1, 4, 1, 5, 9]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)   # prefix = [0, 3, 4, 8, 9, 14, 23]

# sum of nums[1..3] (values 1,4,1):
print(prefix[4] - prefix[1])        # 6
Output6

The leading 0 lets range [l, r] map cleanly to prefix[r+1] − prefix[l] with no special case for l = 0.

Prefix sums + a hash map

The most powerful combination: to count subarrays with a target sum, store how many times each prefix sum has occurred in a hash map. A subarray ending here sums to k exactly when some earlier prefix equals running − k. This handles negatives, which sliding windows cannot.

⚠️
Which technique? — and common traps

Sliding windows need a monotonic condition, which usually means non-negative values (adding grows, removing shrinks). With negatives, reach for prefix sums + a map. Seed the prefix map with {0: 1} (or {0: -1} for indices) so a whole prefix counts. And remember: a difference array is the inverse of a prefix sum — mark range edges, then integrate once.

1 LC 1480Running Sum of 1d Array Easy Prefix sums · the cumulative total

Problem. Return the running sum, where out[i] is the sum of nums[0..i]. LeetCode 1480 ↗

Clarify: Return a new array? (Yes.) Can be done in place? (Yes, but a new array is fine.)

Hint 1
Each running sum is the previous running sum plus the current value.
Hint 2
Carry a total across the scan.

How to think about it This is a prefix sum: keep a running total and append it at each step. Prefix sums are the foundation for O(1) range-sum queries later in the chapter.

running_sum.py
from typing import List

class Solution:
    def runningSum(self, nums: List[int]) -> List[int]:
        out = []
        total = 0
        for x in nums:
            total += x                       # prefix sum up to here
            out.append(total)
        return out

Time O(n) · Space O(n) output. The simplest possible prefix-sum build.

2 LC 303Range Sum Query - Immutable Easy Prefix sums · precompute, answer in O(1)

Problem. Answer many sumRange(left, right) queries on a fixed array, each returning the inclusive range sum. LeetCode 303 ↗

Clarify: Array is immutable? (Yes.) Many queries? (Yes — so precompute.)

Hint 1
Summing each query is O(n); too slow for many.
Hint 2
Precompute prefix sums; any range is one subtraction.

How to think about it Build a prefix array once (prefix[i] = sum of the first i elements, with a leading 0). Then a range sum is prefix[right+1] − prefix[left] — constant time per query. Build once, query fast.

range_sum.py
from typing import List

class NumArray:
    def __init__(self, nums: List[int]):
        self.prefix = [0]
        for x in nums:
            self.prefix.append(self.prefix[-1] + x)
    def sumRange(self, left: int, right: int) -> int:
        return self.prefix[right + 1] - self.prefix[left]

Build O(n) once · Query O(1) · Space O(n). The leading 0 makes range [l, r] map cleanly to prefix[r+1] − prefix[l].

3 LC 724Find Pivot Index Easy Prefix sums · left total vs right total

Problem. Return the leftmost index where the sum to its left equals the sum to its right, or −1. LeetCode 724 ↗

Clarify: Empty sides count as 0? (Yes.) Leftmost such index? (Yes.) Negatives allowed? (Yes.)

Hint 1
Given the total and the running left sum, the right sum is total − left − nums[i].
Hint 2
One pass, updating the left sum as you pass each index.

How to think about it Precompute the total. Sweep tracking the running left sum; at index i the right sum is total − left − nums[i]. If it equals the left sum, i is the pivot. Update left after checking.

pivot_index.py
from typing import List

class Solution:
    def pivotIndex(self, nums: List[int]) -> int:
        total = sum(nums)
        left = 0
        for i, x in enumerate(nums):
            if left == total - left - x:     # left sum == right sum
                return i
            left += x
        return -1

Time O(n) · Space O(1). A prefix-sum classic that needs no extra array — just a running total.

4 LC 643Maximum Average Subarray I Easy Fixed-size window · slide the sum

Problem. Return the maximum average of any contiguous subarray of length k. LeetCode 643 ↗

Clarify: Fixed length k? (Yes.) Return a float average? (Yes.)

Hint 1
Compute the first window's sum, then slide it one step at a time.
Hint 2
Sliding = add the entering element, subtract the leaving one — O(1) per step.

How to think about it The canonical fixed-window move. Sum the first k elements, then slide: each step adds the new element and drops the one that left the window, keeping the sum in O(1). Track the maximum sum and divide by k at the end.

max_average.py
from typing import List

class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        window = sum(nums[:k])
        best = window
        for i in range(k, len(nums)):
            window += nums[i] - nums[i - k]  # slide: add new, drop old
            best = max(best, window)
        return best / k

Time O(n) · Space O(1). Recomputing each window's sum from scratch would be O(n·k); sliding makes it O(n).

5 LC 1876Substrings of Size Three with Distinct Characters Easy Fixed-size window · size 3 check

Problem. Count the length-3 substrings whose three characters are all different. LeetCode 1876 ↗

Clarify: Overlapping substrings counted separately? (Yes.) Only length 3? (Yes.)

Hint 1
Slide a window of size 3 across the string.
Hint 2
A window is 'good' when its three characters are pairwise distinct.

How to think about it A tiny fixed window. Check every consecutive triple and count those with three distinct characters. With a size of 3, direct comparison is simplest and clearest.

good_substrings.py
class Solution:
    def countGoodSubstrings(self, s: str) -> int:
        count = 0
        for i in range(len(s) - 2):
            a, b, c = s[i], s[i + 1], s[i + 2]
            if a != b and b != c and a != c:
                count += 1
        return count

Time O(n) · Space O(1). A gentle warm-up for the fixed-window idea.

6 LC 219Contains Duplicate II Easy Window + last-index map

Problem. Return whether two equal values exist within index distance k. LeetCode 219 ↗

Clarify: Indices within k of each other? (Yes.) Any pair? (Yes.)

Hint 1
For each value, only the most recent index matters.
Hint 2
Store value → last index; on a repeat, check the gap against k.

How to think about it Keep a map from each value to its most recent index — effectively a window of the last occurrence. On revisiting a value, if the index gap is ≤ k, return True; otherwise update its index.

contains_dup_ii.py
from typing import List

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        last = {}                            # value -> most recent index
        for i, x in enumerate(nums):
            if x in last and i - last[x] <= k:
                return True
            last[x] = i
        return False

Time O(n) · Space O(n). Storing only the latest index is what makes the window check correct.

7 LC 1652Defuse the Bomb Easy Circular fixed window

Problem. Replace each number with the sum of the next k numbers (or previous |k|) in a circular array; 0 means all zeros. LeetCode 1652 ↗

Clarify: Array is circular? (Yes — wrap with modulo.) k can be negative? (Yes — look backward.)

Hint 1
For each index, sum the next k (or previous |k|) values, wrapping with modulo.
Hint 2
k = 0 means the answer is all zeros.

How to think about it A circular fixed-size window. For each position, sum the appropriate k neighbours, using index % n to wrap around the ends. (A sliding sum reduces it to O(n); the direct O(n·k) version is clearest here.)

defuse_bomb.py
from typing import List

class Solution:
    def decrypt(self, code: List[int], k: int) -> List[int]:
        n = len(code)
        res = [0] * n
        if k == 0:
            return res
        for i in range(n):
            if k > 0:
                for j in range(i + 1, i + 1 + k):
                    res[i] += code[j % n]    # next k, wrapping around
            else:
                for j in range(i - 1, i - 1 + k, -1):
                    res[i] += code[j % n]    # previous |k|, wrapping
        return res

Time O(n·k) · Space O(n). The modulo wrap is the whole trick for circular windows.

8 LC 3Longest Substring Without Repeating Characters Medium Variable window (longest) · jump the left edge

Problem. Return the length of the longest substring without repeating characters. LeetCode 3 ↗

Clarify: Contiguous substring? (Yes.) Any characters? (Yes.)

Hint 1
Keep a window with no repeats; on a repeat, move the left edge past the previous occurrence.
Hint 2
Store each character's last index to jump in O(1).

How to think about it A variable-length window tracked by a last-seen-index map. When the current character was last seen at or after the window start, jump start just past it. The window stays repeat-free, so track its max length.

longest_unique.py
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}
        start = best = 0
        for i, ch in enumerate(s):
            if ch in last and last[ch] >= start:
                start = last[ch] + 1
            last[ch] = i
            best = max(best, i - start + 1)
        return best

Time O(n) · Space O(min(n, alphabet)). The template for 'longest window satisfying a rule'.

9 LC 159Longest Substring with At Most Two Distinct Characters Medium Variable window · ≤ 2 distinct

Problem. Return the length of the longest substring containing at most two distinct characters. LeetCode 159 ↗

Clarify: At most two distinct (fewer is fine)? (Yes.)

Hint 1
Grow the window; when it has three distinct characters, shrink from the left.
Hint 2
A frequency map tracks how many distinct characters are inside.

How to think about it Grow the right edge, keeping a frequency map of characters in the window. Whenever the map holds more than two distinct characters, shrink from the left (removing counts, deleting empties) until it's back to two. Track the max window length.

two_distinct.py
from collections import defaultdict

class Solution:
    def lengthOfLongestSubstringTwoDistinct(self, s: str) -> int:
        freq = defaultdict(int)
        left = best = 0
        for right, ch in enumerate(s):
            freq[ch] += 1
            while len(freq) > 2:
                freq[s[left]] -= 1
                if freq[s[left]] == 0:
                    del freq[s[left]]
                left += 1
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(1) (≤3 keys). The special case of the 'at most K distinct' template.

10 LC 340Longest Substring with At Most K Distinct Characters Medium Variable window · ≤ K distinct

Problem. Return the length of the longest substring with at most k distinct characters. LeetCode 340 ↗

Clarify: k can be 0? (Then answer is 0.) Fewer than k distinct is fine? (Yes.)

Hint 1
Generalise the two-distinct window to k.
Hint 2
Shrink from the left whenever the window exceeds k distinct characters.

How to think about it The general 'at most K distinct' window. Grow the right edge with a frequency map; when the number of distinct characters exceeds k, shrink from the left until it fits. The largest valid window is the answer.

class Solution:

11 LC 424Longest Repeating Character Replacement Medium Variable window · window − maxfreq ≤ k

Problem. You may replace up to k characters. Return the longest single-letter run achievable. LeetCode 424 ↗

Clarify: Replace with any uppercase letter? (Yes.) k can be 0? (Yes.)

Hint 1
A window is valid if the characters to replace (size − most-frequent count) is ≤ k.
Hint 2
Grow the window; shrink when it becomes invalid.

How to think about it Slide a window keeping letter counts and the highest single-letter frequency. The window is achievable if size − max_freq ≤ k (the rest can be replaced); when it isn't, advance the left edge. Track the largest valid window.

char_replacement.py
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        left = max_freq = best = 0
        for right, ch in enumerate(s):
            count[ch] = count.get(ch, 0) + 1
            max_freq = max(max_freq, count[ch])
            while (right - left + 1) - max_freq > k:
                count[s[left]] -= 1
                left += 1
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(1). Not shrinking max_freq back down is a valid, standard simplification.

12 LC 904Fruit Into Baskets Medium Variable window · ≤ 2 types

Problem. Two baskets each hold one fruit type. Starting anywhere and picking one fruit per tree, return the max fruits collected from a contiguous run. LeetCode 904 ↗

Clarify: At most two fruit types total? (Yes.) Contiguous trees? (Yes.)

Hint 1
This is 'longest subarray with at most two distinct values' in disguise.
Hint 2
Grow the window; shrink when a third type appears.

How to think about it Recognise it as the ≤ 2-distinct window: fruit types are the distinct values. Grow the window with a count map, and shrink from the left whenever a third type enters. The longest valid window is the most fruit you can collect.

fruit_baskets.py
from typing import List
from collections import defaultdict

class Solution:
    def totalFruit(self, fruits: List[int]) -> int:
        count = defaultdict(int)
        left = best = 0
        for right, f in enumerate(fruits):
            count[f] += 1
            while len(count) > 2:            # at most two fruit types
                count[fruits[left]] -= 1
                if count[fruits[left]] == 0:
                    del count[fruits[left]]
                left += 1
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(1). Seeing past the story to 'at most 2 distinct' is the skill.

13 LC 1004Max Consecutive Ones III Medium Variable window · ≤ k zeros

Problem. You may flip at most k zeros to ones. Return the longest run of ones you can make. LeetCode 1004 ↗

Clarify: Flip at most k zeros? (Yes.) Binary array? (Yes.)

Hint 1
A window is valid if it contains at most k zeros.
Hint 2
Grow the window; when it holds more than k zeros, shrink from the left.

How to think about it Slide a window counting the zeros inside. While the count exceeds k, advance the left edge (decrementing the zero count when a zero leaves). The largest window with ≤ k zeros is the answer.

max_ones_iii.py
from typing import List

class Solution:
    def longestOnes(self, nums: List[int], k: int) -> int:
        left = zeros = best = 0
        for right, v in enumerate(nums):
            if v == 0:
                zeros += 1
            while zeros > k:                 # too many zeros to flip
                if nums[left] == 0:
                    zeros -= 1
                left += 1
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(1). 'At most k of something' is the recurring variable-window shape.

14 LC 1456Maximum Number of Vowels in a Substring of Given Length Medium Fixed-size window · running count

Problem. Return the maximum number of vowels in any substring of length k. LeetCode 1456 ↗

Clarify: Fixed length k? (Yes.) Only lowercase? (Yes.)

Hint 1
Count vowels in the first window, then slide.
Hint 2
Each slide adjusts the count by the entering and leaving characters.

How to think about it A fixed window over vowel counts. Count vowels in the first k characters, then slide: add 1 if the entering character is a vowel, subtract 1 if the leaving one was. Track the maximum.

max_vowels.py
class Solution:
    def maxVowels(self, s: str, k: int) -> int:
        vowels = set("aeiou")
        cur = sum(1 for ch in s[:k] if ch in vowels)
        best = cur
        for i in range(k, len(s)):
            cur += (s[i] in vowels) - (s[i - k] in vowels)
            best = max(best, cur)
        return best

Time O(n) · Space O(1). The same slide-the-count move as Maximum Average Subarray.

15 LC 1343Number of Sub-arrays of Size K With Average ≥ Threshold Medium Fixed-size window · compare to k·threshold

Problem. Count length-k subarrays whose average is at least threshold. LeetCode 1343 ↗

Clarify: Fixed length k? (Yes.) Average ≥ threshold means sum ≥ k·threshold? (Yes — avoid floats.)

Hint 1
Average ≥ threshold ⟺ window sum ≥ k × threshold.
Hint 2
Slide the window sum and count when it clears the target.

How to think about it Turn the average test into a sum test: sum ≥ k × threshold. Slide a fixed window of size k, incrementing the count whenever the window sum clears that target. Comparing sums avoids floating-point issues.

k_avg_threshold.py
from typing import List

class Solution:
    def numOfSubarrays(self, arr: List[int], k: int, threshold: int) -> int:
        target = k * threshold              # avoid float division
        window = sum(arr[:k])
        count = 1 if window >= target else 0
        for i in range(k, len(arr)):
            window += arr[i] - arr[i - k]
            if window >= target:
                count += 1
        return count

Time O(n) · Space O(1). Converting the average to an integer sum comparison is the clean move.

16 LC 567Permutation in String Medium Fixed-size window · frequency match

Problem. Return whether s2 contains a permutation of s1 as a substring. LeetCode 567 ↗

Clarify: Contiguous substring that is a permutation? (Yes.) Lowercase only? (Yes.)

Hint 1
A permutation is any window with exactly s1's letter counts.
Hint 2
Slide a window of length |s1|, updating counts in O(1), and compare.

How to think about it Maintain a frequency map for a fixed window of length |s1|, updating it as the window slides (add the entering char, drop the leaving one, delete zeros). When the window's counts equal s1's, a permutation exists.

permutation_in_string.py
from collections import Counter

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        need = Counter(s1)
        window = Counter()
        L = len(s1)
        for i, ch in enumerate(s2):
            window[ch] += 1
            if i >= L:
                left = s2[i - L]
                window[left] -= 1
                if window[left] == 0:
                    del window[left]
            if window == need:
                return True
        return False

Time O(n) · Space O(1). Deleting zeroed keys lets a direct Counter == comparison work.

17 LC 438Find All Anagrams in a String Medium Fixed-size window · collect all matches

Problem. Return the start indices of every substring that is an anagram of p. LeetCode 438 ↗

Clarify: Substrings of length |p|? (Yes.) Lowercase only? (Yes.)

Hint 1
Same fixed-window count-match as Permutation in String.
Hint 2
Record every start index where the window matches, instead of stopping.

How to think about it Identical machinery to Permutation in String, but record every match. Slide a window of length |p|, keeping its frequency map updated; whenever it equals p's counts, append the window's start index.

find_anagrams.py
from typing import List
from collections import Counter

class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        need = Counter(p)
        window = Counter()
        L = len(p)
        res = []
        for i, ch in enumerate(s):
            window[ch] += 1
            if i >= L:
                left = s[i - L]
                window[left] -= 1
                if window[left] == 0:
                    del window[left]
            if window == need:
                res.append(i - L + 1)
        return res

Time O(n) · Space O(1). The anagram-window template underlies a whole family of substring problems.

18 LC 209Minimum Size Subarray Sum Medium Variable window (shortest) · grow then shrink

Problem. Given positive numbers and a target, return the shortest subarray length with sum ≥ target, or 0. LeetCode 209 ↗

Clarify: All values positive? (Yes — enables the window.) Shortest length? (Yes.)

Hint 1
Grow the window until the sum reaches target.
Hint 2
Then shrink from the left while still ≥ target, recording the length.

How to think about it A shortest-window search. Extend the right edge accumulating the sum; whenever it reaches the target, record the length and shrink from the left to find the tightest valid window. Positivity makes the sum monotonic under growth and shrink.

min_subarray_len.py
from typing import List

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = running = 0
        best = float("inf")
        for right, x in enumerate(nums):
            running += x
            while running >= target:
                best = min(best, right - left + 1)
                running -= nums[left]
                left += 1
        return 0 if best == float("inf") else best

Time O(n) · Space O(1). With negatives you'd switch to prefix sums instead of a window.

19 LC 713Subarray Product Less Than K Medium Variable window · count subarrays

Problem. Count contiguous subarrays whose product is strictly less than k. LeetCode 713 ↗

Clarify: All values positive? (Yes.) Strictly less than k? (Yes.)

Hint 1
Grow the window; when the product reaches k, shrink from the left.
Hint 2
For each right end, the number of valid subarrays is the current window length.

How to think about it Slide a window keeping the product of its elements. When the product reaches k, divide out the left elements until it drops below. For each right endpoint, every subarray ending there and starting within the window is valid — add right − left + 1.

product_less_k.py
from typing import List

class Solution:
    def numSubarrayProductLessThanK(self, nums: List[int], k: int) -> int:
        if k <= 1:
            return 0
        prod = 1
        left = count = 0
        for right, v in enumerate(nums):
            prod *= v
            while prod >= k:
                prod //= nums[left]
                left += 1
            count += right - left + 1        # all subarrays ending at right
        return count

Time O(n) · Space O(1). Counting right − left + 1 per step is the window-counting idiom.

21 LC 930Binary Subarrays With Sum Medium Window counting · at-most trick

Problem. Given a binary array, count subarrays whose sum equals goal. LeetCode 930 ↗

Clarify: Only 0/1 values? (Yes.) goal can be 0? (Yes.)

Hint 1
'Exactly goal' = 'at most goal' − 'at most goal−1'.
Hint 2
Count subarrays with sum ≤ x using a sliding window (values are non-negative).

How to think about it Exactly-goal is hard directly, but atMost(goal) − atMost(goal−1) gives it. Because values are non-negative, atMost(x) is a clean sliding window: grow right, shrink left while the sum exceeds x, adding the window length each step.

binary_subarrays.py
from typing import List

class Solution:
    def numSubarraysWithSum(self, nums: List[int], goal: int) -> int:
        def at_most(x):
            if x < 0:
                return 0
            left = total = count = 0
            for right, v in enumerate(nums):
                total += v
                while total > x:
                    total -= nums[left]
                    left += 1
                count += right - left + 1
            return count
        return at_most(goal) - at_most(goal - 1)

Time O(n) · Space O(1). The atMost(k) − atMost(k−1) identity turns 'exactly' problems into two window scans.

22 LC 560Subarray Sum Equals K Medium Prefix sum + hashmap

Problem. Count contiguous subarrays whose sum equals k. LeetCode 560 ↗

A subarray sum is prefix[j] − prefix[i]; you want it to equal k.
Hint 2
Track counts of prefix sums; add how many earlier prefixes equal running − k.

How to think about it The prefix-sum + hashmap pattern (needed here because negatives break sliding windows). A subarray ending now sums to k when some earlier prefix equals running − k. Keep a map of prefix-sum → count (seed {0:1}) and add the needed count at each step.

subarray_sum_k.py
from typing import List
from collections import defaultdict

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        seen = defaultdict(int)
        seen[0] = 1
        prefix = count = 0
        for x in nums:
            prefix += x
            count += seen[prefix - k]
            seen[prefix] += 1
        return count

23 LC 974Subarray Sums Divisible by K Medium Prefix remainder + hashmap

Problem. Count contiguous subarrays whose sum is divisible by k. LeetCode 974 ↗

Hint 2
Count occurrences of each remainder; add the running count of the current one.

How to think about it A remainder-keyed prefix map. Two prefix sums with equal remainder mod k enclose a subarray divisible by k. Track remainder counts (seed {0:1}); Python's % keeps remainders non-negative, handling negatives automatically.

subarrays_div_k.py
from typing import List
from collections import defaultdict

class Solution:
    def subarraysDivByK(self, nums: List[int], k: int) -> int:
        count = defaultdict(int)
        count[0] = 1
        prefix = res = 0
        for x in nums:
            prefix = (prefix + x) % k        # Python % stays non-negative
            res += count[prefix]
            count[prefix] += 1
        return res

Time O(n) · Space O(k). 'Same remainder ⇒ divisible difference' is the key fact.

24 LC 523Continuous Subarray Sum Medium Prefix remainder + earliest index

Problem. Return whether there is a subarray of length ≥ 2 with sum a multiple of k. LeetCode 523 ↗

Same remainder trick — two equal remainders bound a multiple of k.

Store the earliest index per remainder and require the gap ≥ 2.

How to think about it Track the running sum mod k and remember the earliest index for each remainder (seed {0:-1}). When a remainder repeats with an index gap ≥ 2, a valid subarray exists. Keeping the earliest index maximises the chance of a length-≥-2 span.

from typing import List

class Solution:

        prefix = 0
        for i, x in enumerate(nums):
            prefix = (prefix + x) % k
            if prefix in first:

            else:

        return False

25 LC 525Contiguous Array Medium Prefix balance + earliest index

Hint 2

How to think about it Reframe by treating 0 as −1, so a balanced subarray has sum 0 — meaning two positions with the same running balance. Record the earliest index per balance value (seed {0:-1}) and take the largest span between equal balances.

contiguous_array.py
from typing import List

class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        first = {0: -1}
        balance = best = 0
        for i, x in enumerate(nums):
            balance += 1 if x == 1 else -1
            if balance in first:
                best = max(best, i - first[balance])
            else:
                first[balance] = i
        return best

from typing import List

class Solution:

27 LC 238Product of Array Except Self Medium Prefix × suffix products

Problem. Return an array where each position holds the product of all other elements — no division, O(n). LeetCode 238 ↗

Clarify: Zeros allowed? (Yes — why division is banned.) Output counts as space? (No.)

Hint 1
The answer at i is (product left of i) × (product right of i).
Hint 2
One left-to-right pass writes prefixes; a right-to-left pass multiplies in suffixes.

How to think about it Prefix and suffix products — the multiplicative cousin of prefix sums. First pass: out[i] = product of everything before i. Second pass backward: multiply in a running product of everything after i. Two scalars, no division.

product_except.py
from typing import List

class Solution:
    def productExceptSelf(self, nums: List[int]) -> List[int]:
        n = len(nums)
        out = [1] * n
        prefix = 1
        for i in range(n):
            out[i] = prefix
            prefix *= nums[i]
        suffix = 1
        for i in range(n - 1, -1, -1):
            out[i] *= suffix
            suffix *= nums[i]
        return out

Time O(n) · Space O(1) beyond output. Shows prefix techniques extend beyond sums.

28 LC 304Range Sum Query 2D - Immutable Medium 2D prefix sums · rectangle in O(1)

Problem. Answer many queries for the sum of a rectangular submatrix of a fixed grid. LeetCode 304 ↗

Clarify: Matrix immutable? (Yes.) Many queries? (Yes — precompute.)

Hint 1
Build a 2D prefix grid where pre[r][c] is the sum of the rectangle from (0,0) to (r−1,c−1).
Hint 2
A rectangle sum is one addition and two subtractions (inclusion–exclusion).

How to think about it Extend prefix sums to 2D. pre[r+1][c+1] holds the sum of the top-left rectangle up to (r,c), built with inclusion–exclusion. Any query rectangle is then computed as bottom-right − top-strip − left-strip + double-counted-corner in O(1).

range_sum_2d.py
from typing import List

class NumMatrix:
    def __init__(self, matrix: List[List[int]]):
        rows, cols = len(matrix), len(matrix[0])
        self.pre = [[0] * (cols + 1) for _ in range(rows + 1)]
        for r in range(rows):
            for c in range(cols):
                self.pre[r + 1][c + 1] = (matrix[r][c] + self.pre[r][c + 1]
                                          + self.pre[r + 1][c] - self.pre[r][c])
    def sumRegion(self, row1: int, col1: int, row2: int, col2: int) -> int:
        return (self.pre[row2 + 1][col2 + 1] - self.pre[row1][col2 + 1]
                - self.pre[row2 + 1][col1] + self.pre[row1][col1])

Build O(rows·cols) · Query O(1) · Space O(rows·cols). Inclusion–exclusion is the 2D generalisation of the 1D subtraction.

29 LC 1109Corporate Flight Bookings Medium Difference array · range updates

Problem. Apply many 'add seats to flights first..last' updates and return the final per-flight totals. LeetCode 1109 ↗

Clarify: Many range updates, one final read? (Yes.) 1-indexed flights? (Yes.)

Hint 1
Instead of updating every flight in a range, mark the start and just-after-end.
Hint 2
A prefix sum over those marks reconstructs the totals.

How to think about it A difference array: for each booking add seats at the start index and subtract it just past the end. A single prefix-sum pass over the diff array then reconstructs each flight's total — turning many O(range) updates into O(1) each plus one O(n) sweep.

flight_bookings.py
from typing import List

class Solution:
    def corpFlightBookings(self, bookings: List[List[int]], n: int) -> List[int]:
        diff = [0] * (n + 1)
        for first, last, seats in bookings:
            diff[first - 1] += seats         # +seats from flight `first`
            diff[last] -= seats              # cancel after flight `last`
        res = []
        running = 0
        for i in range(n):
            running += diff[i]
            res.append(running)
        return res

Time O(n + bookings) · Space O(n). Difference arrays are the inverse of prefix sums — mark edges, integrate once.

from typing import List

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        diff = [0] * 1001
        for num, start, end in trips:
            diff[start] += num
            diff[end] -= num                 # passengers leave at `end`
        cur = 0
        for delta in diff:
            cur += delta
            if cur > capacity:
                return False
        return True

31 LC 1438Longest Continuous Subarray With Absolute Diff ≤ Limit Medium Monotonic deques · window max and min

Problem. Return the longest subarray where the difference between its max and min is at most limit. LeetCode 1438 ↗

Clarify: Absolute diff of max and min ≤ limit? (Yes.) Contiguous? (Yes.)

Hint 1
You need the current window's max and min quickly.
Hint 2
Maintain two monotonic deques — one decreasing (max), one increasing (min) — and shrink when max − min > limit.

How to think about it Track the window's max and min with two monotonic deques of indices: a decreasing deque gives the max at its front, an increasing deque gives the min. Grow the window; whenever max − min > limit, advance the left edge and pop indices that fall out. The largest valid window is the answer.

abs_diff_limit.py
from typing import List
from collections import deque

class Solution:
    def longestSubarray(self, nums: List[int], limit: int) -> int:
        max_dq, min_dq = deque(), deque()    # decreasing / increasing indices
        left = best = 0
        for right, v in enumerate(nums):
            while max_dq and nums[max_dq[-1]] <= v:
                max_dq.pop()
            max_dq.append(right)
            while min_dq and nums[min_dq[-1]] >= v:
                min_dq.pop()
            min_dq.append(right)
            while nums[max_dq[0]] - nums[min_dq[0]] > limit:
                left += 1
                if max_dq[0] < left:
                    max_dq.popleft()
                if min_dq[0] < left:
                    min_dq.popleft()
            best = max(best, right - left + 1)
        return best

Time O(n) · Space O(n). Two monotonic deques give O(1) amortised window max/min — the same tool as Sliding Window Maximum.

32 LC 76Minimum Window Substring Hard Variable window + need counts

Problem. Return the shortest substring of s containing all characters of t (with multiplicity), or ''. LeetCode 76 ↗

Clarify: Include duplicate requirements? (Yes.) No valid window → ''? (Yes.)

Hint 1
Expand right until the window covers all of t.
Hint 2
Then shrink from the left while it still covers t, tracking the smallest.

How to think about it A grow-then-shrink window with a need-count map and a missing counter. Extend the right edge decrementing needs; when missing hits 0 the window is valid, so shrink from the left to the tightest valid window, recording the best.

min_window.py
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not s or not t:
            return ""
        need = Counter(t)
        missing = len(t)
        left = best_start = 0
        best = float("inf")
        for right, ch in enumerate(s):
            if need[ch] > 0:
                missing -= 1
            need[ch] -= 1
            while missing == 0:
                if right - left + 1 < best:
                    best = right - left + 1
                    best_start = left
                need[s[left]] += 1
                if need[s[left]] > 0:
                    missing += 1
                left += 1
        return "" if best == float("inf") else s[best_start:best_start + best]

Time O(n + m) · Space O(unique chars in t). Each character enters and leaves once, so it's linear despite the inner loop.

33 LC 239Sliding Window Maximum Hard Monotonic deque · front is the max

Problem. Return the maximum of every contiguous window of size k. LeetCode 239 ↗

Clarify: Fixed window size k? (Yes.) O(n) expected? (Yes — a heap is O(n log n).)

Hint 1
A heap works but is O(n log k). Can you get O(1) amortised per window?
Hint 2
Keep a deque of indices with decreasing values; the front is always the window max.

How to think about it Maintain a deque of indices whose values are decreasing. Before adding a new index, pop smaller values off the back (they can never be the max while the new one is in the window). Drop the front if it falls outside the window. The front index always holds the current window's maximum.

window_max.py
from typing import List
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        dq = deque()                         # indices, values decreasing
        res = []
        for i, v in enumerate(nums):
            while dq and nums[dq[-1]] <= v:  # pop smaller tails
                dq.pop()
            dq.append(i)
            if dq[0] <= i - k:               # drop the out-of-window front
                dq.popleft()
            if i >= k - 1:
                res.append(nums[dq[0]])      # front is the window max
        return res

Time O(n) · Space O(k). Each index is pushed and popped once — the monotonic-deque workhorse.

34 LC 992Subarrays with K Different Integers Hard Window counting · exactly K via at-most

Problem. Count contiguous subarrays with exactly k distinct integers. LeetCode 992 ↗

Clarify: Exactly k distinct? (Yes.) Count subarrays? (Yes.)

Hint 1
'Exactly k' = 'at most k' − 'at most k−1'.
Hint 2
Each atMost is a sliding window that shrinks when distinct count exceeds the bound.

How to think about it Exactly-k distinct is hard directly, so compute atMost(k) − atMost(k−1). Each atMost(x) is a sliding window with a frequency map that shrinks from the left whenever the distinct count exceeds x, adding the window length each step.

k_different.py
from typing import List
from collections import defaultdict

class Solution:
    def subarraysWithKDistinct(self, nums: List[int], k: int) -> int:
        def at_most(x):
            count = left = distinct = 0
            freq = defaultdict(int)
            for right, v in enumerate(nums):
                if freq[v] == 0:
                    distinct += 1
                freq[v] += 1
                while distinct > x:
                    freq[nums[left]] -= 1
                    if freq[nums[left]] == 0:
                        distinct -= 1
                    left += 1
                count += right - left + 1
            return count
        return at_most(k) - at_most(k - 1)   # exactly k distinct

Time O(n) · Space O(k). The at-most identity (also used in 930, 1248) is the reusable idea for 'exactly k' counting.

4 · Interview playbook

  • Window or prefix? Non-negative values and a monotonic condition → sliding window. Negatives or "count subarrays with sum = k" → prefix sums + a map.
  • Fixed vs variable window: "of size k" is fixed (add/drop one); "longest/shortest with a property" is variable (grow right, shrink left).
  • Counting exactly k: use atMost(k) − atMost(k−1) — two window passes.
  • Seed the prefix map with {0: 1} (counts) or {0: -1} (indices) so a whole prefix is handled.
  • Range updates? Reach for a difference array; range queries? a prefix array (1D or 2D with inclusion–exclusion). Window max/min? a monotonic deque.

5 · Role notes

SDE / Python backend

Sliding windows power rate limiting, streaming aggregates, and log analysis; prefix sums and difference arrays back range queries and bulk updates. Know when negatives force a prefix-map over a window.

Data Science / ML / AI / GenAI

Rolling means/variances are fixed windows; cumulative sums are prefix arrays; context windows and n-gram scans are variable windows. Difference arrays model bulk interval updates efficiently.

6 · Review

Cheat sheet
  • "Of size k" → fixed window (add entering, drop leaving).
  • "Longest with a property" → variable window (grow right, shrink left while invalid).
  • "Shortest ≥ target" → variable window, shrink greedily.
  • "Count subarrays with exactly k …" → atMost(k) − atMost(k−1).
  • "Subarray sum = k / divisible by k / equal 0s-1s" (negatives ok) → prefix sum + map, seed {0: …}.
  • "Many range-sum queries" → prefix array (2D via inclusion–exclusion).
  • "Many range updates" → difference array, integrate once.
  • "Window max/min" → monotonic deque.

Concept checks

Why does a sliding window fail for "count subarrays with sum = k" when the array has negatives?
Adding an element no longer only increases the sum, so shrinking/growing isn't monotonic — the window can't decide when to move
Because negatives make the array unsorted
Because Python can't sum negative numbers efficiently
Sliding windows rely on a monotonic response: growing the window changes the metric in one direction. Negatives break that (a later element can lower the sum), so you can't know whether to move the left edge. Prefix sums + a hash map handle it instead.
To count subarrays with exactly k distinct integers, why compute atMost(k) − atMost(k−1)?
"Exactly k" equals "at most k" minus "at most k−1", and each atMost is an easy monotonic sliding window
Because k−1 is always faster to compute
To avoid using a hash map
A window counting "at most x distinct" is monotonic and easy; "exactly k" is not directly. Subtracting removes the subarrays with fewer than k distinct, leaving exactly k. The same trick counts sums, odds, etc.
