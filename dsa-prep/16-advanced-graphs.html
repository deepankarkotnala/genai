1 · Foundations

This chapter assumes you're comfortable with DFS, BFS, and Union-Find from Chapter 15. Read top to bottom — each weighted algorithm builds on the last. Already fluent? Skip to §2 Pattern library.

From unweighted to weighted: why BFS isn't enough

On an unweighted graph, BFS finds shortest paths because every edge costs the same — the first time you reach a node is via the fewest edges. Add weights (distances, times, costs) and that breaks: a path with more edges can be cheaper. We need algorithms that account for edge cost. The choice depends on the graph:

Pick by constraints: Dijkstra — non-negative weights, one source. Bellman-Ford — negative edges, or a limit on the number of edges. Floyd-Warshall — shortest paths between all pairs (small graphs). 0-1 BFS — weights are only 0 or 1.

Dijkstra: the weighted shortest-path workhorse

Dijkstra's algorithm finds shortest paths from one source when all edge weights are non-negative. It's BFS with a priority queue: always expand the closest unfinalised node next. Because weights are non-negative, once a node is popped its distance is final — extending any path can only make it longer.

Example — Dijkstra from a source
dijkstra.py
import heapq

def dijkstra(graph, source, n):        # graph[u] = [(v, weight), ...]
    dist = [float("inf")] * n
    dist[source] = 0
    pq = [(0, source)]                 # (distance, node)
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:                # stale entry — already finalised
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:        # relax the edge
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist

g = {0: [(1, 4), (2, 1)], 1: [(3, 1)], 2: [(1, 2), (3, 5)], 3: []}
print(dijkstra(g, 0, 4))               # [0, 3, 1, 4]
Output[0, 3, 1, 4]

The reach to node 1 is 3 (via 0→2→1, cost 1+2), not 4 (direct) — exactly the case plain BFS would get wrong. The d > dist[u] check skips outdated heap entries instead of using a decrease-key.

Bellman-Ford: negative edges and hop limits

Dijkstra fails with negative-weight edges. Bellman-Ford instead relaxes every edge, repeated V−1 times — enough for any shortest path (which has at most V−1 edges) to settle. Its round structure is also the natural way to bound the number of edges used, as in "at most k stops": run exactly k+1 rounds, relaxing off a snapshot of the previous round.

Floyd-Warshall: all-pairs shortest paths

When you need the shortest distance between every pair of nodes and the graph is small, Floyd-Warshall is the simplest tool — three nested loops. For each intermediate node k, it checks whether routing i → k → j beats the current i → j.

Example — Floyd-Warshall core
floyd.py
for k in range(n):                     # intermediate node
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
The loop order matters: k must be the outermost loop. It represents "shortest paths using only nodes 0..k as intermediates," built up one allowed intermediate at a time.

Minimum Spanning Trees: connect everything cheaply

A Minimum Spanning Tree connects all nodes with the least total edge weight. Two greedy algorithms build it. Kruskal's sorts all edges and adds the cheapest that doesn't form a cycle (using Union-Find) — best for sparse graphs. Prim's grows one tree outward, always adding the cheapest edge leaving it — best for dense graphs. Both are provably optimal.

💡
Kruskal or Prim?

Explicit, sparse edge list → Kruskal (sort + Union-Find). Dense / complete graph (like points on a plane) → Prim's O(n²), which avoids materialising every edge.

Specialist tools: Euler, 0-1 BFS, Tarjan

A few problems have their own signature technique. An Eulerian path uses every edge exactly once — built with Hierholzer's algorithm. 0-1 BFS replaces Dijkstra's heap with a deque when weights are only 0 or 1 (push 0-cost to the front, 1-cost to the back). Tarjan's low-link DFS finds bridges and articulation points — edges/nodes whose removal disconnects the graph.

⚠️
Advanced-graph pitfalls

Never run Dijkstra with negative edges — it can finalise a node too early. Skip stale heap entries with the d > dist[u] guard. In Floyd-Warshall, k must be the outermost loop. For hop-limited paths, relax Bellman-Ford off a snapshot so one round adds only one edge. And watch recursion depth in Tarjan's on large graphs.

1 LC 1436Destination City Easy Read the graph · the node with no outgoing edge

Problem. Given a list of directed paths that form a line, return the destination city — the one that never appears as a start. LeetCode 1436 ↗

Clarify: The paths form a single line with one endpoint? (Yes.) The destination has no outgoing path? (Yes.)

Hint 1
The destination is the only city that is never the start of a path.
Hint 2
Collect all start cities, then find the end city missing from that set.

How to think about it A graph-reading warm-up: no traversal needed. Gather every city that appears as a path's origin into a set. The destination is the unique endpoint that is never an origin — scan the ends and return the one absent from the start set.

destination_city.py
from typing import List

class Solution:
    def destCity(self, paths):
        starts = {a for a, b in paths}
        for a, b in paths:
            if b not in starts:
                return b

Time O(n) · Space O(n). Reading a graph by its degrees (here, out-degree 0) often beats traversing it.

2 LC 1557Minimum Vertices to Reach All Nodes Easy In-degree 0 nodes are the only sources

Problem. In a DAG, return the smallest set of vertices from which all nodes are reachable. LeetCode 1557 ↗

Clarify: Graph is acyclic (a DAG)? (Yes.) The answer is unique? (Yes.)

Hint 1
A node with an incoming edge can be reached from somewhere else — you never need it as a start.
Hint 2
So the answer is exactly the nodes with in-degree 0.

How to think about it A node that has any incoming edge is reachable from another node, so it never needs to be a starting vertex. Conversely, a node with no incoming edge can only be reached by starting there. Collect every node that appears as an edge's head, then return the nodes not in that set.

min_vertices.py
from typing import List

class Solution:
    def findSmallestSetOfVertices(self, n, edges):
        has_incoming = {b for a, b in edges}
        return [node for node in range(n) if node not in has_incoming]

Time O(V + E) · Space O(V). In a DAG, the mandatory starting points are precisely the in-degree-0 nodes.

3 LC 1615Maximal Network Rank Medium Degree sum minus a shared edge

Problem. The network rank of two cities is the total number of roads touching either; return the maximum rank over all city pairs. LeetCode 1615 ↗

Clarify: A road connecting the two chosen cities counts once, not twice? (Yes.)

Hint 1
Rank of (i, j) = degree[i] + degree[j], minus 1 if a road directly joins them.
Hint 2
Track degrees and the set of directly-connected pairs, then try all pairs.

How to think about it Count each city's degree and remember which pairs share a direct road. For every pair, the rank is the sum of their degrees, minus one if a road directly connects them (that road was double-counted). Take the maximum over all pairs — with n small, the O(n²) scan is fine.

network_rank.py
from typing import List

class Solution:
    def maximalNetworkRank(self, n, roads):
        deg = [0] * n
        linked = set()
        for a, b in roads:
            deg[a] += 1
            deg[b] += 1
            linked.add((a, b))
            linked.add((b, a))
        best = 0
        for i in range(n):
            for j in range(i + 1, n):
                rank = deg[i] + deg[j] - (1 if (i, j) in linked else 0)
                best = max(best, rank)
        return best

Time O(n²) · Space O(V + E). Degrees plus a shared-edge correction — no traversal required.

4 LC 261Graph Valid Tree Medium Union-Find · n−1 edges and no cycle

Problem. Given n nodes and an undirected edge list, decide whether they form a valid tree. LeetCode 261 ↗

Clarify: A tree is connected and acyclic? (Yes.) Exactly n−1 edges? (A tree always has n−1.)

Hint 1
A tree on n nodes has exactly n−1 edges — reject anything else immediately.
Hint 2
With n−1 edges, the graph is a tree iff it has no cycle; Union-Find detects a cycle when an edge joins two already-connected nodes.

How to think about it Two conditions make a tree: exactly n−1 edges and no cycle. First reject any edge count other than n−1. Then Union-Find the edges: if an edge ever connects two nodes already sharing a root, there's a cycle. Passing both checks means acyclic and (with n−1 edges) automatically connected — a tree.

valid_tree.py
from typing import List

class Solution:
    def validTree(self, n, edges):
        if len(edges) != n - 1:          # a tree has exactly n-1 edges
            return False
        parent = list(range(n))

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra == rb:                 # edge inside one component ⇒ cycle
                return False
            parent[ra] = rb
        return True                      # n-1 edges + no cycle ⇒ connected tree

Time O(E·α) · Space O(V). 'n−1 edges + acyclic ⇒ connected' is the counting shortcut that avoids a separate connectivity check.

5 LC 743Network Delay Time Medium Dijkstra · shortest paths from one source

Problem. A signal starts at node k and travels along weighted directed edges. Return the time for all n nodes to receive it, or −1. LeetCode 743 ↗

Clarify: Edge weights are non-negative travel times? (Yes.) Answer is the max shortest-path distance? (Yes.)

Hint 1
Non-negative weights + single source ⇒ Dijkstra's algorithm.
Hint 2
The answer is the largest shortest-path distance; if any node is unreachable, return −1.

How to think about it This is single-source shortest paths on a non-negatively weighted graph — Dijkstra's. Use a min-heap of (distance, node); pop the closest unfinalised node, finalise it, and relax its out-edges. The time for everyone to receive the signal is the maximum finalised distance; if fewer than n nodes are reached, return −1.

network_delay.py
import heapq
from collections import defaultdict
from typing import List

class Solution:
    def networkDelayTime(self, times, n, k):
        graph = defaultdict(list)
        for u, v, w in times:
            graph[u].append((v, w))
        dist = {}
        pq = [(0, k)]
        while pq:
            d, u = heapq.heappop(pq)
            if u in dist:
                continue
            dist[u] = d
            for v, w in graph[u]:
                if v not in dist:
                    heapq.heappush(pq, (d + w, v))
        return max(dist.values()) if len(dist) == n else -1

Time O(E·log V) · Space O(V + E). Dijkstra with a heap is the workhorse for weighted shortest paths — memorise this template.

6 LC 1584Min Cost to Connect All Points Medium MST (Prim) · minimum connection cost

Problem. Connect all points with edges of Manhattan-distance cost so the total cost is minimum. Return that cost. LeetCode 1584 ↗

Clarify: Cost between two points is their Manhattan distance? (Yes.) All points must be connected? (Yes.)

Hint 1
'Connect everything at minimum total cost' is a Minimum Spanning Tree.
Hint 2
With a dense (complete) graph, Prim's O(n²) — grow the tree by repeatedly adding the nearest outside point.

How to think about it Minimum cost to connect all nodes is the classic Minimum Spanning Tree. Since every pair of points is implicitly connected (a complete graph), Prim's O(n²) form fits: keep each outside point's shortest distance to the growing tree, repeatedly absorb the nearest one, and update its neighbours' distances. Summing the absorbed distances gives the MST cost.

connect_points.py
from typing import List

class Solution:
    def minCostConnectPoints(self, points):
        n = len(points)
        in_tree = [False] * n
        dist = [float("inf")] * n
        dist[0] = 0
        total = 0
        for _ in range(n):
            u = -1
            for i in range(n):                       # pick nearest outside the tree
                if not in_tree[i] and (u == -1 or dist[i] < dist[u]):
                    u = i
            in_tree[u] = True
            total += dist[u]
            xu, yu = points[u]
            for v in range(n):
                if not in_tree[v]:
                    d = abs(xu - points[v][0]) + abs(yu - points[v][1])
                    if d < dist[v]:
                        dist[v] = d
        return total

Time O(n²) · Space O(n). Prim's grows one tree outward; on a dense graph it beats sorting all O(n²) edges for Kruskal.

7 LC 1514Path with Maximum Probability Medium Dijkstra on a max-product

Problem. Edges carry success probabilities. Return the maximum product of probabilities along any path from start to end. LeetCode 1514 ↗

Clarify: Maximise the product of edge probabilities (all in [0, 1])? (Yes.) Undirected edges? (Yes.)

Hint 1
Maximising a product of values ≤ 1 behaves like a shortest-path problem — use Dijkstra with a MAX-heap.
Hint 2
Always expand the currently-best-probability node first; the first pop of the end node is optimal.

How to think about it Dijkstra adapted to maximise a product. Because every probability is ≤ 1, extending a path never increases it, so the greedy 'expand the best-so-far node first' still works. Use a max-heap (negate probabilities), and relax an edge when the new product beats a node's recorded best. The first time you pop the end node, that product is optimal.

max_probability.py
import heapq
from typing import List

class Solution:
    def maxProbability(self, n, edges, succProb, start_node, end_node):
        graph = defaultdict(list)
        for (a, b), p in zip(edges, succProb):
            graph[a].append((b, p))
            graph[b].append((a, p))
        best = [0.0] * n
        best[start_node] = 1.0
        pq = [(-1.0, start_node)]                     # max-heap via negation
        while pq:
            prob, u = heapq.heappop(pq)
            prob = -prob
            if u == end_node:
                return prob
            if prob < best[u]:
                continue
            for v, pe in graph[u]:
                if prob * pe > best[v]:
                    best[v] = prob * pe
                    heapq.heappush(pq, (-best[v], v))
        return 0.0

Time O(E·log V) · Space O(V + E). Dijkstra generalises beyond sums: any monotonic combine (max-product here) works if extending a path can't improve the metric.

8 LC 1631Path with Minimum Effort Medium Dijkstra minimax on a grid

Problem. Travel from top-left to bottom-right of a height grid; a path's effort is its largest adjacent height difference. Minimise that effort. LeetCode 1631 ↗

Clarify: Effort = maximum absolute height difference along the path? (Yes.) 4-directional moves? (Yes.)

Hint 1
The cost of a path is a MAX over its steps, not a sum — Dijkstra still applies with a tweaked relaxation.
Hint 2
Relax with new_effort = max(current_effort, |height difference|).

How to think about it A minimax shortest path: minimise the largest single step. Run Dijkstra over grid cells where a cell's 'distance' is the smallest possible max-difference to reach it. Relax a neighbour with max(effort_so_far, |Δheight|). The first time you pop the bottom-right cell, its value is the minimum possible effort.

min_effort.py
from typing import List

class Solution:
    def minimumEffortPath(self, heights):
        R, C = len(heights), len(heights[0])
        effort = [[float("inf")] * C for _ in range(R)]
        effort[0][0] = 0
        pq = [(0, 0, 0)]                              # (effort so far, r, c)
        while pq:
            e, r, c = heapq.heappop(pq)
            if r == R - 1 and c == C - 1:
                return e
            if e > effort[r][c]:
                continue
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C:
                    ne = max(e, abs(heights[nr][nc] - heights[r][c]))
                    if ne < effort[nr][nc]:
                        effort[nr][nc] = ne
                        heapq.heappush(pq, (ne, nr, nc))
        return 0

Time O(cells·log cells) · Space O(cells). Swapping Dijkstra's 'sum' relaxation for 'max' turns it into a minimax path finder.

9 LC 1976Number of Ways to Arrive at Destination Medium Dijkstra + shortest-path counting

Problem. Count the number of distinct shortest paths from intersection 0 to n−1 (mod 1e9+7). LeetCode 1976 ↗

Clarify: Count only the paths of minimum total time? (Yes.) Return the count modulo 1e9+7? (Yes.)

Hint 1
Run Dijkstra, but alongside each node's distance keep a count of shortest paths to it.
Hint 2
When you find a strictly shorter path, reset the count; when you tie the best, add to it.

How to think about it Dijkstra augmented with a path counter. Keep ways[v] = number of shortest paths to v. When relaxing u→v: if it strictly improves dist[v], set ways[v] = ways[u]; if it ties the best distance, add ways[u] (mod 1e9+7). The answer is ways[n−1].

count_paths.py
import heapq
from collections import defaultdict
from typing import List

class Solution:
    def countPaths(self, n, roads):
        MOD = 10 ** 9 + 7
        graph = defaultdict(list)
        for u, v, w in roads:
            graph[u].append((v, w))
            graph[v].append((u, w))
        dist = [float("inf")] * n
        ways = [0] * n
        dist[0] = 0
        ways[0] = 1
        pq = [(0, 0)]
        while pq:
            d, u = heapq.heappop(pq)
            if d > dist[u]:
                continue
            for v, w in graph[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    ways[v] = ways[u]
                    heapq.heappush(pq, (nd, v))
                elif nd == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % MOD
        return ways[n - 1] % MOD

Time O(E·log V) · Space O(V + E). 'Reset on improve, accumulate on tie' is the standard way to count shortest paths during Dijkstra.

10 LC 787Cheapest Flights Within K Stops Medium Bellman-Ford · bounded edge count

Problem. Find the cheapest price from src to dst using at most k stops (k+1 flights), or −1. LeetCode 787 ↗

Clarify: At most k stops means at most k+1 edges? (Yes.) Prices are non-negative? (Yes.)

Hint 1
The 'at most k+1 edges' cap is exactly what Bellman-Ford's round count controls.
Hint 2
Relax all edges k+1 times, but relax off a SNAPSHOT of last round's distances so each round adds one edge.

How to think about it Plain Dijkstra can't respect a hop limit, but Bellman-Ford can. Run k+1 relaxation rounds; each round may extend paths by one edge. Crucially, relax using a snapshot of the previous round's distances (tmp = dist[:]) so a single round can't chain multiple new edges. After k+1 rounds, dist[dst] is the cheapest price within the hop limit.

cheapest_flights.py
from typing import List

class Solution:
    def findCheapestPrice(self, n, flights, src, dst, k):
        INF = float("inf")
        dist = [INF] * n
        dist[src] = 0
        for _ in range(k + 1):                       # at most k+1 edges
            tmp = dist[:]
            for u, v, w in flights:
                if dist[u] != INF and dist[u] + w < tmp[v]:
                    tmp[v] = dist[u] + w
            dist = tmp
        return dist[dst] if dist[dst] != INF else -1

Time O(k·E) · Space O(V). When a shortest path has an edge-count constraint, Bellman-Ford's round structure is the natural fit.

11 LC 1135Connecting Cities with Minimum Cost Medium MST (Kruskal) · sort edges, union

Problem. Connect all n cities with the given weighted connections at minimum total cost, or −1 if impossible. LeetCode 1135 ↗

Clarify: Cities are labelled 1..n? (Yes.) Return −1 if they can't all be connected? (Yes.)

Hint 1
Minimum total connection cost over an explicit edge list ⇒ Kruskal's MST.
Hint 2
Sort edges by cost; add an edge (via Union-Find) only if it links two different components.

How to think about it Kruskal's MST. Sort the connections by cost and process them cheapest-first, using Union-Find to add an edge only when its endpoints are in different components (otherwise it would form a cycle). If you end up using exactly n−1 edges, all cities are connected; fewer means it's impossible, so return −1.

connecting_cities.py
from typing import List

class Solution:
    def minimumCost(self, n, connections):
        connections.sort(key=lambda c: c[2])
        parent = list(range(n + 1))                  # cities are 1..n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        total = used = 0
        for a, b, cost in connections:
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[ra] = rb
                total += cost
                used += 1
        return total if used == n - 1 else -1

Time O(E·log E) · Space O(n). Kruskal (sort + Union-Find) shines when edges are given explicitly and the graph is sparse.

12 LC 1334Find the City With the Smallest Number of Neighbors Medium Floyd-Warshall · all-pairs shortest paths

Problem. Find the city that can reach the fewest others within a distance threshold (largest index on ties). LeetCode 1334 ↗

Clarify: Need shortest distances between ALL pairs? (Yes.) On ties, return the greater index? (Yes.)

Hint 1
You need shortest paths between every pair of cities — with small n, Floyd-Warshall is simplest.
Hint 2
Then count, for each city, how many others are within the threshold.

How to think about it This asks for all-pairs shortest paths, and with n small the O(n³) Floyd-Warshall is cleanest: for each intermediate k, relax every (i, j) through k. Then count each city's reachable neighbours within the threshold and pick the city with the fewest — scanning in ascending order with ≤ naturally keeps the largest index on ties.

find_city.py
from typing import List

class Solution:
    def findTheCity(self, n, edges, distanceThreshold):
        INF = float("inf")
        dist = [[INF] * n for _ in range(n)]
        for i in range(n):
            dist[i][i] = 0
        for u, v, w in edges:
            dist[u][v] = dist[v][u] = w
        for k in range(n):                           # Floyd–Warshall
            for i in range(n):
                dik = dist[i][k]
                if dik == INF:
                    continue
                for j in range(n):
                    if dik + dist[k][j] < dist[i][j]:
                        dist[i][j] = dik + dist[k][j]
        best_city, fewest = 0, n + 1
        for i in range(n):
            reachable = sum(1 for j in range(n) if i != j and dist[i][j] <= distanceThreshold)
            if reachable <= fewest:                  # ties ⇒ larger index wins
                fewest = reachable
                best_city = i
        return best_city

Time O(n³) · Space O(n²). When you need every pair's distance and n is small, Floyd-Warshall's triple loop is the shortest code to write.

13 LC 721Accounts Merge Medium Union-Find · group shared emails

Problem. Merge accounts that share any email; return each merged account as a name followed by sorted unique emails. LeetCode 721 ↗

Clarify: Accounts merge transitively through shared emails? (Yes.) Emails sorted within each account? (Yes.)

Hint 1
Two accounts belong together if they share an email — that's a connectivity problem.
Hint 2
Union all emails within each account, then group emails by their root.

How to think about it Union-Find over emails. Within each account, union its first email with every other, so all emails of transitively-connected accounts share a root. Record each email's owner name along the way. Finally, bucket emails by root, sort each bucket, and prepend the owner's name.

accounts_merge.py
from collections import defaultdict
from typing import List

class Solution:
    def accountsMerge(self, accounts):
        parent = {}

        def find(x):
            parent.setdefault(x, x)
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            parent[find(a)] = find(b)

        owner = {}
        for account in accounts:
            name = account[0]
            for email in account[1:]:
                owner[email] = name
                union(account[1], email)
        groups = defaultdict(list)
        for email in owner:
            groups[find(email)].append(email)
        return [[owner[root]] + sorted(emails) for root, emails in groups.items()]

Time O(N·α + N·log N) · Space O(N). Union-Find turns 'merge things that share an attribute' into a clean grouping.

Problem. Given equations like a==b and a!=c, decide whether they can all hold simultaneously. LeetCode 990 ↗

Hint 1
Equalities force variables into the same group — union them first.

Then every inequality must join two DIFFERENT groups, or it's contradictory.

How to think about it Two passes over 26 letters with Union-Find. First union every pair joined by ==, forming equality classes. from typing import List

class Solution:
    def equationsPossible(self, equations):

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

15 LC 2492Minimum Score of a Path Between Two Cities Medium Union-Find · min edge in a component

Problem. A path's score is the minimum edge weight on it. Return the minimum score of any path from city 1 to city n. LeetCode 2492 ↗

Hint 1
Because you can revisit nodes, you can always detour to include any edge in the same connected component.
Hint 2
So the answer is simply the minimum-weight edge in the component containing city 1 (and n).

How to think about it Since paths may repeat cities and edges, from city 1 you can reach and traverse any edge in its connected component, then continue to n. So the minimum score is just the smallest edge weight within that component. Union all edges, find city 1's root, and take the minimum weight among edges whose endpoint shares that root.

min_score_path.py
from typing import List

class Solution:
    def minScore(self, n, roads):
        parent = list(range(n + 1))

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]

        for a, b, d in roads:

16 LC 310Minimum Height Trees Medium Topological leaf-peeling

Problem. Return all roots that minimise a tree's height when the graph is rerooted there (1 or 2 answers). LeetCode 310 ↗

Clarify: The graph is a tree (n−1 edges, connected)? (Yes.) At most two centroids exist? (Yes.)

Hint 1
The best roots are the graph's center(s) — found by repeatedly trimming leaves.
Hint 2
Peel all current leaves layer by layer; the last 1 or 2 nodes remaining are the answer.

How to think about it The height-minimising roots are the tree's centroid(s), which you find by topological leaf-peeling: repeatedly remove all current leaves (degree-1 nodes), shrinking inward. When 2 or fewer nodes remain, they're the center(s) — the minimum-height-tree roots. This is Kahn's-style trimming applied to an undirected tree.

min_height_trees.py
from typing import List

class Solution:
    def findMinHeightTrees(self, n, edges):
        if n == 1:
            return [0]
        graph = defaultdict(set)
        for a, b in edges:
            graph[a].add(b)
            graph[b].add(a)
        leaves = [x for x in range(n) if len(graph[x]) == 1]
        remaining = n
        while remaining > 2:                         # peel leaf layers inward
            remaining -= len(leaves)
            new_leaves = []
            for leaf in leaves:
                nb = graph[leaf].pop()
                graph[nb].discard(leaf)
                if len(graph[nb]) == 1:
                    new_leaves.append(nb)
            leaves = new_leaves
        return leaves

Time O(V + E) · Space O(V + E). Peeling leaves toward the center beats rooting a BFS at every node (O(V²)).

17 LC 2359Find Closest Node to Given Two Nodes Medium Functional graph · two walks

Problem. Each node has at most one outgoing edge. Find the node reachable from both node1 and node2 minimising the larger of the two distances. LeetCode 2359 ↗

Clarify: Each node has ≤ 1 outgoing edge (a functional graph)? (Yes.) Minimise max(dist1, dist2), smallest index on ties? (Yes.)

Hint 1
Out-degree ≤ 1 means from each start there's a single chain — just walk it, recording distances.
Hint 2

How to think about it Because every node has at most one out-edge, the reachable set from a start is a single path (until it loops or ends). closest_node.py
from typing import List

class Solution:
    def closestMeetingNode(self, edges, node1, node2):
        def distances(start):
            d, cur, step = {}, start, 0
            while cur != -1 and cur not in d:
                d[cur] = step
                step += 1
                cur = edges[cur]
            return d

        d1, d2 = distances(node1), distances(node2)
        best, best_dist = -1, float("inf")
        for i in range(len(edges)):
            if i in d1 and i in d2:
                m = max(d1[i], d2[i])
                if m < best_dist:
                    best_dist, best = m, i
        return best

18 LC 1786Number of Restricted Paths Medium Dijkstra from n + DAG path counting

Problem. Count paths from node 1 to n where each step strictly decreases the distance-to-n (mod 1e9+7). LeetCode 1786 ↗

Clarify: A restricted path has strictly decreasing distToLastNode at every step? (Yes.) Count modulo 1e9+7? (Yes.)

Hint 1
First compute every node's shortest distance to node n with Dijkstra.
Hint 2
The 'strictly decreasing distance' rule makes the valid edges a DAG — count paths by processing nodes in increasing distance order.

How to think about it Two phases. First run Dijkstra from node n to get every node's dist to n. The restriction (each step must strictly decrease dist) makes valid moves form a DAG. Process nodes in increasing dist order and set ways[u] = Σ ways[v] over neighbours with smaller dist (seeding ways[n] = 1). The answer is ways[1].

restricted_paths.py
import heapq
from collections import defaultdict
from typing import List

class Solution:
    def countRestrictedPaths(self, n, edges):
        MOD = 10 ** 9 + 7
        graph = defaultdict(list)
        for u, v, w in edges:
            graph[u].append((v, w))
            graph[v].append((u, w))
        dist = [float("inf")] * (n + 1)
        dist[n] = 0
        pq = [(0, n)]                                 # Dijkstra outward from node n
        while pq:
            d, u = heapq.heappop(pq)
            if d > dist[u]:
                continue
            for v, w in graph[u]:
                if d + w < dist[v]:
                    dist[v] = d + w
                    heapq.heappush(pq, (dist[v], v))
        ways = [0] * (n + 1)
        ways[n] = 1
        for u in sorted(range(1, n + 1), key=lambda x: dist[x]):   # increasing distance
            for v, w in graph[u]:
                if dist[v] < dist[u]:                 # only strictly-decreasing steps
                    ways[u] = (ways[u] + ways[v]) % MOD
        return ways[1] % MOD

Time O(E·log V) · Space O(V + E). Compute a potential (distance) first, then a monotonicity rule turns the graph into a DAG you can count over.

19 LC 332Reconstruct Itinerary Hard Eulerian path · Hierholzer's algorithm

Problem. Given airline tickets, reconstruct the itinerary that uses every ticket once, starting at JFK, with smallest lexical order. LeetCode 332 ↗

itinerary.py
from collections import defaultdict
from typing import List

class Solution:
    def findItinerary(self, tickets):
        graph = defaultdict(list)
        for src, dst in sorted(tickets, reverse=True):
            graph[src].append(dst)                    # smallest dst ends up on top
        route, stack = [], ["JFK"]
        while stack:
            while graph[stack[-1]]:
                stack.append(graph[stack[-1]].pop())
            route.append(stack.pop())
        return route[::-1]

20 LC 778Swim in Rising Water Hard Dijkstra minimax on a grid

Problem. Water level rises over time; you can swim between cells only when the level ≥ both elevations. Return the earliest time to reach the bottom-right. LeetCode 778 ↗

Clarify: The time to enter a cell is its elevation, and a path's time is its maximum elevation? (Yes.)

Hint 1
You want the path whose MAXIMUM elevation is as small as possible — a minimax path.
Hint 2
Dijkstra with a min-heap keyed on the path's running maximum elevation.

How to think about it The earliest arrival time equals the minimum over all paths of the path's maximum elevation — a minimax problem. Run Dijkstra from the top-left with a min-heap keyed on max(time_so_far, cell_elevation). The first time you pop the bottom-right cell, that key is the least possible peak elevation, hence the earliest safe time.

swim_in_water.py
from typing import List

class Solution:
    def swimInWater(self, grid):
        n = len(grid)
        seen = [[False] * n for _ in range(n)]
        pq = [(grid[0][0], 0, 0)]                      # (max elevation on path, r, c)
        while pq:
            t, r, c = heapq.heappop(pq)
            if seen[r][c]:
                continue
            seen[r][c] = True
            if r == n - 1 and c == n - 1:
                return t
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < n and not seen[nr][nc]:
                    heapq.heappush(pq, (max(t, grid[nr][nc]), nr, nc))
        return -1

Time O(n²·log n) · Space O(n²). Same minimax-Dijkstra shape as Path with Minimum Effort — recognise the family.

21 LC 1368Minimum Cost to Make at Least One Valid Path Hard 0-1 BFS · deque

Problem. Each cell has an arrow; following it is free, changing it costs 1. Return the minimum cost to make a valid path from top-left to bottom-right. LeetCode 1368 ↗

Clarify: Following a cell's existing arrow costs 0, any other direction costs 1? (Yes.)

Hint 1
Edges have weights of only 0 or 1 — that's the exact setting for 0-1 BFS.
Hint 2
Use a deque: push 0-cost moves to the FRONT, 1-cost moves to the BACK.

How to think about it Model each cell's four moves as edges of weight 0 (the arrow's own direction) or 1 (any redirection). With only 0/1 weights, 0-1 BFS gives shortest paths in linear time: a deque replaces Dijkstra's heap — append free moves to the front and paid moves to the back, so the deque stays sorted by cost. The distance to the bottom-right is the answer.

min_cost_path_grid.py
from typing import List

class Solution:
    def minCost(self, grid):
        R, C = len(grid), len(grid[0])
        arrows = {1: (0, 1), 2: (0, -1), 3: (1, 0), 4: (-1, 0)}
        dist = [[float("inf")] * C for _ in range(R)]
        dist[0][0] = 0
        dq = deque([(0, 0)])
        while dq:                                     # 0-1 BFS
            r, c = dq.popleft()
            for d, (dr, dc) in arrows.items():
                nr, nc = r + dr, c + dc
                cost = 0 if grid[r][c] == d else 1
                if 0 <= nr < R and 0 <= nc < C and dist[r][c] + cost < dist[nr][nc]:
                    dist[nr][nc] = dist[r][c] + cost
                    if cost == 0:
                        dq.appendleft((nr, nc))       # free move ⇒ front
                    else:
                        dq.append((nr, nc))
        return dist[R - 1][C - 1]

Time O(cells) · Space O(cells). 0-1 BFS is a deque-based Dijkstra specialised to weights in {0, 1} — no log factor.

22 LC 2360Longest Cycle in a Graph Hard Functional graph · timestamped walk

Problem. Each node has at most one outgoing edge. Return the length of the longest cycle, or −1 if none exists. LeetCode 2360 ↗

Clarify: Out-degree ≤ 1 (a functional graph)? (Yes.) Return −1 when acyclic? (Yes.)

Hint 1
Follow the single chain from each unvisited node, stamping each with a step index.
Hint 2
If you re-enter a node still on the current walk, the cycle length is the step difference.

How to think about it In a functional graph, follow each node's single out-edge, stamping a step index as you go. If you re-enter a node that's still on the current walk, you've closed a cycle whose length is the difference of step indices. Mark whole walks 'done' afterward so shared tails aren't re-explored. Track the maximum cycle length across all walks.

longest_cycle.py
from typing import List

class Solution:
    def longestCycle(self, edges):
        n = len(edges)
        state = [0] * n                               # 0 unseen, 1 on-path, 2 done
        ans = -1
        for i in range(n):
            if state[i]:
                continue
            order, cur, step = {}, i, 0
            while cur != -1 and state[cur] == 0:
                state[cur] = 1
                order[cur] = step
                step += 1
                cur = edges[cur]
            if cur != -1 and state[cur] == 1:         # closed a cycle this walk
                ans = max(ans, step - order[cur])
            node = i                                   # retire the whole walk
            while node != -1 and state[node] == 1:
                state[node] = 2
                node = edges[node]
        return ans

Time O(n) · Space O(n). The three-state walk (unseen / on-path / done) both finds the cycle and avoids reprocessing.

23 LC 1192Critical Connections in a Network Hard Tarjan · bridges (low-link)

Problem. Return all critical connections (bridges) — edges whose removal disconnects the network. LeetCode 1192 ↗

Clarify: A bridge is an edge not on any cycle? (Yes.) Undirected connected graph? (Yes.)

Hint 1
A bridge is an edge that lies on no cycle — detect with Tarjan's low-link values.
Hint 2
During DFS, (u, v) is a bridge iff the lowest reachable discovery time from v exceeds disc[u].

How to think about it Tarjan's bridge algorithm. DFS the graph assigning each node a discovery time disc and a low = the earliest node reachable from its subtree via one back-edge. For a tree edge u→v, if low[v] > disc[u], then v's subtree has no back-edge above u, so removing (u, v) disconnects it — a bridge.

critical_connections.py
from collections import defaultdict
from typing import List

class Solution:
    def criticalConnections(self, n, connections):
        graph = defaultdict(list)
        for a, b in connections:
            graph[a].append(b)
            graph[b].append(a)
        disc = [-1] * n
        low = [0] * n
        timer = [0]
        bridges = []

        def dfs(u, parent):
            disc[u] = low[u] = timer[0]
            timer[0] += 1
            for v in graph[u]:
                if v == parent:
                    continue
                if disc[v] == -1:
                    dfs(v, u)
                    low[u] = min(low[u], low[v])
                    if low[v] > disc[u]:              # no back-edge over (u,v)
                        bridges.append([u, v])
                else:
                    low[u] = min(low[u], disc[v])

        dfs(0, -1)
        return bridges

Time O(V + E) · Space O(V + E). Low-link values are the core of Tarjan's — the same machinery finds articulation points and SCCs.

24 LC 1489Critical and Pseudo-Critical Edges in MST Hard MST + edge inclusion/exclusion tests

Problem. Classify each edge as critical (in every MST), pseudo-critical (in some MST), or neither. LeetCode 1489 ↗

Clarify: Critical = removing it raises the MST weight; pseudo-critical = it can appear in some MST but isn't critical? (Yes.)

Hint 1
Compute the base MST weight with Kruskal.
Hint 2
An edge is critical if excluding it makes the MST heavier (or disconnects); pseudo-critical if forcing it in still achieves the base weight.

How to think about it First compute the base MST weight. For each edge, run two modified Kruskals: skip it — if the resulting MST is heavier or impossible, the edge is critical. Otherwise force it in first — if an MST of the base weight still results, it's pseudo-critical. Sorting edges once (keeping original indices) lets both tests reuse the order.

critical_mst_edges.py
from typing import List

class Solution:
    def findCriticalAndPseudoCriticalEdges(self, n, edges):
        indexed = sorted((w, u, v, i) for i, (u, v, w) in enumerate(edges))

        def mst(skip=-1, force=-1):
            parent = list(range(n))

            def find(x):
                while parent[x] != x:
                    parent[x] = parent[parent[x]]
                    x = parent[x]
                return x

            total = count = 0
            if force != -1:                          # pre-include one edge
                w, u, v, _ = indexed[force]
                parent[find(u)] = find(v)
                total, count = w, 1
            for j, (w, u, v, i) in enumerate(indexed):
                if j == skip:
                    continue
                ru, rv = find(u), find(v)
                if ru != rv:
                    parent[ru] = rv
                    total += w
                    count += 1
            return total if count == n - 1 else float("inf")

        base = mst()
        critical, pseudo = [], []
        for j, (w, u, v, i) in enumerate(indexed):
            if mst(skip=j) > base:                    # removing it worsens the MST
                critical.append(i)
            elif mst(force=j) == base:                # forcing it keeps the MST
                pseudo.append(i)
        return [critical, pseudo]

Time O(E²·α) · Space O(E). 'Exclude to test critical, include to test pseudo-critical' is the standard MST-sensitivity technique.

25 LC 882Reachable Nodes in Subdivided Graph Hard Dijkstra + per-edge budget

Problem. Edges are subdivided into intermediate nodes. Return how many nodes are reachable within maxMoves moves. LeetCode 882 ↗

Clarify: Each edge holds cnt intermediate nodes; crossing it costs cnt+1 moves? (Yes.) Count reachable main + subdivided nodes? (Yes.)

Hint 1
Dijkstra over the ORIGINAL nodes gives the moves used to reach each one.
Hint 2
On each edge, the subdivided nodes reachable = min(cnt, moves left from each end), avoiding double counts.

How to think about it Dijkstra over the original nodes gives dist[u], the moves used to reach each. Every reached main node counts. For each edge (u, v, cnt), the subdivided nodes reachable from u are min(cnt, maxMoves − dist[u]) and similarly from v; add min(cnt, from_u + from_v) so nodes reachable from both ends aren't double-counted.

reachable_nodes.py
from typing import List

class Solution:
    def reachableNodes(self, edges, maxMoves, n):
        graph = defaultdict(list)
        for u, v, cnt in edges:
            graph[u].append((v, cnt))
            graph[v].append((u, cnt))
        dist = {0: 0}
        used_on_edge = {}
        reached_main = set()
        pq = [(0, 0)]
        while pq:
            d, u = heapq.heappop(pq)
            if u in reached_main:
                continue
            reached_main.add(u)
            for v, cnt in graph[u]:
                used_on_edge[(u, v)] = min(cnt, maxMoves - d)     # subdivided nodes we touch
                nd = d + cnt + 1
                if v not in reached_main and nd <= maxMoves and (v not in dist or nd < dist[v]):
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        result = len(reached_main)
        for u, v, cnt in edges:
            a = used_on_edge.get((u, v), 0)
            b = used_on_edge.get((v, u), 0)
            result += min(cnt, a + b)                 # avoid double-counting shared nodes
        return result

Time O(E·log V) · Space O(V + E). Run Dijkstra on the compressed graph, then account for the subdivided nodes with a per-edge budget.

26 LC 1568Minimum Days to Disconnect Island Hard Connectivity · the answer is 0, 1 or 2

Problem. Each day you may sink one land cell. Return the minimum days to make the grid have not exactly one island. LeetCode 1568 ↗

Clarify: 'Disconnected' means 0 islands or more than 1? (Yes.) Answer is provably at most 2? (Yes.)

Hint 1
The answer can only be 0, 1, or 2 — a graph can always be disconnected by removing at most 2 nodes.
Hint 2
Check 0 (already disconnected), then try removing each single cell for 1; otherwise it's 2.

How to think about it A key fact: any grid can be disconnected by removing at most two cells, so the answer is 0, 1, or 2. If the grid isn't exactly one island, return 0. Otherwise try sinking each land cell in turn and re-count islands; if any single removal disconnects it, return 1. Failing that, 2 always works.

min_days_disconnect.py
from typing import List

class Solution:
    def minDays(self, grid):
        R, C = len(grid), len(grid[0])

        def islands():
            seen = [[False] * C for _ in range(R)]
            count = 0
            for i in range(R):
                for j in range(C):
                    if grid[i][j] == 1 and not seen[i][j]:
                        count += 1
                        stack = [(i, j)]
                        seen[i][j] = True
                        while stack:
                            r, c = stack.pop()
                            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                                nr, nc = r + dr, c + dc
                                if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] == 1 and not seen[nr][nc]:
                                    seen[nr][nc] = True
                                    stack.append((nr, nc))
            return count

        if islands() != 1:                            # already disconnected
            return 0
        for i in range(R):
            for j in range(C):
                if grid[i][j] == 1:
                    grid[i][j] = 0
                    if islands() != 1:                # one removal splits it
                        grid[i][j] = 1
                        return 1
                    grid[i][j] = 1
        return 2                                       # otherwise two always suffice

Time O((R·C)²) · Space O(R·C). Bounding the answer to ≤ 2 (an articulation-point fact) collapses a scary problem into a small brute force.

4 · Interview playbook

  • Weighted shortest path? Non-negative weights → Dijkstra. Negative edges or a hop cap → Bellman-Ford. All pairs on a small graph → Floyd-Warshall. Weights only 0/1 → 0-1 BFS.
  • Dijkstra tweaks generalise: max-product (probabilities), minimax (effort/elevation), and path counting all reuse the heap with a different relaxation.
  • Connect everything cheaply? Minimum Spanning Tree — Kruskal (sparse, sort + Union-Find) or Prim's (dense, grow outward).
  • Union-Find still solves grouping, consistency (equations), and component queries — reach for it before writing a traversal.
  • Spot the specialist: "use every edge" → Eulerian path (Hierholzer); "edge whose removal disconnects" → Tarjan bridges; functional graph (out-degree ≤ 1) → just follow the chain.

6 · Review

Cheat sheet
  • Shortest path, non-negative weights, one source → Dijkstra (min-heap).
  • Negative edges / "at most k stops" → Bellman-Ford (relax in rounds).
  • All-pairs shortest paths, small n → Floyd-Warshall (k outermost).
  • Connect all nodes at minimum cost → MST: Kruskal (sparse) or Prim (dense).
  • Max-product / minimax path / count shortest paths → Dijkstra with a tweaked relaxation.
  • Weights only 0 or 1 → 0-1 BFS (deque).
  • Grouping / consistency / component min → Union-Find.
  • Use every edge once → Eulerian path (Hierholzer); edge whose removal disconnects → Tarjan bridges.

Concept checks

Why can't Dijkstra's algorithm handle negative-weight edges?
Dijkstra finalises a node the moment it's popped, assuming no later path can be shorter — but a negative edge could create a cheaper path to an already-finalised node
Because the priority queue cannot store negative numbers
Because negative edges always create infinite loops
Dijkstra's correctness rests on non-negativity: once the closest unfinalised node is popped, no unprocessed path can undercut it. A negative edge violates that — a longer route through it might be cheaper — so a node could be finalised too early. Bellman-Ford, which relaxes all edges repeatedly, is the fix.
When is 0-1 BFS preferable to Dijkstra?
When every edge weight is 0 or 1 — a deque (push 0-cost to the front, 1-cost to the back) replaces the heap and runs in O(V + E) without the log factor
Whenever the graph is undirected
When there are negative-weight edges
With weights restricted to {0, 1}, the deque stays sorted by distance automatically: 0-cost moves keep the same distance (front), 1-cost moves increase it by one (back). This achieves Dijkstra's result in linear time, dropping the O(log V) heap overhead.

  • I can compute all-pairs shortest paths with Floyd-Warshall (k outermost).
  • I can build an MST with both Kruskal's and Prim's, and know when to use each.
  • I can recognise Eulerian-path, 0-1 BFS, and bridge/articulation problems.
