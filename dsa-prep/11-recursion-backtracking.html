Recursion & Backtracking

Recursion solves a problem by solving smaller copies of itself; backtracking is recursion that explores every choice and undoes the ones that don't work. Together they generate subsets, permutations, and solutions to hard constraint puzzles — every problem here has a full, tested solution in LeetCode's class Solution format.

Outcome

Write clean recursion with correct base cases, add memoization, and apply the choose → recurse → un-choose backtracking template to subsets, permutations, combinations, partitions, and constraint satisfaction — pruning aggressively.

1 · Foundations

New to recursion? Read this section top to bottom — each idea builds on the one before it. Already fluent? Skip to §2 Pattern library.

What is recursion?

A recursive function solves a problem by calling itself on a smaller version, until it hits a case small enough to answer directly. Two parts are non-negotiable: a base case that stops the recursion, and a recursive case that moves toward it. Miss the base case and you get infinite recursion — a RecursionError.

Example — factorial, the classic recursion
factorial.py
def factorial(n):
    if n == 0:          # base case
        return 1
    return n * factorial(n - 1)   # recursive case: smaller n

print(factorial(5))     # 120
Output120
Every recursive call is pushed onto the call stack. That stack is both the magic (it remembers where to resume) and the cost (deep recursion uses O(depth) memory, and Python caps it near 1000 frames).

Memoization: don't recompute

Naive recursion can be catastrophically slow when it solves the same subproblem repeatedly — fib(n) is O(2ⁿ) because it recomputes the same Fibonacci values over and over. Memoization caches each result the first time, turning the recursion tree into O(n). This is the doorway to dynamic programming (Ch 18).

Example — Fibonacci, memoized
fib_memo.py
def fib(n, memo={}):
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)   # cache each result once
    return memo[n]

print(fib(30))          # 832040  (fast: each fib(k) computed once)
functools.lru_cache does the same automatically — decorate a function and its calls are cached.

What is backtracking?

Backtracking is recursion that builds a solution one choice at a time, and when a choice leads nowhere, undoes it and tries the next. It explores a decision tree: at each node you choose an option, recurse deeper, then un-choose (restore state) so the next option starts clean.

Example — all subsets via choose / recurse / un-choose
subsets.py
def subsets(nums):
    res = []
    def backtrack(start, path):
        res.append(path[:])              # record a COPY of the current choice
        for i in range(start, len(nums)):
            path.append(nums[i])         # choose
            backtrack(i + 1, path)       # recurse on the rest
            path.pop()                   # un-choose (backtrack)
    backtrack(0, [])
    return res

print(subsets([1, 2, 3]))
# [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
Output[[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]

Note path[:] — you must record a copy, because path keeps mutating as the recursion continues. Forgetting this is the #1 backtracking bug.

Pruning: skip doomed branches early

The decision tree is usually exponential, so the art is cutting branches that can't lead to a solution — a constraint check before recursing (a segment > 255 in an IP address, a queen under attack, a running sum already over target). Good pruning is often the difference between "times out" and "instant".

⚠️
Recursion & backtracking pitfalls

Always define a base case that's actually reached. Record a copy of the path (path[:]), not the live list. After recursing, undo every change you made (pop the element, unmark the cell, remove from the set). Handle duplicates by sorting then skipping equal siblings. And remember Python's ~1000-frame recursion limit for very deep problems.

1 LC 509Fibonacci Number Easy Recursion + memoization

Problem. Return the n-th Fibonacci number. LeetCode 509 ↗

Clarify: F(0)=0, F(1)=1? (Yes.) n can be up to ~30–40? (Yes — memoize to stay fast.)

Hint 1
The definition is recursive: F(n) = F(n−1) + F(n−2).
Hint 2
Plain recursion recomputes subproblems exponentially — cache results in a dict.

How to think about it The recursive definition translates directly, but naive recursion is exponential because it recomputes the same values. A memo dict (top-down DP) stores each result the first time it's computed, collapsing the work to O(n).

fibonacci.py
class Solution:
    def fib(self, n: int) -> int:
        memo = {}
        def f(k):
            if k < 2:
                return k
            if k not in memo:
                memo[k] = f(k - 1) + f(k - 2)
            return memo[k]
        return f(n)

Time O(n) with memo · Space O(n). Memoisation is the bridge from recursion to dynamic programming (Ch 18).

2 LC 70Climbing Stairs Easy Recursion + memoization

Problem. You can climb 1 or 2 steps at a time. Count the distinct ways to reach step n. LeetCode 70 ↗

Clarify: Steps of size 1 or 2 only? (Yes.) Order matters (1+2 ≠ 2+1)? (Yes.)

Hint 1
To reach step n you came from n−1 or n−2, so ways(n) = ways(n−1) + ways(n−2).
Hint 2
That's Fibonacci — memoize to avoid the exponential blowup.

How to think about it The number of ways to reach step n is the sum of the ways to reach the two steps below it — the Fibonacci recurrence. Memoize the recursion so each subproblem is solved once.

climbing_stairs.py
class Solution:
    def climbStairs(self, n: int) -> int:
        memo = {}
        def ways(k):
            if k <= 2:
                return k
            if k not in memo:
                memo[k] = ways(k - 1) + ways(k - 2)
            return memo[k]
        return ways(n)

Time O(n) · Space O(n). Recognising a problem as 'this recurrence' is the core recursion skill.

3 LC 344Reverse String Easy Recursion instead of a loop

Problem. Reverse a list of characters in place — here, recursively. LeetCode 344 ↗

Clarify: In place? (Yes.) Recursion is the point (loops also work)? (Yes.)

Hint 1
Swap the outer pair, then recurse on the inner substring.
Hint 2
Base case: the pointers meet or cross.

How to think about it A recursion drill: swap the two ends, then recurse inward on the smaller range. The base case (pointers meeting) stops it. Every loop has a recursive twin — seeing that equivalence builds recursion intuition.

reverse_string.py
from typing import List

class Solution:
    def reverseString(self, s: List[str]) -> None:
        def helper(l, r):
            if l >= r:
                return
            s[l], s[r] = s[r], s[l]
            helper(l + 1, r - 1)          # recurse inward
        helper(0, len(s) - 1)

Time O(n) · Space O(n) call stack. Recursion here costs stack space that the iterative two-pointer version avoids — a real trade-off to state.

4 LC 206Reverse Linked List Easy Recursion on a linked structure

Problem. Reverse a singly linked list — recursively — and return the new head. LeetCode 206 ↗

Clarify: Recursive version wanted? (Yes.) Long lists risk stack overflow? (Yes — note the iterative alternative.)

Hint 1
Recurse to the end; the last node becomes the new head.
Hint 2
On the way back, make the next node point back to the current one.

How to think about it Recurse to the tail (the new head). As each call returns, flip the link so head.next points back at head, and detach head.next. The reversal happens during the unwinding of the stack.

reverse_list.py
from typing import Optional

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head                   # base case: empty or single node
        new_head = self.reverseList(head.next)
        head.next.next = head             # flip the link on the way back up
        head.next = None
        return new_head

Time O(n) · Space O(n) stack. Elegant, but a 10⁵-node list would overflow — prefer iteration there (Ch 03).

5 LC 21Merge Two Sorted Lists Easy Recursion · pick the smaller head

Problem. Merge two sorted linked lists into one sorted list — recursively. LeetCode 21 ↗

Clarify: Reuse existing nodes? (Yes.) Recursive form? (Yes.)

Hint 1
The merged head is the smaller of the two current heads.
Hint 2
The rest is the merge of the remaining lists — a recursive call.

How to think about it At each step the smaller head leads, and its next is the merge of the rest — a clean recursive definition. Base cases return the non-empty list when one runs out. The recursion depth is the total length.

merge_two.py
from typing import Optional

class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        if not list1:
            return list2
        if not list2:
            return list1
        if list1.val <= list2.val:
            list1.next = self.mergeTwoLists(list1.next, list2)
            return list1
        list2.next = self.mergeTwoLists(list1, list2.next)
        return list2

Time O(n + m) · Space O(n + m) stack. A tidy divide-and-conquer flavour; iterative merge avoids the stack cost.

6 LC 231Power of Two Easy Recursion · halve toward the base case

Problem. Return whether an integer is a power of two. LeetCode 231 ↗

Clarify: Handle n ≤ 0 (never a power of two)? (Yes.) 1 counts (2⁰)? (Yes.)

Hint 1
A power of two is 1, or an even number that stays a power of two when halved.
Hint 2
Recurse on n // 2; reject odd numbers > 1 and non-positives.

How to think about it Recurse toward the base case n == 1: any positive even number is a power of two iff half of it is; an odd number greater than 1 (or a non-positive) is not. A simple linear recursion. (The O(1) bit trick n & (n−1) == 0 is worth mentioning.)

power_of_two.py
class Solution:
    def isPowerOfTwo(self, n: int) -> bool:
        if n == 1:
            return True
        if n <= 0 or n % 2 != 0:
            return False
        return self.isPowerOfTwo(n // 2)

Time O(log n) · Space O(log n) stack. Good practice at spotting the base case and the shrinking recursive step.

Tier 2 · Medium — the backtracking templates (22)
7 LC 78Subsets Medium Backtracking · the include/exclude tree

Problem. Return all subsets (the power set) of a list of distinct integers. LeetCode 78 ↗

Clarify: Elements distinct? (Yes.) Any order of subsets? (Yes.)

Hint 1
Each element is either in a subset or not — a binary decision tree.
Hint 2
Use a start index so you never reuse earlier elements; record the path at every node.

How to think about it The foundational backtracking template. Recurse with a start index; at each node the current path is a valid subset, so record a copy. Then try adding each later element, recurse, and undo. Every node of the decision tree is a subset.

subsets.py
from typing import List

class Solution:
    def subsets(self, nums: List[int]) -> List[List[int]]:
        res = []
        def bt(start, path):
            res.append(path[:])           # every prefix is a valid subset
            for i in range(start, len(nums)):
                path.append(nums[i])
                bt(i + 1, path)
                path.pop()
        bt(0, [])
        return res

Time O(n·2ⁿ) · Space O(n) recursion. The choose → recurse → un-choose rhythm here repeats through the whole chapter.

8 LC 90Subsets II Medium Backtracking · skip duplicate branches

Problem. Return all unique subsets when the input may contain duplicates. LeetCode 90 ↗

Clarify: Duplicates in input? (Yes.) Result must be unique? (Yes.)

Hint 1
Sort so equal values are adjacent.
Hint 2
At the same recursion depth, skip a value equal to the previous one you already tried.

How to think about it Sort first, then use the subsets template with one guard: at a given depth, if the current value equals the previous one (i > start and nums[i] == nums[i-1]), skip it — that branch was already explored. This prevents duplicate subsets without a set.

subsets_ii.py
from typing import List

class Solution:
    def subsetsWithDup(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []
        def bt(start, path):
            res.append(path[:])
            for i in range(start, len(nums)):
                if i > start and nums[i] == nums[i - 1]:
                    continue              # skip duplicate at the same depth
                path.append(nums[i])
                bt(i + 1, path)
                path.pop()
        bt(0, [])
        return res

Time O(n·2ⁿ) · Space O(n). 'Sort, then skip equal siblings' is the universal duplicate-handling trick in backtracking.

9 LC 46Permutations Medium Backtracking · a used[] marker

Problem. Return all permutations of a list of distinct integers. LeetCode 46 ↗

Clarify: Distinct elements? (Yes.) All orderings? (Yes.)

Hint 1
A permutation uses every element exactly once, in some order.
Hint 2
Track which indices are used; recurse until the path has all n elements.

How to think about it Build the permutation position by position. A used array marks which elements are already in the path; at each level try every unused element, recurse, then release it. When the path length reaches n, record it.

permutations.py
from typing import List

class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        res = []
        used = [False] * len(nums)
        def bt(path):
            if len(path) == len(nums):
                res.append(path[:]); return
            for i in range(len(nums)):
                if used[i]:
                    continue
                used[i] = True
                path.append(nums[i])
                bt(path)
                path.pop()
                used[i] = False
        bt([])
        return res

Time O(n·n!) · Space O(n). The used marker (vs a start index) is what distinguishes permutations from combinations.

10 LC 47Permutations II Medium Backtracking · dedup with used[]

Problem. Return all unique permutations when the input may contain duplicates. LeetCode 47 ↗

Clarify: Duplicates present? (Yes.) Unique permutations only? (Yes.)

Hint 1
Sort so equal values are adjacent.
Hint 2
Skip a duplicate value unless its identical predecessor is already used in this path.

How to think about it Sort, then permute with a duplicate guard: skip nums[i] if it equals nums[i-1] and that predecessor is not currently used — meaning we're at the same tree level and would repeat a branch. This canonicalises the order duplicates are placed.

permutations_ii.py
from typing import List

class Solution:
    def permuteUnique(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []
        used = [False] * len(nums)
        def bt(path):
            if len(path) == len(nums):
                res.append(path[:]); return
            for i in range(len(nums)):
                if used[i] or (i > 0 and nums[i] == nums[i - 1] and not used[i - 1]):
                    continue              # skip duplicate branches
                used[i] = True
                path.append(nums[i])
                bt(path)
                path.pop()
                used[i] = False
        bt([])
        return res

Time O(n·n!) · Space O(n). The not used[i-1] condition is subtle — draw two duplicates to see why it dedups.

11 LC 77Combinations Medium Backtracking · fixed-size, start index

Problem. Return all combinations of k numbers chosen from 1..n. LeetCode 77 ↗

Clarify: Order within a combination irrelevant? (Yes.) Choose exactly k? (Yes.)

Hint 1
Use a start index so combinations are built in increasing order (no reorderings).
Hint 2
Stop and record when the path reaches size k.

How to think about it The combinations template: recurse with a start index, appending each candidate and moving the start forward so you never pick a smaller number later (which would create a reordering). Record the path when it has k elements.

combinations.py
from typing import List

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        res = []
        def bt(start, path):
            if len(path) == k:
                res.append(path[:]); return
            for i in range(start, n + 1):
                path.append(i)
                bt(i + 1, path)
                path.pop()
        bt(1, [])
        return res

Time O(k·C(n,k)) · Space O(k). The start index is what turns 'permutations' into 'combinations'.

12 LC 39Combination Sum Medium Backtracking · reuse allowed, prune

Problem. Return all unique combinations of candidates (each reusable unlimited times) that sum to target. LeetCode 39 ↗

Clarify: Reuse the same number multiple times? (Yes.) Candidates distinct? (Yes.)

Hint 1
Recurse on the remaining target; sort to allow early pruning.
Hint 2
Since reuse is allowed, recurse with the same index i (not i+1).

How to think about it Backtrack on the remaining target. Sort candidates so you can break once one exceeds the remainder. Crucially, recurse with the same index i because each number may be reused; a combination completes when the remainder hits 0.

combination_sum.py
from typing import List

class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates.sort()
        res = []
        def bt(start, path, remaining):
            if remaining == 0:
                res.append(path[:]); return
            for i in range(start, len(candidates)):
                if candidates[i] > remaining:
                    break
                path.append(candidates[i])
                bt(i, path, remaining - candidates[i])   # reuse allowed -> i, not i+1
                path.pop()
        bt(0, [], target)
        return res

Time exponential (bounded by the target) · Space O(target). Recursing on i vs i+1 is the single line that allows/forbids reuse.

13 LC 40Combination Sum II Medium Backtracking · each used once, dedup

Problem. Return unique combinations summing to target where each candidate is used at most once and the input may have duplicates. LeetCode 40 ↗

Clarify: Each number used once? (Yes.) Duplicates in input? (Yes.) Unique combinations? (Yes.)

Hint 1
Sort; recurse with i+1 so each element is used once.
Hint 2
Skip a duplicate value at the same depth (i > start and equal to previous).

How to think about it Combine the two guards you've learned: recurse with i+1 (each element used once) and skip duplicate siblings (i > start and equal) so no combination repeats. Sorting enables both the skip and the early break when a value exceeds the remainder.

combination_sum_ii.py
from typing import List

class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates.sort()
        res = []
        def bt(start, path, remaining):
            if remaining == 0:
                res.append(path[:]); return
            for i in range(start, len(candidates)):
                if i > start and candidates[i] == candidates[i - 1]:
                    continue
                if candidates[i] > remaining:
                    break
                path.append(candidates[i])
                bt(i + 1, path, remaining - candidates[i])   # each used once -> i+1
                path.pop()
        bt(0, [], target)
        return res

Time O(2ⁿ) worst · Space O(n). It's Combination Sum with 'use once' + the sort-and-skip dedup — two familiar pieces combined.

14 LC 216Combination Sum III Medium Backtracking · size and sum constraints

Problem. Find all combinations of k distinct digits (1–9) that sum to n. LeetCode 216 ↗

Clarify: Digits 1–9, each once? (Yes.) Exactly k of them summing to n? (Yes.)

Hint 1
Two constraints at once: exactly k numbers AND sum n.
Hint 2
Recurse with a start index over 1..9; prune when a digit exceeds the remainder.

How to think about it Backtrack over digits 1–9 with a start index (each used once). The base case checks both constraints: path length k and remaining sum 0. Break early when the current digit exceeds the remaining target.

combination_sum_iii.py
from typing import List

class Solution:
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        res = []
        def bt(start, path, remaining):
            if len(path) == k:
                if remaining == 0:
                    res.append(path[:])
                return
            for i in range(start, 10):
                if i > remaining:
                    break
                path.append(i)
                bt(i + 1, path, remaining - i)
                path.pop()
        bt(1, [], n)
        return res

Time O(C(9,k)) · Space O(k). Handling two simultaneous constraints in the base case is the new wrinkle.

15 LC 17Letter Combinations of a Phone Number Medium Backtracking · one digit per level

Problem. Given phone digits 2–9, return all letter combinations they could spell. LeetCode 17 ↗

Clarify: Standard phone keypad mapping? (Yes.) Empty input → empty list? (Yes.)

Hint 1
Each digit contributes one letter to each combination — a level per digit.
Hint 2
Recurse over the letters of the current digit, appending and undoing.

How to think about it A per-position backtrack: at level i, try each letter mapped to digits[i], append it, recurse to the next digit, then undo. When the path length equals the number of digits, record the string. The decision tree has one level per digit.

letter_combinations.py
from typing import List

class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:
            return []
        mapping = {"2":"abc","3":"def","4":"ghi","5":"jkl",
                   "6":"mno","7":"pqrs","8":"tuv","9":"wxyz"}
        res = []
        def bt(i, path):
            if i == len(digits):
                res.append("".join(path)); return
            for ch in mapping[digits[i]]:
                path.append(ch)
                bt(i + 1, path)
                path.pop()
        bt(0, [])
        return res

Time O(4ⁿ) · Space O(n). The cleanest 'Cartesian product via backtracking' example.

16 LC 22Generate Parentheses Medium Backtracking · prune by validity

Problem. Generate all combinations of n pairs of well-formed parentheses. LeetCode 22 ↗

Clarify: Only valid (balanced) strings? (Yes.) Exactly n pairs? (Yes.)

Hint 1
Build the string left to right, tracking counts of '(' and ')' used.
Hint 2
You may add '(' while under n, and ')' only while it wouldn't exceed the opens.

How to think about it Backtrack character by character with two counters. Add '(' whenever fewer than n are open; add ')' only when there's an unmatched '(' to close (closed < opened). These two rules prune every invalid branch, so you only ever build well-formed strings.

generate_parens.py
from typing import List

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        res = []
        def bt(path, opened, closed):
            if len(path) == 2 * n:
                res.append("".join(path)); return
            if opened < n:                # can still open
                path.append("("); bt(path, opened + 1, closed); path.pop()
            if closed < opened:           # can close only what's open
                path.append(")"); bt(path, opened, closed + 1); path.pop()
        bt([], 0, 0)
        return res

Time O(4ⁿ/√n) (Catalan) · Space O(n). Pruning by a validity invariant — not generate-then-filter — is the lesson.

17 LC 784Letter Case Permutation Medium Backtracking · branch on letters only

Problem. Return every string formable by toggling the case of each letter (digits stay fixed). LeetCode 784 ↗

Clarify: Digits unchanged? (Yes.) Branch on letters both ways? (Yes.)

Hint 1
At each position, a digit has one choice; a letter has two (lower/upper).
Hint 2
Recurse position by position.

How to think about it Backtrack over positions. A digit is appended as-is (one branch); a letter branches twice, once lowercase and once uppercase. Each root-to-leaf path is one result. A focused variant of the include/exclude tree.

letter_case.py
from typing import List

class Solution:
    def letterCasePermutation(self, s: str) -> List[str]:
        res = []
        def bt(i, path):
            if i == len(s):
                res.append("".join(path)); return
            ch = s[i]
            if ch.isalpha():
                path.append(ch.lower()); bt(i + 1, path); path.pop()
                path.append(ch.upper()); bt(i + 1, path); path.pop()
            else:
                path.append(ch); bt(i + 1, path); path.pop()
        bt(0, [])
        return res

Time O(2ᴸ · n) · Space O(n). Branching factor varies by character — a nice twist on the standard template.

18 LC 79Word Search Medium Grid backtracking · mark and restore

Problem. Return whether a word can be formed from adjacent (up/down/left/right) cells, using each cell at most once. LeetCode 79 ↗

Clarify: Cells reused within a word? (No.) Only 4-directional moves? (Yes.)

Hint 1
DFS from each cell that matches the first letter.
Hint 2
Mark a cell visited before recursing, and restore it afterward.

How to think about it Backtracking on a grid. From each starting cell, match the word letter by letter, exploring the four neighbours. Temporarily overwrite the current cell (mark visited) so the same cell isn't reused, then restore it as the recursion unwinds. Succeed when the whole word is matched.

word_search.py
from typing import List

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows, cols = len(board), len(board[0])
        def bt(r, c, i):
            if i == len(word):
                return True
            if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[i]:
                return False
            tmp = board[r][c]
            board[r][c] = "#"             # mark visited
            found = (bt(r + 1, c, i + 1) or bt(r - 1, c, i + 1)
                     or bt(r, c + 1, i + 1) or bt(r, c - 1, i + 1))
            board[r][c] = tmp             # restore on the way back
            return found
        for r in range(rows):
            for c in range(cols):
                if bt(r, c, 0):
                    return True
        return False

Time O(rows·cols·4ᴸ) · Space O(L) stack. Mark-recurse-restore is the grid analogue of choose-recurse-unchoose.

19 LC 131Palindrome Partitioning Medium Backtracking · partition points

Problem. Return all ways to split the string so every piece is a palindrome. LeetCode 131 ↗

Clarify: Every substring in a partition must be a palindrome? (Yes.) All partitions? (Yes.)

Hint 1
At each position, try every prefix that is a palindrome as the next piece.
Hint 2
Recurse on the remainder from where that piece ends.

How to think about it Backtrack over cut points. From the current start, try each prefix; if it's a palindrome, add it and recurse from its end. When the start reaches the end of the string, the accumulated pieces form one valid partition. Only palindromic prefixes branch, pruning the rest.

palindrome_partition.py
from typing import List

class Solution:
    def partition(self, s: str) -> List[List[str]]:
        res = []
        def bt(start, path):
            if start == len(s):
                res.append(path[:]); return
            for end in range(start + 1, len(s) + 1):
                piece = s[start:end]
                if piece == piece[::-1]:      # only recurse on palindromic prefixes
                    path.append(piece)
                    bt(end, path)
                    path.pop()
        bt(0, [])
        return res

Time O(n·2ⁿ) · Space O(n). Choosing 'where to cut next' is the partition-style backtracking pattern (see Restore IP Addresses).

20 LC 93Restore IP Addresses Medium Backtracking · segments with validity

Problem. Return all valid IP addresses formable by inserting dots into a digit string. LeetCode 93 ↗

Clarify: Exactly four parts, each 0–255, no leading zeros? (Yes.)

Hint 1
Each of the 4 parts takes 1–3 digits; validate as you go.
Hint 2
Prune segments with a leading zero (unless '0') or value > 255.

How to think about it Partition the string into four segments by backtracking. At each step try segment lengths 1–3, rejecting invalid ones (leading zero, or > 255). When four valid parts exactly consume the string, join them with dots. The four-part cap and validity checks prune aggressively.

restore_ip.py
from typing import List

class Solution:
    def restoreIpAddresses(self, s: str) -> List[str]:
        res = []
        def bt(start, parts):
            if len(parts) == 4:
                if start == len(s):
                    res.append(".".join(parts))
                return
            for length in range(1, 4):
                if start + length > len(s):
                    break
                seg = s[start:start + length]
                if (seg[0] == "0" and len(seg) > 1) or int(seg) > 255:
                    continue              # no leading zeros, 0..255
                parts.append(seg)
                bt(start + length, parts)
                parts.pop()
        bt(0, [])
        return res

Time O(1) (bounded by 3⁴ splits) · Space O(1). Same 'partition into pieces' shape as palindrome partitioning, with per-piece validity.

21 LC 50Pow(x, n) Medium Divide and conquer · fast exponentiation

Problem. Compute x raised to the integer power n in O(log n). LeetCode 50 ↗

Clarify: n can be negative? (Yes — invert x.) O(log n) required (not n multiplications)? (Yes.)

Hint 1
x^n = (x^(n/2))² — halve the exponent each step.
Hint 2
Multiply by an extra x when the exponent is odd; handle negative n by inverting x.

How to think about it Fast exponentiation by squaring: compute x^(n//2) once, square it, and multiply by an extra x if n is odd. Halving the exponent each recursive call gives O(log n) instead of O(n). Negative exponents invert the base first.

pow.py
class Solution:
    def myPow(self, x: float, n: int) -> float:
        if n < 0:
            x, n = 1 / x, -n
        def fast(base, exp):
            if exp == 0:
                return 1.0
            half = fast(base, exp // 2)
            return half * half * (base if exp % 2 else 1)
        return fast(x, n)

Time O(log n) · Space O(log n) stack. Divide-and-conquer recursion where each call solves half the problem, not one-less.

22 LC 241Different Ways to Add Parentheses Medium Divide and conquer at each operator

Problem. Given an arithmetic expression, return all results from every way of parenthesising it. LeetCode 241 ↗

Clarify: Only + − * and non-negative integers? (Yes.) Return all possible values? (Yes.)

Hint 1
Split the expression at each operator into left and right subexpressions.
Hint 2
Recursively compute all values of each side, then combine every pair.

How to think about it Divide and conquer on operators. For each operator, recursively compute all values of the left and right subexpressions, then combine every left value with every right value under that operator. A base case (a pure number) returns a single value. Memoise on the substring to reuse overlapping subexpressions.

diff_ways.py
from typing import List

class Solution:
    def diffWaysToCompute(self, expression: str) -> List[int]:
        memo = {}
        def compute(expr):
            if expr.isdigit():
                return [int(expr)]
            if expr in memo:
                return memo[expr]
            res = []
            for i, ch in enumerate(expr):
                if ch in "+-*":
                    left = compute(expr[:i])
                    right = compute(expr[i + 1:])
                    for a in left:
                        for b in right:
                            res.append(a + b if ch == "+" else a - b if ch == "-" else a * b)
            memo[expr] = res
            return res
        return compute(expression)

Time ~Catalan · Space O(result). Recursion that returns a list of possibilities per subproblem — a powerful generalisation.

23 LC 60Permutation Sequence Medium Factorial number system (not brute force)

Problem. Return the k-th permutation (1-indexed) of the numbers 1..n. LeetCode 60 ↗

Clarify: 1-indexed k? (Yes.) n up to ~9? (Yes.)

Hint 1
Don't generate all permutations. The first digit is determined by k // (n−1)!.
Hint 2
Peel off one digit at a time, updating k with the remainder.

How to think about it Use the factorial number system instead of enumerating. There are (n−1)! permutations for each choice of first element, so k // (n−1)! selects it; take the remainder and repeat for the next position, removing each chosen digit. Directly constructs the k-th permutation in O(n²).

permutation_sequence.py
import math

class Solution:
    def getPermutation(self, n: int, k: int) -> str:
        nums = list(range(1, n + 1))
        k -= 1                            # 0-indexed
        res = []
        for i in range(n, 0, -1):
            f = math.factorial(i - 1)
            idx = k // f                  # which number leads this block
            res.append(str(nums.pop(idx)))
            k %= f
        return "".join(res)

Time O(n²) · Space O(n). A reminder that sometimes the smart move is to skip the backtracking and compute the answer arithmetically.

24 LC 526Beautiful Arrangement Medium Backtracking with a divisibility rule

Problem. Count permutations of 1..n where each value at position i divides i or vice versa. LeetCode 526 ↗

Clarify: Position and value are both 1..n? (Yes.) Count arrangements (not list)? (Yes.)

Hint 1
Fill positions 1..n; only place a number that satisfies the divisibility rule.
Hint 2
Backtrack, counting completed arrangements.

How to think about it Backtrack position by position. At position pos, try each unused number that satisfies num % pos == 0 or pos % num == 0; recurse and undo. Reaching past position n counts one valid arrangement. The divisibility constraint prunes most branches early.

beautiful_arrangement.py
class Solution:
    def countArrangement(self, n: int) -> int:
        used = [False] * (n + 1)
        def bt(pos):
            if pos > n:
                return 1
            count = 0
            for num in range(1, n + 1):
                if not used[num] and (num % pos == 0 or pos % num == 0):
                    used[num] = True
                    count += bt(pos + 1)
                    used[num] = False
            return count
        return bt(1)

Time O(k) over valid arrangements · Space O(n). Constraint-guided placement is the same skeleton as N-Queens, just a different rule.

25 LC 698Partition to K Equal Sum Subsets Medium Backtracking · fill buckets with pruning

Problem. Return whether the array can be split into k subsets of equal sum. LeetCode 698 ↗

Clarify: Each element used once? (Yes.) k subsets with the same total? (Yes.)

Hint 1
Target = total / k; fail fast if it doesn't divide or the max exceeds it.
Hint 2
Fill one bucket to target, then recurse on the next; prune when the first element of a bucket fails.

How to think about it Backtrack by filling buckets one at a time to target = total/k. When a bucket reaches the target, recurse to fill the next. Sort descending and prune hard: skip used or overflowing elements, and if the first element placed in a bucket can't lead to a solution, the whole branch is hopeless — break.

k_equal_subsets.py
from typing import List

class Solution:
    def canPartitionKSubsets(self, nums: List[int], k: int) -> bool:
        total = sum(nums)
        if total % k != 0:
            return False
        target = total // k
        nums.sort(reverse=True)
        if nums[0] > target:
            return False
        used = [False] * len(nums)
        def bt(count, cur, start):
            if count == k:
                return True
            if cur == target:
                return bt(count + 1, 0, 0)     # bucket full, start the next
            for i in range(start, len(nums)):
                if used[i] or cur + nums[i] > target:
                    continue
                used[i] = True
                if bt(count, cur + nums[i], i + 1):
                    return True
                used[i] = False
                if cur == 0:              # prune: first element of a bucket failing is fatal
                    break
            return False
        return bt(0, 0, 0)

Time O(k·2ⁿ) worst · Space O(n). The descending sort and the 'first-element' prune are what make it pass — pruning is a first-class part of backtracking.

26 LC 967Numbers With Same Consecutive Differences Medium Backtracking · build digit by digit

Problem. Return all n-digit numbers where adjacent digits differ by exactly k. LeetCode 967 ↗

Clarify: No leading zeros? (Yes — start 1–9.) k can be 0? (Yes — dedup the two branches.)

Hint 1
Grow the number one digit at a time from each valid first digit.
Hint 2
The next digit is last ± k, kept within 0–9.

How to think about it Backtrack building the number digit by digit. From each first digit 1–9, extend by appending last + k or last − k when in range (a set dedups them when k == 0). Record the number once it reaches n digits.

consec_diff.py
from typing import List

class Solution:
    def numsSameConsecDiff(self, n: int, k: int) -> List[int]:
        res = []
        def bt(num, length):
            if length == n:
                res.append(num); return
            last = num % 10
            for nxt in {last + k, last - k}:      # set dedups when k == 0
                if 0 <= nxt <= 9:
                    bt(num * 10 + nxt, length + 1)
        for first in range(1, 10):
            bt(first, 1)
        return res

Time O(2ⁿ) · Space O(n). Building a number as a growing integer (rather than a string) keeps it clean.

27 LC 494Target Sum Medium Recursion + memoization

Problem. Count the ways to assign + or − to each number so the expression equals target. LeetCode 494 ↗

Clarify: Every number gets a sign? (Yes.) Count assignments (not list)? (Yes.)

Hint 1
At each number, branch on + and −.
Hint 2
Memoize on (index, running total) — many branches revisit the same state.

How to think about it Recurse over the numbers, branching on adding or subtracting each. The base case checks whether the running total equals the target. Because different sign choices reach the same (index, total) state, memoise on that pair to collapse the exponential tree — the recursion-to-DP transition.

target_sum.py
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        memo = {}
        def bt(i, total):
            if i == len(nums):
                return 1 if total == target else 0
            if (i, total) not in memo:
                memo[(i, total)] = bt(i + 1, total + nums[i]) + bt(i + 1, total - nums[i])
            return memo[(i, total)]
        return bt(0, 0)

Time O(n·sum) with memo · Space O(n·sum). A perfect illustration of memoisation turning O(2ⁿ) branching into polynomial time.

28 LC 386Lexicographical Numbers Medium DFS over a 10-ary number tree

Problem. Return 1..n in lexicographical (dictionary) order, ideally in O(n). LeetCode 386 ↗

Clarify: Dictionary order (1,10,11,...,2,...)? (Yes.) O(n) time, O(1) extra? (Target.)

Hint 1
Think of numbers as nodes in a 10-ary tree: children of x are 10x..10x+9.
Hint 2
A pre-order DFS visits them in lexicographical order.

How to think about it Model the numbers as a tree where each node x has children 10x, 10x+1, …, 10x+9. A pre-order DFS starting from 1..9 visits them in exactly lexicographical order — appending each node before descending, pruning children that exceed n.

lexical_order.py
from typing import List

class Solution:
    def lexicalOrder(self, n: int) -> List[int]:
        res = []
        def dfs(cur):
            if cur > n:
                return
            res.append(cur)
            for d in range(10):
                nxt = cur * 10 + d
                if nxt > n:
                    break
                dfs(nxt)
        for start in range(1, 10):
            if start > n:
                break
            dfs(start)
        return res

Time O(n) · Space O(log n) depth. Seeing numbers as a traversable tree is the insight — recursion follows naturally.

29 LC 51N-Queens Hard Backtracking · place a queen per row

Problem. Place n queens on an n×n board so none attack each other; return all distinct board layouts. LeetCode 51 ↗

Clarify: Return all solutions as boards? (Yes.) One queen per row by construction? (Yes.)

Hint 1
Place one queen per row; track attacked columns and both diagonals in sets.
Hint 2
A cell is safe if its column, r−c diagonal, and r+c diagonal are all free.

How to think about it Backtrack row by row. Three sets track occupied columns and the two diagonal families (r−c and r+c). For each safe column, place a queen, mark the sets, recurse to the next row, then undo. A completed board (row == n) is recorded.

n_queens.py
from typing import List

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        res = []
        cols, diag1, diag2 = set(), set(), set()
        board = [["."] * n for _ in range(n)]
        def bt(r):
            if r == n:
                res.append(["".join(row) for row in board]); return
            for c in range(n):
                if c in cols or (r - c) in diag1 or (r + c) in diag2:
                    continue
                cols.add(c); diag1.add(r - c); diag2.add(r + c)
                board[r][c] = "Q"
                bt(r + 1)
                board[r][c] = "."
                cols.discard(c); diag1.discard(r - c); diag2.discard(r + c)
        bt(0)
        return res

Time O(n!) with pruning · Space O(n). The diagonal encodings r−c / r+c make O(1) attack checks — the classic constraint-satisfaction backtrack.

31 LC 37Sudoku Solver Hard Backtracking · fill cells, undo on failure

Problem. Fill a partially completed 9×9 Sudoku so every row, column, and 3×3 box contains 1–9. LeetCode 37 ↗

Clarify: Exactly one solution guaranteed? (Yes.) Modify the board in place? (Yes.)

Hint 1
Precompute the empty cells and the used-digit sets for rows/cols/boxes.
Hint 2
Try each legal digit in the next empty cell; recurse, and undo if it fails.

How to think about it Collect the empty cells and maintain per-row, per-column, and per-box sets of used digits for O(1) legality checks. Backtrack over the empty cells: try each legal digit, mark the sets, recurse to the next cell; on failure, restore and try the next digit. Returning True on the last cell locks in the solution.

sudoku_solver.py
from typing import List

class Solution:
    def solveSudoku(self, board: List[List[str]]) -> None:
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]
        empties = []
        for r in range(9):
            for c in range(9):
                if board[r][c] == ".":
                    empties.append((r, c))
                else:
                    d = board[r][c]
                    rows[r].add(d); cols[c].add(d); boxes[(r // 3) * 3 + c // 3].add(d)
        def bt(idx):
            if idx == len(empties):
                return True
            r, c = empties[idx]
            b = (r // 3) * 3 + c // 3
            for d in "123456789":
                if d in rows[r] or d in cols[c] or d in boxes[b]:
                    continue
                board[r][c] = d
                rows[r].add(d); cols[c].add(d); boxes[b].add(d)
                if bt(idx + 1):
                    return True
                board[r][c] = "."
                rows[r].discard(d); cols[c].discard(d); boxes[b].discard(d)
            return False
        bt(0)

Time exponential worst · Space O(1) board. Constraint tracking + backtracking is the template for every 'fill the grid legally' puzzle.

32 LC 212Word Search II Hard Trie + grid backtracking

Problem. Given a board and a list of words, return all words that can be formed by adjacent cells. LeetCode 212 ↗

Clarify: Many words to search at once? (Yes — a trie shares prefixes.) Each cell used once per word? (Yes.)

Hint 1
Searching each word separately is slow; put all words in a trie and DFS once.
Hint 2
Walk the board following trie edges; when you hit a word marker, record it.

How to think about it Build a trie of all words, then DFS the grid once, descending the trie as letters match. When a trie node marks the end of a word, record it (and remove the marker to avoid duplicates). Marking cells visited during the DFS prevents reuse. The trie prunes dead prefixes across all words simultaneously.

word_search_ii.py
from typing import List

class Solution:
    def findWords(self, board: List[List[str]], words: List[str]) -> List[str]:
        trie = {}
        for w in words:
            node = trie
            for ch in w:
                node = node.setdefault(ch, {})
            node["#"] = w                 # store the whole word at the leaf
        rows, cols = len(board), len(board[0])
        res = []
        def bt(r, c, node):
            ch = board[r][c]
            if ch not in node:
                return
            nxt = node[ch]
            if "#" in nxt:
                res.append(nxt.pop("#"))  # found; remove to avoid duplicates
            board[r][c] = "#"
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != "#":
                    bt(nr, nc, nxt)
            board[r][c] = ch
        for r in range(rows):
            for c in range(cols):
                bt(r, c, trie)
        return res

Time O(cells · 4·3^(L−1)) · Space O(total word length). Combining a trie (Ch 14) with grid backtracking is a powerful multi-pattern technique.

33 LC 301Remove Invalid Parentheses Hard BFS over removals (minimum edits)

Problem. Remove the minimum number of parentheses to make the string valid; return all such results. LeetCode 301 ↗

Clarify: Return every distinct minimal-removal result? (Yes.) Non-parenthesis chars stay? (Yes.)

Hint 1
The fewest removals = the first BFS level that contains any valid string.
Hint 2
Each level removes exactly one character from every current string.

How to think about it BFS level by level: each level generates all strings with one more character removed. The first level containing any valid string is, by construction, the minimum-removal set — collect all valid strings there. A set dedups identical results. (A DFS counting excess parentheses is the O-optimal alternative.)

remove_invalid_parens.py
from typing import List

class Solution:
    def removeInvalidParentheses(self, s: str) -> List[str]:
        def is_valid(string):
            count = 0
            for ch in string:
                if ch == "(":
                    count += 1
                elif ch == ")":
                    count -= 1
                    if count < 0:
                        return False
            return count == 0
        level = {s}
        while True:                       # BFS: first level with any valid string is minimal-removal
            valid = [x for x in level if is_valid(x)]
            if valid:
                return valid
            nxt = set()
            for item in level:
                for i in range(len(item)):
                    if item[i] in "()":
                        nxt.add(item[:i] + item[i + 1:])
            level = nxt

Time O(2ⁿ) worst · Space O(2ⁿ). Framing 'minimum removals' as the first valid BFS level is a clean way to guarantee minimality.

34 LC 140Word Break II Hard Backtracking + memoization

Problem. Return all sentences formable by inserting spaces so every word is in the dictionary. LeetCode 140 ↗

Clarify: Return all valid sentences? (Yes.) Words reusable? (Yes.)

Hint 1
From each start, try every dictionary word that is a prefix, then recurse on the rest.
Hint 2
Memoize the list of sentences buildable from each start index.

How to think about it Recurse from a start index: for each dictionary word matching the prefix, prepend it to every sentence buildable from the remainder. Memoise the results per start index so shared suffixes aren't recomputed — turning a potentially exponential re-exploration into reuse of cached sentence lists.

word_break_ii.py
from typing import List

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        words = set(wordDict)
        memo = {}
        def bt(start):
            if start == len(s):
                return [""]
            if start in memo:
                return memo[start]
            res = []
            for end in range(start + 1, len(s) + 1):
                word = s[start:end]
                if word in words:
                    for rest in bt(end):
                        res.append(word if rest == "" else word + " " + rest)
            memo[start] = res
            return res
        return bt(0)

Time O(n² + output) · Space O(output). Backtracking that returns and memoises lists of answers — the same shape as Different Ways to Add Parentheses.

4 · Interview playbook

  • State the base case first, then the recursive step that shrinks toward it — and make sure it's reachable.
  • The backtracking rhythm: choose → recurse → un-choose. Record a copy of the path at leaves, and undo every mutation on the way back.
  • Pick the template: start index → subsets/combinations; used[] marker → permutations; i vs i+1 decides reuse.
  • Dedup by sorting and skipping equal siblings at the same depth.
  • Prune early with a constraint check, and memoize when subproblems repeat — that's the leap to DP.

5 · Role notes

SDE / Python backend

Recursion powers parsers, tree/graph traversal, and config expansion; backtracking drives constraint solvers, permission/route enumeration, and test-case generation. Memoization is the everyday performance fix.

Data Science / ML / AI / GenAI

Recursive search underlies decision trees and beam/DFS search; backtracking generates candidate structures (feature subsets, schedules); memoized recursion is the mental model for DP over sequences.

6 · Review

Cheat sheet
  • Smaller-copy problem → recursion (base case + recursive step).
  • Overlapping subproblems / "count the ways" → memoized recursion.
  • All subsets / partitions → start index; record path at every node.
  • All orderings → used[] marker; recurse to full length.
  • Choose k / target sum → start index + prune; reuse ⇒ recurse on i, else i+1.
  • Duplicates → sort, then skip equal siblings.
  • N-Queens / Sudoku / word search → place → mark → recurse → unmark, prune on constraints.
  • Always record path[:] (a copy), and undo every change.

Concept checks

In the subsets backtracking template, why append path[:] instead of path?
path is a single list that keeps mutating; storing it directly means every recorded subset would later reflect those mutations (all end up empty or wrong)
Because slicing is faster than appending
Because the result must be immutable
Backtracking reuses one path list, appending and popping as it explores. If you store a reference to it, all stored results point at the same list, which is later emptied by the pops. path[:] snapshots the current contents.
What single change to the recursive call decides whether Combination Sum allows reusing an element?
Recursing with the same index i allows reuse; recursing with i+1 uses each element at most once
Sorting the candidates first
Whether you record path[:] or path
The start index controls which elements a deeper call may pick. Passing i lets the same element be chosen again (LC 39); passing i+1 moves past it, so each element is used once (LC 40).
