Boosting I: AdaBoost & Gradient Boosting

One sentence in this module decides the interview: each gradient-boosting tree is fitted to the negative gradient of the loss with respect to the current predictions — not “the residuals”.

Prerequisites · Modules 09, 15, 16Study time · 8 h6 interview questionsHighest priority
🎯
Your interview goal

Say precisely what each tree fits and why “residuals” is only true for squared error, explain AdaBoost's alpha, and know why boosting is uniquely vulnerable to label noise.

1 · From the ground up

🧩
In plain words

A random forest builds hundreds of trees independently and averages them. Boosting does the opposite: it builds trees one at a time, in order, and each new tree's only job is to fix what the trees so far still get wrong. The prediction is a running total, not an average. Almost all of this module is one question — what exactly does "still gets wrong" mean — because the popular answer is not quite right.

🎯
How far you need to go for a GenAI interview

Three things carry all the value: boosting is sequential and additive, each tree fits the negative gradient rather than "the residuals", and more trees can overfit boosting but not a forest. This section covers all three. There is a bonus — boosting is gradient descent on functions — which connects directly to how LLMs are trained, and that connection is worth more to you than any boosting internals.

Start with the problem, not the formula

Bagging attacked instability. It took a model that was already roughly right and steadied it. But averaging cannot fix a model that is systematically off — if every tree leans the same wrong way, so does their average.

So flip the strategy. Start with something deliberately far too simple — one number for every row — which is very wrong but perfectly stable. Then repeatedly add a small correction, closing the gap step by step, keeping each correction small so instability creeps in slowly.

So what: this reverses every design choice. Random Forest wants deep, independent trees. Boosting wants shallow, dependent ones — depth 3 to 6, because each tree is a nudge rather than a model. And boosting cannot be spread across cores by tree, because tree 10 needs tree 9's answer first.

The recipe

Start with one constant for everybody — the average. Then repeat: look at what the total is still getting wrong, fit a small tree to that, shrink it down, and add it on. Stop after a set number of rounds, or when a validation score stops improving.

The shrinking factor is the learning rate, usually 0.01 to 0.1.

So what: that shrinking is not a detail, it is the main thing stopping it overfitting. Many small steps in roughly the right direction generalise far better than a few big ones. This is also why learning_rate and the number of trees must be tuned together — halve one and you roughly double the other.

What each tree actually fits — the part people get wrong

The usual phrasing is "each tree fits the residuals of the last one". For plain regression that happens to be true, which is why the phrase survives. In general it is wrong.

What a tree really fits is the negative gradient of the loss — the direction that would most reduce the error for each row. Work out what that becomes for each kind of problem and the picture is clear:

  • Squared error → the plain residual, actual − predicted. Hence the myth.
  • Classification → actual − predicted probability, which is not a residual in the original units at all.
  • Absolute error → just +1 or −1, throwing away the size completely — which is exactly why that version shrugs off outliers.
So what: say "each tree fits the negative gradient of the loss, which happens to equal the residual only for squared error". That single sentence is the highest-value correction in this module, and it is what makes the next step make sense.

Why this counts as gradient descent

In ordinary gradient descent you hold a list of numbers, work out which direction reduces the error, and step that way. Boosting does the same thing — except the thing being adjusted is the whole function, not a list of numbers.

The ideal step would nudge each training row's prediction by its own gradient. But that only tells you what to do at rows you have seen, and nothing about a new one. So you fit a small tree to those gradient values: the tree is a reusable approximation of the right direction. The learning rate is the step size, in the ordinary sense.

So what: "gradient boosting is gradient descent in function space, where each weak learner approximates the step" ties the module together. It also explains why swapping the loss function is all you change to move between regression, classification and ranking — and it is the same maximum-likelihood-plus-gradient-descent idea that trains an LLM (Module 23).

AdaBoost is the same idea in older clothes

AdaBoost came first and is usually taught with weights instead of gradients. Every row starts equally important; you fit a stump; you then increase the weight on the rows it got wrong, so the next stump is pushed to pay attention to the hard cases. Each stump then votes with a strength based on how accurate it was.

So what: AdaBoost turns out to be gradient boosting with one particular loss function. Knowing that unifies them instead of leaving two unrelated algorithms in your head — and it immediately explains why AdaBoost is so easily upset by mislabelled data, since that loss punishes a confident mistake extremely harshly.

Boosting can overfit — and this is the real contrast with a forest

Adding trees to a random forest settles toward a fixed answer and cannot overfit. Boosting has no such protection. Each tree is fitted to whatever is still wrong, and once the genuine signal is used up, what is left is noise — which the next tree will faithfully fit. Training error keeps falling; validation error bottoms out and then climbs.

So what: the number of trees is a genuine bias–variance knob here, not a "more is better" setting. That is why every boosting library ships early stopping, and why "more trees always helps" is true for Random Forest and false for boosting — a favourite trap, and the cleanest way to show you understand both.

Analogy — a sculptor roughing out a figure. The first pass is a crude block, wrong everywhere but wrong evenly. Each pass after that looks only at where the block still differs from the intended shape and takes a little off there; nobody re-carves the parts that are already right. That is boosting — every tree addresses only the leftover difference, and the statue is the sum of all the passes. The failure mode is in the analogy too: keep chasing ever-finer differences and you start carving the grain of the marble instead of the figure. Knowing when to put the chisel down is early stopping.

3 · Core intuitions

Boosting builds a committee where each member specializes in the previous committee’s mistakes

Start with a weak model. Look at what it gets wrong. Train the next model to focus on exactly that. Add it to the ensemble with a small weight. Repeat. Each individual model is barely better than guessing, but the sum becomes highly accurate — the surprising theoretical result that started the field.

AdaBoost reweights the data; gradient boosting reweights the target

AdaBoost keeps a weight per training sample, increases the weights of misclassified points, and fits the next stump to that reweighted distribution, then adds it with weight α = ½ln((1−ε)/ε) where ε is its weighted error — so accurate learners get large α, and a learner at exactly 50% error gets α = 0 and contributes nothing. Gradient boosting instead leaves sample weights alone and changes what the next tree is trying to predict: the negative gradient of the loss at the current predictions.

The single most important sentence in this module

🧭
Say “negative gradient”, not “residuals”

Each gradient-boosting tree is fitted to the negative gradient of the loss with respect to the current predictions. For squared error that happens to equal y − F(x), the residual, which is why the intuitive story works for regression. But for log-loss it is y − p, and for absolute error it is sign(y − F(x)). Saying “residuals” for the general case is the most common way candidates reveal a shallow understanding.

It is gradient descent in function space

Ordinary gradient descent updates parameters: w ← w − η∇_w J. Gradient boosting updates the function: F ← F − η∇_F J. Since you cannot add a gradient to a function directly, you fit a weak learner to approximate it. The new tree is the descent direction; the learning rate is the step size. This framing makes every boosting hyperparameter interpretable and is the best possible answer to “how are they related?”

Shrinkage and n_estimators trade off, and shrinkage almost always wins

Multiplying each tree’s contribution by a small η (0.01–0.1) means each step is a small correction, so more steps are needed but the ensemble generalizes better — averaging many small corrections is more robust than taking a few large ones. So the standard recipe is: set a low learning rate, set n_estimators high, and let early stopping on a validation set decide when to stop. Halving the learning rate roughly doubles the required number of trees.

Shallow trees, deliberately

Boosting wants weak learners, so depths of 3–8 (or num_leaves around 31 in LightGBM) are typical, versus fully grown trees in a Random Forest. There is an elegant interpretation: a depth-d tree can represent interactions of order at most d, so max_depth directly controls the interaction order your model can capture. Depth 1 (stumps) gives a purely additive model with no interactions; depth 2 allows pairwise interactions. Deeper trees in boosting overfit quickly because each is already fitting a residual signal that is mostly noise by later iterations.

Boosting chases noise, and this is its main structural weakness

Because each iteration focuses on what the ensemble currently gets wrong, and mislabeled points are permanently “wrong”, boosting keeps allocating capacity to them. AdaBoost is especially vulnerable, since exponential loss grows exponentially in the margin violation, so a single badly mislabeled outlier can dominate the weight distribution. Gradient boosting with log-loss is gentler, and Huber or absolute-error losses for regression make it more robust still. This is the crisp reason to prefer a Random Forest on known-noisy labels.

4 · Whiteboard formulas

boosting.txt
=== AdaBoost (binary, y in {-1,+1}) ===
init weights        w_i = 1/n
for m = 1..M:
    fit weak learner h_m to the weighted data
    weighted error  eps_m = SUM_i w_i * 1[h_m(x_i) != y_i] / SUM_i w_i
    learner weight  alpha_m = 0.5 * ln((1 - eps_m)/eps_m)
                    eps=0.5 -> alpha=0 ;  eps->0 -> alpha->infinity
    update weights  w_i <- w_i * exp(-alpha_m * y_i * h_m(x_i))   then renormalize
final               F(x) = sign( SUM_m alpha_m * h_m(x) )
implicit loss       exponential loss  L = exp(-y * F(x))

=== Gradient Boosting (any differentiable loss L) ===
init                F_0(x) = argmin_c SUM_i L(y_i, c)
for m = 1..M:
    pseudo-residual r_i = - [ dL(y_i, F(x_i)) / dF(x_i) ]  at F = F_{m-1}   <- THE key line
    fit tree h_m to predict r_i
    leaf values  gamma_j = argmin_gamma SUM_{x_i in leaf j} L(y_i, F_{m-1}(x_i) + gamma)
    update       F_m(x) = F_{m-1}(x) + eta * h_m(x)      eta = learning rate (shrinkage)

Negative gradient by loss:
    squared error 0.5*(y-F)²   ->  r = y - F           <- the ACTUAL residual
    log-loss (binary)          ->  r = y - p,  p = sigmoid(F)
    absolute error |y-F|       ->  r = sign(y - F)
    Huber                      ->  clipped residual

Function-space view:  F <- F - eta * grad_F J     with h_m approximating -grad_F J

5 · Hands-on drill

  1. Implement gradient boosting for regression from scratch on top of your Module 15 tree: initialize with the mean, loop computing residuals, fit a shallow tree, update with a learning rate. Confirm you match GradientBoostingRegressor closely.
  2. Extend it to log-loss and verify the pseudo-residual is y − p, not y − F. Doing this once permanently fixes the most-failed question in this module.
  3. Plot training and validation loss against n_estimators. Watch training loss fall monotonically while validation loss bottoms out and then rises — the overfitting signature bagging does not have.
  4. Grid the learning rate over {0.3, 0.1, 0.03, 0.01} and record the optimal n_estimators for each. Confirm the inverse relationship.
  5. Corrupt 5% of labels and compare gradient boosting against Random Forest. Quantify boosting’s larger degradation — that number is your evidence for the noise-sensitivity question.
  6. Implement AdaBoost with stumps and print the α sequence to see how learner weights evolve.
⚠️
Gotchas that fail candidates
  • Saying “each tree fits the residuals” without qualifying that this holds only for squared error.
  • Not knowing what AdaBoost’s α means, or that ε = 0.5 gives α = 0.
  • Saying boosting reduces variance. It primarily reduces bias.
  • Using deep trees in boosting.
  • Not using early stopping, or tuning n_estimators by grid search when early stopping is cheaper and better.
  • Claiming boosting is parallelizable across trees. It is sequential by construction; parallelism happens within split finding.
  • Not knowing boosting is sensitive to label noise.

6 · Interview questions

6 questions
01In gradient boosting, what exactly does each new tree fit?negative gradientpseudo-residualstrap＋
Strong answer

Each new tree is fitted to the negative gradient of the loss function with respect to the current model’s predictions, evaluated at the current ensemble — the pseudo-residuals rᵢ = −∂L(yᵢ, F(xᵢ))/∂F(xᵢ). It is not “the residuals” in general.

For squared error the negative gradient works out to exactly y − F(x), the ordinary residual, which is why the popular “fit the residuals” description is fine for regression with MSE. But for binary log-loss it is y − p where p = σ(F(x)) — the difference between the label and the predicted probability, not the raw prediction. For absolute error it is sign(y − F(x)), which is why an MAE-boosted model behaves so differently.

The general formulation is what lets gradient boosting work with any differentiable loss — Poisson for counts, quantile for asymmetric costs, Huber for robustness — and that generality is the whole point of Friedman’s framing.

30-second version

The negative gradient of the loss with respect to current predictions. That equals the residual only under squared error; under log-loss it is y − p, and under absolute error sign(y − F).

What’s being tested

The single highest-signal question in the boosting module. Interviewers use it precisely because “residuals” is the memorized answer and “negative gradient, which reduces to the residual under MSE” is the understood one.

Likely follow-up: “So what is the initial prediction F₀?” — the constant minimizing the loss: the mean of y for squared error, the median for absolute error, and the log-odds of the base rate for log-loss.
02Explain AdaBoost.AdaBoostexponential lossreweighting＋
Strong answer

AdaBoost maintains a weight per training sample, starting uniform at 1/n. At each round it fits a weak learner — classically a decision stump — to the weighted data, computes that learner’s weighted error ε_m, and assigns it an ensemble weight α_m = ½ln((1−ε_m)/ε_m). Then it multiplies the weights of misclassified samples up and correctly classified samples down, via wᵢ ← wᵢ·exp(−α_m yᵢ h_m(xᵢ)), and renormalizes — so the next learner concentrates on what the current committee gets wrong. The final prediction is the sign of the α-weighted vote.

Two things worth noting about α: a learner at exactly 50% error gets α = 0 and contributes nothing, while a near-perfect learner gets a very large α — so accuracy is rewarded superlinearly.

And it can be shown that AdaBoost performs coordinate-wise minimization of an exponential loss exp(−y·F(x)), which makes it a special case of the general gradient-boosting framework and also explains its notable sensitivity to mislabeled points, since exponential loss grows exponentially in the margin violation.

30-second version

Reweight misclassified samples up each round, fit a stump to the reweighted data, and add it with weight α = ½ln((1−ε)/ε). It implicitly minimizes exponential loss, which is why it is so noise-sensitive.

What’s being tested

Whether you know the mechanism, and whether you know the exponential-loss connection. That connection is what unifies this module.

03How do the learning rate and n_estimators interact, and how do you set them?shrinkageearly stoppingtuning＋
Strong answer

They trade off inversely: a lower learning rate means each tree contributes a smaller correction, so more trees are needed to reach the same training fit — roughly, halving the learning rate doubles the number of trees required.

Lower learning rates generalize better, because many small corrections are more robust than a few large ones. So the standard recipe is to fix a small learning rate (0.01–0.1 depending on compute budget), set n_estimators deliberately high, and let early stopping on a validation set determine where to actually stop.

That is strictly better than grid-searching n_estimators, because a single fit with early stopping finds the optimum for that learning rate at the cost of one training run rather than many. In practice I would tune the learning rate against my time budget — 0.1 for fast iteration, 0.01–0.03 for the final model — and always report which iteration early stopping selected, since a model that stopped at 80 trees out of 5,000 is telling you something about the signal in the data.

30-second version

Inversely: halving the rate roughly doubles the trees needed. Fix a small rate, set n_estimators high, and let early stopping choose — which is strictly cheaper than grid-searching the tree count.

What’s being tested

Practical tuning competence. The “use early stopping instead of grid-searching n_estimators” point is what makes it a practitioner’s answer.

04Why does boosting use shallow trees while Random Forest uses deep ones?depthbias-varianceinteraction ordertrap＋
Strong answer

Because they are attacking opposite error components. Random Forest reduces variance by averaging, so it wants base learners with low bias — fully grown trees that individually fit the data well, whose high variance averaging then cancels. Boosting reduces bias by sequentially correcting errors, so it wants base learners that are deliberately weak: a shallow tree contributes a small, low-variance correction and the ensemble builds accuracy gradually.

If you used deep trees in boosting, the first tree would already fit most of the signal, subsequent trees would fit noise in the residuals, and the ensemble would overfit rapidly.

There is also a nice interpretive angle: a depth-d tree can capture interactions of order at most d, so max_depth in boosting directly controls the interaction order of the model — depth 1 gives a purely additive model, depth 2 allows pairwise interactions, and so on. Typical values are 3–8 for boosting (or num_leaves ≈ 31 in LightGBM) versus unlimited depth in a Random Forest.

30-second version

Bagging cuts variance so it wants low-bias deep learners; boosting cuts bias so it wants deliberately weak ones. Also, depth d caps the interaction order — depth 1 is purely additive.

What’s being tested

Whether you can derive the hyperparameter choice from the bias–variance role of each method. The interaction-order interpretation is a strong extra.

055% of your labels are wrong. Random Forest or gradient boosting?label noiserobustnesstrap＋
Strong answer

Random Forest, for a structural reason. Boosting explicitly concentrates each successive learner on what the current ensemble gets wrong, and a mislabeled point is permanently wrong — so boosting keeps allocating capacity to fitting noise, in the worst case building a large part of the ensemble around a handful of bad labels. AdaBoost is the most vulnerable, since its exponential loss grows exponentially in the margin violation, so one badly mislabeled outlier can dominate the weight distribution.

Bagging has the opposite behaviour: each tree sees a bootstrap sample including the bad label only ~63% of the time, and averaging dilutes its influence.

If I did want boosting’s accuracy despite the noise, the mitigations are a robust loss (Huber or absolute error rather than squared error), a lower learning rate with aggressive early stopping, subsample below 1, and stronger leaf regularization.

But the highest-value action is not a modelling choice at all — it is cleaning the labels, since 5% noise puts a ceiling on what any model can achieve, and finding the mislabeled rows (for example by flagging high-loss training examples for review) usually beats any algorithmic workaround.

30-second version

Random Forest — boosting keeps chasing permanently-wrong points, while bagging sees each bad label in only ~63% of bootstraps and averages it away. But the real fix is cleaning the labels.

What’s being tested

Whether you understand why boosting is noise-sensitive, and whether you recognize the data as the real problem. Both halves are needed for a full answer.

06How is gradient boosting related to gradient descent?function spaceunifyingNewton＋
Strong answer

It is gradient descent, performed in function space rather than parameter space. Ordinary gradient descent parameterizes the model and steps w ← w − η∇_w J. Gradient boosting treats the prediction function F itself as the optimization variable and steps F ← F − η∇_F J.

The complication is that you cannot add a gradient to a function directly, so at each stage you compute the negative gradient at each training point — the pseudo-residuals — and fit a weak learner to approximate that vector, giving F_m = F_{m−1} + η·h_m. So the new tree plays the role of the descent direction, and boosting’s learning rate (shrinkage) is exactly the step size η.

The framing makes every hyperparameter interpretable: n_estimators is the number of descent steps, learning_rate is the step size, and early stopping is convergence monitoring. XGBoost extends the analogy to second order, using a Taylor expansion with both the gradient and the Hessian to choose leaf values, which makes it the function-space analogue of Newton’s method rather than plain gradient descent.

30-second version

It is gradient descent in function space: the tree approximates the negative functional gradient and shrinkage is the step size. XGBoost extends it to second order, making it function-space Newton.

What’s being tested

The unifying insight of Modules 09 and 17. Landing the Newton’s-method extension sets you up perfectly for Module 18.
