Your interview goal

Frame deep learning as “the same output layer plus learned features”, state that LLM pretraining is MLE with cross-entropy, and describe the hybrid architecture that combines both.

1 · From the ground up

🧩
In plain words

It is easy to feel that neural networks and large language models are a separate subject, and that everything in this course was the warm-up. They are not, and it was not. A neural network is logistic regression stacked and repeated. Training a language model is maximum likelihood — the same loss factory from Module 01. Benchmark contamination is data leakage wearing a new name. The vocabulary changes; almost none of the ideas do.

Logistic regression is already a neuron

Logistic regression takes your features, multiplies each by a weight, adds them up with a bias term, and squashes the result through a sigmoid. That is σ(w·x + b).

Now open any description of a single unit in a neural network. It takes its inputs, multiplies each by a weight, adds them up with a bias, and passes the result through an activation function. It is the same sentence.

So what: you learned the building block of deep learning in Module 07 and nobody called it that. A neural network is these units arranged in layers, with a non-linear function between them so that stacking actually buys something. Without the non-linearity, stacked linear layers collapse back into one linear layer — which is precisely why the activation function exists.

The loss comes from the same place it always did

Module 01 made the point that you do not invent a loss function — you derive it. Write down what you assume about the noise, apply maximum likelihood, and the loss falls out. Gaussian noise gives you squared error. A yes/no outcome gives you log-loss.

Extend that to a choice among many options and you get cross-entropy. Now ask what an LLM does during pretraining: given the text so far, pick the next token from a vocabulary of perhaps a hundred thousand. That is a many-way choice, so the loss is cross-entropy, so the training objective is maximum likelihood.

So what: "an LLM is trained to predict the next token" and "an LLM is trained by maximum likelihood" are the same statement. The scale is unrecognisable; the principle is the one you already have.

And the optimiser is literally the same code

Module 09 covered gradient descent, mini-batches, momentum, and Adam with its decoupled weight decay. Nothing there was a warm-up for something else — AdamW is what trains the frontier models. Same update rule, same learning-rate schedules, same problems with saddle points and bad initialisation.

So what: when a discussion turns to warmup steps, cosine schedules or gradient clipping, you are on ground you have already covered. The difference is the number of parameters, not the mathematics.

What genuinely changes: who builds the features

There is one real dividing line, and it is worth being precise about. In classical machine learning you build the features — you decide that "transactions in the last 30 days divided by account age" is the useful signal. The model then weights the features you handed it.

In deep learning the network builds its own. Give it raw pixels or raw tokens and the early layers learn edges or word fragments, later layers learn shapes or phrases, and nobody specified any of it. The name for this is representation learning, and it is the actual innovation.

So what: this single difference explains the whole landscape. Deep learning dominates images, audio and text because hand-building features for a pixel grid is hopeless. It does not dominate tabular data, because there your columns already are meaningful features — someone designed that database — and there is rarely enough data to learn better ones.

Why gradient boosting still wins on tables

It is 2026 and the honest answer to "which model for this spreadsheet?" is still a gradient-boosted tree. Three reasons, all following from the point above.

  • The columns are already features. Somebody designed that schema. There is little representation left to learn.
  • The columns are unrelated to each other. Deep learning exploits structure — neighbouring pixels, nearby words. Column 3 next to column 4 in a table means nothing, so there is no structure to exploit.
  • The data is small. Tabular datasets run to thousands or millions of rows, not billions of tokens. Learning representations needs data that most tabular problems do not have.
So what: this is a genuinely common interview question, and the wrong answer is "neural networks are more advanced". The right answer names the conditions — dense homogeneous input, exploitable structure, enough data — and observes that tabular problems usually meet none of them.

Your leakage instincts are the most transferable thing you own

Modules 04 and 05 trained you to ask one question compulsively: could this information have reached the model in a way it will not have in production? That question transfers to modern systems completely intact, and most people asking it about LLMs have never framed it that way.

  • A benchmark that appeared in the pretraining corpus is the test set in the training data. It is exactly the leak from Module 04, at web scale, and it is why an impressive benchmark score can mean nothing.
  • Picking few-shot examples by checking which ones score best on your evaluation set is tuning on the test set — the winner's curse from Module 20.
  • Evaluating a retrieval system on questions whose source document sits in the index, when real questions will not, is the same leak again.
So what: the technology moved on and the failure modes did not. Being the person in the room who asks "how do we know that benchmark was not in the training data?" is worth more than knowing any particular architecture, because that question stays useful when the architecture is replaced.

The system that actually ships is a hybrid

The common production pattern in 2026 is not "an LLM does everything". It is a division of labour along the line this module has been drawing.

The LLM handles the part where features are hopeless to build by hand — read the free-text complaint, pull out the entities, classify the sentiment, summarise the call. Its output becomes a few clean structured columns. Then a gradient-boosted tree takes those columns alongside your existing numeric features and makes the actual decision.

So what: the classical model keeps the decision because it is cheap, fast, calibrated, auditable, and can be monotonically constrained so risk can never fall as debt rises (Module 21). None of those are things an LLM gives you. Use the LLM where features are hard and the classical model where accountability is required — that sentence is a very strong close to a system design answer.
Analogy — you learned to cook by following recipes: someone else decided that this dish needs paprika, and you got good at judging how much. Deep learning is developing your own palate — nobody tells you which spices matter, you work it out from thousands of meals. That is a real and large difference, and it is the only one. Heat, timing, seasoning and knowing when something is done are identical in both worlds. And the cook who can taste anything still uses a recipe for the dish that must come out the same every single time — which is exactly why the boring, auditable model keeps the final decision.

3 · Core intuitions

Logistic regression is a one-layer neural network

Same linear combination, same sigmoid, same cross-entropy loss, same gradient Xᵀ(p−y). A neural network adds hidden layers with non-linear activations, which lets it learn the feature representation rather than requiring you to engineer it. That is the whole conceptual leap: deep learning is representation learning. Saying this in an interview frames everything else you know as directly relevant.

LLM pretraining is maximum likelihood estimation

Next-token prediction minimizes cross-entropy over a vocabulary — the multi-class version of the log-loss you derived in Module 07, applied at enormous scale. The softmax over the vocabulary is exactly Module 07’s multinomial logistic regression, sitting on top of a transformer instead of a linear layer. So when asked how an LLM is trained, the honest first sentence is “it is MLE with a cross-entropy loss”.

Benchmark contamination is data leakage

When a model’s pretraining corpus includes the test set of a benchmark, its score on that benchmark is meaningless in exactly the way a leaked feature makes your CV score meaningless. The concept transfers directly, and so does the fix: evaluate on data you know post-dates the training cutoff, or on private held-out sets. This is one of the cleanest bridges between classical rigour and modern practice, and a good thing to raise unprompted.

Classical ML has not been replaced — and the boundary is worth being crisp about

For tabular supervised learning with plentiful labels, gradient-boosted trees remain the strongest default. LLMs win where the input is unstructured language, where labelled data is scarce but the task is describable in words, where you need flexible zero-shot generalization, or where the output is itself text.

The most valuable practical pattern in 2026 is the hybrid: use an LLM or embedding model to convert unstructured columns into features, then feed those into a gradient-boosted tree that provides the calibrated, cheap, auditable decision. Being able to describe that architecture concretely is one of the most useful things this whole curriculum prepares you to say.

5 · Interview questions

3 questions
01How is logistic regression related to a neural network?bridgerepresentation learning＋
Strong answer

Logistic regression is a neural network with no hidden layers: one linear transformation w·x + b, a sigmoid activation, and a cross-entropy loss — trained by gradient descent with the gradient Xᵀ(p−y). Multinomial logistic regression is the same thing with a softmax output, which is exactly the final layer of nearly every neural classifier.

What a deep network adds is hidden layers with non-linear activations, and the consequence is qualitative: instead of requiring you to engineer features that make the classes linearly separable, the network learns a representation in which they are. That is the essential leap — deep learning is representation learning, and the output layer is still the logistic or softmax regression you already understand.

It is why the loss, the optimizer, the regularization concepts and the calibration concerns all carry over unchanged.

30-second version

It is a neural network with no hidden layers — same linear step, same sigmoid, same cross-entropy, same gradient. Depth adds learned representations; the output layer is still logistic or softmax regression.

What’s being tested

Whether your knowledge is unified or siloed. A very common opening bridge question, and framing deep learning as “the same output layer plus learned features” is the answer that lands.

02When would you use classical ML instead of an LLM in 2026?judgmentcosthybridapplied＋
Strong answer

Whenever the problem is supervised learning on structured data with plenty of labels — which is most business ML. Concretely, classical ML wins on: tabular prediction, where gradient-boosted trees typically match or beat neural and LLM-based approaches while training in minutes; cost and latency, since a tree ensemble is microseconds and fractions of a cent per million predictions versus an LLM’s tokens and hundreds of milliseconds; determinism and auditability, since the same input always yields the same output and you can attribute it, which regulated domains require; calibration, where a properly fitted model gives probabilities you can plug into an expected-cost calculation; and learning from your own historical labels, which an LLM can only access through whatever fits in a prompt.

LLMs win where the input is unstructured language, where labels are scarce but the task is describable in words, where you need zero-shot flexibility across many tasks, or where the required output is text.

And the highest-value pattern is the hybrid: use embedding models or an LLM to turn free-text columns — support tickets, notes, transcripts — into features, then feed those into a gradient-boosted tree that makes the actual calibrated decision. You get the LLM’s language understanding with the tree’s cost profile, determinism and auditability.

30-second version

For tabular supervised problems with plenty of labels — GBDTs win on accuracy, cost, latency, determinism and calibration. LLMs win on unstructured language, scarce labels or text output. Best of all is the hybrid: LLM embeddings as features inside a tree.

What’s being tested

Judgment and cost awareness — the archetypal 2026 question. The hybrid architecture is what elevates the answer from “knows the trade-offs” to “knows what to build”.

03What classical ML concepts still matter most for GenAI work?bridgeevaluationcontamination＋
Strong answer

More than people expect, and I would group them.

Evaluation discipline is the biggest: train/val/test separation, the fact that repeatedly looking at your test set invalidates it, and metric-to-objective alignment all apply directly — and benchmark contamination is just data leakage at internet scale, the exact failure mode from Module 04.

Retrieval is classical ML: RAG’s retriever is nearest-neighbour search over embeddings, evaluated with recall@k, precision@k and NDCG, and subject to the curse of dimensionality — so everything from Module 13 applies.

Calibration matters acutely, since LLMs are systematically overconfident and their stated confidence is unreliable; the same reliability diagrams and post-hoc corrections apply to any classifier built on their outputs.

Cross-entropy and MLE are how these models are trained, so the Module 01 and 07 derivations explain the objective. Class imbalance shows up in rare-intent classification and skewed evaluation sets for LLM-as-judge setups. Ensembling reappears as self-consistency and majority voting over samples. And drift monitoring applies to prompts and provider model versions, which change underneath you without notice — a form of concept drift you do not control.

The summary I would give: GenAI changed the model class, not the discipline of measuring whether something works.

30-second version

Evaluation discipline above all — and benchmark contamination is data leakage at internet scale. Plus retrieval as nearest-neighbour search, calibration for overconfident models, cross-entropy and MLE as the training objective, and drift monitoring for prompt and provider changes.

What’s being tested

Whether you see the field as continuous. Increasingly used to filter candidates whose GenAI knowledge is prompt-level from those with real ML foundations.
