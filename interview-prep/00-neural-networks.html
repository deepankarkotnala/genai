Neural Networks

A neural network is a function with adjustable numbers in it. Training searches for numbers that make its output match the data. Everything else on this page - layers, activations, backpropagation, optimizers - is machinery for doing that search efficiently.

⏱ Study + practice · 12–18 h Difficulty · Beginner → intermediate Prereq · Python, basic ML

1 · What you already know

You can write Python, and you have probably fitted a model with scikit-learn: pass in features and labels, call fit, get predictions.

That is the same job a neural network does. This page is about what fit is doing, because from module 02 onward you will be debugging systems built on it.

2 · What breaks now

Linear and logistic regression draw one straight boundary. That is enough for many problems and useless for the rest.

No straight line separates those four points. A linear model tops out at 50% accuracy here, and adding more training data or a better optimizer does not help, because the shape of the function cannot represent the answer.

Two fixes exist. Invent new features by hand - for XOR, the product of the two inputs - which requires you to already know the answer. Or stack simple functions with a non-linear step between them and let training discover the features. The second is a neural network.

3 · Simple breakdown - training vs inference

A Training

Basic level

What it is. Training is the process that repeatedly adjusts a network's weights so that its predictions on known examples get closer to the correct answers.

Core purpose. It finds values for the weights. Before training they are random and the network's output is meaningless.

Execution model.

Intermediate level

Architecture under the hood. The framework records every operation of the forward pass in a computation graph. Backpropagation walks that graph backwards applying the chain rule, producing one gradient per weight. An optimizer - usually AdamW - turns those gradients into an update, scaled by the learning rate. Memory holds the weights, the gradients, the optimizer's own running averages, and every intermediate activation needed for the backward pass.

State handling. Three kinds of state change: the weights, the optimizer's momentum and variance estimates, and the learning-rate schedule. All three must be checkpointed together, or a resumed run does not continue where it stopped.

Limitations and advanced features. Needs labelled data, and needs enough of it. Memory is roughly four times what inference needs for the same model. The loss can fall while the model gets worse on unseen data, which is overfitting and is invisible unless you hold data back. Advanced features include dropout, weight decay, batch and layer normalisation, learning-rate schedules, early stopping and mixed precision.

B Inference

Basic level

What it is. Inference runs the trained network forward once on new input to produce a prediction, with the weights held fixed.

Core purpose. It is the only part a user ever touches. Training happens once; inference happens on every request forever.

Execution model.

Intermediate level

Architecture under the hood. The same forward pass, with the computation graph switched off. In PyTorch that is model.eval() plus torch.no_grad(). eval() also changes behaviour: dropout stops dropping, and batch-norm uses the running statistics it collected during training instead of the current batch's.

State handling. None. The weights are read-only and nothing survives between requests. Any apparent memory is state your application carried.

Limitations and advanced features. The model cannot learn from what it sees at inference; that requires another training run. It has no way to signal that an input is unlike anything it was trained on - it returns a confident number regardless. Advanced options are quantisation, batching, distillation and export to ONNX or TensorRT.

The core differences

TrainingInference
Workflow design Forward, then loss, then backward, then update. Runs for hours or weeks over many batches, offline. Forward only. Runs in milliseconds, per request, online.
Error recovery Checkpoint weights, optimizer state and schedule together and resume. Divergence is detected by watching validation loss, not training loss. Retry or fall back to a smaller model. A wrong prediction raises nothing - it is only caught by monitoring against real outcomes.
Architectural paradigm An optimisation loop that writes the parameters. A pure function that reads them.

In short - which one you are doing

You are in training when:

  • You have labelled examples and want the model to fit them.
  • You are measuring loss curves and watching a validation set.
  • You need four times the memory the model alone would take.

You are in inference when:

  • The weights are already decided and you are serving requests.
  • Latency, throughput and cost per request are the numbers that matter.
  • You are calling any LLM API - that is always inference.

Do not confuse the two when:

  • You forget model.eval() and dropout stays on, so predictions differ every call.
  • You explain "the model learns from user chats" - it does not, unless someone ran training on them.
  • You size a GPU using inference memory and then try to fine-tune on it.

4 · Without the technology

One neuron is a weighted sum plus a bias. That is all.

Stack two of them and you still have a straight line, because a weighted sum of weighted sums is another weighted sum.

Depth without a non-linear step buys nothing. Insert one function that bends the output - that is the activation - and the stack can represent shapes a single layer cannot.

That one maximum is the difference between a linear model and a neural network.

5 · Runtime mechanics

One training step, in seven parts.

  1. Forward pass. The batch flows through each layer: multiply by weights, add bias, apply the activation.
  2. Loss. A single number saying how wrong the batch was - cross-entropy for classification, mean squared error for regression.
  3. Backward pass. The chain rule is applied from the loss back to every weight, producing a gradient for each: which direction would increase the loss, and how steeply.
  4. Zero the old gradients. Frameworks accumulate them, so last step's must be cleared first.
  5. Optimizer step. Each weight moves a small distance against its gradient. The distance is the learning rate.
  6. Repeat for the next batch. One pass over all the data is an epoch.
  7. Validate. Every so often, run on held-out data with no updates, to check the model is learning the pattern rather than memorising the examples.

Gradient descent is step 5 - the update rule. Backpropagation is step 3 - how the gradients were obtained. They are two parts of one loop, not alternatives, and mixing them up is the most common interview slip on this page.

6 · The components, one at a time

The network

1 · Weight and bias

The numbers training adjusts. A layer from 8 inputs to 4 outputs holds 8×4 weights plus 4 biases. Everything a model "knows" is these numbers.

2 · Layer

One matrix multiply plus a bias. Width is how many outputs; depth is how many layers are stacked.

3 · Activation

The non-linear function between layers. Without it, depth collapses.

FunctionWhat it doesUse it
ReLUmax(0, x)Default for hidden layers
GELUA smooth ReLUInside transformers
SigmoidSquashes to 0–1Binary output only
SoftmaxTurns scores into probabilities summing to 1Multi-class output only

Sigmoid and softmax belong on the output, not between hidden layers. Using sigmoid deep in a stack is what caused vanishing gradients before ReLU.

4 · Forward pass

Input to prediction. In PyTorch, calling the model runs it.

Learning

5 · Loss function

One number measuring wrongness. It must be differentiable, which is why accuracy cannot be a loss - it has no useful slope.

6 · Gradient

For one weight: how much the loss changes if that weight increases slightly. Positive means increasing it makes things worse, so the update moves the other way.

7 · Backpropagation

The chain rule applied backwards through the recorded graph, computing all gradients in one sweep rather than one per weight. It is an algorithm for computing gradients efficiently - it does not update anything.

8 · Gradient descent and the optimizer

The update rule: weight -= learning_rate * gradient. Plain SGD does exactly that. Adam keeps running averages of the gradient and its square, giving each weight its own effective step size, which is why it trains faster with less tuning. AdamW fixes how weight decay interacts with that and is the default for transformers.

9 · Learning rate

The single most important setting. Too high and the loss jumps around or becomes NaN; too low and training crawls. 3e-4 is a reasonable first try for Adam.

10 · Batch and epoch

A batch is the group of examples processed per update. An epoch is one pass over the whole dataset. Larger batches give steadier gradients and use more memory.

Making it generalise

11 · Train, validation and test

Train fits the weights. Validation guides your choices. Test is touched once, at the end. Tuning against the test set makes its number meaningless.

12 · Overfitting and underfitting

Overfitting: training loss falls, validation loss rises. Underfitting: both stay high. The gap between the two curves is the diagnosis.

13 · Regularisation

Dropout zeroes a random fraction of activations during training only. Weight decay pulls weights toward zero. Early stopping halts when validation loss stops improving.

14 · Normalisation

Rescales activations so each layer receives inputs in a stable range. Batch norm uses statistics across the batch and behaves differently in eval mode. Layer norm uses statistics within one example, which is why transformers use it - it does not depend on batch size or on other sequences.

7 · State and data flow

1 · What data is state?Weights and biases; during training also gradients, optimizer averages and the learning-rate schedule.
2 · Who writes each field?backward() writes gradients; optimizer.step() writes weights.
3 · Who reads it?The forward pass reads weights. The optimizer reads gradients.
4 · Replaced, appended or merged?Weights are replaced each step. Gradients accumulate, which is why zero_grad() exists.
5 · What controls merging?The optimizer, through its learning rate and momentum terms.
6 · Only in memory?Yes, until you save.
7 · Checkpointed?Only if you write one - and it must include the optimizer state, not just the weights.
8 · In a database?Usually a file, plus a model registry in production.
9 · How long does it survive?Weights: as long as the file. Gradients: one step.
10 · What key retrieves it again?The checkpoint path, or a model name and version.

9 · Break it

Raise the learning rate by a factor of a hundred.

Once the loss is NaN every weight is NaN and the run is dead. That one at least announces itself. The two that do not.

The second produces a validation score several points too high, which survives review, ships, and then does not reproduce in production.

10 · Fix it

Split first, then fit anything that learns from data on the training half only.

For the learning rate, do not guess - sweep it and read the curve.

And make eval mode impossible to forget by putting it where predictions are made.

Every fix here is about making a silent failure loud. The exploding learning rate was never the dangerous one - it told you immediately.

13 · Interview preparation

Start with the mental model

“The forward pass produces a prediction. Loss measures error. Backprop computes gradients. The optimizer updates parameters.”

Connect math to operations

Discuss tensor shapes, memory, numerical stability, train/eval mode, batching and monitoring.

Explain failure modes

Overfitting, unstable loss, vanishing gradients, leakage, class imbalance and incorrect objectives.

Show experimental discipline

Use baselines, validation sets, ablations, reproducible seeds, tracked metrics and versioned checkpoints.

Neural network interview questions

16 questions
01What is a neural network, and how is it different from linear regression?fundamentalsrepresentation＋
Strong answer

A neural network composes parameterized linear transformations with non-linear activation functions. Linear regression learns one linear mapping from features to a number; a multi-layer network can learn complex non-linear boundaries and intermediate representations. The trade-off is higher data, compute, tuning and interpretability cost.

30-second version

A neural network is a stack of learned transformations. Non-linear activations let the stack model relationships that one linear equation cannot.

Likely follow-up: What happens if every layer uses only linear operations?
02Explain a forward pass.forwardinference＋
Strong answer

A forward pass applies each layer to the input in order using the current parameters. It produces logits, probabilities, values or embeddings depending on the output head. During training, the framework also records operations needed for automatic differentiation; during inference, gradient tracking is disabled to save memory and compute.

30-second version

It is the input-to-prediction computation. Training keeps the computation graph for gradients; inference does not need it.

Likely follow-up: Why are tensor shapes important in the forward method?
03Why do neural networks need non-linear activation functions?activationlinearity＋
Strong answer

Multiple linear layers without a non-linearity collapse mathematically into one linear transformation, regardless of depth. Activations such as ReLU or GELU let layers compose non-linear functions and learn complex decision boundaries and representations.

30-second version

Without activations, depth adds parameters but not expressive power; the whole network is still linear.

Likely follow-up: Why is ReLU usually preferred over sigmoid in hidden layers?
04What is the difference between a loss and an evaluation metric?lossmetric＋
Strong answer

The loss is the differentiable objective optimized during training. A metric measures task quality in a human-meaningful way and does not have to be differentiable - for example accuracy, F1 or recall. They should align, but the best operational metric may not be suitable as a training loss.

30-second version

Loss drives gradients; metrics judge usefulness. I monitor both training/validation loss and task-specific metrics.

Likely follow-up: Why can validation loss improve while accuracy stays flat?
05Explain backpropagation without deriving every equation.backpropgradients＋
Strong answer

Backpropagation starts from the loss and applies the chain rule backward through the recorded computation graph. It computes the derivative of loss with respect to every trainable parameter, reusing intermediate results efficiently. It does not itself update weights; the optimizer performs the update.

30-second version

Backprop assigns credit or blame to each parameter by propagating loss sensitivity backward. The optimizer then uses those gradients.

Likely follow-up: What does loss.backward() do in PyTorch?
06What does the learning rate control, and how do you recognize a bad value?learning rateoptimization＋
Strong answer

The learning rate controls update scale. If it is too high, loss may oscillate, diverge or become NaN. If it is too low, loss decreases very slowly or appears stuck. I start from established ranges, use a scheduler or warmup when appropriate, and inspect learning curves rather than tuning blindly.

30-second version

It is the optimizer’s step size. Too large is unstable; too small wastes compute and may not reach a useful solution.

Likely follow-up: Why is warmup common in transformer training?
07What are vanishing and exploding gradients?gradientsstability＋
Strong answer

Repeated multiplication through deep networks can make gradients shrink toward zero or grow extremely large. Vanishing gradients stop early layers from learning; exploding gradients cause unstable updates and NaNs. Helpful controls include suitable initialization, non-saturating activations, residual connections, normalization, gradient clipping and appropriate learning rates.

30-second version

The backward signal becomes too small to learn or too large to stay stable. Modern architectures use residuals, normalization and careful initialization to control it.

Likely follow-up: How would you inspect gradient norms in PyTorch?
08How do you choose an activation function?ReLUGELUoutput＋
Strong answer

For hidden layers I usually follow the architecture’s proven default: ReLU-family functions for many MLP/CNN models and GELU or gated variants in transformers. For the output, the task and loss decide: raw logits for numerically stable cross-entropy losses, sigmoid probabilities for binary interpretation, and softmax for a mutually exclusive class distribution.

30-second version

Use a stable non-linearity inside the network; match the output and loss to the task, preferably passing logits directly to combined loss functions.

Likely follow-up: What is a dying ReLU?
09How do you detect and reduce overfitting?overfittingregularization＋
Strong answer

Overfitting appears when training performance keeps improving while validation performance stalls or worsens. I first rule out leakage and distribution mismatch, then use more or better data, augmentation, weight decay, dropout, early stopping, a smaller model or fewer training steps. The validation set must remain separate from tuning decisions.

30-second version

A widening train-validation gap is the signal. Fix data issues first, then reduce effective capacity or add regularization.

Likely follow-up: Why can a very large model still generalize well?
10What is the effect of batch size?batch sizememorythroughput＋
Strong answer

Batch size trades memory, throughput and gradient noise. Larger batches use hardware efficiently and produce smoother gradient estimates but require more memory and may need learning-rate scaling. Smaller batches are noisier, which can help exploration or generalization, but they reduce throughput. Gradient accumulation simulates a larger effective batch when memory is limited.

30-second version

Large batches are efficient but memory-heavy and less noisy; small batches are noisier and slower per epoch. I tune batch size with learning rate and hardware constraints.

Likely follow-up: What is gradient accumulation?
11Compare Batch Normalization and Layer Normalization.BatchNormLayerNormtransformer＋
Strong answer

BatchNorm normalizes each feature using statistics across the mini-batch and maintains running statistics for inference. Its behavior depends on batch composition and size. LayerNorm normalizes across a sample’s feature dimension, so it works consistently for variable-length sequences and small batches; that is why transformers use LayerNorm or RMSNorm.

30-second version

BatchNorm depends on batch statistics; LayerNorm normalizes within each example and is a better fit for sequence models.

Likely follow-up: Why does forgetting model.eval() hurt a BatchNorm model?
12What changes between model.train() and model.eval()?dropoutinferencePyTorch＋
Strong answer

Training mode enables stochastic dropout and makes BatchNorm use and update batch statistics. Evaluation mode disables dropout and uses stored BatchNorm statistics. It does not disable gradients by itself, so inference should also use torch.no_grad() or torch.inference_mode().

30-second version

eval() changes layer behavior; no_grad() changes autograd behavior. Production inference normally needs both.

Likely follow-up: Why might predictions differ between training and evaluation?
13Why does weight initialization matter?initializationXavierHe＋
Strong answer

Initialization sets the scale and symmetry of early activations and gradients. Initializing every weight identically prevents units from learning different features, while scales that are too small or large create vanishing or exploding signals. Xavier initialization is designed for roughly symmetric activations; He initialization is commonly paired with ReLU-family activations.

30-second version

Good initialization keeps signals in a trainable range and breaks symmetry so neurons learn different features.

Likely follow-up: Why are biases often initialized to zero while weights are not?
14Training loss is not decreasing. How do you debug it?debugginglossdata＋
Strong answer

I inspect a raw batch and verify targets, shapes, dtypes and preprocessing; confirm the output head and loss contract; try to overfit a tiny batch; inspect learning rate and gradient norms; remove optional regularization; and compare against a simple baseline. For NaNs I check input ranges, division or logarithm operations, mixed precision, exploding gradients and excessively high learning rate.

30-second version

Start with data and objective correctness, then prove the model can memorize a tiny sample, then inspect gradients and optimization.

Likely follow-up: What would it mean if the model cannot overfit ten examples?
15Where are standard neural-network components inside a transformer?transformerGenAIMLP＋
Strong answer

Token IDs index an embedding matrix; attention uses learned linear projections for queries, keys and values, then softmax weights values; each transformer block contains a feed-forward neural network with an activation such as GELU or SwiGLU; residual connections and normalization stabilize depth; and a final linear layer produces vocabulary logits. Pre-training uses next-token cross-entropy and backpropagation, commonly optimized with AdamW.

30-second version

A transformer is a deep neural network whose distinctive operation is attention. The rest - linear layers, activations, normalization, loss and optimization - comes directly from neural-network fundamentals.

Likely follow-up: What is the role of the feed-forward network after attention?
16Fully connected vs sparsely connected layers - which matters in modern LLMs?densesparseMoE＋
Strong answer

A fully connected layer lets every output see every input, so parameters scale as in × out; a sparsely connected layer restricts connections, trading flexibility for a structural prior and cheaper compute. Transformers are overwhelmingly dense - projections, the feed-forward block and the vocabulary head - which is why linear layers dominate memory bandwidth and are the target of quantization and LoRA. The sparsity that actually matters today is conditional: a Mixture-of-Experts layer routes each token to the top-k of many expert FFNs, so total parameters grow while active parameters per token stay small. Attention masks (sliding-window, local) are another practical sparsity that cuts the quadratic cost.

30-second version

Dense means all-to-all connections and parameters as the product of dimensions; sparse means each output sees a subset. In LLMs the useful form is MoE - sparse activation, not sparse weights - which separates total capacity from per-token FLOPs.

Likely follow-up: If MoE cuts FLOPs, why does it not cut serving memory?

14 · In short, and what comes next

Remember these five:

  • Without a non-linear activation, depth collapses into a single linear layer.
  • Backpropagation computes gradients; the optimizer applies them. Two different steps.
  • Training loss falling proves nothing. Watch the validation gap.
  • train() and eval() change behaviour, not just bookkeeping.
  • Leakage is silent and flatters your metrics. Split before you fit.
🔑
The one idea to remember

A neural network is a function with adjustable numbers, and training is a search for numbers that reduce the loss. Layers, activations, optimizers and regularisation all exist to make that search work on real data.
