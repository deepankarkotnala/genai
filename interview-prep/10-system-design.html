GenAI System Design

The senior round. You are not asked to recite RAG — you are handed a scenario with a constraint that makes the obvious design wrong, and watched to see whether you notice.

14 high-signal questionsSenior & staff roundsAnswer aloud, then open
🎯
How to practise this topic

Every question below is a scenario, not a topic. Before opening the answer, say out loud: what am I clarifying first, which layer does the constraint land on, and what am I trading away? A design that never names a trade-off reads as inexperience, however correct it is.

📐
One framework, six scenarios

Run the same order every time: clarify (sources, permissions, freshness, scale, latency, budget) → requirements → draw the layers (ingestion → retrieval → orchestration → safety → evaluation → observability) → close with trade-offs and what you would measure. The scenarios here are an enterprise knowledge assistant, a regulated document Q&A, a multi-tenant platform, a SQL data agent, a code assistant and a multi-agent business workflow.

14 questions
01Design an assistant over our internal docs that respects permissions.frameworkpermissions＋
Strong answer

Clarify before drawing: which sources, whose permissions, how fresh, how many users, what latency and budget. Then state requirements and draw the layers — ingestion and sync, retrieval with permission filters, orchestration, a safety layer, evaluation, observability. Close on the two decisions that matter here: permissions are enforced at retrieval time, not in the prompt, and freshness needs an explicit SLA because a wiki changes daily.

30-second version

Clarify sources, permissions, freshness and scale; draw ingestion → retrieval → orchestration → safety → evaluation → observability; then name the trade-offs. The permission model is the part that makes this design different from a demo.

Likely follow-up: Which of those layers would you build first if you had two weeks?
Red flag: Drawing boxes immediately without asking a single clarifying question.
02How do you guarantee an employee never sees a document they are not allowed to?permissionsretrieval＋
Strong answer

Filter at retrieval, using metadata tied to the user's groups, so a restricted document is never a candidate in the first place. For strongly separated domains, use separate indexes rather than a filter. Keep an output check as a second line of defence, and log which documents were used for each answer so an access question can be answered after the fact.

30-second version

Permissions are a retrieval filter, not a prompt instruction. If a document can be retrieved, treat it as already leaked — the prompt cannot be trusted to keep a secret.

Likely follow-up: The permission changes but the index was built yesterday. What happens?
Red flag: "I'd tell the model not to reveal documents the user can't see."
03How do you keep answers fresh as the source changes constantly?ingestionfreshness＋
Strong answer

Incremental sync driven by change events, or scheduled if the source has no events. Re-embed only what changed, tombstone deletions so removed content stops being retrievable, and invalidate caches when the index is rebuilt. Set a freshness SLA — "edits are searchable within fifteen minutes" — and monitor index lag against it.

30-second version

Event-driven incremental re-indexing, deletions tombstoned, caches invalidated, and a stated freshness SLA with index lag monitored against it.

Likely follow-up: A document is deleted for legal reasons. How fast can you guarantee it is gone?
Red flag: Re-indexing the whole corpus nightly and calling it fresh.
04How do you design RAG where a confident wrong answer is unacceptable?regulatedfaithfulness＋
Strong answer

Bias every trade-off towards abstaining. Require clause-level citations, gate the answer on a faithfulness check that blocks unsupported claims, let the system say "not found in the provided documents", cite the exact document version, and keep an audit trail of what was retrieved and returned. Accept lower coverage and higher latency as the price.

30-second version

Mandatory citations, a faithfulness gate that can block, a real abstain path, and an audit trail. In this domain a missing answer is cheap and a wrong one is not.

Likely follow-up: How do you measure whether the abstain threshold is set correctly?
Red flag: Optimising answer rate or "helpfulness" in a domain where being wrong is the expensive outcome.
05How do you handle document versions and effective dates in legal or finance Q&A?versioningmetadata＋
Strong answer

Version-aware ingestion: keep every version, with effective and expiry dates in metadata rather than overwriting. Filter retrieval to the version in force for the date the question is about, and cite the exact version used. "What did the policy say in March?" and "what does it say now?" are different queries over the same corpus.

30-second version

Keep all versions with effective dates as metadata, filter retrieval by the date in question, and cite the version — never silently overwrite a document.

Likely follow-up: The question does not mention a date. What do you retrieve?
Red flag: Treating ingestion as upsert-by-URL, which quietly destroys the audit trail.
06Why add a separate verification pass, and how does it work?verificationfaithfulness＋
Strong answer

A second pass takes each claim in the drafted answer and checks it against the span it cites, then blocks or flags anything unsupported. It is a different question from "write an answer", which is why a separate call catches what the first one missed. It costs another call and some latency, and in a high-stakes domain that is a good trade; in a support chatbot it usually is not.

30-second version

Claim-by-claim checking against cited spans, as a separate call, with authority to block. Worth the extra cost only where a fabrication is expensive.

Likely follow-up: What if the verifier and the generator make the same mistake?
Red flag: Adding a verifier everywhere without asking what it costs or what it is allowed to do.
07How do you design a multi-tenant RAG platform that enforces quality and isolation?platformmulti-tenant＋
Strong answer

Shared ingestion, retrieval and gateway services, with per-tenant namespaces and quotas so one tenant cannot exhaust or read another. A model gateway in front of every call for routing, caching, fallback and cost attribution. One shared evaluation harness and guardrail middleware that every tenant app inherits, so quality is a property of the platform rather than of whoever built each app.

30-second version

Shared services, per-tenant namespaces and quotas, one model gateway for routing and cost attribution, and platform-owned evaluation plus guardrails that apps inherit.

Likely follow-up: One tenant's traffic is ten times everyone else's. What breaks first?
Red flag: A shared index with a tenant_id filter and no quota story.
08What does a model gateway do, and why centralise it?gatewaycost＋
Strong answer

One entry point for every model call. It routes between a small and a large model, caches, falls back when a provider fails, enforces rate limits, holds the prompt-version registry, and attributes cost per tenant and feature. Centralised because otherwise each of those is re-implemented per app, inconsistently — and because switching provider becomes one change instead of twenty.

30-second version

Routing, caching, fallback, rate limiting, prompt versions and cost attribution in one place, so no app re-implements them and provider changes stay cheap.

Likely follow-up: The gateway is now a single point of failure. What do you do about it?
Red flag: Describing it as a proxy for API keys and nothing else.
09How do you get correct SQL out of a large, ambiguous schema?sql-agentgrounding＋
Strong answer

Ground the generation: retrieve the relevant tables, columns and their descriptions rather than pasting the whole schema, put a semantic layer of approved metrics in front so "revenue" has one definition, add few-shot question-to-SQL pairs from the real schema, and run a repair loop that feeds execution errors back once or twice. Show the generated SQL to the user before or alongside results.

30-second version

Retrieve the relevant schema instead of pasting all of it, define metrics in a semantic layer, few-shot with real examples, and repair against execution errors.

Likely follow-up: Two tables could answer the question and they disagree. What now?
Red flag: "Put the whole schema in the prompt" on a warehouse with two thousand tables.
10How do you enforce governance — read-only, row-level security — on a data agent?governancesecurity＋
Strong answer

At the database, not in the prompt. A read-only role, row-level security tied to the requesting user, and query validation that rejects anything but a SELECT. Then bound the damage a valid query can do: enforced LIMITs, statement timeouts, and a cap on bytes scanned, with alerting on cost spikes.

30-second version

Read-only role, row-level security as the requesting user, SELECT-only validation, plus limits, timeouts and scan caps. The prompt is not a security boundary.

Likely follow-up: The agent needs to write results back to a table. How does that change your answer?
Red flag: Relying on a system prompt that says "only generate SELECT statements".
11How do you safely let an agent run and modify code?code-agentsandbox＋
Strong answer

Execute only in an ephemeral sandbox with no network and no secrets mounted. Bound the number of steps and the spend. Surface every change as a diff and require a human-reviewed pull request to merge — the agent proposes, a person merges. Treat repository content itself as untrusted input, because a comment in a file can carry an injection.

30-second version

Ephemeral sandbox, no network or secrets, bounded steps and cost, changes land as a reviewed PR, and repo content is untrusted input.

Likely follow-up: The agent needs to install a dependency to run the tests. Now what?
Red flag: Giving the agent commit or deploy rights because review is "a bottleneck".
12When is multi-agent actually worth it, over a single agent or a plain workflow?multi-agenttrade-off＋
Strong answer

Only when the work genuinely splits into distinct skills and the routing between them has to be decided at run time. Otherwise a single agent, or a deterministic workflow, is cheaper, faster and far easier to test. Multi-agent buys specialisation and parallelism and pays for it in coordination overhead, latency and new failure modes — agents talking past each other, or looping.

30-second version

Distinct roles plus dynamic routing justifies it. Known steps means a workflow. Multi-agent is a cost you take on for specialisation, not a default.

Likely follow-up: Where do you put the human approval step in a multi-agent business workflow?
Red flag: Reaching for a crew of agents when the process is five known steps in a fixed order.
13On a support bot, how do you balance deflection against giving wrong answers?support-botmetrics＋
Strong answer

Do not optimise deflection alone — it is trivially gamed by answering everything badly. Gate answering on coverage and faithfulness, bias towards escalation when either is weak, and track escalation precision and customer satisfaction beside the deflection rate. A bot that deflects 60% with high satisfaction beats one that deflects 80% and burns trust.

30-second version

Deflection is only meaningful next to escalation precision and satisfaction. Gate on coverage and faithfulness, and escalate when unsure.

Likely follow-up: How would you set the escalation threshold, and how often would you revisit it?
Red flag: Naming deflection rate as the single success metric.
14"It's too expensive. Fix it."costrouting＋
Strong answer

Measure first — cost per request, split by feature and by model, because the fix depends on where it goes. Then the usual three: cache repeated and near-repeated queries, route easy traffic to a smaller model and keep the large one for hard cases, and trim the context you are sending, since retrieved chunks are often most of the bill. Re-run evaluation afterwards to prove quality held.

30-second version

Attribute the cost first, then cache, route small-model-first, and trim context — and re-run the evals to show quality did not move.

Likely follow-up: Routing saved 40% and quality dropped 3 points. Do you ship it?
Red flag: Cutting straight to "use a cheaper model" without measuring where the money actually goes.
