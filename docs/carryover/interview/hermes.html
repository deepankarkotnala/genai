Beginner What is Hermes and how does it differ from Llama? ›

Hermes 3 is a fine-tune of Llama 3.1, available in 3B, 8B and 70B. The base knowledge and context window come from Llama; the fine-tune changes behaviour - instruction following, structured JSON output, tool calling, and a lower refusal rate. It adds no new facts, because fine-tuning changes how a model responds rather than what it knows.

Beginner Why would you run a model locally at all? ›

Four reasons: the data is not permitted to leave the network; volume is high enough that per-token pricing dominates; you need output that reproduces months later; or you are working offline. If none of those apply, a hosted model is usually the better default - local serving trades a hard memory ceiling for those four properties.

Intermediate A local model will not call your tools. How do you debug it? ›

Check the endpoint first: tools must go through the chat endpoint so the model’s chat template is applied. A raw completion call bypasses the template and the model never sees the markers it was trained on. Then check the reply shape - prose in content with an empty tool_calls means it described the call instead of making it. Then improve the tool description to say when to use it. Only after those three would I consider a different model or grammar-constrained output.

Intermediate How do you choose between Ollama and vLLM? ›

By concurrency. Ollama serves one user well, swaps models freely, and falls back to CPU when a model does not fit - which makes it right for development and single-user tools. vLLM pins one model in GPU memory and uses paged attention with continuous batching, so a finished request frees its slot mid-flight and one GPU serves many users. The cost is that setup is a deployment task and a model that does not fit simply fails to start.

Senior How do you decide whether a local model is good enough for an agent? ›

Measure tool-call reliability separately from answer quality, because they are different properties and reading the answers will not reveal the difference. I run each prompt variant twenty times and count four outcomes: correct call, described-but-not-called, wrong tool, malformed arguments. Below roughly 90% correct calls the model goes in a fixed workflow rather than an agent loop, because each failure compounds across steps - at 90% per step, a five-step run succeeds about 59% of the time. That audit runs in CI so a model or quantisation change cannot regress it silently.

Senior What operational risks come with open-weight models? ›

Licence first - open weights is not open source, and Llama’s licence carries an acceptable-use policy and a user threshold requiring permission above it. Then version drift: an upstream re-tag can change tool-call reliability with no signal, so pin name, size and quantisation together. Then quantisation quality, which degrades argument formatting before it degrades prose, so the audit has to run per quantisation. Then capacity, because there is no elastic scaling - you own the queue. I would pair it with a hosted fallback triggered by repeated empty tool calls.
