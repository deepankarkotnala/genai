Beginner  What is LlamaIndex and how is it different from LangChain? ›

LlamaIndex is a data framework specialized for connecting data to LLMs - loading, chunking into Nodes, indexing, retrieving, and synthesizing answers (RAG). LangChain is a general composition framework for any LLM pipeline. LlamaIndex is the data/RAG specialist with stronger ingestion and advanced-retrieval abstractions; they're often combined.

Beginner  What's the difference between a Document and a Node? ›

A Document is a whole source (a file, page, or record). A Node is a chunk of a Document - the actual retrievable unit - carrying text, metadata, an embedding, and relationships to neighboring nodes (prev/next/parent). Node parsers turn Documents into Nodes.

Intermediate  What exactly is a Query Engine made of? ›

A retriever (fetches relevant Nodes from an index), optional node postprocessors (rerank, filter, window-replace), and a response synthesizer (composes Nodes + query into a grounded answer, with a synthesis mode like compact/refine/tree_summarize). It's the end-to-end "ask → answer with sources" object.

Intermediate  Explain sentence-window / auto-merging retrieval. ›

Both solve the small-vs-large chunk dilemma (Module 06's parent-document). Sentence-window embeds single sentences for precise matching but returns each matched sentence with a window of surrounding sentences for context (via a metadata-replacement postprocessor). Auto-merging uses a hierarchy of chunk sizes and merges small matched chunks into their parent when enough siblings hit - giving precision plus coherent context.

Senior  How do you take a LlamaIndex prototype to production? ›

Swap the in-memory store for a real vector DB (Qdrant/pgvector) and persist the index so you don't re-embed on boot. Move ingestion into a scheduled, idempotent IngestionPipeline that handles updates/deletes and tags model_version (Module 04). Tune chunking and add reranking, validated by an eval set (Module 06). Set local/hosted models and temperature via Settings; add metadata-based access control; expose the query engine behind a service boundary (FastAPI). Add tracing/observability and cost controls (Module 14). Treat it as the data layer, with orchestration/agents handled by LangGraph if needed.

Senior  When would you combine LlamaIndex and LangGraph? ›

When the app needs both strong retrieval and multi-step/agentic control. Use LlamaIndex to build a high-quality query engine (advanced retrieval, synthesis), then expose it as a tool to a LangGraph agent that decides when to retrieve, can retrieve iteratively (Agentic RAG, Module 06), branch, and keep state. LlamaIndex handles "how to retrieve well"; LangGraph handles "how to orchestrate the reasoning loop."

Staff · design  Design a multi-source enterprise knowledge engine with LlamaIndex. ›

Ingestion: LlamaHub readers per source (wiki, tickets, docs, DB) → IngestionPipeline (parse to Nodes with rich metadata: source, ACL, freshness, model_version) → embed → persist to a sharded vector store (Module 05). Retrieval: per-source indexes with a router query engine (DocumentSummaryIndex) to pick relevant sources, sentence-window/auto-merging for context, reranking for precision, and metadata pre-filtering for access control (never post-filter security). Synthesis: compact for Q&A, tree_summarize for overviews, always returning source_nodes for citations. Operations: scheduled re-ingestion to meet freshness SLAs, eval gates (recall/faithfulness, Module 06) in CI, observability + cost tracking (Module 14). Expose the engine as a tool to a LangGraph agent for multi-step questions. The deliverable is a governed, fresh, citable retrieval layer reusable across the org.
