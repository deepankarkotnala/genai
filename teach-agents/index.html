Understanding AI Agents

A hands-on, interview-focused course. You build one support-ticket triage agent and grow it, one capability per lesson, from a forty-line loop into a system with retrieval, memory, approval gates, guardrails, evaluation and tracing. No framework, and no API key.

15 lessons · ~49 h Beginner → intermediate One project throughout Runs offline
🚧
Wave 1 of 5 · lessons 1–3 are live, lessons 4–15 are in progress

Lessons 1–3 are complete and runnable: the model abstraction, the explicit agent loop, and the tool layer with validation, plus fixtures and 36 passing tests. Lessons 4–15 are being written in waves — reasoning patterns and retrieval next, then reliability and the refund approval path, then evaluation, tracing, MCP and multi-agent, then deployment and the interview capstone.

The five lessons of the previous version of this course have been retired. They required an API key, taught a codebase that no longer exists, and depended on a spreadsheet that was never part of this repository — so following them alongside these would contradict rather than supplement.

At the heart of every lesson is one idea: an agent runs a loop. It perceives the situation, reasons about what to do, acts by calling a tool, then observes the result — and loops again until the job is done, or until a step limit stops it.

Perceiveread the input / current state
Reasonthe LLM decides what to do next
Act (tool)call a function / run code
Observeread the tool result… then loop

Lessons 1–3 · Foundations

Lesson 01

LLM mechanics

Concept + build · ~2.5 h

Messages and roles, the context window, determinism, structured output, what tool calling really is. Build the model abstraction the whole course runs on.
Lesson 02

The agent loop

Build · ~3 h

Forty lines, no framework. Prompt vs chain vs workflow vs agent, when not to build one, termination and step limits. Adds search_kb.
Lesson 03

Tools & validation

Build · ~3.5 h

Schemas, typed arguments, unknown tools, parallel vs sequential, and the trusted/untrusted boundary. Adds read_ticket and lookup_order.

Lessons 4–15 · In progress

Written in four further waves. Each adds one capability to the same agent:

  • Wave 2 — reasoning and orchestration patterns (ReAct, plan-and-execute, reflection, routing) · retrieval as a tool · context, state and memory
  • Wave 3 — reliability and safe termination · irreversible actions and human approval (issue_refund) · security and guardrails
  • Wave 4 — agent evaluation · tracing, latency and cost · MCP and the tool boundary · multi-agent and A2A
  • Wave 5 — frameworks, deployment and operations · the interview capstone
