What this section is, and how it differs from the course

Fifteen pages, one per lesson of the hands-on course, each written to the same sixteen-section shape: what you already know, what breaks, a comparison of two real technologies, the manual version, the mechanics, the smallest working code, the components, state, full assembly, a trace, a failure, the fix, production concerns, alternatives, interview questions, and what comes next.

This section explains why each mechanism exists. The hands-on course makes you build it against a working codebase with 190 passing tests. Read a page here, then build it there - or the other way round.

Foundations

What a model is, the loop around it, and the tools it can ask for.

Page 01

What a language model actually does

A language model vs a rules engine · ~18 min

A language model scores the next token and nothing else. What that one fact forces on every application built above it, and why an API call is not the same thing as a model.
Page 02

The agent loop

An agent vs a fixed workflow · ~20 min

An agent is a loop: the model chooses one action, your code runs it, the result goes back in. Why the step limit is the only real bound, and when a workflow is the better answer.
Page 03

Tools and the trust boundary

Tool calling vs parsing free text · ~19 min

What a tool declaration really is, why the description is prompt engineering, and why a trusted tool delivers untrusted text into your prompt.
Page 04

Reasoning patterns

ReAct vs plan-and-execute · ~18 min

ReAct, plan-and-execute, reflection and routing are four arrangements of the same loop. What each one changes about cost, latency and failure.

Knowledge

Giving the loop information it was never trained on, and managing the budget.

Page 05

Retrieval

Retrieval vs fine-tuning · ~20 min

How an agent finds information it was never given: chunking, ranking, reranking, and the relevance floor that lets retrieval return nothing instead of the least bad paragraph.
Page 06

Context and memory

Compaction vs a larger context window · ~17 min

State belongs to one run; memory outlives it. Token budgets, capping tool results at the source, and compaction that knows when it would not help.

Safety

The controls that make an agent safe to point at a real system.

Page 07

Reliability

Retry vs fallback · ~18 min

Five controls for the four failures that actually happen. Why a timeout does not stop the work, why retrying is only safe for some errors, and why escalation must never fail.
Page 08

Irreversible actions

An approval gate vs full autonomy · ~18 min

Recommend versus execute, policy in code rather than in the prompt, idempotency keys derived from the request, and why the order of the checks is the design.
Page 09

Security

Absent capability vs an input filter · ~19 min

Prompt injection ranked honestly. Why an absent capability is the only structural defence, why authorisation is checked against the caller, and how the reply itself becomes an exfiltration route.

Operations

Measuring whether it works, and seeing inside one run.

Page 10

Evaluation

Deterministic assertion vs LLM-as-judge · ~18 min

Outcome evaluation checks the answer; trajectory evaluation checks the path. Why you need both, where a deterministic assertion beats a model judge, and how a suite becomes a gate.
Page 11

Tracing and cost

Tracing vs logging · ~17 min

What a trace gives you that logs do not, the span shape that makes a run reassemblable, the four levers on cost, and why traces are a data-retention surface.

Scale

Sharing tools, delegating to peers, and shipping it as a service.

Page 12

MCP

MCP vs an in-process tool · ~17 min

Why N times M becomes N plus M, the three roles, and the security risk people miss - the tool description is written by someone else and lands in your prompt.
Page 13

Multi-agent

A supervisor vs a single agent · ~17 min

An agent is not a tool, because the far side has its own goals. When a supervisor earns its cost, what A2A adds over MCP, and why delegation moves work but never authority.
Page 14

Deployment

A long-lived service vs a batch script · ~17 min

Wrapping the agent in a service forces concurrency, timeouts, health and versioning. Why a prompt change is a deploy, and what a version lets you refuse.

Capstone

Building it yourself vs adopting a framework · ~16 min

How to use it

Every page is self-contained, so you can start anywhere. If you are working through the hands-on course, read the page here that pairs with the lesson you are on: each one links to its lesson at the top.

Each page ends with six interview questions at four levels, and a one idea to remember box. If you can state that idea and name the failure it prevents, the page has done its job.
