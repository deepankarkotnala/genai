Jev - a System-1 Decision Model

An LLM writes. You ask a question, it replies in text, and your code has to read that text and work out what it means. Jev does not write at all. You give it some messy input and a question with fixed options. It gives back one of those options, plus how sure it is. It does this fast and cheap. This page explains the idea and where it fits.

⏱ Quick read · 30–45 min Beginner-friendly Agents · AI/ML pipelines
🗓️
Brand new - read the numbers with care

TypeSafe AI released Jev in early access on 15 September 2026. It is a hosted API with a waitlist. Its speed, cost and accuracy numbers come from TypeSafe's own tests and have not been checked by anyone else yet. Learn the idea here, and test on your own data before you rely on it.

1 · What Jev is, in one line

🔑
The one-sentence model

Jev is a smart function call. Messy input goes in, a typed decision with a confidence score comes out.

Think of the if statements in your code. Some are easy: if amount > 1000. Some are fuzzy: "is this customer angry?" or "is this email about billing?". Normal code can't answer fuzzy questions. Until now you had to call an LLM for them, which is slow and costs money. Jev is built to answer only these fuzzy questions, and to do it quickly.

2 · Why "System 1"?

The name comes from Daniel Kahneman's book Thinking, Fast and Slow. He says people think in two ways:

⚡

System 1 - fast

Quick, gut-feeling judgments. You see a face and know at once that the person is angry. You don't reason it out step by step.

🐢

System 2 - slow

Careful, step-by-step thinking. Solving a maths problem or planning a trip. It is powerful, but slow and tiring.

A chat LLM that "thinks" and then writes is System 2. Jev is System 1: one quick judgment, no essay. Most decisions inside real software are small and repeated thousands of times, like "which team gets this ticket?". A quick judgment is enough for those.

3 · How it is different from an LLM

An LLM builds its answer one token at a time, and each token waits for the one before it. Jev skips that. It looks at the input once and scores every option in parallel, in a single pass.

LLM (System 2)Jev (System 1)
OutputFree textOne of your options, typed
How it answersToken by token, in orderAll options at once, in one pass
SpeedSeconds~70–500 ms (TypeSafe's figure)
ConfidenceOften sounds sure even when wrongTrained to give an honest confidence score
ParsingYou parse the text and hope it's validAlways matches your schema, nothing to parse
Good forWriting, reasoning, planning, chatClassify, route, score, filter, yes/no
🎯
"Can't hallucinate" - what that really means

Jev cannot make up an answer that isn't one of your options, because it never writes free text. That is a real win: no broken JSON and no invented labels. But it can still pick the wrong option. "Always valid" is not the same as "always right".

TypeSafe trains it with a method it calls RLCD (Reinforcement Learning for Calibrated Decisions). Chat LLMs are trained to give answers people like. RLCD trains Jev to give confidence scores that are honest: when it says 90% sure, it should be right about 90% of the time.

4 · The three kinds of question

You ask Jev only three kinds of question. Each one returns a value and a confidence score.

🔀

Choice

Pick one option from a list (up to 255). "Which team should handle this ticket?"

📏

Score

Place something on an ordered scale. "How frustrated is this customer: calm, annoyed, or very angry?"

✅

Noul (yes/no)

A probability from 0 to 1 that something is true. "Is this message urgent?"

Here is roughly what that looks like, based on TypeSafe's early-access Python SDK. The SDK is new, so check the docs for exact names.

triage.py - sketch
# 1. Describe the questions. Jev answers only these - it never writes text.
team = Choice(
    instructions="Which team should handle this support ticket",
    criteria={
        "billing":   "Payment or subscription issues",
        "technical": "Bugs or integration problems",
        "sales":     "Pricing or account questions",
    },
)
mood   = Score(instructions="How frustrated the customer is",
               criteria=["Calm", "Frustrated but civil", "Very angry"])
urgent = Noul(instructions="The message is urgent")

# 2. Send the ticket plus all three questions in ONE call.
#    They run in parallel, so asking three costs about the same time as one.

# 3. Read back typed values - no parsing, no JSON repair.
team.choice        # "billing"
team.confidence    # 0.93
mood.score         # 2.1  (between "civil" and "very angry")
urgent.noul        # 0.81 (81% likely to be urgent)

5 · Confidence is the real feature

The answer alone isn't very useful. The confidence tells your code how much to trust it. Set a different bar for each action, based on how bad a mistake would be:

gate.py
if action.confidence < 0.5:
    send_to_human()                 # not sure -> a person decides
elif action.choice == "refund" and action.confidence > 0.85:
    issue_refund()                  # costly action -> needs a high bar
else:
    ask_user_to_confirm()           # in between -> double-check

This is how Jev makes decisions without a human watching every one: it acts when it is sure and asks for help when it isn't.

6 · Where it fits in agent apps

An agent makes many small decisions in a loop. Most of them are simple choices, not deep reasoning. Using a big LLM for every one is slow and expensive. Give those small choices to Jev.

🚦

Router

Send each request to the right sub-agent, tool or model. "Is this a billing, tech or sales question?"

🛡️

Tool-call guardrail

Before an agent runs a tool, ask Jev: allow, ask a human, or deny? It is fast enough to check every call. See Guardrails.

🖱️

Browser & computer-use steps

"Which of these 40 buttons do I click next?" is just a Choice. TypeSafe showed a flight-booking browser agent finishing in about 7 seconds.

🔍

Checking LLM output

After an LLM writes an answer, ask Jev: "Is this answer supported by the sources?" That gives you a cheap second opinion.

The most useful pattern is the cascade: three layers, cheapest first.

1 · Jev decidesfast, cheap: route / classify / check
2 · Plain code actsroutine cases handled by normal logic
3 · LLM only when neededhard or low-confidence cases escalate
The cascade. Jev handles the many easy calls, code does the safe and exact work, and the expensive LLM sees only the few cases that really need it.

7 · Where it fits in AI / ML work

  • Labelling data at scale. Tag thousands of rows (topic, sentiment, spam or not) for a tiny cost. TypeSafe reports classifying about 1,000 research papers for around $0.08.
  • Making features for a classic model. Turn messy text into clean columns ("urgency score", "product category") that XGBoost or logistic regression can use. See feature engineering.
  • Filtering in RAG. After retrieval, ask Jev "Is this chunk relevant to the question?" and drop the noise before the LLM sees it. See RAG, End-to-End.
  • Moderation and triage. Flag unsafe or off-topic content in real time, inside a request, without adding seconds of delay.
  • Scoring for evals. Score outputs against a fixed rubric (for example "helpful: 1–5") as a quick, cheap judge. See LLM Evals.

8 · When not to use it

✅ Good fit

Routing and triage · moderation · relevance filtering · checking LLM output · tagging at scale · quick decisions inside a web request.

❌ Poor fit

Writing any text · maths, counting or date calculations · decisions that need a written reason for an audit · one-off hard reasoning.

  • It reads instructions literally. Spell out "not" and hidden conditions plainly.
  • Less context is better. Send only the fields that matter. Extra noise lowers accuracy.
  • User input can be an attack. Test for prompt injection like you would with any model.
  • Keep safety rules and maths in code. Let Jev make the fuzzy call and let normal code do everything exact.

9 · Key takeaways

🧠
Remember these

1. Jev is not a cheaper LLM. It is a different tool: it decides and never writes.
2. It returns a typed choice, score or yes/no, with an honest confidence, in one fast pass.
3. Use the confidence to decide: act, double-check, or hand to a human.
4. In agents it is the router, the guardrail and the step-picker. In ML it labels, filters and makes features.
5. Build a cascade: Jev first, plain code next, the big LLM only when needed.
