How to work a live-coding question

Restate the problem, ask about edge cases — empty input, duplicates, negatives — say your approach out loud before typing, write it, then state the time and space complexity yourself. Candidates who narrate get credit for thinking even when the code has a bug; candidates who type in silence do not.

Classic coding-round problems

01Solve Two Sum and give its complexity.codinghashinghigh-frequency＋
Simple answer

Walk the list once, and for each number check whether the value that would complete the pair has already been seen. A dictionary of value to index makes that check constant time, so the whole thing is one pass. The brute-force nested loop is O(n²); this is O(n) time and O(n) space, and naming that trade-off out loud is the point of the question.

two_sum.py
def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}                      # value -> index
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:
            return [seen[need], i]
        seen[num] = i
    return []
Say this in 30 seconds

One pass with a dict of value to index, checking for the complement. O(n) time, O(n) space, versus O(n squared) brute force.

Likely follow-up: What changes if the array is already sorted?
02Find the second-largest distinct element in a list.codinghigh-frequency＋
Simple answer

Track the largest and second-largest in one pass, updating carefully so duplicates of the maximum do not become the runner-up. That is O(n) time and O(1) space. Sorting works too but is O(n log n), and sorted(set(nums))[-2] is fine to mention as the readable version — say both and let them pick.

second_largest.py
def second_largest(nums: list[int]) -> int | None:
    first = second = None
    for n in nums:
        if first is None or n > first:
            first, second = n, first
        elif n != first and (second is None or n > second):
            second = n
    return second
Say this in 30 seconds

One pass tracking the top two, skipping duplicates of the maximum. O(n) time and constant space.

Likely follow-up: What should it return for [5, 5, 5]?
03Check whether two strings are anagrams.codingcounting＋
Simple answer

Compare character counts. Counter(a) == Counter(b) is O(n) and reads in one line. Sorting both and comparing also works but is O(n log n). Ask first whether case, spaces and unicode matter — the clarifying question is worth as much as the solution.

anagram.py
from collections import Counter

def is_anagram(a: str, b: str) -> bool:
    return Counter(a) == Counter(b)
Say this in 30 seconds

Compare character counts with Counter — O(n). Sorting works too but is O(n log n).

Likely follow-up: How would you group a list of words into anagram groups?
04Reverse a linked list.codinglinked list＋
Simple answer

Walk the list re-pointing each node at the previous one, keeping three references: previous, current and the next node saved before you overwrite the pointer. It is O(n) time and O(1) space. The recursive version is neat but uses O(n) stack, which matters on a long list.

reverse_list.py
def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev
Say this in 30 seconds

Iterate re-pointing each node backwards with previous, current and next references. O(n) time, constant space.

Likely follow-up: How would you detect a cycle in the list?
05Find the first non-repeating character in a string.codingcounting＋
Simple answer

Count every character in one pass, then scan the string again and return the first with a count of one. Two passes, O(n) time and O(k) space for the alphabet. Because dictionaries preserve insertion order, you can also just scan the counter itself for the first count of one.

first_unique.py
from collections import Counter

def first_unique(s: str) -> str | None:
    counts = Counter(s)
    for ch in s:
        if counts[ch] == 1:
            return ch
    return None
Say this in 30 seconds

Count in one pass, then scan for the first count of one. O(n) time.

Likely follow-up: How would you do it in a single pass over a stream?
06Print a decreasing star pattern.codingfreshers＋
Simple answer

A fresher-round staple, testing loops and string multiplication rather than algorithms. Use string repetition instead of an inner loop, and work out the indentation as a function of the row number before you type. Say the formula out loud — that is what is being marked.

pattern.py
def stars(n: int) -> None:
    for i in range(n, 0, -1):
        print(" " * (n - i) + "*" * i)

# n = 4:
# ****
#  ***
#   **
#    *
Say this in 30 seconds

One loop counting down, using string repetition for both the indent and the stars.

Likely follow-up: Now print it as a pyramid centred on the page.
07Implement a Fibonacci function three ways.codingrecursioncaching＋
Simple answer

Naive recursion is O(2ⁿ) and recomputes everything. Adding lru_cache memoises it down to O(n). The iterative version is O(n) time and O(1) space and is the one to ship. Showing all three in thirty seconds demonstrates you understand memoisation, not just recursion.

fib.py
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n: int) -> int:
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

def fib_iter(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
Say this in 30 seconds

Naive recursion is exponential, lru_cache brings it to O(n), and the iterative version is O(n) time with constant space.

Likely follow-up: Why does the recursive version blow up at around n=40?
08Flatten an arbitrarily nested list.codingrecursiongenerators＋
Simple answer

Recurse with a generator and yield from, so nesting of any depth is handled and nothing is built in memory until the caller consumes it. Mention the iterative stack-based version as the alternative for very deep nesting, where recursion would hit the limit.

flatten.py
def flatten(items):
    for item in items:
        if isinstance(item, (list, tuple)):
            yield from flatten(item)
        else:
            yield item
Say this in 30 seconds

A recursive generator with yield from, so it is lazy and handles any depth. Use an explicit stack if nesting could be very deep.

Likely follow-up: How would you avoid recursing into strings, which are also iterable?
09Find the longest substring without repeating characters.codingsliding window＋
Simple answer

A sliding window with a dictionary of the last index of each character. Move the right edge forward; when you meet a repeat that is inside the window, jump the left edge past its previous position. Each character is visited once, so it is O(n) time and O(k) space.

longest_substring.py
def longest_unique(s: str) -> int:
    last, start, best = {}, 0, 0
    for i, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1
        last[ch] = i
        best = max(best, i - start + 1)
    return best
Say this in 30 seconds

Sliding window with a last-seen index map, jumping the left edge past repeats. O(n) time.

Likely follow-up: How would you return the substring itself rather than its length?
10Implement linear regression from scratch.codingmlhigh-frequency＋
Simple answer

Initialise weights, then loop: predict with a dot product, compute the mean squared error gradient, and step the weights against it. The whole thing is about ten lines with NumPy. What is being tested is whether you can write the gradient — 2/n · Xᵀ(ŷ − y) — not whether you remember an API.

linreg.py
import numpy as np

def fit(X, y, lr=0.01, epochs=1000):
    X = np.c_[np.ones(len(X)), X]        # bias column
    w = np.zeros(X.shape[1])
    for _ in range(epochs):
        error = X @ w - y
        w -= lr * (2 / len(y)) * (X.T @ error)
    return w
Say this in 30 seconds

Add a bias column, then loop: predict, compute the MSE gradient, step the weights against it.

Likely follow-up: What happens if the learning rate is too high?
11Implement k-means from scratch.codingmlhigh-frequency＋
Simple answer

Pick k initial centroids, then alternate two steps until they stop moving: assign each point to its nearest centroid, then move each centroid to the mean of its assigned points. Broadcasting handles the distance matrix in one line. Mention that the result depends on initialisation, which is why k-means++ and multiple restarts exist.

kmeans.py
import numpy as np

def kmeans(X, k, iters=100):
    centroids = X[np.random.choice(len(X), k, replace=False)]
    for _ in range(iters):
        d = ((X[:, None, :] - centroids[None, :, :]) ** 2).sum(-1)
        labels = d.argmin(axis=1)
        new = np.array([X[labels == i].mean(0) for i in range(k)])
        if np.allclose(new, centroids):
            break
        centroids = new
    return labels, centroids
Say this in 30 seconds

Alternate assigning points to nearest centroids and moving centroids to cluster means, until they stop moving.

Likely follow-up: How would you choose k?
12Write a decorator that retries a function on failure.codingdecoratorshigh-frequency＋
Simple answer

Three nested functions, because it takes arguments. Retry only the exceptions you name, back off exponentially between attempts, and re-raise on the final one rather than returning None — a silent failure is worse than a loud one. Interviewers watch for whether you remember functools.wraps.

retry_decorator.py
import functools, time

def retry(times=3, delay=0.5, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except exceptions:
                    if attempt == times - 1:
                        raise
                    time.sleep(delay * 2 ** attempt)
        return wrapper
    return decorator
Say this in 30 seconds

Three levels for the arguments, catch only named exceptions, exponential backoff, and re-raise on the last attempt.

Likely follow-up: How would you make it work with async functions too?
13Preprocess a dataset with NumPy, Pandas and scikit-learn.codingpandashigh-frequency＋
Simple answer

The trap in this question is fitting transformers before splitting. Split first, then build a Pipeline with a ColumnTransformer so imputation, scaling and encoding are fitted on train only and applied identically to test — and to production later. Writing it as a pipeline rather than loose steps is the senior answer.

preprocess.py
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

num = Pipeline([("impute", SimpleImputer(strategy="median")),
                ("scale", StandardScaler())])
cat = Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                ("encode", OneHotEncoder(handle_unknown="ignore"))])

pre = ColumnTransformer([("num", num, num_cols), ("cat", cat, cat_cols)])
pre.fit(X_train)          # fit on train ONLY
X_test_t = pre.transform(X_test)
Say this in 30 seconds

Split first, then a Pipeline with a ColumnTransformer fitted on train only, so the same transformation applies to test and production.

Likely follow-up: Why handle_unknown='ignore' on the encoder?
14Count word frequency in a large file.codinggeneratorscounting＋
Simple answer

Stream the file line by line into a Counter, so memory scales with vocabulary rather than file size. Mention normalisation — case and punctuation — as a clarifying question. If the vocabulary itself is too large, that is when you shard by hash or move to Spark.

word_count.py
from collections import Counter
import re

def word_counts(path: str) -> Counter:
    counts = Counter()
    with open(path, encoding="utf-8") as f:
        for line in f:                       # streaming, constant memory
            counts.update(re.findall(r"[a-z']+", line.lower()))
    return counts
Say this in 30 seconds

Stream line by line into a Counter, so memory depends on vocabulary size rather than file size.

Likely follow-up: What if the vocabulary does not fit in memory either?

Project and behavioural rounds

15Walk me through your Python project and the technical decisions in it.behaviouralprojecthigh-frequency＋
Simple answer

Use a fixed shape: the problem and who had it, the approach in three sentences, your specific contribution, one hard decision with the alternative you rejected and why, and the measurable result. Two minutes, then stop and let them dig. The most common failure is narrating the architecture for ten minutes without ever saying what you did or what it achieved.

Say this in 30 seconds

Problem, approach, my contribution, one hard trade-off with the rejected alternative, and the measured outcome. Two minutes, then stop.

Likely follow-up: What would you do differently if you started it again today?
16What is the hardest bug you have debugged?behaviouraldebugging＋
Simple answer

Pick one that was genuinely hard to find, not just tedious to fix — a race condition, a memory leak, something that only failed in production. Tell it as an investigation: what the symptom was, what you initially believed, what evidence changed your mind, the root cause, and what you changed so the class of bug could not recur. That last part is what separates a senior answer.

Say this in 30 seconds

Symptom, my wrong first hypothesis, the evidence that corrected it, the root cause, and the change that prevents the whole class of bug.

Likely follow-up: How would you have caught it earlier?
17Tell me about a time you had to optimise something.behaviouralperformance＋
Simple answer

Lead with the number: what was slow, how slow, and what it became. Then explain how you found the bottleneck — profiling, not guessing — what you changed, and what you deliberately chose not to optimise. Mentioning the thing you left alone shows judgment; optimising everything is a warning sign, not a strength.

Say this in 30 seconds

The measured before and after, how I found the bottleneck by profiling, what I changed, and what I chose to leave alone.

Likely follow-up: How did you make sure the optimisation did not break correctness?
18Tell me about a technical decision you got wrong.behaviouralownership＋
Simple answer

Pick a real one with a real cost, and be specific about what you missed at the time. Then explain how you found out, what you did about it, and what you now check because of it. Answers that pick a fake weakness read as evasive; the question is really testing whether you can be honest about your own work.

Say this in 30 seconds

A real decision, what I failed to consider, how the problem surfaced, what I changed, and what I check now because of it.

Likely follow-up: How do you decide when to reverse a decision versus live with it?
19How do you handle disagreement with a colleague on a technical approach?behaviouralcollaboration＋
Simple answer

Separate the disagreement from the person: state what you both actually agree on, name the specific constraint you differ over, and find the cheapest evidence that would settle it — a benchmark, a spike, a small prototype. If it stays subjective, say so, back the decision made, and commit properly. Having disagreed and then supported the other choice is a strong story.

Say this in 30 seconds

Find what we agree on, isolate the real point of difference, get evidence cheaply, and if it stays subjective, commit to the decision made.

Likely follow-up: Tell me about a time you were the one who turned out to be wrong.
20How do you explain a technical trade-off to a non-technical stakeholder?behaviouralcommunication＋
Simple answer

Translate it into their currency — time, money, risk or customer impact — not architecture. Give two options with the consequence of each, make a recommendation rather than leaving them to choose blind, and say what you would need to change your mind. “We can ship in two weeks and take on X, or four weeks and avoid it; I recommend the first because Y” is what a stakeholder can actually act on.

Say this in 30 seconds

Convert it to time, cost, risk or customer impact, give two options with consequences, and make a clear recommendation.

Likely follow-up: What if they overrule your recommendation?
21Why are you switching jobs?behaviouralhigh-frequency＋
Simple answer

Answer forwards, not backwards: what you want to do more of, and why this role offers it. Keep it short and specific — depth in AI systems, ownership of a service end to end, working closer to users. Criticising your current employer costs you more than any honest complaint gains, even when the complaint is fair.

Say this in 30 seconds

What I want to move towards and why this role provides it. Specific, forward-looking, and without criticising the current employer.

Likely follow-up: What would make you stay somewhere for five years?
22What would your first 90 days look like here?behaviouralsenior＋
Simple answer

Three phases. First month: learn the system, the data and the people, ship something small to prove the pipeline works end to end. Second: take ownership of a real piece of work and deliver it. Third: identify and fix something nobody had time for. Frame it as learning before changing — a plan that opens with a rewrite proposal reads as arrogance.

Say this in 30 seconds

Month one learn and ship something small; month two own a real deliverable; month three fix something that had been neglected.

Likely follow-up: How would you decide what that neglected thing should be?
23Do you have any questions for us?behaviouralclosing＋
Simple answer

Always yes, and make them ones only this team can answer. What does success in this role look like at six months? What is the most frustrating part of the current codebase? How do decisions about model or vendor choice get made? These signal you are evaluating the job, not just hoping to be picked — which is exactly the posture that gets offers.

Say this in 30 seconds

Ask what success looks like at six months, what is most frustrating in the codebase, and how technical decisions actually get made.

Likely follow-up: What answer would make you turn the role down?
