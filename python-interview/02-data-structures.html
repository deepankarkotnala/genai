Strings, Collections & Data Structures

The single most reliable question in a Python interview is some version of “list, tuple, set or dict — which and why?” Everything on this page follows from being able to answer that properly.

30 questionsAsked in almost every roundChecked July 2026
⌁
What the interviewer is really testing

Anyone can list the differences between a list and a tuple. What separates candidates is connecting the choice to a cost: dict and set lookups are constant time because of hashing, list lookups are linear, and strings are immutable so building them in a loop is quietly expensive. Name the structure, then name the cost.

30 questions

Strings, bytes and formatting

01Why are Python strings immutable, and what does that cost you?stringsimmutabilityhigh-frequency＋
Simple answer

Immutability lets Python cache and share string objects, use them safely as dict keys, and hash them once. The cost is that every “change” builds a whole new string. So s += x inside a loop copies everything it has built so far, every time round — a thousand items means roughly half a million character copies instead of a thousand. Build a list of pieces and "".join() them at the end instead.

join.py
# Slow: strings are immutable, so every += builds a brand new
# string and copies everything so far. n items -> roughly n*n copying.
out = ""
for part in parts:
    out += part

# Fast: one pass, one allocation for the final string
out = "".join(parts)
Say this in 30 seconds

Immutability makes strings hashable and shareable, but string concatenation in a loop is quadratic. Use join.

Likely follow-up: Does CPython ever optimise s += x? Can you rely on it?
02What is the difference between f-strings, .format() and % formatting?stringsformatting＋
Simple answer

All three interpolate values; f-strings are the modern default because they are evaluated inline, are the fastest, and keep the variable next to where it appears. .format() is still useful when the template is stored separately, for example in a config file. % formatting is legacy and only survives in logging calls, where deferring the formatting is deliberate.

Say this in 30 seconds

f-strings by default — fastest and clearest. .format() for templates defined elsewhere, % only in logging.

Likely follow-up: Why does the logging module recommend %s style over f-strings?
03How does string slicing work, including negative indexes?stringsslicingbasics＋
Simple answer

s[start:stop:step] takes from start up to but not including stop. Negative indexes count from the end, so s[-1] is the last character. Omitting a bound means “to the edge”, and a negative step reverses, which is why s[::-1] is the one-line reverse. Slices never raise IndexError — out-of-range bounds are clamped.

slicing.py
s = "interview"
s[:4]      # 'inte'
s[-4:]     # 'view'
s[::2]     # 'itriw'
s[::-1]    # 'weivretni'
Say this in 30 seconds

start:stop:step, stop is exclusive, negatives count from the end, and out-of-range slices clamp instead of raising.

Likely follow-up: Is s[::-1] the best way to reverse a string? What about memory?
04How would you check whether a string is a palindrome?stringscodinghigh-frequency＋
Simple answer

Normalise first — lowercase and strip non-alphanumeric characters — then compare the string with its reverse, or walk two pointers from both ends. The reverse version is one line and fine for interviews; the two-pointer version uses constant extra space and shows you thought about memory. Say which trade-off you are making.

palindrome.py
def is_palindrome(s: str) -> bool:
    # Step 1: keep only letters and digits, all lowercase,
    # so "A man, a plan!" compares the same as "amanaplan"
    clean = [c.lower() for c in s if c.isalnum()]

    # Step 2: walk one pointer from each end towards the middle
    left, right = 0, len(clean) - 1
    while left < right:
        if clean[left] != clean[right]:
            return False            # mismatch -> not a palindrome
        left, right = left + 1, right - 1
    return True                     # pointers met, everything matched
Say this in 30 seconds

Normalise, then compare against the reverse, or walk two pointers inward for constant extra space.

Likely follow-up: What changes if you must ignore only spaces but keep punctuation?
05What do strip, split and join do, and where do people misuse them?stringsbasics＋
Simple answer

strip removes leading and trailing characters — and it strips a set of characters, not a prefix, so "test.py".strip(".py") surprises people. split breaks a string into a list, and bare split() handles any run of whitespace. join glues an iterable of strings with a separator, and it is called on the separator, which trips up beginners.

Say this in 30 seconds

strip removes a set of characters not a prefix, split with no argument handles all whitespace, and join is called on the separator.

Likely follow-up: What should you use instead of strip to remove a suffix?
06When would you use a regular expression, and when would you avoid one?regexstrings＋
Simple answer

Use regex for pattern matching with variation — validating formats, extracting fields from semi-structured logs, splitting on complex delimiters. Avoid it when a plain string method does the job, when parsing HTML or JSON, or when the pattern becomes unreadable. Compile with re.compile if it runs in a loop, and be aware that badly-nested patterns can blow up on adversarial input.

Say this in 30 seconds

Regex for varied patterns like log parsing; string methods for simple checks; a real parser for HTML or JSON.

Likely follow-up: What is catastrophic backtracking, and how would you avoid it?
07What is the difference between re.match, re.search and re.findall?regex＋
Simple answer

match only checks at the start of the string. search scans the whole string for the first match. findall returns every non-overlapping match as a list, and finditer does the same lazily with full match objects. Most bugs come from reaching for match when you actually meant search.

Say this in 30 seconds

match anchors at the start, search scans anywhere, findall returns all matches. People confuse match and search.

Likely follow-up: How do named groups make a regex easier to maintain?

Lists, tuples and sets

08What is the difference between a list and a tuple?listtuplehigh-frequency＋
Simple answer

A list can be changed after you create it; a tuple cannot. Everything else follows from that. Because a tuple cannot change, it can be a dictionary key or a set member, and it uses slightly less memory. The two also say different things to a reader: a tuple is a fixed record, a list is a collection that grows. Use a list when the contents will change, a tuple when they will not.

Say this in 30 seconds

Lists are mutable, tuples are not. Tuples can be dict keys and signal a fixed record; lists are for changing collections.

Likely follow-up: You said tuples are hashable — is that always true?
09When is a tuple not hashable?tuplehashingtrick question＋
Simple answer

When it contains something mutable. A tuple's hash is computed from its contents, so (1, [2]) raises TypeError if you try to use it as a dict key. Immutability of the container is not enough — everything inside it must be hashable too.

Say this in 30 seconds

If it contains a mutable object like a list. Hashability goes all the way down.

Likely follow-up: How would you fix that tuple so it can be a key?
10What is the time complexity of common list operations?listcomplexityperformance＋
Simple answer

Index access and append are O(1). Append is average O(1): now and then the list runs out of room and copies itself into a bigger block, but that is rare enough to average out. insert(0, x) and pop(0) are O(n) because everything shifts. in is O(n) since it scans. sort is O(n log n). If you need fast operations at both ends, use collections.deque, which makes them O(1).

Say this in 30 seconds

Append and index are constant, inserting or popping at the front is linear, membership is linear. Use deque for both-ends work.

Likely follow-up: Why is append amortised O(1) rather than plain O(1)?
11How do you remove duplicates from a list?listsetcoding＋
Simple answer

If order does not matter, list(set(items)) is the one-liner. If order matters, list(dict.fromkeys(items)) preserves first-seen order because dicts keep insertion order from Python 3.7. Both need hashable items; for unhashable ones you fall back to a loop with a seen list, which is O(n²).

dedupe.py
items = [3, 1, 3, 2, 1]
list(set(items))            # [1, 2, 3] — order lost
list(dict.fromkeys(items))  # [3, 1, 2] — order kept
Say this in 30 seconds

set if order does not matter, dict.fromkeys if it does. Both require hashable items.

Likely follow-up: How would you dedupe a list of dictionaries?
12What does a set give you that a list does not?setcomplexityhigh-frequency＋
Simple answer

Constant-time membership testing and automatic deduplication, because it is hash-based. It also gives you real set algebra — union, intersection, difference — which replaces nested loops with one readable line. The trade-offs are that sets are unordered and can only hold hashable items.

sets.py
a, b = {1, 2, 3}, {3, 4}
a | b   # union        {1, 2, 3, 4}
a & b   # intersection {3}
a - b   # difference   {1, 2}
a ^ b   # symmetric    {1, 2, 4}
Say this in 30 seconds

O(1) membership, automatic dedupe, and set operations. Costs you ordering and requires hashable items.

Likely follow-up: How would you find items present in one list but not another, efficiently?
13What is a frozenset and when would you use it?setimmutability＋
Simple answer

An immutable set. Because it cannot change, it is hashable, so you can use it as a dictionary key or put it inside another set. Typical use is representing a fixed group — a set of permissions, a set of tags — that you want to look up by.

Say this in 30 seconds

An immutable, hashable set. Use it when a set itself needs to be a dict key or a set member.

Likely follow-up: Can you give a concrete case where you needed a set of sets?
14How does sort() differ from sorted()?sortinglistbasics＋
Simple answer

list.sort() sorts in place and returns None — assigning its result is a common bug. sorted() works on any iterable and returns a new list. Both accept key and reverse, and both are stable, meaning equal items keep their original relative order.

sorting.py
people = [("asha", 30), ("ravi", 25)]
sorted(people, key=lambda p: p[1])     # new list, by age
people.sort(key=lambda p: p[1])        # in place, returns None
Say this in 30 seconds

sort mutates a list and returns None; sorted returns a new list from any iterable. Both are stable.

Likely follow-up: Why does stability matter when sorting by two fields?
15How do you sort by more than one field?sortingcoding＋
Simple answer

Return a tuple from the key function — Python compares tuples element by element. For mixed directions, either negate a numeric field or sort twice, relying on stability: sort by the secondary key first, then by the primary one. operator.itemgetter is faster than a lambda for simple field access.

multisort.py
# The key returns a tuple, and Python compares tuples left to right:
# department first, and salary only breaks ties within a department.
# The minus sign flips salary to descending while dept stays ascending.
staff.sort(key=lambda s: (s.dept, -s.salary))
Say this in 30 seconds

Return a tuple from the key function. For mixed directions, negate the number or sort twice using stability.

Likely follow-up: What if the descending field is a string, so you cannot negate it?
16What is list slicing assignment, and what does it let you do?listslicing＋
Simple answer

You can assign to a slice to replace, insert or delete a run of items in place, and the replacement does not have to be the same length. lst[:] = other is the idiom for replacing a list's contents while keeping the same object, which matters when other code holds a reference to it.

slice_assign.py
lst = [1, 2, 3, 4]
lst[1:3] = [9]      # [1, 9, 4]
lst[:] = [7, 8]     # replaces contents, same object
Say this in 30 seconds

You can replace a run of items in place, with a different length, and lst[:] = swaps contents without a new object.

Likely follow-up: When would keeping the same list object actually matter?
17What is tuple unpacking and how far does it go?tuplesyntax＋
Simple answer

You can unpack any iterable into names, including nested structures, and *rest captures the leftovers. It powers swapping without a temporary variable, multiple return values, and clean loop headers with enumerate or dict.items().

unpack.py
# Swap two names with no temporary variable
a, b = b, a

# *middle soaks up everything between the first and last item
first, *middle, last = [1, 2, 3, 4, 5]
# first = 1, middle = [2, 3, 4], last = 5

# Unpacking inside a loop header: enumerate gives (index, item),
# and the inner (name, score) unpacks the item itself
for i, (name, score) in enumerate(pairs):
    ...
Say this in 30 seconds

Bind an iterable to names, with *rest for the remainder. It drives swapping, multiple returns and clean loops.

Likely follow-up: What happens if the number of names does not match?

Dictionaries and the collections module

18How does a dictionary work internally, and why is lookup O(1)?dicthashinghigh-frequency＋
Simple answer

A dict is a hash table. It turns the key into a number with hash() and uses that to jump straight to a slot, instead of scanning every entry. That makes lookup, insert and delete average O(1). If two keys land on the same slot, Python simply tries the next ones until it finds a free one, and the table grows when it starts filling up. Worst case is O(n) if every key collides, but that does not happen with normal data.

Say this in 30 seconds

It hashes the key to jump straight to a slot, so lookup is average constant time rather than a scan.

Likely follow-up: What makes an object usable as a dict key?
19What must be true for an object to be a dictionary key?dicthashing＋
Simple answer

It must be hashable: it needs a __hash__, the hash must not change over the object's life, and objects that are equal must hash the same. In practice that means immutable — strings, numbers, tuples of immutables. If you write a custom class and override __eq__, you must override __hash__ too or the class becomes unhashable.

Say this in 30 seconds

It must be hashable and its hash must not change. Override __eq__ and you must override __hash__.

Likely follow-up: Why does Python set __hash__ to None when you define __eq__?
20Are dictionaries ordered in Python?dictmodern python＋
Simple answer

Yes. Since Python 3.7 dicts preserve insertion order as a language guarantee — in 3.6 it was an implementation detail. That is why dict.fromkeys works for order-preserving dedupe. OrderedDict still exists for its extra methods like move_to_end and for order-sensitive equality.

Say this in 30 seconds

Yes, insertion order is guaranteed from 3.7. OrderedDict remains only for its extra methods.

Likely follow-up: So is there any reason left to use OrderedDict?
21What is the difference between d[key], d.get(key) and d.setdefault(key)?dictbasics＋
Simple answer

d[key] raises KeyError if the key is missing. d.get(key, default) returns the default instead, and never inserts. d.setdefault(key, default) returns the existing value or inserts the default and returns it. Use bracket access when a missing key is a real error — silently defaulting can hide bugs.

Say this in 30 seconds

Brackets raise, get returns a default without inserting, setdefault inserts the default. Let it raise when missing means broken.

Likely follow-up: How is defaultdict different from setdefault?
22What does collections.defaultdict give you?collectionsdict＋
Simple answer

It calls a factory function to create a value the first time a missing key is accessed, so grouping and counting need no existence check. The catch is that merely reading a missing key inserts it, which can silently grow the dict — so do not use it where lookups should stay read-only.

defaultdict.py
from collections import defaultdict

# list is the "factory": the first time a key is touched,
# defaultdict calls list() and stores [] for it automatically.
by_dept = defaultdict(list)

for person in staff:
    # No "if dept not in by_dept" check needed — the list already exists
    by_dept[person.dept].append(person.name)
Say this in 30 seconds

It auto-creates a default value for missing keys, which removes the existence check when grouping. Reading a missing key inserts it.

Likely follow-up: How would you turn it back into a plain dict before returning it?
23When would you use collections.Counter?collectionscounting＋
Simple answer

For counting hashable items. It is a dict subclass that counts in one pass, gives you most_common(n), and supports arithmetic between counters. It turns the classic “find the most frequent word” question into two lines, and it returns 0 rather than raising for a missing key.

counter.py
from collections import Counter

# Counts every word in one pass, then returns the 3 most frequent
# as (word, count) pairs, already sorted highest first.
Counter(words).most_common(3)

# Anagram check: same letters with the same counts, order ignored
Counter("listen") == Counter("silent")    # True
Say this in 30 seconds

Counting hashables in one pass, with most_common built in. It also makes anagram checks trivial.

Likely follow-up: How would you count items that are not hashable?
24What is collections.deque and when does it beat a list?collectionsperformance＋
Simple answer

A double-ended queue with O(1) appends and pops at both ends, where a list is O(n) at the front. Use it for queues, BFS, sliding windows, and fixed-size history via maxlen, which discards from the other end automatically. Random indexing in the middle is slower than a list, so it is not a general replacement.

Say this in 30 seconds

Constant-time operations at both ends. Use it for queues, BFS and sliding windows; lists are better for random access.

Likely follow-up: What does maxlen do when the deque is full?
25What is a namedtuple, and when would you prefer a dataclass?collectionsdataclass＋
Simple answer

A namedtuple is a tuple with named fields — immutable, lightweight, and still unpackable. A dataclass is a normal class with generated __init__, __repr__ and __eq__, and it can be mutable, typed and given methods and defaults. Use namedtuple for a small immutable record, dataclass when the object has behaviour or needs to change.

Say this in 30 seconds

namedtuple for a tiny immutable record; dataclass when you want types, defaults, methods or mutability.

Likely follow-up: Where does NamedTuple from typing fit in?
26How do you merge two dictionaries?dictmodern python＋
Simple answer

a | b since Python 3.9 returns a new merged dict, with b winning on conflicts; a |= b merges in place. {**a, **b} does the same and works on older versions. Note that all of these merge only the top level — nested dicts are replaced wholesale, not combined.

Say this in 30 seconds

a | b on 3.9+, or {**a, **b}. Right side wins, and only the top level is merged.

Likely follow-up: How would you write a recursive deep merge?
27How do you iterate over a dictionary safely while changing it?dictiterationgotcha＋
Simple answer

You cannot — mutating a dict during iteration raises RuntimeError: dictionary changed size during iteration. Iterate over a snapshot instead, with list(d.items()), or build a new dict with a comprehension and replace the old one. The comprehension is usually clearer and avoids the whole class of bug.

safe_iter.py
# Deleting from a dict while looping over it raises RuntimeError.
# Instead, build a fresh dict and rebind the name — no mutation
# happens while the comprehension is reading the original.
d = {k: v for k, v in d.items() if v is not None}
Say this in 30 seconds

You cannot mutate while iterating. Iterate over list(d.items()) or rebuild with a comprehension.

Likely follow-up: Does the same restriction apply to lists?
28What is the difference between dict.keys() and list(dict.keys())?dictviews＋
Simple answer

keys() returns a view — a live window onto the dict that reflects later changes and costs no memory. Wrapping it in list() takes a snapshot you can safely iterate while mutating. Views also support set operations, so a.keys() & b.keys() gives shared keys directly.

Say this in 30 seconds

keys() is a live view that costs nothing and supports set operations; list() makes an independent snapshot.

Likely follow-up: What would a.keys() - b.keys() give you?
29How would you invert a dictionary?dictcoding＋
Simple answer

{v: k for k, v in d.items()} if values are unique and hashable. If values repeat, the last one silently wins, so group instead using a defaultdict(list). Always say which case you are handling — the interviewer is usually checking whether you notice the duplicate-value problem.

invert.py
from collections import defaultdict

# Values may repeat, so each original value maps to a LIST of keys.
# A plain {v: k for ...} comprehension would silently keep only
# the last key for each duplicated value.
inverted = defaultdict(list)
for k, v in d.items():
    inverted[v].append(k)
Say this in 30 seconds

A dict comprehension if values are unique; group into lists with a defaultdict if they are not.

Likely follow-up: What if some values are unhashable, like lists?
30How would you find the top-k most frequent items in a large stream?codingcounterheap＋
Simple answer

Count with a Counter, then use most_common(k), which internally uses a heap and is O(n log k) rather than sorting everything at O(n log n). If the data does not fit in memory, count per chunk and merge counters, or use an approximate structure like count-min sketch and say so.

Say this in 30 seconds

Counter plus most_common(k) — a heap, so O(n log k). For data that does not fit in memory, merge per-chunk counters.

Likely follow-up: Why is a heap better than sorting the whole thing here?
