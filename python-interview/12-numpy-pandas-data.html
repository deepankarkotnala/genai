What the interviewer is really testing

Whether you think in vectors or in loops. Almost every Pandas performance question has the same answer — the work should happen inside the library in C, not in a Python for loop or an apply. And whether you ask what a missing value means before deciding how to fill it.

21 questions

NumPy

01Why is a NumPy array faster than a Python list?numpyperformancehigh-frequency＋
Simple answer

Three reasons. An array stores raw values of one type in a contiguous block, where a list stores pointers to scattered Python objects. Operations run as compiled C loops instead of interpreted Python. And contiguous memory means the CPU cache and vectorised instructions actually work. That is typically a 10 to 100 times difference on numeric work.

Say this in 30 seconds

Contiguous single-type memory, operations in compiled C, and cache-friendly access — instead of a list of scattered Python objects.

Likely follow-up: What happens to that advantage if the array has dtype=object?
02What is broadcasting?numpybroadcastinghigh-frequency＋
Simple answer

NumPy's rule for operating on arrays of different shapes without copying data. It compares shapes from the right; dimensions match if they are equal or one of them is 1, and size-1 dimensions are stretched virtually. That is how you subtract a per-column mean from a whole matrix in one expression, with no loop and no memory duplication.

broadcast.py
X = np.random.rand(1000, 5)
X_centred = X - X.mean(axis=0)     # (1000,5) - (5,) works

# pairwise differences via a new axis
diff = X[:, None, :] - X[None, :, :]   # (1000, 1000, 5)
Say this in 30 seconds

Aligning shapes from the right so size-1 dimensions stretch virtually, letting you combine different shapes without copying.

Likely follow-up: What is the memory risk of broadcasting into a very large shape?
03What is the difference between a view and a copy in NumPy?numpymemorygotcha＋
Simple answer

Basic slicing gives a view — a window onto the same memory, so writing to it changes the original. Fancy indexing with a list or boolean mask gives a copy. This bites people who slice, modify, and are surprised the source changed. Call .copy() when you need independence, and check arr.base when you are unsure.

Say this in 30 seconds

Slicing gives a view sharing memory; fancy or boolean indexing gives a copy. Writing to a view changes the original.

Likely follow-up: How would you check whether an array owns its data?
04How do axis=0 and axis=1 work?numpybasicsgotcha＋
Simple answer

The axis is the one being collapsed. axis=0 operates down the rows, producing one value per column; axis=1 operates across the columns, producing one value per row. The trick that makes it stick: whichever axis you name is the one that disappears from the output shape.

Say this in 30 seconds

The named axis is the one that collapses. axis=0 gives a result per column, axis=1 a result per row.

Likely follow-up: What does keepdims=True do and why is it useful?
05How would you vectorise a loop over an array?numpyvectorizationcoding＋
Simple answer

Replace element-wise Python work with whole-array expressions, boolean masks for conditions, and np.where for if/else. If the condition is complex, compute the mask first and index with it. Note that np.vectorize is not vectorisation — it is a convenience wrapper around a Python loop and gives no real speedup.

vectorise.py
# loop
out = [x * 2 if x > 0 else 0 for x in arr]

# vectorised
out = np.where(arr > 0, arr * 2, 0)
Say this in 30 seconds

Use whole-array expressions, boolean masks and np.where. And note np.vectorize is not actually vectorised.

Likely follow-up: When is a loop genuinely unavoidable?
06How do you handle NaN values in NumPy?numpynangotcha＋
Simple answer

Remember that NaN is not equal to itself, so arr == np.nan never matches — use np.isnan. Ordinary reductions propagate NaN, so one bad value turns the whole mean into NaN; use np.nanmean and friends to skip them. Deciding to skip them is a modelling choice, so make it deliberately rather than by reaching for the nan-function reflexively.

Say this in 30 seconds

NaN is not equal to itself — use np.isnan. Normal reductions propagate it; nanmean and friends skip it, which is a modelling decision.

Likely follow-up: What is the difference between NaN and None in an array?

Pandas

07What is the difference between loc and iloc?pandasbasicshigh-frequency＋
Simple answer

loc selects by label and its slices are inclusive of the end point. iloc selects by integer position and its slices exclude the end, like normal Python. Confusion arises when the index is itself integers, because then a label looks like a position — which is exactly why explicit loc or iloc beats bare bracket indexing.

Say this in 30 seconds

loc is label-based with an inclusive end; iloc is position-based with an exclusive end. Always be explicit about which you mean.

Likely follow-up: What is chained indexing and why does it warn?
08What is the SettingWithCopyWarning and how do you fix it?pandasgotchahigh-frequency＋
Simple answer

It means you assigned to something that might be a view of another DataFrame, so Pandas cannot tell whether the write will land where you expect. It is caused by chained indexing like df[df.a > 0]["b"] = 1. Fix it by doing the selection and assignment in one loc call, or by taking an explicit .copy() when you meant a new frame.

setting_copy.py
# warns, may silently do nothing
df[df.score > 0]["flag"] = True

# correct
df.loc[df.score > 0, "flag"] = True
Say this in 30 seconds

It comes from chained indexing where the write may hit a temporary copy. Use a single loc assignment, or copy explicitly.

Likely follow-up: Why can the chained version silently do nothing?
09How does groupby work?pandasgroupbyhigh-frequency＋
Simple answer

Split, apply, combine: rows are split into groups by key, a function runs on each group, and the results are stitched back together. agg reduces each group to one row, transform returns a value per original row — useful for group means broadcast back — and filter keeps or drops whole groups. Knowing which of the three you need is the actual skill.

groupby.py
df.groupby("dept")["salary"].agg(["mean", "count"])

# per-row group mean, aligned to the original index
df["dept_mean"] = df.groupby("dept")["salary"].transform("mean")
Say this in 30 seconds

Split, apply, combine. agg reduces to one row per group, transform gives one value per original row, filter drops whole groups.

Likely follow-up: How would you get the top 3 rows within each group?
10What is the difference between merge, join and concat?pandasjoins＋
Simple answer

merge is the SQL-style join on columns and is what you want most of the time. join is a convenience method that merges on the index. concat stacks frames, vertically or horizontally, without matching keys. Before any merge, check the row count afterwards — an unexpected many-to-many join silently multiplies your data.

Say this in 30 seconds

merge is the SQL join on columns, join is the index-based shortcut, concat just stacks. Always check row counts after a merge.

Likely follow-up: How does the validate argument to merge help here?
11How do you handle missing values in a DataFrame?pandascleaninghigh-frequency＋
Simple answer

Ask what missing means first — not recorded, not applicable, or genuinely zero are three different problems. Then choose: drop rows if they are few and random, fill with a median or mode if the column is mostly complete, forward-fill for time series, or add an explicit “was missing” indicator column when the missingness itself carries information. Never fill with a mean without checking the distribution.

missing.py
df.isna().mean().sort_values(ascending=False)   # how bad is it?
df["age"] = df["age"].fillna(df["age"].median())
df["age_missing"] = df["age"].isna().astype(int)
Say this in 30 seconds

First ask what missing means, then drop, impute with median or mode, forward-fill for time series, or flag it as its own feature.

Likely follow-up: Why is imputing before splitting train and test a mistake?
12Why is apply slow, and what should you use instead?pandasperformancehigh-frequency＋
Simple answer

apply runs a Python function per row, so you lose all the vectorised C machinery — it is a loop with nicer syntax. Replace it with column arithmetic, np.where or np.select for conditionals, map for lookups, and str accessors for text. Keep apply only for genuinely irreducible row logic, and say so when you use it.

apply.py
# slow
df["band"] = df.apply(lambda r: "high" if r.score > 8 else "low", axis=1)

# fast
df["band"] = np.where(df["score"] > 8, "high", "low")
Say this in 30 seconds

apply is a Python loop in disguise. Use column arithmetic, np.where, np.select or map instead.

Likely follow-up: Is iterrows ever acceptable?
13How would you reduce the memory a DataFrame uses?pandasmemoryperformance＋
Simple answer

Downcast numeric columns to smaller dtypes, convert low-cardinality strings to category — often a huge saving — and load only the columns you need with usecols. Read in chunks, or switch to Parquet, which is columnar and compressed. Check with df.info(memory_usage="deep"), since the default underestimates object columns.

Say this in 30 seconds

Downcast numerics, make low-cardinality strings categorical, read only needed columns, and prefer Parquet over CSV.

Likely follow-up: When would a category dtype actually use more memory?
14How do you reshape between wide and long format?pandasreshaping＋
Simple answer

melt goes wide to long, turning columns into rows — the tidy format most plotting and modelling code wants. pivot and pivot_table go long to wide, with pivot_table aggregating duplicates rather than raising. stack and unstack do the same thing across index levels.

Say this in 30 seconds

melt for wide to long, pivot or pivot_table for long to wide. pivot_table aggregates duplicates instead of failing.

Likely follow-up: Why does pivot raise when pivot_table does not?
15How would you preprocess a raw dataset end to end?pandasworkflowhigh-frequency＋
Simple answer

Look at it first — shape, dtypes, describe, missing counts, duplicates. Then fix types and parse dates, handle duplicates, deal with missing values, treat outliers deliberately rather than clipping by reflex, encode categoricals, and scale numerics. Crucially, split into train and test before fitting any imputer, encoder or scaler, and fit only on train — otherwise test information leaks into your model.

Say this in 30 seconds

Inspect, fix dtypes, handle duplicates and missing values, treat outliers, encode and scale — and split before fitting any transformer.

Likely follow-up: What exactly leaks if you scale before splitting?

Data engineering and pipelines

16How is PySpark different from Pandas?pysparkscale＋
Simple answer

Pandas is single-machine and eager — everything happens now, in one process's memory. Spark is distributed and lazy: transformations build a plan and nothing runs until an action like count or write. Use Pandas when the data fits comfortably in memory, and Spark when it does not. Spark on a small dataset is slower, not faster, because of the coordination overhead.

Say this in 30 seconds

Pandas is single-machine and eager; Spark is distributed and lazy. Spark only wins when the data genuinely does not fit in memory.

Likely follow-up: What is the difference between a transformation and an action?
17What is a shuffle in Spark, and why does it matter?pysparkperformance＋
Simple answer

A shuffle moves data across the network so rows with the same key land on the same executor — triggered by joins, groupBy and repartitioning. It is by far the most expensive operation, so most Spark tuning is about avoiding or shrinking shuffles: broadcast small tables instead of joining them, filter before joining, and partition on the key you join by.

Say this in 30 seconds

Redistributing data across the network for joins and groupBy. It is the main cost in Spark, so broadcast small tables and filter early.

Likely follow-up: What is a broadcast join and when does it stop working?
18What is data skew and how do you fix it?pysparkperformancesenior＋
Simple answer

One key holds far more rows than the others, so a single task does most of the work while the cluster idles and eventually that task fails on memory. Common with a null key or one dominant tenant. Fix it by salting the hot key across several partitions, filtering nulls out before the join, or broadcasting the small side so no shuffle happens at all.

Say this in 30 seconds

One key dominates, so one task does all the work and fails. Salt the hot key, filter nulls, or broadcast the small side.

Likely follow-up: How would you detect skew from the Spark UI?
19How do you design a reliable data pipeline?pipelinesdesignsenior＋
Simple answer

Make every step idempotent so a rerun produces the same result rather than duplicates. Partition output by date so you can reprocess one day without touching the rest. Validate data at each boundary — row counts, null rates, schema — and fail loudly rather than writing bad data. Log lineage so you can answer where a number came from, and alert on freshness, not just on job failure.

Say this in 30 seconds

Idempotent steps, date-partitioned output, validation at each boundary that fails loudly, lineage logging, and freshness alerts.

Likely follow-up: Your job succeeded but wrote zero rows. How would you have caught it?
20What does Airflow give you, and what is a DAG?airfloworchestration＋
Simple answer

Airflow schedules and orchestrates workflows defined as a DAG — a directed acyclic graph of tasks with dependencies, so nothing runs before its inputs are ready. It gives you retries, backfills, alerting and a run history. The classic mistake is doing the heavy processing inside Airflow workers instead of using Airflow to trigger the system that should do it.

Say this in 30 seconds

It orchestrates tasks as a dependency graph with retries, backfills and history. Use it to trigger work, not to do the heavy lifting.

Likely follow-up: How would you backfill three months of data safely?
21Why is Parquet better than CSV for analytics?formatsdata engineering＋
Simple answer

Parquet is columnar, so reading three columns of a hundred does not read the rest. It is compressed, typically several times smaller, and it stores the schema and types, so you never re-guess whether a column is a string or a date. It also holds statistics that let engines skip whole row groups. CSV's only advantage is that a human can open it.

Say this in 30 seconds

Columnar so you read only needed columns, compressed, and it carries the schema. CSV's only edge is human readability.
