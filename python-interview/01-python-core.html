Python Core & How It Runs

The opening ten minutes of almost every Python interview lives here. These are the questions that decide whether the interviewer keeps digging or moves on.

35 questionsScreening round · every levelChecked July 2026
⌁
What the interviewer is really testing

Nobody asks “is Python interpreted?” because they want a definition. They want to know whether you understand that names point at objects, that some objects can be changed and some cannot, and that this explains most surprising Python behaviour. Answer the question, then show you know why it matters.

35 questions

How Python runs your code

01Is Python compiled or interpreted?executionbytecodecpython＋
Simple answer

Both, in stages. Python first compiles your source into bytecode, a compact set of instructions, and then an interpreter called the Python Virtual Machine runs that bytecode. You never trigger the compile step yourself, which is why Python feels interpreted. The .pyc files in __pycache__ are the cached bytecode from that first step.

Say this in 30 seconds

Python compiles source to bytecode, then interprets the bytecode. It is compiled and interpreted, just not compiled to machine code like C.

Likely follow-up: So what is in a .pyc file, and when is it regenerated?
02What is CPython, and how is it different from Python?cpythonimplementation＋
Simple answer

Python is the language — a specification of what the syntax means. CPython is the standard implementation of it, written in C, and it is what you install from python.org. Other implementations exist: PyPy is faster through just-in-time compilation, and MicroPython runs on microcontrollers. The distinction matters because some behaviour you rely on, like reference counting freeing objects immediately, is a CPython detail rather than a language guarantee.

Say this in 30 seconds

Python is the language, CPython is the usual C implementation of it. Some behaviour people treat as Python is really CPython-specific.

Likely follow-up: Name one thing that works in CPython but you should not depend on.
03What happens from the moment you run python app.py until your code executes?executionruntime＋
Simple answer

Python reads the file, parses it into a syntax tree, compiles that tree into bytecode, and hands the bytecode to the virtual machine, which executes it instruction by instruction. Before your code runs, the interpreter sets up the built-ins and the module namespace, and sets __name__ to "__main__". Imports run the same pipeline for every module you pull in.

Say this in 30 seconds

Parse, compile to bytecode, then the virtual machine executes it inside a module namespace where __name__ is __main__.

Likely follow-up: Where does the import system fit into that sequence?
04What does if __name__ == "__main__": actually do?modulesentry point＋
Simple answer

Every module has a __name__ variable. When you run a file directly it is set to "__main__"; when the same file is imported by another module it is set to the module's name. The guard therefore means “only do this when I am the program being run, not when I am being imported.” Without it, importing your script would trigger all its side effects.

app.py
def main():
    print("running the app")

# True only when this file is the one you ran.
# On "import app" it is False, so main() does NOT fire.
if __name__ == "__main__":
    main()
Say this in 30 seconds

It separates code that should run when the file is the entry point from code that should run on import.

Likely follow-up: What breaks in multiprocessing if you leave this guard out on Windows?
05What is dynamic typing, and how is it different from weak typing?typingfundamentals＋
Simple answer

Dynamic typing means a variable's type is checked when the code runs, not when it is written, and the same name can point at a string now and a list later. Weak typing would mean Python silently converts between unrelated types — and it does not. "3" + 5 raises a TypeError rather than guessing. So Python is dynamically typed but strongly typed.

Say this in 30 seconds

Types are checked at runtime, not compile time, but Python still refuses to mix incompatible types silently. Dynamic and strong.

Likely follow-up: If Python is dynamically typed, what do type hints actually do?
06What is duck typing?typingprotocols＋
Simple answer

Duck typing means Python cares about what an object can do, not what class it belongs to. If an object has the methods you call, it works — no shared base class required. This is why any object with __iter__ can be used in a for loop, and why writing to a real file and to an in-memory buffer look identical in your code.

Say this in 30 seconds

If it behaves like the thing you need, Python accepts it. Behaviour matters, inheritance does not.

Likely follow-up: How would you express a duck-typed contract in type hints?
07Are Python variables containers or labels?referencesobjectsfundamentals＋
Simple answer

Labels. A Python variable is a name bound to an object, not a box holding a value. Assignment never copies the object; it just points another name at the same one. Almost every surprising result in Python — shared lists, unexpected mutations, is versus == confusion — comes from missing this.

labels.py
a = [1, 2, 3]
b = a          # b is another label on the SAME list
b.append(4)
print(a)       # [1, 2, 3, 4]
Say this in 30 seconds

Names point at objects. Assignment rebinds a name, it never copies the object.

Likely follow-up: So how do you actually get an independent copy?
08What is the difference between is and ==?identityequalityhigh-frequency＋
Simple answer

== asks “do these have the same value?” and is asks “are these literally the same object in memory?” Two separate lists with identical contents are == but not is. Use is only for singletons — None, True, False — and == for everything else.

Say this in 30 seconds

== compares values, is compares identity. Use is None, never == None.

Likely follow-up: Why does a is b sometimes return True for small integers?
09Why does 256 is 256 give True but 1000 is 1000 can give False?interningidentitytrick question＋
Simple answer

CPython pre-creates and reuses the integer objects from -5 to 256 because they are used constantly. Those are the same object every time, so is is True. Larger integers get fresh objects, so identity is not guaranteed. This is an implementation detail and exactly why comparing numbers with is is a bug waiting to happen.

Say this in 30 seconds

Small integers are cached and reused by CPython. It proves nothing about the language — compare numbers with ==.

Likely follow-up: Does the same caching apply to strings?
10What is mutability, and which built-in types are immutable?mutabilityfundamentalshigh-frequency＋
Simple answer

A mutable object can be changed after creation; an immutable one cannot. Mutable: list, dict, set, and most custom classes. Immutable: int, float, str, tuple, frozenset, bytes. Immutability is what lets a type be used as a dictionary key, and it is why s += "x" in a loop quietly builds a new string each time.

Say this in 30 seconds

Mutable objects can be changed in place; immutable ones create a new object on every change. It decides what can be a dict key.

Likely follow-up: A tuple is immutable — so can a tuple always be a dict key?
11What is a shallow copy versus a deep copy?copymutabilityhigh-frequency＋
Simple answer

A shallow copy makes a new outer object but reuses the same inner objects, so changing a nested list shows up in both copies. A deep copy recursively copies everything, so the two are fully independent. Deep copies are safer but slower, and they fail on objects holding things like open sockets — so copy shallowly and be deliberate about what you deep-copy.

copies.py
import copy

original = [[1, 2], [3, 4]]      # a list holding two inner lists

shallow = copy.copy(original)     # new outer list, SAME inner lists
deep = copy.deepcopy(original)    # new outer list, NEW inner lists too

original[0].append(99)            # change an inner list

print(shallow[0])   # [1, 2, 99]  -> shallow shares that inner list
print(deep[0])      # [1, 2]      -> deep copied it, so it is unaffected
Say this in 30 seconds

Shallow copies the container but shares the contents. Deep copies everything down the tree.

Likely follow-up: How would you make a class control its own copying behaviour?
12What are Python's built-in scopes, and what does LEGB mean?scopelegb＋
Simple answer

When Python looks up a name it searches four places in order: Local (inside the current function), Enclosing (any outer function wrapping it), Global (module level), and Built-in (things like len). The first match wins. This is why defining a variable called list at module level quietly breaks the built-in for the rest of the file.

Say this in 30 seconds

Local, then Enclosing, then Global, then Built-in. First match wins, so shadowing built-ins is dangerous.

Likely follow-up: How do global and nonlocal change this lookup?

Syntax, operators and control flow

13How do and, or and not behave, and what do they return?operatorsshort-circuit＋
Simple answer

They short-circuit and they return one of the operands, not necessarily a boolean. a and b returns a if a is falsy, otherwise b. a or b returns a if a is truthy, otherwise b. That is why name = user_input or "guest" works — but it also means an empty string or 0 would be replaced, which is often a bug.

Say this in 30 seconds

They short-circuit and return an operand, not True or False. or as a default is risky when 0 or empty string is valid.

Likely follow-up: What would you use instead when 0 is a legitimate value?
14What is truthiness, and which values are falsy?truthinessfundamentals＋
Simple answer

Any object can be used in a condition and Python decides whether it counts as true. Falsy values are False, None, 0, 0.0, empty string, empty list, tuple, dict, set, and any object whose __bool__ or __len__ says so. Everything else is truthy. So if items: is the idiomatic way to check for a non-empty list.

Say this in 30 seconds

Empty and zero-like things are falsy, everything else is truthy. Use if items: rather than len(items) > 0.

Likely follow-up: Why is if x is not None: sometimes safer than if x:?
15What is the difference between /, // and %?operatorsnumbers＋
Simple answer

/ is true division and always returns a float, even 4 / 2 gives 2.0. // is floor division, rounding down towards negative infinity, so -7 // 2 is -4, not -3. % gives the remainder and in Python it takes the sign of the divisor, so -7 % 2 is 1. That negative-number behaviour is the part people get wrong.

Say this in 30 seconds

/ always floats, // floors toward negative infinity, % takes the divisor's sign.

Likely follow-up: What does divmod give you?
16What does the walrus operator := do?modern pythonsyntax＋
Simple answer

It assigns a value and returns it in the same expression, so you can bind and test in one line. It is mostly used to avoid computing something twice or to tidy a while-loop that reads then checks. Use it where it removes a repeated call; skip it where it makes the line hard to read.

walrus.py
# Without the walrus: readline() is written twice
line = f.readline()
while line:
    process(line)
    line = f.readline()     # easy to forget this line and loop forever

# With the walrus: read and test in one step
while (line := f.readline()):    # assigns to line, then checks it
    process(line)
Say this in 30 seconds

It assigns inside an expression, so you can capture a value and test it in one step.

Likely follow-up: Where would using it hurt readability?
17What is structural pattern matching, and when would you use it?modern pythonmatch3.10+＋
Simple answer

match/case, added in Python 3.10, checks a value against a shape rather than just a value, and pulls the pieces out at the same time. Use it when you are branching on the shape of data — an event dict, a parsed message, an API response. If you are only comparing a variable to two or three constants, if/elif is clearer.

match.py
match event:
    # Matches a dict with type "click", and pulls x and y out in one step
    case {"type": "click", "x": x, "y": y}:
        handle_click(x, y)

    # A different shape -> a different branch
    case {"type": "key", "code": code}:
        handle_key(code)

    case _:                     # _ is the catch-all, like "else"
        ignore(event)
Say this in 30 seconds

It matches on the shape of data and destructures it in one step. Good for parsing events, overkill for simple equality.

Likely follow-up: How is it different from a switch statement in other languages?
18What is the difference between a for loop and a while loop?loopsbasicshigh-frequency＋
Simple answer

A for loop walks through an iterable and stops when it runs out, so the number of steps comes from the data. A while loop repeats as long as a condition is true, so you control termination yourself and risk an infinite loop if the condition never changes. In Python, for is the default; reach for while when you genuinely do not know how many iterations you need.

Say this in 30 seconds

for iterates over data of known length; while repeats until a condition flips. Prefer for in Python.

Likely follow-up: What does the else clause on a loop do?
19What does else on a for or while loop mean?loopstrick question＋
Simple answer

The else block runs only if the loop finished without hitting break. It is really a “no break happened” clause, which is why the name confuses everyone. The classic use is a search loop: the else runs when nothing was found.

loop_else.py
for user in users:
    if user.is_admin:
        print("admin found")
        break               # break SKIPS the else block below
else:
    # Runs only if the loop finished without ever hitting break.
    # Read it as "no break happened", not as "otherwise".
    print("no admin in this list")
Say this in 30 seconds

It runs when the loop ends naturally, without a break. Think of it as 'no break'.

Likely follow-up: Could you rewrite that without else? Which reads better?
20What is the difference between break, continue and pass?loopsbasics＋
Simple answer

break exits the loop entirely. continue skips the rest of this iteration and moves to the next one. pass does nothing at all — it is a placeholder so a block that must not be empty can stay empty, such as a stub function or an exception you intentionally ignore.

Say this in 30 seconds

Break leaves the loop, continue skips one round, pass does nothing and just fills a required block.

Likely follow-up: What is the difference between pass and ... in a stub?
21How does chained comparison such as 1 < x < 10 work?operatorssyntax＋
Simple answer

Python expands it into 1 < x and x < 10, and importantly it evaluates x only once. That makes it both readable and safe with expensive expressions. Most other languages would evaluate 1 < x to a boolean first and then compare that to 10, producing nonsense.

Say this in 30 seconds

Python chains it into an and, evaluating the middle expression once. It reads like maths and behaves like maths.

Likely follow-up: What does a == b == c mean here?
22What is the ternary conditional expression in Python?syntaxbasics＋
Simple answer

It is written value-first: result = a if condition else b. It is an expression, so it can be used inline in a return statement, a comprehension, or an argument. Keep it to one simple condition; nested ternaries are almost always harder to read than an if block.

Say this in 30 seconds

x if condition else y. It is an expression, so it can go anywhere a value can.

Likely follow-up: Can you use it inside a list comprehension? Where does it go?

Types, numbers and conversion

23What are Python's core built-in data types?typesbasicshigh-frequency＋
Simple answer

Numbers (int, float, complex, bool), text (str), binary (bytes, bytearray), sequences (list, tuple, range), mappings (dict), sets (set, frozenset), and NoneType. A useful way to group them for an interview is by two questions: is it mutable, and is it ordered.

Say this in 30 seconds

Numbers, strings, bytes, list, tuple, range, dict, set, frozenset and None. Group them by mutable versus immutable.

Likely follow-up: Which of those can be dictionary keys, and why?
24Why is 0.1 + 0.2 != 0.3?floatsnumberstrick question＋
Simple answer

Floats are stored in binary, and 0.1 and 0.2 have no exact binary representation, so tiny rounding errors survive the addition. This is not a Python bug — it is how hardware floating point works everywhere. Compare with math.isclose, and for money use decimal.Decimal, which does exact decimal arithmetic.

floats.py
import math
from decimal import Decimal

0.1 + 0.2 == 0.3                    # False
math.isclose(0.1 + 0.2, 0.3)        # True
Decimal("0.1") + Decimal("0.2")     # Decimal('0.3')
Say this in 30 seconds

Binary floating point cannot represent 0.1 exactly. Use math.isclose for comparisons and Decimal for money.

Likely follow-up: Why not just round everything to two decimal places instead?
25Why is bool a subclass of int?typestrick question＋
Simple answer

For historical reasons: Python had no boolean type at first and used 1 and 0. When bool was added it was made a subclass of int so old code kept working. The practical effect is that True + True is 2, and sum([True, False, True]) is a neat way to count matching items.

Say this in 30 seconds

History. True is 1 and False is 0, which is why summing a list of booleans counts them.

Likely follow-up: Where has that caused a real bug you have seen?
26What is type casting, and what is the difference between implicit and explicit conversion?typecasttype conversioncastingbasicshigh-frequency＋
Simple answer

Type casting means changing a value from one type to another. Python does some of it implicitly: in 2 + 3.5 it widens the int to a float by itself, because nothing is lost. Anything that could lose data or has no obvious meaning must be explicit — you call int(), float(), str() or list() yourself. Python never guesses across unrelated types, which is why "3" + 5 raises a TypeError instead of quietly producing 8 or "35".

casting.py
# IMPLICIT — Python widens int to float on its own, nothing is lost
2 + 3.5           # 5.5   (int -> float)
True + 1          # 2     (bool is a subclass of int)

# EXPLICIT — you must ask, because data may be lost or the meaning is unclear
int(3.9)          # 3     truncates, does NOT round
int("42")         # 42
str(42)           # '42'
list("abc")       # ['a', 'b', 'c']

# Python refuses to guess between unrelated types
"3" + 5           # TypeError
int("3.5")        # ValueError — int() parses integers, not decimal text
int(float("3.5")) # 3      — convert in two steps instead
Say this in 30 seconds

Implicit is when Python widens a type safely by itself, like int to float. Explicit is when you call int(), str() or float() because data could be lost. Python never converts between unrelated types on its own.

Likely follow-up: Why does int("3.5") fail when int(3.5) works?
27How do you convert between types safely?castingerrors＋
Simple answer

Use the constructors — int(), float(), str(), list() — but never assume the input is clean. int("12a") raises ValueError, so wrap conversions of external data in try/except ValueError and give a useful error. For user input and API payloads, validating with something like Pydantic beats hand-rolled casting.

Say this in 30 seconds

Use the built-in constructors, but wrap conversions of untrusted data in try/except ValueError, or validate with Pydantic.

Likely follow-up: Why does int("3.5") fail when int(3.5) works?
28What does None mean, and how should you check for it?nonebasics＋
Simple answer

None is Python's single object representing “no value” — different from 0, False or an empty string. Because there is only ever one None object, check it with if x is None, which is faster and cannot be fooled by a class that overrides __eq__.

Say this in 30 seconds

It is the one object meaning 'no value'. Always test it with is None, not == None.

Likely follow-up: How do you type-hint a value that may be None?
29What is the difference between mutable and immutable when passing arguments to a function?argumentsmutabilityhigh-frequency＋
Simple answer

Python passes the reference to the object. If you pass a list and the function calls .append(), the caller sees the change. If you pass an integer or string and the function reassigns it, the caller sees nothing, because reassignment just rebinds the local name. So it is neither pure pass-by-value nor pass-by-reference — it is pass the object reference, and mutability decides what the caller observes.

passing.py
def mutate(items, count):
    items.append(1)   # visible to caller — list is mutable
    count += 1        # invisible — rebinds a local name

nums, n = [], 0
mutate(nums, n)
print(nums, n)        # [1] 0
Say this in 30 seconds

Python passes object references. Mutating the object is visible to the caller; rebinding the name is not.

Likely follow-up: How would you let a function return a changed number cleanly?
30What are bytes and how do they relate to str?bytesencoding＋
Simple answer

str is text — a sequence of characters. bytes is raw binary data. You move between them with an explicit encoding: text.encode("utf-8") gives bytes, data.decode("utf-8") gives text. Files, sockets and HTTP bodies all carry bytes, so encoding bugs almost always come from decoding with the wrong assumption.

Say this in 30 seconds

str is text, bytes is raw data, and you convert with an explicit encoding — usually UTF-8.

Likely follow-up: What happens if you decode UTF-8 data as ASCII?
31What is the difference between type(x) and isinstance(x, T)?typesoop＋
Simple answer

type(x) gives the exact class, so type(True) == int is False. isinstance also accepts subclasses, so isinstance(True, int) is True. Prefer isinstance for checks, because it respects inheritance and accepts a tuple of options — but the most Pythonic answer is often not to type-check at all and rely on duck typing.

Say this in 30 seconds

type is exact, isinstance accepts subclasses. Use isinstance, or avoid the check entirely.

Likely follow-up: When would exact type checking actually be correct?
32What does id() return, and when is it useful?identitymemory＋
Simple answer

It returns a unique number identifying the object for as long as it lives — in CPython, its memory address. Use it while debugging, to answer “are these two names pointing at the same object?” Do not store it: the number changes between runs, and Python reuses it once the object is freed.

Say this in 30 seconds

A unique id for the object while it exists. Useful for debugging identity, never for storing.

Likely follow-up: Could two objects ever share an id during one program run?
33What is the Zen of Python and why does it come up?pepstyle＋
Simple answer

It is a short list of design principles, printed by import this — explicit is better than implicit, simple is better than complex, readability counts. Interviewers rarely want you to recite it. They ask to see whether you can point at a real decision you made where you chose the clearer option over the clever one.

Say this in 30 seconds

A set of guiding principles from import this. The useful answer is an example of choosing readable over clever.

Likely follow-up: Give me a time you rewrote clever code to be more obvious.
34What is PEP 8, and do teams follow it strictly?styletooling＋
Simple answer

PEP 8 is the official Python style guide: naming, indentation, line length, import order. Most teams do follow it, but they enforce it with tools rather than reviews — ruff or black format on save, and CI rejects anything unformatted. The honest answer is that consistency matters more than the specific rules, and automation removes the argument.

Say this in 30 seconds

The Python style guide. Teams follow it via automated formatters and linters rather than manual review.

Likely follow-up: What is the difference between a formatter and a linter?
35What Python version features would you expect a 2026 codebase to use?modern pythonversions＋
Simple answer

On Python 3.10 and above: built-in generics like list[str] instead of List[str], the X | Y union syntax, match statements, and clearer error messages. On 3.11+: exception groups, asyncio.TaskGroup, and a meaningful speed improvement. Knowing which version introduced what signals you have actually kept up rather than learned Python once.

Say this in 30 seconds

3.10+ syntax: list[str], X | None, match statements, and on 3.11 TaskGroup plus a real speedup.

Likely follow-up: How do you handle supporting an older Python in a library?
