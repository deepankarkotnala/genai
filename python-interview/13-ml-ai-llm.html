ML, Deep Learning, LLMs & MLOps

AI engineering interviews in 2026 are majority GenAI, but they still open with classical ML. Expect bias-variance and overfitting first, then RAG versus fine-tuning — a question now asked even at fresher level.

What the interviewer is really testing

For classical ML, whether you can explain a concept without the formula and then say what it means for a real model. For GenAI, whether you have actually shipped something — the difference between a candidate who has read about RAG and one who has debugged a retrieval failure shows up within two questions.

34 questions

Core machine learning

01What is the difference between supervised and unsupervised learning?mlbasicshigh-frequency＋
Simple answer

Supervised learning trains on labelled examples and predicts a known target — classification for categories, regression for numbers. Unsupervised learning has no labels and finds structure instead: clusters, or a lower-dimensional representation. In practice most business problems are supervised, and the hard part is not the algorithm but getting trustworthy labels.

Say this in 30 seconds

Supervised learns from labelled examples to predict a target; unsupervised finds structure without labels. The real difficulty is usually the labels.

Likely follow-up: Where does self-supervised learning fit — and how does an LLM get trained?
02Explain the bias-variance trade-off.mlfundamentalshigh-frequency＋
Simple answer

Bias is error from a model too simple to capture the real pattern — it underfits and does badly everywhere. Variance is error from a model so flexible it memorises the training noise — it overfits and does badly on new data. More complexity lowers bias and raises variance, so you tune to the point where total error is lowest. You see it directly in the gap between training and validation scores.

Say this in 30 seconds

Bias is being too simple and underfitting; variance is being too flexible and memorising noise. You tune complexity to minimise total error.

Likely follow-up: Your training accuracy is 99% and validation is 70%. Which problem is it?
03What is overfitting, and how do you prevent it?mloverfittinghigh-frequency＋
Simple answer

The model learns noise specific to the training set, so it scores well there and poorly on new data. Prevent it with more or better data, simpler models, regularisation such as L1 or L2, cross-validation to detect it honestly, early stopping, and dropout in neural networks. Ensembles help too. The first check is always whether train and validation scores have diverged.

Say this in 30 seconds

Learning noise rather than signal. Fight it with more data, simpler models, regularisation, cross-validation, early stopping and dropout.

Likely follow-up: Can a model overfit even with a huge dataset?
04Why do you need cross-validation instead of one train-test split?mlvalidation＋
Simple answer

A single split gives one noisy estimate that depends heavily on which rows happened to land where. K-fold cross-validation trains k times on different splits and averages, giving both a more stable estimate and a sense of its variance. Use stratified folds for imbalanced classes, and time-based splits for time series — random folds there leak the future into the past.

Say this in 30 seconds

One split is a noisy estimate. K-fold averages over several, and you stratify for imbalance or split by time for time series.

Likely follow-up: Why is random k-fold wrong for forecasting?
05What is data leakage, and how does it sneak in?mlleakagesenior＋
Simple answer

Information from outside the training data reaching the model, so it scores brilliantly in validation and fails in production. It sneaks in through scaling or imputing before splitting, through features computed using the future, through duplicate rows spread across splits, and through a feature that is really a proxy for the target. If a result looks too good, assume leakage and go looking.

Say this in 30 seconds

Training information the model would not have at prediction time. Fit transformers after splitting, and be suspicious of results that look too good.

Likely follow-up: How would you audit a feature set for leakage?
06When is accuracy the wrong metric?mlmetricshigh-frequency＋
Simple answer

Whenever the classes are imbalanced or the two kinds of error cost differently. On a dataset that is 99% negative, predicting everything negative scores 99% and is useless. Use precision, recall and F1, look at the confusion matrix, and pick the metric that matches the cost — recall for fraud or disease detection where a miss is expensive, precision where a false alarm is.

Say this in 30 seconds

With imbalanced classes or asymmetric error costs. Use precision, recall, F1 and the confusion matrix, chosen by which error hurts more.

Likely follow-up: Explain precision and recall to a business stakeholder in one sentence each.
07How would you handle an imbalanced classification dataset?mlimbalancehigh-frequency＋
Simple answer

Start by changing the metric and the threshold rather than the data — often the model is fine and the default 0.5 cut-off is wrong. Then consider class weights, which cost nothing, before resampling. Oversample with SMOTE or undersample the majority if needed, always inside the cross-validation fold so you do not leak. And check whether you can simply collect more of the rare class.

Say this in 30 seconds

Fix the metric and threshold first, then class weights, then resampling inside the fold. Rebalancing the whole dataset first leaks.

Likely follow-up: Why must SMOTE be applied inside the fold rather than before splitting?
08How does a decision tree decide where to split?mltreeshigh-frequency＋
Simple answer

It tries candidate splits and picks the one that most reduces impurity — Gini or entropy for classification, variance for regression. Information gain is just the impurity before the split minus the weighted impurity after. Left unconstrained a tree splits until every leaf is pure, which is perfect overfitting, so you limit depth, minimum samples per leaf, or prune.

Say this in 30 seconds

It picks the split that most reduces impurity — Gini or entropy. Unconstrained it overfits completely, so you limit depth and leaf size.

Likely follow-up: Does the choice between Gini and entropy usually matter?
09What is the difference between bagging and boosting?mlensembleshigh-frequency＋
Simple answer

Bagging trains many models in parallel on bootstrap samples and averages them, which reduces variance — random forest is the example. Boosting trains models sequentially, each correcting the previous one's errors, which reduces bias — XGBoost and LightGBM. Boosting usually scores higher on tabular data but is more sensitive to noise and to hyperparameters.

Say this in 30 seconds

Bagging averages parallel models to cut variance; boosting builds sequentially to cut bias. Boosting usually wins on tabular data.

Likely follow-up: Why is a random forest harder to overfit than a boosted model?
10How does an SVM work, and what are support vectors?mlsvmhigh-frequency＋
Simple answer

An SVM finds the boundary that separates classes with the widest possible margin. The support vectors are the few points sitting closest to that boundary — they alone determine it, and moving any other point changes nothing. For data that is not linearly separable, the kernel trick maps it into a higher-dimensional space where a linear boundary exists, without ever computing those coordinates.

Say this in 30 seconds

It finds the maximum-margin boundary. Support vectors are the closest points, which alone define it. Kernels handle non-linear cases.

Likely follow-up: Why do SVMs scale poorly to very large datasets?
11What does regularisation do, and how do L1 and L2 differ?mlregularisation＋
Simple answer

It penalises large coefficients so the model stays simpler and generalises better. L2 (ridge) shrinks coefficients smoothly towards zero without reaching it, which handles correlated features well. L1 (lasso) can drive coefficients exactly to zero, so it performs feature selection. Elastic net mixes both. Always scale features first, or the penalty falls unevenly.

Say this in 30 seconds

It penalises large coefficients to prevent overfitting. L2 shrinks smoothly, L1 zeroes features out and so selects them.

Likely follow-up: Why must features be scaled before regularising?
12How would you approach a loan-default prediction problem?mlcase studyhigh-frequency＋
Simple answer

Clarify the objective and cost of each error type first — approving a defaulter and rejecting a good customer are not equally expensive. Then build a leak-free dataset with a time-based split, engineer features from repayment history, start with logistic regression as an interpretable baseline, and move to gradient boosting if it earns its complexity. Tune the threshold by business cost, check fairness across groups, and monitor drift after deployment. Regulated lending also means the model must be explainable.

Say this in 30 seconds

Clarify the cost of each error, split by time to avoid leakage, baseline with logistic regression, then boosting, tune the threshold by business cost, and check fairness and explainability.

Likely follow-up: The business wants 99% accuracy. How do you respond?

Deep learning and PyTorch

13Explain backpropagation in plain language.deep learninghigh-frequency＋
Simple answer

Run the input forward to get a prediction and compute the loss. Then work backwards through the network using the chain rule to find how much each weight contributed to that error. Nudge every weight slightly in the direction that reduces the loss. Repeat over many batches. That is all training is — forward pass, loss, backward pass, update.

Say this in 30 seconds

Forward pass to get the loss, then the chain rule backwards to find each weight's contribution, then nudge every weight to reduce the error.

Likely follow-up: What are vanishing gradients and why do they happen?
14What does an activation function do, and why not use a linear one?deep learningbasics＋
Simple answer

It introduces non-linearity. Without it, stacking layers is pointless — a chain of linear transformations collapses into a single linear transformation, so a hundred layers would have exactly the power of one. ReLU is the default because it is cheap and does not saturate for positive values; softmax turns final scores into class probabilities.

Say this in 30 seconds

It adds non-linearity. Without it, any number of layers collapses into one linear function.

Likely follow-up: What is the dying ReLU problem?
15What is the difference between batch size, epoch and iteration?deep learningtraining＋
Simple answer

A batch is the group of samples processed before one weight update. An iteration is one such update. An epoch is one full pass over the training data, so it contains dataset-size divided by batch-size iterations. Larger batches give smoother gradients and better GPU use; smaller batches add noise that sometimes generalises better and always uses less memory.

Say this in 30 seconds

Batch is samples per update, iteration is one update, epoch is one full pass over the data.

Likely follow-up: What happens to the learning rate when you increase the batch size?
16How does attention work in a transformer?transformersllmhigh-frequency＋
Simple answer

Every token produces a query, a key and a value. Comparing one token's query with all the keys gives scores for how relevant each other token is; softmax turns them into weights, and the output is the weighted mix of values. So each token's representation is built from the tokens that matter to it, regardless of distance. Multi-head attention runs several of these in parallel so different heads capture different relationships.

Say this in 30 seconds

Each token asks which other tokens matter via query-key similarity, then mixes their values by those weights. Multiple heads capture different relationships.

Likely follow-up: Why is attention quadratic in sequence length, and what is done about it?
17Why would you use PyTorch, and what is a tensor?pytorchdeep learning＋
Simple answer

A tensor is a multi-dimensional array like a NumPy array, plus two things: it can live on a GPU, and it can track the operations applied to it so gradients can be computed automatically. PyTorch is preferred for research and increasingly for production because the graph is built as the code runs, which makes debugging ordinary Python debugging.

Say this in 30 seconds

A tensor is a NumPy-style array that can sit on a GPU and track gradients. PyTorch builds the graph as code runs, so debugging is normal Python.

Likely follow-up: What does torch.no_grad() do and when do you need it?
18Your training loss goes down but validation loss goes up. What do you do?deep learningdebugginghigh-frequency＋
Simple answer

That is overfitting starting at the point where the curves diverge. Add early stopping at that epoch, increase regularisation with dropout or weight decay, augment or gather more data, or reduce model capacity. Before all of that, confirm the split is clean — divergence this clear sometimes means the validation set is different in kind, not that the model is over-trained.

Say this in 30 seconds

Overfitting from the divergence point. Early stopping, dropout, weight decay, more data or a smaller model — after checking the split is sound.

Likely follow-up: What if both losses are flat and high from the start?

LLMs, RAG and agents

19When would you use RAG versus fine-tuning?ragllmhigh-frequency＋
Simple answer

RAG when the model needs facts it was not trained on — your documents, your data, anything that changes. It updates instantly by reindexing, gives you citations, and controls access per user. Fine-tuning when you need to change behaviour, format or tone consistently, not to add knowledge. They are not alternatives so much as answers to different questions, and in production you often do both.

Say this in 30 seconds

RAG for knowledge that changes and needs citations; fine-tuning for consistent behaviour, style or format. Knowledge versus behaviour.

Likely follow-up: Your RAG answers are wrong but the right document is in the index. What now?
20What is RAG, end to end?ragarchitecturehigh-frequency＋
Simple answer

Documents are chunked, embedded into vectors and stored in an index. At query time the question is embedded, the closest chunks are retrieved, and they are placed into the prompt as context for the model to answer from. The parts that decide quality are chunking strategy, retrieval quality and how the context is assembled — the model is rarely the bottleneck.

Say this in 30 seconds

Chunk, embed, index. At query time embed the question, retrieve nearest chunks, and put them in the prompt as grounding.

Likely follow-up: Which step do you tune first when answers are poor?
21What is an embedding, and how is similarity measured?embeddingsrag＋
Simple answer

An embedding maps text to a vector so that texts with similar meaning sit close together. Similarity is usually cosine, which compares direction and ignores magnitude — that is why vectors are typically normalised. Two things to remember: embeddings from different models are not comparable, and changing the model means reindexing everything.

Say this in 30 seconds

A vector where nearby means similar in meaning, compared with cosine similarity. Changing the model means reindexing everything.

Likely follow-up: Why does keyword search still beat embeddings for some queries?
22How do you choose a chunking strategy?ragchunking＋
Simple answer

Chunk on the document's natural structure — headings, sections, paragraphs — rather than a fixed character count that cuts sentences in half. Add overlap so ideas spanning a boundary survive. Size for the retrieval unit you want: too large and the relevant sentence is diluted by noise, too small and it lacks context to be understood. Always keep metadata like source and section for filtering and citation.

Say this in 30 seconds

Chunk on document structure with overlap, sized so a chunk is self-contained but not diluted, and keep metadata for filtering and citations.

Likely follow-up: How would you chunk a table or a codebase differently?
23Why does hybrid search usually beat pure vector search?ragretrievalsenior＋
Simple answer

Embeddings capture meaning but are poor at exact tokens — product codes, error numbers, names, acronyms. Keyword search such as BM25 nails those and fails on paraphrase. Running both and fusing the results covers each one's blind spot. Adding a reranker on the combined top results usually gives the single biggest quality jump in a RAG system.

Say this in 30 seconds

Vectors miss exact tokens like IDs and codes, keywords miss paraphrase. Fuse both, then rerank — that is usually the biggest quality win.

Likely follow-up: What does a cross-encoder reranker do that the retriever cannot?
24What causes hallucination, and how do you reduce it?llmhallucinationhigh-frequency＋
Simple answer

The model predicts plausible next tokens; it has no notion of truth, so when the context lacks the answer it produces something that reads correctly. Reduce it by grounding answers in retrieved context, instructing the model to say it does not know, requiring citations you can verify against the source, keeping temperature low for factual work, and checking the answer against the context before returning it. You mitigate it; you do not eliminate it.

Say this in 30 seconds

It predicts plausible text, not truth. Ground in retrieved context, allow 'I don't know', require verifiable citations, and check the answer against the source.

Likely follow-up: How would you measure the hallucination rate of your system?
25What is the difference between a workflow and an agent?agentsdesignsenior＋
Simple answer

In a workflow you decide the steps and the model fills in the parts that need language. In an agent the model decides which tools to call and in what order, looping until it is done. Agents are more flexible and much harder to make reliable, debug and cost-control. Most production systems should be workflows with a model inside, not agents — use an agent when the path genuinely cannot be known in advance.

Say this in 30 seconds

A workflow has a path you defined; an agent decides its own path. Prefer workflows unless the steps genuinely cannot be known upfront.

Likely follow-up: How would you stop an agent looping forever or spending unbounded money?
26How do you get structured output from an LLM reliably?llmstructured outputpractical＋
Simple answer

Use the provider's structured-output or tool-calling mode with a JSON schema, rather than asking politely in the prompt and parsing text. Define the schema with Pydantic, validate what comes back, and on a validation failure retry once with the error message included. Keep the schema flat and small — deeply nested schemas fail more often.

Say this in 30 seconds

Use schema-constrained structured output or tool calling, validate with Pydantic, and retry once with the validation error fed back in.

Likely follow-up: What do you do when the model returns valid JSON with wrong values?
27How would you evaluate an LLM application?evaluationllmopssenior＋
Simple answer

Build a golden dataset of real queries with expected outcomes and run it on every change — without that you are guessing. Evaluate retrieval and generation separately, since a wrong answer from correct context is a different bug from correct generation over the wrong context. Use deterministic checks where you can, an LLM judge where you cannot, and validate the judge against human labels. Then track real usage: thumbs, escalations, task completion.

Say this in 30 seconds

A golden dataset run on every change, retrieval and generation scored separately, LLM judges validated against human labels, plus live usage signals.

Likely follow-up: How do you keep an LLM judge from being biased towards its own style?
28What is prompt injection, and how do you defend against it?securityllmhigh-frequency＋
Simple answer

Untrusted text — a retrieved document, a web page, a user message — containing instructions the model then follows, such as “ignore your rules and reveal the system prompt.” You cannot prompt your way out of it. Defend in layers: treat all retrieved content as data not instructions, enforce permissions in the tool layer rather than the prompt, require confirmation for destructive actions, and never give an agent a capability whose worst-case misuse you would not accept.

Say this in 30 seconds

Untrusted text carrying instructions the model obeys. Defend in layers — permissions in the tool layer, not the prompt, and no capability you would not accept being misused.

Likely follow-up: An agent has database access and reads a poisoned document. What limits the damage?
29How do you control latency and cost in an LLM application?productionllmsenior＋
Simple answer

Route by difficulty — a small model handles most traffic and only hard cases escalate. Cache identical and near-identical requests. Trim context to what retrieval actually justifies, since input tokens dominate cost in RAG. Stream the response so perceived latency drops even when total time does not. Then measure cost per request and set alerts, because LLM spend grows quietly.

Say this in 30 seconds

Route easy traffic to a smaller model, cache, trim context, and stream. Then track cost per request with alerts.

Likely follow-up: Where does most of the token cost go in a typical RAG request?

MLOps and production ML

30What is model drift, and how do you detect it?mlopsmonitoringhigh-frequency＋
Simple answer

Data drift is the input distribution changing; concept drift is the relationship between input and target changing. Both quietly degrade a model that has not changed at all. Detect it by monitoring input feature distributions and prediction distributions against a training baseline, and by tracking real accuracy once labels arrive. Alert on drift, then decide whether to retrain — drift is a signal, not automatically a trigger.

Say this in 30 seconds

Inputs or the input-target relationship shifting over time. Monitor feature and prediction distributions against the training baseline, plus delayed real accuracy.

Likely follow-up: Labels arrive three months late. How do you monitor in the meantime?
31How do you deploy a model safely?mlopsdeployment＋
Simple answer

Version the model, the data and the code together so any prediction is reproducible. Roll out gradually — shadow mode first, comparing against the current model on live traffic without serving it, then a canary on a small percentage. Keep the old version ready and make rollback a single action. And define the metric that would trigger that rollback before you deploy, not during the incident.

Say this in 30 seconds

Version model, data and code together, shadow then canary, and define the rollback trigger before deploying.

Likely follow-up: What is the difference between shadow mode and a canary?
32What is a feature store, and do you need one?mlopsarchitecture＋
Simple answer

A shared place to define, compute and serve features consistently to both training and inference. Its real purpose is preventing training-serving skew — the same feature computed two different ways in two codebases. If you have one model and one pipeline you do not need one. Several teams reusing features is when the cost starts paying for itself.

Say this in 30 seconds

One place to define features so training and serving compute them identically, preventing skew. Not worth it for a single model.

Likely follow-up: How does training-serving skew show up in production?
33How would you design a real-time ML inference service?mlopssystem designsenior＋
Simple answer

Start from the latency budget and the traffic, because they decide everything else. Load the model once at startup, not per request. Batch requests if the model benefits and the budget allows. Cache repeated inputs. Keep preprocessing identical to training — ideally the same code path. Add health checks, versioned endpoints, timeouts, and a fallback for when the model service is down: a cached answer or a simple heuristic beats an error page.

Say this in 30 seconds

Work back from the latency budget: load once at startup, batch if it helps, cache, share preprocessing code with training, and have a fallback.

Likely follow-up: What is your fallback when the model service is unavailable?
34How do you make an ML experiment reproducible?mlopsreproducibility＋
Simple answer

Pin the data with a version or snapshot, pin the code with a commit hash, pin the dependencies with a lock file, and set random seeds. Log parameters, metrics and artefacts with something like MLflow so a run can be found again months later. Full bit-exact reproducibility on GPUs is hard, so aim for reproducible enough that the conclusion holds.

Say this in 30 seconds

Version data, code and dependencies, set seeds, and log parameters, metrics and artefacts to an experiment tracker.

Likely follow-up: Why is exact GPU reproducibility so difficult?
