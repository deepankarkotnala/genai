Functions, Scope & Functional Python

Functions are where Python interviews start separating people. The mutable default argument and the closure-in-a-loop question appear again and again because they catch anyone who has only read about Python rather than debugged it.

20 questionsScreening + technical roundChecked July 2026
⌁
What the interviewer is really testing

Every question here comes back to one fact: def runs once, at definition time, and the function body runs later. Defaults are evaluated at definition. Closures capture the variable, not its value at the time. Say that out loud and most of these answers write themselves.

20 questions

Arguments and function signatures

01What is the difference between *args and **kwargs?argskwargshigh-frequency＋
Simple answer

*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. The names are convention only — the * and ** do the work. They are used to accept an unknown number of inputs and, most commonly, to pass arguments through a wrapper to the function it decorates.

args.py
def log_call(*args, **kwargs):
    print(args)     # tuple of positionals
    print(kwargs)   # dict of keywords

log_call(1, 2, mode="fast")   # (1, 2)  {'mode': 'fast'}
Say this in 30 seconds

*args gathers extra positionals into a tuple, **kwargs gathers extra keywords into a dict. Essential for wrappers.

Likely follow-up: What is the difference between using * in a definition and in a call?
02Why is a mutable default argument dangerous?defaultsgotchahigh-frequency＋
Simple answer

Default values are evaluated once, when the def statement runs — not on each call. So a default list or dict is a single object shared by every call that omits it, and mutations accumulate across calls. The fix is to default to None and create the object inside the function.

defaults.py
# broken
def add(item, bucket=[]):
    bucket.append(item)
    return bucket

add(1)   # [1]
add(2)   # [1, 2]  — same list!

# fixed
def add(item, bucket=None):
    bucket = [] if bucket is None else bucket
    bucket.append(item)
    return bucket
Say this in 30 seconds

Defaults are created once at definition time, so a default list is shared across calls. Default to None and build it inside.

Likely follow-up: Is there ever a legitimate use for a mutable default?
03What are positional-only and keyword-only parameters?signaturesmodern python＋
Simple answer

A bare * in the signature forces everything after it to be passed by keyword; a / forces everything before it to be positional. Keyword-only parameters make call sites self-documenting for flags and options. Positional-only lets you rename internal parameters later without breaking callers.

signature.py
def connect(host, /, port=5432, *, timeout=30, retry=False):
    ...

connect("db1", 5432, timeout=5)      # ok
connect(host="db1")                  # TypeError — host is positional-only
Say this in 30 seconds

* makes later parameters keyword-only; / makes earlier ones positional-only. Use keyword-only for flags.

Likely follow-up: Why would a library author want positional-only parameters?
04How does Python resolve arguments when a call mixes positional, keyword and defaults?argumentssignatures＋
Simple answer

Positional arguments fill parameters left to right, then keyword arguments fill by name, then any remaining parameters take their defaults. Passing the same parameter twice raises TypeError, and a missing required parameter does too. Extra arguments only work if the signature has *args or **kwargs to absorb them.

Say this in 30 seconds

Positionals fill left to right, keywords fill by name, then defaults. Duplicates and missing required arguments both raise TypeError.

Likely follow-up: What happens if a keyword argument collides with a positional you already passed?
05Does Python pass arguments by value or by reference?argumentsreferenceshigh-frequency＋
Simple answer

Neither exactly — it passes the object reference by value. The function gets its own name bound to the same object, so mutating the object is visible to the caller, but rebinding the name inside the function is not. That single sentence explains why lists appear to be passed by reference and integers by value.

Say this in 30 seconds

It passes object references by value. Mutating the object shows outside; rebinding the name does not.

Likely follow-up: How would you prove that with a two-line example?
06What does a function return if it has no return statement?functionsbasics＋
Simple answer

None. Every Python function returns something, and None is the implicit default. This is why result = my_list.sort() gives None — the method sorts in place and returns nothing. In-place operations returning None is a deliberate convention to stop you chaining them by mistake.

Say this in 30 seconds

None. That is why assigning the result of list.sort() gives you None.

Likely follow-up: Which other standard library methods return None deliberately?
07How do you return multiple values from a function?functionstuple＋
Simple answer

Return a tuple — return a, b — and unpack it at the call site. For more than three values, or when the meaning is not obvious from position, return a NamedTuple or dataclass instead so callers read fields by name rather than by index.

Say this in 30 seconds

Return a tuple and unpack it. Beyond two or three values, return a NamedTuple or dataclass for readability.

Likely follow-up: At what point does a tuple return become a bad interface?
08What are type hints on a function, and do they enforce anything at runtime?typingfunctions＋
Simple answer

They annotate what a function expects and returns, and Python does not enforce them at all — passing a string where an int is annotated runs fine. They exist for static checkers like mypy, for editor autocomplete, and for humans reading the code. Tools like Pydantic and FastAPI do enforce them, but that is the library doing the work, not Python.

Say this in 30 seconds

Documentation for tools and humans. Python ignores them at runtime; mypy and Pydantic are what give them teeth.

Likely follow-up: How would you enforce types at runtime if you needed to?
09What is a docstring, and how is it different from a comment?documentationbasics＋
Simple answer

A docstring is a string literal as the first statement of a module, class or function, and it is kept at runtime in __doc__, so help(), editors and documentation tools can read it. A comment is stripped and exists only for whoever is reading the source. Docstrings say what and why; comments explain a surprising line.

Say this in 30 seconds

A docstring is stored on the object and readable at runtime; a comment is not. Docstrings document, comments explain oddities.

Likely follow-up: What should a good docstring include for a public API function?
10What is recursion, and what limits it in Python?recursionlimits＋
Simple answer

A function calling itself, with a base case that stops it. Python caps the call stack at around 1000 frames by default and has no tail-call optimisation, so deep recursion raises RecursionError. For deep problems convert to an iterative loop with an explicit stack rather than raising the limit, which risks a hard crash.

Say this in 30 seconds

A function calling itself with a base case. Python's stack limit is about 1000 and there is no tail-call optimisation, so prefer iteration when deep.

Likely follow-up: How would you rewrite a deep recursive tree walk iteratively?

Scope, closures and lambdas

11What is a closure?closureshigh-frequency＋
Simple answer

A function defined inside another function that keeps access to the outer function's variables even after the outer function has returned. Python stores those captured variables on the inner function, so it carries state without needing a class. Closures are the machinery behind decorators and small function factories.

closure.py
def multiplier(factor):
    def multiply(x):
        return x * factor     # 'factor' belongs to the OUTER function
    return multiply           # ...but the inner one keeps using it

double = multiplier(2)        # multiplier has now returned and exited
double(5)                     # 10 — 'factor' is still alive inside double
Say this in 30 seconds

An inner function that remembers variables from the enclosing function after that function has returned.

Likely follow-up: How would you inspect what a closure captured?
12Why do closures created in a loop all give the same value?closuresgotchatrick question＋
Simple answer

Because a closure captures the variable, not the value at the moment it was created. By the time the functions run, the loop has finished and the variable holds its final value, so every function sees the last one. Bind the value with a default argument, or use functools.partial.

loop_closure.py
# all print 2
funcs = [lambda: i for i in range(3)]
[f() for f in funcs]           # [2, 2, 2]

# fixed — default argument binds now
funcs = [lambda i=i: i for i in range(3)]
[f() for f in funcs]           # [0, 1, 2]
Say this in 30 seconds

Closures capture the variable, not its value, so all of them see the loop's final value. Bind it with a default argument.

Likely follow-up: Why does the default-argument trick work?
13What do global and nonlocal do?scopeclosures＋
Simple answer

By default, assigning to a name inside a function creates a new local name. global says “write to the module-level name instead”, and nonlocal says “write to the name in the function wrapping this one.” Both are occasionally necessary. Usually, though, needing them means the value should have been a return value or an attribute on an object.

Say this in 30 seconds

They let you assign to a name from an outer scope — module level for global, enclosing function for nonlocal. Usually a design smell.

Likely follow-up: How would you rewrite a function that uses global to avoid it?
14What is a lambda, and when should you avoid one?lambdafunctional＋
Simple answer

A lambda is a small anonymous function limited to a single expression. It is useful inline as a key or a callback. Avoid it when you would assign it to a name — def gives you a proper name in tracebacks, a docstring, and room for more than one line, all for free.

Say this in 30 seconds

A one-expression anonymous function, good for inline keys and callbacks. If you are naming it, use def.

Likely follow-up: Why does assigning a lambda to a name make debugging harder?
15What is the difference between a function and a method?functionsoop＋
Simple answer

A method is a function that belongs to a class and is accessed through an instance, which automatically passes the instance as the first argument, self. Under the hood the method is still a plain function stored on the class; the binding happens on attribute access. That is why MyClass.method(obj) and obj.method() do the same thing.

Say this in 30 seconds

A method is a function on a class that receives the instance as self automatically when accessed through an object.

Likely follow-up: What does a staticmethod change about that?
16Are functions first-class objects in Python? What does that let you do?functionsfunctional＋
Simple answer

Yes. Functions can be assigned to variables, stored in lists and dicts, passed as arguments and returned from other functions. That is what makes decorators, callbacks, strategy dictionaries and higher-order functions possible without any special syntax.

first_class.py
# Functions are values, so they can be stored in a dict.
# This replaces a long if/elif chain with one lookup.
handlers = {"csv": parse_csv, "json": parse_json}

handlers[file_type](data)    # look the function up, then call it
Say this in 30 seconds

Yes — they can be stored, passed and returned like any value. That is what makes decorators and callbacks work.

Likely follow-up: How would you use that to replace a long if/elif chain?
17What do map, filter and reduce do, and are they idiomatic?functionalmapreduce＋
Simple answer

map applies a function to every item, filter keeps items where a predicate is true, and reduce (from functools) folds a sequence into one value. In modern Python, comprehensions are preferred over map and filter because they read better. reduce survives for genuine accumulations, though an explicit loop is often clearer.

functional.py
# map/filter
list(map(str.upper, names))
# comprehension — preferred
[n.upper() for n in names]
Say this in 30 seconds

They are higher-order functions, but comprehensions are more idiomatic than map and filter. reduce is niche.

Likely follow-up: When is map actually the better choice?
18What is functools.partial used for?functoolsfunctional＋
Simple answer

It pre-fills some arguments of a function and returns a new callable expecting the rest. It is handy for callbacks that must take a fixed signature, for configuring a general function into a specific one, and for avoiding the closure-in-a-loop trap by binding values immediately.

partial.py
from functools import partial

# Freeze host and timeout now; the returned function needs neither.
# Handy for callbacks that must be called with no arguments.
connect_prod = partial(connect, host="prod.db", timeout=5)

connect_prod()               # same as connect(host="prod.db", timeout=5)
Say this in 30 seconds

It freezes some arguments and returns a new function taking the rest. Good for callbacks and pre-configured helpers.

Likely follow-up: How is it different from writing a lambda that calls the function?
19What is functools.lru_cache and when is it unsafe?functoolscachingperformance＋
Simple answer

It caches a function's results keyed by its arguments, so repeated calls with the same inputs are instant. It is unsafe when the function is not pure — if it hits a database, depends on time, or has side effects, you will serve stale results. It also requires hashable arguments and holds references, so an unbounded cache on a long-running service can leak memory.

cache.py
from functools import lru_cache

# Caches results keyed by the arguments, so calling distance("a", "b")
# twice runs the body once. maxsize caps it at 1024 entries so a
# long-running service cannot grow the cache forever.
@lru_cache(maxsize=1024)
def distance(a: str, b: str) -> float:
    ...    # must be pure: same inputs -> same output, no side effects
Say this in 30 seconds

It memoises results by arguments. Only use it on pure functions with hashable arguments, and always set a maxsize.

Likely follow-up: How would you cache something that depends on a database?
20What is the difference between functools.wraps and not using it?functoolsdecorators＋
Simple answer

Without it, a decorator replaces the original function, so __name__, __doc__ and the signature all belong to the wrapper. Debuggers, documentation tools and anything inspecting the function then see the wrong thing. @wraps(func) copies that metadata across and costs one line.

Say this in 30 seconds

It copies the original function's name, docstring and metadata onto the wrapper, so tracebacks and docs stay correct.
