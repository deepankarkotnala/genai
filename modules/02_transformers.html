Transformers

Module 01 treated "the layers" as one box. This page opens it. A transformer layer does one new thing: it lets every position in the sequence read every other position, in one operation, with weights the model learned. That is attention, and everything else in the block is support for it.

⏱ Study + practice · 14–22 h Difficulty · Advanced Prereq · Modules 01, and the gradient idea from step 01

1 · What you already know

From module 01: text becomes token ids, ids become vectors, the vectors pass through a stack of layers, and the last layer produces one logit per vocabulary entry.

You also know the loop: one token is sampled, appended, and the whole sequence is read again.

The stack of layers was a single box on that page. This page is the inside of one of those boxes.

2 · What breaks now

Before transformers, sequences were processed with a recurrent network: read token 1, update a hidden state, read token 2, update it again, and so on to the end.

Two problems, and both are structural rather than fixable by better training:

ProblemWhy the loop causes it
Training is slowStep 400 needs the result of step 399, so a 1,000-token sequence is 1,000 sequential operations. A GPU with thousands of cores runs them one at a time.
Long-range links are lostEverything token 1 contributed has to survive inside one fixed-size vector through 399 rewrites. In practice it does not.

Both come from the same decision: information travels between positions by passing through every position in between. Remove that and both problems go. Attention removes it by letting position 400 read position 1 directly, in one step.

3 · Simple breakdown - transformer vs RNN

A Transformer

Basic level

What it is. A transformer is a neural network architecture built from stacked blocks, where each block combines a self-attention operation with a small feed-forward network, and every position can read every other position directly.

Core purpose. It removes the sequential dependency between positions, so a whole sequence can be processed in parallel during training and long-range relationships survive intact.

Execution model.

Intermediate level

Architecture under the hood. One block holds multi-head self-attention, a two-layer feed-forward network, two layer-norm operations and two residual connections. Each head learns its own Q, K and V projections and they run side by side. Blocks are identical in shape and stacked - 12 in GPT-2 small, 32 in a typical 7B model - with no change in vector width from bottom to top.

State handling. During training there is no state between positions: the whole sequence is one matrix. During generation the KV cache stores the keys and values already computed for earlier positions, so each new token computes attention against them instead of recomputing everything.

Limitations and advanced features. Attention compares every pair of positions, so compute and memory grow with the square of sequence length - doubling the context roughly quadruples the attention cost. The KV cache grows linearly and often dominates GPU memory at long context. Mitigations include grouped-query attention, sliding-window attention, and FlashAttention, which changes how the same maths is executed rather than the maths itself.

B RNN and LSTM

Basic level

What it is. A recurrent neural network processes a sequence one position at a time, carrying a fixed-size hidden state vector forward from each step to the next.

Core purpose. It handles sequences of any length with a fixed, small amount of memory and a cost that grows linearly rather than quadratically.

Execution model.

Intermediate level

Architecture under the hood. A plain RNN applies one weight matrix to the input and another to the previous hidden state, then a non-linearity. An LSTM adds three learned gates - input, forget and output - plus a separate cell state, so the network can hold a value across many steps without it being rewritten each time. A GRU merges those gates into two.

State handling. One hidden vector, overwritten at every position. Everything the model knows about all previous tokens must fit in it. Nothing else survives between steps.

Limitations and advanced features. Positions cannot be computed in parallel, so training does not scale with GPU width. Gradients shrink or explode across long chains, which is what the LSTM gates were invented to reduce rather than remove. Modern state-space models such as Mamba revisit the same idea with a formulation that can be parallelised during training.

The core differences

TransformerRNN / LSTM
Workflow design All positions computed together. Path length between any two positions is 1. Positions computed in order. Path length between positions i and j is the distance between them.
Error recovery Attention weights are inspectable, so you can see which positions a prediction drew on. A wrong answer can be traced to a head and a position. The hidden state is one opaque vector. There is no per-position record of what was used, so a wrong answer cannot be attributed.
Architectural paradigm Direct, learned, all-pairs lookup over the sequence. A compressed running summary carried forward step by step.

In short - which one to choose

Use a transformer when:

  • You are working with language, which is essentially always in this course.
  • Training throughput matters and you have parallel hardware.
  • Relationships between distant positions matter.

A recurrent model is still reasonable when:

  • The sequence is very long and the memory per step must stay constant.
  • You are running on a small embedded device with strict memory limits.
  • Input arrives continuously and there is no fixed window to attend over.

Do not spend time on this comparison when:

  • You are choosing an API model. This decision was made for you years ago.
  • What you actually need is a longer context, which is a serving question, not an architecture one.

4 · Without the technology

The for is the whole problem. Every iteration needs h from the one before, so a 2,000-token sequence is 2,000 dependent matrix multiplications. And whatever token 1 contributed to h has been multiplied and squashed 1,999 times by the end.

The transformer's answer is to delete the loop. Instead of carrying information forward, let each position fetch what it needs from all the others at once.

5 · Runtime mechanics

One attention operation, in eight steps. The input is a matrix of shape [sequence_length, model_width].

  1. Add positional information to the token vectors, so order is represented at all.
  2. Multiply the input by three learned matrices to get Q (query), K (key) and V (value) - one of each per position.
  3. For every pair of positions, take the dot product of one position's Q with another's K. That is the raw score matrix, shape [seq, seq].
  4. Divide every score by the square root of the head width, so the numbers stay in a range where softmax is not saturated.
  5. Apply the causal mask: set every score where the key is to the right of the query to negative infinity.
  6. Softmax each row, so each position's scores over all positions sum to 1. These are the attention weights.
  7. Multiply the weights by V. Each position's output is a weighted sum of every value it was allowed to see.
  8. Concatenate the heads, project once, add the residual, normalise, then run the feed-forward network on each position independently.

Steps 2 to 7 happen for all positions at the same time, as matrix multiplications. There is no loop over the sequence anywhere.

6 · The components, one at a time

Inside one head

1 · Query, key and value

Three different views of the same token, produced by three learned matrices. The query is what this position is looking for; the key is what a position offers; the value is what gets passed on if it is selected.

2 · The score

A dot product between one query and one key. Larger means the two vectors point in a similar direction, which is what "relevant" means here.

3 · Scaling

Dot products of d-dimensional vectors grow with d. Without dividing by sqrt(d), softmax receives large values, returns almost one-hot weights, and the gradients nearly vanish.

4 · The causal mask

A decoder must not read the future, or training would be trivial and generation impossible. Positions to the right are set to negative infinity before softmax, so they come out as exactly zero.

5 · Softmax and the weighted sum

Softmax makes each row a set of weights summing to 1. Multiplying by V gives each position a blend of the values it attended to.

Building the block

6 · Multi-head attention

The width is split into h heads, each with its own Q, K and V projections, each computing attention independently. Their outputs are concatenated and projected once. Different heads reliably specialise - some track the previous token, some match brackets, some follow subject to verb.

7 · Positional encoding

Attention is order-blind: shuffle the input rows and the outputs shuffle with them, unchanged. Position has to be added to the vectors themselves. Original transformers added fixed sine and cosine patterns; most current models use RoPE, which rotates Q and K by an angle proportional to position, so the score depends on relative distance.

8 · Residual connection

Each sub-layer adds its output to its input rather than replacing it. This is what allows 32 blocks to be stacked without the signal degrading, and what gives gradients a short path back to the early layers.

9 · Layer normalisation

Rescales each position's vector to zero mean and unit variance before the sub-layer. Modern models place it before rather than after, which makes deep stacks trainable without a learning-rate warm-up.

10 · Feed-forward network

Two linear layers with a non-linearity, applied to each position separately. It usually expands the width by four and back, and it holds roughly two-thirds of the model's parameters. Attention moves information between positions; the feed-forward network does the processing at each one.

11 · The block, and the stack

One block is attention, then feed-forward, each wrapped in a residual and a norm. The stack is that block repeated with different weights. Nothing changes shape from bottom to top.

12 · KV cache

At generation time, the keys and values for earlier positions do not change. Storing them means each new token computes one query against the cache instead of recomputing the whole sequence.

For a 7B model at 4,000 tokens this is roughly 2 GB, per concurrent request. The KV cache, not the weights, is usually what limits how many users one GPU can serve.

7 · State and data flow

1 · What data is state?During training, none between positions. During generation, the KV cache.
2 · Who writes it?Every layer writes its own keys and values for each new token.
3 · Who reads it?The attention step of that same layer, on every later token.
4 · Replaced, appended or merged?Appended. Entries for earlier positions never change.
5 · What controls merging?Nothing - it is a growing tensor per layer.
6 · Only in memory?Yes, in GPU memory, for the length of one request.
7 · Cached?It is the cache. Some servers additionally reuse it across requests that share a prefix.
8 · In a database?Never.
9 · How long does it survive?Until the request finishes, then it is freed.
10 · What key retrieves it again?None, unless the server implements prefix caching keyed by the prompt.

9 · Break it

Remove the positional encoding and the model stops being able to read.

Attention alone treats the sequence as an unordered set. "The dog bit the man" and "The man bit the dog" produce identical outputs. Nothing raises - the model simply loses grammar.

The second failure is arithmetic, and it is the one that costs money.

10 · Fix it

Positional information goes back in. RoPE is what current models use, because it makes the score depend on the distance between two positions rather than their absolute indexes.

The quadratic cost cannot be removed, only managed. Three levers, in the order you should reach for them:

LeverWhat it changesWhat it costs
Send lessRetrieve the relevant 2k tokens instead of sending 32kA retrieval system - module 06
FlashAttentionNever materialises the full score matrix; same maths, tiledNothing, if your serving stack supports it
Sliding window / GQAEach position attends to fewer keys, or heads share keysSome long-range accuracy

The first lever is the one engineers skip and the one that helps most. A 16× reduction in prompt length is a 256× reduction in attention cost.

11 · Production version

ConcernWhat you do
Memory planningWeights plus KV cache plus activations. The cache is per concurrent request and is usually what runs out first
BatchingContinuous batching keeps the GPU busy across requests of different lengths. It also means results can shift slightly between runs
Prefill versus decodeThe prompt pass is compute-bound; each generated token is memory-bound. They need different tuning and produce different latency curves
Prefix cachingPut the stable part of the prompt first so its KV entries can be reused across requests
Quantisation4-bit weights cut memory roughly fourfold. Quantise the KV cache separately - it is often the bigger win
Long contextAdvertised context length is not free context length. Measure cost and accuracy at your real length before promising it
Attention kernelUse FlashAttention or equivalent. A naive implementation materialises the whole score matrix

13 · Interview preparation

Beginner  What problem did the transformer solve over RNNs? ›

RNNs processed tokens sequentially (slow, un-parallelizable) and struggled with long-range dependencies due to vanishing gradients. The transformer uses self-attention to connect any two tokens directly in one parallel step, enabling both long-range modeling and GPU-efficient training.

Beginner  In attention, what are Q, K, and V? ›

Three learned linear projections of each token's embedding. Query = what this token is looking for; Key = what each token offers for matching; Value = the information each token contributes. Output = softmax(Q·Kᵀ/√d)·V - a relevance-weighted blend of values.

Intermediate  Why divide attention scores by √dₖ? ›

In high dimensions, dot products have large variance (∝ dₖ), pushing softmax toward a near one-hot distribution where gradients vanish. Scaling by √dₖ normalizes the variance, keeping the softmax soft and the model trainable.

Intermediate  Why do residual connections matter for deep transformers? ›

Each sub-layer computes x + f(x). The identity path lets gradients flow directly to earlier layers (avoiding vanishing gradients) and lets each block learn a refinement rather than a full transformation, making 100+ layer stacks trainable.

Senior  Your model degrades when prompts exceed ~8k tokens. Why, and what are your options? ›

Likely exceeding the trained context length - positional encodings are extrapolating to unseen positions, and attention quality drops (lost-in-the-middle). Options: switch to a longer-context model; apply RoPE scaling/interpolation; reduce input via better retrieval/chunking (RAG, End-to-End); summarize or compress context; or use sliding-window/long-context architectures. Measure with a needle-in-haystack eval before/after.

Senior  Explain the KV cache in terms of the causal mask. ›

Because of the causal mask, token i's keys/values never depend on future tokens and never change once computed. So during autoregressive generation we cache each token's K and V; generating token t+1 only requires computing its own Q and attending over the cached K/V - turning per-step cost from O(t²) recompute into O(t). The cache size grows linearly with context, which is the dominant inference memory cost (mitigated by GQA/paged attention).

Staff · design  Design an inference-serving layer to maximize throughput for a 70B model. ›

Use a server like vLLM/TGI exploiting architectural facts: continuous batching (interleave requests at token granularity since each step is independent), paged KV cache (non-contiguous KV blocks → near-zero memory fragmentation, more concurrency), FlashAttention kernels, tensor/pipeline parallelism across GPUs for the large FFN/attention matmuls, quantization (e.g. FP8/INT8) to fit weights and speed matmuls, and GQA models to shrink the cache. Add prefix/prompt caching for shared system prompts. Tune the batch/context tradeoff against the O(n²) attention curve and your latency SLO.

14 · In short, and what comes next

Remember these five:

  • Attention lets every position read every other position in one step.
  • Q, K and V are three learned views of the same token.
  • The causal mask is what stops a decoder reading the future.
  • Cost grows with the square of sequence length. Only the score matrix and the weighted sum are quadratic.
  • Without positional encoding, attention treats the sequence as an unordered set.
🔑
The one idea to remember

Attention moves information between positions; the feed-forward network does the work at each one. Every other part of the block - residuals, norms, multiple heads, positional encoding - exists to make those two operations trainable and order-aware.
